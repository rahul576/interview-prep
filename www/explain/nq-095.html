What is an anagram?

DSA: Arrays & Strings · concept · levels entry

In one line

An anagram is a word or phrase formed by rearranging all the letters of another, using each letter exactly as many times; two strings are anagrams when they have the same characters with the same frequencies, regardless of order.

Detailed explanation

"listen" and "silent" are anagrams: both contain one each of e, i, l, n, s and t. So are "eat", "tea" and "ate". "aab" and "abb" are not anagrams, even though they use the same set of letters, because the counts differ. Order does not matter at all; the multiset of characters is everything.

This simple definition hides several decisions that change the solution, so in an interview you should clarify the rules before coding:

  • Case sensitivity: is "Listen" an anagram of "Silent"? Usually yes after lowercasing, but ask.
  • Spaces and punctuation: phrase anagrams like "dormitory" and "dirty room" only match if spaces are ignored. "Astronomer" and "moon starer" are another classic.
  • Character set: only lowercase English letters (lets you use an int[26] counter), ASCII (int[128]), or full Unicode, where accented characters, combining marks and emojis (surrogate pairs) need a HashMap and possibly normalisation.
  • Is a word an anagram of itself? Mathematically yes, but some problems require a different word.
  • Empty strings and null input: decide the behaviour.

Anagram problems are popular in interviews because they test hashing, sorting, counting and complexity analysis in a small space: checking two strings, grouping a list of words, finding all anagram substrings in a text (sliding window), or counting the minimum deletions to make two strings anagrams.

How it works

  1. Normalise input according to the agreed rules (lowercase, strip spaces).
  2. If lengths differ after normalising, they are not anagrams.
  3. Compare character frequencies: by sorting both, or by counting.
  4. Equal sorted forms or all-zero count differences means anagram.

Example

static boolean isAnagram(String a, String b) {
    String x = a.replaceAll("\\s+", "").toLowerCase();
    String y = b.replaceAll("\\s+", "").toLowerCase();
    if (x.length() != y.length()) return false;
    int[] counts = new int[26];                 // assumes letters a–z after normalising
    for (int i = 0; i < x.length(); i++) {
        counts[x.charAt(i) - 'a']++;
        counts[y.charAt(i) - 'a']--;
    }
    for (int c : counts) if (c != 0) return false;
    return true;
}

isAnagram("listen", "silent");       // true
isAnagram("Dormitory", "dirty room"); // true
isAnagram("aab", "abb");             // false

Common mistakes

  • Comparing only the set of characters and ignoring counts.
  • Not asking about case, spaces and character set.
  • Using int[26] when input may contain digits or Unicode.
  • Forgetting the cheap length check.

How to answer in the interview

"An anagram is a word or phrase formed by rearranging all the letters of another, using each letter exactly as many times as it appears, like listen and silent, or eat, tea and ate. So two strings are anagrams when they have the same characters with the same frequencies; order doesn't matter. Before coding I'd clarify the rules: is it case-sensitive, should spaces and punctuation be ignored, and is the input only lowercase English letters? That decides whether I can use a 26-element counter or need a hash map."

Likely follow-up questions

  • Are "Dormitory" and "dirty room" anagrams? Yes, if you ignore case and spaces.
  • How would you check two strings? Sort and compare, or count frequencies in O(n).
  • How would you find all anagrams of a pattern in a text? Sliding window with character counts.
