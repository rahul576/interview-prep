What is AWS Lambda, and how does it process messages from a queue?

Cloud (AWS) · concept · levels entry

In one line

AWS Lambda runs code on events without managing servers, billed per request and duration, with a 15-minute maximum; for SQS it uses an event source mapping where the Lambda service long-polls the queue, batches messages and invokes your function; success deletes the batch, an error makes messages reappear for retry, partial batch responses (ReportBatchItemFailures) retry only failed items, and the redrive policy sends repeat failures to a DLQ.

Detailed explanation

Lambda basics: you upload code (zip or container image), choose runtime and memory (CPU scales with memory), set a timeout up to 15 minutes, and grant permissions through an execution role. AWS runs instances as needed and reuses warm ones. Java functions benefit from SnapStart to reduce cold starts.

SQS integration: you do not write polling code. The event source mapping (ESM) is managed by the Lambda service:

  • It long-polls the queue and collects messages until the batch size (up to 10 for FIFO, up to 10,000 for standard with a batching window) or the maximum batching window is reached.
  • It invokes your function synchronously with the batch as an event.
  • If the function returns successfully, the ESM deletes the messages.
  • If it throws or times out, nothing is deleted; messages become visible again after the queue's visibility timeout and are retried.

Partial batch failures: enable ReportBatchItemFailures and return the IDs of the failed messages; only those are retried, avoiding reprocessing of successful ones.

DLQ: configure the redrive policy on the source queue with maxReceiveCount; messages exceeding it move to the DLQ. Set the queue visibility timeout to at least six times the function timeout so retries and throttling do not cause premature redelivery.

The ESM also scales the number of concurrent invocations with the backlog.

How it works

  1. Create queue, DLQ and redrive policy.
  2. Create the function with an execution role allowing SQS receive and delete.
  3. Create the event source mapping with batch size and window.
  4. Lambda polls, batches and invokes.
  5. Return failed item IDs; successes are deleted.
  6. Repeated failures go to the DLQ.

Example

public class OrderHandler implements RequestHandler<SQSEvent, SQSBatchResponse> {
    public SQSBatchResponse handleRequest(SQSEvent event, Context ctx) {
        List<SQSBatchResponse.BatchItemFailure> failures = new ArrayList<>();
        for (SQSEvent.SQSMessage m : event.getRecords()) {
            try { process(m.getBody()); }
            catch (Exception e) { failures.add(new SQSBatchResponse.BatchItemFailure(m.getMessageId())); }
        }
        return new SQSBatchResponse(failures);
    }
}
aws lambda create-event-source-mapping --function-name order-handler \
  --event-source-arn arn:aws:sqs:eu-west-1:123456789012:orders \
  --batch-size 10 --function-response-types ReportBatchItemFailures

Common mistakes

  • Visibility timeout shorter than the function timeout.
  • Throwing for the whole batch when one message fails.
  • Configuring the DLQ on the function instead of the source queue for SQS triggers.
  • Non-idempotent processing.

How to answer in the interview

"Lambda runs code in response to events without managing servers; you pay per request and per millisecond, with a fifteen-minute maximum. For SQS, the Lambda service uses an event source mapping: it long-polls the queue, batches messages by size and window, and invokes the function. If the function succeeds, the messages are deleted; if it throws, the batch becomes visible again after the visibility timeout and is retried, unless I return partial batch failures with ReportBatchItemFailures so only failed messages retry. Messages that keep failing go to the dead-letter queue via the queue's redrive policy."

Likely follow-up questions

  • Why visibility timeout larger than Lambda timeout? Otherwise messages reappear while still being processed; AWS recommends at least six times.
  • Cold starts in Java? SnapStart, provisioned concurrency, lean dependencies.
  • FIFO with Lambda? Ordered per message group; a failing group blocks until resolved.
