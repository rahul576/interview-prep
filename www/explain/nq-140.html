What are creational, structural, and behavioral design patterns? Give examples.

Design Patterns · concept · levels entry, mid

In one line

Creational patterns control object creation (Singleton, Factory Method, Builder), structural patterns compose objects (Adapter, Decorator, Proxy, Facade), and behavioural patterns manage interaction (Strategy, Observer, Template Method), and all appear in Java and Spring.

Detailed explanation

Creational, with real usage:

  • Singleton: one shared instance. Spring beans are singleton-scoped by default; Runtime.getRuntime() is a JDK singleton.
  • Factory Method: a method decides which concrete class to return: Calendar.getInstance(), NumberFormat.getInstance(), List.of(...).
  • Builder: step-by-step construction: StringBuilder, HttpRequest.newBuilder(), Lombok @Builder, UriComponentsBuilder.

Structural:

  • Adapter: makes an incompatible interface usable: InputStreamReader adapts bytes to characters; Arrays.asList presents an array as a List; Spring MVC HandlerAdapter.
  • Decorator: wraps to add behaviour: BufferedInputStream, Collections.unmodifiableList and synchronizedList.
  • Proxy: controls access: Spring AOP proxies for @Transactional/@Cacheable, Hibernate lazy proxies.
  • Facade: simple API over a complex subsystem. JdbcTemplate hides connections, statements, result sets and exception translation; SLF4J is a facade over logging frameworks.

Behavioural:

  • Strategy: interchangeable algorithms: Comparator, payment strategies.
  • Observer: notify subscribers: ApplicationEventPublisher + @EventListener, JavaBeans PropertyChangeListener.
  • Template Method: fixed skeleton with variable steps: HttpServlet.service() calling doGet/doPost, AbstractList; JdbcTemplate applies the idea via callbacks like RowMapper.

Note that one class can embody several patterns: JdbcTemplate is a facade and a template-method-with-callbacks.

How it works

  1. Creational: replace direct new with a factory, builder or managed instance.
  2. Structural: wrap or combine objects behind an interface.
  3. Behavioural: delegate the varying part of behaviour to another object.
  4. Let Spring provide many of them (container, AOP, events).

Example

// Creational – Builder
var client = HttpClient.newBuilder().connectTimeout(Duration.ofSeconds(5)).build();

// Structural – Adapter + Decorator
BufferedReader in = new BufferedReader(new InputStreamReader(socket.getInputStream(), UTF_8));

// Behavioural – Template Method via callback, Strategy via lambda
List<User> users = jdbcTemplate.query("SELECT id, name FROM users",
        (rs, i) -> new User(rs.getLong("id"), rs.getString("name")));
users.sort(Comparator.comparing(User::name));

Common mistakes

  • Giving only textbook definitions without real examples.
  • Calling StringBuilder a perfect GoF Builder (it is a mutable accumulator; the analogy is loose).
  • Confusing Facade with Adapter (Facade simplifies; Adapter converts).
  • Overlooking that @Transactional is a Proxy, not a Decorator or Observer.

How to answer in the interview

"Creational patterns control object creation: Singleton, like Spring's default beans; Factory Method, like Calendar.getInstance or List.of; and Builder, like HttpRequest.newBuilder or Lombok. Structural patterns compose objects: Adapter, like InputStreamReader; Decorator, like BufferedInputStream; Proxy, like Spring AOP proxies; and Facade, like JdbcTemplate hiding JDBC boilerplate. Behavioural patterns manage interaction: Strategy, like Comparator; Observer, like Spring application events; and Template Method, like HttpServlet calling doGet or JdbcTemplate callbacks."

Likely follow-up questions

  • Which pattern does Spring use for @Transactional? Proxy (AOP), via JDK dynamic proxies or CGLIB.
  • Facade vs Adapter? Facade simplifies a subsystem; Adapter makes one interface match another.
  • Which pattern is SLF4J? A facade over Logback, Log4j 2 and others.
