How do firewalls work in Linux and in the cloud? Explain iptables, security groups and stateful filtering.

Networking · concept · levels mid, senior

In one line

Firewalls allow or deny traffic by IP, port and protocol; Linux uses netfilter via iptables or nftables (often managed by ufw or firewalld), stateful filtering tracks connections so return traffic is allowed automatically, and in AWS security groups are stateful allow-lists on interfaces while NACLs are stateless subnet rules; always default deny, least access.

Detailed explanation

Linux: the kernel's netfilter framework inspects packets at hooks (prerouting, input, forward, output, postrouting). iptables organises rules into tables (filter, nat, mangle) and chains (INPUT, OUTPUT, FORWARD); rules are evaluated top-down and the first match decides, then the chain policy applies. nftables (nft) is the modern replacement with a cleaner syntax and better performance, and current distributions use it under the hood (iptables-nft). Friendlier front-ends: ufw on Ubuntu, firewalld with zones on RHEL. Docker and Kubernetes (kube-proxy in iptables mode, CNIs) also write netfilter rules; eBPF-based CNIs like Cilium can bypass iptables.

Stateful filtering: conntrack tracks connections (NEW, ESTABLISHED, RELATED). A rule like "accept ESTABLISHED,RELATED" lets replies back in, so you only write rules for the direction that initiates the connection. Stateless filters evaluate each packet alone, so you must permit return traffic explicitly, usually to the ephemeral port range.

Cloud (AWS): security groups attach to ENIs (instances, load balancers, RDS), contain allow rules only, are stateful, and can reference other security groups as sources, which is cleaner than IPs. Network ACLs apply to subnets, are stateless, have numbered allow and deny rules evaluated in order, and need inbound and outbound rules including ephemeral ports. Azure has NSGs (stateful, with allow and deny and priorities) on subnets or NICs, plus Azure Firewall; GCP has VPC firewall rules and policies. Centralised cloud firewalls add FQDN filtering and inspection.

Good practice: default deny inbound, open only required ports to specific sources (SSH via a bastion or SSM instead of 0.0.0.0/0), restrict egress for sensitive workloads, manage rules as code (Terraform), and review them regularly.

How it works

  1. Packet arrives at an interface.
  2. Cloud NACL (stateless) and security group (stateful) evaluate it.
  3. On the host, netfilter checks conntrack state, then rules.
  4. First matching rule accepts or drops; else default policy.
  5. Replies to accepted connections pass automatically through stateful layers.

Example

# nftables: default-deny inbound, allow established, SSH from admin net, HTTPS from anywhere
sudo nft add table inet filter
sudo nft add chain inet filter input '{ type filter hook input priority 0; policy drop; }'
sudo nft add rule inet filter input ct state established,related accept
sudo nft add rule inet filter input iif lo accept
sudo nft add rule inet filter input ip saddr 10.0.100.0/24 tcp dport 22 accept
sudo nft add rule inet filter input tcp dport 443 accept
# ufw equivalent
sudo ufw default deny incoming && sudo ufw allow from 10.0.100.0/24 to any port 22 && sudo ufw allow 443/tcp

Common mistakes

  • Forgetting ephemeral return ports in NACLs.
  • Opening SSH or databases to 0.0.0.0/0.
  • Flushing iptables rules and breaking Docker or Kubernetes networking.
  • Rules added by hand, never reviewed or codified.

How to answer in the interview

"A firewall applies rules that allow or deny traffic by source and destination IP, port and protocol. On Linux, netfilter does it, configured with iptables or the newer nftables, usually through ufw or firewalld. A stateful firewall tracks connections, so return traffic for an allowed connection is allowed automatically. In AWS, security groups are stateful, attached to interfaces, with allow rules only, while network ACLs are stateless subnet rules, so return traffic on ephemeral ports must be allowed explicitly. Good practice is default deny and opening only the minimum ports to specific sources."

Likely follow-up questions

  • Why does a request work from one subnet but not another in the same VPC? Different NACLs or route tables, or the security group allows only the first subnet's CIDR or SG.
  • Security group referencing another SG? Allows traffic from any interface in that group, independent of IPs.
  • iptables versus nftables? nftables is the successor with one framework for IPv4, IPv6 and more.
