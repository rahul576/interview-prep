How do you find the kth largest element in an unsorted array?

DSA: Algorithms & DP · concept · levels mid

In one line

Use a min-heap of size k (push each element, pop when the size exceeds k, and the root is the kth largest). That is O(n log k) time and O(k) space, and it works for streams. Or use quickselect (partition and recurse into one side), which is O(n) on average and O(n²) worst case, mitigated by a random pivot. Sorting is the simple O(n log n) baseline.

Detailed explanation

Sorting descending and taking index k-1 is correct but does more work than needed. We don't need the whole order, only one rank.

Min-heap of size k. Keep the k largest elements seen so far in a min-heap. Its root is the smallest of those k, so it is the kth largest overall. For each element, offer it, and if size > k, poll the root. Each operation is O(log k), so the total is O(n log k), with O(k) memory. That is great when k is small, and it naturally handles streams or data that doesn't fit in memory, because you process elements one at a time. Java's PriorityQueue is a min-heap by default.

Quickselect (Hoare's selection). Use quicksort's partition step: choose a pivot and rearrange so the larger elements are on one side. The kth largest is at index n - k in ascending order. After partitioning, the pivot is at its final position p. If p == target, done. If target < p, recurse left only. Otherwise recurse right only. Because we recurse into one side, the expected work is n + n/2 + n/4 + ... = O(n). With consistently bad pivots (sorted input with a first-element pivot) it degrades to O(n²). A random pivot makes that extremely unlikely, and median of medians guarantees O(n) worst case, at a high constant cost. Quickselect is in-place (O(1) extra space, or O(log n) recursion), but it mutates the array and needs everything in memory.

Other options:

  • Building a max-heap of all n (heapify is O(n)) and popping k times costs O(n + k log n).
  • For huge distributed data, compute a top-k per partition and merge them, or use approximate quantile sketches (t-digest, KLL) for percentiles.

How it works

  1. Heap: for each x, heap.offer(x), and if (heap.size() > k) heap.poll(). Return heap.peek().
  2. Quickselect: target = n - k, lo = 0, hi = n - 1.
  3. Pick a random pivot and partition [lo, hi] to get its index p.
  4. If p == target, return a[p]. If p < target, set lo = p + 1. Otherwise hi = p - 1.
  5. Repeat.

Example

int kthLargestHeap(int[] nums, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();
    for (int x : nums) { heap.offer(x); if (heap.size() > k) heap.poll(); }
    return heap.peek();
}

int kthLargestQuickselect(int[] a, int k) {
    int target = a.length - k, lo = 0, hi = a.length - 1;
    Random rnd = new Random();
    while (true) {
        int p = partition(a, lo, hi, lo + rnd.nextInt(hi - lo + 1));
        if (p == target) return a[p];
        if (p < target) lo = p + 1; else hi = p - 1;
    }
}
int partition(int[] a, int lo, int hi, int pivotIdx) {   // Lomuto
    int pivot = a[pivotIdx]; swap(a, pivotIdx, hi);
    int store = lo;
    for (int i = lo; i < hi; i++) if (a[i] < pivot) swap(a, i, store++);
    swap(a, store, hi);
    return store;
}
// [3,2,1,5,6,4], k=2 -> 5

Common mistakes

  • Using a max-heap of size k (that gives the kth smallest).
  • Off-by-one in the target index (n - k for ascending order).
  • Quickselect with a fixed pivot on sorted input.
  • Forgetting that quickselect modifies the input.

How to answer in the interview

"One approach is a min-heap of size k. I push each element and pop the smallest when the size exceeds k, so the top is the kth largest. That's O(n log k) time, O(k) space, and it works on streams. The other is quickselect: use quicksort's partition and recurse only into the side containing the target index, which gives O(n) on average. The worst case is O(n squared), so I'd use a random pivot. Sorting is simplest but O(n log n). For a stream of a billion numbers, I'd pick the heap, because it needs only O(k) memory."

Likely follow-up questions

  • Stream of a billion numbers? A min-heap of size k, using O(k) memory, single pass.
  • Median of a stream? Two heaps: a max-heap for the lower half and a min-heap for the upper half.
  • Guaranteed linear time? The median-of-medians pivot, though it is rarely faster in practice.
