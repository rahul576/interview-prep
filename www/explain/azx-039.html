What is Azure Arc, and when would you use it?

Azure · concept · levels mid, senior

In one line

Azure Arc extends Azure Resource Manager to machines and Kubernetes clusters outside Azure (on-premises, edge, AWS, GCP), so they can be governed with Azure Policy, RBAC, Monitor, Update Manager, Defender and GitOps from one control plane, and it also delivers Arc data services and Extended Security Updates.

Detailed explanation

Many organisations run a hybrid estate: VMware clusters, edge sites, AWS accounts and Azure. Each environment traditionally has its own tools for patching, monitoring and policy. Arc projects those resources into ARM so they appear in a resource group with tags, RBAC and the same APIs as Azure resources.

Arc-enabled servers: install the Connected Machine agent on Windows or Linux. The machine becomes a Microsoft.HybridCompute/machines resource with a managed identity, so you can apply Azure Policy and machine configuration (guest configuration), deploy the Azure Monitor Agent with DCRs, patch with Azure Update Manager, protect with Defender for Servers, run scripts with Run Command, and use SSH via Arc with Entra ID. Extended Security Updates for Windows Server 2012/R2 can be bought and delivered through Arc.

Arc-enabled Kubernetes: connect any CNCF-conformant cluster (EKS, GKE, AKS on Azure Local, OpenShift, k3s) with an agent that makes an outbound connection. Then use GitOps with Flux v2 configurations, Azure Policy for Kubernetes (Gatekeeper), Container Insights, Defender for Containers, and cluster extensions.

Arc data services: run SQL Managed Instance enabled by Azure Arc on your Kubernetes, and SQL Server enabled by Azure Arc for inventory, licensing (pay-as-you-go) and best-practice assessment of on-prem SQL.

Arc also underpins Azure Local (formerly Azure Stack HCI) and VMware vSphere / SCVMM integration for lifecycle operations. The agents need outbound HTTPS (443) to Azure endpoints, directly, via proxy, or through Arc private link scope; no inbound ports are opened.

How it works

  1. Generate an onboarding script (service principal for scale) for servers or clusters.
  2. Agent connects outbound and registers the resource in ARM.
  3. Apply tags, RBAC and policy assignments at the resource group or management group.
  4. Deploy extensions: AMA, Defender, Flux, Update Manager.
  5. Manage everything through the portal, CLI, IaC and Resource Graph.

Example

# Connect an EKS or on-prem cluster
az connectedk8s connect -n k8s-factory-01 -g rg-arc-edge --location westeurope
# Add a GitOps configuration
az k8s-configuration flux create -g rg-arc-edge -c k8s-factory-01 -t connectedClusters \
  -n platform --namespace flux-system --scope cluster \
  -u https://github.com/contoso/platform-gitops --branch main --kustomization name=base path=./clusters/factory

Common mistakes

  • Treating Arc as a migration tool; it manages resources where they are.
  • Forgetting outbound network requirements and proxy configuration.
  • Onboarding thousands of servers without tagging and RBAC design.
  • Assuming every Azure VM feature works the same on Arc machines.

How to answer in the interview

"Azure Arc extends Azure Resource Manager to resources outside Azure. Arc-enabled servers make on-prem or other-cloud machines Azure resources, so I can apply Azure Policy and machine configuration, monitor with Azure Monitor, patch with Update Manager, protect with Defender and control access with RBAC. Arc-enabled Kubernetes connects any conformant cluster, like EKS or on-prem, for GitOps with Flux, policy and monitoring. It also brings Arc data services and delivers Extended Security Updates for old Windows Server. I use it when the company wants one governance control plane across hybrid and multi-cloud."

Likely follow-up questions

  • Network needs? Outbound 443 to Azure endpoints, optionally via proxy or private link scope; no inbound.
  • Arc vs Azure Local? Azure Local is hybrid infrastructure; Arc is the management layer it uses.
  • Cost? The Arc control plane is free; you pay for services used (Defender, Monitor, Update Manager for Arc).
