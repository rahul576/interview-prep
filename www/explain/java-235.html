How do records work in detail? Can you add validation or methods to them?

Java 8+ Features · concept · levels mid, senior

In one line

A record is a final class whose components become private final fields with accessors, and the compiler generates the canonical constructor, equals, hashCode and toString; you can add validation in a compact constructor, methods, static factories and interfaces, but records can't extend classes and aren't suitable as JPA entities.

Detailed explanation

record Money(BigDecimal amount, String currency) {} produces a final class extending java.lang.Record, with fields amount and currency, accessors amount() and currency() (no get prefix), a canonical constructor taking both, and value-based equals/hashCode/toString over all components. Records are shallowly immutable: the fields can't be reassigned, but a component that is a mutable List can still be changed unless you copy it.

Compact constructors omit the parameter list and assignments; the code runs before the fields are assigned, so you can validate and normalise the parameters: reject negative amounts, trim strings, or defensively copy a list with List.copyOf. You may also write the full canonical constructor or add extra constructors that delegate to it with this(...).

Records may declare instance methods, static fields and methods (e.g. of(...) factories), nested types, and implement interfaces, which makes them ideal subtypes of sealed interfaces. They cannot declare extra instance fields, extend another class, or be abstract. You can override accessors, equals or toString if needed, keeping the contract.

JPA entities need a no-args constructor, mutable state and often proxies (subclassing), so records don't fit. They are excellent for DTOs, API request/response bodies (Jackson supports them), query projections (Spring Data, JPQL constructor expressions), value objects and map keys. Hibernate 6 supports records as embeddables.

How it works

  1. The compiler generates fields, accessors, canonical constructor and object methods.
  2. A compact constructor's body runs first, operating on parameters.
  3. The implicit field assignments happen at the end of the compact constructor.
  4. Serialisation of records always goes through the canonical constructor, so validation also applies on deserialisation.

Example

public record Money(BigDecimal amount, String currency) {
    public Money {                                   // compact constructor
        Objects.requireNonNull(amount, "amount");
        if (amount.signum() < 0) throw new IllegalArgumentException("negative amount");
        currency = currency.toUpperCase(Locale.ROOT); // normalise
    }
    public static Money inr(String value) { return new Money(new BigDecimal(value), "INR"); }
    public Money plus(Money other) {
        if (!currency.equals(other.currency)) throw new IllegalArgumentException("currency mismatch");
        return new Money(amount.add(other.amount), currency);
    }
}

public record Order(String id, List<String> items) {
    public Order { items = List.copyOf(items); }      // defensive, unmodifiable copy
}

Common mistakes

  • Assuming records are deeply immutable when they hold mutable collections.
  • Trying to assign this.amount inside a compact constructor (not allowed; reassign the parameter).
  • Using records as JPA entities.
  • Calling accessors getAmount() out of habit.

How to answer in the interview

"A record is a final class; its components become private final fields with accessors named after them, and the compiler generates the canonical constructor, equals, hashCode and toString. I validate and normalise in a compact constructor, for example rejecting negative amounts or copying a list with List.copyOf. Records can have instance methods, static factories and nested types, and implement interfaces, which pairs nicely with sealed types. They can't extend a class or add instance fields, and they aren't suitable as JPA entities, but they're great DTOs, projections and value objects."

Likely follow-up questions

  • How do you make a record defensively copy a List? Reassign items = List.copyOf(items) in the compact constructor.
  • Can records have static fields? Yes, static fields and methods are allowed; extra instance fields are not.
  • Do records work with Jackson? Yes, modern Jackson versions deserialise via the canonical constructor.
