Which OWASP risks for LLM and agentic applications are most relevant to MCP, and how do they map to controls?

MCP Servers · concept · levels mid, senior

In one line

The OWASP Top 10 for LLM Applications and OWASP's agentic AI threat guidance map closely to MCP: prompt injection (via descriptions and results), excessive agency, sensitive information disclosure, supply chain vulnerabilities and improper output handling, controlled by untrusted-input handling and approvals, least privilege, minimisation and DLP, vetting and pinning, and validation and parameterisation.

Detailed explanation

OWASP's GenAI Security Project publishes the Top 10 for LLM applications (the 2025 edition is current) and separate guidance on agentic threats. They are a useful common language with security teams. The most relevant entries for MCP:

Prompt injection (LLM01), the top risk. In MCP it arrives indirectly through tool descriptions (tool poisoning) and tool results (emails, pages, tickets). Controls: treat all of it as untrusted, require human approval for side effects, separate untrusted reading from privileged actions, and add detection.

Excessive agency (LLM06): agents with more tools, permissions or autonomy than they need. Controls: least privilege at tool, credential and network layers; read-only modes; approvals for high-impact actions.

Sensitive information disclosure (LLM02): secrets or personal data leaking through tool results, arguments or logs. Controls: data minimisation, redaction, never returning secrets, DLP on arguments, session separation.

Supply chain (LLM03): malicious or compromised servers and packages, typosquatting, rug pulls. Controls: vetting, internal registries, pinning, signing and sandboxing.

Improper output handling (LLM05): using model output, such as generated SQL, shell commands, file paths or URLs, without validation. Controls: tools validate and parameterise everything they execute, allowlist commands and paths, and treat model-provided arguments as untrusted input like any user input.

Agentic guidance adds threats such as tool misuse, privilege compromise, memory poisoning and identity spoofing, which map to the same set of controls plus strong authentication and audit.

How it works

  1. List the servers and tools in your deployment.
  2. For each OWASP risk, identify where it enters (description, result, argument, credential, package).
  3. Assign a control per entry point.
  4. Verify with threat modelling and red-team tests.
  5. Re-assess when servers or tools change.

Common mistakes

  • Citing OWASP without mapping risks to concrete controls.
  • Treating model-generated arguments as trusted because "our model produced them".
  • Focusing only on prompt injection and ignoring supply chain.
  • Quoting a ranking from an outdated edition without checking.

How to answer in the interview

"The OWASP Top 10 for LLM applications, plus OWASP's agentic AI guidance, map closely to MCP. Prompt injection, the top risk, arrives through tool descriptions and results, so I treat them as untrusted and keep humans in the loop for side effects. Excessive agency means more tools, permissions or autonomy than needed; the control is least privilege at tool, credential and network levels. Sensitive information disclosure covers secrets or personal data leaking through results or arguments, mitigated by minimisation, redaction and DLP. Supply chain covers malicious or compromised servers, so I vet, pin and sandbox. Improper output handling covers executing model output like SQL or shell without validation, so tools validate and parameterise everything."

Likely follow-up questions

  • Hardest to eliminate? Prompt injection, because models cannot reliably separate data from instructions.
  • Excessive agency example? A summarisation agent that also has delete tools.
  • How to verify controls? Threat modelling and red-team test suites in CI.
