Explain primary key, foreign key, unique key, and composite key.

Databases & SQL · concept · levels entry, mid

In one line

A primary key is the unique, non-null identifier of each row (one per table), a foreign key references another table's key to enforce referential integrity, a unique key enforces uniqueness on other columns (usually allowing NULLs), and a composite key is any key made of several columns.

Detailed explanation

Primary key (PK): there is exactly one per table, it must be unique and NOT NULL, and every other table refers to rows through it. Databases automatically create a unique index for it; in MySQL InnoDB that index is the clustered index, so the PK also decides the physical row order.

Foreign key (FK): a column (or columns) whose values must exist in the referenced table's primary or unique key. order_items.order_id REFERENCES orders(id) means you cannot insert an item for a non-existent order, and you cannot delete an order that still has items unless you define ON DELETE CASCADE, SET NULL or RESTRICT behaviour. Important detail: PostgreSQL does not automatically index the FK column itself (MySQL InnoDB does), so you usually add one to keep joins and cascading deletes fast.

Unique key: enforces that values in a column, such as users.email, are unique. A table can have many. In PostgreSQL, MySQL and Oracle multiple NULLs are allowed because NULL is not equal to NULL (PostgreSQL 15+ supports NULLS NOT DISTINCT to change that); SQL Server allows only one NULL in a unique constraint.

Composite key: a key consisting of multiple columns that are unique together, such as (order_id, line_number) in an order line table, or (student_id, course_id) in a many-to-many join table.

Many teams use a surrogate key (auto-increment or UUID) as the PK and enforce natural keys like email with unique constraints, because natural values can change.

How it works

  1. Define the PK; the database builds a unique index.
  2. Define FKs; on each insert/update the database checks the parent exists.
  3. On parent delete/update, the FK action (restrict, cascade, set null) applies.
  4. Unique constraints create unique indexes and reject duplicates.
  5. Composite keys index their columns in the declared order.

Example

CREATE TABLE users (
  id    BIGSERIAL PRIMARY KEY,
  email VARCHAR(255) NOT NULL UNIQUE
);
CREATE TABLE orders (
  id      BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE RESTRICT
);
CREATE INDEX idx_orders_user ON orders(user_id);   -- FK index (Postgres)
CREATE TABLE order_line (
  order_id    BIGINT REFERENCES orders(id) ON DELETE CASCADE,
  line_number INT,
  sku         TEXT NOT NULL,
  PRIMARY KEY (order_id, line_number)               -- composite key
);

Common mistakes

  • Using an email or name as PK, which then has to change everywhere.
  • Assuming a unique constraint forbids NULLs.
  • Forgetting to index FK columns in PostgreSQL, making joins and parent deletes slow.
  • Dropping FKs "for performance" and ending up with orphan rows.

How to answer in the interview

"A primary key uniquely identifies a row, it's unique and not null and there's one per table, like orders.id. A foreign key references another table's key, like order_items.order_id to orders.id, and the database enforces referential integrity, so I can't create an item for a missing order, with cascade or restrict rules for deletes. A unique key enforces uniqueness on other columns such as email; a table can have several and they usually allow NULLs. A composite key is made of several columns that are unique together, like order id plus line number. Primary and unique keys get indexes automatically, but in Postgres I add an index on foreign key columns myself."

Likely follow-up questions

  • Natural or surrogate PK? Usually a surrogate (bigint or UUIDv7), with natural keys enforced by unique constraints.
  • What is a candidate key? Any minimal set of columns that uniquely identifies rows; the PK is the chosen one.
  • What does ON DELETE CASCADE do? Deleting the parent automatically deletes its child rows.
