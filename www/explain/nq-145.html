What is the Factory Method pattern?

Design Patterns · concept · levels entry, mid

In one line

Factory Method defines a method for creating objects but lets subclasses or the factory logic decide the concrete class, so clients depend on an interface and new products can be added without changing them (open/closed).

Detailed explanation

Direct new EmailNotification() calls spread knowledge of concrete classes across the codebase. Factory Method centralises that decision.

Strict GoF form: an abstract creator class has business logic that calls an abstract createProduct() method; each concrete creator subclass overrides it to return a different product. For example an abstract ReportExporter with export() calling createWriter(), and PdfReportExporter / CsvReportExporter overriding createWriter(). The creator's workflow stays the same; only the product differs.

Everyday form: a factory class or method that takes a parameter, NotificationFactory.create(Channel.SMS), and returns the right implementation of Notification. Strictly this is a "simple factory", but the intent, hiding the concrete type, is the same and interviewers accept it if you mention the distinction.

Static factory methods in the JDK, such as List.of, LocalDate.of, Optional.empty, Calendar.getInstance and NumberFormat.getInstance, are a related idiom from Effective Java: named, can return cached instances or subtypes, and need not create a new object each time.

Benefits: decoupling (callers know only the interface), single place for creation logic, easier testing (swap the factory), and open/closed extension. In Spring, a switch factory is often replaced by injecting Map<String, Notification> of beans keyed by name, or by @Bean methods, which are themselves factory methods.

How it works

  1. Define a product interface (Notification).
  2. Write concrete products (EmailNotification, SmsNotification).
  3. Provide a creation method (overridable in subclasses, or parameterised).
  4. Clients call the factory and use the product through its interface.
  5. Add a new product by adding a class and registering it.

Example

interface Notification { void send(String to, String message); }
class EmailNotification implements Notification { public void send(String to, String m) { /* SMTP */ } }
class SmsNotification   implements Notification { public void send(String to, String m) { /* SMS API */ } }

// Simple/parameterised factory
class NotificationFactory {
    static Notification create(Channel channel) {
        return switch (channel) {
            case EMAIL -> new EmailNotification();
            case SMS   -> new SmsNotification();
        };
    }
}

// GoF Factory Method via subclassing
abstract class Notifier {
    protected abstract Notification createNotification();
    public void notifyUser(String to, String msg) { createNotification().send(to, msg); }
}
class SmsNotifier extends Notifier { protected Notification createNotification() { return new SmsNotification(); } }

Common mistakes

  • Not distinguishing simple factory from GoF Factory Method.
  • Returning concrete types from the factory, defeating the purpose.
  • A giant switch that every team edits (consider a registry or bean map).
  • Confusing it with Abstract Factory (families of products).

How to answer in the interview

"Factory Method defines a method for creating an object but lets subclasses, or the factory implementation, decide which concrete class to instantiate. The client asks for a product through an abstraction, say factory.create(channel), and gets an email, SMS or push notification without knowing the classes. That decouples clients from concrete types and follows open/closed, since new products just extend the factory. Strictly, GoF Factory Method uses subclass overriding; in everyday Java we also use static factories like List.of or Calendar.getInstance. In Spring I often inject a map of beans instead of a switch."

Likely follow-up questions

  • How does Abstract Factory differ? It creates families of related products through several methods; Factory Method creates one product.
  • Advantages of static factory methods over constructors? Names, caching, returning subtypes, and no obligation to create a new object.
  • Is a Spring @Bean method a factory method? Yes, the container calls it to create the bean.
