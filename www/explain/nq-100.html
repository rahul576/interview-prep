How would you generate a key for each word to identify anagrams?

DSA: Arrays & Strings · concept · levels mid

In one line

Use either the sorted characters (simple, O(k log k)) or a character-frequency key such as "1#0#2#..." or Arrays.toString(counts) (O(k)); avoid the prime-product trick because of overflow, and always normalise case and spaces first.

Detailed explanation

The key must satisfy one rule: two words get the same key if and only if they are anagrams, and the key type must have value-based equals and hashCode so it works in a HashMap.

Option 1 – sorted string. char[] c = w.toCharArray(); Arrays.sort(c); key = new String(c); Short, readable and works for any characters. O(k log k) per word.

Option 2 – frequency key. Count letters into int[26], then serialise the counts. Using a separator matters: without it, counts like [1, 11] and [11, 1] could both become "111". Options:

  • StringBuilder with '#' between counts: "1#0#0#...".
  • Arrays.toString(counts) → "[1, 0, 0, ...]", easy and unambiguous.
  • Append each letter followed by its count, skipping zeros ("a1e1t1"), which is shorter for sparse words.
  • A List<Integer> of counts as the key, since List implements value equality.

This is O(k + 26) per word, better for long words.

Option 3 – prime product. Assign each letter a distinct prime (a=2, b=3, c=5 ...) and multiply. By the fundamental theorem of arithmetic, equal products mean equal multisets. It is clever but overflows a long for moderately long words, causing false matches unless you use BigInteger, which removes the speed advantage. Mention it, then reject it.

Why not int[] directly? Arrays inherit equals and hashCode from Object, so two arrays with identical counts are different keys.

Normalisation: decide on case-folding (toLowerCase(Locale.ROOT) to avoid locale surprises like Turkish dotted i) and whether to strip spaces and punctuation, then build the key from the normalised string while storing the original word in the group.

How it works

  1. Normalise the word.
  2. Build the key: sort characters, or count into an array and serialise with separators.
  3. Use the key in computeIfAbsent.
  4. Store the original word in the list.

Example

static String sortedKey(String w) {
    char[] c = w.toLowerCase(Locale.ROOT).toCharArray();
    Arrays.sort(c);
    return new String(c);
}

static String countKey(String w) {
    int[] counts = new int[26];
    for (char ch : w.toLowerCase(Locale.ROOT).toCharArray())
        if (ch >= 'a' && ch <= 'z') counts[ch - 'a']++;
    StringBuilder sb = new StringBuilder();
    for (int n : counts) sb.append(n).append('#');
    return sb.toString();               // e.g. "1#0#0#0#1#...#1#..."
}

sortedKey("Tea");  // "aet"
countKey("tea");   // "1#0#0#0#1#0#...#1#0#..."

Common mistakes

  • Using int[] or char[] as the map key.
  • Building count strings without separators.
  • Prime products overflowing silently.
  • Locale-sensitive toLowerCase() without a locale.

How to answer in the interview

"I'd use either the sorted characters, new String of the sorted char array, which is simple and O(k log k), or a frequency key: count letters into an int[26] and build a string like 1#0#0#2, or use Arrays.toString of the counts. That's O(k) and better for long words. A list of counts also works as a key because it has proper equals and hashCode. There's a clever prime-product trick, but it overflows for long words, so I'd avoid it. And I'd normalise first, lowercasing and stripping spaces if the problem says they don't matter."

Likely follow-up questions

  • Why can't the int[] itself be a key? Arrays use identity-based equals and hashCode.
  • Why the separator? Without it, different count arrays can serialise to the same string.
  • Which key would you use for Unicode? Sorted code points, or a TreeMap/Map of code-point counts converted to a string.
