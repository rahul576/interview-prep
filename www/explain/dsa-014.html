How do you find the next greater element for every element in an array?

DSA: Lists, Stacks & Queues · concept · levels mid

In one line

Use a monotonic (decreasing) stack of indices. Scanning left to right, while the current value is greater than the value at the top index, pop it and record the current value as its answer, then push the current index. Leftovers get -1. Each index is pushed and popped once, so it is O(n).

Detailed explanation

For each element we want the first element to its right that is strictly larger. The brute force scans right from every element, which is O(n²) for decreasing input.

The insight: elements still waiting for an answer form a decreasing sequence. An element is still waiting only because everything after it so far was smaller or equal, so each waiting element is no larger than the ones waiting below it. When a new value arrives, it resolves all waiting elements smaller than it, and these are exactly the ones on top of the stack. So:

  • While stack is non-empty and nums[i] > nums[stack.peek()]: ans[stack.pop()] = nums[i].
  • stack.push(i).

We store indices, not values, so we know where to write the answer, and so we can compute distances. For "daily temperatures" the answer is i - popped.

Complexity: every index is pushed once and popped at most once, so the total work is O(n) even though there's a nested while loop. Space is O(n) for the stack and answers.

Variants of the same pattern:

  • Next smaller element: use an increasing stack and pop while the current value is smaller.
  • Previous greater: scan right to left, or read the stack top before pushing.
  • Circular array: loop i over 0..2n-1 using i % n, pushing only in the first pass.
  • Stock span, largest rectangle in a histogram, trapping rain water, sum of subarray minimums.

How it works

  1. ans filled with -1, an empty Deque<Integer> stack.
  2. For i in 0..n-1:
  3. While the stack is non-empty and nums[i] > nums[top]: ans[pop] = nums[i].
  4. push(i).
  5. Indices left on the stack have no greater element and keep -1.

Example

public int[] nextGreater(int[] nums) {
    int n = nums.length;
    int[] ans = new int[n];
    Arrays.fill(ans, -1);
    Deque<Integer> stack = new ArrayDeque<>();
    for (int i = 0; i < 2 * n; i++) {               // 2n pass = circular version
        int x = nums[i % n];
        while (!stack.isEmpty() && x > nums[stack.peek()]) ans[stack.pop()] = x;
        if (i < n) stack.push(i);
    }
    return ans;
}
// linear [2,1,2,4,3]   -> [4,2,4,-1,-1]
// circular [2,1,2,4,3] -> [4,2,4,-1,4]

Common mistakes

  • Storing values instead of indices, so you can't place the answer.
  • Using >= versus > incorrectly when duplicates matter ("strictly greater").
  • Believing the nested while makes it O(n²).
  • Pushing indices again in the second pass of the circular version.

How to answer in the interview

"I'd use a monotonic stack of indices whose values are decreasing. Scanning left to right, while the current value is greater than the value at the index on top of the stack, I pop that index and record the current value as its next greater element. Then I push the current index. Whatever remains at the end has no greater element, so it gets minus one. Each index is pushed and popped at most once, so it's O(n) time and O(n) space, despite the inner loop. The same pattern solves daily temperatures, stock span and largest rectangle in a histogram."

Likely follow-up questions

  • Circular array? Iterate twice (i % n) and push only during the first pass.
  • Daily temperatures? The same algorithm, storing i - poppedIndex instead of the value.
  • Largest rectangle in a histogram? An increasing stack. On pop, the width runs from the new top to the current index.
