What do the main HTTP status codes mean? Explain 200, 201, 204, 400, 401, 403, 404, 409, 429, 500, 502 and 503.

REST & API Design · concept · levels entry

In one line

2xx is success (200 OK with body, 201 Created, 204 No Content); 4xx is a client problem (400 bad input, 401 not authenticated, 403 authenticated but not allowed, 404 not found, 409 conflict, 429 rate limited); 5xx is a server problem (500 unexpected error, 502 bad upstream response, 503 temporarily unavailable).

Detailed explanation

Status codes let clients, proxies and monitoring react without parsing the body, so using them correctly matters.

Success

  • 200 OK: request succeeded and the body has the result (GET, or an update returning the resource).
  • 201 Created: a new resource was created, typically from POST; include a Location header with its URI.
  • 204 No Content: success without a body, common for DELETE or updates that return nothing.

Client errors

  • 400 Bad Request: malformed JSON, missing fields, validation failures. Some APIs use 422 Unprocessable Content for syntactically valid but semantically invalid input.
  • 401 Unauthorized: despite the name, it means unauthenticated: no token, expired or invalid credentials. It should include a WWW-Authenticate header.
  • 403 Forbidden: the caller is authenticated but not allowed, for example missing a scope or role.
  • 404 Not Found: the resource does not exist. It is also used to avoid revealing that a resource exists to someone who is not allowed to see it.
  • 409 Conflict: the request conflicts with current state: duplicate unique value, invalid state transition, version clash.
  • 429 Too Many Requests: rate limit exceeded; send Retry-After.

Server errors

  • 500 Internal Server Error: an unexpected bug or unhandled exception. Do not leak stack traces.
  • 502 Bad Gateway: a gateway or proxy received an invalid response from the upstream (crashed service, connection reset).
  • 503 Service Unavailable: the server is temporarily unable to handle requests, overloaded or in maintenance; may include Retry-After.
  • Related: 504 Gateway Timeout when the upstream did not answer in time.

The class tells clients about retries: 4xx usually should not be retried unchanged (except 429 after waiting), while 502, 503 and 504 are typically transient and retryable for idempotent requests.

How it works

  1. Client sends request; server processes.
  2. Outcome mapped to a class: 2xx, 4xx or 5xx.
  3. Specific code plus headers (Location, Retry-After, WWW-Authenticate).
  4. Error body explains details, e.g. Problem Details.

Example

@ExceptionHandler(OrderNotFoundException.class)
ProblemDetail notFound(OrderNotFoundException e) {
    return ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, e.getMessage());
}

@ExceptionHandler(OptimisticLockingFailureException.class)
ProblemDetail conflict() {
    return ProblemDetail.forStatusAndDetail(HttpStatus.CONFLICT, "Order was modified, reload and retry");
}

Common mistakes

  • Returning 200 with an error flag in the body.
  • Using 401 when the user is logged in but lacks permission (should be 403).
  • Returning 500 for validation errors.
  • Confusing 502 (bad response) with 504 (timeout).

How to answer in the interview

"200 is success with a body, 201 means something was created, usually with a Location header, and 204 is success without a body. 400 means the client sent invalid input. 401 is really 'unauthenticated': credentials missing or invalid, whereas 403 means you're authenticated but not allowed. 404 is not found, 409 is a conflict with current state like a duplicate or version clash, and 429 means rate limited, with Retry-After. On the server side, 500 is an unexpected error, 502 means a gateway got a bad response from the upstream, and 503 means the service is temporarily overloaded or down. Generally 4xx shouldn't be retried as-is, while 502 and 503 can be retried with backoff."

Likely follow-up questions

  • Would you return 404 or 403 when a user requests another user's order? Why? Usually 404, so you don't reveal the order exists.
  • 400 or 422 for validation? Either if consistent; 422 separates semantic from syntax errors.
  • What does 504 mean? The gateway timed out waiting for the upstream.
