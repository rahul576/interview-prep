What is a blocking queue?

Collections · concept · levels mid

In one line

A BlockingQueue is a thread-safe queue where put blocks when full and take blocks when empty, with timed offer/poll variants, giving a simple, correct producer-consumer hand-off and, when bounded, natural back-pressure.

Detailed explanation

java.util.concurrent.BlockingQueue<E> extends Queue with operations that wait. Producers and consumers can then coordinate through the queue alone, without writing wait/notify code, and the queue's internal locks and conditions provide the memory visibility guarantees: everything a producer did before put is visible to the consumer after take.

Implementations:

  • ArrayBlockingQueue: bounded, array-based, one lock, optional fairness.
  • LinkedBlockingQueue: linked nodes, optionally bounded (default Integer.MAX_VALUE), separate put and take locks.
  • PriorityBlockingQueue: unbounded, priority-ordered.
  • DelayQueue: elements available only after their delay expires.
  • SynchronousQueue: no capacity; each put waits for a take.
  • LinkedTransferQueue and LinkedBlockingDeque as well.

A bounded queue is the key to stability: when consumers fall behind, producers block (or fail fast with a timed offer) instead of filling the heap. That is back-pressure. Blocking queues also sit at the heart of ThreadPoolExecutor, whose work queue decides whether tasks wait, trigger new threads or get rejected. Blocking methods throw InterruptedException, which is how consumers are cancelled. Nulls are not allowed, because poll uses null to mean "nothing".

How it works

  1. Producer calls put(e); if full, it waits on a "notFull" condition.
  2. Element is enqueued; a waiting consumer is signalled on "notEmpty".
  3. Consumer calls take(); if empty, it waits on "notEmpty".
  4. Element is dequeued; a waiting producer is signalled on "notFull".

Example

BlockingQueue<LogLine> q = new ArrayBlockingQueue<>(5_000);

// producer: fail fast instead of blocking a request thread forever
if (!q.offer(line, 50, TimeUnit.MILLISECONDS)) droppedCounter.increment();

// consumer
while (!Thread.currentThread().isInterrupted()) {
    try {
        LogLine l = q.take();
        writer.write(l);
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
}

Common mistakes

  • Unbounded queues hiding overload until OutOfMemoryError.
  • Swallowing InterruptedException.
  • Mixing put on request threads with slow consumers, causing request stalls.
  • Trying to insert null.

How to answer in the interview

"A BlockingQueue is a thread-safe queue that adds waiting operations: put blocks the producer while the queue is full and take blocks the consumer while it's empty. offer and poll with timeouts wait for a limited time, and the plain versions return immediately. That makes producer-consumer simple and correct without wait and notify. Implementations include ArrayBlockingQueue, LinkedBlockingQueue, PriorityBlockingQueue, DelayQueue and SynchronousQueue. A bounded queue gives natural back-pressure, and thread pool executors use one as their task queue."

Likely follow-up questions

  • Why is bounded safer? It limits memory and forces producers to slow down or fail visibly.
  • Which queue for delayed retries? DelayQueue.
  • How do you drain in batches? drainTo(list, max).
