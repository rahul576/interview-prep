Which Java, Spring Boot, Hibernate, and microservices technologies have you used in your projects?

Project Experience · scenario · levels entry, mid, senior

In one line

Give a structured, honest list tied to real usage: Java version and features, Spring Boot modules (Web, Data JPA, Security, Actuator), Hibernate specifics (mappings, fetching, N+1, locking, migrations), the microservices stack (gateway, config, Kafka, Resilience4j, Docker/Kubernetes) and testing and observability tools.

Detailed explanation

Interviewers ask this to map your experience before drilling in. They are not impressed by a long buzzword list; they want to see you know why you used each tool and can go deep on any of them. Every item you mention is a potential follow-up, so only list what you can explain.

Organise the answer in layers:

  • Java: version (17 or 21) and features used: streams, records, Optional, CompletableFuture, virtual threads where useful.
  • Spring Boot 3: Spring Web (REST controllers, Bean Validation, @ControllerAdvice with ProblemDetail), Spring Data JPA, Spring Security as an OAuth2 resource server validating JWTs, Actuator with Micrometer metrics, caching, scheduling, profiles and configuration properties.
  • Hibernate/JPA: entity relationships and cascading, lazy loading and fixing N+1 with fetch joins, @EntityGraph or batch fetching, optimistic locking with @Version, batch inserts (hibernate.jdbc.batch_size), DTO projections, second-level cache if used, and Flyway or Liquibase for migrations.
  • Microservices: Spring Cloud Gateway, configuration via Kubernetes ConfigMaps/Secrets or Spring Cloud Config, service discovery through Kubernetes DNS or Eureka, Spring Kafka, Resilience4j (circuit breaker, retry, bulkhead), OpenFeign, RestClient or WebClient, Docker, Kubernetes with Helm.
  • Testing: JUnit 5, Mockito, Testcontainers for PostgreSQL and Kafka, @WebMvcTest/@DataJpaTest slices, contract tests.
  • Observability: Prometheus and Grafana, structured logging with correlation ids, OpenTelemetry tracing.

Close with one example of depth, such as an N+1 problem you found, so the interviewer has an easy, strong follow-up.

How it works

  1. Group technologies by layer.
  2. For each, say what you used it for.
  3. Mark depth: "used daily" versus "worked with briefly".
  4. End with a concrete problem you solved.

Example

// N+1 fix I can talk about
@EntityGraph(attributePaths = {"lines", "lines.product"})
@Query("select o from Order o where o.customerId = :cid")
List<Order> findWithLines(Long cid);
spring:
  jpa:
    properties:
      hibernate.jdbc.batch_size: 50

Common mistakes

  • Listing tools you cannot explain.
  • No structure, just a long list.
  • Not distinguishing personal hands-on work from team usage.
  • Outdated stack details (for example claiming Spring Boot 3 with javax.* packages).

How to answer in the interview

"On the Java side I'm on Java 21, using streams, records, Optional, CompletableFuture and virtual threads in one I/O-heavy service. With Spring Boot 3 I build REST APIs with Spring Web and validation, Spring Data JPA, Spring Security as an OAuth2 resource server with JWTs, and Actuator with Micrometer. In Hibernate I handle relationships and lazy loading, fix N+1 queries with fetch joins and entity graphs, use @Version for optimistic locking and batch inserts, and Flyway for migrations. For microservices: Spring Cloud Gateway, Kubernetes ConfigMaps, Spring Kafka, Resilience4j, Docker and Helm. Testing with JUnit 5, Mockito and Testcontainers, and observability with Prometheus, Grafana and OpenTelemetry. For example, I recently fixed an N+1 issue on the order history endpoint."

Likely follow-up questions

  • Can you tell me about an N+1 problem you found and how you fixed it? Describe detection (SQL logs, Hibernate statistics), fix (fetch join/entity graph) and query count before and after.
  • Why Testcontainers over H2? Tests run against the real database engine and its SQL dialect.
  • Feign or WebClient/RestClient? Declarative clients for simple calls; RestClient or WebClient for more control.
