A training job fails with CUDA errors after upgrading the container image. How do you troubleshoot it?

MLOps · scenario · levels mid, senior

In one line

CUDA errors after an image upgrade are almost always a version mismatch between the node's NVIDIA driver, the CUDA runtime in the container and the framework build, or a GPU architecture the new build no longer supports; verify with nvidia-smi and framework checks, then pin a compatible combination.

Detailed explanation

There are three layers. The kernel driver lives on the host node and is exposed into containers by the NVIDIA Container Toolkit or GPU Operator. The CUDA runtime and libraries (cuDNN, NCCL) live in the image. The framework (PyTorch, TensorFlow, JAX) is compiled against a specific CUDA version and for a list of compute capabilities (GPU architectures).

Typical failures:

  • Driver too old: the image moved to a newer CUDA major or minor version than the host driver supports. Errors look like "CUDA driver version is insufficient for CUDA runtime version" or torch.cuda.is_available() returning False. CUDA has minor version compatibility within a major release, but some features need newer drivers, and a new major (for example CUDA 12 to 13) needs a newer driver branch.
  • Framework/CUDA mismatch: a pip wheel built for a different CUDA version, or mixed libraries from conda and pip, causing missing libcudnn or symbol errors.
  • Unsupported architecture: "no kernel image is available for execution on the device" means the build doesn't include kernels for your GPU's compute capability, for example older GPUs dropped from a new release.
  • NCCL issues in multi-GPU jobs after the upgrade.

nvidia-smi inside the container shows the driver version and the maximum CUDA version the driver supports (not what's installed in the image). The framework reports the CUDA version it was built with.

How it works

  1. Read the exact error and compare old and new image tags and changelogs.
  2. Run nvidia-smi in the container: driver version, max CUDA, GPU model.
  3. Run framework checks: CUDA availability, build CUDA version, device capability.
  4. Check the framework's support matrix against driver and GPU.
  5. Fix: use an image matching the driver, upgrade the node driver, or choose a build that supports the architecture.
  6. Pin versions and add a GPU smoke test in CI on each target GPU type.

Example

kubectl exec -it train-pod -- nvidia-smi
kubectl exec -it train-pod -- python - <<'PY'
import torch
print(torch.__version__, torch.version.cuda, torch.backends.cudnn.version())
print(torch.cuda.is_available(), torch.cuda.get_device_name(0), torch.cuda.get_device_capability(0))
print(torch.cuda.get_arch_list())
x = torch.randn(1024, 1024, device="cuda"); print((x @ x).sum().item())
PY

Common mistakes

  • Reading nvidia-smi's CUDA version as the version installed in the container.
  • Installing CUDA toolkits manually on top of framework wheels that bundle their own.
  • Using latest tags for base images.
  • Upgrading images without testing on every GPU type in the fleet.

How to answer in the interview

"After an image upgrade I'd suspect compatibility across three layers: the node driver, the CUDA runtime in the image and the framework build. I'd run nvidia-smi in the container to see the driver and the maximum CUDA it supports, and check torch.version.cuda, is_available and the device capability. Typical causes are a CUDA version newer than the driver, a wheel built for a different CUDA, or a GPU architecture dropped from the new build. The fix is pinning a compatible combination, preferably official framework images, and running a GPU smoke test on each GPU type in CI before rollout."

Likely follow-up questions

  • How do you upgrade GPU drivers without breaking workloads? Roll out via a new node pool or GPU Operator canary, drain gradually, and keep the old pool until jobs pass.
  • What does "no kernel image is available" mean? The build lacks kernels for that GPU's compute capability.
  • Why use official framework images? They ship tested CUDA, cuDNN and NCCL combinations.
