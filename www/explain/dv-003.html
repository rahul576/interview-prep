How do you find files and search text in Linux? Explain find, grep and locate.

Linux · concept · levels entry

In one line

find walks the directory tree and matches files by name, type, size, owner or time; grep searches text inside files with patterns; locate queries a prebuilt index for fast name lookups; combine them with pipes, -exec and xargs.

Detailed explanation

find inspects the live filesystem, so it is always accurate but can be slow on huge trees. Its tests include -name and -iname (glob patterns, quoted so the shell does not expand them), -type f or d, -size +1G, -mtime -1 (modified within the last day) or -mmin -30, -user, -perm. You can limit depth with -maxdepth and stay on one filesystem with -xdev. It can act on results: -delete, -exec cmd {} \; (once per file) or -exec cmd {} + (batched, much faster).

grep searches file contents line by line. Key flags: -r recursive, -i ignore case, -n line numbers, -v invert, -l list only filenames, -c count, -w whole words, -E extended regular expressions, -F fixed strings, and -A/-B/-C for context lines. --include='*.log' restricts which files are searched. ripgrep (rg) is a popular faster alternative that respects .gitignore.

locate (often plocate or mlocate) searches a database of file paths built by updatedb, usually nightly from a timer. It returns results almost instantly, but files created after the last update are missing and deleted files may still appear, and it may not be installed on minimal servers or containers.

Combining them is the real skill: find to select files, xargs or -exec to run grep on them, and -print0 with xargs -0 so filenames with spaces do not break the pipeline.

How it works

  1. Decide: search by file attributes (find), by content (grep) or by name fast (locate).
  2. find evaluates tests left to right per file and prints or acts on matches.
  3. grep reads each file and prints matching lines.
  4. locate looks up names in the updatedb database.
  5. Pipes and xargs connect them safely.

Example

find /var/log -name "*.log" -mtime -1                 # logs changed in the last day
find / -xdev -type f -size +1G -mtime -7 2>/dev/null  # >1 GB, modified this week
grep -rn "ERROR" /var/log/app --include='*.log'
grep -rli "timeout" /etc/nginx/
find . -name "*.yaml" -print0 | xargs -0 grep -l "image: nginx"
sudo updatedb && locate sshd_config

Common mistakes

  • Unquoted patterns like find . -name *.log, expanded by the shell first.
  • Using -exec ... \; for thousands of files instead of +.
  • Trusting locate for files created minutes ago.
  • Piping find to xargs without -print0/-0 and breaking on spaces.

How to answer in the interview

"find walks the directory tree and matches by name, type, size, owner or modification time, for example find /var/log -name '*.log' -mtime -1 for logs changed in the last day, and it can act on results with -exec or by piping to xargs. grep searches text inside files: -r for recursive, -i to ignore case, -n for line numbers, -v to invert, so grep -rn ERROR finds errors with line numbers. locate is much faster because it uses a database built by updatedb, but it can be out of date. Combining them with pipes is a daily skill."

Likely follow-up questions

  • How would you find all files larger than 1 GB modified in the last week? find / -xdev -type f -size +1G -mtime -7.
  • Difference between -exec {} \; and {} +? One process per file versus batching many files per command.
  • How do you search compressed logs? zgrep or zcat file.gz | grep.
