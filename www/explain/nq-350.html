What are an MCP host, client, and server?

AI/ML & GenAI · concept · levels mid

In one line

The host is the user-facing AI application that runs or calls the model and coordinates connections; the client is the protocol connector the host creates for exactly one server; the server is a program wrapping a system (GitHub, a database, an API) that exposes tools, resources and prompts, running locally over stdio or remotely over HTTP.

Detailed explanation

Host: what the user sees, such as a desktop chat assistant, an IDE with an AI agent, a CLI coding agent or your own chatbot. Responsibilities: managing the conversation and the model, choosing which servers are enabled, creating clients, merging tool lists into the model context, and enforcing permissions and approvals before tools run.

Client: lives inside the host process; one client per server connection. It speaks MCP: runs the initialisation handshake, lists tools and resources, sends tools/call and resources/read requests, receives notifications and handles reconnection. It also keeps servers isolated, so one server cannot see another's data.

Server: a separate, usually lightweight program focused on one system. A GitHub server might expose create_issue and search_code tools; a PostgreSQL server might expose a read-only query tool and table schemas as resources. Servers can be:

  • Local, launched by the host as a subprocess and communicating over stdio, often with access to local files or CLI credentials.
  • Remote, hosted as a web service over Streamable HTTP, with OAuth-based authorisation, shared by many users.

Mapping example: a desktop assistant is the host; it creates one client for a GitHub server and another for a Postgres server; when the user asks to file a bug, the model chooses create_issue, the host asks for approval, and the GitHub client sends the call.

How it works

  1. User configures servers in the host.
  2. Host creates one client per server.
  3. Each client connects and negotiates capabilities.
  4. Host presents combined tools to the model.
  5. Model requests a tool; host approves; the relevant client calls its server.

Example

Host: IDE agent

Common mistakes

  • Calling the server "the AI"; the server has no model.
  • Assuming one client serves several servers.
  • Running local servers with the user's full credentials unnecessarily.

How to answer in the interview

"The host is the AI application the user interacts with, for example a desktop assistant, an IDE agent or our own chatbot. It runs or calls the model, decides which servers are connected and enforces permissions. The client lives inside the host; the host creates one client per server, and it speaks the protocol: handshake, listing tools, sending calls. The server is a separate program wrapping a system like GitHub or a database, exposing tools, resources and prompts, either locally over stdio or remotely over HTTP. So the host creates a client for the GitHub server, and the model can call its create_issue tool."

Likely follow-up questions

  • Can one application be both client and server? Yes, for example a gateway or agent that consumes servers and exposes its own capabilities.
  • Does the server need an LLM? No; it can request one through sampling.
  • Local or remote? Local for developer tools and files; remote for shared, centrally governed services.
