What is Route 53, and what are the common DNS record types?

Cloud (AWS) · concept · levels entry

In one line

Route 53 is AWS's managed DNS, domain registration and health-checking service; common records are A/AAAA (name to IPv4/IPv6), CNAME (name to another name, not at the apex), alias (AWS-specific pointer to AWS resources, works at the apex), MX, TXT and NS.

Detailed explanation

DNS translates names like shop.example.com into IP addresses. Route 53 hosts your DNS zones on a global anycast network with a 100% availability SLA. A public hosted zone answers queries from the internet; a private hosted zone answers only inside associated VPCs, useful for internal names like db.internal.example.com. Route 53 can also register domains.

Record types: A maps a name to IPv4 addresses, AAAA to IPv6. CNAME maps a name to another name (www -> shop.example.net); the DNS standard forbids a CNAME at the zone apex (example.com) because the apex must hold SOA and NS records. MX lists mail servers with priorities. TXT holds text such as domain verification, SPF and DKIM/DMARC settings. NS lists the authoritative name servers; to delegate a domain or subdomain you set NS records at the parent. SOA holds zone metadata, and CAA limits which certificate authorities may issue certificates.

Alias records are a Route 53 extension. They look like A or AAAA records to clients, but point to an AWS resource: an ALB or NLB, CloudFront distribution, API Gateway, S3 website endpoint, or another record in the zone. Route 53 resolves the target's current IPs itself, so they work at the apex, follow IP changes automatically and queries to AWS targets are free.

Routing policies add intelligence: simple, weighted (canary splits), latency-based, failover with health checks, geolocation, geoproximity and multivalue answer. TTL controls how long resolvers cache answers; lower it before migrations.

How it works

  1. Register or delegate the domain to the hosted zone's NS servers.
  2. Create records in the hosted zone.
  3. Resolvers query Route 53 and cache answers for the TTL.
  4. Alias records resolve to the AWS resource's current IPs.
  5. Health checks and routing policies decide which answer to return.

Example

aws route53 change-resource-record-sets --hosted-zone-id Z123EXAMPLE \
  --change-batch '{
    "Changes": [{
      "Action": "UPSERT",
      "ResourceRecordSet": {
        "Name": "example.com",
        "Type": "A",
        "AliasTarget": {
          "HostedZoneId": "Z32O12XQLNTSW2",
          "DNSName": "my-alb-123456.eu-west-1.elb.amazonaws.com",
          "EvaluateTargetHealth": true
        }
      }
    }]
  }'

example.com is an alias A record to the ALB, www is a CNAME to example.com, MX points to the mail provider, and a TXT record holds SPF.

Common mistakes

  • Trying to create a CNAME at the zone apex.
  • Pointing an A record at a load balancer IP, which changes.
  • High TTLs before a migration, so changes take hours.
  • Forgetting to update NS records at the registrar.

How to answer in the interview

"Route 53 is AWS's managed DNS service; it also registers domains and runs health checks for routing. A records map names to IPv4 and AAAA to IPv6; a CNAME maps a name to another name but can't be used at the apex like example.com. Route 53 adds alias records, which point straight to AWS resources like an ALB or CloudFront, work at the apex, follow IP changes and are free to query. Other common types are MX for mail, TXT for verification and SPF, and NS for delegation. Hosted zones can be public or private to a VPC, and routing policies like weighted, latency and failover add traffic control."

Likely follow-up questions

  • Why alias over CNAME for an ALB? Works at the apex, no extra lookup, free queries, follows IP changes.
  • How do you do DNS failover? Failover routing policy with health checks on the primary.
  • What is TTL and why lower it? Cache duration; lower it before changes so clients pick up new answers quickly.
