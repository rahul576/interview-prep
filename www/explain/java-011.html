What is a functional interface, and how do lambdas and method references relate to it?

Java 8+ Features · concept · levels entry, mid

In one line

A functional interface has exactly one abstract method (a SAM type); lambdas and method references are concise ways to provide that single method's implementation, and @FunctionalInterface asks the compiler to enforce the rule.

Detailed explanation

Java has no standalone function types. Instead, a lambda always has a target type, which must be a functional interface. Because the interface has only one abstract method, the compiler knows exactly which method the lambda implements and checks that parameter and return types match. Functional interfaces may still declare any number of default and static methods, and abstract methods that redeclare public Object methods such as equals do not count; that is why Comparator qualifies.

The optional @FunctionalInterface annotation documents intent and makes the compiler fail if the interface ever gains a second abstract method. The java.util.function package (Java 8) provides standard shapes: Function<T,R>, BiFunction, Predicate<T>, Supplier<T>, Consumer<T>, UnaryOperator<T>, BinaryOperator<T> plus primitive specialisations like IntPredicate. Older interfaces such as Runnable, Callable and Comparator are also functional.

A lambda expression (x -> x * 2) is an inline implementation. A method reference (String::toUpperCase) is shorthand for a lambda that only calls an existing method. Lambdas can capture local variables only if they are effectively final.

How it works

  1. Define or choose an interface with one abstract method.
  2. Write a lambda or method reference where that interface type is expected.
  3. The compiler infers parameter types from the target type and checks compatibility.
  4. At runtime, invokedynamic and LambdaMetafactory create an instance implementing the interface.
  5. Calling the interface method executes the lambda body.

Example

@FunctionalInterface
interface PriceRule {
    BigDecimal apply(BigDecimal price);
    default PriceRule then(PriceRule next) { return p -> next.apply(apply(p)); }
}

PriceRule discount = p -> p.multiply(new BigDecimal("0.90"));
PriceRule round    = p -> p.setScale(2, RoundingMode.HALF_UP);
BigDecimal result  = discount.then(round).apply(new BigDecimal("19.99")); // 17.99

Function<String, String> upper = String::toUpperCase;   // method reference
Predicate<String> blank = String::isBlank;
Supplier<List<String>> listFactory = ArrayList::new;

Common mistakes

  • Thinking default methods disqualify an interface from being functional.
  • Believing @FunctionalInterface is required for lambdas to work.
  • Writing custom interfaces when a standard java.util.function type fits.
  • Modifying captured local variables inside a lambda (compile error).

How to answer in the interview

"A functional interface has exactly one abstract method, a SAM type, though it can have default and static methods. The @FunctionalInterface annotation is optional but makes the compiler enforce that. Java ships common ones in java.util.function: Function, Predicate, Supplier, Consumer, UnaryOperator and BiFunction, and Runnable, Callable and Comparator are functional too. A lambda is just a concise implementation of that single method, and a method reference like String::toUpperCase is shorthand for a lambda that calls an existing method. The interface is the lambda's target type."

Likely follow-up questions

  • What does "effectively final" mean? A local variable never reassigned after initialisation, so a lambda may capture it.
  • Is Comparator functional despite many methods? Yes, only compare is abstract; equals overrides an Object method.
  • Can you create a lambda without a target type? No, Object o = () -> {} fails without a cast to a functional interface.
