How can you determine whether two strings are anagrams?

DSA: Arrays & Strings · scenario · levels entry

In one line

First compare lengths; then either sort both character arrays and compare (O(n log n)) or count character frequencies with an int[26] or HashMap in one pass (O(n) time).

Detailed explanation

Step 0: normalise. If the problem ignores case or spaces, lowercase and remove them first, because that changes the lengths.

Step 1: length check. Strings of different lengths cannot be anagrams. This O(1) check avoids all further work in many cases.

Approach A: sort and compare. Convert both strings with toCharArray(), sort with Arrays.sort, and compare with Arrays.equals. It is short, obviously correct and works for any char values. Time O(n log n), space O(n) for the arrays (strings are immutable, so copies are needed anyway).

Approach B: frequency counting. For lowercase English letters, use an int[26]. Walk both strings together: increment for each character of the first, decrement for the second. If every count ends at zero, they are anagrams. Time O(n), extra space O(1) (a fixed 26 or 128 slots). A slight variant counts the first string and decrements while scanning the second, returning false as soon as a count goes negative, which exits early.

Approach C: HashMap counts for Unicode or arbitrary characters: Map<Integer, Integer> keyed by code point (to handle emojis and other supplementary characters correctly), using merge(cp, 1, Integer::sum). Still O(n) but with higher constants due to boxing and hashing.

Which to choose: counting is asymptotically best and is what interviewers usually want for "optimal"; sorting is simpler and perfectly fine for short strings. For very long strings or high volumes, counting wins clearly.

How it works

  1. Normalise both strings.
  2. If lengths differ, return false.
  3. Increment counts for string A, decrement for string B.
  4. Verify all counts are zero (or stop early on a negative).
  5. Return the result.

Example

// Sorting: O(n log n)
static boolean anagramSort(String a, String b) {
    if (a.length() != b.length()) return false;
    char[] x = a.toCharArray(), y = b.toCharArray();
    Arrays.sort(x); Arrays.sort(y);
    return Arrays.equals(x, y);
}

// Counting: O(n), lowercase a–z
static boolean anagramCount(String a, String b) {
    if (a.length() != b.length()) return false;
    int[] c = new int[26];
    for (int i = 0; i < a.length(); i++) c[a.charAt(i) - 'a']++;
    for (int i = 0; i < b.length(); i++) if (--c[b.charAt(i) - 'a'] < 0) return false;
    return true;
}

// Unicode-safe
static boolean anagramUnicode(String a, String b) {
    Map<Integer, Integer> m = new HashMap<>();
    a.codePoints().forEach(cp -> m.merge(cp, 1, Integer::sum));
    b.codePoints().forEach(cp -> m.merge(cp, -1, Integer::sum));
    return m.values().stream().allMatch(v -> v == 0);
}

Common mistakes

  • Skipping the length check.
  • Using int[26] with uppercase letters or spaces (index out of bounds).
  • Comparing sorted arrays with == instead of Arrays.equals.
  • Ignoring surrogate pairs for emoji or some scripts.

How to answer in the interview

"First I check the lengths; if they differ they can't be anagrams. Then I can sort both: convert to char arrays, Arrays.sort them and compare with Arrays.equals, which is O(n log n). Or I count frequencies in one pass: for lowercase English letters, an int[26], incrementing for the first string and decrementing for the second, then check all counts are zero. That's O(n) time and O(1) extra space. For Unicode I'd use a HashMap keyed by code point. And I'd normalise case and spaces first if the problem says so."

Likely follow-up questions

  • Which approach for very long strings? Counting, O(n) with a fixed array.
  • What if the character set is huge? Use a HashMap of code points.
  • Can you do it without extra space? Sorting in place, if mutating copies is allowed; Java strings themselves are immutable.
