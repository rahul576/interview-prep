Data transfer and NAT gateway charges are a large part of your AWS bill. How do you reduce them?

Cloud (AWS) · scenario · levels senior

In one line

Find the top talkers with Cost Explorer usage types and VPC flow logs, then remove NAT traffic with gateway endpoints (S3, DynamoDB) and interface endpoints (ECR, CloudWatch, STS), keep traffic within an AZ with topology-aware routing, serve internet egress through CloudFront, and compress and cache data.

Detailed explanation

Diagnose before fixing. In Cost Explorer group by usage type: NatGateway-Bytes (NAT processing, charged per GB on top of hourly fees), DataTransfer-Regional-Bytes (cross-AZ, charged in both directions), inter-region transfer and DataTransfer-Out-Bytes (internet egress). Then use VPC flow logs with Athena or CloudWatch Logs Insights, or NAT gateway CloudWatch metrics, to identify which source IPs, workloads and destinations generate the bytes.

NAT costs typically come from workloads in private subnets talking to AWS services through NAT: pulling container images from ECR (image layers are stored in S3), shipping logs and metrics to CloudWatch, reading and writing S3, calling STS, SQS or Secrets Manager. Gateway endpoints for S3 and DynamoDB are free and remove that traffic from NAT entirely. Interface endpoints for ECR (api and dkr), CloudWatch Logs, STS, SQS and others cost per hour per AZ plus a small per-GB fee, but are much cheaper than NAT processing at volume. Also cache images (pull-through cache, larger nodes, image streaming) and check for workloads repeatedly downloading the same data from the internet.

Cross-AZ costs come from chatty microservices, load balancers sending traffic across zones, Kafka brokers and consumers or database replicas in other AZs. Fixes include Kubernetes topology-aware routing or traffic distribution preferences, zone-aware clients (Kafka rack awareness with follower fetching), disabling cross-zone load balancing where safe, and co-locating chatty services, balanced against resilience.

Internet egress is cheaper and faster through CloudFront, which also has no charge for origin fetches from AWS origins. Compression, efficient formats and caching reduce volume across the board.

How it works

  1. Break down the bill by data transfer usage type.
  2. Map bytes to workloads with flow logs and NAT metrics.
  3. Add gateway endpoints and route tables for S3 and DynamoDB.
  4. Add interface endpoints for the heaviest AWS APIs.
  5. Localise cross-AZ traffic and push egress through CloudFront.
  6. Re-measure and set budgets on data transfer usage types.

Example

aws ec2 create-vpc-endpoint --vpc-id vpc-123 --vpc-endpoint-type Gateway \
  --service-name com.amazonaws.eu-west-1.s3 --route-table-ids rtb-a rtb-b rtb-c

for svc in ecr.api ecr.dkr logs sts; do
  aws ec2 create-vpc-endpoint --vpc-id vpc-123 --vpc-endpoint-type Interface \
    --service-name com.amazonaws.eu-west-1.$svc --private-dns-enabled \
    --subnet-ids subnet-a subnet-b subnet-c --security-group-ids sg-endpoints
done
SELECT srcaddr, dstaddr, SUM(bytes)/1e9 AS gb
FROM vpc_flow_logs
WHERE interface_id = 'eni-natgw123' AND day = '2026/11/20'
GROUP BY srcaddr, dstaddr ORDER BY gb DESC LIMIT 20;

Common mistakes

  • Guessing instead of measuring, then optimising the wrong flow.
  • Adding interface endpoints for tiny traffic where hourly fees exceed savings.
  • Forgetting cross-AZ traffic is billed on both sides.
  • Breaking resilience by pinning everything to one AZ.

How to answer in the interview

"First I find the source: Cost Explorer by usage type separates NAT processing, cross-AZ, inter-region and internet egress, and VPC flow logs show which workloads generate it. Large NAT bills usually come from pulling images and sending logs or objects to AWS services through NAT, so I add free gateway endpoints for S3 and DynamoDB and interface endpoints for ECR, CloudWatch and STS. Cross-AZ charges come from chatty services, Kafka or replicas in other zones, which topology-aware routing and zone-aware clients reduce. Internet egress goes through CloudFront, plus compression and caching."

Likely follow-up questions

  • Why can a busy Kubernetes cluster generate surprising cross-AZ costs? Services load-balance randomly across pods in all AZs, so most calls cross zones.
  • Are gateway endpoints really free? Yes, no hourly or per-GB charges for S3 and DynamoDB gateway endpoints.
  • How do you prevent regressions? Budgets and anomaly detection on data transfer usage types.
