What do soft delete and purge protection mean for Azure Key Vault, and how do you rotate secrets and keys?

Azure · concept · levels entry, mid, senior

In one line

Soft delete (always on) keeps deleted vaults and objects recoverable for 7-90 days; purge protection stops anyone permanently purging them before that period ends; rotate with key rotation policies, certificate auto-renewal and Event Grid near-expiry events driving automation, while apps reference versionless secrets so they pick up new values.

Detailed explanation

Soft delete is mandatory on Key Vault. When a vault, key, secret or certificate is deleted, it moves to a deleted state for the configured retention (7 to 90 days, default 90) and can be recovered with its versions. The name stays reserved during that time, which surprises teams that delete and recreate a vault with the same name in IaC.

Purge protection is optional but cannot be disabled once enabled. Without it, someone with purge permission can permanently destroy deleted objects immediately. With it, nobody, including a Global Administrator or an attacker with stolen credentials, can purge before retention ends. It is required for customer-managed keys used by Storage, SQL TDE, Disk Encryption Sets and others, because losing the key makes the encrypted data unrecoverable.

Rotation:

  • Keys: a rotation policy (for example rotate 30 days before expiry, expire after one year) creates new key versions automatically; services using versionless key URIs adopt them.
  • Certificates: issued by integrated CAs (DigiCert, GlobalSign) or self-signed can auto-renew at a set percentage of lifetime.
  • Secrets: Key Vault cannot know how to change a database password, so it publishes SecretNearExpiry and SecretExpired events to Event Grid; a Function generates the new credential, updates the target system and writes a new secret version. A dual-credential pattern (two passwords or two storage keys, alternating) avoids downtime.

Apps should reference the secret without a version: App Service Key Vault references refresh periodically, the AKS Secrets Store CSI driver supports rotation polling, and SDK clients can re-read on failure. Use the Azure RBAC permission model (not legacy access policies), private endpoints with public access disabled, and diagnostic logs.

How it works

  1. Create vault with RBAC model, purge protection and private endpoint.
  2. Set expiry dates on secrets and rotation policies on keys.
  3. Subscribe a Function to near-expiry events via Event Grid.
  4. Function rotates the credential using the alternate-credential pattern.
  5. Apps reference versionless secrets and refresh.
  6. Alert on failed rotations and on purge attempts.

Example

az keyvault create -n kv-orders-prod -g rg-orders --enable-rbac-authorization true \
  --enable-purge-protection true --retention-days 90 --public-network-access Disabled
az keyvault key rotation-policy update --vault-name kv-orders-prod -n cmk-storage \
  --value '{"lifetimeActions":[{"trigger":{"timeBeforeExpiry":"P30D"},"action":{"type":"Rotate"}}],
            "attributes":{"expiryTime":"P1Y"}}'
# App Service setting: @Microsoft.KeyVault(SecretUri=https://kv-orders-prod.vault.azure.net/secrets/SqlPassword/)

Common mistakes

  • Pinning secret versions in app settings, so rotations are ignored.
  • Rotating a password in one step and breaking running apps.
  • Expecting to recreate a deleted vault name immediately.
  • Leaving vaults on access policies with broad "get/list all".

How to answer in the interview

"Soft delete is always on: deleted vaults and objects stay recoverable for seven to ninety days. Purge protection makes sure nobody, not even an admin or an attacker, can permanently purge them before that, which is mandatory for customer-managed encryption keys. For rotation, keys use rotation policies, certificates auto-renew with integrated CAs, and for secrets, Event Grid near-expiry events trigger a Function that creates a new credential, updates the target and stores a new version. Apps reference secrets without a version, so they pick up the new value, and I use the RBAC model and private endpoints."

Likely follow-up questions

  • Rotate a DB password without downtime? Two credentials; update the inactive one, switch apps, then rotate the other.
  • Can purge protection be turned off? No, once enabled it is permanent.
  • Managed identity instead? Best of all: Entra auth to the database removes the password.
