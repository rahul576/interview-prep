What is G1 GC?

JVM & Performance · concept · levels mid, senior

In one line

G1 (Garbage First), the default collector since Java 9, divides the heap into equal-sized regions (typically 1-32 MB) tagged eden, survivor, old or humongous, runs young collections, concurrent marking and mixed collections that evacuate the old regions with the most garbage first, compacting by evacuation, all sized to a pause goal (MaxGCPauseMillis, default 200 ms).

Detailed explanation

Regions. Instead of fixed contiguous generations, the heap is a grid of around 2,048 regions of the same size, a power of two chosen from the heap size. Each region's role changes over time. This flexibility lets G1 resize the young generation every cycle and collect any chosen set of regions, the collection set.

Young collections. When the eden regions fill, G1 pauses the application and, with many parallel threads, evacuates live objects from eden and survivor regions into fresh survivor or old regions. Evacuated regions become free. G1 picks the number of eden regions so that the predicted pause fits the goal.

Concurrent marking. When old-generation occupancy crosses the Initiating Heap Occupancy Percent (adaptive, initially 45%), G1 starts a cycle: an initial mark during a young pause, concurrent marking of the whole heap while the application runs, a short remark pause, and a cleanup that immediately frees regions with no live data. Marking produces liveness statistics per region.

Mixed collections. In the following pauses, G1 adds to the young regions a selection of old regions with the least live data (most garbage): they are cheapest to evacuate and free the most memory per millisecond. That is the "garbage first" idea. Evacuation copies live objects together, so compaction happens naturally, without a separate phase.

Humongous objects. Objects of at least half a region are allocated in contiguous humongous regions. They are expensive and can waste space; frequent big arrays may trigger marking cycles and evacuation failures. Humongous objects that die young can be eagerly reclaimed during young pauses.

Supporting structures. Remembered sets per region and a card table track cross-region references, maintained by write barriers, so regions can be collected independently.

Fallback. If there are no free regions for evacuation, G1 performs a (parallel) full GC, a long pause to avoid through headroom and lower allocation. G1 suits heaps from a few GB to tens of GB with a balance of throughput and latency.

How it works

  1. Allocation fills eden regions.
  2. Young pause evacuates live young objects.
  3. Old occupancy passes IHOP: concurrent marking computes per-region liveness.
  4. Remark and cleanup pauses; empty regions freed.
  5. Mixed pauses evacuate young plus garbage-rich old regions.
  6. Cycle repeats; full GC only on failure.

Example

java -XX:+UseG1GC -Xms8g -Xmx8g \
     -XX:MaxGCPauseMillis=150 \
     -XX:G1HeapRegionSize=16m \
     -Xlog:gc*:file=gc.log:time,uptime -jar api.jar

Common mistakes

  • Fixing the young size with -Xmn, which overrides G1's pause-driven sizing.
  • Setting an unrealistic pause goal like 10 ms.
  • Ignoring humongous allocations in logs.
  • Assuming G1 never runs a full GC.

How to answer in the interview

"G1, Garbage First, is the default collector since Java 9. It divides the heap into many equal regions, typically 1 to 32 MB, each acting as eden, survivor, old or humongous for very large objects. Young collections evacuate live objects from young regions. When the heap fills, G1 runs concurrent marking alongside the application to learn how much live data each old region has, then mixed collections evacuate young regions plus the old regions with the most garbage first, hence the name. Copying live objects out compacts memory as a side effect. I set a goal with MaxGCPauseMillis, 200 ms by default, and G1 sizes its work to meet it. It balances throughput and latency for heaps from a few to tens of gigabytes."

Likely follow-up questions

  • What are humongous objects and why can they be a problem? Objects of at least half a region placed in contiguous humongous regions; they waste space, trigger marking early and can cause evacuation failures.
  • What is a collection set? The set of regions G1 chooses to evacuate in a given pause.
  • When would you move from G1 to ZGC? When pause times still violate latency targets after reducing allocation and tuning.
