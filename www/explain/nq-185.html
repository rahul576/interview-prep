What is the role of Spring Framework 6 in modern Java applications?

Spring Framework · concept · levels mid, senior

In one line

Spring Framework 6 (2022) is the foundation of Spring Boot 3: it raised the baseline to Java 17 and **Jakarta EE 9+ (jakarta.), added AOT processing for GraalVM native images, Micrometer Observation, HTTP interface clients and RestClient, RFC 7807/9457 Problem Details, and virtual thread* support in 6.1; Spring Framework 7 continues on that baseline.

Detailed explanation

Spring Framework 6 was a generational release that modernised Spring for current Java and cloud deployment.

Baseline and Jakarta. It requires Java 17+ and moved from Java EE javax. packages to *Jakarta EE 9+ jakarta.* (Servlet, Persistence, Validation, Annotation). This rename is the main migration effort when upgrading to Boot 3: imports change, and every library you use must have a Jakarta-compatible version (for example Hibernate 6).

AOT and native images. A new ahead-of-time engine analyses the application context at build time and generates code and reflection hints, so applications can be compiled into GraalVM native images that start in tens of milliseconds with low memory, good for serverless and scale-to-zero.

Observability. The Micrometer Observation API instruments Spring MVC, WebFlux, RestTemplate/RestClient, JDBC and messaging once and feeds both metrics and distributed tracing (Micrometer Tracing with OpenTelemetry or Brave), replacing Spring Cloud Sleuth.

HTTP and errors. Declarative HTTP interface clients with @HttpExchange, and from 6.1 the fluent synchronous RestClient. Problem Details (RFC 7807, now superseded by RFC 9457) via ProblemDetail and ErrorResponse give standard JSON error bodies.

Concurrency. Version 6.1 added support for virtual threads (Java 21) and Boot 3.2 enables them with spring.threads.virtual.enabled=true. 6.1 also added CRaC support for checkpoint/restore.

In late 2025 Spring Framework 7 / Spring Boot 4 followed, keeping Java 17 as the minimum and building on these features, so knowledge of 6 remains directly relevant.

How it works

  1. Upgrade the JDK to 17 or 21.
  2. Move to Boot 3.x, which brings Framework 6 and Jakarta-based dependencies.
  3. Replace javax. imports with jakarta. (OpenRewrite recipes automate this).
  4. Adopt RestClient or HTTP interfaces, ProblemDetail, observation.
  5. Optionally build native images with the AOT plugin.

Example

@HttpExchange("/customers")
interface CustomerClient {
    @GetExchange("/{id}")
    Customer get(@PathVariable long id);
}

@Bean
CustomerClient customerClient(RestClient.Builder b) {
    RestClient rc = b.baseUrl("https://crm.internal").build();
    return HttpServiceProxyFactory.builderFor(RestClientAdapter.create(rc))
            .build().createClient(CustomerClient.class);
}

@ExceptionHandler(CustomerNotFound.class)
ProblemDetail notFound(CustomerNotFound e) {
    return ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, e.getMessage());
}

Common mistakes

  • Upgrading Spring but keeping libraries that still depend on javax.*.
  • Expecting native images to work without reflection hints for dynamic code.
  • Confusing Framework versions with Boot versions (Boot 3 = Framework 6).
  • Assuming virtual threads speed up CPU-bound code.

How to answer in the interview

"Spring Framework 6 is the foundation of Spring Boot 3. It raised the baseline to Java 17 and moved from javax to jakarta packages, which was the main migration work. It introduced AOT processing so apps can become GraalVM native images with fast startup, built-in observability through Micrometer Observation for metrics and tracing, declarative HTTP interface clients and later RestClient, Problem Details for standard errors, and virtual thread support in 6.1. Spring Framework 7 and Boot 4 now build on the same baseline."

Likely follow-up questions

  • What changed when migrating to Boot 3? javax to jakarta, Java 17, Hibernate 6, Sleuth replaced by Micrometer Tracing, property renames.
  • Native image downsides? Long builds, closed-world assumptions, reflection hints.
  • RestClient vs WebClient? RestClient is synchronous and blocking; WebClient is reactive.
