What are Atlantis and Terraform Cloud/HCP Terraform used for?

Infrastructure as Code · concept · levels mid

In one line

Both automate Terraform pull-request workflows: Atlantis is self-hosted open source that comments plan/apply on PRs with project locks; HCP Terraform (formerly Terraform Cloud) is HashiCorp's service offering remote runs, state, workspaces, private registry, Sentinel/OPA policies, drift detection and audit history.

Detailed explanation

Running Terraform from laptops does not scale: credentials are spread around, nobody sees what was applied, and two people can apply conflicting changes.

Atlantis is an open-source server you host yourself (on Kubernetes, ECS or a VM). It receives webhooks from GitHub, GitLab, Bitbucket or Azure DevOps. When a PR changes Terraform code, it runs plan for the affected projects (defined in atlantis.yaml or auto-detected) and posts the output as a comment. After approval, a reviewer comments atlantis apply, and Atlantis applies and comments the result. Locks per project prevent two PRs from modifying the same state concurrently, and apply requirements such as approved and mergeable enforce review. Custom workflows can add Conftest policy checks, Infracost or Terragrunt. You own its operations and security.

HCP Terraform (and its self-hosted edition Terraform Enterprise) is a managed platform. Workspaces hold state, variables (including sensitive ones), team permissions and run history. Runs execute remotely on HashiCorp-managed or self-hosted agents, triggered by VCS, CLI or API. It provides a private module and provider registry, policy as code with Sentinel or OPA, cost estimation, run tasks integrating third-party scanners, drift detection and health assessments, dynamic provider credentials via OIDC, and audit trails. Pricing is usage-based, so cost at scale is a consideration, and some features are limited to higher tiers. Alternatives in the same space include Spacelift, env0, Scalr and Terrateam.

Both keep cloud credentials off developer machines and give a consistent, reviewable apply process.

How it works

  1. Developer opens a PR changing Terraform code.
  2. Webhook triggers a plan (Atlantis server or HCP Terraform run).
  3. Plan and policy results appear on the PR.
  4. Approval, then apply via comment (Atlantis) or confirm/merge (HCP Terraform).
  5. State, locks and history are kept centrally.

Example

# atlantis.yaml
version: 3
projects:
  - name: network-prod
    dir: envs/prod/network
    autoplan:
      when_modified: ["*.tf", "../../modules/network/**/*.tf"]
    apply_requirements: [approved, mergeable]
    workflow: with-policy
workflows:
  with-policy:
    plan:
      steps:
        - init
        - plan
        - run: terraform show -json $PLANFILE > plan.json && conftest test plan.json
# HCP Terraform via the cloud block
terraform {
  cloud {
    organization = "acme"
    workspaces { name = "network-prod" }
  }
}

Common mistakes

  • Letting anyone comment atlantis apply without approval requirements.
  • Giving the Atlantis server admin credentials for every account.
  • Assuming plans are harmless; they can execute code.
  • Ignoring HCP Terraform per-resource pricing at scale.

How to answer in the interview

"Both automate Terraform around pull requests. Atlantis is open source and self-hosted: when a PR changes Terraform it runs plan and posts the result as a comment, and an approved reviewer comments atlantis apply, with locks so two PRs can't change the same project at once. HCP Terraform, formerly Terraform Cloud, is HashiCorp's service: remote plans and applies, managed state, workspaces with variables and team permissions, a private registry, Sentinel or OPA policies, cost estimation, drift detection and full run history. Either way, credentials stay off developer machines and applies are consistent and reviewable."

Likely follow-up questions

  • What are the security considerations of self-hosting Atlantis? It holds powerful credentials, and a malicious PR can run code during plan (external data sources, local-exec, malicious providers); restrict repos, verify webhook secrets, use per-environment roles and approval requirements.
  • Can HCP Terraform run in private networks? Yes, via self-hosted agents.
  • How do you migrate state to HCP Terraform? Add the cloud block and run terraform init to migrate.
