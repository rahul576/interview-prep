Design a recommendation system for a streaming service like Netflix.

AI & ML System Design · design · levels senior, lead

In one line

Recommendations run as a funnel: candidate generation (collaborative filtering, embeddings + ANN search, trending) narrows millions to hundreds, a ranking model scores them with rich features from a feature store, then re-ranking adds diversity and rules; results are partly precomputed and measured with A/B tests.

Detailed explanation

Scoring every title for every user on each request is too expensive, so stages trade precision for speed:

  1. Candidate generation (recall): several cheap sources: two-tower embedding models (user tower and item tower) with approximate nearest neighbour search (FAISS, ScaNN, vector DBs); "because you watched X" item similarity; trending in your region; continue watching.
  2. Ranking (precision): a heavier model (gradient-boosted trees or deep networks) predicts probability of play/completion using user history, item metadata, context (device, time of day), and real-time signals (what was just watched).
  3. Re-ranking: diversity (not ten thrillers), freshness, business rules (licensing, maturity ratings), de-duplication, row/page layout.

The feature store (Feast, Tecton, Databricks/Vertex/SageMaker feature stores) serves the same feature definitions online (low latency) and offline (training), avoiding training/serving skew.

Feedback loops: models learn from what they showed; add exploration and measure long-term metrics (retention), not just clicks. Cold start: new users get popular/onboarding-based picks; new items use content features.

How it works

  1. Nightly batch: train models, compute embeddings, precompute candidates per user.
  2. Request: fetch precomputed candidates + real-time ones → features → rank → re-rank → cache per session.
  3. Log impressions, plays, skips → training data.
  4. A/B test model changes on engagement and retention.

Example

Candidates: 300 (ANN 150 + similar-to-recent 80 + trending 50 + continue-watching 20)
Ranker scores 300 in ~30 ms → top 60 → re-rank for diversity → rows on the home page

Common mistakes

  • Optimising only clicks (clickbait, filter bubbles).
  • Different feature code for training and serving.
  • No exploration, so new content never gets a chance.

How to answer in the interview

"It's a multi-stage funnel. Candidate generation pulls a few hundred items from several sources, such as embedding-based ANN search, item similarity and trending. A ranking model scores them using user, item, context and real-time features served from a feature store, so training and serving match. A re-ranking step adds diversity and business rules. Heavy work is precomputed offline, real-time signals adjust at request time, and everything is A/B tested on long-term engagement."

Likely follow-up questions

  • New user? Popular items, onboarding preferences, contextual bandits.
  • Real-time signals? Stream recent events into the online feature store.
  • Metrics? Offline NDCG/recall; online watch time, retention.
