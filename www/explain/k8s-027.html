What are CSI drivers and volume snapshots, and how do you use them for backups?

Kubernetes · concept · levels mid, senior

In one line

CSI (Container Storage Interface) is the standard plugin model through which vendor drivers provision, attach and mount storage; a StorageClass names the provisioner for dynamic PVCs, VolumeSnapshot/VolumeSnapshotClass take storage-level snapshots, and you restore by creating a PVC with a snapshot dataSource. Snapshots are crash-consistent unless you quiesce the app.

Detailed explanation

Storage drivers used to live inside Kubernetes ("in-tree"), tying vendors to Kubernetes releases. CSI moved them out: each vendor ships a driver, such as the AWS EBS CSI driver, Azure Disk, GCE PD, Ceph RBD, Longhorn or Portworx, and in-tree drivers were migrated to CSI. A driver typically has a controller component (create and delete volumes, snapshots, attach to nodes) running as a Deployment with sidecars like external-provisioner and external-snapshotter, and a node component as a DaemonSet that mounts volumes into pods.

Dynamic provisioning: a PVC references a StorageClass whose provisioner is the CSI driver; parameters choose disk type, IOPS or encryption. volumeBindingMode: WaitForFirstConsumer delays creation until the pod is scheduled, so the disk lands in the right zone. allowVolumeExpansion enables resizing.

Snapshots use the snapshot CRDs and controller: a VolumeSnapshotClass (driver, deletion policy) and a VolumeSnapshot pointing at a PVC; the driver takes a storage snapshot, represented by a VolumeSnapshotContent. To restore or clone, create a new PVC with dataSource pointing to the snapshot.

Consistency: a snapshot captures the disk as if power were cut: crash-consistent. Databases usually recover but may replay logs, and multi-volume apps can be inconsistent across volumes. For application-consistent backups, flush or freeze first (pre-snapshot hooks, fsfreeze, database backup mode) or use the database's own backup (pg_basebackup, WAL archiving). Velero orchestrates hooks, snapshots and Kubernetes object backup and can copy data to object storage in another region. A snapshot in the same account and region as the disk is not a real backup.

How it works

  1. PVC → StorageClass → CSI controller creates the disk.
  2. Pod scheduled → attach to node → node plugin mounts it.
  3. VolumeSnapshot created → driver takes snapshot.
  4. Restore: new PVC with dataSource: VolumeSnapshot.
  5. Copy snapshots or backups off-site for real DR.

Example

apiVersion: snapshot.storage.k8s.io/v1
kind: VolumeSnapshot
metadata: { name: pg-data-2026-11-21, namespace: db }
spec:
  volumeSnapshotClassName: ebs-snapclass
  source: { persistentVolumeClaimName: data-pg-0 }
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata: { name: pg-restore, namespace: db }
spec:
  storageClassName: gp3
  accessModes: [ReadWriteOnce]
  resources: { requests: { storage: 100Gi } }
  dataSource:
    apiGroup: snapshot.storage.k8s.io
    kind: VolumeSnapshot
    name: pg-data-2026-11-21

Common mistakes

  • Treating crash-consistent snapshots as database backups without testing recovery.
  • Snapshots only in the same region and account.
  • Forgetting the snapshot CRDs and controller are separate installs on some clusters.
  • Immediate binding mode creating volumes in the wrong zone.

How to answer in the interview

"CSI is the standard storage plugin model: vendors ship drivers like the EBS or Azure Disk driver, and a StorageClass references the provisioner so PVCs get volumes dynamically. CSI also standardises snapshots: a VolumeSnapshotClass plus a VolumeSnapshot pointing at a PVC, and you restore by creating a PVC with the snapshot as its dataSource. Snapshots are crash-consistent, so for databases I quiesce first with hooks or rely on native database backups for application consistency. Velero orchestrates snapshots together with Kubernetes objects and copies data to another region."

Likely follow-up questions

  • Why is a same-region snapshot not a backup? It shares the account, region and failure or compromise domain.
  • How do you resize a PVC? Increase the request if the StorageClass allows expansion.
  • What is WaitForFirstConsumer? Delays provisioning until scheduling, choosing the pod's zone.
