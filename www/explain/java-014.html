Which features from Java 17 and Java 21 do you use, such as records, sealed classes, pattern matching and virtual threads?

Java 8+ Features · concept · levels mid, senior

In one line

From Java 17 and 21 I regularly use records for immutable data, sealed classes for closed hierarchies, pattern matching for instanceof and switch with record patterns and exhaustiveness checks, and virtual threads for scalable blocking I/O.

Detailed explanation

Records (final in Java 16) are concise immutable data carriers. Declaring record Money(BigDecimal amount, String currency) generates private final fields, accessors, a canonical constructor, equals, hashCode and toString. They are ideal for DTOs, value objects, query projections and map keys, and support compact constructors for validation.

Sealed classes and interfaces (final in Java 17) restrict which types may extend them using permits. Subtypes must be final, sealed or non-sealed. This models closed domains such as payment results or API responses, and lets the compiler know every possible subtype.

Pattern matching for instanceof (Java 16) removes the cast: if (o instanceof Card c). Pattern matching for switch and record patterns (both final in Java 21) let you deconstruct records directly in case labels, add guards with when, and, combined with sealed types, give exhaustiveness checking: forget a subtype and the code doesn't compile.

Virtual threads (final in Java 21, Project Loom) are lightweight threads scheduled by the JVM on a small pool of carrier threads. Blocking I/O unmounts the virtual thread instead of blocking an OS thread, so a simple thread-per-request style scales to very high concurrency. In Spring Boot 3.2+ you can enable them with spring.threads.virtual.enabled=true. Other daily features: switch expressions, text blocks, var, and sequenced collections (Java 21).

How it works

  1. Model data with records and validate in compact constructors.
  2. Close a hierarchy with a sealed interface whose permitted subtypes are records.
  3. Handle each subtype in a switch with record patterns; the compiler checks completeness.
  4. Run blocking work on virtual threads via Executors.newVirtualThreadPerTaskExecutor().

Example

sealed interface PaymentResult permits Approved, Declined, Pending {}
record Approved(String txId, BigDecimal amount) implements PaymentResult {}
record Declined(String reason) implements PaymentResult {}
record Pending(Duration retryAfter) implements PaymentResult {}

String describe(PaymentResult r) {
    return switch (r) {                       // exhaustive, no default needed
        case Approved(var id, var amt) when amt.signum() > 0 -> "Paid " + amt + " (" + id + ")";
        case Approved a      -> "Zero-amount approval";
        case Declined(var reason) -> "Declined: " + reason;
        case Pending p       -> "Retry in " + p.retryAfter().toSeconds() + "s";
    };
}

try (var exec = Executors.newVirtualThreadPerTaskExecutor()) {
    orders.forEach(o -> exec.submit(() -> paymentClient.charge(o)));
}

Common mistakes

  • Using records as JPA entities (they are final and immutable).
  • Adding a default branch to a sealed switch, which hides missing cases.
  • Pooling virtual threads; they are cheap and meant to be created per task.
  • Expecting virtual threads to speed up CPU-bound work.

How to answer in the interview

"Records are my default for DTOs and value objects: the compiler generates the constructor, accessors, equals, hashCode and toString. Sealed interfaces with permits let me model closed hierarchies like payment results. With pattern matching for switch and record patterns, final in Java 21, I can deconstruct those records in case labels and the compiler checks the switch is exhaustive. Java 21 also finalised virtual threads, which make thread-per-request scale for blocking I/O; in Spring Boot I just enable them with one property. I also use switch expressions and text blocks daily."

Likely follow-up questions

  • How would you model API responses with a sealed interface and records? sealed interface ApiResponse permits Success, Failure with record subtypes, handled by an exhaustive switch.
  • What is pinning with virtual threads? A virtual thread stuck to its carrier, historically inside synchronized blocks; Java 24 largely removed that limitation.
  • What is the current LTS after 21? Java 25 (September 2025).
