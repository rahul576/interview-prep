What cloud platforms have you worked with?

Cloud (AWS) · scenario · levels entry

In one line

Name the platforms you used (AWS, Azure, GCP) and, for each, the services by category (compute, storage, databases, messaging), how you deployed and managed them (IaC, CI/CD), security and monitoring (IAM, CloudWatch, Azure Monitor), plus certifications, honestly separating your work from the platform team's.

Detailed explanation

Interviewers want depth and honesty, not a catalogue. A structured answer covers, per platform:

  • Compute: EKS, ECS/Fargate, EC2, Lambda on AWS; AKS, App Service, Azure Functions on Azure; GKE and Cloud Run on GCP.
  • Storage and data: S3, RDS/Aurora PostgreSQL, DynamoDB, ElastiCache; Blob Storage, Azure SQL, Cosmos DB.
  • Messaging: SQS, SNS, EventBridge, MSK; Service Bus, Event Hubs.
  • Delivery: Terraform or CloudFormation/CDK or Bicep, CI/CD with GitHub Actions, Jenkins or Azure DevOps, container registries ECR or ACR.
  • Security: IAM roles and policies, IRSA or EKS Pod Identity, Azure managed identities and RBAC, Secrets Manager or Key Vault, VPC/VNet design, security groups.
  • Observability: CloudWatch, X-Ray, Azure Monitor and Application Insights, or Datadog and Grafana.

Explain what you did: wrote Terraform modules, configured IAM roles for service accounts, set up autoscaling, troubleshot networking, optimised cost. Mention certifications if you have them (for example AWS Certified Developer or Solutions Architect Associate, AZ-204). Saying "the platform team managed the VPCs and I owned the service-level resources" is a strong, honest answer.

How it works

  1. Lead with the primary platform and your duration on it.
  2. Describe the architecture of one real system.
  3. Name services by category with your responsibility.
  4. Mention IaC, CI/CD, security and monitoring.
  5. Add secondary platforms and certifications.

Example

Sample answer: "On AWS, our Spring Boot services ran on EKS, images in ECR, PostgreSQL on RDS, documents in S3, async processing with SQS and Lambda, secrets in Secrets Manager, monitoring in CloudWatch. I wrote Terraform modules for SQS queues with DLQs and IAM roles."

Common mistakes

  • Listing dozens of services without context.
  • Claiming platform-team work as your own.
  • Ignoring security and cost.
  • Not knowing equivalents on another cloud.

How to answer in the interview

"Mainly AWS, plus some Azure. On AWS our Spring Boot services ran on EKS with images in ECR, data in RDS PostgreSQL and S3, asynchronous processing with SQS and Lambda, secrets in Secrets Manager and monitoring in CloudWatch, all provisioned with Terraform. I wrote the Terraform for our queues and IAM roles and set up IAM roles for service accounts. On Azure I worked with AKS, Container Registry, Service Bus, Blob Storage, Key Vault and Application Insights through Azure DevOps pipelines. The platform team owned networking and accounts; I owned the service-level resources."

Likely follow-up questions

  • How did you manage secrets? Secrets Manager or Key Vault, accessed via IAM roles or managed identities, synced with External Secrets.
  • How did pods get AWS permissions? IRSA or EKS Pod Identity, no static keys.
  • How did you control cost? Right-sizing, autoscaling, Savings Plans, lifecycle rules and tagging.
