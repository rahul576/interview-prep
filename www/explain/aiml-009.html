Compare decision trees, random forests and gradient boosting.

AI/ML & GenAI · concept · levels mid, senior

In one line

A decision tree is one interpretable but unstable set of rules; a random forest averages many independent trees (bagging) to cut variance; gradient boosting adds small trees sequentially to correct errors and is usually the most accurate choice for tabular data.

Detailed explanation

A decision tree repeatedly splits the data on the feature and threshold that best separate the target (using Gini impurity, entropy or variance reduction), producing readable rules like "if tenure < 6 months and support tickets > 3, churn risk is high". Trees handle mixed feature types and non-linear interactions without scaling, but a deep tree memorises the training data (overfits) and is unstable: a small change in data can produce a completely different tree.

A random forest trains hundreds of deep trees, each on a bootstrap sample of rows and considering a random subset of features at each split, then averages their predictions (or votes). Because the trees make partly independent errors, averaging greatly reduces variance. Forests are robust, need little tuning, parallelise well and give an out-of-bag error estimate for free.

Gradient boosting builds shallow trees sequentially. Each new tree is fitted to the negative gradient of the loss (for squared error, simply the residuals) of the current ensemble, and its contribution is shrunk by a learning rate. This mainly reduces bias. Modern implementations, XGBoost, LightGBM and CatBoost, add regularisation, histogram-based splits, native missing-value handling and (CatBoost) strong categorical support. On structured business data they frequently beat neural networks, but they need tuning of learning rate, depth, number of trees and early stopping to avoid overfitting.

How it works

  1. Tree: choose the best split, recurse until a depth or leaf-size limit.
  2. Forest: draw a bootstrap sample, grow a tree with random feature subsets, repeat N times.
  3. Forest prediction: average or majority vote across trees.
  4. Boosting: start with a constant prediction, compute residuals or gradients.
  5. Fit a small tree to them, add it scaled by the learning rate, repeat until validation loss stops improving.

Example

model = lgb.LGBMClassifier(n_estimators=2000, learning_rate=0.05,

model.fit(X_train, y_train, eval_set=[(X_val, y_val)],

Common mistakes

  • Using one deep tree in production and being surprised by poor generalisation.
  • Running boosting without early stopping or with a high learning rate.
  • Trusting default impurity-based feature importance, which is biased toward high-cardinality features.
  • Assuming deep learning will beat boosting on tabular data.

How to answer in the interview

"A decision tree learns simple if-then splits; it's interpretable but overfits and is unstable. A random forest trains many trees on bootstrap samples with random feature subsets and averages them, which cuts variance and works well with little tuning. Gradient boosting adds small trees one after another, each fixing the errors of the ensemble so far using the gradient of the loss. Libraries like XGBoost, LightGBM and CatBoost are usually my first choice for tabular data, with early stopping and tuned learning rate and depth."

Likely follow-up questions

  • Why don't trees need feature scaling? Splits depend only on the order of values, not their magnitude.
  • How do you explain a boosted model? SHAP values for global and per-prediction explanations.
  • Which hyperparameters matter most in boosting? Learning rate, number of trees, depth or leaves, and subsampling.
