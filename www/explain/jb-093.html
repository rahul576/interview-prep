What is the difference between a process and a thread?

Concurrency · concept · levels entry, mid

In one line

A process is an independent running program with its own address space and resources; a thread is a unit of execution inside a process that shares the process's heap but has its own stack and program counter.

Detailed explanation

The operating system isolates processes from each other: each has its own virtual memory, file descriptors, environment and security context. A bug in one process cannot directly corrupt another's memory. The price is that communication requires inter-process communication (IPC): sockets, pipes, shared files or explicitly shared memory, and creating a process or switching between processes is relatively expensive.

A thread lives inside a process. All threads of a process share the heap, loaded classes, static fields and open resources, so they can communicate simply by reading and writing the same objects. Each thread has its own call stack (local variables, method frames), program counter and register state. Threads are cheaper to create and switch than processes, which is why servers handle many requests with threads.

That shared memory is both the benefit and the danger: two threads modifying the same object need synchronisation, or you get race conditions and visibility problems. And because nothing isolates threads, a severe failure such as OutOfMemoryError or a native crash affects the whole process.

In Java, one running JVM is one OS process. Inside it run many threads: your application threads (for example Tomcat request threads), garbage-collector threads, JIT compiler threads and others. Platform threads map one-to-one to OS threads; virtual threads (Java 21) are lighter threads scheduled by the JVM on top of a few OS threads.

How it works

  1. The OS starts a process (java -jar app.jar) with its own address space.
  2. The JVM creates the main thread plus internal threads (GC, JIT, signal handling).
  3. Your code starts more threads; each gets its own stack, all share the heap.
  4. The OS scheduler runs threads on CPU cores, switching between them.
  5. Processes talk via IPC (HTTP, sockets); threads talk via shared objects guarded by locks.

Example

public class Demo {
    static int shared = 0;                       // on the heap/statics: shared

    public static void main(String[] args) throws Exception {
        Runnable task = () -> {
            int local = 0;                       // on each thread's own stack
            for (int i = 0; i < 1000; i++) { local++; }
            synchronized (Demo.class) { shared += local; }
        };
        Thread t1 = new Thread(task), t2 = new Thread(task);
        t1.start(); t2.start(); t1.join(); t2.join();
        System.out.println(ProcessHandle.current().pid() + " -> " + shared); // one PID, 2000
    }
}

Running jcmd <pid> Thread.print shows many threads all inside that one process.

Common mistakes

  • Saying threads share the stack; each thread has its own stack.
  • Thinking more threads always means more speed; contention and switching cost add up.
  • Forgetting that shared heap data needs synchronisation.
  • Assuming one crashing thread is always isolated.

How to answer in the interview

"A process is an independent running program with its own memory address space, file handles and resources, and processes are isolated, so they communicate through sockets, pipes or files. A thread is a unit of execution inside a process. All threads in a process share the heap and resources, but each has its own stack and program counter. Threads are cheaper to create and switch, and sharing memory makes communication easy, but shared mutable data then needs synchronisation. A JVM is a good example: one process running many threads, such as request handlers, GC threads and JIT compiler threads."

Likely follow-up questions

  • Why is a crash in one thread potentially fatal for the whole JVM? Threads share memory and the process; an OutOfMemoryError, corrupted shared state or a native crash takes down everything.
  • What is a context switch? The OS saving one thread's registers and stack pointer and restoring another's; cheaper for threads than processes.
  • Are Java threads OS threads? Platform threads are; virtual threads are scheduled by the JVM onto a small pool of OS carrier threads.
