Walk through the major MCP specification revisions and what each introduced.

MCP Servers · concept · levels mid, senior

In one line

MCP revisions are dated: 2024-11-05 initial release (tools, resources, prompts, sampling, stdio, HTTP+SSE); 2025-03-26 Streamable HTTP, OAuth 2.1 authorization, tool annotations; 2025-06-18 structured output, elicitation, resource links, servers as OAuth resource servers, batching removed; 2025-11-25 experimental Tasks, Client ID Metadata Documents, icons, URL elicitation, governance; 2026-07-28 stateless core, extensions, deprecations.

Detailed explanation

MCP uses date-based version identifiers that mark the last date of backwards-incompatible change.

2024-11-05: initial release. Anthropic open-sourced MCP with the core primitives: tools, resources, prompts, client features sampling and roots, logging, and two transports: stdio and HTTP+SSE.

2025-03-26: production remote servers. Replaced HTTP+SSE with Streamable HTTP, introduced an authorization framework based on OAuth 2.1, added tool annotations (readOnlyHint, destructiveHint…), audio content, a completions capability and progress messages. It also added JSON-RPC batching, later removed.

2025-06-18: structure and security. Added structured tool output (outputSchema, structuredContent), elicitation, resource links in tool results, and the MCP-Protocol-Version HTTP header. Authorization was tightened: MCP servers are classified as OAuth resource servers, publish protected resource metadata, and clients must use resource indicators (RFC 8707) so tokens are bound to the intended server. JSON-RPC batching was removed.

2025-11-25: long-running work and governance. Added experimental Tasks for durable long-running operations, Client ID Metadata Documents as a simpler alternative to dynamic client registration, icons for tools, resources and prompts, URL-mode elicitation for sensitive flows, and a formalised governance process with SEPs.

2026-07-28: stateless core. Per the reference material, removed the handshake and sessions, introduced per-request metadata and discovery, replaced server-to-client requests with input-required results, added an extensions framework and MCP Apps, moved Tasks to an extension, and deprecated sampling, roots and logging under a new feature lifecycle.

In practice, what matters is knowing which features your hosts, SDKs and servers support, and understanding the direction of travel: from local developer tools toward secure, scalable, remote enterprise services.

How it works

  1. Each revision is published as a dated spec plus schema.
  2. Clients and servers negotiate a shared version.
  3. SDKs implement revisions over time; tiers indicate how quickly.
  4. Deprecated features keep working for a defined window before removal.

Example

2024-11-05  tools/resources/prompts, sampling, roots, stdio + HTTP+SSE
2025-03-26  Streamable HTTP, OAuth 2.1 auth, tool annotations, audio
2025-06-18  outputSchema/structuredContent, elicitation, resource links, RFC 8707, no batching
2025-11-25  Tasks (experimental), CIMD, icons, URL elicitation, governance
2026-07-28  stateless core, discovery, extensions + MCP Apps, Tasks extension, deprecations

Common mistakes

  • Following old tutorials that use HTTP+SSE or omit authorization.
  • Assuming every host supports the latest revision's features.
  • Confusing SDK version numbers with protocol revision dates.
  • Memorising dates without understanding why changes were made.

How to answer in the interview

"MCP versions are dates. 2024-11-05 was the initial open-source release from Anthropic with tools, resources, prompts, sampling, and stdio plus HTTP+SSE. 2025-03-26 replaced HTTP+SSE with Streamable HTTP, added OAuth 2.1 authorization and tool annotations. 2025-06-18 added structured output, elicitation and resource links, made servers OAuth resource servers with resource indicators, and removed batching. 2025-11-25 added experimental Tasks, Client ID Metadata Documents, icons, URL-mode elicitation and formal governance. 2026-07-28 made the core stateless, added extensions and MCP Apps, moved Tasks to an extension and deprecated sampling, roots and logging. The trend is toward secure, scalable remote servers."

Likely follow-up questions

  • Do you need to memorise dates? Not exactly; know the features and check what your hosts and SDKs support.
  • Why was batching removed? Little use, extra complexity and ambiguity in streaming and error handling.
  • What are resource indicators for? Binding tokens to a specific server so they cannot be replayed elsewhere.
