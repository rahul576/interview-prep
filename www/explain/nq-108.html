What is the difference between \(O(n)\) and \(O(n^2)\) time complexity?

DSA: Arrays & Strings · concept · levels entry

In one line

O(n) means running time grows linearly with input size (double n → double time, typical of a single loop), while O(n²) grows quadratically (double n → four times the time, typical of nested loops over the same data); for large n the gap is enormous.

Detailed explanation

Big-O notation describes how the number of operations grows as the input size n grows, ignoring constant factors and lower-order terms. It is usually stated for the worst case.

O(n) – linear. The work is proportional to n: each element is handled a constant number of times. Examples: finding the maximum in an array, summing values, a single pass building a HashMap (grouping anagrams by key), checking two strings with a frequency counter. Double the input, roughly double the time.

O(n²) – quadratic. The work is proportional to n×n, usually because for every element you loop over all (or about half of) the others. Examples: comparing every pair of words, bubble sort, insertion sort in the worst case, a naive duplicate check with two nested loops. Double the input, roughly quadruple the time; ten times the input, a hundred times the time.

Why it matters in practice: for small n both are fast, and a quadratic algorithm with tiny constants can even beat a linear one. But growth dominates quickly. Assuming roughly 10⁸–10⁹ simple operations per second:

  • n = 1,000: O(n) ≈ 1,000 ops; O(n²) ≈ 1,000,000 ops (both instant).
  • n = 100,000: 10⁵ vs 10¹⁰ (instant vs tens of seconds).
  • n = 1,000,000: 10⁶ vs 10¹² (milliseconds vs many minutes to hours).

Between them sits O(n log n), the cost of efficient comparison sorting (merge sort, Java's TimSort for objects). It grows only slightly faster than linear, since log₂ of a million is about 20. Many problems are solved by turning an O(n²) approach into O(n log n) (sort first) or O(n) (hash map).

Remember that Big-O hides constants and memory effects; for performance-critical code, measure.

How it works

  1. Identify the input size n.
  2. Count how many times the innermost operation runs as a function of n.
  3. One loop over n → O(n); a loop inside a loop over n → O(n²).
  4. Keep the dominant term and drop constants.
  5. Compare growth for realistic n.

Example

// O(n): single pass with a HashSet
static boolean hasDuplicateLinear(int[] a) {
    Set<Integer> seen = new HashSet<>();
    for (int x : a) if (!seen.add(x)) return true;
    return false;
}

// O(n^2): compare every pair
static boolean hasDuplicateQuadratic(int[] a) {
    for (int i = 0; i < a.length; i++)
        for (int j = i + 1; j < a.length; j++)
            if (a[i] == a[j]) return true;
    return false;
}

Common mistakes

  • Treating any two loops as O(n²); two sequential loops are O(n) + O(n) = O(n).
  • Forgetting hidden loops, such as list.contains inside a loop (O(n²) overall).
  • Ignoring that O(1) hash operations are average-case.
  • Assuming the asymptotically better algorithm is always faster for tiny n.

How to answer in the interview

"O(n) means the running time grows in proportion to the input: a million items takes about a million steps, typical of a single loop or one pass with a hash map. O(n²) grows with the square of the input, so doubling n makes it four times slower; that's typical of nested loops comparing every pair. For small inputs both are fast, but at a million items a linear algorithm does around a million operations and a quadratic one around a trillion, the difference between milliseconds and hours. O(n log n), like efficient sorting, sits in between, much closer to linear."

Likely follow-up questions

  • Where does O(n log n) sit? Between them, close to linear; it is the cost of comparison sorting.
  • Are two sequential loops O(n²)? No, they are O(n); only nested loops multiply.
  • What hidden O(n) calls can create O(n²)? List.contains, indexOf, or String concatenation inside a loop.
