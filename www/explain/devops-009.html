What is the difference between kill and kill -9? What is a zombie process?

Linux · concept · levels entry, mid

In one line

kill sends SIGTERM, a catchable request to shut down gracefully; kill -9 sends SIGKILL, which cannot be caught, so there is no cleanup. A zombie is a child that has exited but has not been reaped by its parent.

Detailed explanation

Signals are how the kernel and other processes notify a process. SIGTERM (15), the default for kill, says "please terminate". A well-written program catches it, stops accepting work, finishes in-flight requests, flushes buffers, closes files and connections, and exits. SIGKILL (9) is handled by the kernel itself: the process is stopped immediately and cannot catch, block or ignore it. Nothing is flushed, temporary files and locks are left behind, and writes may be incomplete, so it is a last resort after SIGTERM has failed. SIGINT (Ctrl+C) and SIGHUP (often "reload config") are other common ones.

A zombie process (state Z, shown as <defunct>) has finished running, but its parent has not yet called wait() to read its exit status, so a small entry stays in the process table. It uses no CPU or memory, and you cannot kill it, because it is already dead. The fix is the parent: make it reap its children, or kill the parent so the zombie is adopted by PID 1 (init or systemd), which reaps it. Many zombies indicate a buggy parent and can eventually exhaust PIDs.

systemd handles this for services: systemctl stop sends SIGTERM, waits TimeoutStopSec (90 seconds by default), then sends SIGKILL.

How it works

  1. kill PID sends SIGTERM; the process runs its handler and exits.
  2. If it does not exit in time, kill -9 PID sends SIGKILL.
  3. When a process exits, it becomes a zombie until the parent calls wait().
  4. If the parent dies first, PID 1 adopts and reaps the child.
  5. systemd automates SIGTERM, timeout, then SIGKILL.

Example

kill 4321                  # SIGTERM
sleep 10; kill -0 4321 && kill -9 4321   # still alive? force it
ps -eo pid,ppid,stat,cmd | awk '$3 ~ /Z/'   # list zombies and parents
kill -TERM <parent-pid>    # fix the parent, not the zombie
systemctl stop myapp       # SIGTERM, then SIGKILL after TimeoutStopSec

Common mistakes

  • Using kill -9 first and causing data corruption.
  • Trying to kill zombies instead of fixing the parent.
  • Applications that ignore SIGTERM, making every stop take the full timeout.
  • Confusing zombies with orphans (orphans are alive and adopted by PID 1).

How to answer in the interview

"kill sends SIGTERM by default, which asks the process to stop; it can catch it, finish requests, flush data and exit cleanly. kill -9 sends SIGKILL, which cannot be caught or ignored, so the kernel stops it immediately with no cleanup, and that risks corrupted files, so it is a last resort. A zombie is a child that has exited but whose parent has not called wait to collect its status, so it stays in the process table in state Z. It uses no resources and killing it does nothing; you fix or kill the parent so init reaps it. systemd sends SIGTERM and then SIGKILL after a timeout."

Likely follow-up questions

  • Why does PID 1 in a container need to handle signals properly? PID 1 ignores signals without handlers and must reap zombies, so use exec-form entrypoints or an init like tini.
  • What is kill -0? It checks whether a process exists without sending a signal.
  • What does SIGHUP usually do? Reloads configuration in many daemons.
