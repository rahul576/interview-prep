What is the difference between an AI agent and an LLM workflow?

AI Agents & AIOps · concept · levels entry, mid

In one line

In an LLM workflow the developer defines the steps in code and the model fills in each step; in an agent the model itself decides dynamically which steps and tools to use, in a loop of act, observe, decide, which suits open-ended tasks but costs predictability, latency and money.

Detailed explanation

Both use large language models, but they differ in who controls the flow. A workflow is ordinary software with LLM calls at chosen points: classify the email, retrieve related orders, draft a reply, check it against policy. The path is known in advance, so you can test each step, set clear timeouts, estimate cost exactly and debug failures by looking at one prompt. Patterns like prompt chaining, routing and parallel calls are all workflows.

An agent receives a goal, instructions and a set of tools, and runs in a loop: the model decides on an action, the runtime executes the tool, the result is fed back as an observation, and the model decides the next step until it judges the task done or a limit is hit. The number and order of steps are not known upfront. That flexibility is exactly what open-ended problems need: investigating a production incident, fixing a bug across a codebase, researching a question where each finding changes the next search.

The trade-off is real. Agents are less predictable, can take wrong turns, loop or claim false success, use more tokens and time because each step resends a growing context, and introduce new risks when tools have side effects. They are also harder to evaluate, because you must judge trajectories, not just outputs. Modern guidance, such as Anthropic's "Building effective agents", recommends using the simplest solution that works: often a single well-prompted call, then a workflow, and an agent only where flexibility pays off. In practice many systems are hybrids: a deterministic workflow with an agentic step inside.

How it works

  1. Workflow: code calls the model at step 1, validates output, passes it to step 2, and so on.
  2. Agent: the model receives goal, tools and history.
  3. The model chooses a tool call or a final answer.
  4. The runtime executes the tool and appends the result.
  5. The loop repeats until done, or a step, cost or time limit stops it.

Example

# Workflow: fixed path
def handle_email(email):
    category = llm("Classify: refund, delivery, other", email)
    orders = crm.find_orders(email.sender)
    draft = llm(f"Draft a {category} reply using orders: {orders}", email)
    return policy_check(draft)

# Agent: model chooses the path
def run_agent(goal, tools, max_steps=15):
    messages = [system_prompt, user(goal)]
    for _ in range(max_steps):
        reply = llm(messages, tools=tools)
        if not reply.tool_calls:
            return reply.text
        for call in reply.tool_calls:
            messages.append(tool_result(call.id, tools[call.name](**call.args)))
    return "Stopped: step limit reached"

Common mistakes

  • Building an agent for a task with fixed, known steps.
  • Calling any chatbot with a tool an "agent" without understanding the loop.
  • No step or cost limits on agent loops.
  • Not evaluating trajectories, only final answers.

How to answer in the interview

"In a workflow, I define the steps in code, for example classify, retrieve, draft and check, and each step calls a model with a specific prompt. It is predictable, cheaper and easy to test. In an agent, the model decides what to do next: it gets a goal and tools and runs in a loop, calling a tool, observing the result and choosing the next step until it is done. That suits open-ended tasks like investigating an incident or fixing a bug across a codebase, where you can't know the steps in advance. The cost is less predictability, more tokens and latency, and new failure modes. So I use workflows where the steps are known and agents only where the flexibility is really needed."

Likely follow-up questions

  • A task you would keep as a workflow? Invoice field extraction and posting to an ERP: fixed steps, high need for auditability.
  • Can you combine both? Yes, a workflow can contain an agentic step for the unstructured part.
  • What makes agents viable now? Better tool calling, longer context and reasoning models, plus standards like MCP.
