What is a lambda expression?

Java 8+ Features · concept · levels entry, mid

In one line

A lambda expression is an anonymous function, written (parameters) -> body, that implements the single abstract method of a functional interface; it can capture only effectively final locals and is compiled via invokedynamic rather than as a separate inner class.

Detailed explanation

Lambdas let you pass behaviour as a value. Instead of an anonymous class with boilerplate, you write order -> order.total().compareTo(LIMIT) > 0. Syntax variants: no parameters () -> 42; one parameter without parentheses x -> x * 2; explicit types (int a, int b) -> a + b; a block body with return (a, b) -> { log(a); return a + b; }.

A lambda has no type of its own; its type comes from the target type, which must be a functional interface. The same lambda () -> "hi" can be a Supplier<String> or a Callable<String> depending on context. The compiler infers parameter types from that target.

Capture rules: a lambda may read local variables from the enclosing scope only if they are final or effectively final (never reassigned). It captures the value, not the variable. Instance fields and statics can be read and modified, which is a common source of thread-safety bugs in parallel code. Inside a lambda, this refers to the enclosing instance, not to the lambda, because lambdas don't introduce a new scope; you also can't redeclare an enclosing local variable name.

Implementation: javac moves the body into a private synthetic method and emits an invokedynamic instruction. At first execution, LambdaMetafactory creates a class implementing the interface at runtime. No Outer$1.class file is generated, and non-capturing lambdas are typically cached as a singleton.

How it works

  1. The compiler determines the target functional interface.
  2. It type-checks the lambda against the interface's single method.
  3. The body becomes a private (static if non-capturing) method in the enclosing class.
  4. invokedynamic bootstraps an implementation at first call.
  5. Invoking the interface method calls the synthetic method with captured values.

Example

Comparator<Order> byTotal = (a, b) -> a.total().compareTo(b.total());
Runnable task = () -> System.out.println("running");
Predicate<Order> big = o -> o.total().compareTo(new BigDecimal("1000")) > 0;

BigDecimal limit = new BigDecimal("500");       // effectively final
List<Order> filtered = orders.stream()
    .filter(o -> o.total().compareTo(limit) > 0)
    .toList();
// limit = BigDecimal.ONE;  // would make the lambda above a compile error

// Equivalent anonymous class (more boilerplate)
Comparator<Order> old = new Comparator<>() {
    @Override public int compare(Order a, Order b) { return a.total().compareTo(b.total()); }
};

Common mistakes

  • Trying to modify a captured local variable (use an AtomicInteger or better, a reduction).
  • Assuming this refers to the lambda.
  • Writing large multi-line lambdas instead of extracting a named method.
  • Swallowing checked exceptions inside lambdas.

How to answer in the interview

"A lambda is an anonymous function: parameters, an arrow and a body, like (a, b) -> a + b. Its type is always a functional interface, so I can pass it wherever a Comparator, Runnable or Predicate is expected. It's much more concise than an anonymous inner class. It can capture local variables only if they're effectively final, and this refers to the enclosing instance. Under the hood the compiler uses invokedynamic and LambdaMetafactory, so there's no separate class file per lambda."

Likely follow-up questions

  • How does this differ in a lambda versus an anonymous class? Lambda: enclosing instance; anonymous class: the anonymous object.
  • Why must captured locals be effectively final? The value is copied; allowing changes would create confusing semantics and races.
  • Can a lambda throw checked exceptions? Only if the functional method declares them.
