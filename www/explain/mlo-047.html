When would you use online learning instead of periodic batch retraining?

MLOps · concept · levels senior, lead

In one line

Online learning updates a model continuously with each new labelled example; use it when patterns change very fast and labels arrive quickly (ads click-through, news recommendations), but it brings instability, poisoning risk and harder reproducibility, so it needs safeguards; periodic retraining stays the default because it is simpler and more controllable.

Detailed explanation

In periodic batch retraining, you train a fresh model on a fixed dataset, evaluate it and promote it. In online (incremental) learning, the model's parameters are updated as new examples arrive—per event or in small mini-batches—so it adapts within minutes or hours. Algorithms that support this include SGD-based linear models (partial_fit in scikit-learn), factorisation machines, online gradient boosting variants, libraries like River or Vowpal Wabbit, and neural networks fine-tuned incrementally.

When it pays off: patterns change very fast and labels arrive quickly. Advertising click-through prediction, news and content feeds, trending items, some dynamic pricing and spam filtering fit. Yesterday's model may already be stale because new ads, articles and items appear constantly.

Risks. Instability: noisy or unusual traffic (a bot attack, a holiday) can push the model in bad directions, and errors compound through feedback loops because the model's own decisions shape future training data. Poisoning: attackers can feed crafted interactions to manipulate it. Reproducibility and audit: the model is different every minute, so explaining a past decision requires snapshots. Catastrophic forgetting of older patterns is also possible.

Safeguards: continuous validation against a holdout stream, regular snapshots for rollback, learning-rate and update-size limits, anomaly detection and filtering on incoming data, a frozen fallback model, and alerts on sudden metric shifts.

A common middle ground is frequent incremental fine-tuning, such as hourly warm-started updates with an evaluation gate, rather than truly per-event learning.

How it works

  1. Start from a batch-trained, validated base model.
  2. Stream labelled events; filter anomalies and bots.
  3. Update parameters in small steps with bounded learning rate.
  4. Evaluate continuously on a holdout stream (progressive validation).
  5. Snapshot model state regularly with version IDs.
  6. Roll back automatically on metric degradation.

Example

from river import linear_model, preprocessing, metrics

model = preprocessing.StandardScaler() | linear_model.LogisticRegression()
auc = metrics.ROCAUC()

for x, y in click_stream():          # features dict, clicked 0/1
    p = model.predict_proba_one(x).get(True, 0.0)
    auc.update(y, p)                 # test-then-train (progressive validation)
    model.learn_one(x, y)
    if step % 100_000 == 0:
        snapshot(model, auc.get())   # rollback point

Common mistakes

  • Using online learning where labels take weeks.
  • No snapshots, so a corrupted model can't be restored.
  • Evaluating on data the model has already learned from.
  • Ignoring feedback loops from the model's own decisions.

How to answer in the interview

"Online learning updates the model continuously as new labelled examples arrive instead of retraining from scratch. It's worth it when patterns change very fast and labels come quickly, like ad click-through or news recommendations. But the risks are real: instability from noisy traffic, feedback loops, poisoning by crafted feedback, and harder reproducibility. So it needs safeguards: progressive validation on a holdout stream, regular snapshots for rollback, limits on update size and anomaly filtering. Otherwise periodic retraining is simpler and more auditable, so it's my default."

Likely follow-up questions

  • How would you evaluate an online model fairly? Progressive test-then-train validation plus a holdout stream and A/B comparison with a batch model.
  • What is a feedback loop? Model decisions shape the data it learns from, reinforcing biases.
  • Middle ground? Frequent warm-start retraining with gates.
