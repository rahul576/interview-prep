What are PriorityQueue and ArrayDeque, and when do you use them?

Collections · concept · levels entry, mid

In one line

PriorityQueue is a binary min-heap where poll returns the smallest element (O(log n) offer/poll, O(1) peek); ArrayDeque is a resizable circular array with O(1) operations at both ends and is the recommended stack and queue. Neither is thread safe.

Detailed explanation

PriorityQueue stores elements in an array laid out as a binary heap: for index i, its children are at 2i+1 and 2i+2, and every parent is less than or equal to its children. The head is always the minimum by natural order or a supplied Comparator. offer appends and "sifts up" (O(log n)), poll removes the root, moves the last element up and "sifts down" (O(log n)), and peek is O(1). Only the head is guaranteed to be the minimum, so iterating or printing shows heap order, not sorted order. It rejects null. Typical uses are top-K problems, schedulers, Dijkstra's shortest path and merging sorted streams.

ArrayDeque keeps elements in a circular array with head and tail indexes that wrap around. Adding or removing at either end is amortised O(1), and it doubles when full. It has no per-element node objects, so it is faster and lighter than LinkedList. The Javadoc itself says it is likely faster than Stack when used as a stack and faster than LinkedList as a queue. The legacy Stack extends Vector and synchronises every call, which is pointless overhead. ArrayDeque does not allow null either.

For concurrency use PriorityBlockingQueue, ConcurrentLinkedDeque or LinkedBlockingDeque.

How it works

  1. PriorityQueue offer: place at the end, swap with parent while smaller.
  2. PriorityQueue poll: take root, move last to root, swap with smaller child while larger.
  3. ArrayDeque addFirst: decrement head modulo capacity and store.
  4. ArrayDeque addLast: store at tail, increment modulo capacity; grow if head meets tail.

Example

// Top 3 largest using a min-heap of size k
PriorityQueue<Integer> heap = new PriorityQueue<>();
for (int x : nums) {
    heap.offer(x);
    if (heap.size() > 3) heap.poll();     // drop smallest
}

Deque<Character> stack = new ArrayDeque<>();
stack.push('(');
char top = stack.pop();

Queue<Job> fifo = new ArrayDeque<>();
fifo.offer(job);
Job next = fifo.poll();

Common mistakes

  • Printing a PriorityQueue and expecting sorted output.
  • Using Stack or LinkedList instead of ArrayDeque.
  • Comparators like (a, b) -> a - b that overflow; use Integer.compare.
  • Sharing either structure between threads.

How to answer in the interview

"PriorityQueue is a binary heap backed by an array: poll always gives the smallest element by natural order or a comparator, offer and poll are log n and peek is constant. I use it for top K, scheduling and Dijkstra, remembering its iterator isn't sorted. ArrayDeque is a circular resizable array with constant-time operations at both ends, and it is the recommended replacement for both Stack and LinkedList as a stack or queue. Neither is thread safe; the concurrent versions are PriorityBlockingQueue and ConcurrentLinkedDeque."

Likely follow-up questions

  • Why isn't a printed PriorityQueue sorted? The array is in heap order; only the root is guaranteed minimal.
  • How do you make a max-heap? new PriorityQueue<>(Comparator.reverseOrder()).
  • Why avoid Stack? It is a synchronised legacy Vector subclass.
