What is the purpose of @SpringBootApplication?

Spring Boot · concept · levels mid, senior

In one line

@SpringBootApplication on the main class combines @SpringBootConfiguration (a specialised @Configuration), @EnableAutoConfiguration and @ComponentScan of its package and sub-packages; main calls SpringApplication.run, and attributes like exclude disable specific auto-configurations.

Detailed explanation

It is a meta-annotation that saves writing three annotations:

  1. @SpringBootConfiguration: marks the class as a source of bean definitions, like @Configuration, so you can declare @Bean methods there (though dedicated config classes are cleaner). Spring Boot's test support uses it to find the main configuration when running @SpringBootTest.
  2. @EnableAutoConfiguration: activates auto-configuration. Boot loads candidate classes from AutoConfiguration.imports files and applies them when their conditions match the classpath, beans and properties.
  3. @ComponentScan: scans the package of the annotated class and all sub-packages for @Component, @Service, @Repository, @Controller and @Configuration classes. Boot adds filters so auto-configuration classes are not picked up twice. The package also serves as the default base for JPA entity scanning and Spring Data repository detection, through @AutoConfigurationPackage.

Because of the scan rule, the main class should sit in the root package, for example com.acme.shop, with features in com.acme.shop.orders, com.acme.shop.payments. If it lives in com.acme.shop.app while services are in com.acme.shop.orders, those services are not found and startup fails with missing bean errors, or endpoints silently return 404.

The main method calls SpringApplication.run(App.class, args), which determines the application type (servlet, reactive or none), creates the ApplicationContext, loads configuration, refreshes the context, starts the embedded server and runs ApplicationRunner/CommandLineRunner beans.

Useful attributes: exclude / excludeName to switch off auto-configurations (for example DataSourceAutoConfiguration in a service without a database), and scanBasePackages / scanBasePackageClasses to widen scanning, which is better than moving classes awkwardly but can hide a poor package structure.

How it works

  1. JVM calls main, which calls SpringApplication.run.
  2. The annotated class is registered as the primary configuration source.
  3. Component scanning registers your beans from the base package down.
  4. Auto-configuration adds framework beans conditionally.
  5. Context refreshes; embedded server starts; runners execute.

Example

package com.acme.shop;   // root package

@SpringBootApplication(exclude = DataSourceAutoConfiguration.class)
public class ShopApplication {
    public static void main(String[] args) {
        SpringApplication.run(ShopApplication.class, args);
    }
}

// Equivalent long form
@SpringBootConfiguration
@EnableAutoConfiguration(exclude = DataSourceAutoConfiguration.class)
@ComponentScan
class ShopApplicationLongForm { }
com.acme.shop.ShopApplication      <- scans everything below
com.acme.shop.orders.OrderService  <- found
com.acme.billing.InvoiceService    <- NOT found (outside the package)

Common mistakes

  • Main class in a sub-package, so components are not scanned.
  • Putting many @Bean definitions in the main class, which also affects test slices.
  • Adding @EnableAutoConfiguration or @ComponentScan again on other classes.
  • Using exclude when a property such as spring.autoconfigure.exclude per environment would be better.

How to answer in the interview

"@SpringBootApplication is a convenience annotation on the main class that combines three annotations. @SpringBootConfiguration, a specialised @Configuration, marks it as a source of bean definitions. @EnableAutoConfiguration turns on Spring Boot's auto-configuration, which creates beans based on the classpath and properties. And @ComponentScan scans the package of that class and its sub-packages for components, which is why the main class should be in the root package. The main method calls SpringApplication.run to create the context and start the embedded server. I can exclude specific auto-configurations through its exclude attribute, for example DataSourceAutoConfiguration."

Likely follow-up questions

  • What happens if the main class is in a sub-package below your services? Those services are not scanned, so injection fails or endpoints are missing; move the class or set scanBasePackages.
  • How does @SpringBootTest find the configuration? It searches up the package tree for @SpringBootConfiguration.
  • What does SpringApplication.run return? The ConfigurableApplicationContext.
