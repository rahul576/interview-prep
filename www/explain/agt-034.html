Users find your agent too slow; tasks take minutes. How do you speed it up?

AI Agents & AIOps · scenario · levels mid, senior

In one line

Profile traces to split model time, tool time and number of steps, then reduce steps with higher-level tools, run independent tool calls in parallel, use smaller faster models for simple steps, cut context with prompt caching and compaction, optimise or cache slow tools, and stream progress or run long tasks asynchronously.

Detailed explanation

Agent latency is roughly number of sequential model calls × time per call, plus tool execution time. Time per call depends on input size (prefill), output length (especially reasoning tokens) and model size. So the first step is profiling representative traces: how many steps, how long each model call takes, how much time tools take, and where the run waits.

Fewer steps is usually the biggest win. Higher-level tools that do in one call what took several (for example get_customer_overview instead of five lookups) remove whole round trips. Better instructions and examples stop unnecessary exploration, and plan-and-execute can let cheap code run predictable steps.

Parallelism: independent operations, such as fetching several records or searching multiple sources, should be parallel tool calls in a single step, and tools should execute them concurrently. Sub-agents can work in parallel for broad tasks.

Model choice: smaller, faster models for classification, extraction or summarising tool output; the strong model only where needed. Reduce reasoning effort for simple steps where the model supports it, and limit verbose outputs.

Context size: long system prompts and growing histories slow every call. Prompt caching of stable prefixes reduces time to first token as well as cost; compaction and concise tool results keep inputs small.

Tools: slow tools get optimised, cached or given timeouts; batch APIs reduce round trips.

User experience: stream tokens and progress ("searching orders... found 3, checking refunds") so users see work happening, and run genuinely long tasks asynchronously with a notification when done. Perceived latency matters as much as total latency.

How it works

  1. Collect traces; measure per-step model time, tool time and step count.
  2. Identify the critical path and biggest contributors.
  3. Merge multi-step patterns into higher-level tools.
  4. Parallelise independent calls.
  5. Route simple steps to faster models; enable prompt caching; compact context.
  6. Stream progress; move long tasks to async with notifications.

Example

Profile of "Why was my invoice higher?" (p50 before)
  model calls: 9 x 4.1 s = 36.9 s
  tools:       9 x 1.3 s = 11.7 s
  total ~ 49 s

Changes
  - get_billing_summary tool replaces 4 lookups          -> 5 model calls
  - parallel fetch of invoice + usage + plan             -> 1 step instead of 3
  - small model summarises usage records                 -> 1.2 s instead of 4 s
  - prompt caching of 6k-token system prompt + tools     -> faster first token
After: 4 model calls, total ~ 11 s; streaming shows progress after 1.5 s

Common mistakes

  • Optimising tool latency while ignoring the number of model round trips.
  • Using the largest reasoning model for every step.
  • Sequential calls for independent data.
  • Putting dynamic content at the start of the prompt, breaking caching.
  • Silent spinners for minutes with no progress feedback.

How to answer in the interview

"I profile representative traces to see model time versus tool time and how many steps a task takes, because agent latency is mostly the number of sequential model calls times their duration. The biggest win is often fewer steps: higher-level tools that do in one call what took several, and better instructions to avoid exploration. Independent operations run as parallel tool calls. Simple steps like classifying or summarising use smaller, faster models. Prompt caching, compaction and concise tool results shrink every call. Slow tools get optimised or cached. And for user experience I stream progress so users see what's happening, and run genuinely long tasks asynchronously with a notification."

Likely follow-up questions

  • Latency target for an interactive agent? First visible feedback within one to two seconds, and typical tasks within ten to thirty seconds; longer tasks go async.
  • Does prompt caching reduce latency? Yes, it reduces prefill time for the cached prefix.
  • Speculative execution? Pre-fetching likely-needed data in parallel can hide tool latency, if reads are cheap and safe.
