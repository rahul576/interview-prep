What are sequenced collections and other notable features introduced in Java 21?

Java 8+ Features · concept · levels mid, senior

In one line

Java 21 (an LTS release) introduced sequenced collections (getFirst, getLast, reversed), finalised record patterns and pattern matching for switch, finalised virtual threads, and added generational ZGC, among other improvements.

Detailed explanation

Sequenced collections (JEP 431) fill an old gap: there was no common type for "a collection with a defined encounter order". Getting the last element of a List, Deque, LinkedHashSet or SortedSet needed different code for each. Java 21 adds SequencedCollection with getFirst, getLast, addFirst, addLast, removeFirst, removeLast and reversed() (a view), SequencedSet, and SequencedMap with firstEntry, lastEntry, pollFirstEntry, putFirst and sequencedKeySet. List, Deque, LinkedHashSet, SortedSet, LinkedHashMap and SortedMap were retrofitted.

Record patterns (JEP 440) let you destructure records, including nested ones, inside instanceof and switch. Pattern matching for switch (JEP 441) lets case labels test types, use guards with when, handle case null, and check exhaustiveness over sealed hierarchies.

Virtual threads (JEP 444) became final, making thread-per-request scale for blocking I/O. Generational ZGC (JEP 439) improves throughput and reduces allocation stalls for low-latency apps. Other additions include the Key Encapsulation Mechanism API, and previews of string templates (later withdrawn), unnamed patterns, structured concurrency and scoped values. The next LTS after 21 is Java 25 (September 2025), which finalised features like scoped values, flexible constructor bodies and compact source files.

How it works

  1. Ordered collections now implement SequencedCollection/SequencedMap.
  2. reversed() returns a live reverse-ordered view, not a copy.
  3. A switch over a sealed type tries patterns top-down; guards refine matches.
  4. The compiler reports an error if a sealed subtype is not covered.

Example

List<String> steps = new ArrayList<>(List.of("cart", "pay", "ship"));
String first = steps.getFirst();          // "cart"  (was steps.get(0))
String last  = steps.getLast();           // "ship"  (was steps.get(steps.size()-1))
List<String> backwards = steps.reversed();

LinkedHashMap<String, Integer> recent = new LinkedHashMap<>();
recent.putLast("a", 1); recent.putFirst("b", 2);
var oldest = recent.firstEntry();         // b=2

sealed interface Shape permits Circle, Rect {}
record Point(double x, double y) {}
record Circle(Point c, double r) implements Shape {}
record Rect(Point tl, Point br) implements Shape {}

double area(Shape s) {
    return switch (s) {
        case Circle(Point p, double r) -> Math.PI * r * r;
        case Rect(Point(var x1, var y1), Point(var x2, var y2)) -> Math.abs((x2 - x1) * (y2 - y1));
    };
}

Common mistakes

  • Thinking reversed() copies the collection; it is a view.
  • Calling getFirst() on an empty list expecting null (it throws NoSuchElementException).
  • Listing preview features (e.g. string templates) as final Java 21 features.
  • Adding default to sealed switches and losing exhaustiveness checks.

How to answer in the interview

"Java 21 is an LTS release. Sequenced collections add SequencedCollection, SequencedSet and SequencedMap, so List, Deque, LinkedHashSet and LinkedHashMap share getFirst, getLast, addFirst and reversed. Record patterns let me deconstruct records directly in instanceof and switch, and pattern matching for switch became final with guards and exhaustiveness checks over sealed types. Virtual threads became final, and generational ZGC arrived. The next LTS after 21 is Java 25."

Likely follow-up questions

  • How would you refactor a chain of if-instanceof checks? Use a sealed interface and an exhaustive pattern-matching switch with record patterns.
  • Does HashMap implement SequencedMap? No, it has no defined order.
  • What is case null for? Handling null in a switch instead of getting an NPE.
