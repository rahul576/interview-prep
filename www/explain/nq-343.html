Have you automated development activities using Generative AI?

AI/ML & GenAI · scenario · levels mid

In one line

Describe concrete automations you built, such as AI PR summaries and review comments, release-note generation, test generation opened as draft PRs, agentic dependency upgrades and failed-build triage, integrated into CI/CD via LLM APIs, with guardrails (human approval, least privilege, data exclusion, cost tracking) and measured results.

Detailed explanation

This differs from "do you use an assistant": the interviewer wants to hear that you automated a workflow, ideally in the pipeline, and controlled the risks.

Typical automations:

  • PR summary and risk notes: a CI job sends the diff to an LLM API and posts a comment describing the change and risky areas.
  • Release notes: merged PR titles and descriptions turned into grouped, readable notes.
  • Test generation: a script finds classes with low coverage (from JaCoCo), asks the model for tests, runs them and opens a draft PR only if they compile and pass.
  • Agentic maintenance: an agent upgrades dependencies, runs the build and fixes compile errors.
  • Build triage: on failure, summarise the log and suggest a likely cause in Slack.

Guardrails separate a mature answer from a risky one: AI output never merges automatically; CI tokens are scoped (comment and draft-PR only); secrets and personal data are excluded; prompts treat the diff as untrusted data; and you track cost and usefulness, for example acceptance rate.

How it works

  1. Choose a repetitive task with a clear output.
  2. Trigger it from CI or a scheduled job.
  3. Build the prompt from repository data and call the LLM API.
  4. Validate the output (compiles, tests pass, schema valid).
  5. Publish as a comment or draft PR for human approval.
  6. Track acceptance rate, time saved and cost.

Example

name: ai-pr-summary
on: pull_request
permissions: { contents: read, pull-requests: write }
jobs:
  summary:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - run: git diff origin/${{ github.base_ref }}...HEAD > diff.txt
      - run: python scripts/ai_summary.py diff.txt > summary.md
        env: { LLM_API_KEY: "${{ secrets.LLM_API_KEY }}" }
      - run: gh pr comment ${{ github.event.number }} --body-file summary.md
        env: { GH_TOKEN: "${{ github.token }}" }

Sample result: after two months, reviewers rated 70% of summaries useful; cost was a few dollars per hundred PRs.

Common mistakes

  • Auto-merging AI changes.
  • Giving the bot broad repository or cloud permissions.
  • Sending secrets or customer data in prompts.
  • Not measuring whether the automation helps.

How to answer in the interview

"Yes. I built a GitHub Actions step that sends each PR diff to an LLM API and posts a summary with risk notes, and another job that drafts release notes from merged PRs. We also had a script that generated unit tests for low-coverage classes and opened them as draft PRs only if they passed. The guardrails mattered: nothing merges automatically, the token can only comment or open drafts, secrets are excluded, and we tracked cost and the share of suggestions people accepted, which was around seventy percent for summaries."

Likely follow-up questions

  • How did you measure whether it was worth it? Acceptance rate, reviewer survey, review time and cost per PR.
  • What failed? Generated tests that asserted buggy behaviour; we added mutation testing and review.
  • How do you protect against prompt injection in diffs? Treat diff as data, give the bot no write privileges beyond comments.
