What are the different types of garbage collectors in Java?

JVM & Performance · concept · levels mid

In one line

HotSpot offers Serial (single-threaded, small heaps), Parallel (multi-threaded, maximum throughput), G1 (the default since Java 9, region-based with pause targets), ZGC and Shenandoah (concurrent, low-latency, pauses around a millisecond or less), and Epsilon (no-op, for testing); CMS was removed in Java 14.

Detailed explanation

Serial GC (-XX:+UseSerialGC). One thread does all collection work with stop-the-world pauses. Lowest overhead and footprint, suitable for small heaps, client tools, and containers with one CPU. The JVM selects it automatically when it sees fewer than two CPUs or under about 1.8 GB of memory.

Parallel GC (-XX:+UseParallelGC), the "throughput collector". Many threads collect young and old generations in parallel, still stop-the-world. It maximises total throughput and minimises GC CPU overhead, making it ideal for batch jobs, ETL and analytics, where long pauses are acceptable.

G1 GC (-XX:+UseG1GC), default on server-class machines since Java 9. The heap is split into regions; young collections are parallel pauses; old-generation marking is concurrent; mixed collections reclaim the regions with the most garbage first. It aims at a pause goal (MaxGCPauseMillis, default 200 ms). A strong general-purpose choice for most web services with heaps from a few GB to tens of GB.

ZGC (-XX:+UseZGC). Production-ready since Java 15. Uses coloured pointers and load barriers to mark, relocate and compact concurrently; pauses are typically well under a millisecond, independent of heap size, scaling to multi-terabyte heaps. Generational since Java 21 and generational-only in later releases. Costs some throughput and CPU, and needs headroom.

Shenandoah (-XX:+UseShenandoahGC). Developed by Red Hat, available in most OpenJDK builds (not Oracle's JDK). Also concurrent compaction with very short pauses; a generational mode has been added in recent releases.

Epsilon (-XX:+UnlockExperimentalVMOptions -XX:+UseEpsilonGC). Allocates but never collects; the JVM dies when the heap is exhausted. Useful for performance testing and very short-lived jobs.

CMS (Concurrent Mark Sweep) was the former low-pause collector: deprecated in Java 9, removed in Java 14. Its fragmentation and tuning complexity were replaced by G1 and ZGC.

How it works

  1. Define the goal: footprint, throughput or latency.
  2. Small and single-CPU: Serial.
  3. Batch throughput: Parallel.
  4. General services: G1 with a pause goal.
  5. Strict latency or very large heaps: ZGC (or Shenandoah).
  6. Validate with GC logs under realistic load.

Example

java -XX:+UseParallelGC -Xmx8g -jar nightly-batch.jar
java -XX:+UseG1GC -XX:MaxGCPauseMillis=100 -XX:MaxRAMPercentage=70 -jar api.jar
java -XX:+UseZGC -Xmx32g -jar trading-gateway.jar
java -XX:+PrintCommandLineFlags -version | grep -o 'Use[A-Za-z]*GC'  # which GC?

Common mistakes

  • Recommending CMS on modern JDKs.
  • Not realising small pods silently get Serial GC.
  • Choosing ZGC for small heaps where G1 is simpler and enough.
  • Picking a collector without measuring.

How to answer in the interview

"Serial GC uses one thread with stop-the-world pauses, fine for small heaps and single-CPU containers. Parallel GC is the throughput collector: many threads, longer pauses, great for batch jobs. G1, the default since Java 9, divides the heap into regions, collects the regions with the most garbage first and aims at a pause target like 200 ms, so it's a good general choice. ZGC and Shenandoah do almost all work concurrently, giving pauses around a millisecond or less regardless of heap size, for latency-sensitive services; ZGC has been generational since Java 21. CMS was removed in Java 14, and Epsilon is a no-op collector for testing. For a typical REST service I'd start with G1 and measure."

Likely follow-up questions

  • Which collector would you choose for a 4 GB REST service, and why? G1 with a suitable pause goal; consider ZGC only if p99 latency targets are still missed.
  • Why was CMS removed? Fragmentation, complex tuning and maintenance cost, with G1 and ZGC as better alternatives.
  • How do you check which GC is active? -XX:+PrintCommandLineFlags, jcmd VM.flags, or the first lines of the GC log.
