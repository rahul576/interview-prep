What is data leakage in machine learning, and how do you prevent it?

MLOps · concept · levels mid, senior

In one line

Data leakage means training uses information not available at prediction time, so offline metrics look great and production fails; main forms are target leakage, train-test contamination (duplicates, preprocessing fitted on all data) and future data in temporal problems; prevent it with time-based splits, point-in-time correct joins, pipelines fitted on training data only, and treat suspiciously high scores as a warning.

Detailed explanation

Target leakage happens when a feature is derived from, or updated after, the outcome. Examples: a "collections flag" set after a loan defaults used to predict default; "number of support calls" including calls about the cancellation in a churn model; a hospital "treatment given" field that reveals the diagnosis. The model learns a shortcut that doesn't exist at prediction time.

Train-test contamination happens when information crosses the split. The same customer, or near-duplicate records (repeated transactions, augmented images, the same document in two versions), appears in both training and test; or preprocessing—scaling, imputation, target encoding, feature selection—is fitted on the full dataset before splitting, so test statistics leak into training. Group-aware splits (by customer or patient) and fitting transformations inside a pipeline on training folds only prevent this.

Temporal leakage: with time-dependent data, a random split lets the model train on the future and test on the past. Use time-based splits—train on earlier periods, validate and test on later ones—often with a gap matching label maturity. Point-in-time correct feature joins ensure each training example only uses feature values known at its prediction timestamp, which feature stores support with as-of joins.

Warning signs: AUC of 0.99 on a hard problem, one feature with overwhelming importance, or a large gap between offline and production performance. These should trigger a leakage review: check each top feature's timing and meaning with domain experts.

How it works

  1. Define the prediction moment for each example.
  2. Build features with as-of joins relative to that moment.
  3. Split by time (and by entity group) with appropriate gaps.
  4. Fit all preprocessing inside a pipeline on training data only.
  5. Deduplicate across splits.
  6. Review suspicious results and top features with domain experts.

Example

from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

train = df[df.application_date < "2026-04-01"]
test  = df[df.application_date >= "2026-05-01"]      # 1-month gap for label maturity

pipe = Pipeline([("scale", StandardScaler()), ("clf", LogisticRegression(max_iter=1000))])
pipe.fit(train[FEATURES], train.default)             # scaler fitted on train only
print(pipe.score(test[FEATURES], test.default))
assert "collections_flag" not in FEATURES            # set after default: target leakage

Common mistakes

  • Random splits on time series or event data.
  • Scaling or target-encoding before splitting.
  • Using "current" snapshot tables for historical training examples.
  • Celebrating near-perfect offline metrics.

How to answer in the interview

"Data leakage is when the model learns from information that won't be available at prediction time, so offline metrics are excellent and production is poor. Target leakage is a feature derived from the outcome, like a collections flag set after default. Train-test contamination is duplicates across splits or preprocessing fitted on the whole dataset. For temporal data I use time-based splits and point-in-time correct feature joins. And a suspiciously high score triggers a leakage review of the top features with domain experts."

Likely follow-up questions

  • How would you audit an existing model for leakage? Check top features' timestamps and meaning, retrain with time splits and compare.
  • Is leakage possible through hyperparameter tuning? Yes, tuning on the test set leaks; use a separate validation set.
  • What is a group split? All records of one entity go to the same split.
