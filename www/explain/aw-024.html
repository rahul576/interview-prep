What is Elastic Beanstalk, and when would you use it?

Cloud (AWS) · concept · levels entry

In one line

Elastic Beanstalk is AWS's PaaS for web apps: you upload code or a Docker image, pick a platform (Java, Node.js, Python, .NET, Go, PHP, Docker), and it provisions EC2, load balancer, Auto Scaling, monitoring and health checks, while still letting you see and tune the underlying resources and offering rolling, immutable and blue-green deployments.

Detailed explanation

Beanstalk sits between raw EC2 and fully managed containers. You create an application and one or more environments (for example orders-staging, orders-prod). A web server environment runs behind an ALB with an Auto Scaling group; a worker environment processes messages from an SQS queue. Beanstalk uses CloudFormation under the hood and creates normal resources in your account, so you can inspect instances, adjust instance types, scaling rules and security groups, and customise them through .ebextensions or platform hooks.

Managed platform updates apply OS and runtime patches in a maintenance window. Enhanced health reporting aggregates instance and request metrics into a health status.

Deployment policies: All at once (fast, downtime), Rolling (batch by batch, reduced capacity), Rolling with additional batch (launches extra instances first to keep full capacity), Immutable (launches a completely new set of instances in a temporary Auto Scaling group, switches when healthy, easy rollback), and Traffic splitting (canary-style percentage of traffic to new instances). Blue-green is done by cloning an environment, deploying there and swapping CNAMEs.

Beanstalk suits small teams, prototypes and conventional web apps that want production-ready infrastructure quickly. Limitations: less flexibility for microservices, slower deployments than containers, and platform conventions to learn. Many teams move to ECS on Fargate, EKS or App Runner as they grow. Note that AWS has announced App Runner will stop accepting new customers, so check the current status before recommending it for new projects.

How it works

  1. Create an application and environment, choosing a platform.
  2. Upload a source bundle, JAR or Dockerfile.
  3. Beanstalk provisions resources via CloudFormation.
  4. Configure scaling, instance type and environment variables.
  5. Deploy new versions with the chosen policy.
  6. Monitor health; roll back to a previous application version if needed.

Example

pip install awsebcli
eb init orders-api --platform "Corretto 21" --region eu-west-1
eb create orders-prod --elb-type application --instance_type t3.medium
eb setenv SPRING_PROFILES_ACTIVE=prod
eb deploy                      # uses the configured deployment policy
eb health
# .ebextensions/deploy.config
option_settings:
  aws:elasticbeanstalk:command:
    DeploymentPolicy: Immutable

Common mistakes

  • Editing instances by hand; changes vanish on replacement.
  • Using All at once in production.
  • Creating the RDS database inside the environment, tying its lifecycle to it.
  • Ignoring platform version updates.

How to answer in the interview

"Elastic Beanstalk is AWS's platform as a service for web apps. I upload a JAR, zip or Docker image, pick a platform like Java or Node.js, and Beanstalk creates and manages the EC2 instances, load balancer, Auto Scaling, monitoring and health checks. Unlike fully managed services I can still see and tune those resources. It supports rolling, rolling with additional batch, immutable and traffic-splitting deployments, and blue-green through environment CNAME swaps. It's great for small teams and simple apps; as needs grow, teams often move to ECS on Fargate or EKS."

Likely follow-up questions

  • Immutable vs rolling? Immutable launches fresh instances and switches when healthy; rolling updates existing instances in batches.
  • Where should the database live? Outside the environment, as a separate RDS instance.
  • What are platform hooks? Scripts run at defined deployment stages for customisation.
