How do you transform a list of objects into a map for for_each, and flatten nested structures?

Terraform · concept · levels mid, senior

In one line

Convert a list of objects into a map with a for expression keyed by a unique, stable attribute ({ for s in var.subnets : s.name => s }), use flatten with nested for expressions for parent-child structures and a composite key like "vnet/subnet", because stable keys prevent mass recreation.

Detailed explanation

for_each accepts only a map or a set of strings, and each key becomes part of the resource address, for example azurerm_subnet.this["app"]. Keys must be known at plan time, so derive them from input values such as names, not from attributes of resources that do not exist yet.

A list of objects is converted with a map-producing for expression. Using a meaningful attribute like name as the key is important: with count, instances are addressed by position, so removing the second item of a list shifts every later item and Terraform destroys and recreates them. With name keys, removing one item affects only that item.

Nested structures are common: several VNets, each with several subnets. for_each cannot loop over two levels directly, so you first flatten: a nested for expression produces a list of lists of small objects, each carrying the parent and child values you need, and flatten() turns it into a single list. Then you convert that list into a map with a composite key such as "${vnet_key}/${subnet.name}", which is unique across the whole structure and readable in plans. The resource then uses each.value.vnet_name, each.value.cidr and so on.

If two objects produce the same key, Terraform fails with a duplicate key error, unless you use the grouping ... syntax, which you usually do not want here. Test such transformations in terraform console first.

How it works

  1. Define the input as a map or list of objects with unique names.
  2. For one level, build { for x in list : x.name => x }.
  3. For nested levels, produce a list of child objects that include parent keys.
  4. Apply flatten() to get one flat list.
  5. Convert to a map with a composite key.
  6. Use the map in for_each and reference each.value.

Example

variable "vnets" {
  type = map(object({
    address_space = list(string)
    subnets       = list(object({ name = string, cidr = string }))
  }))
}

locals {
  subnets = {
    for s in flatten([
      for vnet_key, vnet in var.vnets : [
        for sn in vnet.subnets : {
          key       = "${vnet_key}/${sn.name}"
          vnet_name = vnet_key
          name      = sn.name
          cidr      = sn.cidr
        }
      ]
    ]) : s.key => s
  }
}

resource "azurerm_subnet" "this" {
  for_each             = local.subnets
  name                 = each.value.name
  virtual_network_name = azurerm_virtual_network.this[each.value.vnet_name].name
  resource_group_name  = azurerm_resource_group.net.name
  address_prefixes     = [each.value.cidr]
}

Common mistakes

  • Using list indexes as keys, which recreates resources when the list changes.
  • Keys derived from values known only after apply.
  • Non-unique keys, such as subnet names repeated across VNets without the parent prefix.
  • Building unreadable one-liners instead of named locals.

How to answer in the interview

"for_each needs a map or set of strings, so I turn a list of objects into a map with a for expression keyed by a unique, stable attribute like the name; keys must be known at plan time. For nested data, like VNets with subnets, I use nested for expressions with flatten to get a flat list of objects carrying both parent and child values, then convert it to a map with a composite key like vnet slash subnet. Stable name-based keys matter because adding or removing one item only touches that item instead of recreating everything after it."

Likely follow-up questions

  • What if two objects produce the same key? Terraform errors with a duplicate key; make the key composite.
  • How do you debug it? Evaluate local.subnets in terraform console.
  • Migrating from count to for_each? Use moved blocks from index to key addresses.
