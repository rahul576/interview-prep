Compare common sorting algorithms. Which does Java use?

DSA: Algorithms & DP · concept · levels entry, mid

In one line

Quicksort is O(n log n) on average, O(n²) worst case, in-place, not stable. Merge sort is O(n log n) always and stable, but needs O(n) extra space. Heap sort is O(n log n) in-place, not stable. Counting/radix sort can be linear for bounded integer keys. Comparison sorts can't beat Ω(n log n). Java uses dual-pivot quicksort for primitives and TimSort (stable) for objects.

Detailed explanation

  • Quicksort picks a pivot, partitions elements into smaller and larger, and recurses. It is very cache-friendly and fast in practice. A bad pivot choice (sorted input with a first-element pivot) gives O(n²), mitigated by random or median-of-three pivots. Introsort (C++ std::sort) switches to heap sort if the recursion gets too deep.
  • Merge sort splits in half, sorts each, and merges. It is guaranteed O(n log n) and stable, but needs O(n) buffer space. It is the natural choice for linked lists and external sorting of data on disk.
  • Heap sort builds a max-heap and repeatedly extracts the max. It is O(n log n) worst case and O(1) space, but has poor cache locality and is not stable.
  • Insertion sort is O(n²), but very fast for tiny or nearly sorted arrays, which is why hybrids use it for small partitions.
  • Counting sort is O(n + k) for small integer ranges. Radix sort is O(d·(n + b)) for fixed-width keys. They are not comparison-based, so the bound doesn't apply.

Lower bound: any comparison sort needs at least log₂(n!) ≈ n log n comparisons, because it must distinguish all n! orderings (the decision tree argument).

What Java uses (OpenJDK):

  • Arrays.sort(int[]/long[]/double[]...): dual-pivot quicksort (Yaroslavskiy), with insertion sort for small ranges and some special-casing in newer JDKs. Stability is meaningless for primitives, because equal ints are indistinguishable.
  • Arrays.sort(Object[]), Collections.sort, List.sort: TimSort, a hybrid of merge sort and insertion sort that detects existing runs. It is stable, O(n log n) worst case, and close to O(n) on already sorted data.
  • Arrays.parallelSort: a parallel merge sort on the ForkJoin pool for large arrays.

Why stability matters: sorting objects by a secondary key, then by a primary key, keeps the secondary order within ties. For example, sort employees by name, then stably by department, and each department stays alphabetical.

How it works

  1. Small or nearly sorted input: insertion sort, or TimSort exploits the runs.
  2. Primitives, average case: quicksort variants (no stability needed).
  3. Objects or a stable requirement: merge-based (TimSort).
  4. Memory-tight with a worst-case guarantee: heap sort.
  5. Bounded integer keys: counting or radix sort.
  6. Data larger than RAM: external merge sort.

Example

int[] nums = {5, 2, 9, 1};
Arrays.sort(nums);                         // dual-pivot quicksort

List<Employee> staff = loadStaff();
staff.sort(Comparator.comparing(Employee::name));        // TimSort, stable
staff.sort(Comparator.comparing(Employee::department));  // names stay ordered within dept

Common mistakes

  • Saying Java uses plain quicksort for everything.
  • Forgetting that quicksort's worst case is n².
  • Claiming radix sort beats the n log n "limit" without noting it isn't comparison-based.
  • Writing comparators that violate the contract, which makes TimSort throw IllegalArgumentException: Comparison method violates its general contract.

How to answer in the interview

"Quicksort averages O(n log n) and sorts in place, but its worst case is O(n squared) with bad pivots, and it isn't stable. Merge sort is always O(n log n) and stable but needs O(n) extra space. Heap sort is O(n log n) in place but not stable. Counting and radix sort can be linear for small integer ranges, because they don't compare. Comparison sorts can't beat n log n. Java uses dual-pivot quicksort for primitive arrays, where stability doesn't matter, and TimSort for objects, a stable merge and insertion sort hybrid that's very fast on partially sorted data."

Likely follow-up questions

  • Why does stability matter for objects? Multi-key sorts rely on equal elements keeping their earlier order.
  • Why not TimSort for primitives? Stability is useless there and quicksort avoids the extra memory.
  • Sorting 1 TB of data? External merge sort: sort chunks in memory, then k-way merge the runs.
