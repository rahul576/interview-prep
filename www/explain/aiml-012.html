What is feature engineering, and which common transformations do you apply?

AI/ML & GenAI · concept · levels entry, mid

In one line

Feature engineering turns raw data into inputs that expose patterns to a model: scaling, categorical encoding, date/time parts, aggregates, ratios and logs, driven by domain knowledge and built only from information available at prediction time.

Detailed explanation

Models only see the columns you give them, and for tabular problems good features often improve results more than switching algorithms. Scaling puts numeric features on comparable ranges: standardisation (zero mean, unit variance) or min-max normalisation. It matters for distance-based and gradient-based models such as k-means, k-NN, SVMs, logistic regression and neural networks, but not for tree models.

Categorical encoding depends on cardinality. One-hot encoding suits a handful of categories. For high-cardinality fields such as merchant ID, use target encoding (mean target per category, computed out-of-fold with smoothing to avoid leakage), frequency encoding, hashing, or learned embeddings. Date and time become day of week, hour, month, holiday flags, and "time since last event". Event logs become aggregates over windows, like orders in the last 30 days or average basket value. Log transforms tame skewed values like income, ratios (debt to income) and interaction terms capture relationships, and text can become TF-IDF or embedding features.

The most valuable features usually come from domain experts: fraud analysts know that a new device plus a high-value order plus a shipping address change is suspicious. The biggest risk is data leakage: any feature using information that would not exist at prediction time (future transactions, a "refunded" flag when predicting fraud at checkout) gives great offline scores and fails in production. The same transformation code must run in training and serving, ideally through a pipeline or a feature store with point-in-time correct joins.

How it works

  1. Understand the prediction moment and what data exists then.
  2. Clean and type the raw columns.
  3. Create domain features: aggregates, ratios, time-since, flags.
  4. Encode categoricals and scale numerics inside a pipeline fitted on training data only.
  5. Validate each feature's value with ablation or importance, and drop leaky ones.

Example

from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import OneHotEncoder, StandardScaler, FunctionTransformer
import numpy as np

df["order_hour"] = df["order_ts"].dt.hour
df["is_weekend"] = df["order_ts"].dt.dayofweek >= 5
df["log_amount"] = np.log1p(df["amount"])

prep = ColumnTransformer([
    ("num", StandardScaler(), ["log_amount", "orders_30d", "days_since_last"]),
    ("cat", OneHotEncoder(handle_unknown="ignore"), ["channel", "country"]),
])

Common mistakes

  • Fitting scalers or encoders on the full dataset before splitting.
  • Target encoding without out-of-fold computation.
  • Building aggregates that accidentally include the current or future events.
  • Writing separate feature code for training and production.

How to answer in the interview

"Feature engineering is turning raw data into variables that make the signal easy to learn. I scale numerics for distance and gradient-based models, one-hot encode low-cardinality categoricals and use target or frequency encoding for high-cardinality ones, extract date parts, and build windowed aggregates like orders in the last 30 days. The best features come from domain experts. Above all I make sure every feature uses only data available at prediction time and that the same pipeline runs in training and production."

Likely follow-up questions

  • Why is feature engineering less central for deep learning on images or text? The network learns representations directly from raw pixels or tokens.
  • What is a feature store? Shared storage of feature definitions and values with point-in-time correctness for training and low-latency serving.
  • How do you detect leakage? Suspiciously high scores, features that dominate importance, and checking timestamps.
