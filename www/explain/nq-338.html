How have you used AI tools to speed up application development?

AI/ML & GenAI · scenario · levels mid

In one line

AI speeds development most on repetitive and exploratory work: scaffolding and boilerplate, tests and test data, mechanical refactorings and migrations, scripts and config, and understanding code, logs and errors faster, while code review and quality gates stay unchanged.

Detailed explanation

The honest framing is that AI shortens the boring parts so you can spend more time on design and review. Good examples:

Scaffolding: new endpoints, DTOs, MapStruct mappers, JPA entities, configuration classes, OpenAPI specs, Flyway scripts. Pointing the assistant at an existing similar class ("follow the style of CustomerController") keeps output consistent.

Tests: unit tests with JUnit 5 and Mockito, parameterised edge cases, Testcontainers setups, and realistic test data builders. AI is good at enumerating boundary cases (null, empty, max length, negative amounts).

Migrations and refactorings: e.g. moving to Spring Boot 3 requires javax. to jakarta. namespace changes, replacing deprecated APIs, upgrading JUnit 4 to 5, or adopting records. Agentic tools can apply these across dozens of files and fix compile errors. Deterministic tools such as OpenRewrite recipes are often better for the bulk transformation, with AI handling the leftovers.

Scripts and infrastructure: SQL queries, shell scripts, Dockerfiles, Helm values, GitHub Actions workflows.

Understanding: summarising an unfamiliar module, explaining a stack trace, spotting patterns in logs, comparing libraries.

None of this bypasses process: AI-written code goes through the same code review, automated tests, static analysis (SonarQube) and security scans. Mention how you measure the gain, for example cycle time or time to first PR.

How it works

  1. Identify repetitive or exploratory tasks in your workflow.
  2. Give the tool a reference pattern and clear constraints.
  3. Generate in small steps; run the build and tests after each.
  4. Review the diff as you would a colleague's PR.
  5. Let CI quality gates validate everything.
  6. Reinvest saved time in design, review and hard problems.

Example

Sample STAR story:

  • Situation: 14 services needed to move from Spring Boot 2.7 to 3.x before end of support.
  • Task: do it without freezing feature work.
  • Action: ran OpenRewrite's Spring Boot 3 migration recipe, then used an AI agent to fix remaining compile errors, update security configuration to the lambda DSL and adjust tests; each service went through normal review and CI.
  • Result: migration took about three weeks instead of the estimated two months.
mvn -U org.openrewrite.maven:rewrite-maven-plugin:run \
  -Drewrite.recipeArtifactCoordinates=org.openrewrite.recipe:rewrite-spring:RELEASE \
  -Drewrite.activeRecipes=org.openrewrite.java.spring.boot3.UpgradeSpringBoot_3_0

Common mistakes

  • Claiming speed without mentioning quality controls.
  • Using AI for bulk transformations that a deterministic tool does more reliably.
  • Accepting generated tests that only assert the current (possibly buggy) behaviour without thought.
  • No measurement of the improvement.

How to answer in the interview

"The biggest gains are in repetitive and exploratory work. I let the assistant scaffold endpoints, DTOs and mappers following our existing patterns, generate unit tests and test data, and do mechanical migrations. For example, on a Spring Boot 3 upgrade across fourteen services we used OpenRewrite for the bulk changes and an AI agent to fix the remaining errors, which took weeks instead of months. It also helps me understand unfamiliar code and stack traces faster. But everything still goes through code review, our test suite and Sonar quality gates, so speed doesn't cost quality."

Likely follow-up questions

  • Example where AI saved significant time? The migration above, or generating a full test suite for a legacy module.
  • Where does AI slow you down? Ambiguous tasks or complex domain logic where reviewing wrong output takes longer than writing it.
  • How do you measure productivity gains? Cycle time, PR throughput and developer surveys, not lines of code.
