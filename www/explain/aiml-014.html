What is the curse of dimensionality, and how does PCA help?

AI/ML & GenAI · concept · levels mid, senior

In one line

In high dimensions data becomes sparse, distances lose meaning and models need far more data and overfit more easily; PCA helps by projecting data onto a few orthogonal directions of maximum variance, keeping most information in fewer features.

Detailed explanation

The curse of dimensionality describes several effects. The volume of the feature space grows exponentially, so a fixed number of samples covers it ever more thinly. In many dimensions, the distance to the nearest neighbour and to the farthest point become almost the same, so distance-based methods like k-NN, k-means and similarity search lose discriminative power. With many features and limited rows, models find spurious correlations and overfit; training and storage also get slower.

Principal component analysis (PCA) is a linear technique. After centring (and usually standardising) the data, it finds the eigenvectors of the covariance matrix, computed in practice via singular value decomposition. The first principal component is the direction of greatest variance, the second is orthogonal to it with the next greatest variance, and so on. Keeping the top components that explain, say, 95 percent of the variance compresses the data, removes noise and correlated redundancy, speeds training and allows 2-D visualisation. The cost is interpretability, because each component is a mix of original features, and PCA only captures linear structure; high variance is not always the same as being predictive.

Alternatives include feature selection (keep the best original features using importance, L1 regularisation or mutual information), non-linear methods like UMAP and t-SNE (mainly for visualisation), autoencoders, and simply collecting more data. For text and images, learned embeddings are the modern form of dimensionality reduction.

How it works

  1. Standardise features so units do not dominate.
  2. Compute the covariance structure via SVD.
  3. Sort components by explained variance.
  4. Choose the number of components from the cumulative explained-variance curve.
  5. Project data onto those components and train on the reduced features, applying the same fitted transform at inference.

Example

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA

pca_pipe = make_pipeline(StandardScaler(), PCA(n_components=0.95))
X_reduced = pca_pipe.fit_transform(X_train)   # e.g. 300 features -> 40 components
print(pca_pipe[-1].explained_variance_ratio_.cumsum()[-1])

Common mistakes

  • Running PCA without scaling, so the feature with the biggest units dominates.
  • Fitting PCA on the full dataset including the test set.
  • Using t-SNE output as model features or reading cluster distances from it.
  • Assuming the components with most variance are the most predictive.

How to answer in the interview

"As dimensions grow, the space grows exponentially, so data becomes sparse, nearest and farthest neighbours look similar, and models need much more data and overfit more easily. PCA reduces dimensions by finding orthogonal directions of maximum variance and projecting onto the top few, often keeping 95 percent of the variance with far fewer features. That speeds training and reduces noise, at the cost of interpretability and only capturing linear structure. Alternatives are feature selection, or UMAP and t-SNE for visualisation."

Likely follow-up questions

  • Why scale before PCA? PCA follows variance, so unscaled large-unit features would dominate.
  • How many components do you keep? Enough for a target explained variance, or tune it by downstream validation score.
  • PCA versus feature selection? PCA creates new combined features; selection keeps original, interpretable ones.
