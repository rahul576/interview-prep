How do you check if a string of brackets is balanced?

DSA: Lists, Stacks & Queues · concept · levels entry

In one line

Use a stack: push opening brackets. On a closing bracket, the stack must be non-empty and the popped bracket must match its type. At the end the stack must be empty. That is O(n) time, O(n) space worst case. In Java use ArrayDeque, not the legacy Stack.

Detailed explanation

Brackets must close in last-opened, first-closed order. In "([{}])" the innermost { must close before [. This LIFO structure is exactly what a stack models. A simple counter works only for a single bracket type. With mixed types, "([)]" has balanced counts but is invalid, because ) closes while [ is still the most recent unclosed bracket.

There are three failure conditions:

  1. A closing bracket with an empty stack: ")(".
  2. A mismatched type: "(]".
  3. Leftover openers at the end: "((".

A small Map from closer to opener (or a switch) keeps the matching clean, and non-bracket characters are simply skipped if the input can contain other text (validating code or expressions).

Space is O(n) in the worst case (all openers). An early exit helps: if the length is odd, return false. If the stack size exceeds the remaining characters, it can't recover.

Java note: java.util.Stack extends Vector, so it is synchronised and legacy. ArrayDeque with push/pop/peek is faster and recommended by the Javadoc itself. ArrayDeque does not accept nulls, which is fine here.

Real-world use: parsers and compilers, JSON/XML validation, editors highlighting matching brackets, and evaluating expressions (shunting-yard).

How it works

  1. Create Deque<Character> stack = new ArrayDeque<>().
  2. For each char: if it is an opener, push.
  3. If it is a closer: if the stack is empty or pop() != matching opener, return false.
  4. Ignore other characters if allowed.
  5. Return stack.isEmpty().

Example

public boolean isValid(String s) {
    Map<Character, Character> pairs = Map.of(')', '(', ']', '[', '}', '{');
    Deque<Character> stack = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        if (c == '(' || c == '[' || c == '{') {
            stack.push(c);
        } else if (pairs.containsKey(c)) {
            if (stack.isEmpty() || stack.pop() != pairs.get(c)) return false;
        }
    }
    return stack.isEmpty();
}
// "({[]})" -> true   "([)]" -> false   "((" -> false   ")" -> false

Common mistakes

  • Using a single counter for multiple bracket types.
  • Popping without checking for an empty stack, which throws NoSuchElementException or EmptyStackException.
  • Forgetting the final isEmpty() check.
  • Using the legacy Stack class without knowing why it is discouraged.

How to answer in the interview

"I'd use a stack. For each character, if it's an opening bracket I push it. If it's a closing bracket, the stack must not be empty and the popped bracket must be the matching type, otherwise it's unbalanced. At the end the stack must be empty, otherwise some brackets were never closed. That's O(n) time and O(n) space in the worst case. A counter only works for one bracket type, because cases like '([)]' need ordering. In Java I'd use ArrayDeque rather than the legacy synchronised Stack class."

Likely follow-up questions

  • Longest valid parentheses substring? Use a stack of indices seeded with -1, tracking lengths. O(n).
  • Minimum additions to make it valid? Count unmatched openers and unmatched closers.
  • Only one bracket type? A counter that must never go negative and ends at 0. O(1) space.
