Which movements are allowed from each cell, and why are movement restrictions important?

DSA: Algorithms & DP · concept · levels entry

In one line

In the standard grid-path problem you may move only right or down; that restriction makes the grid a directed acyclic graph, which is exactly what lets dynamic programming compute each cell from already-solved neighbours. With more directions you need graph algorithms such as Dijkstra or BFS.

Detailed explanation

The movement rules are the most important constraint to clarify first, because they decide the algorithm. When every move goes right or down, each step strictly increases i + j. There can be no cycles: you can never return to a cell you have already left. The grid is therefore a DAG, and processing cells in row-major order is a valid topological order. Each cell depends only on cells that are already final, so a single pass of DP is correct.

If diagonal moves (down-right) are also allowed, the graph is still acyclic. You just add a third term: min(top, left, topLeft). The DP order stays the same.

If moves in four directions (or eight) are allowed, paths can go up or left and loop back. A cell's best cost may depend on cells "after" it in row order, so no fixed fill order exists and DP breaks. Now treat the grid as a weighted graph: with non-negative cell costs use Dijkstra with a priority queue; with uniform costs plain BFS finds the shortest path; with 0/1 costs a deque-based 0-1 BFS works; with negative costs and no negative cycles, Bellman-Ford.

How it works

  1. Ask: which moves are allowed, can costs be negative, are there obstacles?
  2. Right/down (optionally diagonal): confirm acyclic, use DP in row-major order.
  3. Four/eight directions: model cells as nodes and moves as edges.
  4. Choose BFS for unit costs or Dijkstra for non-negative weights.
  5. State the complexity that follows from the choice.

Example

// Four directions allowed: Dijkstra on the grid
int[][] dist = new int[m][n];
for (int[] row : dist) Arrays.fill(row, Integer.MAX_VALUE);
PriorityQueue<int[]> pq = new PriorityQueue<>(Comparator.comparingInt(a -> a[0]));
dist[0][0] = grid[0][0];
pq.add(new int[]{grid[0][0], 0, 0});
int[][] dirs = {{1,0},{-1,0},{0,1},{0,-1}};
while (!pq.isEmpty()) {
    int[] cur = pq.poll();
    if (cur[0] > dist[cur[1]][cur[2]]) continue;        // stale entry
    for (int[] d : dirs) {
        int r = cur[1] + d[0], c = cur[2] + d[1];
        if (r < 0 || c < 0 || r >= m || c >= n) continue;
        int nd = cur[0] + grid[r][c];
        if (nd < dist[r][c]) { dist[r][c] = nd; pq.add(new int[]{nd, r, c}); }
    }
}

Common mistakes

  • Assuming right/down without asking.
  • Applying DP when moves in four directions create cycles.
  • Using Dijkstra with negative costs.
  • Forgetting the diagonal term when diagonals are allowed.

How to answer in the interview

"I'd ask first, because it changes the algorithm. Usually only right and down are allowed. That matters because every move goes forward, so there are no cycles: the grid is a directed acyclic graph and row-major order is a topological order, which makes DP correct. Diagonals just add another term to the min. If you can also move up and left, paths can loop, the fill order breaks down, and I'd treat it as a weighted graph and run Dijkstra, assuming non-negative costs, or BFS if all costs are equal."

Likely follow-up questions

  • Why does Dijkstra require non-negative costs? It finalises a node when popped, assuming no later path can be cheaper; negative edges break that.
  • When is BFS enough? When every move has the same cost.
  • What is the complexity of Dijkstra on the grid? O(V log V) with V = m·n, since each cell has a constant number of edges.
