What is CountDownLatch, and how does it work with multiple threads?

Concurrency · concept · levels mid

In one line

CountDownLatch is a one-shot synchroniser created with a count: worker threads call countDown(), and threads calling await() block until the count reaches zero, after which the latch stays open and cannot be reset.

Detailed explanation

A latch is like a gate that opens once. You create it with new CountDownLatch(n). Any thread can call countDown(), which decrements the count (it never goes below zero). Any number of threads can call await(); they block until the count hits zero, then all of them are released together. Once zero, later await() calls return immediately. There is also await(timeout, unit), which returns false if the time runs out, and getCount() for diagnostics.

Memory visibility is part of the contract: actions in a thread before calling countDown() happen-before actions after a successful return from await() in another thread. So results written by workers before counting down are safely visible to the waiting thread.

Typical uses:

  • Wait for N tasks to finish: a coordinator starts N workers and awaits a latch of N.
  • Wait for N services to initialise before accepting traffic.
  • Starting gun: a latch of 1 that many threads await, released with a single countDown(), so they start at the same instant; very useful in concurrency tests.

The latch is deliberately one-time use. For repeated phases where a group of threads waits for each other at a barrier, use CyclicBarrier (resets automatically and can run a barrier action) or Phaser (dynamic number of parties, multiple phases). For "wait for these tasks" in modern code, invokeAll, CompletableFuture.allOf or structured concurrency are often clearer, but a latch remains useful when the events are not tasks you submitted.

Always call countDown() in a finally block: if a worker throws before counting down, the waiting thread blocks forever (or until timeout).

How it works

  1. Coordinator creates new CountDownLatch(3) and shares it with three workers.
  2. Coordinator calls await() and blocks.
  3. Each worker does its job and calls countDown() in finally.
  4. On the third countDown() the count reaches 0 and all awaiting threads are released.
  5. The latch stays at 0; it cannot be reused.

Example

CountDownLatch ready = new CountDownLatch(3);
ExecutorService pool = Executors.newFixedThreadPool(3);

for (String svc : List.of("cache", "search-index", "pricing")) {
    pool.execute(() -> {
        try {
            warmUp(svc);
        } finally {
            ready.countDown();                    // always, even on failure
        }
    });
}

if (!ready.await(30, TimeUnit.SECONDS)) {
    throw new IllegalStateException("Warm-up incomplete, remaining: " + ready.getCount());
}
startAcceptingTraffic();
pool.shutdown();

Common mistakes

  • Calling countDown() outside finally, so failures hang the waiter.
  • Waiting without a timeout in production code.
  • Trying to reuse a latch for multiple rounds.
  • Creating the latch with the wrong count when the number of tasks is dynamic (use Phaser instead).

How to answer in the interview

"CountDownLatch is a synchroniser created with a count, say three. Each worker calls countDown when it finishes its part, and one or more threads call await, which blocks until the count reaches zero; then all waiters proceed, and what the workers did before counting down is visible to them. Typical uses are a main thread waiting for services to initialise, or a test using a latch of one as a starting gun for many threads. It's one-shot and can't be reset, so for repeated rounds I'd use CyclicBarrier or Phaser. And I always call countDown in finally so a failing worker doesn't leave everyone waiting forever."

Likely follow-up questions

  • How is CyclicBarrier different from CountDownLatch? A barrier makes a fixed group of threads wait for each other and resets for the next round; a latch waits for events and is single use.
  • What happens if countDown is called more times than the count? The count stays at zero; extra calls have no effect.
  • What is a Phaser? A reusable barrier with a dynamic number of registered parties and multiple phases.
