What is AWS CloudTrail, and how is it different from CloudWatch?

Cloud (AWS) · concept · levels entry

In one line

CloudTrail records API activity, who did what, when, from where and with what result, for auditing, security investigations and compliance; CloudWatch handles operational monitoring: metrics, logs, dashboards and alarms about how systems perform.

Detailed explanation

Every action in AWS, a console click, CLI command, SDK call or a service acting on your behalf, is an API call. CloudTrail captures these as events containing the identity (user, role, session, federated identity), time, source IP, user agent, the request parameters and the response or error. It answers questions like "who deleted this security group?", "which role read this secret?", or "what did the compromised key do?".

There are several event types. Management events (control-plane actions such as RunInstances, CreateUser, PutBucketPolicy) are recorded by default and visible for 90 days in Event history at no charge. Data events (high-volume data-plane actions like s3:GetObject, PutObject, Lambda Invoke, DynamoDB item operations) must be explicitly enabled on a trail or event data store and cost extra. Insights events detect unusual API call rates or error rates.

For long-term retention and organisation-wide coverage, create an organisation trail delivering logs from all accounts and regions to a central S3 bucket in a dedicated log archive account, with log file integrity validation, KMS encryption, restrictive bucket policies and Object Lock. CloudTrail Lake lets you query events with SQL; alternatively use Athena on the S3 logs. Trails can also stream to CloudWatch Logs for metric filters and alarms.

CloudWatch is different: it collects metrics (CPU, latency, queue depth, custom business metrics), logs from applications and services, alarms that notify or trigger actions, dashboards, and features like synthetics and Application Signals. CloudWatch answers "is it healthy and how is it performing?"; CloudTrail answers "who changed what?". They complement each other, and GuardDuty analyses CloudTrail for threats.

How it works

  1. A principal calls an AWS API.
  2. CloudTrail records the event within minutes.
  3. Event history keeps 90 days of management events.
  4. Trails deliver events to S3 (and optionally CloudWatch Logs).
  5. Investigators query with CloudTrail Lake or Athena.
  6. EventBridge or metric filters alert on sensitive actions.

Example

# Who deleted a security group in the last few days?
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=EventName,AttributeValue=DeleteSecurityGroup \
  --max-results 5 \
  --query "Events[].{time:EventTime,user:Username,event:EventName}"
{ "source": ["aws.cloudtrail"],
  "detail": { "eventName": ["StopLogging", "DeleteTrail", "UpdateTrail"] } }

The EventBridge pattern alerts security when anyone tries to disable CloudTrail; an SCP can also deny those actions outright.

Common mistakes

  • Relying only on 90-day event history.
  • Trail logs stored in the same account an attacker could control.
  • Expecting S3 object reads to appear without data events.
  • Confusing CloudTrail audit logs with application logs in CloudWatch.

How to answer in the interview

"CloudTrail records API activity in the account, every console action, CLI command and SDK call, with who made it, when, from which IP and what was requested. It's the audit log for security investigations and compliance. Management events are recorded by default; data events like S3 object reads or Lambda invocations must be enabled. Best practice is an organisation trail to a central, locked-down S3 bucket in a log archive account with file validation. CloudWatch is for operations: metrics, application logs, dashboards and alarms about how resources perform. CloudTrail tells you who changed something, CloudWatch tells you how it's behaving."

Likely follow-up questions

  • Alert when someone disables CloudTrail? EventBridge rule on StopLogging/DeleteTrail, and an SCP denying those actions.
  • What is log file validation? Signed digest files prove logs weren't modified or deleted.
  • How do you investigate a leaked access key? Filter CloudTrail by the access key ID to list every action it performed.
