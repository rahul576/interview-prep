What is the difference between filter(), map(), and reduce()?

Java 8+ Features · concept · levels mid, senior

In one line

filter keeps elements matching a Predicate (same type, possibly fewer), map transforms each element with a Function (one output per input, possibly a new type), and reduce is a terminal operation that combines all elements into one result using an identity and an associative accumulator.

Detailed explanation

filter(Predicate<? super T>) evaluates test for each element and passes through only those returning true. The element type doesn't change and the count can only shrink. It is a lazy, stateless intermediate operation.

map(Function<? super T, ? extends R>) applies a function to every element and emits the result. Exactly one output per input, but the type may change, for example Order to BigDecimal. Primitive variants mapToInt, mapToLong, mapToDouble avoid boxing. Also lazy and stateless. Functions passed to map should be free of side effects.

reduce folds the stream into a single value and starts execution. Three forms exist:

  • reduce(identity, accumulator) returns T, e.g. reduce(0L, Long::sum); the identity must satisfy acc(identity, x) == x.
  • reduce(accumulator) returns Optional<T> because the stream might be empty.
  • reduce(identity, accumulator, combiner) lets the result type differ from the element type and specifies how to merge partial results in parallel.

The accumulator must be associative and stateless, because in parallel streams partial results are grouped arbitrarily. Subtraction, for instance, is not associative and gives wrong answers in parallel.

In practice, specialised reductions are clearer and often faster: mapToLong(...).sum(), count(), max(comparator), or collect(Collectors.summingLong(...)). For accumulating into mutable containers, use collect (mutable reduction), not reduce.

How it works

  1. filter drops non-matching elements as they flow by.
  2. map replaces each surviving element with its transformed value.
  3. reduce starts with the identity and applies the accumulator per element.
  4. In parallel, each chunk reduces separately and results are combined.

Example

long paidTotal = orders.stream()
    .filter(Order::isPaid)              // Stream<Order>, fewer elements
    .map(Order::amount)                 // Stream<Long>
    .reduce(0L, Long::sum);             // single long

long same = orders.stream()
    .filter(Order::isPaid)
    .mapToLong(Order::amount)           // no boxing
    .sum();

Optional<Order> biggest = orders.stream()
    .reduce((a, b) -> a.amount() >= b.amount() ? a : b);

int totalChars = words.stream()         // result type differs: needs combiner
    .reduce(0, (sum, w) -> sum + w.length(), Integer::sum);

Common mistakes

  • Using a non-associative accumulator or a wrong identity (e.g. 1 for sum).
  • Using reduce to build lists instead of collect.
  • Performing side effects inside map.
  • Forgetting the single-argument reduce returns an Optional.

How to answer in the interview

"filter takes a Predicate and keeps only matching elements, so the stream may get shorter but the type stays the same. map takes a Function and transforms each element, one output per input, possibly to a different type. Both are lazy intermediate operations. reduce is terminal: it combines all elements into a single result using an identity and an associative accumulator, for example filter paid orders, map to amount, reduce with Long::sum. In practice I often prefer specialised reductions like mapToLong and sum, or collectors, which are clearer."

Likely follow-up questions

  • Why must the accumulator be associative? Parallel execution combines partial results in arbitrary groupings.
  • What does the third argument of reduce do? It combines partial results when the result type differs from the element type.
  • reduce versus collect? reduce for immutable values; collect for mutable containers.
