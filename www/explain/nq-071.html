What alternative approaches can you use to find the maximum price without stream max()?

Coding Exercises · scenario · levels mid

In one line

Alternatives: a classic for loop tracking the maximum (O(n)), Collections.max with a comparator, mapToDouble().max() or summaryStatistics(), reduce, or sorting and taking the last — which works but costs O(n log n) and is the least efficient.

Detailed explanation

1. Plain loop. The most basic and often fastest: keep the best product so far and update it when a higher price appears. It is O(n), needs no extra allocation, and makes edge cases explicit — you must decide what to do for an empty list, and you can easily handle ties or nulls. It is also easy to debug.

2. Collections.max. Collections.max(products, Comparator.comparingDouble(Product::getPrice)) does the same loop internally. It is concise, but on an empty collection it throws NoSuchElementException, so check isEmpty() first.

3. Primitive streams. If only the price is needed, products.stream().mapToDouble(Product::getPrice).max() returns an OptionalDouble. summaryStatistics() computes count, sum, min, max and average in one pass — useful when several statistics are needed; on an empty stream getMax() returns Double.NEGATIVE_INFINITY, so check getCount().

4. reduce. products.stream().reduce((a, b) -> a.getPrice() >= b.getPrice() ? a : b) returns Optional<Product>. It is essentially what max does, so it is mainly a demonstration of understanding.

5. Sort and take the last (or first after reversing). products.stream().sorted(comparator).reduce((a, b) -> b) or sorting a copy and taking get(size - 1). It works but costs O(n log n) time and O(n) memory, and if you sort the original list in place you also mutate it. Only reasonable if you need the sorted list anyway, or the top k elements (then a PriorityQueue of size k is better).

Choosing. In production code I prefer stream().max(...) or Collections.max for readability, a loop in hot paths with special requirements, and summaryStatistics when several aggregates are needed.

How it works

  1. Decide what is needed: the product or just the price, one statistic or several.
  2. Choose an O(n) approach unless sorting is needed anyway.
  3. Handle the empty case explicitly.
  4. Decide tie behaviour (first vs last maximum).

Example

// 1. loop
Product best = null;
for (Product p : products) {
    if (best == null || p.getPrice() > best.getPrice()) best = p;
}

// 2. Collections.max (throws on empty)
Product top = products.isEmpty() ? null
        : Collections.max(products, Comparator.comparingDouble(Product::getPrice));

// 3. primitive stream statistics
DoubleSummaryStatistics stats = products.stream()
        .mapToDouble(Product::getPrice).summaryStatistics();
double maxPrice = stats.getCount() > 0 ? stats.getMax() : 0.0;

// 4. reduce
Optional<Product> viaReduce = products.stream()
        .reduce((a, b) -> a.getPrice() >= b.getPrice() ? a : b);

// 5. sort (O(n log n), least efficient)
List<Product> copy = new ArrayList<>(products);
copy.sort(Comparator.comparingDouble(Product::getPrice));
Product last = copy.isEmpty() ? null : copy.get(copy.size() - 1);

Common mistakes

  • Initialising the loop maximum to 0, which fails for negative values.
  • Forgetting Collections.max throws on empty collections.
  • Sorting the original list in place just to find the maximum.
  • Trusting summaryStatistics().getMax() on an empty stream.

How to answer in the interview

"A plain loop is simplest and O(n): start with the first product, or negative infinity for the price, update whenever a higher price appears, and handle an empty list. Collections.max with comparingDouble does the same and throws NoSuchElementException on an empty list. With streams but without max, mapToDouble(Product::getPrice).summaryStatistics().getMax() gives min, average and count in one pass too, or I can use reduce keeping the higher-priced product. Sorting and taking the last element works but costs O(n log n), so it's the least efficient."

Likely follow-up questions

  • Which would you use in production? stream().max or Collections.max for clarity, a loop for hot paths.
  • How do you find the top 5? A min-heap PriorityQueue of size 5, O(n log k).
  • Why not initialise with 0? Prices are non-negative, but in general negative values would break it; use the first element or negative infinity.
