What is the difference between a lambda expression and an anonymous inner class?

Java 8+ Features · concept · levels entry, mid

In one line

A lambda can only implement a functional interface, shares its enclosing scope (this is the outer instance) and is linked via invokedynamic; an anonymous inner class can implement any interface or extend a class, can have fields/state, introduces its own scope (this is itself) and compiles to a separate Outer$1.class.

Detailed explanation

Applicability: a lambda needs a target type with exactly one abstract method. An anonymous class can implement interfaces with several methods, or extend a concrete or abstract class (e.g. new TimerTask() { ... }), and pass constructor arguments to the superclass.

this and scope: inside a lambda, this and super refer to the enclosing instance; the lambda body is lexically part of the enclosing method. Consequently a lambda cannot redeclare a local variable name that already exists in the enclosing scope. An anonymous class creates a new scope: this is the anonymous object, and its own fields or locals can shadow outer names.

State: an anonymous class can declare instance fields and helper methods, so it can hold mutable state between calls (a counter, a cache). A lambda has no fields of its own; it can only capture effectively final locals (both forms share this capture rule) or use enclosing fields.

Compilation and performance: every anonymous class becomes its own class file loaded at runtime, and every evaluation creates a new instance that also holds an implicit reference to the outer instance (if in an instance context), a classic memory-leak cause in listeners. Lambdas use invokedynamic and LambdaMetafactory; non-capturing ones are cached, and a lambda only captures this if it actually uses it. In practice lambdas give less class-loading overhead and better JIT optimisation, though the performance difference is rarely decisive.

Readability: lambdas are far shorter for single-method behaviour.

How it works

  1. Lambda: body becomes a synthetic method; invokedynamic creates the interface instance.
  2. Anonymous class: javac generates Outer$N.class with captured values and this$0 as fields.
  3. Each new of the anonymous class allocates a new object.
  4. Name lookup in a lambda resolves to the enclosing scope; in an anonymous class, to the class first.

Example

public class Greeter {
    String name = "outer";

    void demo() {
        Runnable lambda = () -> System.out.println(this.name);   // prints "outer"

        Runnable anon = new Runnable() {
            String name = "inner";
            @Override public void run() { System.out.println(this.name); } // prints "inner"
        };

        // Anonymous class with state and two methods: not possible as a lambda
        Iterator<Integer> counter = new Iterator<>() {
            private int i = 0;
            public boolean hasNext() { return i < 3; }
            public Integer next() { return i++; }
        };

        int x = 1;
        // Runnable bad = () -> { int x = 2; };   // compile error: x already defined
    }
}

Common mistakes

  • Believing lambdas are just syntactic sugar for anonymous classes.
  • Expecting this inside a lambda to refer to the lambda.
  • Forgetting anonymous classes in instance methods hold the outer reference.
  • Converting multi-method or stateful anonymous classes to lambdas.

How to answer in the interview

"A lambda can only implement a functional interface, while an anonymous class can implement any interface or extend a class, even an abstract one, and can have its own fields. Inside a lambda, this means the enclosing instance; inside an anonymous class, it's the anonymous object. A lambda shares the enclosing scope, so it can't redeclare a local variable name. The compiler generates a separate Outer$1.class for each anonymous class, while lambdas are linked at runtime with invokedynamic, which means less class loading. I still use an anonymous class when I need state, several methods or to extend an abstract class."

Likely follow-up questions

  • When would you still choose an anonymous class? For multiple methods, mutable state, or extending an abstract class.
  • Can both capture non-final locals? No, both require effectively final locals.
  • Which can cause memory leaks? Anonymous classes implicitly reference the outer instance; lambdas only if they use this.
