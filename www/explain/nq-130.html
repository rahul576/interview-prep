What is PriorityQueue, and how does it order elements?

Collections · concept · levels entry

In one line

A PriorityQueue returns elements by priority, not insertion order: it is a binary min-heap in an array, ordered by natural order or a Comparator, with O(log n) offer/poll and O(1) peek; its iteration is not sorted, it rejects null and it is not thread safe.

Detailed explanation

A normal queue is FIFO. A PriorityQueue instead always hands out the highest-priority element first, which by default means the smallest according to Comparable. Pass a Comparator to define a different priority, such as Comparator.reverseOrder() for a max-heap or Comparator.comparing(Task::deadline) for earliest deadline first.

Internally it is a binary heap stored in an Object[] queue. The tree is implicit: the children of index i are 2i + 1 and 2i + 2, and the parent is (i - 1) / 2. The heap property says every parent is less than or equal to its children, so the minimum is always at index 0.

  • offer(e): place at the end and sift up, swapping with the parent while smaller: O(log n).
  • poll(): remove the root, move the last element to the root and sift down, swapping with the smaller child: O(log n).
  • peek(): read index 0: O(1).
  • remove(Object) and contains: O(n) linear scan.
  • Building from a collection uses heapify in O(n).

Because only the root is guaranteed minimal, iterating, printing or toArray shows heap order, which looks partially shuffled. To get sorted output, repeatedly poll. Null elements are rejected and equal-priority elements have no FIFO guarantee; add a sequence number as a tie-breaker if you need stability. For concurrency use PriorityBlockingQueue.

Typical uses: task schedulers, Dijkstra and A* search, merging k sorted lists, event simulation and top-k problems.

How it works

  1. Append element at index size.
  2. Sift up while it is smaller than its parent.
  3. On poll, take index 0 and move last element to 0.
  4. Sift down by swapping with the smaller child.
  5. Grow the array when full.

Example

// k largest numbers: keep a min-heap of size k
static List<Integer> topK(int[] nums, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>(k);
    for (int n : nums) {
        heap.offer(n);
        if (heap.size() > k) heap.poll();   // remove smallest
    }
    List<Integer> result = new ArrayList<>(heap);
    result.sort(Comparator.reverseOrder());
    return result;
}

PriorityQueue<Task> tasks =
    new PriorityQueue<>(Comparator.comparing(Task::deadline));
PriorityQueue<Integer> pq = new PriorityQueue<>();
pq.offer(3); pq.offer(1); pq.offer(2);
System.out.println(pq);   // [1, 3, 2] - heap order, not sorted

Common mistakes

  • Expecting a sorted printout or for-each order.
  • Comparators written as a - b, which can overflow.
  • Changing an element's priority field while it is in the queue.
  • Assuming FIFO among equal priorities.

How to answer in the interview

"PriorityQueue is a queue where poll always returns the highest-priority element, which is the smallest by natural order by default, or whatever a Comparator says, for example reverseOrder for a max-heap. Internally it's a binary heap stored in an array, so offer and poll are log n and peek is constant. Only the head is guaranteed to be the minimum, so iterating or printing doesn't give sorted order. It doesn't allow null and isn't thread safe; PriorityBlockingQueue is the concurrent version. I use it for scheduling, Dijkstra, merging sorted lists and top-k problems."

Likely follow-up questions

  • k largest numbers? Min-heap of size k; poll when it exceeds k; O(n log k).
  • How to update a priority? Remove and re-insert (O(n)), or insert a new entry and skip stale ones.
  • Why does printing look unsorted? It shows the heap array, not sorted order.
