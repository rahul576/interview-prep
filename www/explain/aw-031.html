What is AWS Lambda versus EC2 from a beginner point of view: when would you choose each?

Cloud (AWS) · concept · levels entry

In one line

Lambda runs code on events without servers, scales automatically and bills per request and duration, ideal for spiky or event-driven workloads but limited to 15 minutes with cold starts; EC2 gives full servers you manage, billed while running, suited to long-running, steady or specialised workloads; containers on Fargate sit between.

Detailed explanation

Lambda is event-driven compute. You upload a function (or container image), choose memory (CPU scales with it), and attach triggers: API Gateway or a function URL for HTTP, S3 uploads, SQS messages, DynamoDB streams, EventBridge schedules. AWS runs as many copies as needed in parallel and scales to zero when idle. You pay per request and per millisecond of execution, with a free tier, so low or bursty traffic costs very little. There is no OS to patch.

Its limits: a maximum 15-minute run time per invocation; cold starts when a new execution environment initialises (usually tens to hundreds of milliseconds, more for large Java apps; mitigated by SnapStart or provisioned concurrency); limited local storage (up to 10 GB /tmp) and memory (up to 10 GB); concurrency limits per account; no GPUs; and an event-driven programming model, which needs care with database connections (use RDS Proxy).

EC2 gives you virtual servers with full control over OS, software, networking and hardware: GPUs, large memory, specialised instance families. It suits long-running processes, steady high traffic, software needing specific OS configuration, stateful workloads and legacy apps. You pay per second while the instance runs, whether busy or idle, and you are responsible for patching, scaling and availability.

Cost depends on the traffic pattern. For an API idle most of the day, Lambda is far cheaper. For a constant, high request rate keeping servers busy all day, EC2 or containers with Savings Plans usually win, because Lambda's per-invocation price adds up. ECS or EKS on Fargate offer serverless containers without the 15-minute limit, a common middle ground.

How it works

  1. Lambda: event arrives, environment starts or reused, handler runs, billed per ms.
  2. Concurrency scales with incoming events.
  3. EC2: launch instances, install software, run continuously.
  4. Scale EC2 with Auto Scaling groups.
  5. Choose based on duration, traffic pattern, control and team skills.

Example

# Lambda: resize images when uploaded to S3
import boto3
s3 = boto3.client("s3")

def handler(event, context):
    for rec in event["Records"]:
        bucket, key = rec["s3"]["bucket"]["name"], rec["s3"]["object"]["key"]
        obj = s3.get_object(Bucket=bucket, Key=key)
        thumb = make_thumbnail(obj["Body"].read())
        s3.put_object(Bucket=f"{bucket}-thumbs", Key=key, Body=thumb)

Lambda fits: thumbnails, webhooks, scheduled jobs, low-traffic APIs. EC2 fits: a video transcoding fleet running 24/7, a game server, a GPU training job, a commercial app requiring Windows services.

Common mistakes

  • Forcing long batch jobs into Lambda and hitting timeouts.
  • Ignoring cold starts for latency-sensitive Java APIs.
  • Assuming serverless is always cheaper at high steady load.
  • Opening a new database connection per invocation without RDS Proxy.

How to answer in the interview

"Lambda runs my code in response to events, an API request, an S3 upload or a queue message, without servers to manage. It scales automatically, even to zero, and I pay per request and duration, so it's very cheap for spiky or low traffic. The limits are a 15-minute maximum run time, cold starts and less control over the environment. EC2 gives me full servers where I control the OS and software, paying while they run, which suits long-running services, steady heavy traffic or special hardware like GPUs. Containers on Fargate sit in between."

Likely follow-up questions

  • Constant high-traffic API: which is cheaper? Usually EC2 or Fargate with Savings Plans, because Lambda's per-request cost adds up.
  • How do you reduce cold starts? Smaller packages, SnapStart for Java, provisioned concurrency.
  • What is reserved concurrency? A guaranteed and capped number of concurrent executions for a function.
