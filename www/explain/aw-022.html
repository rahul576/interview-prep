What is AWS KMS, and how is encryption at rest handled in AWS?

Cloud (AWS) · concept · levels entry

In one line

AWS KMS creates and controls encryption keys held in FIPS-validated HSMs that never leave KMS unencrypted; services encrypt at rest using KMS (often by default) via envelope encryption with data keys, and you choose AWS managed or customer managed keys, controlled by key policies and IAM and audited in CloudTrail.

Detailed explanation

Encryption at rest protects data on disks, backups and storage media. The hard part is not the algorithm (AES-256) but key management: who can use keys, how they are rotated and how usage is audited. KMS centralises this.

KMS keys (formerly CMKs) live in hardware security modules validated under FIPS 140-3; key material cannot be exported in plaintext. Services integrate directly: S3 encrypts all new objects by default (SSE-S3) and supports SSE-KMS; EBS volumes and snapshots, RDS and Aurora, DynamoDB (encrypted by default), EFS, SQS, Secrets Manager and many others encrypt with KMS when enabled, and accounts can turn on EBS encryption by default.

There are AWS owned keys (invisible, used by some services), AWS managed keys (aws/s3, aws/ebs, created automatically, rotated by AWS, but you cannot change their policy or share them cross-account), and customer managed keys. With customer managed keys you control the key policy, enable or schedule automatic rotation (yearly by default, configurable), grant cross-account use, separate key administrators from key users, and can disable a key in an emergency, making the data unreadable. Every Encrypt, Decrypt and GenerateDataKey call is logged in CloudTrail.

KMS uses envelope encryption. KMS can directly encrypt only up to 4 KB, so for real data a service calls GenerateDataKey: KMS returns a plaintext data key and the same key encrypted under the KMS key. The service encrypts data locally with the plaintext key, discards it, and stores the encrypted data key alongside the data. To read, it sends the encrypted data key to KMS for decryption, which requires permission. This is fast, scales and keeps the master key inside the HSM.

How it works

  1. Create a customer managed key with a key policy.
  2. Enable encryption on the resource using that key.
  3. The service requests a data key from KMS.
  4. Data is encrypted locally; the encrypted data key is stored with it.
  5. Reads require kms:Decrypt permission on the key.
  6. CloudTrail logs every key use.

Example

aws kms create-key --description "orders prod data" \
  --tags TagKey=Application,TagValue=orders
aws kms create-alias --alias-name alias/orders-prod --target-key-id <key-id>
aws kms enable-key-rotation --key-id <key-id>

aws ec2 enable-ebs-encryption-by-default
aws s3api put-bucket-encryption --bucket orders-data \
  --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":
  {"SSEAlgorithm":"aws:kms","KMSMasterKeyID":"alias/orders-prod"},"BucketKeyEnabled":true}]}'

Common mistakes

  • Thinking encryption at rest protects against a role that can read the data.
  • Key policies that lock out all administrators.
  • Using AWS managed keys when cross-account sharing is needed.
  • Scheduling key deletion without checking what uses the key.

How to answer in the interview

"KMS creates and manages encryption keys stored in HSMs that never leave KMS unencrypted. Most services encrypt at rest with KMS by default or with a setting: S3, EBS, RDS, DynamoDB and so on. I can use AWS managed keys, which are simple, or customer managed keys, where I control the key policy, rotation and who can use or administer the key, share it across accounts, and disable it in an emergency. Every use is logged in CloudTrail. Under the hood it's envelope encryption: KMS generates a data key that encrypts the data, and only the encrypted data key is stored with it."

Likely follow-up questions

  • Why a customer managed key? Control over policy, cross-account access, rotation settings, separation of duties and the ability to disable.
  • What is an S3 Bucket Key? A bucket-level data key that cuts KMS request costs for SSE-KMS.
  • What is CloudHSM? Dedicated single-tenant HSMs you manage, for strict compliance needs.
