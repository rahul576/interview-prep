How would you calculate the minimum path sum?

DSA: Algorithms & DP · scenario · levels mid

In one line

The minimum path sum is computed by filling a DP table where each cell stores the smallest sum to reach it: minSum[i][j] = grid[i][j] + min(minSum[i-1][j], minSum[i][j-1]), with edge cells having only one predecessor.

Detailed explanation

This is the LeetCode-style "Minimum Path Sum" problem: given an m×n grid of non-negative numbers, find a path from the top-left to the bottom-right moving only right or down that minimises the sum of values along it. Rather than enumerating paths, we compute for every cell the best accumulated sum to reach it, a bottom-up dynamic programming approach.

The edge cells matter. The top-left cell's sum is its own value. Any cell in the first row can only be reached from its left neighbour, and any cell in the first column only from the cell above, so their sums are cumulative totals. Every interior cell has two predecessors and takes the minimum. Because cells are processed in row-major order, both predecessors are always already computed when we need them.

For memory, notice that row i only needs row i-1. A 1D array of size n works: before updating dp[j], it still holds the value from the row above (the "top"), and dp[j-1] already holds the current row's value (the "left"). If modifying the input is allowed, you can even store sums in place in the grid itself. Both approaches keep time at O(m·n).

How it works

  1. Let m rows and n columns; validate the grid is non-empty.
  2. Initialise the top-left with grid[0][0].
  3. Accumulate along the first row and first column.
  4. For each interior cell, add the grid value to the minimum of top and left.
  5. Read the result from the bottom-right cell.

Example

int minPathSum(int[][] g) {
    int m = g.length, n = g[0].length;
    for (int i = 0; i < m; i++) {
        for (int j = 0; j < n; j++) {
            if (i == 0 && j == 0) continue;
            int top  = i > 0 ? g[i - 1][j] : Integer.MAX_VALUE;
            int left = j > 0 ? g[i][j - 1] : Integer.MAX_VALUE;
            g[i][j] += Math.min(top, left);   // in place
        }
    }
    return g[m - 1][n - 1];
}

For [[1,3,1],[1,5,1],[4,2,1]] the filled table is [[1,4,5],[2,7,6],[6,8,7]], so the answer is 7 via 1 → 3 → 1 → 1 → 1.

Common mistakes

  • Initialising out-of-range neighbours with 0 instead of "infinity", which wrongly makes edges cheap.
  • Overwriting the input grid when the caller still needs it.
  • Mixing up which array slot is "top" and which is "left" in the 1D version.
  • Not mentioning complexity or the space optimisation.

How to answer in the interview

"I'd fill a table row by row. The top-left cell is its own value, the first row only gets contributions from the left and the first column only from above, so those are running sums. Every other cell is its value plus the minimum of the cell above and the cell to the left. The bottom-right then holds the minimum path sum. For the classic 3 by 3 example the answer is 7. Time is O(m times n), and I can bring memory down to a single array of length n, or reuse the grid if mutation is acceptable."

Likely follow-up questions

  • What changes if some cells are blocked? Treat blocked cells as infinity and skip them; if the end stays infinity, no path exists.
  • Why does the 1D array work? Before overwriting dp[j] it still holds the value from the previous row.
  • How do you return the path too? Keep a parent matrix or backtrack using the dp values.
