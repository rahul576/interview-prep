What are Gang of Four (GoF) design patterns?

Design Patterns · concept · levels entry, mid

In one line

The Gang of Four (GoF) patterns are the 23 design patterns catalogued in the 1994 book Design Patterns: Elements of Reusable Object-Oriented Software by Gamma, Helm, Johnson and Vlissides, grouped into creational, structural and behavioural patterns.

Detailed explanation

In the early 1990s, these four authors noticed that experienced object-oriented designers kept solving the same problems in the same ways. They documented 23 of those solutions in a standard format: name, intent, motivation, structure, participants, consequences, implementation and known uses. The consequences section matters most: every pattern trades something (more classes, more indirection) for something else (flexibility, decoupling).

The catalogue is split into three groups:

  • Creational (5): Abstract Factory, Builder, Factory Method, Prototype, Singleton.
  • Structural (7): Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy.
  • Behavioural (11): Chain of Responsibility, Command, Interpreter, Iterator, Mediator, Memento, Observer, State, Strategy, Template Method, Visitor.

Two design principles from the book underpin most patterns: "program to an interface, not an implementation" and "favour object composition over class inheritance."

A pattern is a design idea, not code to copy. The same Strategy can be a class hierarchy in 1994-style C++ or a one-line lambda in modern Java. The lasting value is shared vocabulary: "put a decorator around the client for retries" tells a colleague the whole structure instantly.

The patterns are visible everywhere in Java: Iterator in collections, Decorator in java.io, Observer in listeners, Proxy in java.lang.reflect.Proxy, Template Method in AbstractList, Strategy in Comparator; and in Spring: Proxy for AOP, Factory in BeanFactory, Template Method in JdbcTemplate, Observer in application events.

How it works

  1. Identify the design problem (creation, composition or interaction).
  2. Look up the pattern whose intent matches.
  3. Read its consequences to judge if the trade-off fits.
  4. Implement it idiomatically for your language.

Example

// Iterator (behavioural) – built into the JDK
Iterator<String> it = names.iterator();
while (it.hasNext()) System.out.println(it.next());

// Decorator (structural)
Reader r = new BufferedReader(new FileReader("notes.txt"));

// Factory Method (creational)
NumberFormat inr = NumberFormat.getCurrencyInstance(new Locale("en", "IN"));

Common mistakes

  • Saying the GoF "invented" the patterns; they documented existing practice.
  • Treating the 23 as the only patterns (enterprise, concurrency and cloud patterns exist).
  • Copying UML diagrams literally instead of adapting to modern language features.
  • Using patterns to look sophisticated rather than to solve a problem.

How to answer in the interview

"The Gang of Four are Erich Gamma, Richard Helm, Ralph Johnson and John Vlissides, who wrote Design Patterns in 1994. The book catalogues 23 patterns, proven solutions to recurring object-oriented design problems, grouped as creational, structural and behavioural. Each comes with trade-offs, so it's a design idea, not code to paste. For me the biggest value is vocabulary: saying 'use a strategy here' communicates a whole design. And they're all over the JDK and Spring, like Iterator, Decorator in java.io, and proxies for transactions."

Likely follow-up questions

  • Which patterns are in the JDK or Spring? Iterator, Decorator (I/O), Strategy (Comparator), Proxy (AOP), Template Method (JdbcTemplate), Observer (events).
  • Which GoF patterns are less used today? Interpreter and Flyweight are niche; Visitor is often replaced by pattern matching.
  • What principle does the book favour? Composition over inheritance, and programming to interfaces.
