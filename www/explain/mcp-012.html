What is elicitation in MCP, and what security rules apply to it?

MCP Servers · concept · levels mid, senior

In one line

Elicitation lets a server ask the user for more information mid-operation through the client: form mode sends a message and a restricted flat JSON Schema, URL mode sends the user to a web page for sensitive flows; users can accept, decline or cancel, and servers must never request secrets or payment data via forms.

Detailed explanation

Without elicitation, a tool missing information has two bad options: fail, or guess. Elicitation, added in the 2025-06-18 revision, lets the server pause and ask the user through the host. Examples: a deployment tool asks which environment to target; a booking tool asks the user to confirm one of three slots; a migration tool asks for confirmation before a large change.

Form mode. The server sends an elicitation/create request with a human-readable message and a requestedSchema. The schema is deliberately restricted: a flat object with primitive properties only, strings (with optional formats like email, date, uri), numbers/integers, booleans and enums, no nested objects or arrays of objects. That keeps forms simple for hosts to render safely. The user responds with one of three actions: accept (with content matching the schema), decline (explicitly refused) or cancel (dismissed without choosing). The server must handle all three sensibly.

URL mode, added in the 2025-11-25 revision, directs the user to a URL opened in their browser for interactions that should not pass through the MCP client or model at all: OAuth consent for a third-party service, entering API credentials, or making a payment. The sensitive data goes straight from the user to the server's web page.

Security rules: servers must not request passwords, API keys, tokens or payment details in form mode. Hosts must clearly show which server is asking, let users review and change responses before sending, allow declining at any time, and should guard against servers spamming requests. For URL mode, hosts should show the full URL and domain and require explicit consent before opening it.

How it works

  1. Client advertises the elicitation capability (form and/or url).
  2. During a tool call, the server needs input and sends elicitation/create.
  3. Host renders a form (form mode) or asks consent to open a URL (URL mode), naming the server.
  4. User accepts, declines or cancels.
  5. Server continues with the data, falls back, or aborts cleanly.

Example

{"jsonrpc":"2.0","id":21,"method":"elicitation/create","params":{
  "mode":"form",
  "message":"Which environment should I deploy build 4812 to?",
  "requestedSchema":{"type":"object",
    "properties":{
      "environment":{"type":"string","enum":["staging","production"]},
      "notify_team":{"type":"boolean","default":true}},
    "required":["environment"]}}}

→ {"jsonrpc":"2.0","id":21,"result":{"action":"accept",
     "content":{"environment":"staging","notify_team":true}}}

Common mistakes

  • Asking for an API key or password through a form.
  • Treating decline and cancel as errors or retrying in a loop.
  • Using nested schemas the host cannot render.
  • Hosts not displaying which server is requesting information.

How to answer in the interview

"Elicitation lets a server ask the user for more information during an operation, through the client, instead of failing or guessing, like asking which environment to deploy to. In form mode the server sends a message and a restricted, flat JSON schema with simple fields and enums, the host renders a form, and the user can accept, decline or cancel; the server must handle all three. URL mode sends the user to a web page for sensitive flows like OAuth consent, credentials or payments, so that data never passes through the client or the model. Servers must not request secrets or payment details in form mode, and hosts must show which server is asking."

Likely follow-up questions

  • Why secrets via URL mode? The data goes directly to the server's page and never enters the client, logs or model context.
  • Elicitation versus asking in chat? Elicitation is structured, validated and clearly attributed to a server.
  • Does every host support it? No; check capabilities and provide a fallback.
