Design product search for an e-commerce site with filters, facets and ranking.

Classic Design Problems · design · levels entry, mid, senior

In one line

E-commerce search uses a dedicated search index (Elasticsearch/OpenSearch) fed by a CDC/event indexing pipeline, with text analysis (stemming, synonyms, typo tolerance), aggregations for facets, ranking that blends relevance and business signals, and replicas and caching for scale.

Detailed explanation

The catalogue database is optimised for transactions, not for "red running shoes under 2000 with 4+ stars". A search engine with an inverted index handles full-text matching, filtering and aggregations in milliseconds.

Indexing pipeline: catalogue, price and stock changes flow via CDC (Debezium) or domain events into an indexer that builds a denormalised product document. Full reindexes build a new index and switch an alias atomically, giving zero-downtime schema changes.

Text analysis makes matching forgiving: tokenising, lowercasing, stemming ("running" to "run"), synonyms ("sofa" = "couch"), fuzzy matching for typos, and language-specific analysers. Brand and category fields are stored as keyword types for exact filtering.

Facets (brand counts, price buckets, sizes) come from aggregations on keyword or numeric fields. Filters go in the filter clause, which does not affect scoring and is cached.

Ranking starts with BM25 text relevance plus field boosts (title over description), then blends business signals: popularity, conversion rate, stock, margin, recency. Mature teams use learning-to-rank models trained on clicks and purchases, and hybrid search combining keyword and vector (semantic) retrieval. Query understanding extracts category, colour and price from the text.

How it works

  1. Catalogue change -> CDC event -> indexer enriches with price, stock, ratings -> upsert document.
  2. User query -> query understanding (spell-correct, detect "shoes", "red", "<2000").
  3. Search: bool query with text must, structured filters, aggregations for facets.
  4. Rerank top results with business signals or an LTR model.
  5. Return results plus facet counts; log impressions, clicks and purchases.
  6. Analytics on zero-result and low-CTR queries improve synonyms and ranking.

Example

POST /products/_search
{
  "query": { "function_score": {
    "query": { "bool": {
      "must":   { "multi_match": { "query": "running shoes", "fields": ["title^3", "brand^2", "description"], "fuzziness": "AUTO" } },
      "filter": [ { "term": { "color": "red" } }, { "range": { "price": { "lte": 2000 } } }, { "term": { "in_stock": true } } ] } },
    "field_value_factor": { "field": "popularity", "modifier": "log1p" } } },
  "aggs": {
    "brands": { "terms": { "field": "brand" } },
    "price":  { "range": { "field": "price", "ranges": [ {"to": 1000}, {"from": 1000, "to": 2000}, {"from": 2000} ] } } }
}

Common mistakes

  • Querying the relational database with LIKE '%term%'.
  • Putting filters in scoring queries, losing caching and distorting relevance.
  • Reindexing in place instead of building a new index behind an alias.
  • Ranking purely by text relevance and ignoring stock and conversion.
  • Not measuring search quality at all.

How to answer in the interview

"I'd use OpenSearch or Elasticsearch as a separate search index, fed by CDC from the catalogue so price and stock stay fresh, with full rebuilds swapped in through an alias. Analysers handle stemming, synonyms and typos. Facets come from aggregations on keyword fields, and filters use non-scoring cached clauses. Ranking blends BM25 relevance with popularity, conversion and stock, and later a learning-to-rank or hybrid vector model trained on click data. I'd scale with replicas, cache popular queries, and track zero-result queries to improve synonyms."

Likely follow-up questions

  • How do you measure a ranking change? A/B test on conversion and revenue per search, offline with NDCG on judged queries.
  • How fresh must stock be? Near real-time via CDC; re-check at add-to-cart.
  • Keyword vs vector search? Hybrid: keyword for precision on SKUs and brands, vectors for intent.
