How do tool results work in MCP, and what is structured content?

MCP Servers · concept · levels mid, senior

In one line

A tools/call result contains a content array of blocks (text, image, audio, embedded resources, resource links), optional structuredContent JSON that must match the tool's outputSchema, and an isError flag; for compatibility, structured data should also be serialised as JSON in a text block.

Detailed explanation

Tool results are designed for two consumers: the model, which reads content, and code (hosts, agents, UIs), which benefits from typed data.

The content array holds one or more blocks:

  • text: the most common, readable by the model;
  • image and audio: base64-encoded data with a mimeType;
  • embedded resources: a full resource (URI plus text or blob) inlined in the result;
  • resource links: a URI, name and MIME type pointing to data the client can fetch later with resources/read, instead of inlining large payloads.

Blocks can carry annotations like intended audience (user or assistant) and priority.

Since the 2025-06-18 revision, tools may declare an outputSchema and return structuredContent, a JSON object. The rules: if an output schema is declared, the server must return structured content conforming to it, and clients should validate it. This makes outputs machine-readable, so an agent's code or a UI can use result.structuredContent.total without parsing prose.

For backward compatibility, a tool returning structured content should also include the same data serialised as JSON in a text block, so older clients and the model still see it.

Finally, isError: true marks a tool execution error: the tool ran but failed, with the content explaining why, which is shown to the model so it can recover.

How it works

  1. Server executes the tool.
  2. Builds content blocks for the model (concise text, maybe a resource link).
  3. If outputSchema exists, builds structuredContent and validates it before sending.
  4. Adds a text block with the JSON for older clients.
  5. Sets isError on failure.
  6. Client validates structured content and passes content to the model.

Example

{
  "jsonrpc": "2.0", "id": 12,
  "result": {
    "content": [
      { "type": "text", "text": "{\"total\":2412,\"errors_by_type\":{\"timeout\":1800,\"5xx\":612}}" },
      { "type": "resource_link", "uri": "logs://checkout/2026-11-20/errors.ndjson",
        "name": "Full error log", "mimeType": "application/x-ndjson" }
    ],
    "structuredContent": { "total": 2412, "errors_by_type": { "timeout": 1800, "5xx": 612 } },
    "isError": false
  }
}

Common mistakes

  • Declaring an outputSchema but returning data that does not match.
  • Returning only structuredContent, so older clients show nothing.
  • Inlining megabytes of data instead of a resource link.
  • Throwing an exception instead of returning isError: true with a helpful message.

How to answer in the interview

"A tools/call result has a content array: text, images or audio as base64 with a MIME type, embedded resources, or resource links that point to a URI the client can read later instead of inlining big data. Since the 2025-06-18 revision a tool can declare an outputSchema and return structuredContent, a JSON object that must match the schema and that clients should validate, so code and agents get typed results instead of parsing prose. For compatibility, the same JSON should also be in a text block. And isError marks an execution failure, which the model sees and can recover from."

Likely follow-up questions

  • When return a resource link? When data is large or only sometimes needed, like full logs or exports.
  • Does the model see structuredContent? Depends on the host; the text block guarantees it can.
  • Can results include images? Yes, base64 image blocks, e.g. a chart or screenshot.
