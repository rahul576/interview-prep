How do you undo changes in Git: reset, revert, restore and reflog?

Git · concept · levels entry, mid

In one line

git revert adds a new commit that undoes an old one (safe on shared branches), git reset moves the branch pointer back (soft, mixed, hard), git restore discards or unstages uncommitted changes, and git reflog lets you recover commits you thought were lost.

Detailed explanation

Choosing the right undo command depends on two questions: has the change been committed? and has it been pushed and shared?

For uncommitted changes, git restore <file> throws away edits in the working tree (replacing the older git checkout -- file), and git restore --staged <file> unstages a file while keeping the edits. These touch nothing in history.

For local, unpushed commits, git reset moves the current branch. --soft keeps the undone changes staged (handy for squashing), --mixed (default) keeps them unstaged, and --hard discards them along with uncommitted work. Resetting commits others have pulled forces a git push --force that breaks their clones; never do it on shared branches.

For pushed, shared commits, git revert <sha> creates a new commit with the inverse changes, so history only moves forward. Reverting a merge commit needs -m 1.

git reflog records every position HEAD has had locally, including after resets and rebases. Orphaned commits survive until garbage collection (reflog entries expire after roughly 30 to 90 days by default), so a bad reset --hard is usually recoverable.

How it works

  1. Uncommitted edit: git restore file or git restore --staged file.
  2. Wrong last commit message or missing file: git commit --amend (only if unpushed).
  3. Unpushed commits to undo: git reset --soft|--mixed|--hard <target>.
  4. Pushed commit to undo: git revert <sha> and push normally.
  5. Lost something: git reflog, find the entry, git reset --hard <sha> or create a branch at it.

Example

# Undo a bad commit already on main
git revert 3f2a91c
git push

# Squash my last 3 local commits into one
git reset --soft HEAD~3
git commit -m "Add order export"

# Oops: reset --hard removed work; recover it
git reflog
# a1b2c3d HEAD@{1}: commit: WIP payment retry
git branch rescue a1b2c3d

Common mistakes

  • Using reset --hard with uncommitted work you wanted to keep.
  • Resetting and force-pushing a shared branch.
  • Thinking a revert removes a secret; it stays in history.
  • Forgetting -m 1 when reverting a merge commit.

How to answer in the interview

"It depends on whether the change is committed and shared. Local edits: git restore, or --staged to unstage. Unpushed commits: git reset, where soft keeps changes staged, mixed keeps them in the working tree and hard throws them away. Pushed commits on a shared branch: git revert, which adds an undo commit without rewriting history. If I lose commits after a bad reset or rebase, git reflog shows where HEAD has been, so I can branch from the lost commit."

Likely follow-up questions

  • How do you remove a pushed secret? Rotate it immediately first, then rewrite history with git filter-repo or BFG and force-push, and ask others to re-clone.
  • What is the difference between reset and checkout of a commit? Reset moves the branch; checking out a commit moves only HEAD (detached HEAD).
  • Is --force-with-lease safe? Safer: it refuses to overwrite remote commits you have not seen.
