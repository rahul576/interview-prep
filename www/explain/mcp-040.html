What are MCP extensions, and what is MCP Apps?

MCP Servers · concept · levels mid, senior

In one line

Extensions add optional features outside the core spec, negotiated through an extensions map in capabilities (so not every host supports them), such as Tasks, enterprise-managed authorization and OAuth client credentials; MCP Apps is an extension letting servers ship interactive UIs that hosts render sandboxed, communicating through the host.

Detailed explanation

Why extensions. The core protocol must stay small and stable so every client and server can implement it. Yet many valuable features only matter to some environments: enterprise identity integration, rich UIs, long-running jobs. Extensions, formalised (per the reference material) in the 2026-07-28 revision, let such features be specified, versioned and adopted independently of core revisions.

Negotiation. Both sides advertise supported extensions in an extensions map within their capabilities. An extension is used only when both declare it. Consequently, you cannot assume any particular host supports a given extension, and servers must work sensibly without it.

Examples of official extensions:

  • Tasks: durable handles for long-running operations, moved out of core.
  • Enterprise-managed authorization: lets an organisation's identity provider control which MCP servers users can access, instead of per-user, per-server OAuth consent.
  • OAuth client credentials: machine-to-machine access for agents and backend services without a user present.

MCP Apps lets a server provide interactive user interfaces, such as a chart, a form, a map, a seat picker or a dashboard, as UI resources (HTML) that a supporting host renders inside the conversation. Security model: the UI runs sandboxed, typically in an iframe with restricted permissions and content security policy, and it does not get direct access to the host or other servers. It communicates via messages through the host, for example to call the server's tools or send a message to the conversation, so the host keeps control and can require user consent.

Fallback. Servers should always return a useful text or structured result too, so hosts without MCP Apps support still work.

How it works

  1. Client and server list supported extensions in capabilities.
  2. Both sides activate only mutually supported extensions.
  3. For MCP Apps, a tool result references a UI resource.
  4. Host fetches the UI, renders it in a sandboxed iframe.
  5. UI sends requests to the host (e.g. call a tool); host mediates and returns results.
  6. Hosts without support display the text/structured fallback.

Example

{
  "capabilities": {
    "tools": {},
    "extensions": {
      "io.modelcontextprotocol/tasks": {},
      "io.modelcontextprotocol/ui": {}
    }
  }
}
Tool result: text "Found 3 flights under ₹6,000" + structured list
             + reference to ui://flights/picker (rendered only by hosts supporting MCP Apps)

Common mistakes

  • Building a server that only works with one extension-capable host.
  • No text fallback for UI results.
  • Treating the UI as trusted code with host privileges.
  • Using extensions without checking negotiated capabilities.

How to answer in the interview

"Extensions, formalised in the 2026-07-28 revision, add optional functionality outside the core spec so not every implementation has to support it. They're negotiated through an extensions map in capabilities, and only used when both sides declare them, so you can't assume a host supports one. Official examples include Tasks, enterprise-managed authorization and OAuth client credentials. MCP Apps is an extension that lets servers provide interactive UIs, like a chart or form, as UI resources the host renders in the conversation. The UI runs sandboxed, typically in an iframe, and communicates through the host, which keeps control. Servers should still return text for hosts without support."

Likely follow-up questions

  • Fallback for hosts without MCP Apps? A text summary plus structured content with the same information.
  • Why is enterprise-managed auth useful? Central admin control over which servers users may connect, with SSO.
  • Can companies write private extensions? Yes, with their own namespaced identifiers.
