How do you use VPC Flow Logs to troubleshoot connectivity?

Cloud (AWS) · scenario · levels mid

In one line

VPC Flow Logs capture metadata about IP traffic (addresses, ports, protocol, bytes, ACCEPT or REJECT) per VPC, subnet or ENI to CloudWatch Logs, S3 or Firehose; to troubleshoot, look for the flow: REJECT points to security groups or NACLs, no record suggests routing or DNS, and one-way ACCEPT often means a stateless NACL blocking return traffic.

Detailed explanation

Flow logs are created at three levels: a VPC (all ENIs), a subnet, or a single network interface, and can also cover Transit Gateway attachments. Records are aggregated over an interval (1 or 10 minutes) and delivered to CloudWatch Logs, S3 (cheap, queryable with Athena) or Kinesis Data Firehose. The default format includes srcaddr, dstaddr, srcport, dstport, protocol, packets, bytes, action and log-status; custom formats add fields such as vpc-id, subnet-id, instance-id, tcp-flags, pkt-srcaddr, flow-direction and traffic-path. They contain no payloads, and some traffic is not logged, such as to the Amazon DNS resolver, IMDS or the DHCP service.

The troubleshooting logic:

  • REJECT on the request: a security group inbound rule or a NACL blocks it. Flow logs do not say which, so check both.
  • ACCEPT inbound but REJECT on the response: almost always a NACL, because NACLs are stateless and need explicit rules for the ephemeral return ports (1024-65535). Security groups are stateful and allow return traffic automatically.
  • No records at all between the two addresses: traffic never reached the interface, suggesting routing (missing route, wrong route table, missing peering or TGW route), DNS resolving to the wrong IP, or the client never sending.
  • ACCEPT both ways but the app still fails: the network is fine; look at the application, TLS or the listening port.

Complementary tools: Reachability Analyzer checks the path configuration between two resources without sending traffic and names the blocking component; Network Access Analyzer finds unintended access paths; Traffic Mirroring captures actual packets when payloads are needed.

How it works

  1. Enable flow logs on the VPC, subnet or ENI.
  2. Reproduce the failing connection.
  3. Query records for the source and destination IPs and port.
  4. Interpret ACCEPT, REJECT or absence.
  5. Fix the security group, NACL, route or DNS.
  6. Confirm with Reachability Analyzer.

Example

aws ec2 create-flow-logs --resource-type VPC --resource-ids vpc-0abc \
  --traffic-type ALL --log-destination-type cloud-watch-logs \
  --log-group-name /vpc/flow/prod --deliver-logs-permission-arn arn:aws:iam::123456789012:role/flowlogs
# Logs Insights: traffic between app and database
fields @timestamp, srcAddr, srcPort, dstAddr, dstPort, action
| filter (srcAddr = "10.0.1.25" and dstAddr = "10.0.3.40")
    or (srcAddr = "10.0.3.40" and dstAddr = "10.0.1.25")
| sort @timestamp desc
| limit 50

Result: 10.0.1.25:51544 -> 10.0.3.40:5432 ACCEPT, then 10.0.3.40:5432 -> 10.0.1.25:51544 REJECT. The app subnet's NACL lacked an inbound rule for ephemeral ports; adding it fixed the issue.

Common mistakes

  • Expecting payloads or HTTP details in flow logs.
  • Blaming security groups for return-traffic rejects caused by NACLs.
  • Enabling flow logs only after the incident with no baseline.
  • Sending huge volumes to CloudWatch without retention.

How to answer in the interview

"Flow logs record metadata about IP traffic, source and destination, ports, protocol, bytes and ACCEPT or REJECT, for a VPC, subnet or network interface, delivered to CloudWatch Logs or S3. When an app can't connect, I query the flow between the two IPs. No record suggests routing or DNS; a REJECT points to a security group or NACL; and an accepted request with a rejected response usually means a stateless NACL missing the ephemeral port range. I query with Logs Insights or Athena. They have no payloads, so I also use Reachability Analyzer to check the path without sending traffic."

Likely follow-up questions

  • Why ACCEPT for the request but REJECT for the response? A stateless NACL is missing the outbound or inbound ephemeral port rule.
  • What does Reachability Analyzer add? It analyses configuration and names the blocking component.
  • How do you keep flow log costs down? S3 destination with Athena, 10-minute aggregation, targeted ENIs, lifecycle rules.
