How do you call other services from Spring Boot? Compare RestTemplate, WebClient, RestClient and Feign.

Spring Boot · concept · levels mid, senior

In one line

RestTemplate is the classic blocking client (maintenance mode), WebClient is the non-blocking reactive client, RestClient (Spring 6.1) is the modern fluent synchronous client, and OpenFeign / HTTP interfaces are declarative; whichever you choose, configure timeouts, pooling, retries, circuit breakers and tracing.

Detailed explanation

RestTemplate has existed since Spring 3. It uses a template-method API (getForObject, exchange) and blocks the calling thread. It still works and is not removed, but it is in maintenance mode; new features go to the newer clients, and the Spring team has signalled its eventual deprecation.

WebClient comes with Spring WebFlux and returns Mono/Flux. It is non-blocking, built on Reactor Netty by default, and shines when you need high concurrency with few threads, streaming responses, or many parallel calls combined reactively. In a blocking MVC app you can use it with .block(), but you pay for the reactive dependency and complexity.

RestClient, added in Spring Framework 6.1 / Boot 3.2, gives a fluent API similar to WebClient but synchronous, sharing RestTemplate's infrastructure (message converters, request factories, interceptors). It is my default for blocking code, especially with virtual threads, where blocking is cheap.

Declarative clients: Spring Cloud OpenFeign generates a client from an annotated interface and integrates with load balancing and circuit breakers. Spring's own HTTP interfaces (@HttpExchange, @GetExchange) do the same backed by RestClient or WebClient, without Spring Cloud. OpenFeign itself is now feature-complete, with the Spring Cloud team recommending HTTP interfaces for new code.

Operational concerns matter more than API style. Set connect and read timeouts explicitly (JDK HttpURLConnection defaults to no timeout), use connection pooling (Apache HttpClient 5 or Reactor Netty), add retries with backoff only for idempotent calls, a circuit breaker (Resilience4j), and use the Boot-provided builders (RestClient.Builder, WebClient.Builder) so Micrometer observations and trace headers are propagated.

How it works

  1. Inject the auto-configured builder (it carries observation and converters).
  2. Configure base URL, timeouts and a pooled request factory.
  3. Build the client or an HTTP interface proxy.
  4. Wrap calls with retry and circuit breaker policies.
  5. Map error status codes to domain exceptions.

Example

@Bean
RestClient inventoryClient(RestClient.Builder builder) {
    var settings = ClientHttpRequestFactorySettings.defaults()
        .withConnectTimeout(Duration.ofSeconds(1))
        .withReadTimeout(Duration.ofSeconds(2));
    return builder.baseUrl("http://inventory")
        .requestFactory(ClientHttpRequestFactoryBuilder.detect().build(settings))
        .build();
}

StockDto stock = inventoryClient.get().uri("/stock/{sku}", sku)
    .retrieve()
    .onStatus(s -> s.value() == 404, (req, res) -> { throw new UnknownSkuException(sku); })
    .body(StockDto.class);

// Declarative HTTP interface on top of RestClient
interface InventoryApi { @GetExchange("/stock/{sku}") StockDto stock(@PathVariable String sku); }

@Bean
InventoryApi inventoryApi(RestClient inventoryClient) {
    return HttpServiceProxyFactory.builderFor(RestClientAdapter.create(inventoryClient))
        .build().createClient(InventoryApi.class);
}

Common mistakes

  • No timeouts configured, so a hung dependency exhausts threads.
  • Creating a new client per request, losing pooling.
  • Calling .block() inside a WebFlux event loop.
  • Retrying non-idempotent POSTs.
  • Using new RestTemplate() instead of the builder, losing tracing.

How to answer in the interview

"RestTemplate is the classic blocking client and is in maintenance mode, so I don't use it for new code. WebClient is the reactive non-blocking client from WebFlux, which I'd choose for high concurrency, streaming or reactive stacks. RestClient, from Spring 6.1, gives a modern fluent synchronous API and is my default for blocking services, especially with virtual threads. For many endpoints I like declarative clients, Spring HTTP interfaces or OpenFeign, where I write an interface and the client is generated. Whatever the client, I set connect and read timeouts, use connection pooling, add retries with backoff for idempotent calls and a circuit breaker, and build it from Boot's builder so trace headers propagate."

Likely follow-up questions

  • What default timeout does a client have if you configure none? Often infinite or very long, which ties up threads and cascades failures.
  • Feign or HTTP interfaces? HTTP interfaces for new code without Spring Cloud; Feign if already invested.
  • How do you test a client? WireMock or MockRestServiceServer with RestClient.
