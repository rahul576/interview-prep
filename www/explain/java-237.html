What are the four kinds of method references?

Java 8+ Features · concept · levels mid, senior

In one line

The four kinds of method references are: static (Integer::parseInt), bound instance on a particular object (System.out::println), unbound instance on an arbitrary object of a type (String::toUpperCase), and constructor (ArrayList::new).

Detailed explanation

A method reference is shorthand for a lambda whose body only calls one existing method. The compiler matches the referenced method's signature against the target functional interface, so the same syntax can fit different interfaces.

  1. Static method reference, ClassName::staticMethod: the lambda's arguments become the method's arguments. Integer::parseInt as a Function<String,Integer> equals s -> Integer.parseInt(s).
  2. Bound instance method reference, expression::method: the receiver object is evaluated once, when the reference is created, and fixed. System.out::println equals x -> System.out.println(x); this::validate and order::addItem are common.
  3. Unbound instance method reference, ClassName::instanceMethod: no receiver yet; the first lambda argument becomes the receiver and the remaining arguments are passed on. String::toUpperCase as Function<String,String> equals s -> s.toUpperCase(); String::compareToIgnoreCase as a Comparator<String> equals (a, b) -> a.compareToIgnoreCase(b).
  4. Constructor reference, ClassName::new: calls a matching constructor. ArrayList::new can be a Supplier<List<T>> or an IntFunction<List<T>> (capacity). Array constructors work too: String[]::new, used in stream.toArray(String[]::new).

The difference between bound and unbound matters: with a bound reference, a null receiver throws NullPointerException immediately at creation; and if the expression has side effects it runs once, not per call.

How it works

  1. The compiler determines the target type (e.g. Function<String,Integer>).
  2. It searches for a method compatible with the functional method's parameters.
  3. For unbound references it also tries using the first parameter as receiver.
  4. It generates the equivalent lambda linkage via invokedynamic.

Example

Function<String, Integer> parse = Integer::parseInt;          // static
Consumer<String> print = System.out::println;                 // bound
Function<String, String> upper = String::toUpperCase;         // unbound
BiFunction<String, String, Boolean> starts = String::startsWith; // unbound, 2 args
Supplier<List<String>> newList = ArrayList::new;               // constructor
Function<String, Customer> create = Customer::new;             // Customer(String name)

List<String> names = employees.stream()
    .sorted(Comparator.comparing(Employee::getSalary))         // unbound
    .map(Employee::getName)
    .toList();
String[] arr = names.stream().toArray(String[]::new);          // array constructor

Common mistakes

  • Confusing bound and unbound references with the same method name.
  • Assuming a bound receiver is re-evaluated on each call.
  • Ambiguity errors when a class has both a static and an instance method that fit.
  • Using a method reference where a lambda would be clearer (e.g. with extra logic).

How to answer in the interview

"There are four kinds. A static method reference like Integer::parseInt. A bound instance method reference on a particular object, like System.out::println, where the receiver is fixed when the reference is created. An unbound instance method reference on an arbitrary object of a type, like String::toUpperCase, where the first lambda argument becomes the receiver. And a constructor reference, like ArrayList::new, including array constructors like String[]::new. Each is shorthand for a lambda that only calls that method, and the compiler matches it to the target functional interface."

Likely follow-up questions

  • Which kind is Comparator.comparing(Employee::getSalary)? Unbound instance method reference.
  • When is the receiver of a bound reference evaluated? Once, when the reference expression is evaluated.
  • What does String[]::new map to? An IntFunction<String[]>.
