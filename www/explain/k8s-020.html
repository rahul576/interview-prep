What is the difference between labels and annotations, and what are finalizers?

Kubernetes · concept · levels entry, mid

In one line

Labels are short key-value pairs that identify objects and are used by selectors; annotations hold non-identifying metadata for tools and can be large; finalizers are keys in metadata.finalizers that block deletion until a controller finishes cleanup and removes them, and stuck finalizers leave objects Terminating.

Detailed explanation

Labels (app=orders, env=prod, team=payments) are indexed and queryable. Everything that groups objects uses them: Service and Deployment selectors, NetworkPolicies, PDBs, topology spread, node selection, kubectl get -l, and cost reporting. Keys can have a prefix (app.kubernetes.io/name) and values are limited to 63 characters, so labels stay small and stable. The recommended app.kubernetes.io/* labels make tooling consistent.

Annotations are not used for selection. They carry information for humans and tools: kubectl.kubernetes.io/last-applied-configuration, Prometheus scrape hints, ingress or load balancer controller options, cert-manager issuers, checksum/config hashes to trigger rollouts, change ticket or owner contact. They can be much larger (total annotations up to 256 KB).

Finalizers implement safe, asynchronous deletion. When you delete an object that has finalizers, the API server does not remove it; it sets deletionTimestamp, and the object appears as Terminating. Controllers responsible for each finalizer see that timestamp, perform cleanup (delete the cloud load balancer behind a Service, release a PersistentVolume's disk, remove external DNS records, tidy a CRD's external resources), then remove their key. When the list is empty, the object is deleted. Built-in examples: kubernetes.io/pvc-protection prevents deleting a PVC in use, and namespace finalizers wait until all contents are gone.

If the responsible controller is uninstalled or broken, the object stays Terminating forever. Removing the finalizer by hand works but skips cleanup, possibly leaking cloud resources, so first try to fix or reinstall the controller.

How it works

  1. Controller adds its finalizer when it creates external resources.
  2. User deletes the object; deletionTimestamp is set.
  3. Controller cleans up the external resources.
  4. Controller removes its finalizer.
  5. API server deletes the object once no finalizers remain.

Example

metadata:
  name: orders
  labels:
    app.kubernetes.io/name: orders
    env: prod
  annotations:
    prometheus.io/scrape: "true"
    owner: payments-team@example.com
  finalizers:
  - example.com/cleanup-dns
kubectl get pods -l app.kubernetes.io/name=orders,env=prod
kubectl get ns stuck-ns -o jsonpath='{.spec.finalizers} {.status.conditions}'
# last resort, after confirming cleanup is not needed:
kubectl patch mycrd foo --type merge -p '{"metadata":{"finalizers":null}}'

Common mistakes

  • Putting large or frequently changing data in labels.
  • Using annotations where a selector needs a label.
  • Force-removing finalizers without checking for leaked cloud resources.
  • Uninstalling an operator before deleting its custom resources.

How to answer in the interview

"Labels are small key-value pairs that identify objects, like app=orders or env=prod, and selectors in Services, Deployments, NetworkPolicies and kubectl -l use them. Annotations hold non-identifying metadata for tools, like last-applied config, scrape settings or controller options, and can be large. Finalizers block deletion: deleting the object only sets a deletion timestamp, the responsible controller cleans up, for example deleting a cloud load balancer, and then removes its finalizer so the object goes away. If that controller is gone, the object stays Terminating."

Likely follow-up questions

  • When may you remove a finalizer by hand? When the controller is gone and you've verified or done the cleanup yourself.
  • Why is a namespace stuck Terminating? Remaining objects with finalizers or an unavailable aggregated API.
  • Can selectors use annotations? No, only labels (and some field selectors).
