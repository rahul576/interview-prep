How do you design human-in-the-loop controls for agents?

AI Agents & AIOps · concept · levels mid, senior

In one line

Human-in-the-loop means designed checkpoints: approval before high-risk actions, interrupts that persist state and resume after input, a clear view of the proposed action, context and reasoning, options to approve, edit or reject, escalation when the agent is unsure or stuck, and risk-based thresholds to avoid approval fatigue.

Detailed explanation

The goal is not to have a human watch everything, but to put human judgment exactly where the risk is. The key category is high-risk actions: sending external messages, spending money, changing production systems, deleting data, granting access, or anything irreversible. These require approval before execution, enforced by the runtime, not by asking the model nicely.

Technically this is an interrupt. When the agent proposes such an action, the runtime pauses, persists the state (LangGraph interrupt, a Temporal signal wait, or an approval record in a database), and sends a request to the right person or queue through Slack, Teams, email or an app. The request shows the proposed action with its exact parameters, the relevant context and a short justification from the agent. The reviewer can approve, edit (fix an email draft, change a parameter) or reject with feedback, and the agent resumes with that input. Requests have timeouts and fallbacks.

Agents should also escalate on their own when they are uncertain, have failed several attempts, or face ambiguous or conflicting instructions, handing over with a summary rather than guessing.

The biggest practical risk is approval fatigue: if people approve 200 trivial requests a day, they stop reading and approve everything, which gives false comfort. So approvals are risk-based: reads and reversible low-impact actions run automatically, thresholds (amount, number of records, environment) trigger review, and the UI makes the decision quick and clear, highlighting what is unusual. All decisions, including who approved what and when, are logged for audit, and approval data later informs which actions can safely become autonomous.

How it works

  1. Classify each tool or action by risk and reversibility.
  2. Configure policies: auto, notify, approve, or forbidden.
  3. On a gated action, pause and persist state.
  4. Send an approval request with action, context and reasoning.
  5. Human approves, edits or rejects; agent resumes accordingly.
  6. Log decisions; review approval rates to adjust thresholds.

Example

from langgraph.types import interrupt

def send_customer_email(state):
    draft = state["email_draft"]
    decision = interrupt({
        "action": "send_email",
        "to": draft["to"],
        "subject": draft["subject"],
        "body": draft["body"],
        "reason": state["agent_reason"],
    })
    if decision["type"] == "approve":
        return {"result": mailer.send(**draft)}
    if decision["type"] == "edit":
        return {"result": mailer.send(**decision["edited_draft"])}
    return {"result": "rejected", "feedback": decision.get("feedback")}

Common mistakes

  • Relying on the prompt ("always ask before deleting") instead of runtime enforcement.
  • Approval requests without enough context to judge.
  • Gating everything, causing rubber-stamp approvals.
  • Holding a thread or session open while waiting for the human.
  • No audit log of approvals.

How to answer in the interview

"I design specific points where a person reviews or guides the agent. The main one is approval before high-risk actions: external messages, money, production changes, deletions, anything irreversible. Technically the agent hits an interrupt: its state is saved, a request goes to the right person showing the proposed action, context and reasoning, and they can approve, edit or reject with feedback, and then the agent resumes. Agents also escalate themselves when they're uncertain or stuck. To avoid approval fatigue, I make approvals risk-based: low-risk, reversible actions run automatically and thresholds trigger review. Everything is logged."

Likely follow-up questions

  • Agent running at night with nobody available? Queue the action, continue with safe work, escalate to on-call for urgent items, or time out safely.
  • How do you choose thresholds? Start strict, then relax based on approval and error data per action type.
  • Who should approve? The owner of the affected system or business process, not just any user.
