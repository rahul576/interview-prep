How do you build a basic MCP server in Python?

MCP Servers · concept · levels entry, mid, senior

In one line

Use the official Python SDK (mcp package) with its FastMCP-style API: create a server, register tools, resources and prompts with decorators, let type hints and docstrings generate schemas and descriptions, then run over stdio or Streamable HTTP and test with the Inspector.

Detailed explanation

The official Python SDK includes a high-level API, FastMCP, that hides protocol details. You create mcp = FastMCP("name") and register capabilities with decorators:

  • @mcp.tool() turns a function into a tool. The function name becomes the tool name, the docstring becomes the description, and the type hints become the input JSON Schema. Literal types produce enums, defaults make parameters optional, and Pydantic models or Annotated[..., Field(description=...)] give richer schemas and per-field descriptions. Returning a typed object (Pydantic model, TypedDict, dataclass) can generate an output schema and structured content automatically.
  • @mcp.resource("config://app") exposes a resource; a URI with placeholders like "users://{user_id}/profile" creates a resource template.
  • @mcp.prompt() defines a prompt template with arguments.

Tools can accept a Context parameter to report progress, log, read resources or elicit input. Because type hints and docstrings directly drive what the model sees, writing them well is the most effective way to improve tool use.

Running: mcp.run() defaults to stdio for local hosts; mcp.run(transport="streamable-http") serves HTTP, or you can mount the app into an existing ASGI application (Starlette/FastAPI) with authentication middleware. Projects are commonly managed with uv, and hosts launch them with uv run.

Logging: in stdio servers, never print() to stdout; use the logging module writing to stderr.

How it works

  1. uv init and uv add "mcp[cli]".
  2. Write functions with type hints and docstrings; decorate them.
  3. Run uv run mcp dev server.py to test in the Inspector.
  4. Choose transport: stdio for local, Streamable HTTP for remote.
  5. Add the server to a host config (Claude Desktop, VS Code, Claude Code).

Example

import logging, sys
from typing import Literal
from pydantic import BaseModel
from mcp.server.fastmcp import FastMCP

logging.basicConfig(stream=sys.stderr, level=logging.INFO)   # never stdout on stdio
mcp = FastMCP("orders")

class OrderSummary(BaseModel):
    order_no: str
    status: str
    total_inr: float

@mcp.tool()
def get_order(order_no: str) -> OrderSummary:
    """Get status and total for one order by its order number (e.g. ORD-1042)."""
    o = db.find_order(order_no)
    if o is None:
        raise ValueError(f"No order {order_no}. Check the number or use search_orders.")
    return OrderSummary(order_no=o.no, status=o.status, total_inr=o.total)

@mcp.resource("orders://policies/returns")
def returns_policy() -> str:
    """Current returns policy text."""
    return open("policies/returns.md").read()

@mcp.prompt()
def delayed_order_reply(order_no: str) -> str:
    return f"Draft a polite reply to a customer whose order {order_no} is delayed."

if __name__ == "__main__":
    mcp.run()          # stdio; use transport="streamable-http" for remote

Common mistakes

  • print() statements corrupting the stdio stream.
  • Missing type hints, producing untyped object schemas.
  • Empty or vague docstrings.
  • Relative file paths that break when the host launches from another directory.

How to answer in the interview

"I use the official Python SDK with its FastMCP-style API. I create a server object, then decorate functions: @mcp.tool for tools, @mcp.resource with a URI for resources or templates, @mcp.prompt for prompts. The SDK builds input schemas from type hints, including Pydantic models, and uses docstrings as descriptions, so good hints and docstrings directly improve how models use the tools; typed return values give structured output. Then I run it over stdio for local use or Streamable HTTP for remote, usually with uv, test it in the Inspector via mcp dev, and add it to a host like Claude Desktop or VS Code. Logs go to stderr."

Likely follow-up questions

  • Where does logging go in stdio servers? stderr, or MCP log notifications; stdout is reserved for protocol messages.
  • How do you add auth for HTTP? Mount in an ASGI app with token-validation middleware, or use the SDK's auth helpers.
  • Async tools? Supported; use async def for I/O-bound work.
