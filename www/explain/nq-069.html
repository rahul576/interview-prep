What does Comparator.comparingDouble() return?

Coding Exercises · concept · levels entry

In one line

It returns a Comparator<T> that compares objects by a primitive double key extracted with a ToDoubleFunction<T>, using Double.compare — so there is no boxing and special values like NaN and -0.0 are ordered consistently.

Detailed explanation

The signature is:

static <T> Comparator<T> comparingDouble(ToDoubleFunction<? super T> keyExtractor)

You pass a function that extracts a double from each object — typically a method reference like Product::getPrice — and you get back a ready-to-use Comparator<T>. Its compare(a, b) is effectively Double.compare(keyExtractor.applyAsDouble(a), keyExtractor.applyAsDouble(b)).

Why Double.compare? Comparing doubles by hand is error-prone:

  • (int) (a.getPrice() - b.getPrice()) truncates: prices 10.4 and 10.1 differ by 0.3, which becomes 0, so they wrongly compare as equal.
  • Using < and > treats NaN inconsistently (every comparison with NaN is false) and treats 0.0 and -0.0 as equal, which can violate the comparator contract and confuse sorting.

Double.compare defines a total order: -0.0 is less than 0.0, and NaN is greater than all other values, including positive infinity, and equal to itself. This keeps sorting algorithms and TreeMap correct.

Why not Comparator.comparing(Product::getPrice)? That works too, but boxes each double into a Double to use compareTo. The primitive specialisation avoids the allocation and expresses intent. Similar methods exist for int and long: comparingInt and comparingLong.

Using the result. As a normal Comparator it can be passed to sorted, List.sort, max, min, Collectors.maxBy, TreeSet or PriorityQueue, and combined with default methods: reversed() for descending, thenComparing(...) or thenComparingDouble(...) for tie-breakers.

How it works

  1. You supply a ToDoubleFunction<T> key extractor.
  2. comparingDouble returns a new Comparator<T> (serializable).
  3. On each comparison it extracts both keys as primitives.
  4. It returns Double.compare(key1, key2).

Example

Comparator<Product> byPrice = Comparator.comparingDouble(Product::getPrice);

List<Product> cheapestFirst = products.stream().sorted(byPrice).toList();
List<Product> dearestFirst  = products.stream().sorted(byPrice.reversed()).toList();
Optional<Product> top = products.stream().max(byPrice);

Comparator<Product> byPriceThenName = byPrice.thenComparing(Product::getName);

PriorityQueue<Product> queue = new PriorityQueue<>(byPrice);

// wrong: truncation makes 10.4 and 10.1 "equal"
Comparator<Product> bad = (a, b) -> (int) (a.getPrice() - b.getPrice());

Common mistakes

  • Writing comparators by subtracting doubles and casting to int.
  • Using comparing with a double getter and boxing.
  • Thinking it returns a sorted list rather than a Comparator.
  • Forgetting reversed() returns a new comparator; the original is unchanged.

How to answer in the interview

"It returns a Comparator<T>. I give it a ToDoubleFunction that extracts a primitive double key from each object, like Product::getPrice, and the comparator compares two objects by calling Double.compare on their keys. That avoids boxing and handles special values such as NaN and minus zero consistently. I can pass it to sorted, max, min or list.sort, and chain it with reversed or thenComparing."

Likely follow-up questions

  • Why Double.compare instead of subtracting prices? Subtraction and int casting lose precision and break on NaN; Double.compare is a consistent total order.
  • What are the int and long versions? comparingInt and comparingLong.
  • Is the returned comparator stateless? Yes, safe to store as a constant and reuse.
