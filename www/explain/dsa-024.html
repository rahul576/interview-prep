Explain binary search and its common pitfalls.

DSA: Algorithms & DP · concept · levels entry

In one line

Binary search finds a target in sorted (or monotonic) data by halving the search range each step, which is O(log n). The pitfalls are overflow in mid (use lo + (hi - lo) / 2), off-by-one bounds, and infinite loops when the range doesn't shrink. Powerful variants are lower/upper bound and binary search on the answer.

Detailed explanation

Binary search works whenever you can ask a yes/no question that is monotonic: false, false, ..., true, true. For a sorted array, the question is "is a[mid] >= target?". Each comparison discards half of the remaining candidates, so a billion elements need only about 30 steps.

Pitfalls:

  1. Overflow: (lo + hi) / 2 overflows when lo + hi > Integer.MAX_VALUE. This was a real bug in the JDK's Arrays.binarySearch for years, fixed in Java 6. Use lo + (hi - lo) / 2 or (lo + hi) >>> 1.
  2. Off-by-one: choose one invariant and stick to it. Either a closed interval [lo, hi] with while (lo <= hi), lo = mid + 1 and hi = mid - 1, or a half-open [lo, hi) with while (lo < hi) and hi = mid.
  3. Infinite loops: with lo = mid and mid rounding down, a two-element range never shrinks. When moving lo = mid, round mid up.
  4. Unsorted input: binary search silently returns wrong answers.

Variants:

  • First occurrence / lower bound: the first index with a[i] >= target. On a match, keep searching left (hi = mid). Java's Collections.binarySearch returns any matching index, not necessarily the first.
  • Last occurrence / upper bound: the first index with a[i] > target, minus one.
  • Rotated sorted array: one half is always sorted. Check if the target lies in it.
  • Binary search on the answer: when the answer lies in a range and feasibility is monotonic. Example: "minimum ship capacity to deliver packages within D days". If capacity C works, any larger C works too. Search C in [max(weights), sum(weights)], checking feasibility in O(n), for a total of O(n log(sum)). The same applies to Koko eating bananas, splitting an array for the largest sum, and git bisect.

How it works

  1. Define the search space and the monotonic predicate.
  2. lo, hi according to the chosen invariant.
  3. mid = lo + (hi - lo) / 2.
  4. If the predicate is true, hi = mid. Otherwise lo = mid + 1.
  5. The loop ends with lo == hi, the first true position. Verify it if the target must exist.

Example

// Lower bound: first index i with a[i] >= target (returns a.length if none)
int lowerBound(int[] a, int target) {
    int lo = 0, hi = a.length;                 // half-open [lo, hi)
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] >= target) hi = mid; else lo = mid + 1;
    }
    return lo;
}

// Binary search on the answer: min capacity to ship within `days`
int shipWithinDays(int[] w, int days) {
    int lo = Arrays.stream(w).max().getAsInt(), hi = Arrays.stream(w).sum();
    while (lo < hi) {
        int cap = lo + (hi - lo) / 2;
        if (daysNeeded(w, cap) <= days) hi = cap; else lo = cap + 1;
    }
    return lo;
}

Common mistakes

  • (lo + hi) / 2 overflow.
  • Mixing closed and half-open conventions in one loop.
  • Returning any match when the question asks for the first or last.
  • Not recognising "minimise the maximum" problems as binary search on the answer.

How to answer in the interview

"Binary search works on sorted or monotonic data. I compare the middle element with the target and discard half the range each step, so it's O(log n). The classic pitfalls are integer overflow when computing mid as low plus high over two, so I use low plus (high minus low) over two, off-by-one errors from mixing interval conventions, and infinite loops when the range doesn't shrink. I pick one invariant, usually half-open. The variants I use most are lower bound for the first occurrence, and binary search on the answer, for example finding the minimum capacity to ship packages in D days, where feasibility is monotonic."

Likely follow-up questions

  • Rotated sorted array? At each mid one half is sorted. Check if the target falls in that half's range.
  • Square root of x? Binary search on the answer in [0, x], using mid <= x / mid to avoid overflow.
  • Real-world use? git bisect, database B-tree page search, finding a performance regression across versions.
