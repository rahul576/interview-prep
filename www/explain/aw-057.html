What is AWS CloudFormation? Explain stacks, change sets and drift detection.

Cloud (AWS) · concept · levels mid

In one line

CloudFormation is AWS-native infrastructure as code: YAML or JSON templates are deployed as stacks whose state AWS tracks, change sets preview updates, failures roll back automatically, drift detection finds manual changes, and StackSets deploy across accounts and regions.

Detailed explanation

A template declares Resources (the only required section) plus Parameters, Mappings, Conditions, Outputs and optional Transforms such as AWS::Serverless for SAM. Intrinsic functions like !Ref, !GetAtt, !Sub and !ImportValue wire resources together. CloudFormation builds a dependency graph and creates resources in parallel where possible.

A stack is the unit of lifecycle: everything in it is created, updated and deleted together, and AWS stores the state, so there is no state file to lock or lose. Nested stacks reuse templates, and exports share values between stacks.

Before updating production, create a change set: it lists every resource to be added, modified or removed and whether a modification needs replacement. Replacement matters because changing properties such as an RDS identifier or DynamoDB key schema deletes and recreates the resource. Protect critical resources with DeletionPolicy: Retain or Snapshot, UpdateReplacePolicy and stack policies, and enable termination protection.

If any resource fails during create or update, CloudFormation rolls back to the last known good state; you can also attach rollback triggers tied to CloudWatch alarms. If a rollback itself fails, the stack lands in UPDATE_ROLLBACK_FAILED and you continue rollback, skipping the broken resources. Drift detection compares the live configuration with the template and shows property-level differences caused by console changes. StackSets push one template to many accounts and regions, with service-managed permissions and automatic deployment to new accounts in an OU. IaC generator can create templates from existing resources, and resource import brings them under management.

How it works

  1. Write and lint the template (cfn-lint, cfn-guard).
  2. Create a change set against the existing stack.
  3. Review additions, modifications and replacements.
  4. Execute; CloudFormation updates resources in dependency order.
  5. On failure, automatic rollback restores the previous state.
  6. Periodically run drift detection.

Example

AWSTemplateFormatVersion: "2010-09-09"
Parameters:
  Env: {Type: String, AllowedValues: [dev, prod]}
Resources:
  DataBucket:
    Type: AWS::S3::Bucket
    DeletionPolicy: Retain
    UpdateReplacePolicy: Retain
    Properties:
      BucketName: !Sub "orders-data-${Env}-${AWS::AccountId}"
      VersioningConfiguration: {Status: Enabled}
Outputs:
  BucketArn: {Value: !GetAtt DataBucket.Arn, Export: {Name: !Sub "${Env}-data-bucket"}}
aws cloudformation create-change-set --stack-name orders-prod \
  --change-set-name v42 --template-body file://template.yaml \
  --parameters ParameterKey=Env,ParameterValue=prod
aws cloudformation describe-change-set --stack-name orders-prod --change-set-name v42
aws cloudformation detect-stack-drift --stack-name orders-prod

Common mistakes

  • Executing updates without reviewing replacements in a change set.
  • Hard-coding physical names, which blocks replacements.
  • Fixing production by hand in the console, creating drift.
  • Huge monolithic stacks near the 500-resource limit instead of splitting by lifecycle.

How to answer in the interview

"CloudFormation is AWS-native IaC. I describe resources in YAML with parameters, conditions and outputs and deploy them as a stack, which is created, updated and deleted as a unit, with state managed by AWS. Before an update I create a change set to see what will be added, modified or replaced, because some property changes replace resources. On failure it rolls back automatically. Drift detection reports manual changes, and StackSets roll the same template out to many accounts and regions."

Likely follow-up questions

  • What happens when an update fails halfway? Completed changes are rolled back to the previous state; if rollback fails, you use continue-update-rollback.
  • How protect a database from deletion? DeletionPolicy Snapshot or Retain, stack policies and termination protection.
  • How share values between stacks? Outputs with exports and Fn::ImportValue, or SSM parameters for looser coupling.
