How do you use templatefile in Terraform, for example for cloud-init or configuration files?

Terraform · concept · levels entry, mid, senior

In one line

templatefile(path, vars) renders a template file with ${} interpolation and %{ for } / %{ if } directives, commonly for cloud-init/user_data and configuration files, keeping large scripts out of HCL; remember that changed user_data can replace instances and that secrets do not belong in it.

Detailed explanation

Embedding a 60-line bootstrap script in a heredoc inside HCL is hard to read, impossible to lint and easy to break with escaping. templatefile reads an external file (conventionally *.tftpl) and renders it with a map of variables. Only the variables you pass are available, which makes templates explicit and testable.

Inside the template, ${var_name} interpolates a value, and template directives add logic: %{ for s in servers ~} ... %{ endfor ~} loops, %{ if enable_agent } ... %{ endif } conditionals, and the ~ strip markers remove surrounding whitespace and newlines. Literal ${ sequences, common in shell scripts, must be escaped as $${, and %{ as %%{.

The most common use is user_data / custom_data for virtual machines, launch templates and scale sets: a cloud-init YAML or shell script that installs packages and agents, writes configuration and receives values such as environment name, storage endpoint or cluster join address. Other uses: Nginx or application config files uploaded to object storage, Kubernetes manifests, IAM or bucket policies (though jsonencode is better for JSON).

Two cautions. Many resources treat user_data as ForceNew or require a restart, so changing the template can replace instances; with launch templates it creates a new version used by the next rollout, which is usually what you want. And user data is visible to anyone who can describe the instance and is stored in state, so do not bake secrets into it; let the instance fetch them from a secret store using its identity.

How it works

  1. Write the template file with placeholders and directives.
  2. Call templatefile("${path.module}/init.tftpl", {...}).
  3. Terraform renders the string during plan.
  4. The rendered result is passed to an argument like user_data.
  5. Changes to inputs or file content change the rendered value and the plan.

Example

# cloud-init.tftpl
#cloud-config
write_files:
  - path: /etc/app/config.env
    content: |
      ENVIRONMENT=${environment}
      STORAGE_URL=${storage_url}
runcmd:
%{ for pkg in packages ~}
  - apt-get install -y ${pkg}
%{ endfor ~}
  - systemctl enable --now app
resource "aws_launch_template" "app" {
  name_prefix   = "app-"
  image_id      = data.aws_ami.ubuntu.id
  instance_type = "t3.medium"
  user_data = base64encode(templatefile("${path.module}/cloud-init.tftpl", {
    environment = var.environment
    storage_url = aws_s3_bucket.assets.bucket_regional_domain_name
    packages    = ["nginx", "jq"]
  }))
}

Common mistakes

  • Putting passwords or tokens in user data.
  • Forgetting to escape ${ in shell scripts.
  • Being surprised by instance replacement after a template edit.
  • Building JSON with templates and getting quoting wrong.

How to answer in the interview

"templatefile reads a file and renders it with the variables I pass. Inside I interpolate with dollar-brace syntax and can use %{ for } loops and %{ if } conditionals, for example one line per backend server. The most common use is user_data, a cloud-init file or bootstrap script that installs agents and gets values like the environment name or storage endpoint, and also config files for storage or Kubernetes. It keeps big scripts out of HCL, so they're readable and can be linted separately. I remember that changing user_data often forces instance replacement, and I never bake secrets in; instances fetch them from a vault."

Likely follow-up questions

  • Why is jsonencode better than a JSON template? It produces valid, correctly escaped JSON from HCL values.
  • What do ~ markers do? Strip whitespace and newlines around directives.
  • How do you test templates? Render with terraform console or terraform test and lint the output.
