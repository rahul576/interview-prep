How would you implement the solution in Java, and can it be implemented using streams?

DSA: Arrays & Strings · scenario · levels mid

In one line

Loop version: for each word, sort its characters, computeIfAbsent(key).add(word), return new ArrayList<>(map.values()); stream version: Collectors.groupingBy(Solution::key); both are O(n·k log k), and a small key helper keeps either readable.

Detailed explanation

Imperative loop. Easy to read, easy to debug and step through, and gives full control: early validation, skipping invalid words, reusing buffers. This is usually what I would write first in an interview.

Streams. Collectors.groupingBy(classifier) is a direct expression of "group words by key". The classifier is the same key function. You can choose the map type and downstream collector: groupingBy(Solution::key, LinkedHashMap::new, Collectors.toList()) for ordered groups, or Collectors.counting() for counts. The result is a Map<String, List<String>>; wrap values() in a new list for List<List<String>>.

The key helper. Extracting key(String w) into a method makes both versions short and lets you swap a sorted key for a counting key without touching the grouping code. Inside the helper, a stream version of sorting is possible: w.chars().sorted().collect(StringBuilder::new, StringBuilder::appendCodePoint, StringBuilder::append).toString() but the char[] + Arrays.sort version is clearer and faster.

Complexity is identical for both: O(n·k log k) with sorting, O(n·k) with counting. Streams add small overhead (lambdas, collector machinery), irrelevant for typical inputs.

Parallelism: words.parallelStream().collect(Collectors.groupingByConcurrent(Solution::key)) can use multiple cores for very large inputs, at the cost of losing input order within groups; measure before using it.

Which in production? Either is fine. I prefer the stream version when the logic is just "group by key" because it states intent, and the loop when there is extra logic, error handling or performance tuning.

How it works

  1. Write key(String) returning the sorted characters.
  2. Loop: iterate words, compute key, computeIfAbsent(...).add(word).
  3. Stream: Arrays.stream(words).collect(groupingBy(Solution::key)).
  4. Convert the map values into a List<List<String>>.

Example

public class Solution {

    static String key(String w) {
        char[] c = w.toCharArray();
        Arrays.sort(c);
        return new String(c);
    }

    // Loop version
    public static List<List<String>> groupLoop(String[] words) {
        Map<String, List<String>> groups = new HashMap<>();
        for (String w : words) {
            groups.computeIfAbsent(key(w), k -> new ArrayList<>()).add(w);
        }
        return new ArrayList<>(groups.values());
    }

    // Stream version
    public static List<List<String>> groupStream(String[] words) {
        return new ArrayList<>(Arrays.stream(words)
                .collect(Collectors.groupingBy(Solution::key, LinkedHashMap::new, Collectors.toList()))
                .values());
    }

    public static void main(String[] args) {
        String[] in = {"eat", "tea", "tan", "ate", "nat", "bat"};
        System.out.println(groupStream(in));   // [[eat, tea, ate], [tan, nat], [bat]]
    }
}

Common mistakes

  • Putting the whole sort-and-build expression inline in the lambda, hurting readability.
  • Returning map.values() directly when the signature promises a List.
  • Using parallelStream with a non-concurrent collector and expecting order.
  • Forgetting LinkedHashMap::new when order is required in the stream version.

How to answer in the interview

"In the loop version I create a HashMap of String to List, and for each word I sort its characters, use the sorted string as the key and computeIfAbsent the list to add the word; then I return a new ArrayList of the map values. With streams it's Arrays.stream(words).collect(Collectors.groupingBy(Solution::key)).values(), where key sorts the characters. Both are O(n·k log k). I'd put the key logic in a small helper method so either version reads clearly; in production I'd use the stream for plain grouping and the loop if there's extra logic."

Likely follow-up questions

  • Which version would you prefer in production? The stream for simple grouping; the loop when there is validation or tuning.
  • How do you keep order with streams? Pass LinkedHashMap::new as the map factory.
  • Can it run in parallel? Yes with groupingByConcurrent, but only worth it for very large inputs.
