How would you compare possible paths and store accumulated sums?

DSA: Algorithms & DP · concept · levels mid

In one line

Comparing every path by brute force is exponential; because paths share prefixes, we store the best accumulated sum per cell, either top-down with memoization or bottom-up in a DP table, so each cell is computed once in O(m·n).

Detailed explanation

In an m×n grid with right/down moves, every path has exactly (m-1) downs and (n-1) rights, so the number of paths is the binomial coefficient C(m+n-2, m-1). For a 20×20 grid that is about 35 billion paths. A naive recursion minCost(i, j) = grid[i][j] + min(minCost(i-1, j), minCost(i, j-1)) explores all of them, recomputing the same cells again and again. This is the signature of overlapping subproblems.

The fix is to store results. Top-down memoization keeps the recursive definition but caches minCost(i, j) in a table the first time it is computed; later calls are O(1) lookups. Bottom-up tabulation fills the table iteratively in an order where dependencies are ready, typically row by row. Either way, "comparing paths" collapses to a single min of two stored values per cell, because the stored value already represents the best of all paths into that cell.

Both have O(m·n) time. Top-down is easy to derive from the recurrence and only computes reachable states, but recursion depth can reach m+n frames, risking StackOverflowError on huge grids. Bottom-up avoids recursion and allows the rolling-array space optimisation.

How it works

  1. Write the recurrence and identify base cases.
  2. Notice the same (i, j) is reached by many paths (overlap).
  3. Top-down: recurse, check the memo, compute once, store.
  4. Bottom-up: allocate dp, fill in row-major order.
  5. Each cell does constant work, so total work is proportional to the number of cells.

Example

// Top-down with memoization
long[][] memo;
long minCost(int[][] g, int i, int j) {
    if (i < 0 || j < 0) return Long.MAX_VALUE;
    if (i == 0 && j == 0) return g[0][0];
    if (memo[i][j] != -1) return memo[i][j];
    long best = Math.min(minCost(g, i - 1, j), minCost(g, i, j - 1));
    return memo[i][j] = g[i][j] + best;
}
// init: memo = new long[m][n]; for (long[] r : memo) Arrays.fill(r, -1);

Common mistakes

  • Claiming brute force is O(m·n).
  • Using 0 as the "not computed" marker when 0 is a valid cost.
  • Ignoring stack depth in the recursive version.
  • Overflow when adding to MAX_VALUE; check before adding.

How to answer in the interview

"Enumerating paths is exponential: there are m plus n minus 2 choose m minus 1 of them. But they share prefixes, so the best cost to any cell is reused by every path through it. I'd store that best accumulated cost per cell. Top-down, I memoize a recursive minCost(i, j); bottom-up, I fill a table in row order. Comparing paths then becomes one min of two stored values per cell, so each cell is computed once and the total is O(m times n). I'd prefer bottom-up in production to avoid deep recursion."

Likely follow-up questions

  • What would the recursion depth be in the top-down version? Up to m+n-1 frames, one per step along a path.
  • How many paths are there? C(m+n-2, m-1).
  • When is memoization better than tabulation? When only a fraction of states are reachable.
