What are the major features introduced in Java 8?

Java 8+ Features · concept · levels entry, mid

In one line

Java 8 (2014) introduced lambda expressions and functional interfaces, method references, the Stream API, Optional, default and static interface methods, the java.time API, CompletableFuture, and replaced PermGen with Metaspace.

Detailed explanation

Java 8 was the largest language change since generics in Java 5, moving Java towards a functional style while staying backward compatible.

  • Lambdas and functional interfaces let you pass behaviour as data: (a, b) -> a + b. The java.util.function package added Function, Predicate, Supplier, Consumer, BiFunction and primitive variants.
  • Method references (String::length, ArrayList::new) shorten lambdas that only call a method.
  • The Stream API provides declarative, lazy pipelines (filter, map, collect) and easy parallel streams.
  • Default and static interface methods let interfaces carry implementations. This was essential: the JDK could add stream(), forEach and removeIf to Collection/Iterable without breaking every existing implementation.
  • Optional models possibly absent return values.
  • java.time (JSR-310) gives immutable, thread-safe LocalDate, Instant, ZonedDateTime, Duration and DateTimeFormatter.
  • CompletableFuture enables non-blocking composition (thenApply, thenCompose, allOf).
  • Other additions: Base64, StampedLock, LongAdder, ConcurrentHashMap improvements, Map.computeIfAbsent/merge/getOrDefault, String.join, repeatable and type annotations, the Nashorn JavaScript engine (removed in Java 15), and Metaspace replacing PermGen, which removed the classic OutOfMemoryError: PermGen space.

Java 8 is still found in legacy systems, but modern projects target Java 17, 21 or 25 (Spring Boot 3 requires 17+).

How it works

  1. Lambdas compile to invokedynamic call sites bootstrapped by LambdaMetafactory.
  2. Collections gained stream() through default methods.
  3. Stream pipelines run lazily when a terminal operation is invoked.
  4. CompletableFuture chains callbacks on the common ForkJoinPool or a supplied executor.

Example

// Before Java 8
List<String> names = new ArrayList<>();
for (Employee e : employees) {
    if (e.getSalary() > 50_000) names.add(e.getName().toUpperCase());
}
Collections.sort(names);

// Java 8
List<String> names8 = employees.stream()
    .filter(e -> e.getSalary() > 50_000)
    .map(Employee::getName)
    .map(String::toUpperCase)
    .sorted()
    .collect(Collectors.toList());

Optional<Employee> boss = employees.stream().filter(Employee::isManager).findFirst();
LocalDate due = LocalDate.now().plusDays(30);
CompletableFuture<Report> report = CompletableFuture.supplyAsync(this::loadData)
    .thenApply(this::buildReport);

Common mistakes

  • Listing only lambdas and streams and forgetting default methods or java.time.
  • Saying var or records are Java 8 features (they are Java 10 and 16).
  • Claiming Nashorn is still in the JDK.
  • Not explaining why default methods were needed.

How to answer in the interview

"Java 8 was the biggest change in years. It added lambdas and functional interfaces like Function, Predicate and Supplier, plus method references. The Stream API brought declarative filter-map-collect pipelines, including parallel streams. Optional made possibly absent return values explicit. Interfaces gained default and static methods, which let the JDK add stream and forEach to Collection without breaking implementations. The java.time API replaced Date and Calendar, CompletableFuture enabled async composition, and Metaspace replaced PermGen."

Likely follow-up questions

  • Why were default methods needed to add the Stream API? Adding abstract stream() to Collection would have broken every existing implementation.
  • What replaced PermGen? Metaspace, allocated in native memory and growing dynamically.
  • Which Java 8 feature do you use most? Typically streams with lambdas, plus java.time.
