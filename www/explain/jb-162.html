What is a Spring Bean?

Spring Framework · concept · levels entry, mid

In one line

A Spring bean is an object whose creation, wiring and lifecycle are managed by the IoC container, declared with @Component and its stereotypes or @Bean methods, receiving injected dependencies, possibly wrapped in proxies, with a scope (singleton by default) and lifecycle callbacks.

Detailed explanation

Any Java object can be a bean; the difference is who controls it. Instead of your code calling new OrderService(new JdbcOrderRepository(...)), the container creates the object from a bean definition (class, scope, dependencies, init and destroy methods, lazy flag, qualifiers) and hands it to whoever needs it.

Declaring beans:

  • Stereotype annotations: @Component, @Service, @Repository, @Controller/@RestController on your own classes, detected by component scanning.
  • @Bean methods in @Configuration classes: the return value becomes the bean; ideal for third-party classes or custom construction.
  • Others: auto-configuration in Spring Boot, programmatic registration, and historically XML.

What the container adds: dependency injection (preferably through the constructor), configuration values via @Value or @ConfigurationProperties, proxies for @Transactional, @Async, @Cacheable and security, and lifecycle callbacks such as @PostConstruct after injection and @PreDestroy on shutdown. Each bean has a name (class name in camel case by default, or the method name for @Bean) and can be looked up by type or name.

Scope: the default singleton scope means one shared instance per container, used by all threads concurrently. Consequently singleton beans must be stateless or thread-safe: no request-specific data in fields. Other scopes: prototype (new instance per lookup), and web scopes request, session, application. Objects that represent data, like JPA entities or DTOs, are usually not beans; they are created per use.

How it works

  1. Spring reads bean definitions from scanning and configuration classes.
  2. It instantiates the bean and injects dependencies.
  3. Aware callbacks and BeanPostProcessors run; @PostConstruct executes.
  4. Proxies may wrap the bean for AOP features.
  5. The bean is used by others; on shutdown @PreDestroy runs (singletons).

Example

@Service                               // a bean, found by component scanning
class InvoiceService {
    private final InvoiceRepository repo;
    private final Clock clock;
    InvoiceService(InvoiceRepository repo, Clock clock) { this.repo = repo; this.clock = clock; }

    @PostConstruct void ready() { log.info("InvoiceService ready"); }

    @Transactional
    public Invoice issue(Order o) { return repo.save(new Invoice(o, LocalDate.now(clock))); }
}

@Configuration
class TimeConfig {
    @Bean Clock clock() { return Clock.systemUTC(); }   // third-party class as a bean
}

// Thread-safety trap: shared mutable state in a singleton
@Service
class BadService {
    private String currentUser;   // overwritten by concurrent requests
}

Common mistakes

  • Storing per-request state in singleton fields.
  • Creating a service with new and then wondering why @Transactional or injection does not work.
  • Making entities or DTOs into beans.
  • Thinking "singleton" means one per JVM.

How to answer in the interview

"A Spring bean is an object whose creation, wiring and lifecycle are managed by the Spring IoC container instead of my code calling new. I declare beans with stereotype annotations like @Component, @Service and @Repository, picked up by component scanning, or with @Bean methods in a @Configuration class, which is handy for third-party classes. The container injects dependencies into beans, wraps them in proxies for features like transactions, and calls lifecycle callbacks such as @PostConstruct and @PreDestroy. Each bean has a scope, singleton by default, meaning one shared instance per container, so singleton beans must be stateless or thread-safe."

Likely follow-up questions

  • What happens if a singleton bean keeps request-specific data in a field? Concurrent requests overwrite each other's data, causing data leaks and race conditions.
  • How is a bean's name chosen? Lower camel case class name, or the @Bean method name, unless specified.
  • Are all objects in a Spring app beans? No, entities, DTOs and value objects are normal objects.
