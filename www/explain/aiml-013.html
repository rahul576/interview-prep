How do you handle missing values in a dataset?

AI/ML & GenAI · concept · levels entry, mid

In one line

First understand why values are missing, then drop, impute (mean, median, mode, k-NN or iterative), add a missing indicator, or use models that handle missing values natively, fitting the logic on training data only and applying it identically in production.

Detailed explanation

The mechanism matters. Data can be missing completely at random (MCAR), such as a random sensor glitch; missing at random (MAR), where missingness depends on other observed variables, such as older customers skipping an optional field; or missing not at random (MNAR), where it depends on the value itself, such as high earners declining to state income. Sometimes missing is meaningful: "no previous loan" for a new customer is information, not an error. Talking to data owners often reveals a pipeline bug that should be fixed upstream.

Options: drop rows when few are affected and missingness is random; drop columns that are mostly empty and unimportant. Simple imputation uses the median (robust to skew) for numerics and the most frequent value or an explicit "Unknown" category for categoricals. Model-based imputation, such as k-nearest neighbours or iterative imputation (MICE-style, predicting each feature from the others), preserves relationships better. Adding a missing indicator feature lets the model learn that missingness itself is predictive. Time series often use forward-fill or interpolation.

Gradient boosting libraries such as XGBoost, LightGBM and CatBoost handle missing values natively by learning which branch missing values should follow. Whatever you choose, fit the imputer on the training set only inside a pipeline and use the same fitted logic in serving, otherwise you get leakage and training-serving skew. In production, monitor missing rates: a sudden jump is a classic data-quality alert indicating a broken upstream source.

How it works

  1. Profile missing rates per column and per segment.
  2. Investigate causes with data owners and classify the mechanism.
  3. Decide per column: drop, impute, indicator, or leave for a native-handling model.
  4. Implement inside a pipeline fitted on training data.
  5. Monitor missing rates in production and alert on changes.

Example

from sklearn.pipeline import make_pipeline
from sklearn.impute import SimpleImputer
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.linear_model import LogisticRegression

Common mistakes

  • Filling with the global mean before the train/test split.
  • Dropping all rows with any missing value and silently biasing the sample.
  • Using 0 or -999 as a filler for linear models.
  • Applying different imputation in production than in training.

How to answer in the interview

"I start by asking why values are missing, because a random sensor drop, a pipeline bug and a meaningful absence like 'no previous loans' need different treatment. Then I choose per column: drop if it's rare and random, impute with median or mode or a model-based method, and often add a missing indicator because missingness can be predictive. Boosting libraries handle NaNs natively. I fit imputation on training data only inside the pipeline so production behaves identically, and I monitor missing rates as a data-quality signal."

Likely follow-up questions

  • Why can mean imputation introduce bias? It shrinks variance, weakens correlations and ignores why data is missing.
  • What is MNAR? Missingness depends on the unobserved value itself, so simple imputation is biased.
  • How do you impute time series? Forward-fill, interpolation or seasonal models, never using future values.
