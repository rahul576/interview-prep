What is the difference between INNER JOIN, LEFT JOIN, RIGHT JOIN, and FULL JOIN?

Databases & SQL · concept · levels entry, mid

In one line

With customers and orders: INNER JOIN returns only customers with orders, LEFT JOIN returns all customers (order columns NULL when none), RIGHT JOIN returns all orders, and FULL JOIN returns everything from both sides, padded with NULLs.

Detailed explanation

Imagine customer has Asha, Ben and Chen, and orders has two orders for Asha, one for Ben, and one orphaned order with a customer id that no longer exists.

  • INNER JOIN keeps only pairs where orders.customer_id = customer.id matches: Asha twice, Ben once. Chen and the orphan order disappear.
  • LEFT JOIN (left outer join) keeps every customer. Chen appears once with NULL order columns. Adding WHERE o.id IS NULL keeps only Chen: customers who never ordered.
  • RIGHT JOIN keeps every order, including the orphan, with NULL customer columns. Most people write it as a LEFT JOIN with the tables swapped.
  • FULL OUTER JOIN keeps both Chen and the orphan, which is handy for reconciliation between two systems. MySQL does not support it, so you emulate it with a LEFT JOIN UNION a RIGHT JOIN (or a UNION ALL with an anti-join to avoid de-duplicating real duplicates).

A subtle but common trap: in an outer join, a filter on the optional side must go into the ON clause. LEFT JOIN orders o ON ... WHERE o.status = 'PAID' removes customers with no orders, because NULL = 'PAID' is not true, so it behaves like an inner join. LEFT JOIN orders o ON o.customer_id = c.id AND o.status = 'PAID' keeps them.

How it works

  1. The engine matches rows using the ON condition.
  2. Matching pairs are produced for all join types.
  3. Outer joins add unmatched rows from the preserved side with NULLs.
  4. Then WHERE filters the combined result.
  5. Finally grouping, selection and ordering are applied.

Example

-- All customers with their order count (0 when none)
SELECT c.id, c.name, COUNT(o.id) AS orders
FROM customer c
LEFT JOIN orders o
  ON o.customer_id = c.id AND o.status = 'PAID'
GROUP BY c.id, c.name;

-- Customers who never ordered
SELECT c.* FROM customer c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL;

-- MySQL FULL JOIN emulation
SELECT c.id, o.id FROM customer c LEFT JOIN orders o ON o.customer_id = c.id
UNION
SELECT c.id, o.id FROM customer c RIGHT JOIN orders o ON o.customer_id = c.id;

Common mistakes

  • Filtering the right table in WHERE after a LEFT JOIN.
  • Using COUNT(*) instead of COUNT(o.id), so customers without orders count as 1.
  • Assuming FULL JOIN works in MySQL.
  • Joining on names instead of keys.

How to answer in the interview

"Using customers and orders: an inner join returns only customers who have orders. A left join returns every customer, and order columns are NULL when there's no match, so adding WHERE order id IS NULL gives customers who never ordered. A right join is the mirror, every order even without a customer. A full outer join returns all rows from both sides, matched where possible, which is useful for reconciliation; MySQL doesn't support it, so I'd emulate it with a union of left and right joins. One thing I watch: conditions on the optional table belong in the ON clause, otherwise the left join becomes an inner join."

Likely follow-up questions

  • Why does WHERE turn a LEFT JOIN into an inner join? The NULL rows fail the comparison and are filtered out.
  • **COUNT() vs COUNT(o.id) after a LEFT JOIN?* COUNT(*) counts the NULL row as 1; COUNT(o.id) gives 0.
  • NOT EXISTS vs LEFT JOIN IS NULL? Same result; NOT EXISTS is often clearer and optimised as an anti-join.
