How would you filter products whose stock count is below 10?

Coding Exercises · scenario · levels entry

In one line

Use products.stream().filter(p -> p.getStock() < 10).toList(): filter keeps elements whose predicate returns true, and toList() (Java 16+) collects them into an unmodifiable list; use collect(Collectors.toList()) on Java 8, and name the Predicate if it is reused.

Detailed explanation

filter is an intermediate operation that takes a Predicate<T> — a function returning boolean — and passes on only the elements for which it returns true. Like all intermediate operations it is lazy: nothing happens until a terminal operation such as toList(), collect or count runs.

The result is a new list. The original products list is not modified, which is one of the main advantages of streams: you describe what you want, and the source stays intact for other uses.

Collecting. Stream.toList(), added in Java 16, returns an unmodifiable list; calling add on it throws UnsupportedOperationException. On Java 8–15 you write collect(Collectors.toList()), which in practice returns an ArrayList but makes no mutability guarantee. If the caller needs to modify the result, use Collectors.toCollection(ArrayList::new).

Naming and combining predicates. If the low-stock rule appears in several places, extract it: Predicate<Product> lowStock = p -> p.getStock() < 10; or a static method Product::isLowStock. Predicates compose with and, or and negate(), and Predicate.not(lowStock) (Java 11) reads nicely inside filter. A named constant for the threshold (LOW_STOCK_THRESHOLD = 10) avoids a magic number.

Null safety. If the list could contain null elements, p.getStock() would throw; filter them out first with filter(Objects::nonNull), or better, do not allow nulls in the list. If getStock() returns an Integer that might be null, handle that explicitly.

How it works

  1. products.stream() creates a stream over the list.
  2. filter(predicate) is registered as a lazy step.
  3. toList() triggers processing: each product is tested.
  4. Matching products are added to a new unmodifiable list.
  5. The original list is unchanged.

Example

// Java 16+
List<Product> lowStock = products.stream()
        .filter(p -> p.getStock() < 10)
        .toList();

// Java 8
List<Product> lowStock8 = products.stream()
        .filter(p -> p.getStock() < 10)
        .collect(Collectors.toList());

// reusable, composable predicate
Predicate<Product> isLowStock = p -> p.getStock() < 10;
Predicate<Product> isElectronics = p -> "Electronics".equals(p.getCategory());

List<Product> lowStockElectronics = products.stream()
        .filter(isLowStock.and(isElectronics))
        .toList();

long count = products.stream().filter(isLowStock).count();

Common mistakes

  • Expecting filter to remove elements from the original list (use removeIf for that).
  • Calling add on the result of toList() and getting UnsupportedOperationException.
  • Writing <= 10 when the requirement says below 10.
  • Building a stream but forgetting the terminal operation, so nothing runs.

How to answer in the interview

"I'd write products.stream().filter(p -> p.getStock() < 10).toList(). filter keeps only the elements for which the predicate returns true, and toList, available since Java 16, collects them into an unmodifiable list; on Java 8 I'd use collect(Collectors.toList()). The original list isn't modified. If the rule is reused, I'd name it as a Predicate, say isLowStock, and combine it with others using and, or and negate, and I'd put the threshold in a named constant."

Likely follow-up questions

  • How would you count them without collecting? filter(...).count().
  • How do you remove them from the original list? products.removeIf(p -> p.getStock() < 10) on a mutable list.
  • What if you only need to know whether any exist? anyMatch(isLowStock), which short-circuits.
