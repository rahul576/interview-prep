What are intermediate and terminal operations? Give examples.

Java 8+ Features · concept · levels entry

In one line

Intermediate operations return a Stream and are lazy (filter, map, flatMap, sorted, distinct, limit, peek); terminal operations trigger processing and produce a non-stream result or side effect (collect, toList, reduce, count, forEach, findFirst, anyMatch); some are stateful and some short-circuiting.

Detailed explanation

Intermediate operations transform one stream into another. They don't process anything when called; they add a stage. They come in two flavours:

  • Stateless: filter, map, flatMap, mapToInt, peek, mapMulti; each element is handled independently.
  • Stateful: sorted (must see all elements before emitting), distinct (remembers seen elements), limit and skip (count elements, costly in ordered parallel streams).
  • Short-circuiting intermediate: limit, takeWhile can turn an infinite stream into a finite one.

Terminal operations start execution, consume the stream and return something that is not a stream:

  • Reductions/collections: collect, toList (Java 16, unmodifiable), toArray, reduce, count, min, max, sum/average on primitive streams.
  • Searching/matching (short-circuiting): findFirst, findAny, anyMatch, allMatch, noneMatch; they stop as soon as the answer is known.
  • Side effects: forEach, forEachOrdered.
  • Escape hatches: iterator() and spliterator().

A pipeline has any number of intermediate operations and exactly one terminal one. Choosing operations wisely matters for performance: place cheap filters before expensive maps, avoid sorted on large data unless required, and use short-circuiting terminals when you only need one answer.

How it works

  1. Intermediate calls build a lazy chain of stages.
  2. The terminal operation creates the sink chain and starts the source.
  3. Stateless stages pass elements through immediately; stateful ones buffer.
  4. Short-circuiting operations signal the source to stop.
  5. The terminal result is returned and the stream is closed for reuse.

Example

List<String> result = products.stream()
    .filter(Product::inStock)                 // intermediate, stateless
    .map(Product::name)                       // intermediate, stateless
    .distinct()                               // intermediate, stateful
    .sorted()                                 // intermediate, stateful
    .limit(10)                                // intermediate, short-circuiting
    .toList();                                // terminal

boolean anyExpensive = products.stream()
    .anyMatch(p -> p.price().compareTo(new BigDecimal("50000")) > 0);   // terminal, short-circuit

long count = products.stream().filter(Product::inStock).count();       // terminal
Optional<Product> cheapest = products.stream().min(Comparator.comparing(Product::price));
products.stream().map(Product::sku).forEach(System.out::println);      // terminal, side effect

Common mistakes

  • Treating peek or map as terminal.
  • Calling sorted before a filter that would shrink data.
  • Using forEach to populate a list instead of collect/toList.
  • Assuming toList() returns a mutable list.

How to answer in the interview

"Intermediate operations transform a stream into another stream and are lazy: filter, map, flatMap, peek, distinct, sorted, limit and skip. Some are stateless, like filter and map, while sorted and distinct are stateful because they need to see many elements, and limit is short-circuiting. Terminal operations start the processing and produce a non-stream result or side effect: collect, toList, forEach, reduce, count, min, max, findFirst, findAny, anyMatch, allMatch and noneMatch. The matching and finding ones are short-circuiting. A pipeline has any number of intermediate operations and exactly one terminal one."

Likely follow-up questions

  • Why is sorted() called a stateful operation? It must buffer all elements before emitting the first sorted one.
  • Which operations short-circuit? limit, takeWhile, findFirst, findAny, anyMatch, allMatch, noneMatch.
  • Is toList() the same as Collectors.toList()? No, toList() returns an unmodifiable list.
