What is a mock object, and what is a spy in Mockito?

Testing · concept · levels mid

In one line

A mock is a completely fake object whose methods do nothing and return defaults unless stubbed, while a spy wraps a real object and calls real methods unless you stub specific ones (a partial mock); stub spies with doReturn().when(), and prefer mocks and better design over spies.

Detailed explanation

Both are created by Mockito and both record invocations, so you can verify calls on either. The difference is what happens when a method is called.

Mock (mock(Foo.class) or @Mock): Mockito generates a subclass or uses the inline mock maker so that every method returns a default: null for objects, 0 for numbers, false, empty collections, Optional.empty() and empty streams. No real code runs. You decide behaviour with stubbing. Mocks are the normal choice for dependencies at the boundary of the unit under test.

Spy (spy(realObject) or @Spy): Mockito copies the state of a real instance into a proxied object. Calls go to the real implementation unless you stub a particular method. This is useful when:

  • testing legacy code where one method calls an expensive or external operation you need to override, but the rest of the class must behave normally;
  • you want to observe calls on a real object (for example a real in-memory list) while keeping its behaviour.

Stubbing spies correctly: when(spy.calculate()).thenReturn(5) first calls the real calculate() while setting up the stub, which may throw or have side effects. Use doReturn(5).when(spy).calculate() instead, which does not invoke the real method. Note also that a spy is a copy: changes to the original object are not visible through the spy and vice versa.

Spies in new code are a design smell: if you need to fake part of a class, that part is probably a separate responsibility that should be extracted into its own injected dependency and mocked normally. Spring tests have @MockitoSpyBean for spying on a bean in the context.

How it works

  1. Mock: generated object, all methods return defaults.
  2. Spy: proxy around a copy of a real instance.
  3. Stubbed method → returns the stubbed value (both).
  4. Unstubbed method → default (mock) or real code (spy).
  5. Invocations recorded → verify works for both.

Example

@Test
void mockReturnsDefaults() {
    List<String> mockList = mock(List.class);
    mockList.add("a");
    assertThat(mockList.size()).isZero();          // nothing real happened
    verify(mockList).add("a");
}

@Test
void spyCallsRealMethods() {
    List<String> spyList = spy(new ArrayList<>());
    spyList.add("a");
    assertThat(spyList.size()).isEqualTo(1);       // real behaviour
    doReturn(100).when(spyList).size();            // safe stubbing
    assertThat(spyList.size()).isEqualTo(100);
}

@Test
void partialMockForLegacyReport() {
    ReportGenerator gen = spy(new ReportGenerator());
    doReturn(List.of(sampleRow())).when(gen).loadRowsFromDatabase();
    assertThat(gen.render()).contains("Total: 40.00");   // real render logic
}

Common mistakes

  • Using when(spy.method()), which executes the real method during stubbing.
  • Expecting the original object to change when the spy is modified.
  • Spying on the class under test to fake its own methods instead of refactoring.
  • Spying on final or private methods and expecting stubs to apply.

How to answer in the interview

"A mock is a completely fake object created from a class or interface: every method does nothing and returns a default like null, zero or an empty collection until I stub it, and Mockito records calls so I can verify them. A spy wraps a real object: calls go to the real methods unless I stub specific ones, so it's a partial mock. That's handy for legacy code where I need real behaviour but must override one expensive method. With spies I stub using doReturn-when, because when-thenReturn would call the real method during stubbing. In new code I treat spies as a smell and extract the dependency instead."

Likely follow-up questions

  • Why does when(spy.method()) cause problems? It invokes the real method while stubbing, which may throw or cause side effects.
  • Is a spy a reference to the original? No, it is a copy; changes are not shared.
  • What is @MockitoSpyBean? A Spring test annotation wrapping a context bean in a Mockito spy.
