What types of memory do agents use, and how do you implement them?

AI Agents & AIOps · concept · levels mid, senior

In one line

Agents use short-term memory (the current context window, managed with compaction) and long-term memory that persists across sessions: semantic (facts, preferences), episodic (past events and attempts) and procedural (learned ways of working), stored in databases or vector stores, retrieved when relevant, and governed by privacy, user control and expiry.

Detailed explanation

Short-term or working memory is whatever is in the context during a run: the conversation, tool results, the plan and scratch notes. It is limited and expensive, so long sessions use compaction (summarising older turns), trimming verbose tool outputs, and sometimes a scratchpad file the agent keeps updated.

Long-term memory survives across sessions and comes in kinds borrowed from cognitive science. Semantic memory holds facts and preferences: "the user prefers metric units", "this team deploys with Argo CD on AKS". Episodic memory stores records of past interactions or task attempts: "last month's disk-full incident on node pool B was fixed by raising log rotation". Procedural memory captures how to do things, typically as updated instructions, playbooks or skills the agent loads.

Implementation varies. Structured facts fit a relational or key-value store keyed by user or tenant. Unstructured notes and episodes go into a vector store for similarity retrieval, often combined with metadata filters. Retrieval can be automatic, injecting relevant memories into the prompt at the start of a turn, or agent-driven, with memory tools such as save_memory and search_memory, or a memory directory of files the agent reads and edits. Writing is the harder part: deciding what is worth remembering, deduplicating, and updating or invalidating facts that changed, often with a background extraction step after a conversation.

Memory raises privacy and correctness issues. Users should be able to see, correct and delete memories; sensitive categories need rules or should not be stored; memories should carry provenance and timestamps and expire; and every read must be scoped to the authenticated user or tenant. Wrong memories are dangerous because they persist and get reused confidently.

How it works

  1. During a run, keep working state in context; compact when it grows.
  2. At the end of a turn or session, extract candidate memories.
  3. Store with owner, type, source, timestamp and expiry.
  4. At the start of a new task, retrieve relevant memories filtered by user/tenant.
  5. Let the agent and user update or delete memories; expire stale ones.

Example

memory_record = {
    "tenant_id": "acme",
    "user_id": "u-481",
    "type": "semantic",
    "text": "Prefers Terraform over Bicep for new infrastructure",
    "source": "conversation 2026-05-12",
    "created_at": "2026-05-12T10:31:00Z",
    "expires_at": "2027-05-12T00:00:00Z",
}
store.upsert(memory_record, embedding=embed(memory_record["text"]))

# Retrieval is always scoped to the authenticated identity, not model output
hits = store.search(query_embedding, filter={"tenant_id": session.tenant, "user_id": session.user}, top_k=5)

Common mistakes

  • Storing everything, so retrieval returns noise.
  • No user or tenant filter on memory retrieval.
  • Never updating or expiring facts that changed.
  • Hiding memory from users, with no way to correct it.

How to answer in the interview

"Short-term memory is the context window during a session: conversation, tool results and notes, compacted by summarising when it gets long. Long-term memory persists across sessions. Semantic memory stores facts and preferences, episodic memory stores past interactions or task attempts, and procedural memory captures how to do tasks, usually as updated instructions or skills. I store it in a database or vector store and retrieve it either automatically by similarity or through memory tools the agent calls. Every record is scoped to the user or tenant, has provenance and expiry, and users can see, correct and delete what is remembered."

Likely follow-up questions

  • What goes wrong with incorrect memories? The agent repeats the error confidently across sessions; provenance, confirmation and easy correction mitigate it.
  • Vector store or plain DB? Structured facts in a DB; fuzzy recall of notes and episodes in a vector store with filters.
  • What should never be stored? Credentials, payment data and sensitive personal categories unless explicitly required and consented.
