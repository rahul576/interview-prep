What is a model registry, and how is it used in a deployment workflow?

MLOps · concept · levels entry, mid, senior

In one line

A model registry is a central catalogue of versioned models, each linked to its training run, data and metrics, labelled with aliases or stages like production or champion, and used as the source of truth for promotion, approval, serving and rollback.

Detailed explanation

Without a registry, "which model is in production?" is answered by a filename in an S3 bucket. A model registry gives each model a name (for example fraud-scorer) and numbered, immutable versions. Every version records lineage: the training run, its parameters and metrics, the code commit, the data version and the environment, so anyone can see exactly what was deployed and how it was built. It also stores signatures (input and output schema), descriptions and owners.

Versions are labelled to describe their role without copying files. Older MLflow used fixed stages (Staging, Production, Archived); current MLflow recommends flexible aliases such as @champion and @challenger, plus tags like validation_status=approved. Cloud platforms have equivalents: SageMaker Model Registry with approval status on model packages, and registries in Azure ML and Vertex AI.

In the deployment workflow the registry is the hand-off point between training and serving. The training pipeline registers a new version. Automated evaluation checks it against thresholds and the current champion, and a human review approves it if required. CI/CD promotes it by moving the alias or setting approval, often first in a staging environment. The serving system deploys whatever version the production alias points to, by model URI rather than hard-coded paths. Rollback is simply pointing the alias back to the previous version. Permissions control who can register and who can promote, and audit history records every change, which matters for regulated domains.

How it works

  1. Pipeline trains a model and registers version N with lineage.
  2. Automated checks compare it with the current champion.
  3. Reviewer approves; CI/CD moves the alias in staging, then production.
  4. Serving loads the model by alias and deploys it.
  5. Rollback moves the alias back to version N-1.

Example

from mlflow import MlflowClient
import mlflow

client = MlflowClient()
mv = mlflow.register_model(f"runs:/{run_id}/model", "fraud-scorer")    # version 14
client.set_model_version_tag("fraud-scorer", mv.version, "validation_status", "approved")
client.set_registered_model_alias("fraud-scorer", "champion", mv.version)

# serving side
model = mlflow.pyfunc.load_model("models:/fraud-scorer@champion")
# rollback
client.set_registered_model_alias("fraud-scorer", "champion", "13")

Common mistakes

  • Serving models from hard-coded file paths instead of the registry.
  • Letting anyone move the production alias without review.
  • Registering models without data version or metrics.
  • Deleting old versions, removing the rollback path.

How to answer in the interview

"A model registry is a central catalogue of trained models with numbered versions. Each version links to the run that produced it, with parameters, metrics, code commit and data version, so lineage is clear. Versions get stages or aliases such as staging, production or champion and challenger, which describe their role without copying files. The training pipeline registers a version, automated evaluation and human review approve it, CI/CD promotes it by moving the alias, and serving deploys whatever holds the production alias. Rollback means pointing the alias back. MLflow, Azure ML, SageMaker and Vertex AI all provide this with permissions and audit history."

Likely follow-up questions

  • Who should be allowed to move the production alias? Only the CI/CD pipeline after approval, or a small set of owners, because it changes production behaviour.
  • Stages or aliases in MLflow? Aliases are the current recommendation; stages are deprecated.
  • How do you deploy a challenger safely? Shadow or canary traffic, comparing metrics with the champion.
