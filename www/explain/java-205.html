How does Java serialization work, and why is it discouraged today?

Core Java & OOP · concept · levels mid, senior

In one line

Java serialization writes object graphs of Serializable classes to a binary stream with ObjectOutputStream, using serialVersionUID for versioning and skipping transient fields; it is discouraged because of deserialization attacks, tight coupling to internals and poor portability.

Detailed explanation

A class opts in by implementing the marker interface java.io.Serializable. ObjectOutputStream.writeObject walks the whole object graph, writing class descriptors and non-transient, non-static field values; ObjectInputStream.readObject recreates the objects without calling their constructors (only the no-arg constructor of the first non-serialisable superclass runs). Hooks such as writeObject, readObject, readResolve and writeReplace customise the process.

serialVersionUID identifies the class version. If you do not declare it, the JVM computes one from the class structure, so even adding a method can change it and cause InvalidClassException when reading old data. Declare it explicitly if you must serialise.

Why it is discouraged:

  • Security. Deserialising untrusted bytes can execute code through gadget chains: classes on the classpath whose readObject or related methods do dangerous things. This caused major remote-code-execution incidents (for example via Apache Commons Collections in many app servers). Oracle's own architects have called serialization a "horrible mistake".
  • Fragility. The format exposes private fields, so refactoring breaks compatibility, and invariants enforced in constructors are bypassed.
  • Interoperability and performance. It is Java-only, verbose and slow compared with modern formats.

Prefer JSON (Jackson), Protocol Buffers or Avro with explicit schemas for APIs, messages and caches. If you are stuck with it, use deserialization filters (ObjectInputFilter, Java 9, and context-specific filter factories in Java 17) to allow-list classes, and use the serialization proxy pattern.

How it works

  1. Class implements Serializable; optionally declares serialVersionUID.
  2. writeObject writes class metadata and field values recursively, handling shared references and cycles.
  3. transient and static fields are skipped.
  4. readObject allocates objects without constructors and fills fields.
  5. Filters (if configured) accept or reject classes before instantiation.

Example

public class Session implements Serializable {
    private static final long serialVersionUID = 1L;
    private String userId;
    private transient String accessToken;   // not written
}

// Allow-list classes when reading
ObjectInputFilter filter = ObjectInputFilter.Config.createFilter(
        "com.shop.Session;java.base/*;!*");
try (var in = new ObjectInputStream(input)) {
    in.setObjectInputFilter(filter);
    Session s = (Session) in.readObject();
}

Common mistakes

  • Deserialising data from network, cookies or queues without filters.
  • Relying on the generated serialVersionUID.
  • Assuming constructors and validation run on deserialisation.
  • Using Java serialization for caches (for example Redis) that outlive deployments.

How to answer in the interview

"A class implements the Serializable marker interface, and ObjectOutputStream writes the object graph into a binary format, skipping transient and static fields. serialVersionUID identifies the class version, and a mismatch throws InvalidClassException. It's discouraged because deserialising untrusted data has led to many remote code execution attacks via gadget chains, it couples the format to private internals and bypasses constructors, and it's Java-only and slow. I use JSON with Jackson or Protobuf and Avro for messaging. If it's unavoidable, I configure ObjectInputFilter allow-lists."

Likely follow-up questions

  • What happens to a static field during serialization? It isn't serialised; after reading you see the current class value.
  • What does readResolve do? Replaces the deserialised object, e.g. to preserve singletons.
  • How do records serialise? Through their canonical constructor, which is safer.
