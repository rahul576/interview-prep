How do you use module-level for_each to create the same set of infrastructure several times?

Terraform · concept · levels mid, senior

In one line

Since Terraform 0.13, a module block accepts for_each (and count), so a map of settings creates one instance per key, addressed as module.app["eu"]; the module must not configure providers itself, and very large maps increase the blast radius of one state.

Detailed explanation

Copy-pasting the same module block for every team, region or environment is error-prone: a fix applied to one copy is forgotten in another. Module-level for_each expresses "the same set of infrastructure, N times, with different settings".

You pass a map (or set of strings). Inside the module block, each.key is the instance key and each.value holds its settings, which pairs well with an object type with optional() defaults. Each instance gets a stable address like module.team["payments"].aws_s3_bucket.this. Because instances are keyed by name, adding a new team creates only that instance and removing a key destroys only that instance, unlike count, where removing an item in the middle shifts indexes and can replace others. Outputs of the instances are available as a map, for example module.team["payments"].bucket_arn or { for k, m in module.team : k => m.bucket_arn }.

There are constraints. A module used with for_each or count must not contain provider configuration blocks; providers are passed from the root. And providers cannot be chosen dynamically per instance: the providers argument is static for all instances of one module block. So "one instance per region" still needs one aliased provider per region and typically one module block per region (or Stacks, which support provider for_each). Keys must be known at plan time, so they should come from configuration, not from computed values.

Finally, putting many instances into one state means a single plan touches all of them: plan time grows, a mistake in shared code affects every instance at once, and locking blocks everyone. For large or independently owned sets, split by team or environment into separate states.

How it works

  1. Define a map of instance settings in variables or locals.
  2. Add for_each = var.teams to the module block.
  3. Pass each.key and each.value attributes as inputs.
  4. Terraform creates instances module.x["key"].
  5. Reference outputs per key or with a for expression.

Example

variable "teams" {
  type = map(object({
    cpu_quota = string
    budget    = number
    admins    = list(string)
  }))
}

module "team" {
  source   = "./modules/team-namespace"
  for_each = var.teams

  name      = each.key
  cpu_quota = each.value.cpu_quota
  budget    = each.value.budget
  admins    = each.value.admins
}

output "namespaces" {
  value = { for k, m in module.team : k => m.namespace }
}

Common mistakes

  • Using count with a list, then removing an item and shifting all indexes.
  • Provider blocks inside the module.
  • Trying providers = { aws = each.value.provider }; not allowed.
  • Keys derived from computed values.
  • Hundreds of instances in one state.

How to answer in the interview

"Since Terraform 0.13 a module block accepts for_each and count like resources. I pass a map where each key is an instance, say a team or a region, and the value holds its settings, and inside the module block I use each.key and each.value. Each instance gets an address like module.team["payments"], and adding or removing a key only affects that instance because keys are stable. The module must not contain its own provider configuration, and providers can't be selected dynamically per instance, so for many regions I still need one aliased provider and module block per region. Large sets in one state increase blast radius and plan time, so I split them."

Likely follow-up questions

  • Same stack in five regions? Five aliased providers and five module blocks, separate states per region, or Stacks.
  • How do you rename a key without recreating? A moved block from the old key to the new key.
  • count or for_each on modules? for_each, except for simple on/off toggles with count = var.enabled ? 1 : 0.
