What is the difference between a hard link and a soft (symbolic) link?

Linux · concept · levels entry

In one line

A hard link is another directory entry for the same inode, so it survives deletion of the "original"; a symbolic link is a small file storing a path, so it breaks if the target is removed, but it can cross filesystems and point to directories.

Detailed explanation

In Linux, a file's data and metadata (permissions, owner, size, block pointers) live in an inode; the name is just a directory entry pointing at that inode number. A hard link (ln target linkname) adds a second directory entry pointing to the same inode. There is no "original" and "copy": both names are equal, they share content and permissions, and the inode's link count increases. Data is only freed when the link count reaches zero and no process has the file open.

A symbolic link or symlink (ln -s target linkname) is a separate small file with its own inode whose content is a path. The kernel follows that path when you open it. If the target is deleted, moved or renamed, the symlink becomes dangling (broken). ls -l shows symlinks with an l type and an arrow (app -> /opt/app-2.3).

Hard links have restrictions: they cannot cross filesystems, because inode numbers are only unique within one filesystem, and you normally cannot hard-link directories, to prevent loops in the tree. Symlinks can do both, and can even point to things that do not exist yet.

In practice, symlinks are everywhere: current -> releases/2026-11-20 for atomic deployments, /etc/nginx/sites-enabled pointing into sites-available, and the usr-merge links like /bin -> usr/bin. Hard links are used by backup tools such as rsync --link-dest to deduplicate unchanged files.

How it works

  1. A filename maps to an inode number in a directory.
  2. A hard link adds another name for the same inode; link count +1.
  3. Deleting one name decrements the count; data stays until zero.
  4. A symlink stores a path; the kernel resolves it on access.
  5. If the path no longer exists, the symlink is dangling.

Example

echo "hello" > report.txt
ln report.txt report-hard.txt
ln -s report.txt report-soft.txt
ls -li report*
# 1311 -rw-r--r-- 2 alice ... report-hard.txt
# 1311 -rw-r--r-- 2 alice ... report.txt
# 1320 lrwxrwxrwx 1 alice ... report-soft.txt -> report.txt
rm report.txt
cat report-hard.txt     # hello
cat report-soft.txt     # No such file or directory (dangling)
stat -c '%i %h %n' report-hard.txt   # inode and link count

Common mistakes

  • Thinking a hard link is a copy that can diverge.
  • Creating relative symlinks that break when moved.
  • Using rm -r on a symlinked directory path with a trailing slash and deleting the target's contents.
  • Expecting hard links across mount points to work.

How to answer in the interview

"A hard link is another directory entry pointing to the same inode, so both names refer to exactly the same data, and the data is only freed when the last link is removed. A symlink is a small file that stores a path to another file; if the original is deleted the symlink becomes dangling, while a hard link keeps working. Hard links cannot cross filesystems and normally cannot link directories, but symlinks can do both. I create them with ln and ln -s, and ls -l shows symlinks with an arrow. We use symlinks for things like a current release pointer in deployments."

Likely follow-up questions

  • How can you see the inode number and link count of a file? ls -li or stat.
  • How do you find broken symlinks? find . -xtype l.
  • Why are symlink swaps used for deployments? Replacing the link with ln -sfn (or an atomic rename) switches releases instantly.
