What are switch expressions and text blocks in modern Java?

Java 8+ Features · concept · levels entry, mid

In one line

Switch expressions (standard since Java 14) use arrow syntax, return a value, have no fall-through, use yield in blocks and are checked for exhaustiveness; text blocks (Java 15) are multi-line string literals in triple quotes that keep JSON, SQL or HTML readable.

Detailed explanation

The old switch statement was error-prone: forgetting break caused fall-through, you needed a mutable variable assigned in each case, and nothing told you if a case was missing. Switch expressions fix all three. With case X -> ... only the matching branch runs, several labels can share a branch (case SAT, SUN ->), and the whole switch evaluates to a value: var label = switch (status) { ... };. When a branch needs several statements, use a block and yield the result. Because the expression must produce a value for every input, the compiler requires exhaustiveness: all enum constants or all permitted subtypes of a sealed type, otherwise a default. Since Java 21, switch also supports type patterns, record patterns, guards (when) and case null.

Text blocks start with """ followed by a newline and end with """. They preserve line breaks, need no \n or escaped quotes, and strip incidental indentation based on the leftmost content line and the closing delimiter position. Escapes \ (line continuation) and \s (preserve a trailing space) give fine control. Combine with formatted(...) for values, but never build SQL with string concatenation of user input; use bind parameters.

How it works

  1. The switch selector is evaluated once.
  2. Labels are tested; the first match's arrow branch runs.
  3. A single expression or yield from a block supplies the value.
  4. The compiler verifies exhaustiveness and type compatibility.
  5. For text blocks, the compiler normalises line endings and removes common indentation at compile time.

Example

enum Status { NEW, PAID, SHIPPED, CANCELLED }

String label = switch (order.status()) {
    case NEW, PAID -> "In progress";
    case SHIPPED   -> "On the way";
    case CANCELLED -> {
        log.info("cancelled order {}", order.id());
        yield "Cancelled";
    }
};   // no default: compiler checks all enum constants are covered

String sql = """
    SELECT id, total
    FROM orders
    WHERE customer_id = ?
      AND status = 'PAID'
    """;

String json = """
    {"id": "%s", "status": "%s"}
    """.formatted(order.id(), label);

Common mistakes

  • Mixing : and -> labels in the same switch (not allowed).
  • Using return instead of yield inside an expression block.
  • Adding default to enum or sealed switches, hiding newly added cases.
  • Formatting user input into SQL text blocks instead of using parameters.

How to answer in the interview

"Switch expressions, standard since Java 14, use arrow syntax and evaluate to a value, so I can write var label = switch on status with one case per line. There's no fall-through, several labels can share a case, and yield returns a value from a block. The compiler checks exhaustiveness for enums and sealed types, which catches missing cases when someone adds a constant. Text blocks, standard since Java 15, are multi-line strings in triple quotes; they keep SQL, JSON or HTML readable without escaping and strip incidental indentation automatically."

Likely follow-up questions

  • How do switch expressions combine with sealed interfaces? Switching over a sealed type with type or record patterns is exhaustive without default.
  • Can the old colon syntax be used as an expression? Yes, with yield, but arrow form is clearer.
  • How is indentation decided in text blocks? By the least-indented non-blank line, including the closing delimiter.
