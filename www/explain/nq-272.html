What is JUnit 5?

Testing · concept · levels entry

In one line

JUnit 5 is the modern Java testing framework made of the JUnit Platform (runs tests), JUnit Jupiter (the API and extension model) and JUnit Vintage (runs JUnit 3/4 tests), offering annotations like @Test, @BeforeEach, @DisplayName, @Nested, parameterised tests, assertions such as assertThrows and assertAll, and the @ExtendWith extension model.

Detailed explanation

JUnit 5 was released in 2017 as a complete redesign of JUnit 4. Its architecture separates concerns:

  • The Platform is the foundation for launching tests on the JVM. IDEs (IntelliJ, Eclipse, VS Code), Maven Surefire and Gradle integrate with it, and other test engines can plug in.
  • Jupiter is what you write tests with: annotations in org.junit.jupiter.api and the extension API.
  • Vintage is an engine that runs legacy JUnit 4 tests, allowing gradual migration.

Core annotations: @Test; lifecycle hooks @BeforeEach, @AfterEach, @BeforeAll, @AfterAll (static unless the class uses @TestInstance(PER_CLASS)); @DisplayName for readable names; @Nested for grouping scenarios in inner classes; @Disabled; @Tag for selecting groups (e.g. "slow"); @Timeout; @TempDir; @RepeatedTest; @TestFactory for dynamic tests.

Parameterised tests: @ParameterizedTest with sources @ValueSource, @CsvSource, @CsvFileSource, @MethodSource, @EnumSource, @NullAndEmptySource, running the same test with many inputs.

Assertions (org.junit.jupiter.api.Assertions): assertEquals, assertTrue, assertNotNull, assertIterableEquals, assertThrows (returns the exception for further checks), assertAll (reports all failures together), assertTimeout; messages can be lazy Supplier<String>. Assumptions (assumeTrue) skip tests when preconditions are not met.

Extension model: @ExtendWith registers extensions that hook into the lifecycle, resolve parameters and handle exceptions. Mockito (MockitoExtension), Spring (SpringExtension, included in @SpringBootTest) and Testcontainers are all extensions, and several can be combined, unlike JUnit 4's single @RunWith. Test classes and methods can be package-private. JUnit 6, released in 2025, keeps the same Jupiter API with a Java 17 baseline.

How it works

  1. The build tool asks the Platform to discover tests.
  2. The Jupiter engine finds classes with @Test and other annotated methods.
  3. For each test, a new instance is created (default per-method lifecycle).
  4. Extensions and lifecycle methods run around each test.
  5. Results are reported per test to the IDE or build.

Example

@DisplayName("Shopping cart")
class CartTest {

    private Cart cart;

    @BeforeEach
    void setUp() { cart = new Cart(); }

    @Test
    void startsEmpty() { assertTrue(cart.isEmpty()); }

    @Nested
    class WhenItemAdded {
        @BeforeEach void add() { cart.add(new Item("BOOK", 2)); }

        @Test
        void reportsQuantity() {
            assertAll(
                () -> assertEquals(1, cart.lines()),
                () -> assertEquals(2, cart.quantityOf("BOOK")));
        }
    }

    @ParameterizedTest(name = "quantity {0} is rejected")
    @ValueSource(ints = {0, -1})
    void rejectsInvalidQuantity(int qty) {
        assertThrows(IllegalArgumentException.class, () -> cart.add(new Item("BOOK", qty)));
    }
}

Common mistakes

  • Importing org.junit.Test (JUnit 4) in a Jupiter-only build, so the test never runs.
  • Non-static @BeforeAll without per-class lifecycle.
  • Relying on test method execution order.
  • Putting the message first in assertEquals as in JUnit 4.

How to answer in the interview

"JUnit 5 is the current generation of JUnit, split into three parts: the Platform, which launches tests and integrates with IDEs and build tools; Jupiter, the API I write tests with; and Vintage, which runs old JUnit 4 tests. I use @Test, the lifecycle annotations BeforeEach, AfterEach and BeforeAll, DisplayName for readable names and Nested classes to group scenarios. ParameterizedTest with ValueSource or CsvSource runs the same test with many inputs. Assertions include assertEquals, assertThrows and assertAll. And instead of JUnit 4 runners it has an extension model, @ExtendWith, which Mockito and Spring plug into."

Likely follow-up questions

  • How do you write a parameterised test? @ParameterizedTest plus a source such as @CsvSource({"1,2,3"}) and matching method parameters.
  • What does assertAll do? Runs all grouped assertions and reports every failure together.
  • Can JUnit 4 and 5 tests coexist? Yes, with the Vintage engine on the Platform.
