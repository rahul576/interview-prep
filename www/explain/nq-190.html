What is request scope?

Spring Framework · concept · levels mid

In one line

A request-scoped bean has one instance per HTTP request, declared with @RequestScope; singletons receive a scoped proxy that routes each call to the instance bound to the current request thread, so it is ideal for per-request context but fails outside a web request.

Detailed explanation

Some data belongs to exactly one request: the authenticated user details, tenant id, correlation id, locale or a small request-level cache to avoid repeated lookups. A request-scoped bean gives each HTTP request its own instance, created on first use and discarded when the request completes (with destroy callbacks run at request end).

You declare it with @RequestScope, which is shorthand for @Scope(value = WebApplicationContext.SCOPE_REQUEST, proxyMode = ScopedProxyMode.TARGET_CLASS). The proxy is essential. Controllers and services are singletons created at startup, when there is no request at all. So Spring injects a CGLIB proxy instead of the real object. Each time you call a method on the proxy, it looks up the current request through RequestContextHolder, which stores request attributes in a ThreadLocal bound by DispatcherServlet or RequestContextFilter, finds or creates the instance stored in that request, and delegates the call.

Because the lookup is thread-bound, it works only on the thread handling the request. From an @Async method, a CompletableFuture task, a scheduled job, a Kafka listener or a parallel stream, there is no bound request and Spring throws IllegalStateException: No thread-bound request found (or "Scope 'request' is not active"). In those cases pass the data explicitly or propagate context with a TaskDecorator.

For WebFlux, request scope does not exist; use the Reactor Context or exchange attributes instead.

How it works

  1. Startup: singletons receive a scoped proxy for the request bean.
  2. A request arrives; DispatcherServlet binds request attributes to the thread.
  3. A method call on the proxy looks up the bean in the current request attributes.
  4. If missing, Spring creates and stores a new instance for this request.
  5. At request end, attributes are cleared and the instance's destroy callbacks run.

Example

@Component
@RequestScope
public class RequestContext {
    private String tenantId;
    private String correlationId;
    // getters and setters
}

@Component
class TenantFilter extends OncePerRequestFilter {
    private final RequestContext ctx;
    TenantFilter(RequestContext ctx) { this.ctx = ctx; }
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain chain)
            throws ServletException, IOException {
        ctx.setTenantId(req.getHeader("X-Tenant"));
        chain.doFilter(req, res);
    }
}

@Service
class InvoiceService {
    private final RequestContext ctx;              // proxy
    InvoiceService(RequestContext ctx) { this.ctx = ctx; }
    List<Invoice> list() { return repo.findByTenant(ctx.getTenantId()); }
}

Common mistakes

  • Accessing request beans from @Async or scheduled threads.
  • Declaring @Scope("request") without a proxy mode and injecting it into a singleton, failing at startup.
  • Putting heavy objects in request scope when a parameter would do.
  • Assuming it works in WebFlux.

How to answer in the interview

"A request-scoped bean lives for one HTTP request: each request gets its own instance, discarded when it completes. I declare it with @RequestScope, which includes proxyMode TARGET_CLASS. Because singletons are created once, Spring injects a proxy, and every method call is routed to the instance bound to the current request thread through RequestContextHolder. I use it for per-request data like the user context, tenant id or correlation id. It only works inside a web request; from an Async method or scheduled job it fails with no thread-bound request found."

Likely follow-up questions

  • Why does it fail in @Async? The async thread has no request attributes bound; copy the data or use a TaskDecorator.
  • Request scope vs ThreadLocal? Request scope is managed and cleaned up by Spring; raw ThreadLocals leak in pools if not cleared.
  • Alternative for logging context? MDC with correlation id, propagated by Micrometer context propagation.
