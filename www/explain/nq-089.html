How does CompletableFuture differ from Future and Callable?

Concurrency · concept · levels mid

In one line

Callable is the task; Future is a handle to its result with only blocking get(), isDone() and cancel(); CompletableFuture is a Future plus CompletionStage: callbacks, chaining, combining, built-in error handling and manual completion.

Detailed explanation

These three are often confused because they appear together, but they play different roles.

Callable<V> is a functional interface describing work: V call() throws Exception. It does not run by itself; you give it to an executor.

Future<V> (Java 5) is what ExecutorService.submit returns: a handle to a result that may not exist yet. Its API is small: get() and get(timeout) block until done, isDone(), isCancelled() and cancel(mayInterrupt). Java 19 added resultNow(), exceptionNow() and state() for inspecting completed futures without checked exceptions. What it cannot do is notify you: there is no way to say "when this finishes, do that". To combine two Futures you must block on both; to transform the result you must block first; exceptions only appear, wrapped in ExecutionException, when you call get(). So Futures push you towards blocking threads.

CompletableFuture<V> (Java 8) implements Future and CompletionStage. You can still get() or join(), but the point is non-blocking composition: thenApply, thenCompose, thenCombine, thenAccept, allOf, anyOf; error handling with exceptionally, handle, whenComplete; timeouts with orTimeout. It can also be completed manually with complete() / completeExceptionally(), so it can wrap callback APIs (a message listener, an async HTTP client) without any thread waiting. It does not need a Callable: you usually start it with a Supplier via supplyAsync.

One behavioural difference: cancel(true) on a FutureTask interrupts the running thread, whereas on a CompletableFuture it only marks it cancelled.

How it works

  1. Callable defines work; submit wraps it in a FutureTask and returns it as a Future.
  2. With Future, the caller blocks on get() to use the result.
  3. With CompletableFuture, supplyAsync starts work and returns immediately.
  4. Callbacks are registered and run when the stage completes.
  5. Manual completion lets any code (a callback, another thread) supply the result.

Example

// Future: must block to use results
Future<Rate> rateF = pool.submit(() -> fx.rate("EUR"));        // Callable
Future<Price> priceF = pool.submit(() -> catalog.price(sku));
Money total = priceF.get().convert(rateF.get());                // two blocking calls

// CompletableFuture: composed without blocking
CompletableFuture<Money> totalCf =
        CompletableFuture.supplyAsync(() -> catalog.price(sku), pool)
            .thenCombine(CompletableFuture.supplyAsync(() -> fx.rate("EUR"), pool),
                         Price::convert)
            .exceptionally(ex -> Money.ZERO);

// Manual completion bridging a callback API
CompletableFuture<Reply> reply = new CompletableFuture<>();
client.send(request, new Callback() {
    public void onSuccess(Reply r) { reply.complete(r); }
    public void onError(Throwable t) { reply.completeExceptionally(t); }
});

Common mistakes

  • Calling Callable and Future the same thing.
  • Blocking on CompletableFuture.get() immediately, losing its benefits.
  • Expecting CompletableFuture.cancel(true) to interrupt work.
  • Mixing blocking get() calls inside callback chains.

How to answer in the interview

"Callable is just a task that returns a value. Future is the handle I get when I submit it to an executor, and it's limited: I can check isDone, cancel, or block with get, but I can't attach a callback, chain another step, combine two futures or handle an exception without blocking. CompletableFuture implements both Future and CompletionStage: I can still block with get or join, but mostly I build non-blocking pipelines with thenApply, thenCompose, thenCombine and allOf, handle errors with exceptionally or handle, and I can complete it myself, which is great for bridging callback APIs."

Likely follow-up questions

  • When might a plain Future still be enough? When you submit a task and simply wait for it at one point, for example in a batch job or with invokeAll.
  • What is FutureTask? The standard Future implementation that is also a Runnable, wrapping a Callable.
  • How do you convert a callback API to CompletableFuture? Create an empty CompletableFuture and call complete or completeExceptionally from the callbacks.
