How would you convert product names to uppercase using method references?

Coding Exercises · scenario · levels entry

In one line

Chain two method references: products.stream().map(Product::getName).map(String::toUpperCase).toList(); both are references to an instance method of an arbitrary object of a type (unbound), and for locale-safe results use s -> s.toUpperCase(Locale.ROOT).

Detailed explanation

A method reference is shorthand for a lambda that only calls an existing method. Java has four kinds:

  1. Static method: Integer::parseInt means s -> Integer.parseInt(s).
  2. Instance method of a particular (bound) object: System.out::println means x -> System.out.println(x).
  3. Instance method of an arbitrary object of a type (unbound): String::toUpperCase means s -> s.toUpperCase() — the first parameter becomes the receiver.
  4. Constructor: ArrayList::new means () -> new ArrayList<>().

Both Product::getName (p -> p.getName()) and String::toUpperCase (s -> s.toUpperCase()) are of the third kind: the stream element is the object on which the method is invoked.

Two maps vs one lambda. map(p -> p.getName().toUpperCase()) works too, but two small maps with method references read like a sentence — "take the name, upper-case it" — and each step is independently reusable. Performance is effectively identical because the JIT inlines such tiny calls.

Locale. String.toUpperCase() without arguments uses the default locale of the JVM. In a Turkish locale, "title".toUpperCase() produces "TİTLE" with a dotted capital İ, which breaks comparisons, keys and identifiers. For machine-oriented text (codes, keys, enum names) use toUpperCase(Locale.ROOT). Since String::toUpperCase cannot carry an argument, you write a lambda: map(s -> s.toUpperCase(Locale.ROOT)). For display text in a known language, pass that locale.

Nulls. If some names are null, String::toUpperCase throws NullPointerException; add filter(Objects::nonNull) or handle missing names explicitly.

If you need products, not strings, map to new objects instead: map(p -> p.withName(p.getName().toUpperCase(Locale.ROOT))).

How it works

  1. map(Product::getName) converts Stream<Product> to Stream<String>.
  2. map(String::toUpperCase) converts each string.
  3. toList() collects into a new unmodifiable list.
  4. The original products are unchanged.

Example

List<String> names = products.stream()
        .map(Product::getName)
        .map(String::toUpperCase)
        .toList();

// locale-safe
List<String> safe = products.stream()
        .map(Product::getName)
        .filter(Objects::nonNull)
        .map(s -> s.toUpperCase(Locale.ROOT))
        .toList();

// keep products, change names
List<Product> renamed = products.stream()
        .map(p -> p.withName(p.getName().toUpperCase(Locale.ROOT)))
        .toList();

products.stream().map(Product::getName).forEach(System.out::println); // bound reference

Common mistakes

  • Ignoring locale for keys or identifiers.
  • Expecting the original products' names to change.
  • Calling String::toUpperCase on null names.
  • Calling the unbound form a static method reference.

How to answer in the interview

"I'd write products.stream().map(Product::getName).map(String::toUpperCase).toList(). Both are references to an instance method of an arbitrary object of a type: Product::getName means p -> p.getName(), and String::toUpperCase means s -> s.toUpperCase(). Two simple maps read better than one lambda doing both. For locale-safe behaviour, for example the Turkish i problem, I'd use s -> s.toUpperCase(Locale.ROOT). If I needed products with upper-case names rather than strings, I'd map to new Product objects instead."

Likely follow-up questions

  • Which kind is String::toUpperCase? Unbound instance method reference: the element is the receiver.
  • When can't you use a method reference? When you need extra arguments or logic, like a locale.
  • Are method references faster than lambdas? Effectively the same after JIT.
