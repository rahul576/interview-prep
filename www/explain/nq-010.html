How do text blocks simplify multiline strings?

Modern Java (11-21) · concept · levels entry

In one line

Text blocks (standard since Java 15) are multiline string literals between """ delimiters that need no escaping of quotes or newlines, automatically strip incidental indentation, and are ideal for SQL, JSON and HTML, with formatted() for values.

Detailed explanation

Before text blocks, embedding JSON or SQL in Java meant concatenating lines with +, adding \n and escaping every double quote. The result was unreadable and easy to break.

A text block starts with three double quotes followed by a line break (content cannot begin on the opening line) and ends with three double quotes. Inside, you write the text as it should look; double quotes do not need escaping.

Indentation is handled by the compiler. It looks at all non-blank content lines and the closing delimiter line, finds the smallest common leading whitespace, and removes it. This is incidental indentation caused by your code formatting. Anything beyond it is essential indentation and is kept. So moving the closing """ further left keeps more indentation; placing it at the end of the last line means no trailing newline.

Other rules: line endings are normalised to \n, trailing spaces on each line are stripped, \ at the end of a line joins it with the next (useful for long single-line strings), and \s produces a single space that survives stripping. The result is an ordinary String, so .formatted(...) (Java 15), String.format or a template engine fill in values.

Use them for SQL in @Query annotations, JSON fixtures in tests, GraphQL queries, HTML snippets and log message templates. Never build SQL from user input with formatted; use bind parameters to avoid SQL injection.

How it works

  1. Opening """ then newline.
  2. Compiler removes common leading whitespace (incidental indentation).
  3. Trailing spaces stripped; escapes processed (\ line join, \s).
  4. Result is a normal String constant.

Example

@Query("""
    SELECT o FROM Order o
    WHERE o.status = :status
      AND o.createdAt > :since
    ORDER BY o.createdAt DESC
    """)
List<Order> recent(String status, Instant since);

String json = """
    {
      "orderId": "%s",
      "amount": %d
    }
    """.formatted(orderId, amount);

String oneLine = """
    This is a very long sentence \
    kept on one line.""";

Common mistakes

  • Putting text on the same line as the opening """ (compile error).
  • Being surprised by a trailing newline before the closing delimiter.
  • Using formatted to inject user input into SQL.
  • Mixing tabs and spaces, which confuses indentation stripping.

How to answer in the interview

"Text blocks, standard since Java 15, are multiline string literals between triple quotes. Instead of concatenating lines and escaping every quote and newline, I write the JSON or SQL exactly as it looks. The compiler removes the incidental indentation that comes from code layout, based on the least indented line including the closing delimiter, normalises line endings and strips trailing spaces. A backslash at a line end joins lines and \s keeps a space. I use them for JPQL in @Query annotations and JSON payloads in tests, and fill values with formatted, but never for building SQL from user input."

Likely follow-up questions

  • How is indentation inside a text block decided? By the minimum common indentation of content lines and the closing delimiter; the rest is kept.
  • Are text blocks different at runtime? No, they compile to ordinary String constants.
  • How do you avoid the trailing newline? Put the closing """ directly after the last content.
