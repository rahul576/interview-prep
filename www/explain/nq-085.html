What is the difference between wait(), sleep(), yield(), and join()?

Concurrency · concept · levels mid

In one line

wait() (an Object method) releases the monitor and waits for a notification; sleep() pauses for a time keeping any locks; yield() is a scheduler hint to let other threads run; join() waits until another thread terminates.

Detailed explanation

wait() belongs to Object and must be called while holding that object's monitor, inside synchronized (obj), otherwise IllegalMonitorStateException is thrown. It atomically releases the lock and parks the thread in the object's wait set until notify()/notifyAll(), a timeout (wait(ms)), interruption or a spurious wakeup. Before returning it reacquires the lock. It is for condition-based coordination, and must be used in a while loop.

Thread.sleep(ms) is a static method that pauses the current thread for at least the given time. It does not release any locks it holds, so sleeping inside a synchronized block blocks every other thread needing that lock. It is for time-based delays, such as simple retry backoff or tests; it is not a coordination mechanism. On virtual threads, sleep parks the virtual thread without blocking a carrier.

Thread.yield() is a static hint that the current thread is willing to give up the CPU so other runnable threads can run. The scheduler may ignore it. It does not release locks, has no guarantees and is rarely useful outside of spin-wait experiments; Thread.onSpinWait() is the modern hint for busy-wait loops.

join() is an instance method called on another thread object: worker.join() makes the current thread wait until worker terminates (or until a timeout with join(ms)). When it returns, everything the worker did is visible (thread termination happens-before join returning). It is implemented with wait internally on platform threads.

wait, sleep and join all throw the checked InterruptedException if the thread is interrupted while waiting; yield does not.

How it works

  1. wait: hold lock, call obj.wait(), lock released, sleep until notified, reacquire, re-check condition.
  2. sleep: thread goes TIMED_WAITING for the duration, locks still held.
  3. yield: thread moves from running to runnable; scheduler may reschedule it immediately.
  4. join: caller waits (WAITING) until target is TERMINATED.
  5. Interrupts wake wait/sleep/join with InterruptedException.

Example

Object lock = new Object();

Thread worker = new Thread(() -> {
    synchronized (lock) {
        try {
            Thread.sleep(1000);      // holds 'lock' the whole second
            lock.notifyAll();
        } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
    }
});

synchronized (lock) {
    worker.start();
    lock.wait(5000);                 // releases 'lock', so worker can enter
}
worker.join();                        // wait until worker has finished
Thread.yield();                       // just a hint, no guarantee

(Real code would wait in a loop on a condition variable.)

Common mistakes

  • Calling wait() without holding the monitor.
  • Sleeping while holding a lock, blocking others.
  • Using sleep to "wait until another thread is ready" instead of proper coordination.
  • Relying on yield() for correctness.
  • Swallowing InterruptedException.

How to answer in the interview

"wait is an Object method I call inside synchronized on that object: the thread releases the monitor and waits until another thread calls notify or notifyAll, or a timeout, then reacquires the lock. sleep is a static Thread method that pauses the current thread for a time without releasing any locks. yield is a static hint to the scheduler that the thread is willing to give up the CPU; it has no guarantees and is rarely useful. join is called on another thread and makes the current thread wait until that thread terminates, optionally with a timeout. wait, sleep and join all throw InterruptedException."

Likely follow-up questions

  • What happens if you call wait() without holding the lock? It throws IllegalMonitorStateException.
  • Why is wait on Object and sleep on Thread? wait is tied to an object's monitor and wait set; sleep only concerns the current thread's timing.
  • What does join guarantee about memory? All actions of the terminated thread are visible to the thread that returns from join.
