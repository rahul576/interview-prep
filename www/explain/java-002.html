Explain the difference between the JDK, the JRE and the JVM.

Core Java & OOP · concept · levels entry

In one line

The JVM executes bytecode; the JRE is the JVM plus the standard class libraries needed to run programs; the JDK is the JRE plus development tools such as javac, jar, javadoc, jdb, jlink and jcmd.

Detailed explanation

JVM (Java Virtual Machine) is the runtime engine. It loads classes (class loaders), verifies bytecode, and executes it, first with an interpreter and then, for hot code, with the JIT compiler (C1 and C2 in HotSpot) which compiles to optimised native machine code. It also manages memory, garbage collection, threads and security checks. The JVM is a specification; HotSpot (in OpenJDK) is the main implementation, with alternatives such as OpenJ9, and GraalVM adds a different JIT and native-image compilation.

JRE (Java Runtime Environment) is the JVM plus the Java SE class libraries (java.lang, java.util, java.net...) and supporting files. Historically, end users installed a JRE to run applications.

JDK (Java Development Kit) contains everything in the runtime plus developer tools: the javac compiler, java launcher, jar, javadoc, jdb, jshell, diagnostic tools (jcmd, jstack, jmap, jfr) and jlink/jpackage.

Platform independence comes from this split: javac compiles .java source into platform-neutral bytecode (.class), and any conforming JVM on Windows, Linux or macOS runs it: "write once, run anywhere". The JVM itself is platform-specific.

Modern reality: since Java 9 the platform is modular, and since Java 11 Oracle and most OpenJDK vendors (Temurin, Corretto, Zulu) no longer ship a separate JRE download. Instead you use the JDK, or build a custom minimal runtime containing only needed modules with jlink, which is common for container images. Distroless or vendor "JRE" images are often jlink-built runtimes.

How it works

  1. Write App.java.
  2. javac (JDK) compiles it to App.class bytecode.
  3. java App starts the JVM, which loads and verifies the class.
  4. The interpreter runs bytecode; hot methods are JIT-compiled to native code.
  5. The JVM uses the class libraries (runtime) and manages memory with the GC.

Example

javac -d out src/com/shop/App.java        # JDK tool: source -> bytecode
java -cp out com.shop.App                  # JVM runs the bytecode
javap -c -cp out com.shop.App              # inspect the bytecode

# Build a minimal runtime for a container (Java 9+)
jdeps --print-module-deps app.jar          # e.g. java.base,java.sql
jlink --add-modules java.base,java.sql \
      --strip-debug --no-header-files --no-man-pages \
      --output /opt/runtime
/opt/runtime/bin/java -jar app.jar

Common mistakes

  • Saying the JVM compiles Java source; javac does, the JVM JIT-compiles bytecode.
  • Claiming Java is purely interpreted.
  • Saying bytecode is platform-specific; the JVM is.
  • Not knowing that separate JRE downloads largely disappeared after Java 11.

How to answer in the interview

"The JVM loads and executes compiled bytecode, using an interpreter and a JIT compiler for hot code, and it manages memory and garbage collection. The JRE is the JVM plus the standard class libraries needed to run applications. The JDK contains all of that plus development tools like javac, jar, javadoc, jshell and diagnostic tools like jcmd. Because code is compiled to bytecode that any JVM can run, Java is platform-independent, while each JVM is platform-specific. Since Java 11 a separate JRE isn't really shipped any more, and for containers I use jlink to build a minimal custom runtime."

Likely follow-up questions

  • What does the JIT compiler do, and why does it matter for performance? It profiles running code and compiles hot methods to optimised native code, using inlining and escape analysis, so long-running Java can approach native speed.
  • What is a class loader? A component that finds and loads class bytecode; the bootstrap, platform and application loaders form a delegation hierarchy.
  • What is GraalVM native image? Ahead-of-time compilation of a Java app into a native executable with fast startup and low memory, with some reflection limits.
