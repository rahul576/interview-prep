What are the main limitations of current LLMs that engineers must design around?

AI/ML & GenAI · concept · levels mid, senior

In one line

Engineers must design around hallucinations, knowledge cutoffs, finite and imperfectly used context, non-determinism and prompt sensitivity, prompt injection, weak exact computation, and real cost and latency; good LLM systems stay correct despite these limits.

Detailed explanation

Hallucination: models generate plausible text, not verified facts, so they can state wrong things confidently, invent APIs or cite sources that do not exist. Mitigation: ground answers in retrieved sources, require citations, let tools fetch facts, and validate outputs.

Knowledge cutoff and no private data: a model knows only what was in its training data up to a date and nothing about your company. Retrieval (RAG) and tool calls supply current and private information.

Context limits: context windows are large, but long inputs cost more, add latency and are used less reliably; information buried in the middle may be ignored. Curate context: retrieve the relevant chunks, summarise history and put key instructions clearly.

Non-determinism and sensitivity: the same prompt can give different answers, and small wording changes alter behaviour. Use structured outputs with JSON Schema, validation and retries, low temperature where appropriate, and evaluate statistically with test sets rather than one-off checks.

Prompt injection and jailbreaks: untrusted text in emails, web pages or tickets can override instructions. Security must come from architecture: least-privilege tools, human approval for risky actions and separation of data from instructions, not from asking the model nicely.

Exact computation: counting, arithmetic on large numbers and precise date logic are unreliable without tools such as a code interpreter or calculator.

Cost and latency: every token costs money and time, especially for large and reasoning models. This drives model routing, caching (including prompt caching), streaming and batching.

How it works

  1. Ground facts through retrieval and tools, with citations.
  2. Constrain outputs with schemas and validate them in code.
  3. Curate and trim context rather than dumping everything.
  4. Give tools least privilege and gate risky actions with approval.
  5. Offload exact maths and lookups to deterministic code.
  6. Evaluate continuously and monitor quality, cost and latency.

Example

resp = client.generate(model="small-fast-model",
    prompt=build_prompt(question, retrieved_chunks),
    response_schema=AnswerSchema)          # JSON Schema enforced
answer = AnswerSchema.model_validate_json(resp.text)
if not all(c in retrieved_ids for c in answer.citations):
    answer = escalate_to_larger_model_or_human(question)

The design checks citations against what was actually retrieved, instead of trusting the model.

Common mistakes

  • Treating the model as a database of facts.
  • Relying on a system prompt as the only security control.
  • Testing a prompt once and assuming it always works.
  • Sending huge contexts "just in case", raising cost and lowering accuracy.

How to answer in the interview

"I design around a few known limits. Models hallucinate, so important facts are grounded in retrieved sources or tools and verified. They have a knowledge cutoff and no private data, which retrieval provides. Context is finite and long inputs are used less reliably, so I curate it. Outputs vary and are sensitive to wording, so I use structured outputs, validation and evaluation sets. Prompt injection means security comes from least privilege and approvals, not instructions. Exact maths goes to tools. And cost and latency push me to route simple tasks to smaller models and cache. In my experience, hallucinated or unvalidated output causes most incidents."

Likely follow-up questions

  • Which limitation causes most incidents? Unvalidated, confidently wrong output reaching users or systems.
  • Does temperature 0 make outputs deterministic? Not fully; batching and infrastructure can still cause variation.
  • How do you measure hallucination? Groundedness checks against sources, human review samples and LLM-as-judge calibrated against humans.
