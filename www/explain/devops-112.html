How does storage work in Kubernetes? Explain PV, PVC and StorageClass.

Kubernetes · concept · levels mid, senior

In one line

A PersistentVolume (PV) is a piece of storage; a PersistentVolumeClaim (PVC) is a workload's request for size and access mode; a StorageClass lets a CSI driver provision volumes dynamically, with a reclaim policy and binding mode such as WaitForFirstConsumer for zone-aware placement.

Detailed explanation

Containers have ephemeral filesystems: when a pod is replaced, its data is gone. Kubernetes separates what storage a workload needs from how it is provided.

PersistentVolume. A cluster-scoped object representing real storage: an EBS volume, Azure Disk, GCE persistent disk, NFS share or local disk. It has a capacity, access modes, a reclaim policy and the driver details. Admins can create PVs statically, but usually they are created dynamically.

PersistentVolumeClaim. A namespaced request: "10 GiB, ReadWriteOnce, class gp3". Kubernetes binds the claim to a matching PV one-to-one; pods reference the claim, not the PV, so manifests stay portable.

StorageClass. Describes a type of storage and the provisioner (a CSI driver such as ebs.csi.aws.com or disk.csi.azure.com) plus parameters (disk type, IOPS, encryption). When a PVC names a class, or uses the default class, the CSI driver creates a volume and PV automatically. allowVolumeExpansion: true allows growing claims.

Access modes. ReadWriteOnce (one node read-write, typical for block disks), ReadWriteOncePod (one pod only), ReadOnlyMany and ReadWriteMany (many nodes, needs file storage such as EFS, Azure Files or NFS).

Reclaim policy. Delete removes the underlying disk when the PVC is deleted (default for dynamic provisioning); Retain keeps it for manual recovery, wise for important data.

Binding mode. With Immediate, the disk is created as soon as the PVC exists, possibly in a zone where the pod cannot run. WaitForFirstConsumer delays provisioning until the pod is scheduled, then creates the disk in that node's zone. Block volumes are zonal, so a pod cannot later move to another zone without its data being moved too.

How it works

  1. StatefulSet or pod spec references a PVC with class gp3.
  2. Pod is scheduled; with WaitForFirstConsumer the zone is now known.
  3. CSI controller creates the disk; a PV is created and bound to the PVC.
  4. Kubelet and CSI node plugin attach and mount the volume into the pod.
  5. On PVC deletion the reclaim policy deletes or retains the disk.

Example

apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata: { name: gp3 }
provisioner: ebs.csi.aws.com
parameters: { type: gp3, encrypted: "true" }
reclaimPolicy: Retain
volumeBindingMode: WaitForFirstConsumer
allowVolumeExpansion: true
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata: { name: data, namespace: shop }
spec:
  accessModes: [ReadWriteOnce]
  storageClassName: gp3
  resources: { requests: { storage: 20Gi } }

Common mistakes

  • Expecting ReadWriteMany from block storage.
  • Immediate binding in multi-zone clusters, creating disks in the wrong zone.
  • Delete reclaim policy on critical data without backups (VolumeSnapshots).
  • Missing CSI driver or default StorageClass after a cluster upgrade.

How to answer in the interview

"A PersistentVolume represents real storage, like a cloud disk. A PersistentVolumeClaim is a workload's request for a size and access mode, and pods reference the claim. A StorageClass enables dynamic provisioning: when a PVC references it, the CSI driver creates the volume and PV automatically. Access modes include ReadWriteOnce for a single node, ReadWriteOncePod, and ReadWriteMany for shared file storage. The reclaim policy decides whether the disk is deleted or retained when the claim goes away, and WaitForFirstConsumer creates the disk in the same zone as the scheduled pod."

Likely follow-up questions

  • Why might a pod be stuck Pending with an unbound PVC? No default or wrong StorageClass, missing CSI driver, no matching static PV, quota limits, or zone conflicts; kubectl describe pvc shows events.
  • How do you back up volumes? CSI VolumeSnapshots or tools like Velero.
  • Can you resize a PVC? Yes, if the class allows expansion and the driver supports it.
