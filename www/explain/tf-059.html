How do you use terraform console, and for what tasks?

Terraform · concept · levels entry, mid, senior

In one line

terraform console is an interactive, read-only shell that evaluates Terraform expressions against the current configuration, variables and state, ideal for testing functions, building for expressions and debugging locals before putting them in code.

Detailed explanation

Terraform expressions can get complex: nested for expressions, flatten, merge, cidrsubnet, regex. Iterating by running full plans is slow and noisy. The console lets you type an expression and see its value immediately.

When you start it in an initialised directory, it loads the configuration, variable values (from tfvars, -var and -var-file, environment variables) and the current state through the backend. So you can inspect var.environment, local.common_tags, or real attributes such as azurerm_virtual_network.main.address_space from state. Values that are only known after apply show as (known after apply).

Typical uses:

  • Testing functions: cidrsubnet("10.0.0.0/16", 8, 2) returns "10.0.2.0/24"; formatdate, regex, jsondecode behave as expected.
  • Developing for expressions: building the flatten-to-map transformation for for_each step by step, and checking that keys are unique and readable.
  • Debugging locals whose result surprises you, or checking what a module output contains.
  • Scripting: pipe an expression in non-interactively, echo 'local.subnets' | terraform console, useful in tests or scripts.

The console never changes infrastructure. But because it reads state, it needs backend access, and it may display sensitive values from state, so treat it with the same care as state pull. It also holds the state lock while open, so exit it when done in shared environments.

How it works

  1. Run terraform init so providers, modules and backend are ready.
  2. Start terraform console, optionally with -var-file.
  3. Type expressions; Terraform evaluates them with current inputs and state.
  4. Refine the expression until the output is right.
  5. Copy it into a local or resource argument; exit with exit or Ctrl+D.

Example

$ terraform console -var-file=prod.tfvars
> cidrsubnet("10.0.0.0/16", 8, 2)
"10.0.2.0/24"
> [for i in range(3) : cidrsubnet("10.0.0.0/16", 8, i)]
[
  "10.0.0.0/24",
  "10.0.1.0/24",
  "10.0.2.0/24",
]
> keys(local.subnets)
[
  "hub/AzureFirewallSubnet",
  "hub/GatewaySubnet",
]
> exit

$ echo 'local.common_tags' | terraform console

Common mistakes

  • Debugging complex expressions by running repeated full plans.
  • Forgetting to pass the same var files as the real pipeline, getting different results.
  • Leaving a console open and holding the state lock.
  • Printing sensitive values from state on shared screens.

How to answer in the interview

"terraform console is an interactive shell that evaluates Terraform expressions using the current configuration, variables and state. I use it to test functions, like checking what cidrsubnet returns, to build tricky for expressions with flatten before using them in for_each, and to debug locals that don't produce what I expect. It can also run non-interactively by piping an expression in. It's read-only and never changes infrastructure, but it reads state, so it needs backend access and can show sensitive data."

Likely follow-up questions

  • How would you debug unexpected for_each keys? Evaluate keys(local.map) in the console and fix the composite key.
  • Can it evaluate resources not yet created? Their computed attributes show as known after apply.
  • Alternatives? Temporary outputs or terraform test with assertions.
