What is the difference between latency and throughput, and why do percentiles matter?

SD Fundamentals · concept · levels entry, mid

In one line

Latency is how long one request takes; throughput is how many requests are handled per second. Measure latency as percentiles (p50, p95, p99) because averages hide the slow tail that users feel.

Detailed explanation

The two interact. As utilisation approaches 100%, queues form and latency grows sharply, even before throughput stops increasing (queueing theory). That's why systems are run with headroom, often at 50–70% utilisation.

Averages are misleading: if 99 requests take 50 ms and one takes 5 s, the average is ~100 ms, which describes nobody. p99 tells you that 1 in 100 requests is slower than that value. In systems with fan-out, tail latency compounds: if a page calls 20 services and each has a 1% chance of being slow, about 18% of page loads hit at least one slow call.

How it works

  1. Record request durations as histograms (Prometheus, OpenTelemetry).
  2. Compute p50/p95/p99 per endpoint.
  3. Set SLOs on percentiles, e.g. 99% of checkout requests < 300 ms.
  4. Reduce tail latency with timeouts, caching, avoiding GC pauses, and hedged requests (send a second request if the first is slow).

Example

histogram_quantile(0.99,
  sum by (le, route) (rate(http_server_request_duration_seconds_bucket[5m])))

This query gives p99 latency per route over 5 minutes.

Common mistakes

  • Reporting only average latency.
  • Averaging percentiles across servers (mathematically wrong; aggregate histograms instead).
  • Load testing only throughput while latency silently explodes.
  • Ignoring client-side latency (network, rendering).

How to answer in the interview

"Latency is time per request and throughput is requests per second. They're linked: near capacity, queueing makes latency spike. I always look at percentiles, not averages, because p99 is what users complain about, and with fan-out the tail dominates. So I set SLOs on p95 or p99 and keep capacity headroom."

Likely follow-up questions

  • What are hedged requests? Send a duplicate request after a short delay to another replica; use whichever returns first.
  • Why keep utilisation below 100%? Queueing delay grows non-linearly near saturation.
  • How do you aggregate p99 across instances? Merge histograms, never average percentiles.
