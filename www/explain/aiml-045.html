What is named entity recognition and information extraction, and how do LLMs change it?

AI/ML & GenAI · concept · levels mid, senior

In one line

NER finds and classifies entities (people, organisations, dates, amounts, codes) and information extraction pulls structured fields from documents; LLMs let you extract custom fields from a schema and instructions without training, using structured outputs for valid JSON, plus rule validation and field-level accuracy measurement.

Detailed explanation

Named entity recognition tags spans of text with types: PERSON, ORG, LOCATION, DATE, MONEY, product codes. Information extraction is broader: turning documents into records, such as invoice number, supplier, line items and total; contract parties, governing law and renewal date; symptoms and medications in clinical notes; or relations between entities.

Traditional approaches use rule-based patterns (regular expressions for IBANs, dates), statistical sequence models, and fine-tuned transformer models such as BERT-based taggers or spaCy pipelines. They are fast, cheap and accurate on the entity types they were trained for, but each new entity type or document style needs labelled training data, and complex fields that require reasoning (for example "termination notice period") are hard.

LLMs changed the economics. Given a schema and instructions, they extract custom fields from emails, PDFs, scanned documents (with vision) and transcripts without training, cope with varied layouts and wording, resolve references ("the Supplier" means the company named earlier) and normalise values (dates to ISO 8601, amounts to numbers with currency). Structured output features, such as JSON schema mode or tool calling, guarantee syntactically valid JSON matching the schema, though not correct values.

So validation remains essential: rules (line items sum to total, dates plausible, VAT number format valid, required fields present), cross-checks against master data, asking the model to quote the source text span for each field, and routing low-confidence or failed cases to human review. Measure field-level precision and recall on a labelled sample, since an overall document score hides which fields fail. For very high volumes, a hybrid of regex and small models for easy fields, with an LLM for complex ones, keeps cost down.

How it works

  1. Define the target schema with field descriptions and formats.
  2. Pre-process documents: OCR or PDF parsing, chunking long documents.
  3. Call the LLM with instructions and structured output to fill the schema.
  4. Validate with rules and master data; record source spans.
  5. Send failures to human review; measure field-level accuracy and feed corrections back.

Example

from pydantic import BaseModel
from datetime import date

class Invoice(BaseModel):
    invoice_number: str
    supplier_name: str
    invoice_date: date
    total_amount: float
    currency: str

result = llm.extract(document_text, schema=Invoice)    # structured output / tool call
assert abs(sum(i.amount for i in line_items) - result.total_amount) < 0.01

Common mistakes

  • Assuming valid JSON means correct values.
  • No validation rules or human review for financial fields.
  • Measuring only document-level success instead of per field.
  • Sending 100-page documents whole when only a few sections matter.

How to answer in the interview

"NER finds entities like names, organisations, dates and amounts, and information extraction more broadly turns documents into structured records. Traditional models like spaCy or fine-tuned BERT are fast but need labelled data for every new entity type. LLMs let me define a schema and extract custom fields from almost any document without training, normalising values, and structured outputs guarantee valid JSON. I still validate with rules, like totals adding up, send low-confidence cases to humans and measure field-level accuracy on a labelled sample."

Likely follow-up questions

  • Extracting from 100,000 contracts cost-effectively? Batch APIs, a smaller model for easy fields, only relevant sections, caching and sampling for QA.
  • How do you get confidence scores? Validation outcomes, agreement between runs or models, and source-span checks.
  • How do you handle scanned PDFs? OCR or a vision-capable model, with layout preserved.
