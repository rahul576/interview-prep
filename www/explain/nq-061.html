What is the difference between Comparable and Comparator?

Coding Exercises · concept · levels entry

In one line

Comparable (java.lang) is implemented by the class itself with compareTo and defines its single natural ordering; Comparator (java.util) is a separate strategy object with compare(a, b), letting you define many orderings without changing the class, even for classes you cannot modify.

Detailed explanation

Comparable<T> has one method, int compareTo(T other), returning a negative number, zero or a positive number when this is less than, equal to or greater than other. A class implements it when it has one obvious natural order: String (lexicographic), Integer (numeric), LocalDate (chronological), BigDecimal. Methods that need ordering and receive no comparator — Collections.sort(list), stream().sorted(), TreeSet, TreeMap, Arrays.sort(Object[]) — use the natural order.

Comparator<T> has int compare(T a, T b) with the same sign convention, but lives outside the class. This gives flexibility:

  • Multiple orderings for the same type: by price, by name, by category then price.
  • Orderings for classes you cannot change, such as library types.
  • Context-specific orderings: a sort for a report vs a sort for the UI.

Since Java 8, comparators are easy to build with factory methods — Comparator.comparing, comparingInt, comparingDouble, thenComparing, reversed, nullsFirst, naturalOrder, reverseOrder — and it is a functional interface, so lambdas and method references work.

Contracts. Both must be consistent: antisymmetric (sign of compare(a,b) is the opposite of compare(b,a)), transitive, and ideally consistent with equals (compareTo == 0 exactly when equals is true). BigDecimal is a famous exception: 2.0 and 2.00 compare as equal but are not equals, so a TreeSet and a HashSet treat them differently. Violating transitivity can cause IllegalArgumentException: Comparison method violates its general contract from TimSort.

Never implement compareTo by subtracting ints — it can overflow. Use Integer.compare or Comparator helpers.

How it works

  1. Natural order: class implements Comparable<T> and compareTo.
  2. Sorting without a comparator uses compareTo.
  3. Custom order: create a Comparator<T> (lambda or factory methods).
  4. Pass it to sort, sorted, TreeMap, max, min.

Example

class Product implements Comparable<Product> {
    private final String sku;
    private final String name;
    private final double price;
    // constructor, getters

    @Override
    public int compareTo(Product other) {
        return this.sku.compareTo(other.sku);   // natural order by SKU
    }
}

Collections.sort(products);                                   // natural order
products.sort(Comparator.comparingDouble(Product::getPrice));  // by price
products.sort(Comparator.comparing(Product::getName).reversed());

TreeMap<Product, Integer> bySku = new TreeMap<>();              // uses compareTo
TreeSet<Product> byPrice = new TreeSet<>(Comparator.comparingDouble(Product::getPrice));

Common mistakes

  • Implementing compareTo by subtraction, risking overflow.
  • compareTo inconsistent with equals, causing surprising TreeSet behaviour.
  • Making a class Comparable when there is no single obvious order.
  • Comparators that are not transitive.

How to answer in the interview

"Comparable lives in java.lang and is implemented by the class itself, with compareTo defining its single natural ordering; String, Integer and LocalDate implement it. Comparator lives in java.util and is a separate object with compare(a, b), so I can define many orderings — by price, by name, by category then price — without touching the class, even for classes I can't modify. Sorting methods, TreeSet and TreeMap use the natural order when no comparator is given, or the comparator I pass. Since Java 8 comparators are easy to build with Comparator.comparing."

Likely follow-up questions

  • What contract should compareTo follow with equals? Ideally compareTo returns 0 exactly when equals is true.
  • What happens if a TreeSet comparator says two items are equal? The second is treated as a duplicate and not added.
  • Why not subtract in compare? Integer overflow can flip the sign.
