What are method references, and what are their different types?

Java 8+ Features · concept · levels entry, mid

In one line

A method reference (::) is shorthand for a lambda that only calls an existing method; the four kinds are static (Integer::parseInt), instance of a particular object (System.out::println), instance of an arbitrary object of a type (String::toUpperCase), and constructor (ArrayList::new).

Detailed explanation

When a lambda's body just forwards its arguments to one method, a method reference says the same thing more clearly. The compiler matches the referenced method to the target functional interface.

  1. Static method reference, ClassName::staticMethod. Arguments pass straight through. Integer::parseInt ≡ s -> Integer.parseInt(s); Math::max as BinaryOperator<Integer>.
  2. Instance method of a particular object (bound), object::method. The receiver is a specific object, evaluated once when the reference is created. System.out::println ≡ x -> System.out.println(x); this::validate; cart::addItem.
  3. Instance method of an arbitrary object of a type (unbound), ClassName::instanceMethod. The first lambda parameter becomes the receiver, and any remaining parameters become arguments. String::toUpperCase ≡ s -> s.toUpperCase(); String::compareToIgnoreCase as Comparator<String> ≡ (a, b) -> a.compareToIgnoreCase(b); Employee::getSalary in Comparator.comparing.
  4. Constructor reference, ClassName::new. ArrayList::new can be a Supplier<List<T>>; Product::new can be a Function<String, Product> if a one-arg constructor exists. Array constructors: String[]::new as IntFunction<String[]>, used in toArray(String[]::new).

Use them when the method name says it all. If the lambda does more (extra arguments, conditions, transformations), keep the lambda. Overloaded methods can make references ambiguous (e.g. Integer::toString matches both static and instance forms), causing compile errors.

How it works

  1. Determine the target functional interface and its method signature.
  2. Find a compatible method (static, bound, unbound, or constructor).
  3. For unbound references, try the first parameter as the receiver.
  4. Link it at runtime via invokedynamic, like a lambda.

Example

List<String> raw = List.of("10", "20", "x30");

List<Integer> nums = raw.stream()
    .filter(s -> s.chars().allMatch(Character::isDigit))   // static
    .map(Integer::parseInt)                                // static
    .toList();

nums.forEach(System.out::println);                         // bound instance

List<String> upper = raw.stream().map(String::toUpperCase).toList();   // unbound
List<String> sorted = new ArrayList<>(raw);
sorted.sort(String::compareToIgnoreCase);                  // unbound, 2 params -> Comparator

Supplier<Set<String>> setFactory = TreeSet::new;           // constructor
Function<String, Customer> newCustomer = Customer::new;    // Customer(String name)
String[] arr = raw.stream().toArray(String[]::new);        // array constructor

orders.stream().filter(this::isEligible).count();          // bound to this

Common mistakes

  • Mixing up bound and unbound forms.
  • Overusing references where a lambda is clearer.
  • Ambiguity with overloaded methods (Integer::toString).
  • Assuming a bound receiver is re-evaluated on every call.

How to answer in the interview

"A method reference is a shorter form of a lambda whose body just calls an existing method, written with a double colon. There are four kinds. A static method reference like Integer::parseInt. A reference to an instance method of a particular object, like System.out::println or this::validate. A reference to an instance method of an arbitrary object of a type, like String::toUpperCase, where the first argument becomes the receiver. And a constructor reference like ArrayList::new. I use them when the method name says it all, because they read better than the equivalent lambda."

Likely follow-up questions

  • What does String::compareToIgnoreCase map to as a Comparator? (a, b) -> a.compareToIgnoreCase(b).
  • What is String[]::new? An array constructor reference, an IntFunction<String[]>.
  • Why might Integer::toString fail to compile? It's ambiguous between static toString(int) and instance toString().
