What is a proxy versus a reverse proxy, and what is a CDN?

Networking · concept · levels mid, senior

In one line

A forward proxy acts for clients (outbound filtering, caching, egress control); a reverse proxy acts for servers (TLS termination, routing, load balancing, caching); a CDN is a global network of edge reverse proxies caching content near users, cutting latency, offloading origins and absorbing DDoS.

Detailed explanation

Forward proxy: clients are configured (explicitly via HTTP_PROXY/HTTPS_PROXY, PAC files, or transparently) to send requests through it. The destination server sees the proxy's IP. Uses: corporate web filtering and logging, egress control for servers in private networks (only allow-listed domains, for example Squid or a cloud firewall with FQDN rules), caching, and anonymity. For HTTPS, the client uses CONNECT to tunnel, unless the proxy does TLS inspection with its own CA.

Reverse proxy: clients connect to it as if it were the server; it forwards to backends that stay private. Functions: TLS termination, routing by host and path, load balancing with health checks, compression, caching, rate limiting, authentication, WAF and request size limits. Examples: NGINX, HAProxy, Envoy, Traefik, cloud application load balancers, Kubernetes Ingress controllers and API gateways.

CDN: a large, distributed network of reverse proxies in points of presence (PoPs) worldwide. DNS or anycast routes users to a nearby edge. The edge serves cached responses (images, JS, CSS, video segments, even cacheable API responses) based on Cache-Control headers and TTLs, and fetches misses from the origin, often via an origin shield. Benefits: lower latency, less origin load and bandwidth, DDoS absorption at huge capacity, TLS at the edge, WAF and bot protection, and edge compute (Cloudflare Workers, CloudFront Functions or Lambda@Edge). Examples: Amazon CloudFront, Azure Front Door, Cloudflare, Akamai, Fastly, Google Cloud CDN.

Cache invalidation after deployments is best avoided with content-hashed filenames (app.3f9c2.js) cached for a year, while HTML is cached briefly or revalidated; explicit purges are the fallback.

How it works

  1. Forward: client to proxy to internet server.
  2. Reverse: internet client to proxy to private backends.
  3. CDN: user resolves to the nearest edge; hit served from cache.
  4. Miss: the edge fetches from origin (possibly via shield), caches per headers.
  5. Deploy: new hashed assets; HTML updated or purged.

Example

# forward proxy for a private server's outbound calls
export HTTPS_PROXY=http://egress-proxy.internal:3128 NO_PROXY=.internal,169.254.169.254
curl -I https://pypi.org/simple/
# CDN behaviour
curl -sI https://www.example.com/static/app.3f9c2.js | grep -iE "cache-control|age|x-cache"
aws cloudfront create-invalidation --distribution-id E123ABC --paths "/index.html"

Common mistakes

  • Confusing the two proxy directions.
  • Caching personalised or authenticated responses at the CDN.
  • Relying on purges instead of versioned asset names.
  • Leaving the origin publicly reachable so attackers bypass the CDN.

How to answer in the interview

"A forward proxy acts for clients: a company proxy sends employees' or servers' outbound requests to the internet, filtering, logging or caching them, and the server sees the proxy. A reverse proxy acts for servers: clients connect to it and it forwards to backends, handling TLS termination, routing by host or path, load balancing, compression and rate limiting, like NGINX, HAProxy or Envoy. A CDN is a large distributed set of reverse proxies at edge locations near users that cache content, cutting latency, offloading the origin and absorbing DDoS, like CloudFront, Front Door or Cloudflare."

Likely follow-up questions

  • How do you invalidate CDN cache safely after a deploy? Content-hashed asset names with long TTLs, short TTL or revalidation for HTML, and targeted purges if needed.
  • How do you stop users bypassing the CDN? Restrict the origin to CDN IP ranges or use origin access control or secret headers.
  • What does Cache-Control: s-maxage do? Sets the TTL for shared caches like CDNs, separately from browsers.
