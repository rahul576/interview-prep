What monitoring tools does Azure provide, and how do you set up alerting?

Azure · concept · levels mid

In one line

Azure Monitor is the umbrella: metrics for every resource, logs collected into a Log Analytics workspace queried with KQL, Application Insights for APM and tracing, Container Insights / Managed Prometheus / Managed Grafana for AKS, and alert rules that trigger action groups.

Detailed explanation

Platform metrics are collected automatically for Azure resources, such as CPU, request counts or queue length, stored as time series and good for near-real-time alerts. Resource logs and the activity log (who changed what in the subscription) are sent through diagnostic settings to a Log Analytics workspace, Storage or Event Hubs. VM and server logs are collected by the Azure Monitor Agent using data collection rules, which replaced the legacy agents.

In Log Analytics you query data with KQL (Kusto Query Language): pipe-based queries for filtering, aggregation, joins and charts. Workspace design matters for cost and access: a central workspace per environment or region is common, with table-level retention and cheaper Basic/Auxiliary log plans for verbose data.

Application Insights (workspace-based) provides application performance monitoring: requests, dependencies, exceptions, traces, availability tests, an application map and distributed tracing. The recommended instrumentation is the Azure Monitor OpenTelemetry distro, so code uses vendor-neutral OpenTelemetry APIs.

For AKS, Container Insights collects container logs and inventory, Azure Monitor managed service for Prometheus scrapes metrics, and Azure Managed Grafana provides dashboards.

Alerting: alert rules can be metric alerts, log search alerts (KQL), activity log alerts or service health alerts. When they fire, they invoke action groups: email, SMS, push, voice, webhooks, Logic Apps, Functions, Automation runbooks, or ITSM and on-call tools. Alert processing rules suppress alerts during maintenance windows or route them centrally.

How it works

  1. Enable diagnostic settings (ideally via Azure Policy) to send logs to Log Analytics.
  2. Deploy Azure Monitor Agent with data collection rules for VMs.
  3. Instrument apps with OpenTelemetry and Application Insights.
  4. Enable Container Insights and Managed Prometheus for AKS.
  5. Build dashboards and workbooks; define SLO-based alert rules.
  6. Connect alerts to action groups and on-call tooling.

Example

Top five slowest requests in the last hour (KQL):

requests
| where timestamp > ago(1h)
| top 5 by duration desc
| project timestamp, name, resultCode, duration, operation_Id, cloud_RoleName

Error-rate log alert query:

requests
| where timestamp > ago(5m)
| summarize failed = countif(success == false), total = count()
| extend errorRate = 100.0 * failed / total
| where errorRate > 2

Common mistakes

  • Forgetting diagnostic settings, so resource logs are never collected.
  • Sending everything to Analytics logs at full retention, causing huge bills.
  • Alerting on raw CPU rather than user-facing symptoms.
  • Separate Application Insights resources with no correlation between services.
  • Action groups that only email a shared mailbox nobody reads.

How to answer in the interview

"Azure Monitor is the umbrella. Every resource emits platform metrics, and logs are collected through diagnostic settings and the Azure Monitor Agent into a Log Analytics workspace, which I query with KQL. Application Insights provides APM: requests, dependencies, exceptions and distributed tracing, now instrumented with OpenTelemetry. For AKS I use Container Insights plus Managed Prometheus and Managed Grafana. Alerts are metric or log search alert rules, ideally based on SLOs like error rate and latency, which trigger action groups that notify email, Teams, PagerDuty or webhooks, or run automation. I enforce diagnostic settings with Azure Policy so nothing is missed."

Likely follow-up questions

  • How would you write a KQL query for the top 5 slowest requests in the last hour? requests | where timestamp > ago(1h) | top 5 by duration desc.
  • How do you reduce Log Analytics cost? Filter in data collection rules, use Basic logs and shorter retention, and commitment tiers.
  • Metric alert or log alert? Metric alerts for fast, simple thresholds; log alerts for complex conditions.
