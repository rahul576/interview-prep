What is the difference between an interface default method and a static method, and how is the diamond problem resolved?

Core Java & OOP · concept · levels entry

In one line

A default method gives an interface method an inherited implementation; a static method belongs to the interface itself and is not inherited; diamond conflicts between defaults must be overridden explicitly, optionally delegating with Interface.super.method().

Detailed explanation

Java 8 added both to interfaces, mainly to evolve APIs without breaking implementers. Default methods let the JDK add forEach, stream, removeIf and sort to Collection/List without breaking every existing implementation. An implementing class inherits the default and may override it. Default methods can call other interface methods, which makes them good for convenience methods built on top of abstract ones.

Static interface methods are utilities tied to the interface: Comparator.comparing, List.of, Map.entry. They are called as InterfaceName.method() and are not inherited by implementing classes or sub-interfaces, so myList.of(...) does not compile. Java 9 added private (and private static) interface methods for sharing code between defaults.

When a class inherits the same default method from two unrelated interfaces, the compiler cannot choose, so you get a compile error until the class overrides it. Inside the override you can delegate to one or combine both with A.super.hello() and B.super.hello().

The resolution rules are:

  1. Classes win: a method from a superclass (concrete or abstract) beats any interface default.
  2. More specific interface wins: if B extends A and both define the default, B's version is chosen.
  3. Otherwise the class must override explicitly.

Interfaces still cannot hold instance state, so default methods are not a replacement for abstract classes when shared fields are needed.

How it works

  1. The compiler collects candidate methods from the superclass chain and all interfaces.
  2. Superclass methods take priority.
  3. Among interfaces, sub-interfaces override super-interfaces.
  4. Remaining ambiguity is a compile error requiring an override.
  5. Static interface methods are resolved only through the interface name.

Example

interface Camera  { default String start() { return "camera on"; } }
interface Phone   { default String start() { return "phone on"; }
                    static Phone basic() { return new Phone() {}; } }

class SmartPhone implements Camera, Phone {
    @Override public String start() {           // required: diamond conflict
        return Phone.super.start() + " + " + Camera.super.start();
    }
}

Phone p = Phone.basic();        // static: called on the interface
// SmartPhone.basic();          // does not compile: static methods are not inherited

Common mistakes

  • Trying to call a static interface method through an instance or implementing class.
  • Expecting a default method to beat a superclass method.
  • Putting heavy logic or pseudo-state into defaults.
  • Trying to declare default equals/hashCode/toString, which is a compile error.

How to answer in the interview

"A default method is an implementation in an interface that implementing classes inherit and can override; that's how Java 8 added forEach and stream to existing collections. A static method belongs to the interface, is called with the interface name, like Comparator.comparing, and isn't inherited. If a class gets the same default from two interfaces, it won't compile until the class overrides it, and inside it can call a particular one with InterfaceName.super.method(). The rules are: class methods always win, then the more specific interface, otherwise you must override."

Likely follow-up questions

  • Can a default method override equals from Object? No, it's a compile error, because class methods always win.
  • Can interfaces have private methods? Yes, since Java 9, to share code between defaults.
  • Interface with defaults vs abstract class? Abstract classes can hold state and constructors.
