Explain the different types of SQL joins.

Databases & SQL · concept · levels entry

In one line

INNER JOIN keeps only matching rows, LEFT/RIGHT OUTER JOIN keep all rows from one side with NULLs for no match, FULL OUTER JOIN keeps all rows from both, CROSS JOIN is the cartesian product, and a SELF JOIN joins a table to itself.

Detailed explanation

A join combines rows from two tables based on a condition, usually a foreign key equal to a primary key. The join type decides what happens to rows that have no partner.

  • INNER JOIN returns only pairs where the condition matches. Customers without orders and orders without customers disappear.
  • LEFT (OUTER) JOIN returns every row from the left table; when there is no match, the right-side columns are NULL. This is the standard anti-join trick: LEFT JOIN ... WHERE right.id IS NULL finds rows with no match, such as customers who never ordered. NOT EXISTS expresses the same thing and is often equally fast.
  • RIGHT (OUTER) JOIN is the mirror image; most teams rewrite it as a LEFT JOIN for readability.
  • FULL OUTER JOIN returns all rows from both sides, matched where possible. MySQL lacks it, so it is emulated with a LEFT JOIN UNION a RIGHT JOIN.
  • CROSS JOIN pairs every row with every row: 1,000 x 1,000 = 1,000,000 rows. Useful for generating combinations, such as every store with every date.
  • SELF JOIN uses aliases to join a table to itself, for example employee e JOIN employee m ON e.manager_id = m.id.

For performance, join columns (especially foreign keys) should be indexed, and the optimizer chooses an algorithm: nested loop, hash join or merge join.

How it works

  1. The engine reads the driving table (chosen by the optimizer).
  2. For each row it finds matches in the other table, via an index lookup, hash table or sorted merge.
  3. Matched rows produce combined output rows.
  4. For outer joins, unmatched rows from the preserved side are emitted with NULLs.
  5. WHERE filters are applied after the join, which matters for outer joins.

Example

-- Customers who have never placed an order
SELECT c.id, c.name
FROM customer c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL;

-- Self join: employee with manager name
SELECT e.name AS employee, m.name AS manager
FROM employee e
LEFT JOIN employee m ON m.id = e.manager_id;

Common mistakes

  • Putting a filter on the right table in WHERE after a LEFT JOIN, which silently makes it an inner join; put it in ON instead.
  • Forgetting the join condition and producing an accidental cartesian product.
  • Joining on non-indexed or mismatched-type columns.
  • Getting duplicated totals by joining two one-to-many tables at once.

How to answer in the interview

"An inner join returns only rows that match in both tables. A left join keeps every row from the left table and fills the right side with NULLs where there's no match, so I can find customers without orders with a left join and a WHERE order id IS NULL, or with NOT EXISTS. A right join is the mirror, and a full outer join keeps everything from both sides. A cross join is the cartesian product, and a self join joins a table to itself, like employees to their managers. I make sure join columns, especially foreign keys, are indexed, and I watch out for WHERE clauses turning a left join into an inner join."

Likely follow-up questions

  • How do you find customers who never ordered? LEFT JOIN with WHERE o.id IS NULL, or NOT EXISTS.
  • Why can WHERE break a LEFT JOIN? Comparing a NULL right-side column filters those rows out.
  • What join algorithms exist? Nested loop, hash join and merge join, chosen by the optimizer.
