Compare Azure VPN Gateway and ExpressRoute for hybrid connectivity.

Azure · concept · levels mid, senior

In one line

VPN Gateway builds encrypted IPsec tunnels over the internet, quick and cheap but with variable latency; ExpressRoute is a private connection through a provider with predictable latency, higher bandwidth and an SLA, but not encrypted by default; a common design uses ExpressRoute primary with VPN as backup.

Detailed explanation

Azure VPN Gateway is deployed in a GatewaySubnet and supports site-to-site IPsec/IKE tunnels from an on-premises VPN device, point-to-site connections for individual users (OpenVPN, IKEv2, Entra ID authentication), and VNet-to-VNet. It can run active-active with BGP for resilience, and zone-redundant SKUs exist. Throughput depends on the SKU, from a few hundred Mbps up to around 10 Gbps aggregate on the largest SKUs, with per-tunnel limits lower. Because traffic crosses the public internet, latency and jitter vary. It can be set up in under an hour once the on-premises device is configured.

ExpressRoute is a private layer 2/3 connection between your network and Microsoft's edge through a connectivity provider (MPLS, colocation cross-connect or point-to-point Ethernet), with circuits from 50 Mbps to 10 Gbps, or ExpressRoute Direct with 10 or 100 Gbps ports directly into Microsoft. Each circuit has two redundant connections and an availability SLA. Private peering connects to your VNets; Microsoft peering reaches Microsoft 365 and public Azure services. Add-ons include Global Reach (connect on-premises sites through Microsoft's backbone), FastPath (bypass the gateway for performance) and premium for global VNet reach. An ExpressRoute gateway in the VNet connects to the circuit. Provisioning takes weeks because a provider is involved.

Encryption: ExpressRoute is private but not encrypted by default. For sensitive data, use MACsec on ExpressRoute Direct ports, IPsec over ExpressRoute (VPN tunnels on private peering, for example via Virtual WAN), or application-level TLS.

Resilience: for critical connectivity use two circuits in different peering locations, or ExpressRoute as primary with site-to-site VPN as failover. Both gateways can coexist in the same VNet; with BGP, Azure prefers ExpressRoute routes and falls back to VPN when they are withdrawn.

How it works

  1. Assess bandwidth, latency, compliance and timeline needs.
  2. VPN: deploy gateway, configure on-premises device, create connection.
  3. ExpressRoute: order circuit with provider, create ER gateway, link circuit.
  4. Configure BGP and route advertisements.
  5. Add encryption (MACsec or IPsec) where required.
  6. Configure VPN as backup and test failover.

Example

az network vnet-gateway create -g rg-hub -n vpngw-hub --vnet vnet-hub \
  --gateway-type Vpn --vpn-type RouteBased --sku VpnGw2AZ \
  --public-ip-addresses pip-vpngw-1 pip-vpngw-2 --asn 65515
az network vpn-connection create -g rg-hub -n conn-onprem-dc1 \
  --vnet-gateway1 vpngw-hub --local-gateway2 lgw-dc1 \
  --shared-key "$PSK" --enable-bgp
az network vnet-gateway list-learned-routes -g rg-hub -n vpngw-hub -o table

Common mistakes

  • Assuming ExpressRoute traffic is encrypted.
  • A single ExpressRoute circuit at one peering location with no backup.
  • VPN backup configured but never tested.
  • Overlapping address spaces between on-premises and Azure.
  • Ignoring route preference, so traffic takes the VPN unexpectedly.

How to answer in the interview

"Azure VPN Gateway creates encrypted IPsec tunnels over the public internet, site-to-site from an on-premises device or point-to-site for users. It is quick and cheap to set up, with bandwidth up to several gigabits per second depending on the SKU, but latency depends on the internet path. ExpressRoute is a private connection through a provider or ExpressRoute Direct, with predictable latency, bandwidth up to 100 Gbps and an SLA, and it does not traverse the public internet. However, it is not encrypted by default, so for sensitive data I add MACsec on ExpressRoute Direct or IPsec over it. A common design uses ExpressRoute as the primary path and a site-to-site VPN as BGP-based backup, which I test regularly."

Likely follow-up questions

  • How would you test that the VPN backup works? Planned test: disable the ExpressRoute connection or withdraw routes in a maintenance window, then check effective routes and Connection Monitor.
  • What is ExpressRoute Global Reach? It connects on-premises sites to each other through Microsoft's backbone via their circuits.
  • When is VPN alone enough? Small sites, dev environments or low, non-critical bandwidth.
