What is experiment tracking, and what should be logged for each training run?

MLOps · concept · levels entry, mid, senior

In one line

Experiment tracking keeps a structured record of every training run so you can compare and reproduce results; log parameters, metrics, code and data versions, environment and artefacts, automatically, using tools such as MLflow, Weights & Biases or managed platforms.

Detailed explanation

Model development is a search: many runs with different features, algorithms and hyperparameters. Without a record, teams end up with spreadsheets, files named model_final_v3_really.pkl, and no way to explain why last month's model was better. Experiment tracking is a central store of runs, grouped into experiments, where each run captures everything needed to understand and reproduce it.

For each run, log:

  • Parameters and hyperparameters: model type, learning rate, depth, regularisation, feature set name, class weights.
  • Metrics: training curves such as loss per epoch, and final validation and test metrics, including segment metrics (per region or customer type) and latency or model size.
  • Code version: Git commit, and whether the working tree was dirty.
  • Data version: dataset snapshot ID, table version or DVC hash, plus the date range and filters.
  • Environment: library versions, container image digest, hardware (GPU type).
  • Artefacts: the model file, evaluation plots, confusion matrices, feature importance, sample predictions, sometimes the exact training data split.
  • Tags: purpose, author, ticket or hypothesis.

Common tools are MLflow (open source, self-hosted or managed in Databricks), Weights & Biases, Neptune, and the tracking built into Azure ML, SageMaker and Vertex AI. The crucial practice is that logging happens automatically in the training code or pipeline, through autologging or a shared wrapper, so it never depends on people remembering. Runs from the pipeline and from notebooks go to the same server, and the best run links directly to a model registry version.

How it works

  1. Training code starts a run in an experiment.
  2. Parameters, code commit, data version and environment are logged.
  3. Metrics are logged during and after training.
  4. Artefacts are uploaded to object storage linked to the run.
  5. The UI or API compares runs; the chosen one is registered.

Example

import mlflow, mlflow.sklearn
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.metrics import roc_auc_score

mlflow.set_experiment("churn")
with mlflow.start_run(run_name="gbt-depth5"):
    params = {"n_estimators": 400, "max_depth": 5, "learning_rate": 0.05}
    mlflow.log_params(params)
    mlflow.set_tags({"git_commit": GIT_SHA, "data_version": "churn_snapshot_2026_11_01"})
    model = GradientBoostingClassifier(**params).fit(X_train, y_train)
    mlflow.log_metric("val_auc", roc_auc_score(y_val, model.predict_proba(X_val)[:, 1]))
    mlflow.sklearn.log_model(model, "model")

Common mistakes

  • Logging metrics but not the data version, making runs irreproducible.
  • Relying on people to log manually.
  • Only logging the final metric, not segments or curves.
  • Separate tracking for notebooks and pipelines.

How to answer in the interview

"Experiment tracking keeps a structured record of every training run so we can compare runs and reproduce any result. For each run I log parameters and hyperparameters, metrics during training and final validation and test metrics, including key segments, the Git commit, the data version or snapshot, the environment such as library versions and container image, and artefacts like the model file, plots and feature importance, plus tags for purpose and ticket. Tools are MLflow, Weights and Biases or the tracking in Azure ML, SageMaker or Vertex AI. And logging must be automatic in the training code."

Likely follow-up questions

  • How would you find why last month's model performed better? Compare the two runs' parameters, data versions, code diffs and environments in the tracker.
  • What is autologging? Framework integrations that capture parameters, metrics and models automatically.
  • Where are artefacts stored? In object storage referenced by the tracking server.
