Why do LLMs hallucinate, and which techniques reduce hallucinations in applications?

LLMOps & RAG · concept · levels mid, senior

In one line

LLMs hallucinate because they generate plausible text, not verified facts, and guess when knowledge is missing or prompts demand an answer; reduce it with grounding in retrieved sources with citations, permission to say "I don't know", tools for facts and calculations, verification steps and lower temperature with structured outputs, measured by evaluation.

Detailed explanation

A language model is trained to predict likely continuations. It has no built-in notion of truth, and its knowledge is compressed, incomplete and frozen at a training cutoff. When a question falls into a gap, when it is ambiguous, or when the prompt implies an answer must exist ("list the five papers that..."), the most likely continuation is still a fluent, confident answer: invented citations, numbers, API methods, legal cases or product features. Training that rewards answering over abstaining reinforces this.

Techniques that reduce hallucination in applications:

  • Grounding: retrieve relevant sources (RAG, search, databases) and instruct the model to answer only from the provided context, with citations per claim, so answers can be checked and unsupported claims stand out.
  • Allow abstention: explicitly permit and reward "I don't know based on the available documents", and design the UI to accept that answer. Ask clarifying questions for ambiguous inputs.
  • Tools for facts: look up order status, prices or dates from systems of record; use a calculator or code execution for arithmetic; call real APIs instead of recalling them.
  • Verification: a second step checks groundedness (each claim against sources, by an LLM judge or NLI model); self-consistency samples several answers and flags disagreement; validate generated code by running tests; validate references against a database.
  • Decoding and format: low temperature and structured outputs with nullable fields for factual extraction, so the model is not forced to invent values.
  • Human review for high-stakes outputs (legal, medical, financial).

Measure it: build an evaluation set with known answers and unanswerable questions, track faithfulness and hallucination rate (share of answers with unsupported claims), and monitor production samples.

How it works

  1. Retrieve sources or call tools for facts.
  2. Prompt with grounding rules, citations and abstention allowed.
  3. Generate at low temperature with structure.
  4. Verify claims against sources; check consistency.
  5. Return answer with citations, or abstain or escalate.

Example

System: Answer using ONLY the sources. After each sentence cite [source-id].
If the sources do not contain the answer, reply exactly: "I couldn't find this in the documents."
Never invent policy numbers, dates or amounts.

Post-check: for each sentence, judge("Is this claim fully supported by [cited source]?")
→ unsupported sentences removed or answer routed to human review

Common mistakes

  • Thinking RAG alone eliminates hallucination.
  • Prompts that pressure the model to always answer.
  • Letting the model do arithmetic or recall prices from memory.
  • Not measuring hallucination rate before and after changes.

How to answer in the interview

"LLMs predict likely next tokens, so they produce fluent, plausible text rather than verified facts. When the knowledge is missing, the question is ambiguous or the prompt pressures them to answer, they fill gaps with confident guesses like invented references or API names. To reduce it, I ground answers in retrieved sources and require citations, tell the model to answer only from that context and explicitly allow 'I don't know', use tools for facts and calculations, add verification such as a groundedness check or self-consistency, and use low temperature and structured outputs for factual tasks. And I measure hallucination rates on realistic questions."

Likely follow-up questions

  • Measure hallucination rate? Labelled test set plus faithfulness scoring by calibrated judges and human samples.
  • Does fine-tuning fix it? It can improve format and domain behaviour but can also teach confident guessing; grounding is more reliable.
  • Hallucination in agents? Invented tool names or arguments; use strict schemas and validate tool calls.
