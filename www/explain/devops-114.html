What are Kubernetes operators and CRDs?

Kubernetes · concept · levels senior, lead

In one line

A CustomResourceDefinition (CRD) extends the Kubernetes API with new resource types; an operator is a controller that watches those resources and runs a reconciliation loop encoding operational knowledge (provision, back up, fail over, upgrade); examples include Prometheus Operator, cert-manager, Strimzi, CloudNativePG, built with kubebuilder or Operator SDK.

Detailed explanation

Kubernetes' built-in controllers know how to run Deployments and Jobs, but not how to run a PostgreSQL cluster safely: initialise replicas, promote a new primary, take backups, upgrade versions in the right order. The operator pattern captures that human runbook in software.

CRDs. A CRD registers a new kind, such as Certificate, Kafka or Cluster, with an OpenAPI schema for validation, versions (with conversion between them), optional status and scale subresources, and printer columns. After installation, the API server stores and serves these objects like any built-in resource: kubectl, RBAC, watches and GitOps all work.

Controllers and reconciliation. The operator runs as a deployment that watches its custom resources (and the objects it creates). For each change it compares desired state (spec) with actual state and acts to converge: create StatefulSets, Services and Secrets, call cloud APIs, trigger backups. Reconciliation is level-based and idempotent: it recomputes from current state rather than replaying events, so it recovers after crashes. It writes progress to status and uses owner references so created objects are garbage-collected, and finalizers to clean up external resources before deletion.

Examples. Prometheus Operator (ServiceMonitor, PrometheusRule), cert-manager (Certificate, Issuer), Strimzi for Kafka, CloudNativePG for PostgreSQL, Crossplane for cloud resources, Argo CD itself.

Building. kubebuilder and Operator SDK (Go, built on controller-runtime) scaffold CRDs, controllers, RBAC and webhooks; Operator SDK also supports Ansible- and Helm-based operators. Capability is often described as levels, from basic install to full autopilot.

How it works

  1. Install CRDs and the operator deployment with its RBAC.
  2. User applies a custom resource, for example a Cluster with 3 instances.
  3. Operator reconciles: creates pods, services, secrets, backups.
  4. It watches for failures; promotes a replica if the primary dies.
  5. Status reports health; upgrades are handled by changing the spec.

Example

apiVersion: postgresql.cnpg.io/v1
kind: Cluster
metadata: { name: orders-db, namespace: shop }
spec:
  instances: 3
  storage: { size: 50Gi, storageClass: gp3 }
  backup:
    barmanObjectStore:
      destinationPath: s3://acme-pg-backups/orders

Common mistakes

  • Installing many operators with cluster-wide permissions without review.
  • Ignoring CRD version upgrades and conversion, breaking existing objects.
  • Webhooks with failurePolicy: Fail whose outage blocks the API.
  • Writing a custom operator where a Helm chart or existing operator would do.

How to answer in the interview

"A custom resource definition extends the Kubernetes API with new types, like a PostgresCluster or Certificate, with schema validation, so kubectl, RBAC and GitOps work with them. An operator is a controller that watches those resources and runs a reconciliation loop, comparing spec with actual state and acting to converge, encoding operational knowledge like provisioning, backups, failover and upgrades. Examples are the Prometheus Operator, cert-manager, Strimzi for Kafka and CloudNativePG. They're built with kubebuilder or Operator SDK on controller-runtime."

Likely follow-up questions

  • What risks come with many third-party operators? Broad RBAC, webhook outages blocking the API, CRD upgrade pain, resource use and abandoned projects.
  • What is a finalizer? A marker that delays deletion until the controller has cleaned up external resources.
  • Level-based vs edge-based? Reconciling from current state rather than individual events makes controllers robust to missed events.
