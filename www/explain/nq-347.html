What is Model Context Protocol (MCP)?

AI/ML & GenAI · concept · levels mid

In one line

The Model Context Protocol (MCP) is an open standard, introduced by Anthropic in November 2024, for connecting AI applications to external tools and data; it uses a client-server architecture with JSON-RPC 2.0 messages over stdio or Streamable HTTP, and servers expose tools, resources and prompts.

Detailed explanation

Before MCP, every AI application needed custom code for every system it wanted to use: a GitHub plugin for one assistant, a different one for another. MCP is often described as USB-C for AI: a system exposes an MCP server once, and any MCP-compatible host (Claude apps, IDE assistants, agent frameworks, your own application) can use it. It has been adopted widely across AI vendors and developer tools, and in late 2025 Anthropic donated it to a Linux Foundation-hosted foundation for neutral governance.

Architecture: a host application contains one MCP client per connected server. Messages are JSON-RPC 2.0 requests, responses and notifications. Transports are stdio (the host launches the server as a local subprocess) and Streamable HTTP for remote servers, which replaced the earlier HTTP+SSE transport. Remote servers typically use OAuth 2.1-based authorisation.

Server capabilities:

  • Tools: functions the model can call, each with a name, description and JSON Schema for inputs (e.g. create_issue).
  • Resources: data the application can read into context, identified by URIs (files, database rows, documents).
  • Prompts: reusable prompt templates, often exposed as slash commands.

Clients can also offer features to servers, such as sampling (server asks the host's model to generate), roots and elicitation (asking the user for input).

How it works

  1. The host starts or connects to an MCP server.
  2. Client and server run an initialize handshake to agree version and capabilities.
  3. The client lists the server's tools, resources and prompts.
  4. The host gives tool definitions to the model.
  5. The model requests a tool call; the client sends tools/call and returns the result.

Example

{ "jsonrpc": "2.0", "id": 7, "method": "tools/call",
  "params": { "name": "create_issue",
              "arguments": { "repo": "acme/orders", "title": "Fix NPE in checkout" } } }

Host configuration for a local server (pattern used by many hosts):

{ "mcpServers": { "github": { "command": "github-mcp-server", "args": ["stdio"] } } }

Common mistakes

  • Thinking MCP is a model or an Anthropic-only product.
  • Confusing MCP with a REST API; it is a protocol for discovery and invocation by AI hosts.
  • Ignoring security: MCP standardises connection, not trust.

How to answer in the interview

"MCP, the Model Context Protocol, is an open standard Anthropic introduced in late 2024 for connecting AI applications to tools and data. It's often called USB-C for AI: instead of each AI app writing custom integrations, a system exposes an MCP server once and any compatible host, like Claude, an IDE assistant or our own agent, can use it. It's client-server with JSON-RPC 2.0, over stdio for local servers or Streamable HTTP for remote ones. Servers expose tools the model can call, resources it can read and reusable prompts."

Likely follow-up questions

  • How is MCP different from calling a REST API? MCP adds standard discovery, schemas and invocation that any host understands; the server may call REST internally.
  • What is an MCP resource? Read-only context identified by a URI, chosen by the app or user.
  • How are remote servers secured? OAuth-based authorisation plus host-side approvals and least privilege.
