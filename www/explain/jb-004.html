What is the difference between primitive and reference data types?

Core Java & OOP · concept · levels entry, mid

In one line

Java's eight primitive types hold their value directly, have fixed sizes and cannot be null; reference types hold a reference to an object on the heap, default to null, and are compared by reference with ==.

Detailed explanation

The eight primitives are byte (8-bit), short (16), int (32), long (64), float (32-bit IEEE 754), double (64), char (16-bit UTF-16 code unit) and boolean. A primitive variable contains the actual bits of the value. Local primitives live in the stack frame; primitive fields live inside the object that owns them. As fields they default to 0, 0.0, '\u0000' or false; local variables have no default and must be assigned before use.

Reference types include classes, interfaces, enums, records, arrays and String. The variable holds a reference, essentially a pointer managed by the JVM, to an object allocated on the heap. Several variables can refer to the same object, so mutation through one is visible through all. Reference fields default to null, and dereferencing null throws NullPointerException (Java 14+ gives helpful NPE messages naming the null expression).

Consequences:

  • Comparison: == on primitives compares values; on references it compares identity. Use equals for logical equality.
  • Parameter passing: Java is always pass-by-value. For references, the value copied is the reference, so a method can mutate the object but cannot make the caller's variable point elsewhere.
  • Performance and memory: an int[] of a million elements is about 4 MB; a List<Integer> is several times larger because each element is a separate object with a header plus a reference.

Generics and collections only work with reference types, so each primitive has a wrapper class (Integer, Long, Double, Character, Boolean, ...), and autoboxing/unboxing converts automatically. That convenience can allocate objects and throws NPE when unboxing null. (Project Valhalla is working on value classes to narrow this gap, but that is not in a final Java release yet.)

How it works

  1. Declaring int x = 5 reserves 32 bits holding 5 directly.
  2. Person p = new Person() allocates the object on the heap and stores its reference in p.
  3. Person q = p copies the reference; both point to one object.
  4. Passing to a method copies the value (primitive or reference).
  5. When no references remain, the GC can reclaim the object.

Example

int a = 10;  int b = a;  b++;                 // a stays 10
int[] arr1 = {1, 2}; int[] arr2 = arr1; arr2[0] = 99; // arr1[0] is now 99

static void reassign(StringBuilder sb) { sb = new StringBuilder("new"); }
static void mutate(StringBuilder sb)   { sb.append("!"); }

StringBuilder s = new StringBuilder("hi");
reassign(s);  mutate(s);
System.out.println(s);                         // hi!

Common mistakes

  • Saying Java passes objects "by reference".
  • Comparing Integer or String with ==.
  • Using wrappers for counters in hot loops.
  • Assuming char holds any Unicode character; supplementary characters need two chars.

How to answer in the interview

"Java has eight primitives: byte, short, int, long, float, double, char and boolean. A primitive variable holds the value itself, has a fixed size, can't be null, and as a field defaults to zero or false. Reference types like classes, arrays and String hold a reference to an object on the heap; they default to null and == compares references, not contents. Primitives are faster and smaller. Generics need reference types, so each primitive has a wrapper and autoboxing converts between them, which costs allocations and throws NullPointerException if you unbox null."

Likely follow-up questions

  • What problems can autoboxing cause in a tight loop? Many short-lived allocations and GC pressure.
  • Is Java pass-by-reference? No, always pass-by-value; for objects the reference is copied.
  • Is String primitive? No, it's a final reference type with literal support.
