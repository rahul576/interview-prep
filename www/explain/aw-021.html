What is the difference between Secrets Manager and Parameter Store?

Cloud (AWS) · concept · levels entry

In one line

Both store values encrypted with KMS and read via IAM, but Secrets Manager is built for secrets with automatic rotation, cross-region replication and resource policies for cross-account sharing at a per-secret cost, while Parameter Store is a general configuration store whose standard tier is free and has no native rotation.

Detailed explanation

Secrets Manager is purpose-built for credentials: database passwords, API keys, OAuth tokens. Its key feature is automatic rotation on a schedule: a Lambda rotation function creates a new credential, sets it in the target system, tests it and switches the AWSCURRENT label. AWS provides managed rotation for RDS, Aurora, Redshift and DocumentDB, and RDS can even manage the master password in Secrets Manager for you. It supports cross-region replication for multi-region applications and DR, resource-based policies for sharing a secret with another account, versioning with staging labels, and secrets up to 64 KB. It costs a small monthly fee per secret plus a charge per API calls.

Parameter Store (part of Systems Manager) is for configuration in general: feature settings, URLs, AMI IDs, and also simple secrets as SecureString. Standard parameters are free with generous limits; advanced parameters cost a little. It has hierarchies, versions and labels, and integrates widely with ECS, Lambda, CloudFormation and CodeBuild. It has no built-in rotation, though you can build it yourself. Parameter Store can even reference Secrets Manager secrets via the /aws/reference/secretsmanager/ path, giving one API for both.

A common split: Parameter Store for configuration and static values, Secrets Manager for credentials that should rotate or be shared across accounts or regions. For applications, caching clients and the AWS Parameters and Secrets Lambda Extension reduce API calls and cost.

Rotation only helps if applications pick up new values: they should fetch secrets at runtime with a short cache rather than baking them into environment variables at deploy time, and connection pools should handle re-authentication.

How it works

  1. Store the value; KMS encrypts it.
  2. App role is granted GetSecretValue or GetParameter on that resource.
  3. App fetches at startup and refreshes from a cache.
  4. Secrets Manager rotation Lambda creates and tests a new credential.
  5. Labels switch to the new version; the old one is retired.

Example

aws secretsmanager create-secret --name prod/orders/db \
  --secret-string '{"username":"orders_app","password":"initial-Pa55"}'
aws secretsmanager rotate-secret --secret-id prod/orders/db \
  --rotation-lambda-arn arn:aws:lambda:eu-west-1:123456789012:function:rds-rotation \
  --rotation-rules AutomaticallyAfterDays=30

aws ssm put-parameter --name /orders/prod/payment-api-url \
  --type String --value https://api.payments.example.com

Common mistakes

  • Paying for Secrets Manager for plain configuration.
  • Putting rotating DB passwords in Parameter Store with no rotation.
  • Reading the secret only at deploy time, so rotation breaks the app.
  • Over-broad GetSecretValue permissions.

How to answer in the interview

"Both encrypt values with KMS and are read at runtime with IAM. Secrets Manager is built for secrets: it rotates them automatically with a Lambda, with managed rotation for RDS and other databases, supports cross-region replication and sharing through resource policies, and costs a bit per secret plus API calls. Parameter Store is for configuration in general; standard parameters are free and SecureString handles simple secrets, but there's no native rotation. So I use Parameter Store for config and static values, and Secrets Manager for database passwords and API keys that must rotate, making sure apps fetch with a cache so rotation doesn't break them."

Likely follow-up questions

  • How does an app pick up a rotated secret without restarting? Fetch at runtime with a short-lived cache and retry auth failures with a refreshed secret.
  • What is the alternating-users rotation strategy? Two DB users alternate so one is always valid during rotation.
  • Can ECS inject secrets? Yes, task definitions reference Secrets Manager or Parameter Store ARNs.
