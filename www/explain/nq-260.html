What is the difference between INNER JOIN and LEFT JOIN?

Databases & SQL · concept · levels entry

In one line

An INNER JOIN returns only rows that match in both tables, while a LEFT (OUTER) JOIN returns every row from the left table and fills the right-table columns with NULL where there is no match.

Detailed explanation

Think of customers on the left and orders on the right. With an INNER JOIN, a customer appears once for each matching order, and customers who never ordered disappear. With a LEFT JOIN, every customer appears at least once: matched customers once per order, unmatched customers exactly once with NULL in all order columns.

That NULL row is what makes LEFT JOIN useful for questions like "list all customers and their order count" or "find customers who never ordered" (the anti-join pattern: WHERE o.order_id IS NULL).

The classic trap is where you put filters. The ON clause decides which right rows match; the WHERE clause filters the finished result. If you write LEFT JOIN orders o ON ... WHERE o.status = 'PAID', the unmatched customers have o.status = NULL, the condition is not true, and they are removed. The query now behaves like an INNER JOIN. Move right-table conditions into ON (ON o.customer_id = c.customer_id AND o.status = 'PAID') to keep all customers. For inner joins, ON versus WHERE makes no difference to the result.

How it works

  1. Both joins first pair rows that satisfy the ON condition.
  2. INNER JOIN stops there and returns only those pairs.
  3. LEFT JOIN additionally adds each left row with no partner, padding right columns with NULL.
  4. WHERE then filters this combined result.
  5. Aggregates like COUNT(o.order_id) count only non-NULL values, so unmatched customers get 0.

Example

-- All customers with number of paid orders (0 if none)
SELECT c.name, COUNT(o.order_id) AS paid_orders
FROM customers c
LEFT JOIN orders o
  ON o.customer_id = c.customer_id AND o.status = 'PAID'
GROUP BY c.customer_id, c.name;

-- Customers who never placed an order
SELECT c.name
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.customer_id
WHERE o.order_id IS NULL;

Common mistakes

  • Filtering the right table in WHERE after a LEFT JOIN.
  • Using COUNT(*) instead of COUNT(o.order_id), which counts the NULL row as 1.
  • Assuming LEFT JOIN never increases row count; one-to-many matches still multiply rows.
  • Writing = NULL instead of IS NULL in the anti-join.

How to answer in the interview

"INNER JOIN gives me only rows with a match on both sides, so customers with at least one order, one row per pair. LEFT JOIN keeps every row from the left table; where there's no match, the right columns are NULL, so customers who never ordered still show up. The trap I watch for is putting a right-table condition, like status equals PAID, in the WHERE clause, because that removes the NULL rows and quietly makes it an inner join. Those conditions belong in ON."

Likely follow-up questions

  • How do you find customers who never ordered? LEFT JOIN and WHERE o.order_id IS NULL, or NOT EXISTS.
  • What is a FULL OUTER JOIN? It keeps unmatched rows from both sides.
  • Is LEFT JOIN slower than INNER JOIN? Usually similar; the optimiser has fewer reordering options, but indexes matter far more.
