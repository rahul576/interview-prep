How have you used Generative AI or large language models in software development?

AI/ML & GenAI · scenario · levels entry

In one line

Describe concrete, real uses of AI in your development work (code generation, tests, refactoring, explaining code, debugging, documentation), show that you review and verify output and respect security and privacy rules, and quantify the impact; mention any LLM features you built.

Detailed explanation

This is an experience question, and interviewers want specifics plus judgement. Vague answers ("I use ChatGPT sometimes") sound weak; uncritical answers ("it writes all my code") sound risky. Aim for three layers.

1. Daily assistance. Typical high-value uses for a Java backend or DevOps engineer: scaffolding DTOs, mappers, REST controllers and configuration; generating unit tests and parameterised edge cases; explaining unfamiliar legacy code; drafting SQL, regular expressions, shell scripts, Dockerfiles and Kubernetes manifests; interpreting stack traces and logs; brainstorming design options; and drafting documentation and PR descriptions.

2. Judgement. AI output can be confidently wrong, outdated or insecure (invented library methods, missing input validation, SQL built by string concatenation). Explain that you read every diff, run the tests, and treat AI code exactly like a junior colleague's pull request. Mention data hygiene: only company-approved tools, no secrets, credentials or customer data in prompts.

3. Building with LLMs (if applicable). If you integrated an LLM into a product, for example a support assistant using retrieval-augmented generation over documentation via Spring AI or LangChain4j, describe the architecture briefly and how you evaluated it.

Finish with impact: for example, test-writing time for a module dropped from a day to a few hours, or onboarding onto a legacy service took days instead of weeks.

How it works

  1. Pick two or three representative uses you genuinely have.
  2. For each, say what the tool did and what you did.
  3. Explain your review and verification habits.
  4. State the security and privacy rules you follow.
  5. Add a product integration if you have one.
  6. Close with a measurable result.

Example

Sample STAR answer:

  • Situation: we inherited a 10-year-old billing module with little test coverage.
  • Task: add a feature safely.
  • Action: I asked the assistant to explain the main classes and generate characterisation tests for the existing behaviour, reviewed and corrected them, then refactored with the tests as a safety net.
  • Result: coverage on that module went from about 20% to 75% in two days, and the feature shipped without regressions.

Common mistakes

  • Being vague or claiming usage you cannot discuss in depth.
  • Implying you merge AI output without review.
  • Admitting to pasting secrets or customer data into public tools.
  • No mention of results.

How to answer in the interview

"I use an AI assistant every day, mainly for repetitive and exploratory work. It scaffolds DTOs, mappers and controllers following our patterns, generates unit tests including edge cases I might miss, and explains unfamiliar legacy code or stack traces. For example, on an old billing module it helped me write characterisation tests quickly, taking coverage from about 20 to 75 percent before refactoring. I always review and run everything, because it can be confidently wrong or insecure, and I only use company-approved tools without secrets or customer data. I've also built a small RAG-based assistant over our docs using Spring AI."

Likely follow-up questions

  • What risks do you watch for in AI code? Invented APIs, missing validation, injection flaws, licence issues and subtle logic errors.
  • Has AI ever misled you? Yes, for example a deprecated API; tests and documentation caught it.
  • How do you keep your own skills sharp? I make sure I understand every line I commit and still solve hard problems myself.
