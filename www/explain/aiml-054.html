What are foundation models, and why did they change how AI applications are built?

AI/ML & GenAI · concept · levels entry, mid

In one line

Foundation models are large models pretrained on broad data and adapted to many tasks through prompting, retrieval, tools or fine-tuning; one model replacing many task-specific ones lowered the barrier to building AI features and shifted engineering toward integration, evaluation, safety and cost, while concentrating capability in a few providers.

Detailed explanation

The term describes models such as large language models and multimodal models trained at huge scale on diverse data (text, code, images, audio) with self-supervised objectives like next-token prediction. Because they learn general representations of language and the world, they serve as a foundation that can be adapted to countless downstream tasks: prompting (zero- or few-shot), retrieval of relevant context (RAG), tool use to call APIs and act, and fine-tuning (often parameter-efficient like LoRA) when needed.

Before, every task, such as sentiment analysis, translation, summarisation, entity extraction or question answering, needed its own labelled dataset, feature engineering and dedicated model, built and maintained by ML specialists over weeks or months. Now one model handles all of these and far more, often with no training. A backend developer can ship a useful feature in days by calling an API with a well-designed prompt and context.

This shifted the work in AI engineering. Less effort goes into training models; more goes into integration (APIs, streaming, tool calling, agents), prompt and context engineering, retrieval pipelines, evaluation (since outputs are open-ended and non-deterministic), safety and guardrails (prompt injection, harmful content, data leakage), observability, and cost and latency management (model routing, caching, batching). Product thinking around where AI genuinely helps users also became central.

It also concentrated capability in a few providers that can afford frontier training runs, raising questions of vendor dependency, pricing power, data governance, model deprecation and geopolitical or regulatory control. Open-weight models partly balance this, and frameworks like the EU AI Act add obligations for general-purpose AI model providers. Foundation models also inherit biases and errors from their training data, which flow into every application built on them.

How it works

  1. Providers pretrain a large model on broad data, then instruction- and preference-tune it.
  2. Developers access it via API or by self-hosting open weights.
  3. Applications adapt it with prompts, retrieved context and tools.
  4. Fine-tuning is added only when prompting and RAG are insufficient.
  5. Teams evaluate, monitor and manage cost, swapping models as better ones appear.

Common mistakes

  • Assuming no evaluation is needed because "the model is smart".
  • Hard-coding one vendor without an abstraction layer.
  • Fine-tuning before trying prompting and retrieval.
  • Ignoring per-token cost at scale.

How to answer in the interview

"Foundation models are large models pretrained on broad data that can be adapted to many tasks via prompting, retrieval, tools or fine-tuning. Previously each task needed its own labelled data and model built by specialists; now one model handles most of them, often without training, so a backend developer can ship an AI feature in days. That shifted engineering toward integration, context design, evaluation, safety and cost management. It also concentrated capability in a few providers, raising dependency and governance concerns, partly balanced by open-weight models."

Likely follow-up questions

  • What new skills does this require of engineers? Prompt and context design, evaluation, RAG, tool integration, security against prompt injection, and cost control.
  • How do you reduce vendor dependency? A model gateway abstraction, portable evals, and tested fallbacks including open-weight models.
  • When is fine-tuning still worth it? Stable high-volume tasks needing consistent format or a smaller cheaper model.
