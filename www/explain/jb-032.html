What is the difference between isEmpty() and isBlank()?

Core Java & OOP · concept · levels mid, senior

In one line

isEmpty() is true only when length is zero; isBlank() (Java 11) is true when the string is empty or contains only whitespace (Unicode-aware via Character.isWhitespace); both throw NullPointerException on null.

Detailed explanation

isEmpty() has existed since Java 6 and is simply length() == 0. So "" is empty, but " ", "\t" and "\n" are not.

isBlank() was added in Java 11. It returns true if the string is empty or every code point is whitespace according to Character.isWhitespace. That covers spaces, tabs, newlines, carriage returns and Unicode space separators such as the em space. Note one subtlety: the non-breaking space (U+00A0) is not whitespace by Character.isWhitespace, so a string of NBSPs is not blank. Input copied from web pages or Word documents sometimes contains it.

For user input validation (name, address, comment fields) you almost always want blank semantics: a name of three spaces is not a name. Java 11 also added the matching Unicode-aware methods strip(), stripLeading(), stripTrailing() and lines(). The older trim() removes only characters with code point <= U+0020 (ASCII space and control characters), so it misses Unicode spaces.

Both are instance methods, so calling them on a null reference throws NullPointerException. Options:

  • Explicit check: s == null || s.isBlank().
  • Apache Commons Lang StringUtils.isBlank(s) / isEmpty(s), which are null-safe (note their isBlank also uses Character.isWhitespace).
  • Spring's StringUtils.hasText(s) (true if not null and contains non-whitespace).
  • At API boundaries, Bean Validation: @NotBlank (not null and at least one non-whitespace character), @NotEmpty (not null and length > 0), @NotNull.

Normalising input early (strip, then validate) avoids storing values with stray spaces that break uniqueness or lookups.

How it works

  1. isEmpty: returns length() == 0.
  2. isBlank: if empty, true; otherwise scans characters and returns false at the first non-whitespace.
  3. Compact Strings let Latin-1 strings be checked byte by byte quickly.
  4. Calling either on null fails before the method runs.

Example

"".isEmpty();          // true
" ".isEmpty();         // false
" ".isBlank();         // true
"\t\n".isBlank();      // true
" ".isBlank();    // true  (em space)
" ".isBlank();    // false (non-breaking space)
"  hi ".strip();       // "hi"

record SignupRequest(@NotBlank @Size(max = 80) String name,
                     @NotBlank @Email String email) {}

Common mistakes

  • Validating required fields with isEmpty, letting whitespace through.
  • Calling isBlank on possibly-null values.
  • Using trim() and expecting Unicode spaces to be removed.
  • Confusing @NotEmpty with @NotBlank.

How to answer in the interview

"isEmpty is true only when the length is zero, so a string of spaces isn't empty. isBlank, added in Java 11, is true when the string is empty or only whitespace, and it's Unicode-aware through Character.isWhitespace, so tabs and newlines count. For validating input like a name, isBlank is what I want. Both are instance methods, so calling them on null throws NullPointerException; I check null first, use StringUtils.isBlank, or at the API boundary put @NotBlank on the request field. strip is the Unicode-aware counterpart of trim."

Likely follow-up questions

  • What is the difference between trim() and strip()? trim removes chars up to U+0020; strip removes all Unicode whitespace.
  • @NotEmpty vs @NotBlank? NotEmpty allows whitespace-only; NotBlank doesn't.
  • Is a non-breaking space blank? Not according to isBlank.
