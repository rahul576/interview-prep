Explain the Azure OpenAI deployment types: Standard, Global, Data Zone, Provisioned and Batch.

Azure AI & Foundry · concept · levels mid, senior

In one line

Deployment types decide where inference runs and how you pay: Standard (pay-per-token, one region), Global Standard (any region, highest quota), Data Zone Standard (within a geography like EU or US), Provisioned (reserved PTUs, predictable latency) and Batch (asynchronous jobs within 24 hours at about half price).

Detailed explanation

When you deploy a model in Azure OpenAI or Foundry, you pick a deployment type (the SKU). It controls two things: the processing location and the billing model.

Standard (regional): pay per token, and inference is processed in the region of the resource. Best for strict regional data processing, but quotas are lower and new models may not be available in every region.

Global Standard: pay per token, but Azure routes each request to any Azure region with capacity. It has the highest default quotas, best availability and usually first access to new models. Data at rest (files, stored conversations) stays in your resource's geography; only processing may happen elsewhere.

Data Zone Standard: a middle ground. Processing stays within a data zone, such as the EU or the US, which satisfies many residency requirements while still pooling capacity across several regions.

Provisioned (regional, Data Zone or Global provisioned): you reserve provisioned throughput units (PTUs) of dedicated model capacity, billed hourly or more cheaply via monthly or yearly reservations. You get predictable latency and throughput, and pay whether you use it or not.

Batch (Global Batch or Data Zone Batch): you upload a JSONL file of requests, the service processes it asynchronously with a 24-hour target, at roughly 50% of Standard price, and uses a separate quota so it doesn't consume online capacity. Ideal for bulk classification, summarisation, embeddings backfills or evaluations.

How it works

  1. Determine residency needs: regional, data zone or global.
  2. Determine traffic shape: spiky (Standard), steady high (Provisioned), offline (Batch).
  3. Create the deployment with the matching SKU.
  4. Set capacity (TPM or PTUs) within quota.
  5. Monitor usage and adjust.

Example

# EU-only processing, pay per token
az cognitiveservices account deployment create -g rg-ai -n foundry-eu \
  --deployment-name chat-eu --model-name gpt-4.1 --model-format OpenAI \
  --model-version "2025-04-14" --sku-name DataZoneStandard --sku-capacity 200

Common mistakes

  • Choosing Global for data that must legally be processed in the EU.
  • Using regional Standard and fighting low quotas unnecessarily.
  • Running nightly bulk jobs online instead of Batch.
  • Buying PTUs for spiky, low-volume traffic.

How to answer in the interview

"Deployment types decide where inference runs and how you pay. Standard is pay-per-token in the resource's region. Global Standard is also pay-per-token but can route to any region, giving the highest quotas, while data at rest stays in your geography. Data Zone keeps processing in the EU or US. Provisioned reserves dedicated capacity in PTUs for predictable latency, billed hourly or by reservation. Batch processes large file-based jobs within 24 hours at about half price. For strict EU residency I'd pick Data Zone Standard or Data Zone Provisioned."

Likely follow-up questions

  • EU data with strict residency? Data Zone EU, or regional Standard in an EU region if processing must stay in one country.
  • Does Batch affect online quota? No, it has its own enqueued-token quota.
  • Can you mix types? Yes, e.g. Provisioned for baseline with spillover to Standard.
