Design an email service like Gmail at a high level.

Classic Design Problems · design · levels senior, lead

In one line

Email = SMTP ingress with SPF/DKIM/DMARC checks and spam/virus filtering, mailbox storage partitioned by user, deduplicated attachments in object storage, a per-user search index, a queued outbound path with retries and reputation management, and sync via IMAP/APIs/push.

Detailed explanation

Almost all access is within one user's mailbox, which makes partitioning by user natural: messages keyed by (user_id, message_id) in a wide-column store (Gmail used Bigtable), with labels/folders and thread IDs as metadata.

Inbound: MX records point to SMTP servers that accept mail, verify sender authenticity (SPF: allowed IPs; DKIM: signature; DMARC: policy), then run spam and malware filtering (ML classifiers, reputation, attachment sandboxing) before delivery.

Attachments go to object storage keyed by content hash, so a 10 MB file sent to 500 colleagues is stored once.

Search: each user has an inverted index over subject, body, sender, labels, updated on delivery; with billions of users this is a huge but embarrassingly parallel index sharded by user.

Outbound: messages queue for delivery; remote servers may be slow or reject temporarily (4xx), so retries with backoff for up to days, bounce handling, and IP reputation management so mail isn't marked as spam.

How it works

  1. Receive via SMTP → auth checks → spam/virus → store message + attachment refs → index → notify clients.
  2. Clients: web/mobile APIs with push; third-party via IMAP/POP; sync tokens for incremental changes.
  3. Send: API → outbound queue → DKIM sign → SMTP to recipient MX → retries/bounces.

Example

DNS: example.com TXT "v=spf1 include:_spf.mailprovider.com -all"
     selector._domainkey.example.com TXT "v=DKIM1; p=MIIBI..."
     _dmarc.example.com TXT "v=DMARC1; p=quarantine"

Common mistakes

  • Global search index not partitioned by user.
  • Storing duplicate attachments per recipient.
  • No retry/backoff for temporary SMTP failures.
  • Ignoring sender authentication.

How to answer in the interview

"Inbound SMTP servers verify SPF, DKIM and DMARC and run spam and malware filters. Mailboxes are partitioned by user in a wide-column store, attachments are deduplicated in object storage, and each user has their own search index updated on delivery. Outbound mail goes through a queue with retries, signing and reputation management. Clients sync through APIs with push, or IMAP."

Likely follow-up questions

  • Fast search across 15 years? Per-user inverted index, recent data hot, older tiers cold.
  • Large mailing lists? Fan-out on send with batching and per-domain throttling.
  • Threading? Group by References/In-Reply-To headers and subject heuristics.
