Which AIOps and AI-for-SRE tools are you aware of, and how would you evaluate one?

AI Agents & AIOps · concept · levels mid, senior

In one line

AI features now exist in observability platforms (Dynatrace Davis AI, Datadog Watchdog and Bits AI, New Relic, Splunk), incident platforms (PagerDuty, BigPanda), cloud SRE agents (Azure SRE Agent, AWS DevOps Agent) and open source (K8sGPT, HolmesGPT); evaluate them on your own incidents for accuracy, noise reduction and time saved, plus data access, security, integration and cost.

Detailed explanation

The market changes quickly, so knowing categories matters more than memorising every product. Observability platforms embed AI: Dynatrace uses its Davis AI for causal root cause analysis based on its topology model; Datadog offers Watchdog for anomaly detection and Bits AI as an assistant and investigating agent; New Relic and Splunk have AI assistants for querying and explaining telemetry. Incident and event management platforms such as PagerDuty and BigPanda focus on alert correlation, noise reduction and AI-generated incident summaries. Cloud providers offer operations agents, such as Azure SRE Agent and AWS's DevOps agent, which investigate issues using the provider's own telemetry and resources. In open source, K8sGPT scans Kubernetes clusters and explains problems, and HolmesGPT investigates alerts using pluggable data sources.

Evaluation should never rely on vendor demos. Run a proof of concept on your own data: replay past incidents with known root causes and measure suggestion accuracy, measure noise reduction on current alert streams while checking nothing important was hidden, and estimate time saved for responders. Then check what data it needs, where it is processed and stored, security controls for any actions, integration effort with your stack, and the cost model, which may scale with data volume or hosts.

How it works

  1. Define the problem: noise, slow diagnosis, Kubernetes troubleshooting.
  2. Shortlist tools that fit the existing stack.
  3. Prepare 20-30 past incidents with documented causes.
  4. Run tools on replayed and live data for several weeks.
  5. Score accuracy, noise reduction, missed incidents and responder feedback.
  6. Review security, data residency, integration and cost.

Common mistakes

  • Choosing on demos built with vendor sample data.
  • Measuring noise reduction without checking missed incidents.
  • Ignoring data residency and what telemetry is sent to models.
  • Underestimating cost growth with telemetry volume.

How to answer in the interview

"Most observability platforms now have AI built in, like Dynatrace Davis, Datadog Watchdog and Bits AI, and New Relic and Splunk assistants. PagerDuty and BigPanda focus on correlation and incident summaries, the clouds offer SRE agents like Azure SRE Agent, and open source has K8sGPT and HolmesGPT. To evaluate one, I run a proof of concept on our own past incidents and live alerts, measuring root cause accuracy, noise reduction without hiding real problems, and responder time saved. I also check data access and residency, security for any actions, integration effort and the cost model."

Likely follow-up questions

  • Fair PoC? Same incidents for every tool, known answers, fixed time box.
  • Build vs buy? Buy correlation; build thin agents for unique workflows.
  • Lock-in? Prefer tools that work on OpenTelemetry data.
