How do you generate all subsets or permutations, and what is backtracking?

DSA: Algorithms & DP · concept · levels mid, senior

In one line

Backtracking builds candidates step by step: choose an option, explore recursively, then un-choose (undo) and try the next. It prunes branches that can't lead to a valid solution. Subsets: 2ⁿ (include or exclude each item). Permutations: n! (pick an unused item for each position). Duplicates: sort, then skip equal elements at the same depth.

Detailed explanation

Many problems ask you to enumerate all valid configurations: subsets, permutations, combinations summing to a target, N-Queens, Sudoku, word search. The search space is a decision tree, and backtracking is a DFS over it that keeps one mutable partial solution and restores it after each branch. That is far cheaper than copying state at every node.

The template:

backtrack(state):
    if state is complete/valid: record copy
    for each choice available:
        if choice is invalid: continue   (pruning)
        make choice
        backtrack(next state)
        undo choice

Subsets (power set): at index i, branch on include or exclude. Or, in the common "start index" style, every node of the recursion tree is a subset: loop j from start, add nums[j], recurse with j + 1, then remove. There are 2ⁿ subsets, and copying each costs O(n), so the total is O(n·2ⁿ).

Permutations: for each position, choose any element not yet used (tracked with a boolean[] used), recurse, then unmark. There are n! permutations, so O(n·n!) total.

Duplicates in the input ([1, 2, 2]): sort first. In the loop, skip an element if it equals the previous one at the same recursion level. For subsets: j > start && nums[j] == nums[j-1]. For permutations: i > 0 && nums[i] == nums[i-1] && !used[i-1]. That way each distinct result is generated once.

Pruning is what makes backtracking practical. N-Queens rejects a placement as soon as a column or diagonal is attacked. Combination sum stops once the running sum exceeds the target (after sorting). Sudoku uses constraint checks per cell. The worst case stays exponential, but the explored tree shrinks dramatically.

How it works

  1. Sort the input if duplicates or pruning by size matter.
  2. Keep a path (current partial solution) and the result list.
  3. At each call, record path if it is a valid solution, as a copy.
  4. Loop over the choices, skipping invalid or duplicate ones.
  5. Add the choice, recurse, then remove it (backtrack).

Example

List<List<Integer>> subsetsWithDup(int[] nums) {
    Arrays.sort(nums);
    List<List<Integer>> res = new ArrayList<>();
    build(nums, 0, new ArrayList<>(), res);
    return res;
}
void build(int[] nums, int start, List<Integer> path, List<List<Integer>> res) {
    res.add(new ArrayList<>(path));                      // every node is a subset
    for (int j = start; j < nums.length; j++) {
        if (j > start && nums[j] == nums[j - 1]) continue; // skip duplicates at this depth
        path.add(nums[j]);
        build(nums, j + 1, path, res);
        path.remove(path.size() - 1);                     // un-choose
    }
}
// [1,2,2] -> [], [1], [1,2], [1,2,2], [2], [2,2]

Common mistakes

  • Adding path itself instead of a copy, so all results end up as the same (empty) list.
  • Forgetting to undo the choice.
  • Deduplicating with a Set<List> after the fact, which is wasteful.
  • No pruning, which causes timeouts on larger inputs.

How to answer in the interview

"Backtracking builds a solution incrementally: choose an option, explore recursively, then undo that choice before trying the next one, so a single mutable path is reused. For subsets, at each element I either include or exclude it, giving 2 to the n subsets. For permutations, I pick each unused element for the next position, giving n factorial. Pruning invalid branches early, as in N-Queens or Sudoku, is what makes it practical. With duplicate inputs, I sort first and skip an element that equals the previous one at the same depth, so each result appears once."

Likely follow-up questions

  • Combination sum? Sort, loop from start (reuse allowed: recurse with j, not j+1), and break when the candidate exceeds the remainder.
  • N-Queens pruning? Track used columns and both diagonals (r+c, r-c) in sets or bitmasks.
  • Iterative subsets? Bitmasks from 0 to 2ⁿ-1, or start with [[]] and add each element to all existing subsets.
