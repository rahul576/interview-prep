How do you build a security baseline for AWS accounts with GuardDuty, Security Hub, Config and CloudTrail?

Cloud (AWS) · design · levels senior

In one line

With AWS Organizations and a delegated security account, enable an organisation CloudTrail to an immutable log archive, GuardDuty for threat detection, AWS Config for configuration history and rules, and Security Hub to aggregate findings against AWS FSBP and CIS standards, routing findings through EventBridge to alerts and automated remediation.

Detailed explanation

The baseline must apply to every account automatically, including new ones, so it is enabled organisation-wide, often via Control Tower, with a security tooling account as delegated administrator for GuardDuty, Security Hub, Config, Inspector, Macie and IAM Access Analyzer. Nobody works in the management account.

CloudTrail: one organisation trail across all regions sends management events (and chosen data events) to an S3 bucket in a log archive account, with SSE-KMS, versioning, Object Lock, log file validation, and a bucket policy that member accounts cannot change. CloudTrail Lake or Athena supports queries.

GuardDuty analyses CloudTrail management events, VPC flow logs, DNS logs, and with protection plans S3 data events, EKS audit logs and runtime, RDS logins, Lambda network activity and malware scans of EBS and S3. It detects compromised credentials, crypto mining, communication with known malicious IPs, unusual API calls and privilege escalation, and Extended Threat Detection correlates multi-stage attacks.

AWS Config records resource configurations and changes and evaluates rules like encrypted volumes, public buckets or open SSH, aggregated centrally. Security Hub collects findings from GuardDuty, Config, Inspector, Macie, Access Analyzer, Firewall Manager and partners in the standard ASFF/OCSF format and runs security standards: AWS Foundational Security Best Practices, CIS AWS Foundations Benchmark, PCI DSS and NIST, scoring each account.

Findings flow to EventBridge, which triggers notifications (Slack, PagerDuty, ticketing) and automated remediation with Lambda or SSM Automation, for example closing an open security group or blocking public access. Add IAM Access Analyzer, Inspector for vulnerability scanning and Macie for sensitive data discovery.

How it works

  1. Set up Organizations with log archive and security accounts.
  2. Create an organisation CloudTrail into the immutable log bucket.
  3. Delegate GuardDuty, Security Hub and Config admin to the security account; auto-enable for new accounts.
  4. Enable Security Hub standards and central configuration.
  5. Route high-severity findings via EventBridge to on-call and remediation.

Example

{
  "source": ["aws.securityhub"],
  "detail-type": ["Security Hub Findings - Imported"],
  "detail": {"findings": {
    "Compliance": {"Status": ["FAILED"]},
    "GeneratorId": [{"suffix": "EC2.19"}],
    "Severity": {"Label": ["HIGH", "CRITICAL"]}

}
aws guardduty create-detector --enable
aws guardduty update-organization-configuration --detector-id $DET \
  --auto-enable-organization-members ALL

Common mistakes

  • Trails per account that local admins can disable.
  • Enabling services in only one region; attackers use unused regions.
  • Alerting on every finding, so teams ignore the noise.
  • Turning on auto-remediation without testing, breaking production.

How to answer in the interview

"With AWS Organizations I enable the baseline everywhere automatically, administered from a dedicated security account. An organisation CloudTrail sends logs from all accounts and regions to an immutable bucket in a log archive account. GuardDuty analyses CloudTrail, flow logs, DNS and EKS logs for threats like compromised credentials or crypto mining. Config records configuration history and evaluates rules. Security Hub aggregates findings from GuardDuty, Config, Inspector, Macie and Access Analyzer and scores accounts against FSBP and CIS. Findings go through EventBridge to alerts and automated remediation."

Likely follow-up questions

  • How auto-remediate SSH open to 0.0.0.0/0? Config rule or Security Hub finding triggers an SSM Automation that revokes the rule and notifies the owner.
  • Why a separate log archive account? Attackers with workload admin rights cannot tamper with evidence.
  • How reduce Security Hub noise? Disable irrelevant controls, suppress accepted risks, and route by severity and owner.
