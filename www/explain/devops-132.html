Terraform vs Pulumi vs Crossplane: how do they differ?

Infrastructure as Code · concept · levels mid, senior

In one line

Terraform (and its open-source fork OpenTofu) uses declarative HCL with a state file and plan/apply runs; Pulumi defines infrastructure in general-purpose languages (TypeScript, Python, Go, C#) with the same state-and-preview model; Crossplane turns Kubernetes into a control plane where cloud resources are CRDs continuously reconciled by controllers. Choose by team skills and platform model.

Detailed explanation

Terraform is the de facto standard: huge provider ecosystem, HCL that is readable for ops and dev, explicit plan before apply, and state in a backend. In August 2023 HashiCorp changed its licence from MPL to the Business Source License (BSL), which restricts competing commercial use. The community forked the last MPL version as OpenTofu, now a Linux Foundation project, CLI-compatible for most configurations and adding features such as client-side state encryption. HashiCorp itself was acquired by IBM. For most users both work; organisations choose based on licence policy and features.

Pulumi keeps the desired-state model (state in Pulumi Cloud or a self-managed backend, pulumi preview and up) but you write programs in real languages. You get loops, functions, classes, package managers, IDE support and unit tests with familiar frameworks, which developers like for complex, dynamic infrastructure. The risk is that infrastructure code becomes too clever and harder for others to review.

Crossplane takes a different approach. It runs in a Kubernetes cluster; providers install CRDs like Bucket or RDSInstance, and controllers continuously reconcile real cloud resources to match them, so drift is corrected automatically without anyone running a plan. Platform teams build Compositions and composite resource definitions (XRDs) that expose a simple API like PostgresInstance to developers, delivered via GitOps with Argo CD. Costs: you need a reliable management cluster, debugging goes through controller status and events, and there is no reviewable plan output like Terraform's.

How it works

  1. Terraform/OpenTofu: write HCL → plan → review → apply → state updated.
  2. Pulumi: write a program → preview → up; engine diffs against state.
  3. Crossplane: commit a claim/XR to Git → Argo CD applies it → controllers create and keep reconciling the resource.

Example

// Pulumi (TypeScript): three buckets with a loop
import * as aws from "@pulumi/aws";
for (const env of ["dev", "staging", "prod"]) {
  new aws.s3.Bucket(`logs-${env}`, { tags: { env } });
}
# Crossplane: developer-facing claim backed by a platform Composition
apiVersion: platform.acme.io/v1alpha1
kind: PostgresInstance
metadata: { name: orders-db, namespace: orders }
spec:
  size: medium
  version: "16"

Common mistakes

  • Saying Terraform is "no longer open source" without mentioning OpenTofu and what BSL actually restricts.
  • Choosing Pulumi and writing untestable, overly abstract code.
  • Adopting Crossplane without a robust, backed-up management cluster.
  • Mixing tools to manage the same resources.

How to answer in the interview

"Terraform uses declarative HCL with a state file and explicit plan and apply runs; after HashiCorp moved to the BSL licence in 2023, the community fork OpenTofu stays open source and is largely compatible. Pulumi keeps a similar state and preview model but lets you write infrastructure in TypeScript, Python or Go, with loops, functions and unit tests, which suits developer-heavy teams. Crossplane turns Kubernetes into a control plane: cloud resources are CRDs and controllers reconcile them continuously, so drift is fixed automatically and platform teams can offer simple composite APIs through GitOps. I'd choose based on team skills and whether we're building a Kubernetes-centred platform; Terraform or OpenTofu remains the most common default."

Likely follow-up questions

  • When is continuous reconciliation a disadvantage? During incidents, when a manual emergency change gets reverted, or when an unexpected change applies without a reviewed plan.
  • Can Pulumi use Terraform providers? Yes, many Pulumi providers are bridged from Terraform providers.
  • How do you migrate Terraform to OpenTofu? Pin a compatible version, run tofu init and tofu plan and verify there are no changes.
