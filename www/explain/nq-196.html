What are cross-cutting concerns, and how can AOP be used for logging?

Spring Framework · scenario · levels mid

In one line

Cross-cutting concerns are requirements spread across many modules (logging, auditing, security, transactions, metrics); for logging, an @Aspect with @Around advice on a pointcut or custom annotation uses ProceedingJoinPoint.proceed() to log method, arguments, result, exceptions and duration in one place, while avoiding sensitive data and keeping overhead low.

Detailed explanation

A cross-cutting concern is something many classes need but none of them is really about. If every service method starts with "log entry, start timer" and ends with "log exit, log duration, catch and log exception", the business logic drowns in boilerplate, the format drifts between teams and changing it means editing hundreds of methods.

With Spring AOP you write that behaviour once. Create a class annotated with @Aspect and @Component (with Boot, spring-boot-starter-aop or the AspectJ weaver dependency enables it). Define a pointcut: either all methods in a package, such as execution(* com.acme.service..*(..)), or, more precisely, methods carrying a custom annotation like @LogExecutionTime, so teams opt in explicitly.

Use @Around advice, because it can wrap the whole call. It receives a ProceedingJoinPoint, from which you read the method signature and arguments. Record the start time, call proceed() to execute the real method, then log the result and duration. If the method throws, log the exception with the duration and rethrow it, so callers and transaction rollback are unaffected.

Good practice: don't log passwords, tokens or personal data (log ids, mask or skip arguments, or use an opt-in attribute); log at DEBUG for argument detail and INFO or metrics for timings; keep the aspect cheap, as it runs on every matching call; put the correlation id in the MDC so logs can be traced. For timings, Micrometer's @Timed or @Observed may be a better fit than logs.

How it works

  1. Create a marker annotation @LogExecutionTime with runtime retention.
  2. Write an @Aspect with @Around("@annotation(...)").
  3. Spring proxies beans with annotated methods.
  4. On each call: log start, proceed(), log result and duration.
  5. On exception: log with duration, rethrow.

Example

@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface LogExecutionTime { boolean logArgs() default false; }

@Aspect
@Component
class LoggingAspect {
    private static final Logger log = LoggerFactory.getLogger(LoggingAspect.class);

    @Around("@annotation(cfg)")
    public Object around(ProceedingJoinPoint pjp, LogExecutionTime cfg) throws Throwable {
        String method = pjp.getSignature().toShortString();
        long start = System.nanoTime();
        try {
            Object result = pjp.proceed();
            log.info("{} ok in {} ms", method, (System.nanoTime() - start) / 1_000_000);
            return result;
        } catch (Throwable ex) {
            log.warn("{} failed in {} ms: {}", method,
                     (System.nanoTime() - start) / 1_000_000, ex.toString());
            throw ex;
        } finally {
            if (cfg.logArgs() && log.isDebugEnabled())
                log.debug("{} args={}", method, Arrays.toString(pjp.getArgs()));
        }
    }
}

@Service
class OrderService {
    @LogExecutionTime
    public Order place(PlaceOrder cmd) { /* business logic only */ }
}

Common mistakes

  • Swallowing the exception in the advice, which breaks error handling and transaction rollback.
  • Logging full arguments, leaking personal data or secrets.
  • Very broad pointcuts that also advise controllers, repositories and framework beans.
  • Expecting the aspect to run for self-invoked or private methods.

How to answer in the interview

"Cross-cutting concerns are requirements that affect many classes but aren't their core job: logging, auditing, security, transactions, metrics. Writing them by hand duplicates code everywhere. With Spring AOP I create an Aspect component with Around advice on a custom annotation like LogExecutionTime, or a pointcut on service methods. The advice gets a ProceedingJoinPoint, logs the method, records the start time, calls proceed, logs the result and duration, or logs and rethrows the exception. Business methods stay clean, and I avoid logging sensitive data and keep the aspect lightweight."

Likely follow-up questions

  • Why doesn't it run for a same-class call? Self-invocation bypasses the proxy.
  • Around vs Before/After? Around can time, change arguments or results, and decide whether to proceed.
  • Better tool for timings? Micrometer @Timed/@Observed for metrics and traces.
