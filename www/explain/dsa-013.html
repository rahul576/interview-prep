How do you implement a queue using two stacks, and what is the amortised cost?

DSA: Lists, Stacks & Queues · concept · levels mid

In one line

Keep an inbox stack for pushes and an outbox stack for pops and peeks. Only when the outbox is empty, move everything from the inbox into it, which reverses the order so the oldest is on top. A single pop can be O(n), but every element moves at most once, so the amortised cost is O(1) per operation.

Detailed explanation

A queue is FIFO and a stack is LIFO. Pouring one stack into another reverses the order, turning LIFO into FIFO. The trick is when to pour.

  • push(x): always inbox.push(x). O(1).
  • pop() / peek(): if outbox is empty, pop every element from inbox and push it onto outbox. Then pop or peek the outbox top.

Why only transfer when the outbox is empty? The outbox holds older elements in correct FIFO order. If you poured new elements on top of them, newer items would come out first and the order would break.

Amortised analysis. Over its life, each element is pushed to the inbox once, popped from the inbox once, pushed to the outbox once and popped from the outbox once. That is 4 O(1) operations. So any sequence of n operations costs O(n) in total, which is O(1) amortised per operation, even though one unlucky pop after a million pushes does a million moves. "Amortised" means the average over a worst-case sequence. It is not an average over random inputs. It is the same reasoning as ArrayList doubling its capacity.

When does amortised O(1) matter? For throughput it is great. For hard real-time latency a single O(n) pause might be unacceptable. A de-amortised version spreads the transfer across operations, or you simply use ArrayDeque.

The reverse problem, a stack using queues, works by rotating: after enqueueing x, dequeue and re-enqueue the previous n-1 elements, so x is at the front. Push is O(n) and pop is O(1).

How it works

  1. push(x): in.push(x).
  2. pop(): if (out.isEmpty()) while (!in.isEmpty()) out.push(in.pop()); then return out.pop();.
  3. peek(): the same transfer, then out.peek().
  4. empty(): in.isEmpty() && out.isEmpty().

Example

class MyQueue {
    private final Deque<Integer> in = new ArrayDeque<>(), out = new ArrayDeque<>();
    public void push(int x) { in.push(x); }
    public int pop()  { shift(); return out.pop(); }
    public int peek() { shift(); return out.peek(); }
    public boolean empty() { return in.isEmpty() && out.isEmpty(); }
    private void shift() {
        if (out.isEmpty()) while (!in.isEmpty()) out.push(in.pop());
    }
}
// push 1,2,3 -> in=[3,2,1] ; pop -> shift: out=[1,2,3] -> returns 1
// push 4 -> in=[4] ; pop -> out not empty -> returns 2 (no transfer)

Common mistakes

  • Transferring on every pop even when the outbox isn't empty, which breaks the order.
  • Moving elements back to the inbox after each pop, which makes every operation O(n).
  • Calling it "O(1) worst case". It is O(1) amortised, with O(n) worst case for a single pop.
  • Confusing amortised with average-case analysis.

How to answer in the interview

"I keep two stacks: an inbox where every push goes, and an outbox for pop and peek. When the outbox is empty and someone pops, I move all elements from the inbox to the outbox, which reverses them so the oldest is on top. I only transfer when the outbox is empty, otherwise I'd break FIFO order. Any single pop can be O(n), but each element is moved at most once in its lifetime, so over any sequence of operations the cost is O(1) amortised per operation. That's the same argument as ArrayList resizing."

Likely follow-up questions

  • Stack using queues? On push, enqueue then rotate the previous elements behind it. Push O(n), pop O(1).
  • What does amortised mean exactly? The total cost of any sequence of n operations divided by n. It is a worst-case guarantee on the average.
  • Thread-safe version? Lock both stacks together, or use ConcurrentLinkedQueue instead.
