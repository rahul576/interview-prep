How does logistic regression work, and why is it still widely used?

AI/ML & GenAI · concept · levels entry, mid

In one line

Logistic regression passes a weighted sum of features through the sigmoid to output a probability, is trained by minimising log loss, and remains popular because it is fast, interpretable, well calibrated and a strong baseline.

Detailed explanation

The model computes z = w1x1 + w2x2 + ... + b and then p = 1 / (1 + e^-z). The sigmoid squashes any real number into (0, 1), which we read as the probability of the positive class, for example "probability this customer churns in 30 days". Equivalently, it models the log-odds as a linear function: log(p / (1 - p)) = z. A decision is made by applying a threshold to p, chosen from business costs rather than fixed at 0.5.

Training finds the weights that minimise log loss (binary cross-entropy), which heavily penalises confident wrong predictions. The loss is convex, so optimisers such as L-BFGS or gradient descent reliably reach the global minimum. Regularisation (L2 ridge, L1 lasso, or elastic net) prevents overfitting and L1 can zero out useless features. For more than two classes, multinomial (softmax) regression generalises it.

It is still widely used because each coefficient has a clear meaning: a one-unit increase in a feature multiplies the odds by e^w. That matters in regulated domains like credit scoring and insurance, where decisions must be explained to customers and regulators. It trains and predicts in microseconds, works well with many sparse features (text, one-hot), produces reasonably calibrated probabilities and is the baseline any complex model must beat to justify its cost. Its main limitation is the linear decision boundary, which you address with feature engineering: polynomial terms, interactions, binning or splines.

How it works

  1. Scale numeric features and encode categoricals.
  2. Compute the linear score z for each example.
  3. Convert to a probability with the sigmoid.
  4. Compute log loss plus a regularisation penalty and update weights to minimise it.
  5. Choose a threshold and interpret coefficients as odds ratios.

Example

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
import numpy as np

clf = make_pipeline(StandardScaler(), LogisticRegression(C=1.0, max_iter=1000))
clf.fit(X_train, y_train)
odds_ratios = np.exp(clf[-1].coef_[0])
proba = clf.predict_proba(X_test)[:, 1]

Common mistakes

  • Forgetting to scale features, which distorts regularisation and slows convergence.
  • Reading coefficients as importance when features are on different scales or highly correlated.
  • Calling it a regression model for continuous targets; it is a classifier.
  • Using 0.5 as the threshold on imbalanced data.

How to answer in the interview

"Logistic regression takes a weighted sum of the features plus a bias and passes it through a sigmoid, giving a probability for the positive class. It's trained by minimising log loss, usually with L2 or L1 regularisation, and the loss is convex so training is reliable. I still use it a lot: it's fast, the coefficients show how each feature changes the log-odds, which regulators like in credit scoring, the probabilities are reasonably calibrated, and it's the baseline complex models must beat. For non-linear patterns I add interactions, splines or binned features."

Likely follow-up questions

  • How do you handle a non-linear relationship? Add polynomial, spline or binned features, or interaction terms.
  • What does L1 regularisation do? Pushes some coefficients to exactly zero, acting as feature selection.
  • How do you handle class imbalance? Class weights, resampling and choosing the threshold from costs.
