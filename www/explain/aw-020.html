What are Systems Manager Session Manager and Parameter Store?

Cloud (AWS) · concept · levels entry

In one line

Session Manager gives shell access to instances through the SSM agent and IAM, with no SSH keys, bastions or open inbound ports, and logs every session; Parameter Store is a hierarchical, versioned key-value store for configuration, with SecureString values encrypted by KMS, read at runtime with IAM permissions.

Detailed explanation

Both are capabilities of AWS Systems Manager.

Session Manager replaces SSH. The SSM agent, preinstalled on Amazon Linux, Ubuntu and Windows AMIs, makes an outbound HTTPS connection to the Systems Manager service. When an authorised user runs aws ssm start-session or clicks Connect in the console, the session is tunnelled through that channel. Benefits: no port 22 open in security groups, no SSH keys to distribute and rotate, no bastion host, and instances can sit in private subnets with only NAT or VPC endpoints (ssm, ssmmessages, ec2messages). Access is controlled by IAM policies (which instances, by tag, which documents), sessions can be logged to S3 or CloudWatch Logs and recorded in CloudTrail, and it supports port forwarding, for example to reach a private RDS database from a laptop. The instance needs an instance profile with AmazonSSMManagedInstanceCore. It also works for on-premises servers registered as hybrid nodes.

Parameter Store stores configuration values as parameters named in hierarchies, such as /orders/prod/db-url and /orders/prod/feature-x. Types are String, StringList and SecureString, which is encrypted with a KMS key. Every change creates a new version, and labels can point to versions. Standard parameters are free (up to 4 KB, 10,000 per region); advanced parameters allow 8 KB, more parameters and policies such as expiration, at a cost. Applications, ECS task definitions, Lambda, CloudFormation and pipelines read parameters at runtime with IAM permissions scoped by path, so configuration stays out of code and images. GetParametersByPath loads a whole application's config at once.

How it works

  1. Instance runs the SSM agent with an instance profile.
  2. Agent connects outbound to Systems Manager.
  3. User with IAM permission starts a session; traffic flows over that channel.
  4. Session activity is logged.
  5. Apps call GetParameter(s) with their role; SecureStrings are decrypted via KMS.

Example

# Shell on a private instance, no SSH
aws ssm start-session --target i-0abc123def456

# Port-forward to a private RDS database
aws ssm start-session --target i-0abc123def456 \
  --document-name AWS-StartPortForwardingSessionToRemoteHost \
  --parameters '{"host":["orders.cluster-xyz.eu-west-1.rds.amazonaws.com"],"portNumber":["5432"],"localPortNumber":["5432"]}'

# Store and read configuration
aws ssm put-parameter --name /orders/prod/db-password --type SecureString --value 'S3cr3t!'
aws ssm get-parameters-by-path --path /orders/prod --with-decryption

Common mistakes

  • Keeping port 22 open "just in case" after adopting Session Manager.
  • Missing VPC endpoints or instance profile, so instances never register.
  • Granting ssm:GetParameter on instead of a path.
  • No session logging.

How to answer in the interview

"Session Manager, part of Systems Manager, gives me a shell on EC2 or on-prem servers through the SSM agent and the AWS API, so I don't need SSH keys, a bastion host or an open port 22. Access is controlled with IAM, and every session can be logged to S3 or CloudWatch. It can also port-forward to private databases. Parameter Store is a key-value store for configuration organised in hierarchies like /orders/prod/db-url, with versioning; SecureString parameters are encrypted with KMS, so it can hold simple secrets. Applications read parameters at runtime with their IAM role, keeping configuration out of code and images."

Likely follow-up questions

  • When Secrets Manager instead? When you need automatic rotation, cross-region replication or cross-account sharing.
  • What endpoints does a private instance need? ssm, ssmmessages and ec2messages interface endpoints.
  • How do apps get parameter changes? Reload periodically or use caching extensions such as the Parameters and Secrets Lambda extension.
