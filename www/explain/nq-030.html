What is the difference between unary and binary functional interfaces?

Java 8+ Features · concept · levels entry

In one line

Unary functional interfaces take one argument (Function, Predicate, Consumer, UnaryOperator) and binary ones take two (BiFunction, BiPredicate, BiConsumer, BinaryOperator); binary forms are typically used to combine or compare two values, as in reduce, Map.merge or Comparator.

Detailed explanation

"Unary" and "binary" refer to arity, the number of parameters of the functional method.

Unary (one input):

  • Function<T,R>: R apply(T)
  • Predicate<T>: boolean test(T)
  • Consumer<T>: void accept(T)
  • UnaryOperator<T>: T apply(T) (same type in and out)
  • Primitive: IntFunction, IntPredicate, ToIntFunction, IntUnaryOperator...

Binary (two inputs):

  • BiFunction<T,U,R>: R apply(T, U)
  • BiPredicate<T,U>: boolean test(T, U)
  • BiConsumer<T,U>: void accept(T, U)
  • BinaryOperator<T>: T apply(T, T) (all same type)
  • Primitive: IntBinaryOperator, ToIntBiFunction, ObjIntConsumer...

Supplier<T> takes zero arguments, so it's neither unary nor binary (sometimes called nullary).

Operator versus Function naming: in the *Operator interfaces all arguments and the result share one type; in Function/BiFunction the types can differ. So BinaryOperator<Integer> fits Integer::sum, while a BiFunction<Product, Integer, BigDecimal> computes a line total from a product and a quantity.

Binary interfaces show up where two values interact: Stream.reduce (combine accumulator and element), Map.merge and compute (old value plus new value or key), Map.forEach and replaceAll (key and value), and Comparator<T>, which is effectively a binary function (T, T) -> int although it isn't in java.util.function.

There's nothing built in for three or more arguments. Define your own @FunctionalInterface (e.g. TriFunction<A,B,C,R>), group parameters into a record, or curry (Function<A, Function<B, Function<C, R>>>), though the latter hurts readability.

How it works

  1. Count the inputs your behaviour needs.
  2. One input: pick from the unary family; two: from the binary family.
  3. If all types match, prefer the Operator variant.
  4. For more parameters, define a custom interface or a parameter record.

Example

// Unary
Function<String, Integer> length = String::length;
Predicate<String> blank = String::isBlank;
UnaryOperator<String> upper = String::toUpperCase;

// Binary
BiFunction<Product, Integer, BigDecimal> lineTotal =
    (p, qty) -> p.price().multiply(BigDecimal.valueOf(qty));
BiPredicate<String, Integer> longerThan = (s, n) -> s.length() > n;
BinaryOperator<Integer> sum = Integer::sum;
Map<String, Integer> stock = new HashMap<>();
stock.merge("SKU-9", 4, sum);
stock.forEach((sku, qty) -> System.out.println(sku + ":" + qty));   // BiConsumer

// Three parameters: custom interface
@FunctionalInterface
interface TriFunction<A, B, C, R> { R apply(A a, B b, C c); }
TriFunction<BigDecimal, Integer, BigDecimal, BigDecimal> priceWithTax =
    (unit, qty, rate) -> unit.multiply(BigDecimal.valueOf(qty)).multiply(BigDecimal.ONE.add(rate));

Common mistakes

  • Calling Supplier "unary".
  • Using BiFunction<T,T,T> where BinaryOperator<T> is expected and clearer.
  • Inventing a TriFunction when a record parameter would be cleaner.
  • Forgetting Comparator is conceptually binary.

How to answer in the interview

"The difference is the number of arguments. Unary interfaces take one: Function, Predicate, Consumer and UnaryOperator. Binary ones take two: BiFunction, BiPredicate, BiConsumer and BinaryOperator. Binary forms are typically used to combine two values, like reduce, Map.merge, or a Comparator comparing two objects. In the Operator versions the arguments and result share one type, while the Function versions allow different types. For three arguments there's nothing built in, so I'd define my own functional interface or group the parameters into a record."

Likely follow-up questions

  • How would you model a function with three parameters? A custom @FunctionalInterface like TriFunction, or a record bundling the inputs.
  • What arity is Supplier? Zero arguments.
  • Is there a BiSupplier? No, a supplier takes no input; return a record or pair instead.
