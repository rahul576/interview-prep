Which Java/JDK version are you currently using in your projects?

Modern Java (11-21) · concept · levels entry, mid, senior

In one line

Name a concrete LTS version (for example Java 21), explain why (long-term support, Spring Boot 3 needs Java 17+), the features you actually use, and your upgrade experience.

Detailed explanation

The interviewer wants to know whether you are current and whether you understand the release model. Since Java 9 there is a feature release every six months, and every two years one is a long-term support (LTS) release: 11, 17, 21 and 25 (September 2025). Companies run production on LTS versions because vendors (Oracle, Eclipse Temurin, Amazon Corretto, Azul, Microsoft) provide security updates for years.

A strong answer in 2026 is usually "Java 21, and we are evaluating or moving to 25", or "Java 17, with a plan to move to 21". Link the choice to the ecosystem: Spring Boot 3.x requires Java 17 as a minimum, and Spring Boot 4 (late 2025) keeps a Java 17 baseline while recommending newer versions. Being on an old version such as 8 or 11 is not a disaster if you can explain the migration plan.

Then show you use the features, not just the version number: records for DTOs, switch expressions and pattern matching, text blocks for SQL and JSON in tests, sequenced collections, and virtual threads for blocking I/O services.

Finally, mention the upgrade. Typical work: updating Maven/Gradle and plugins (compiler, Surefire, Jacoco, Lombok, Mockito/ByteBuddy versions that understand the new bytecode), moving from **javax.* to jakarta.*** when going to Spring Boot 3, replacing removed or encapsulated internal APIs, updating base Docker images, and running the full test suite and a canary before production.

How it works

  1. State the version and that it is LTS.
  2. Give the reason: support window and framework baseline.
  3. List 3-4 features you use daily, with a concrete place.
  4. Describe one upgrade and a problem you solved.
  5. Mention what is next (for example Java 25 evaluation).

Upgrade checklist we used (17 -> 21):
- bump maven-compiler, surefire, jacoco, lombok, mockito
- base image eclipse-temurin:21-jre
- run tests + integration tests on 21 in CI
- canary one service, then roll out

Common mistakes

  • Saying "Java 8" with no awareness of newer versions or a migration plan.
  • Naming a non-LTS version for production without a reason.
  • Listing features you have never actually used.
  • Not knowing which Java version your Spring Boot version requires.

How to answer in the interview

"We run Java 21, which is an LTS release. We moved from 11 to 17 when we adopted Spring Boot 3, since it needs at least 17, and then to 21 last year. Staying on LTS gives us years of security patches. Day to day I use records for DTOs and event payloads, switch expressions and pattern matching, text blocks for SQL in tests, and we enabled virtual threads on a couple of I/O-heavy services. The upgrade was mostly build plugin and library bumps, the javax to jakarta migration and updating our base images; we ran the full test suite on the new JDK and canaried one service first. We're now evaluating Java 25."

Likely follow-up questions

  • What problems did you hit when upgrading the JDK? Old Lombok/Mockito/agent versions failing on new bytecode, and libraries using internal JDK APIs.
  • Which JDK distribution do you use? For example Eclipse Temurin or Amazon Corretto, chosen for free long-term updates.
  • Why not upgrade every six months? Non-LTS versions get updates only until the next release.
