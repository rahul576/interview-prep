Would you build agents on a managed platform like Foundry Agent Service, Bedrock AgentCore or Vertex Agent Engine, or run your own?

AI Agents & AIOps · design · levels senior, lead

In one line

Managed platforms (Microsoft Foundry Agent Service, Amazon Bedrock AgentCore, Google Vertex AI Agent Engine) provide runtime, memory, identity, tool hosting, sandboxes and observability for a faster, safer start; self-hosting gives control, portability and custom architectures; decide on model choice and lock-in, data residency and networking, compliance, cost at scale and team skills.

Detailed explanation

Building a production agent involves much more than prompts: a runtime that scales and isolates sessions, short- and long-term memory, identity and credential management for tools, tool and MCP integrations, sandboxed code execution, observability and evaluation, and security controls. Managed platforms package these. Microsoft Foundry Agent Service, Amazon Bedrock AgentCore and Google Vertex AI Agent Engine each offer hosted runtimes plus memory, identity, gateways for tools and tracing, integrated with their cloud's networking, IAM and compliance certifications. For a company already standardised on that cloud, they shorten time to production significantly.

Running your own, with a framework such as LangGraph, a provider SDK like the OpenAI Agents SDK or Claude Agent SDK, deployed on Kubernetes or serverless, gives full control over architecture, scaling, state stores and costs, portability across clouds and model providers, and freedom to build patterns the platforms do not support. The price is building and operating memory, identity, sandboxing and observability yourself.

Key criteria: model choice and lock-in, since platforms favour their catalogues and APIs, though many support open frameworks; data residency, private networking and compliance requirements; the cost model at expected volume; maturity of features you need; and team skills. A common outcome is a hybrid: managed platforms for standard internal business agents, custom infrastructure for core product agents where differentiation and control matter. Either way, insist on tracing, evaluation, policy enforcement and exportable state.

How it works

  1. List required capabilities: memory, tools, sandbox, identity, evals.
  2. Map them to each platform and to a self-hosted stack.
  3. Assess lock-in: framework portability, data export, model options.
  4. Check residency, networking, compliance and cost at projected scale.
  5. Prototype the same agent on the top candidates.
  6. Decide per use case; document exit strategy.

Example

A decision record for two agents in the same company:

agents:
  hr-policy-assistant:
    choice: managed (Foundry Agent Service)
    reasons: [already on Azure, Entra identity built in, standard RAG + tools, small team]
    exit_plan: prompts, tools (MCP) and knowledge index kept in our repos and storage
  checkout-support-agent:
    choice: self-hosted (LangGraph on AKS)
    reasons: [core product, custom routing across models, strict latency budget, per-tenant cost control]
    must_have: [OpenTelemetry tracing, eval suite in CI, policy gateway, sandbox pods]

Common mistakes

  • Choosing a platform before knowing required capabilities.
  • Ignoring how state and memory can be exported later.
  • Underestimating the effort to self-host sandboxing and identity.
  • Assuming one choice must fit every agent.

How to answer in the interview

"Managed platforms like Foundry Agent Service, Bedrock AgentCore and Vertex AI Agent Engine give you the runtime, memory, identity for tools, MCP integrations, sandboxed code execution and observability, so you reach production faster with security built in, especially if you're already on that cloud. Self-hosting with LangGraph or an SDK on Kubernetes gives control, portability and custom architectures, but you build those pieces. I'd weigh model choice and lock-in, residency and networking, compliance, cost at scale and team skills. Often it's managed for standard business agents and custom for core product agents."

Likely follow-up questions

  • Capabilities to insist on? Tracing, evals, policy enforcement, scoped identity and data export.
  • Avoid lock-in? Open frameworks, MCP for tools, portable state stores.
  • Cost comparison? Model token cost dominates; compare platform fees at projected volume.
