How would you convert a string into a character array to compare its characters?

DSA: Arrays & Strings · concept · levels entry

In one line

Call word.toCharArray(), which returns a new char[] copy (strings are immutable); then sort it with Arrays.sort, compare with Arrays.equals, or rebuild a string with new String(chars); alternatives are charAt(i) loops and word.chars() streams.

Detailed explanation

A Java String is immutable: you cannot rearrange its characters in place. To sort or modify characters you need a mutable copy, and toCharArray() provides exactly that, a fresh char[] with the string's UTF-16 code units. Modifying the array never affects the original string.

Typical uses with anagrams:

  • Sorting: char[] c = word.toCharArray(); Arrays.sort(c); arranges characters in ascending order.
  • Comparing two arrays: Arrays.equals(c1, c2) compares contents. Using c1 == c2 or c1.equals(c2) compares references, so it is false for different arrays.
  • Building a key: new String(c) or String.valueOf(c) turns the sorted array back into a string, which has proper equals and hashCode and can be used as a HashMap key. c.toString() does not do this; it returns something like [C@6d06d69c.

Alternatives:

  • charAt(i) loop: iterate without allocating an array. Ideal for counting frequencies, where you never need a copy.
  • word.chars(): returns an IntStream of char values, useful in stream pipelines: word.chars().sorted() and collect back into a StringBuilder.
  • word.codePoints(): like chars() but yields full Unicode code points, needed for characters outside the Basic Multilingual Plane (emoji like 😀 are two chars, a surrogate pair). Sorting a char[] containing surrogate pairs can split them and produce invalid strings, though keys still compare consistently.

Since Java 9, strings are internally stored compactly (Latin-1 bytes when possible), but toCharArray() still gives you char values transparently.

How it works

  1. toCharArray() allocates a new array of length length().
  2. It copies each UTF-16 code unit into it.
  3. You mutate or sort the array freely.
  4. Convert back with new String(array) when you need a string.

Example

String word = "listen";
char[] chars = word.toCharArray();     // ['l','i','s','t','e','n']
Arrays.sort(chars);                    // ['e','i','l','n','s','t']
String key = new String(chars);        // "eilnst"

char[] other = "silent".toCharArray();
Arrays.sort(other);
boolean anagram = Arrays.equals(chars, other);   // true
boolean wrong   = chars.equals(other);           // false – reference comparison

// Stream alternative
String key2 = word.chars().sorted()
    .collect(StringBuilder::new, StringBuilder::appendCodePoint, StringBuilder::append)
    .toString();                        // "eilnst"

// Unicode-safe sort by code points
String key3 = word.codePoints().sorted()
    .collect(StringBuilder::new, StringBuilder::appendCodePoint, StringBuilder::append)
    .toString();

Common mistakes

  • Using chars.toString() as a key.
  • Comparing arrays with == or .equals.
  • Expecting changes to the array to modify the original string.
  • Allocating arrays when a simple charAt loop would do.

How to answer in the interview

"I'd call word.toCharArray(), which returns a new char array copy, because strings are immutable. Then I can sort it with Arrays.sort and compare two arrays with Arrays.equals, or turn it back into a string with new String(chars) to use as a map key. Alternatives are a charAt loop when I just need to read characters without copying, or word.chars() for an IntStream, for example word.chars().sorted(). For characters outside the basic plane, like emoji, I'd use codePoints instead."

Likely follow-up questions

  • Why is the sorted string a good map key? All anagrams produce the same string, and String has value-based equals and hashCode.
  • Why not use char[] as a key? Arrays use identity equality and hash codes.
  • Does toCharArray() cost anything? Yes, O(k) time and memory for the copy.
