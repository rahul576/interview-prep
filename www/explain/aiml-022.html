Explain backpropagation in simple terms.

AI/ML & GenAI · concept · levels mid, senior

In one line

Backpropagation computes the gradient of the loss for every weight by running a forward pass to get the loss, then a backward pass that applies the chain rule layer by layer from output to input, reusing intermediate results; an optimiser then updates the weights.

Detailed explanation

To improve a network we need to know, for each of possibly billions of weights, "if I nudge this weight slightly, how much does the loss change?" That number is the gradient. Computing it naively, one weight at a time, would be impossibly slow. Backpropagation computes all of them in roughly the cost of one extra forward pass.

In the forward pass, inputs flow through the layers, and the network stores intermediate values (activations). The loss function compares the prediction with the target. In the backward pass, we start from the loss and move backwards. The chain rule says that if the loss depends on a layer's output, which depends on its weights, then dLoss/dWeight = dLoss/dOutput × dOutput/dWeight. Each layer receives the gradient with respect to its output from the layer above, computes gradients for its own weights, and passes the gradient with respect to its input to the layer below. Because every layer reuses the gradient already computed for later layers, nothing is computed twice; this is dynamic programming over the computation graph.

An optimiser such as SGD with momentum or AdamW uses these gradients to update weights. Frameworks like PyTorch, TensorFlow and JAX implement reverse-mode automatic differentiation: you write only the forward computation and call backward(). Practical issues include vanishing and exploding gradients in deep networks, addressed with ReLU-family activations, careful initialisation, residual connections, normalisation layers and gradient clipping, plus memory cost from storing activations, reduced with gradient checkpointing.

How it works

  1. Forward pass: compute each layer's output and keep activations.
  2. Compute the loss from the final output and target.
  3. Compute the gradient of the loss with respect to the output.
  4. Move backwards: each layer computes its weight gradients and passes an input gradient down.
  5. The optimiser updates all weights; gradients are reset for the next batch.

Example

import torch

for x, y in loader:
    optimizer.zero_grad()
    logits = model(x)               # forward pass
    loss = loss_fn(logits, y)
    loss.backward()                 # backpropagation (autodiff)
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step()                # gradient-based update

Common mistakes

  • Confusing backpropagation (computing gradients) with gradient descent (using them).
  • Forgetting zero_grad(), so gradients accumulate across batches.
  • Assuming autodiff is numerical finite differences; it is exact up to floating point.
  • Ignoring exploding gradients in RNNs or very deep networks.

How to answer in the interview

"Training has two passes. The forward pass pushes inputs through the network to a prediction and a loss. The backward pass works out, for every weight, how much the loss would change if that weight changed, using the chain rule from the output back to the input. Each layer reuses the gradient from the layer after it, so it's efficient, roughly the cost of another forward pass. Then an optimiser like Adam updates the weights. In practice PyTorch's autograd does this automatically when I call backward."

Likely follow-up questions

  • What is the vanishing gradient problem? Gradients shrink through many layers so early layers barely learn; fixed with ReLU, residual connections, normalisation and good initialisation.
  • What is gradient clipping? Capping the gradient norm to prevent exploding updates.
  • Why does training use more memory than inference? Activations must be stored for the backward pass, plus gradients and optimiser state.
