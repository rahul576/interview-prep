Explain Predicate, Supplier, Consumer, and Function.

Java 8+ Features · concept · levels entry

In one line

Predicate<T> tests a condition via boolean test(T), Supplier<T> produces a value with no input via T get(), Consumer<T> performs an action via void accept(T), and Function<T,R> transforms via R apply(T); each offers composition methods such as and/or/negate and andThen/compose.

Detailed explanation

Predicate<T> represents a boolean-valued condition. It's used by Stream.filter, Collection.removeIf, anyMatch/allMatch/noneMatch and Optional.filter. Default methods and, or and negate combine predicates; static Predicate.not (Java 11) works nicely with method references (filter(not(String::isBlank))), and Predicate.isEqual(x) creates an equality test.

Supplier<T> represents a deferred value or factory: no input, returns a value. It enables laziness, so the value is computed only when needed: Optional.orElseGet, Objects.requireNonNullElseGet, Stream.generate, ThreadLocal.withInitial, Collectors.toCollection(TreeSet::new), and logger APIs that accept message suppliers.

Consumer<T> represents an action with side effects: it takes a value and returns nothing. Used by Iterable.forEach, Optional.ifPresent, Stream.peek. andThen chains consumers to run in sequence.

Function<T, R> represents a transformation from T to R, ideally pure. Used by Stream.map, Map.computeIfAbsent, Comparator.comparing, Collectors.groupingBy. f.andThen(g) means "f, then g"; f.compose(g) means "g, then f"; Function.identity() returns its input.

A quick memory aid by signature: Predicate T → boolean, Supplier () → T, Consumer T → void, Function T → R.

How it works

  1. Choose the interface by input/output shape.
  2. Implement its method with a lambda or method reference.
  3. Pass it to an API that calls test, get, accept or apply.
  4. Compose small instances into larger behaviour with default methods.

Example

Predicate<String> notEmpty = s -> !s.isEmpty();
Predicate<String> isEmail  = s -> s.contains("@");
Predicate<String> validEmail = notEmpty.and(isEmail);

Supplier<UUID> idGen = UUID::randomUUID;
Supplier<List<String>> listFactory = ArrayList::new;

Consumer<String> log  = s -> System.out.println("LOG " + s);
Consumer<String> save = repo::save;
Consumer<String> logAndSave = log.andThen(save);

Function<String, String>  trim   = String::trim;
Function<String, Integer> length = String::length;
Function<String, Integer> trimmedLength = trim.andThen(length);

inputs.stream()
      .map(trim)
      .filter(validEmail)
      .forEach(logAndSave);

String id = Optional.ofNullable(requestId).orElseGet(() -> idGen.get().toString());

Common mistakes

  • Confusing andThen and compose order.
  • Using Function for side effects or Consumer when a result is needed.
  • Writing orElse(supplier.get()), losing laziness.
  • Combining predicates with lambdas instead of and/or.

How to answer in the interview

"Predicate represents a condition: its test method returns a boolean, it's used in filter, and predicates combine with and, or and negate. Supplier produces a value without input through get, useful for lazy creation, factories and orElseGet. Consumer performs an action on a value through accept and returns nothing, as in forEach or logging, and andThen chains consumers. Function transforms a value with apply, as in map, and composes with andThen and compose. For example, a Predicate notEmpty and a Function String::length."

Likely follow-up questions

  • How would you combine two predicates? p1.and(p2), p1.or(p2), or p1.negate().
  • Difference between andThen and compose? f.andThen(g) applies f first; f.compose(g) applies g first.
  • What's Predicate.not for? Negating method references concisely (Java 11).
