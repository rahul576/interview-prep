What is the difference between docker run -it and docker run -d?

Docker · concept · levels entry

In one line

-i keeps STDIN open and -t allocates a pseudo-terminal, so -it gives an interactive session in the foreground; -d runs the container detached in the background and prints its ID, after which you use logs, exec and attach to work with it.

Detailed explanation

-i (interactive) connects your terminal's standard input to the container's main process and keeps it open, so you can type into it or pipe data in (cat dump.sql | docker run -i postgres psql …). -t (tty) allocates a pseudo-terminal, which gives you a prompt, line editing, colours and correct handling of control characters. Together, docker run -it ubuntu bash drops you into a shell inside a fresh container, ideal for exploring an image, testing commands or debugging. The shell is the main process, so exiting the shell stops the container.

By default docker run without -d runs in the foreground: your terminal shows the container's output and waits until it exits. -d (detached) starts the container in the background and immediately returns the container ID. This is how you run long-lived services such as web servers, databases or brokers.

Working with a detached container:

  • docker logs -f name follows its output.
  • docker exec -it name sh starts an extra shell for debugging without touching the main process.
  • docker attach name connects your terminal to the main process's streams.

You can combine flags: -dit starts a container in the background with stdin and a TTY allocated, so a shell-based container does not exit immediately and you can attach later. Avoid -t in scripts and CI where there is no terminal, because it fails with "the input device is not a TTY"; use -i alone when piping.

Ctrl+C in an -it session sends SIGINT to the main process; if it exits, the container stops. Ctrl+P Ctrl+Q detaches while leaving it running.

How it works

  1. docker run -it image cmd → foreground, stdin + TTY attached.
  2. docker run -d image → background, returns ID.
  3. logs, exec, attach interact with detached containers.
  4. Main process exits → container exits regardless of mode.

Example

docker run -it --rm python:3.13-slim python         # interactive REPL, removed on exit
docker run -d --name cache -p 6379:6379 redis:7     # background service
docker logs -f --tail 20 cache
docker exec -it cache redis-cli ping
docker run -dit --name box alpine sh                # background shell
docker attach box                                   # Ctrl+P Ctrl+Q to detach
echo "select 1;" | docker run -i --rm postgres:17 psql -h db -U app   # -i only, no TTY

Common mistakes

  • docker run -d ubuntu and wondering why it exits immediately (bash has no TTY and finishes).
  • Using -t in CI pipelines.
  • Debugging a service by attaching and pressing Ctrl+C, killing it.
  • Forgetting --rm for throwaway interactive containers.

How to answer in the interview

"-i keeps standard input open and -t allocates a pseudo-terminal, so docker run -it ubuntu bash gives me an interactive shell, great for exploring an image or debugging; when I exit the shell, the container stops because the shell was its main process. -d runs the container detached in the background and prints its ID, which is how I run services like a web server or database. For a detached container I read output with docker logs -f, open a shell with docker exec -it, or attach to the main process with docker attach. I can combine them as -dit."

Likely follow-up questions

  • Ctrl+C in docker run -it? SIGINT goes to the main process; if it exits, the container stops.
  • How to detach without stopping? Ctrl+P then Ctrl+Q (needs -it).
  • Why "the input device is not a TTY"? -t used without a terminal, e.g. in CI.
