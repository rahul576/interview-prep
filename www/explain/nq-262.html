How would you calculate total revenue using an aggregate function?

Databases & SQL · concept · levels entry

In one line

Use the aggregate SUM(o.amount) together with GROUP BY for per-group totals, wrap it in COALESCE(..., 0) when groups can be empty, filter out cancelled orders, and store money as DECIMAL/NUMERIC.

Detailed explanation

An aggregate function takes many rows and returns one value. SUM(o.amount) adds up the amount of every row in a group; without GROUP BY the whole result is one group, giving one grand total.

Important details:

  • NULL handling: SUM ignores NULL values. If every value in a group is NULL, or there are no rows (for example an unmatched customer from a LEFT JOIN), the result is NULL, not 0. COALESCE(SUM(o.amount), 0) fixes that.
  • Line items: if revenue lives in an order_items table, compute SUM(oi.quantity * oi.unit_price), and decide whether discounts, tax and shipping are included.
  • Business rules: revenue usually excludes cancelled, failed or refunded orders, so filter with WHERE o.status = 'COMPLETED' (or subtract refunds explicitly). Agree the definition with the business.
  • Data types: money must be DECIMAL(12,2) or NUMERIC, never FLOAT/DOUBLE, because binary floating point cannot represent values like 0.10 exactly and errors accumulate across millions of rows. In Java, map it to BigDecimal.
  • Currency: never sum amounts in different currencies; group by currency or convert first.

How it works

  1. FROM and JOIN produce the rows.
  2. WHERE removes rows that should not count (cancelled orders).
  3. GROUP BY splits rows into groups.
  4. SUM is evaluated per group, skipping NULLs.
  5. HAVING can filter on the total; SELECT returns it with an alias.

Example

SELECT c.customer_id, c.name,
       EXTRACT(YEAR FROM o.order_date) AS order_year,
       COALESCE(SUM(oi.quantity * oi.unit_price), 0) AS total_revenue,
       COUNT(DISTINCT o.order_id)                     AS orders,
       AVG(o.amount)                                  AS avg_order_value
FROM customers c
JOIN orders o       ON o.customer_id = c.customer_id
JOIN order_items oi ON oi.order_id = o.order_id
WHERE o.status = 'COMPLETED'
GROUP BY c.customer_id, c.name, EXTRACT(YEAR FROM o.order_date);

Note AVG(o.amount) here would be wrong because each order repeats per item; compute it from a pre-aggregated subquery instead.

Common mistakes

  • Storing or summing money as floating point.
  • Expecting SUM to return 0 for empty groups.
  • Summing o.amount after joining line items, which double-counts.
  • Including cancelled or refunded orders.
  • Mixing currencies in one sum.

How to answer in the interview

"I'd use SUM(o.amount) AS total_revenue with a GROUP BY for one total per customer and year. SUM skips NULLs and returns NULL for an empty group, so with a LEFT JOIN I'd wrap it in COALESCE to show zero. If revenue comes from line items I'd sum quantity times unit price, and I'd apply the business rules, like excluding cancelled or refunded orders. Money columns should be DECIMAL, mapped to BigDecimal in Java, never floating point."

Likely follow-up questions

  • What other aggregates help in this report? COUNT for order count, AVG for average order value, MIN/MAX for first and last order dates.
  • **What is the difference between COUNT() and COUNT(column)?* COUNT(*) counts rows; COUNT(column) skips NULLs.
  • How do you filter on the total? Use HAVING SUM(o.amount) > 10000.
