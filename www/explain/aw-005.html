What does an IAM policy document look like? Explain Effect, Action, Resource and Condition.

Cloud (AWS) · concept · levels entry

In one line

An IAM policy is a JSON document with a Version (2012-10-17) and a list of Statements; each statement has an Effect (Allow or Deny), the Actions (API operations like s3:GetObject), the Resources (ARNs) and an optional Condition that adds constraints such as source IP, MFA or tags.

Detailed explanation

Every AWS API call is checked against policies. A policy statement reads like a sentence: "Allow these actions on these resources when these conditions are true."

Version should always be "2012-10-17", the current policy language version; older or missing versions disable features such as policy variables. Effect is Allow or Deny. Everything is implicitly denied by default, an Allow grants access, and an explicit Deny always wins over any allow, from any policy.

Action lists API operations as service:Operation, for example s3:GetObject, ec2:StartInstances or dynamodb:Query. Wildcards work (s3:Get, s3:) but broad wildcards are a common source of over-permission. NotAction inverts the list and should be used carefully.

Resource identifies what the actions apply to by ARN, such as arn:aws:s3:::reports-bucket/ for objects in a bucket or arn:aws:dynamodb:eu-west-1:123456789012:table/Orders. Note that bucket-level actions (s3:ListBucket) need the bucket ARN, while object actions need bucket/.

Condition adds rules using operators and condition keys: aws:SourceIp, aws:MultiFactorAuthPresent, aws:PrincipalTag/team, aws:ResourceTag/..., aws:RequestedRegion, s3:prefix and many service-specific keys. Conditions enable attribute-based access control and guardrails like "deny outside eu-west-1".

Resource-based policies (S3 bucket policies, KMS key policies, SQS queue policies, role trust policies) also have a Principal element saying who the statement applies to, because they are attached to the resource rather than to an identity. Validate policies with IAM Access Analyzer and prefer specific actions and resources over *.

How it works

  1. A request arrives with principal, action, resource and context.
  2. AWS gathers identity policies, resource policies, permission boundaries, session policies and SCPs.
  3. Any matching explicit Deny: request denied.
  4. Otherwise a matching Allow is needed in each applicable layer.
  5. No Allow: implicit deny.

Example

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ReadReports",
      "Effect": "Allow",
      "Action": ["s3:GetObject"],
      "Resource": "arn:aws:s3:::reports-bucket/finance/*",
      "Condition": {
        "IpAddress": { "aws:SourceIp": "203.0.113.0/24" },
        "Bool": { "aws:MultiFactorAuthPresent": "true" }
      }
    },
    {
      "Sid": "ListFinancePrefix",
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::reports-bucket",
      "Condition": { "StringLike": { "s3:prefix": "finance/*" } }
    }
  ]
}

Common mistakes

  • "Action": "", "Resource": "" for convenience.
  • Using the object ARN for s3:ListBucket (it needs the bucket ARN).
  • Forgetting that an explicit Deny anywhere overrides allows.
  • Omitting Version, which breaks policy variables.

How to answer in the interview

"A policy is JSON with a Version, normally 2012-10-17, and a list of statements. Each statement has an Effect, Allow or Deny; Actions, the API operations like s3:GetObject; Resources, the ARNs it applies to; and optionally a Condition, for example only from our office IP range, only with MFA, or only for resources tagged with my team. Everything is denied by default, an Allow grants access and an explicit Deny always wins. Resource-based policies like bucket policies also have a Principal. I keep actions and resources specific and validate with IAM Access Analyzer."

Likely follow-up questions

  • What does an explicit Deny do against an Allow? It always wins; the request is denied.
  • What is a policy variable? A placeholder like ${aws:username} resolved at evaluation time.
  • How do SCPs fit in? They set the maximum permissions in an account; they never grant anything themselves.
