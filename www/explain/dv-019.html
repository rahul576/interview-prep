What is Git, and what are the basic commands every engineer uses?

Git · concept · levels entry

In one line

Git is a distributed version control system: every clone has the full history, changes flow from the working directory to the staging area to the repository, and daily work uses status, add, commit, diff, log, clone, pull, push, branch, switch and merge.

Detailed explanation

Version control records who changed what and why, lets you go back to earlier versions and lets people work in parallel. Git is distributed: unlike centralised systems such as SVN, every clone holds the complete history, so you can commit and branch offline and collaborate by exchanging commits with remotes (GitHub, GitLab, Azure Repos), named origin by default.

Git has three areas. The working directory is the files you edit. The staging area (index) is where git add collects exactly what goes into the next commit. The repository (.git) stores commits: snapshots with author, timestamp, message and parent, each identified by a SHA hash.

A branch is just a movable pointer to a commit, so branching is cheap. You branch per feature, then merge back into main, usually via a pull request.

Daily commands: git status (what changed and is staged), git diff (--staged for staged lines), git log --oneline --graph, git clone, git pull (fetch and integrate), git push, git branch, git switch (clearer than checkout) and git merge. A .gitignore keeps build outputs and secrets out.

How it works

  1. git clone the repository.
  2. git switch -c feature/login to start a branch.
  3. Edit files, check with git status and git diff.
  4. git add the relevant files, then git commit -m "message".
  5. git pull to integrate others' work, git push -u origin feature/login.
  6. Open a pull request and merge into main.

Example

git clone https://github.com/acme/shop.git && cd shop
git switch -c feature/discount-code
# ...edit src/cart.js...
git status
git diff
git add src/cart.js
git commit -m "Add discount code support to cart"
git push -u origin feature/discount-code
git log --oneline --graph -5

Common mistakes

  • git add . without checking, committing secrets or build files.
  • Vague commit messages like "fix" or "changes".
  • Working directly on main instead of a branch.
  • Confusing Git (the tool) with GitHub (a hosting service).
  • Huge commits mixing unrelated changes.

How to answer in the interview

"Git is a distributed version control system, so every developer has the full history locally and we share changes through a remote like GitHub. Files move through three areas: I edit in the working directory, git add stages the changes I want, and git commit records a snapshot with a message. Day to day I use git status and git diff to see what changed, git log for history, git pull to get teammates' work and git push to publish mine. For each feature I create a branch with git switch -c, and when it's ready it's merged into main, usually via a pull request."

Likely follow-up questions

  • fetch vs pull? fetch downloads remote commits without changing your branch; pull is fetch plus merge or rebase.
  • What is HEAD? A pointer to the commit or branch you currently have checked out.
  • merge vs rebase? Merge joins histories with a merge commit; rebase replays your commits on top for a linear history.
