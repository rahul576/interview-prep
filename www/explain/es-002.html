What are mappings and analyzers? Explain the difference between text and keyword fields.

Elasticsearch · concept · levels entry, mid

In one line

A mapping is the index schema (field names and types). An analyzer (character filters + tokenizer + token filters) turns text into searchable terms. text fields are analysed for full-text search, while keyword fields keep the exact value for filters, sorting and aggregations. Map both with a multi-field when you need both, and prefer explicit mappings to dynamic ones.

Detailed explanation

Mappings. These declare each field's type: text, keyword, long, date, boolean, nested, dense_vector, and so on. Elasticsearch can dynamically map new fields by guessing (a JSON string becomes text plus a .keyword sub-field). That's handy in development, but risky in production. Guesses can be wrong (a zip code becomes a number), the first document "wins" the type, and arbitrary keys can cause a mapping explosion of thousands of fields, which bloats the cluster state (there is a default limit of 1000 fields per index). Use explicit mappings, index templates, and dynamic: strict or false. An existing field's type can't be changed in place. You reindex.

Analyzers run at index time (and usually at query time on the query string):

  1. Character filters, such as stripping HTML or mapping characters.
  2. A tokenizer splits text into tokens (standard, whitespace, ngram).
  3. Token filters modify tokens: lowercase, stop, stemmer (running becomes run), synonym, asciifolding.

The standard analyzer (lowercase plus Unicode word splitting) is the default. Language analyzers (english) add stemming and stop words.

text vs keyword:

  • "Order Shipped To Pune" as text becomes [order, shipped, to, pune]. match queries find "shipped" and relevance is scored.
  • As keyword it stays the single exact term "Order Shipped To Pune". It suits term filters, sorting and terms aggregations. It is case-sensitive unless you add a normalizer.

Use keyword for ids, emails, status codes, tags and enums. Use text for names, titles, descriptions and messages. A multi-field gives both: name (text) and name.raw (keyword).

How it works

  1. Define an index template with the mappings and analyzers.
  2. Indexing: text fields go through the analyzer into terms in the inverted index. Keyword fields go in as a single term plus doc values.
  3. match analyses the query text the same way and finds the terms.
  4. term does not analyse the input, so it is an exact lookup.
  5. To change a mapping: create a new index and use _reindex plus an alias swap.

Example

PUT /customers
{
  "settings": { "analysis": { "normalizer": { "lc": { "type": "custom", "filter": ["lowercase"] } } } },
  "mappings": {
    "dynamic": "strict",
    "properties": {
      "name":   { "type": "text", "analyzer": "english",
                  "fields": { "raw": { "type": "keyword" } } },
      "email":  { "type": "keyword", "normalizer": "lc" },
      "status": { "type": "keyword" },
      "joined": { "type": "date" }
    }
  }
}

GET /_analyze
{ "analyzer": "english", "text": "Running Shoes" }      // -> ["run", "shoe"]

Common mistakes

  • A term query on a text field: "Shipped" won't match the stored term "shipped".
  • Aggregating on text fields (disabled by default, and fielddata is memory-hungry).
  • Leaving dynamic mapping on for user-generated keys.
  • Expecting a mapping type change without a reindex.

How to answer in the interview

"A mapping is the schema: it defines field types. A text field is analysed for full-text search. An analyzer, which is a tokenizer plus token filters, splits it into lowercase terms and may remove stop words or apply stemming, so 'Running Shoes' can match 'run'. A keyword field is stored as a single exact value and is used for exact filters, sorting and aggregations, such as status, email or SKU. Often I map a field as both with a multi-field. In production I use explicit mappings and templates rather than dynamic mapping, because guessed types and mapping explosions cause real problems, and changing a type means reindexing."

Likely follow-up questions

  • Why does a term query on a text field return nothing? The stored terms are analysed (lowercased or stemmed), and term doesn't analyse the input.
  • Case-insensitive keyword? Use a normalizer with lowercase.
  • Autocomplete field? search_as_you_type, edge n-grams, or the completion suggester.
