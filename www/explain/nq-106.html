What is the time complexity of comparing each string with every other string?

DSA: Arrays & Strings · concept · levels mid

In one line

Comparing every string with every other means n(n−1)/2 pairs, i.e. O(n²) comparisons; each anagram check costs O(k) (counting) or O(k log k) (sorting), so the total is O(n²·k) or O(n²·k log k).

Detailed explanation

The brute-force grouping algorithm takes each word and compares it with every later word to see whether they are anagrams. The number of unordered pairs among n items is n(n−1)/2: for 4 words, 6 pairs; for 1,000 words, about 500,000; for 10,000 words, about 50 million. Dropping constants gives O(n²) comparisons.

Each comparison is not free. Checking whether two words of length up to k are anagrams costs:

  • O(k) with a frequency count (after an O(1) length check), or
  • O(k log k) if you sort both words inside every comparison.

So the total is O(n²·k) or O(n²·k log k). A smarter brute force sorts each word once up front (O(n·k log k)) and then compares sorted forms in O(k), giving O(n·k log k + n²·k), still dominated by the quadratic term.

The brute force also needs bookkeeping: a visited boolean array so a word already placed in a group is not used to start another group, and logic to collect groups. Space is O(n) for that array plus the output.

Why it matters: with the hashing approach, 10,000 words means 10,000 key computations instead of 50 million comparisons; at 1,000,000 words, the brute force needs about 5 × 10¹¹ comparisons (hours), the hashing approach a few million operations (well under a second). This is the standard justification for moving from pairwise comparison to grouping by a canonical key: a quadratic algorithm becomes linear in n.

How it works

  1. For i from 0 to n−1, skip if visited; start a group with word i.
  2. For j from i+1 to n−1, if not visited and anagram(i, j), add j and mark visited.
  3. Each anagram check costs O(k) or O(k log k).
  4. Total pairs n(n−1)/2 gives O(n²) checks.
  5. Multiply by the per-check cost.

Example

// Brute force: O(n^2 · k)
static List<List<String>> groupBrute(String[] w) {
    boolean[] used = new boolean[w.length];
    List<List<String>> out = new ArrayList<>();
    for (int i = 0; i < w.length; i++) {
        if (used[i]) continue;
        List<String> g = new ArrayList<>(List.of(w[i]));
        used[i] = true;
        for (int j = i + 1; j < w.length; j++) {
            if (!used[j] && isAnagram(w[i], w[j])) {   // O(k)
                g.add(w[j]);
                used[j] = true;
            }
        }
        out.add(g);
    }
    return out;
}

Common mistakes

  • Saying O(n²) without the per-comparison cost k.
  • Counting n² pairs instead of n(n−1)/2 (fine for Big-O, but know the exact count).
  • Forgetting the visited array, producing duplicate groups.
  • Re-sorting both words in every comparison.

How to answer in the interview

"Comparing every string with every other string means n times n minus one over two pairs, which is O(n²) comparisons. Each anagram check costs O(k) with counting or O(k log k) with sorting, so the total is O(n²·k) or O(n²·k log k). The brute force also needs a visited array so a word isn't grouped twice. For ten thousand words that's about fifty million comparisons, versus ten thousand key computations in the hashing approach, which is why grouping by a key is preferred."

Likely follow-up questions

  • How does the brute force track grouped words? A boolean visited array, skipping words already assigned.
  • Can you speed up the brute force? Pre-sort each word once and check lengths first, but it stays quadratic.
  • When is brute force acceptable? For tiny inputs, like a handful of words.
