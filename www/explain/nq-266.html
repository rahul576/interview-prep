What is the difference between GROUP BY and ORDER BY?

Databases & SQL · concept · levels entry

In one line

GROUP BY combines rows with the same key into groups for aggregation and reduces the row count; ORDER BY only sorts the final result and never changes how many rows there are.

Detailed explanation

These two clauses are often confused because both take a list of columns, but they do completely different jobs.

GROUP BY changes the shape of the result. Rows sharing the same values in the listed columns become one group, and you get one output row per group, typically with aggregates like SUM, COUNT or AVG. A thousand order rows might become fifty customer-year rows. Once you group, the SELECT may only contain grouped columns and aggregates. HAVING then filters the groups.

ORDER BY changes only the sequence. It takes whatever rows the query produced, grouped or not, and sorts them ascending or descending by columns, expressions or aliases. Row count and values are untouched.

A frequent misconception is that GROUP BY sorts the output. Some engines used to return grouped rows in key order because they grouped by sorting, and old MySQL versions even sorted implicitly, but that is not guaranteed: hash aggregation, parallel plans or a new version can return groups in any order. MySQL 8.0 removed implicit GROUP BY sorting. If you need sorted groups, write both clauses.

They also run at different stages of logical processing: GROUP BY runs before SELECT, ORDER BY runs after it, which is why ORDER BY can use select aliases and GROUP BY generally cannot.

How it works

  1. FROM/JOIN and WHERE produce rows.
  2. GROUP BY forms groups; aggregates are computed.
  3. HAVING filters groups.
  4. SELECT produces output columns and aliases.
  5. ORDER BY sorts the output; LIMIT applies last.

Example

-- GROUP BY: 1 row per customer
SELECT customer_id, COUNT(*) AS orders, SUM(amount) AS revenue
FROM orders
GROUP BY customer_id
HAVING COUNT(*) >= 3
ORDER BY revenue DESC;   -- ORDER BY: sorts those rows

-- ORDER BY alone: same number of rows as the table
SELECT order_id, customer_id, amount
FROM orders
ORDER BY order_date DESC;

Common mistakes

  • Assuming GROUP BY output is sorted.
  • Using ORDER BY expecting it to remove duplicates.
  • Filtering aggregates in WHERE instead of HAVING.
  • Grouping by a unique column, which aggregates nothing.

How to answer in the interview

"GROUP BY combines rows with the same values in the listed columns into one group so I can compute aggregates like SUM or COUNT per group. It reduces the number of rows, and HAVING filters the groups. ORDER BY just sorts the final rows, ascending or descending, without changing how many there are. GROUP BY doesn't guarantee any order, so if I want sorted groups I still add ORDER BY."

Likely follow-up questions

  • What is the difference between WHERE and HAVING? WHERE filters individual rows before grouping; HAVING filters groups using aggregates.
  • Is SELECT DISTINCT the same as GROUP BY? Without aggregates they give the same rows; GROUP BY is needed for aggregates.
  • Can you ORDER BY an aggregate? Yes, for example ORDER BY SUM(amount) DESC.
