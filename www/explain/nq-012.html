What are sequenced collections in Java 21?

Modern Java (11-21) · concept · levels mid, senior

In one line

Java 21 added SequencedCollection, SequencedSet and SequencedMap, giving every collection with a defined encounter order a uniform API: getFirst, getLast, addFirst, addLast, removeFirst, removeLast and a reversed() view.

Detailed explanation

Many collections have a defined order (List, Deque, LinkedHashSet, TreeSet, LinkedHashMap, TreeMap), but before Java 21 they shared no type expressing it, and accessing the ends was inconsistent:

  • List: list.get(0) and list.get(list.size() - 1);
  • Deque: getFirst() / getLast();
  • SortedSet: first() / last();
  • LinkedHashSet: iterate to the end, no direct way;
  • reversing: Collections.reverse (mutates) or descendingIterator, depending on the type.

JEP 431 retrofitted three interfaces into the hierarchy:

  • SequencedCollection<E> extends Collection: addFirst, addLast, getFirst, getLast, removeFirst, removeLast, reversed(). List and Deque extend it.
  • SequencedSet<E>: a sequenced collection with no duplicates; LinkedHashSet implements it and SortedSet/NavigableSet (TreeSet) extend it.
  • SequencedMap<K,V>: firstEntry, lastEntry, pollFirstEntry, pollLastEntry, putFirst, putLast, reversed(), and sequencedKeySet(), sequencedValues(), sequencedEntrySet(). LinkedHashMap implements it and SortedMap extends it.

reversed() returns a view, not a copy: changes through it affect the original. Operations that make no sense throw: addFirst on a TreeSet throws UnsupportedOperationException because the sort order decides position, and on unmodifiable lists modification methods throw as usual. getFirst on an empty collection throws NoSuchElementException.

HashSet and HashMap have no defined order, so they do not implement these interfaces. Now you can write methods that accept "any ordered collection" with SequencedCollection as the parameter type.

How it works

  1. Ordered collections now implement the sequenced interfaces.
  2. Default methods provide the end-access operations.
  3. reversed() wraps the collection as a reverse-ordered view.
  4. Unsupported positional changes throw for sorted or unmodifiable types.

Example

List<String> steps = new ArrayList<>(List.of("cart", "pay", "ship"));
steps.getFirst();            // "cart"
steps.getLast();             // "ship"
steps.addFirst("login");
for (String s : steps.reversed()) System.out.println(s);

LinkedHashMap<String, Integer> recent = new LinkedHashMap<>();
recent.put("a", 1); recent.put("b", 2);
recent.firstEntry();         // a=1
recent.putFirst("z", 0);     // move/insert at the front
recent.pollLastEntry();      // removes b=2

void printEnds(SequencedCollection<?> c) {
    System.out.println(c.getFirst() + " .. " + c.getLast());
}

Common mistakes

  • Assuming reversed() returns an independent copy.
  • Calling addFirst on a TreeSet.
  • Expecting HashSet or HashMap to offer these methods.
  • Forgetting the empty-collection exception.

How to answer in the interview

"Before Java 21, ordered collections had no shared API for their ends: for a List you wrote get(size - 1), for a Deque getLast, for a LinkedHashSet you had to iterate. Java 21 added SequencedCollection, SequencedSet and SequencedMap. They provide getFirst, getLast, addFirst, addLast, removeFirst, removeLast and reversed, which returns a reversed view; maps get firstEntry, lastEntry, pollFirstEntry, putFirst and sequenced key and entry views. List, Deque, LinkedHashSet, LinkedHashMap, TreeSet and TreeMap implement them, so I can write code that accepts any ordered collection. HashSet and HashMap don't, because they have no defined order."

Likely follow-up questions

  • Why does HashSet not implement SequencedSet? It has no defined encounter order.
  • What does putFirst do on a LinkedHashMap? Inserts or moves the mapping to the front.
  • Is reversed() expensive? No, it's a lightweight view.
