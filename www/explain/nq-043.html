What is the difference between map() and mapToDouble()?

Java 8+ Features · concept · levels entry, mid

In one line

map returns a Stream<R> of objects, so numbers are boxed (Double); mapToDouble returns a DoubleStream of primitives, avoiding boxing and offering numeric operations like sum(), average() and summaryStatistics().

Detailed explanation

Java generics only work with reference types, so a Stream<Double> holds Double objects, each a separate heap allocation with a header and a reference. When you write products.stream().map(Product::getPrice), every primitive double price is autoboxed into a Double. Summing them then needs reduce(0.0, Double::sum), which unboxes and reboxes repeatedly.

Java 8 added three primitive specialisations: IntStream, LongStream and DoubleStream. mapToDouble(ToDoubleFunction<T>) converts an object stream into a DoubleStream, where elements are plain double values with no boxing. These streams provide numeric terminal operations directly: sum(), average(), min(), max(), count() and summaryStatistics(), which returns count, sum, min, average and max in one pass. mapToInt and mapToLong are the equivalents for int and long, and IntStream.range creates primitive ranges.

average(), min() and max() return OptionalDouble (or OptionalInt), because an empty stream has no average or minimum. sum() returns 0.0 for an empty stream, because zero is a valid identity for addition.

To go back to objects, use boxed() (gives Stream<Double>) or mapToObj(...) to build any object from the primitive. The performance difference matters on large data or hot paths: fewer allocations mean less GC pressure. For money, note that double is not suitable for exact currency; BigDecimal with map and reduce(BigDecimal.ZERO, BigDecimal::add) is the correct choice there.

How it works

  1. stream() gives a Stream<Product>.
  2. map(Product::getPrice) yields Stream<Double> with a boxed object per element.
  3. mapToDouble(Product::getPrice) yields DoubleStream with raw double values.
  4. Numeric terminal operations (sum, average) run without unboxing.
  5. boxed() or mapToObj() converts back to an object stream when needed.

Example

record Product(String name, double price) {}

double total = products.stream()
    .mapToDouble(Product::price)
    .sum();

OptionalDouble avg = products.stream()
    .mapToDouble(Product::price)
    .average();                 // empty list -> OptionalDouble.empty()

DoubleSummaryStatistics stats = products.stream()
    .mapToDouble(Product::price)
    .summaryStatistics();       // count, sum, min, avg, max in one pass

// Boxed equivalent (more allocation, clumsier):
double total2 = products.stream()
    .map(Product::price)
    .reduce(0.0, Double::sum);

List<String> labels = IntStream.rangeClosed(1, 3)
    .mapToObj(i -> "Item " + i)
    .toList();

Common mistakes

  • Calling .getAsDouble() on average() without handling the empty case.
  • Using double for currency where rounding errors matter.
  • Boxing with map and then unboxing in reduce on large data sets.
  • Forgetting boxed() before collect(Collectors.toList()) on a primitive stream.

How to answer in the interview

"map returns a Stream of objects, so mapping prices with map gives a Stream of Double, which means boxing every value. mapToDouble takes a ToDoubleFunction and returns a DoubleStream of primitive doubles, so there is no boxing, and it gives numeric operations directly: sum, average, min, max and summaryStatistics. So the idiomatic way to total prices is mapToDouble then sum. mapToInt and mapToLong are the int and long versions, and I can go back to objects with boxed or mapToObj. average returns an OptionalDouble because an empty stream has no average. For real money I would use BigDecimal instead of double."

Likely follow-up questions

  • Why does average() return an OptionalDouble? An empty stream has no meaningful average, so absence is made explicit instead of returning NaN or zero.
  • Why is there no CharStream or FloatStream? The designers limited specialisations to int, long and double; chars() returns an IntStream.
  • How do you collect a DoubleStream into a list? boxed().toList() or collect(...) with a supplier, accumulator and combiner.
