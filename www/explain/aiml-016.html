What is the difference between model parameters and hyperparameters?

AI/ML & GenAI · concept · levels entry, mid

In one line

Parameters are values the model learns from data (weights, biases, split thresholds); hyperparameters are settings you choose before training (learning rate, depth, number of layers) and tune on validation data.

Detailed explanation

Parameters are the internal values adjusted by the training algorithm to fit the data: the coefficients of a linear or logistic regression, the weights and biases of a neural network, the split features, thresholds and leaf values of a decision tree, or the centroids of k-means. After training, the parameters are the model; saving a model means saving them. A large language model's "70 billion parameters" are its learned weights.

Hyperparameters control how learning happens or how complex the model can be, and the training algorithm does not learn them directly. Examples: learning rate, batch size, number of epochs, optimiser choice, number of layers and units, dropout rate, regularisation strength (C or alpha), maximum tree depth, number of trees, min samples per leaf, and k in k-means or k-NN. They shape the bias-variance trade-off: a deeper tree or weaker regularisation lowers bias but raises variance.

Hyperparameters are tuned by training several models and comparing them on validation data or with cross-validation. Methods include grid search (exhaustive, expensive), random search (usually more efficient in high dimensions), Bayesian optimisation (tools like Optuna model which settings look promising) and early-stopping schedulers like Hyperband/ASHA. The test set stays untouched until the end, otherwise your reported score is optimistically biased. With LLMs, generation settings such as temperature, top-p and max tokens are sometimes loosely called hyperparameters, though strictly they are inference-time decoding settings, not part of training.

How it works

  1. Split data into training, validation and test (or use cross-validation).
  2. Define a search space of hyperparameters.
  3. For each candidate, train the model, which learns its parameters.
  4. Score each candidate on validation data.
  5. Pick the best configuration, retrain if needed, and evaluate once on the test set.

Example

import optuna
from sklearn.model_selection import cross_val_score
from sklearn.ensemble import RandomForestClassifier

def objective(trial):
    model = RandomForestClassifier(
        n_estimators=trial.suggest_int("n_estimators", 100, 800),
        max_depth=trial.suggest_int("max_depth", 3, 20),
        min_samples_leaf=trial.suggest_int("min_samples_leaf", 1, 20))

Common mistakes

  • Tuning hyperparameters on the test set.
  • Grid-searching many dimensions when random or Bayesian search is cheaper.
  • Calling the number of trees or layers a "parameter".
  • Ignoring that the best settings change when data volume changes.

How to answer in the interview

"Parameters are what the model learns from the data during training, like the weights of a network or the split points of a tree. Hyperparameters are the knobs I set before training that control learning and complexity, like learning rate, batch size, tree depth or regularisation strength. I tune them by comparing models on validation data or cross-validation, using random search or Bayesian optimisation with something like Optuna, and only touch the test set once at the end."

Likely follow-up questions

  • Why is tuning on the test set a mistake? You overfit to it, so the final score no longer estimates real-world performance.
  • Random search versus grid search? Random explores important dimensions better for the same budget.
  • Is temperature a hyperparameter? Loosely, but it is an inference-time decoding setting, not learned or used in training.
