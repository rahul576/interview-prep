What is Amazon EventBridge, and how does it differ from SNS?

Cloud (AWS) · concept · levels mid

In one line

EventBridge is a serverless event bus: producers, AWS services and SaaS partners publish JSON events, rules match them with content-based patterns and route them to targets, with extras like schema registry, archive and replay, Pipes and Scheduler; SNS is simpler, faster pub/sub fan-out with attribute or payload filtering.

Detailed explanation

Every account has a default event bus that receives events from AWS services, such as EC2 state changes, ECS task stops, CodePipeline failures, or GuardDuty findings. You can create custom buses for your application events and partner buses for SaaS sources like Zendesk or Datadog. Events follow a common envelope: source, detail-type, time, account and a free-form detail.

Rules contain event patterns that can match on any field, including nested values, prefixes, numeric ranges, exists checks and anything-but, for example orders from com.shop.orders with amount above 1,000. Each rule can send to up to five targets: Lambda, SQS, SNS, Step Functions, Kinesis, ECS tasks, another bus (including cross-account or cross-region), or API destinations for any HTTP endpoint. Input transformers reshape the payload, and targets get retries and their own DLQ.

Extra features: the schema registry discovers event structures and generates code bindings; archive and replay stores events and re-sends them to a bus later; EventBridge Pipes connect a source such as SQS, Kinesis or DynamoDB Streams to a target with filtering and enrichment; EventBridge Scheduler runs millions of one-off or cron schedules with time zones.

SNS is a topic-based pub/sub service: higher throughput, lower latency, fan-out to SQS, Lambda, HTTP, email, SMS and mobile push. It supports subscription filter policies on message attributes or the payload, and FIFO topics, but lacks the bus model, SaaS integration, schema registry and replay. A common pattern is EventBridge for routing domain events between teams and SNS for high-volume fan-out.

How it works

  1. Producer calls PutEvents on a custom bus.
  2. EventBridge evaluates all rules on that bus.
  3. Matching rules transform the input and deliver to targets.
  4. Failed deliveries retry with backoff, then go to the target's DLQ.
  5. An archive keeps a copy for later replay.

Example

{
  "source": ["com.shop.orders"],
  "detail-type": ["OrderPlaced"],
  "detail": {
    "amount": [{"numeric": [">", 1000]}],
    "country": [{"anything-but": ["US"]}]
  }
}
aws events start-replay --replay-name orders-last-week \
  --event-source-arn arn:aws:events:eu-west-1:111122223333:archive/orders \
  --event-start-time 2026-11-10T00:00:00Z --event-end-time 2026-11-17T00:00:00Z \
  --destination Arn=arn:aws:events:eu-west-1:111122223333:event-bus/orders

Common mistakes

  • Using EventBridge for very high-volume, latency-sensitive streams where Kinesis or SNS fit better.
  • No DLQ on targets, so failed deliveries are lost after retries.
  • Replaying into a bus whose rules are not idempotent.
  • Huge payloads; keep events small and reference data in S3.

How to answer in the interview

"EventBridge is a serverless event bus. My services put JSON events on a custom bus, AWS services publish to the default bus, and SaaS partners can send events too. Rules match content-based patterns on any field and route to targets like Lambda, SQS, Step Functions, API destinations or another bus, with input transformation. It adds a schema registry, archive and replay, Pipes and Scheduler. SNS is simpler pub/sub with higher throughput and lower latency for plain fan-out, with filter policies, so I use it for high-volume fan-out and EventBridge for routing domain events."

Likely follow-up questions

  • How would you replay last week's events into a new consumer? Create a rule for the new consumer, then start a replay from the archive for that time range.
  • How send events to another account? Rule target is the other account's bus, allowed by its resource policy.
  • EventBridge or SQS? EventBridge routes events; SQS buffers work for one consumer. Often combine both.
