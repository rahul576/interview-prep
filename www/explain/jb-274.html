Explain Singleton, Factory, and Abstract Factory patterns.

Design Patterns · concept · levels mid, senior

In one line

Singleton ensures one instance with a global access point, Factory Method lets a method or subclass decide which concrete class to create, and Abstract Factory creates families of related objects; the factories decouple clients from concrete classes.

Detailed explanation

Singleton. A private constructor plus a static accessor guarantees one instance per class loader. In plain Java the safest forms are an enum with one constant or the initialization-on-demand holder idiom, both thread-safe without explicit locking. Its downsides are global mutable state, hidden dependencies and harder testing. In Spring you rarely write one, because beans are singleton-scoped by default and are injected rather than fetched globally.

Factory Method. Defines a method that returns an abstract product and lets a subclass, or the method's logic, choose the concrete type. Example: NotificationFactory.create(Channel.SMS) returns an SmsSender, but the caller only knows NotificationSender. Strictly in GoF, the creator class declares an abstract createSender() and subclasses override it; in daily Java, static factory methods such as List.of, LocalDate.of and Calendar.getInstance() follow the same spirit.

Abstract Factory. An interface with several creation methods for products designed to work together. A CloudFactory might have createStorage(), createQueue() and createSecrets(); AwsFactory returns S3, SQS and Secrets Manager clients, AzureFactory returns Blob Storage, Service Bus and Key Vault. Swapping the factory swaps the whole family consistently, so you never mix an AWS queue with Azure storage by accident. JDK examples include DocumentBuilderFactory and JDBC's driver-specific objects.

Spring's FactoryBean is a factory hook: a bean whose getObject() produces the actual object (Spring uses it for proxies, SqlSessionFactoryBean and similar).

How it works

  1. Singleton: private constructor, single static instance, controlled creation.
  2. Factory Method: client calls create(type); implementation picks and returns a concrete class.
  3. Abstract Factory: client receives a factory interface; each method returns one family member.
  4. Configuration (or Spring profiles) selects which factory implementation is used.

Example

// Factory Method
interface NotificationSender { void send(String to, String msg); }
class NotificationFactory {
    NotificationSender create(Channel c) {
        return switch (c) {
            case EMAIL -> new EmailSender();
            case SMS   -> new SmsSender();
            case PUSH  -> new PushSender();
        };
    }
}

// Abstract Factory
interface CloudFactory { BlobStore storage(); MessageQueue queue(); }
class AwsFactory implements CloudFactory {
    public BlobStore storage() { return new S3BlobStore(); }
    public MessageQueue queue() { return new SqsQueue(); }
}

// Singleton
enum Registry { INSTANCE; /* state + methods */ }

Common mistakes

  • Using Singleton for things that should be injected.
  • Calling any new wrapped in a method an "Abstract Factory".
  • Factories with giant switches that must be edited for every new type (consider a map of beans).
  • Singletons with mutable state accessed without synchronisation.

How to answer in the interview

"Singleton guarantees one instance with a global access point; in Java I'd use an enum or the holder idiom for thread safety, but in Spring I let the container manage singleton beans because hand-written singletons hurt testability. Factory Method defines a method that creates objects and lets a subclass or a parameter decide the concrete class, like a NotificationFactory returning an email or SMS sender. Abstract Factory goes further and creates families of related objects that must be used together, like all clients for one cloud provider. Both decouple clients from concrete classes; Spring's FactoryBean is an example."

Likely follow-up questions

  • How can reflection or serialization break a Singleton? Reflection calls the private constructor; deserialisation creates a new object unless readResolve is defined. Enums prevent both.
  • When choose Abstract Factory over Factory Method? When several related products must vary together.
  • How does Spring replace factories? Inject Map<String, Interface> of beans and select by key.
