How do S3 storage classes, lifecycle policies and security work?

Cloud (AWS) · concept · levels mid, senior

In one line

Storage classes trade retrieval cost and latency for cheaper storage (Standard → IA → Glacier tiers, or Intelligent-Tiering), lifecycle rules transition and expire objects automatically, and security relies on Block Public Access, least-privilege IAM and bucket policies, encryption (SSE-S3/SSE-KMS), versioning, Object Lock and presigned URLs.

Detailed explanation

Storage classes: S3 Standard for hot data; Standard-IA and One Zone-IA for data read rarely but needed quickly (cheaper storage, per-GB retrieval fee, 30-day minimum); Glacier Instant Retrieval for archives read a few times a year with millisecond access; Glacier Flexible Retrieval (minutes to hours) and Glacier Deep Archive (hours, cheapest) for long-term retention; Intelligent-Tiering moves objects between tiers automatically based on access, ideal when patterns are unknown. Express One Zone serves very low-latency workloads in a single AZ.

Lifecycle policies act on prefixes or tags: transition logs to IA after 30 days and Glacier after 90, expire them after a year, delete noncurrent versions after N days and abort incomplete multipart uploads. Without these, versioned buckets quietly grow forever.

Security: new buckets have Block Public Access enabled and ACLs disabled by default, and I keep it that way at account level; public content goes through CloudFront with Origin Access Control. Access is granted via IAM roles and bucket policies (for example, deny non-TLS requests, allow only a specific VPC endpoint or organisation). All objects are encrypted at rest by default with SSE-S3; I use SSE-KMS with a customer managed key when I need key-level access control and audit. Presigned URLs give time-limited upload or download access without making anything public.

Data protection: versioning keeps previous versions so deletes become recoverable delete markers; Object Lock in compliance mode makes backups immutable for a retention period, which defends against ransomware and malicious admins. Replication copies data to another region or account.

How it works

  1. Choose the class at upload or let Intelligent-Tiering decide.
  2. Lifecycle rules run daily, transitioning or expiring matching objects.
  3. Each request is evaluated against IAM, bucket policy, BPA, KMS key policy and endpoint policies; an explicit deny anywhere wins.
  4. CloudTrail data events and server access logs record who did what.

Example

{
  "Rules": [{
    "ID": "logs-tiering",
    "Filter": { "Prefix": "logs/" },
    "Status": "Enabled",
    "Transitions": [
      { "Days": 30, "StorageClass": "STANDARD_IA" },
      { "Days": 90, "StorageClass": "GLACIER" }
    ],
    "Expiration": { "Days": 365 },
    "NoncurrentVersionExpiration": { "NoncurrentDays": 30 },
    "AbortIncompleteMultipartUpload": { "DaysAfterInitiation": 7 }
  }]
}

Common mistakes

  • Moving millions of tiny objects to IA or Glacier, where per-object fees and minimum sizes cost more than they save.
  • Versioning without noncurrent-version expiry.
  • Disabling Block Public Access to serve a website instead of using CloudFront.
  • Using SSE-KMS at very high request rates without S3 Bucket Keys, inflating KMS costs.

How to answer in the interview

"Storage classes trade storage price against access cost: Standard for hot data, Standard-IA for infrequent access, Glacier Instant, Flexible and Deep Archive for archives, and Intelligent-Tiering when I don't know the pattern. Lifecycle rules move objects down the tiers and expire old objects, noncurrent versions and incomplete uploads. For security I keep Block Public Access on, grant access through roles and bucket policies with least privilege, use KMS encryption where key control matters, and hand out presigned URLs for temporary access. Versioning protects against accidental deletes, and Object Lock gives immutable backups against ransomware."

Likely follow-up questions

  • Who deleted an object? CloudTrail data events (DeleteObject) or server access logs; versioning lets you restore it.
  • Serve a private bucket publicly? CloudFront with Origin Access Control.
  • Governance vs compliance mode? Governance can be bypassed with special permission; compliance cannot, even by root.
