What is the difference between inheritance and composition?

Core Java & OOP · concept · levels mid

In one line

Inheritance is is-a: a subclass reuses and specialises a parent, fixed at compile time and tightly coupled to its implementation; composition is has-a: a class delegates to objects it holds, which is flexible at runtime and easier to test; favour composition, use inheritance for true subtypes (LSP).

Detailed explanation

Inheritance (class SavingsAccount extends Account) gives you code reuse and polymorphism in one keyword. The subclass inherits fields and methods, overrides what differs, and can be used wherever the parent is expected. Its costs:

  • It is white-box reuse: the subclass depends on how the parent is implemented, including which methods call which. Parent changes can silently break subclasses (fragile base class).
  • It is static: decided at compile time; you can't switch the parent at runtime.
  • Java allows one superclass, so combining features leads to class explosions.
  • The subclass inherits the entire public API, even methods that don't make sense (Stack extends Vector).

Composition (class Car { private final Engine engine; }, class CheckoutService { private final PaymentGateway gateway; }) is black-box reuse through interfaces. The containing class forwards work to its components. Benefits: swap implementations at runtime or via dependency injection, combine behaviours freely (decorators, strategies), expose only the methods you want, and test with mocks. Costs: a bit more boilerplate for forwarding.

Liskov substitution principle: a subtype must be usable wherever its supertype is expected without breaking correctness. The famous counterexample is Square extends Rectangle: setting width on a square also changes its height, violating rectangle callers' expectations. If LSP doesn't hold, inheritance is the wrong tool.

Use inheritance when the relationship is a genuine, stable is-a, the base is designed for extension (otherwise make classes final), and you want polymorphism over a closed set of types. Modern Java's sealed interfaces with records and default methods cover many cases where inheritance used to be the only option.

How it works

  1. Inheritance: the subclass's object contains the parent's fields; method calls dispatch to overrides.
  2. Composition: the object holds references to collaborators.
  3. Calls are delegated explicitly, possibly with extra logic.
  4. Collaborators are usually injected through constructors as interfaces.

Example

// Inheritance mistake: every combination needs a subclass
class Notifier { void send(String msg) { /* email */ } }
class SmsNotifier extends Notifier { /* ... */ }
class SmsAndSlackNotifier extends SmsNotifier { /* explosion */ }

// Composition: combine channels at runtime
interface Channel { void send(String msg); }
class Notifier2 {
    private final List<Channel> channels;
    Notifier2(List<Channel> channels) { this.channels = List.copyOf(channels); }
    void notifyAll(String msg) { channels.forEach(c -> c.send(msg)); }
}
new Notifier2(List.of(new EmailChannel(), new SlackChannel()));

Common mistakes

  • Inheriting from concrete utility classes for reuse.
  • Violating LSP (Square/Rectangle, read-only list throwing on add).
  • Overly deep abstract base hierarchies in services.
  • Dogmatically refusing inheritance even for real subtypes or framework templates.

How to answer in the interview

"Inheritance models is-a: a subclass reuses and specialises the parent, like SavingsAccount extends Account. It's fixed at compile time and couples the subclass to the parent's implementation, so parent changes can break subclasses, the fragile base class problem, and Java only allows one superclass. Composition models has-a: a class holds other objects and delegates, like a service holding a PaymentGateway interface. That's more flexible, since I can swap implementations at runtime and test with mocks. So I favour composition and use inheritance only for genuine subtypes that respect Liskov substitution."

Likely follow-up questions

  • Can you give an example where inheritance was a design mistake? Stack extends Vector or Properties extends Hashtable, both inheriting unwanted methods.
  • What is LSP? Subtypes must be substitutable for their base types without breaking behaviour.
  • How does Spring encourage composition? Constructor injection of interface-typed collaborators.
