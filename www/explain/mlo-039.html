What security threats are specific to machine learning systems, and how do you mitigate them?

MLOps · concept · levels senior, lead

In one line

ML-specific threats are the model supply chain (malicious model files, pickle exploits, backdoors), data poisoning, adversarial examples and evasion, and API attacks like model extraction and membership inference; mitigate with safe formats and signed artefacts, data provenance and validation, adversarial testing, and authentication, rate limiting and monitoring.

Detailed explanation

ML systems inherit normal application security and add new attack surfaces.

Model supply chain. Pre-trained models and datasets come from public hubs. Pickle-based files can execute code on load; weights can contain backdoors that trigger on specific inputs; names can be typosquatted. Mitigations: safetensors/ONNX, artefact scanning, hashing and signing (for example Sigstore), an internal trusted registry or proxy, and an ML bill of materials recording base models and datasets.

Data poisoning. If an attacker can influence training data—user-generated content, feedback loops, scraped web data, labelling vendors—they can bias the model or plant backdoors. Mitigations: data provenance, access control on training data, validation and anomaly detection on new data, limits on any single source's influence, and human review of suspicious clusters.

Adversarial examples and evasion. Small, crafted input changes make a model misclassify; in fraud and spam, attackers iteratively probe for inputs that pass. Mitigations: adversarial testing and training, ensembles and rules, monitoring score distributions, and not exposing raw scores.

API attacks. Model extraction: heavy querying to clone a model. Membership inference: deducing whether a specific record was in training data. Model inversion: reconstructing sensitive attributes. Mitigations: authentication, rate limiting and quotas, returning labels or rounded scores instead of full probabilities, query-pattern monitoring, and differential privacy for sensitive training data.

For LLM applications, add prompt injection and data exfiltration through tools, covered by frameworks like the OWASP Top 10 for LLM Applications and MITRE ATLAS.

How it works

  1. Threat-model the ML system: data sources, artefacts, APIs, consumers.
  2. Lock down the supply chain: safe formats, scanning, signing, trusted registry.
  3. Protect training data with provenance, access control and validation.
  4. Test robustness with adversarial and red-team exercises.
  5. Harden APIs: auth, rate limits, output minimisation, monitoring.
  6. Respond: incident playbooks for poisoning or extraction.

Example

# CI gate for model artefacts
- name: scan model
  run: modelscan -p ./artifacts/model/          # flags unsafe pickle opcodes
- name: sign model
  run: cosign sign-blob --yes artifacts/model.safetensors > model.sig
# serving: verify signature before load; API gateway: 100 req/min per key, scores rounded to 2 decimals

Common mistakes

  • Loading community models directly into production.
  • Treating training data as trusted because it is internal.
  • Returning full probability vectors to anonymous clients.
  • No monitoring for unusual query patterns.

How to answer in the interview

"Beyond normal app security, I worry about four things. The model supply chain: hub models can contain malicious pickle code or backdoors, so we use safe formats, scan and sign artefacts and load only from a trusted registry. Data poisoning, where attackers influence training data, so we track provenance and validate data. Adversarial evasion, especially in fraud, tested with adversarial examples and mitigated with ensembles and monitoring. And API attacks like model extraction and membership inference, mitigated with authentication, rate limits, output rounding and privacy techniques."

Likely follow-up questions

  • How would you detect model extraction? High-volume, systematic or synthetic-looking queries per client, and coverage of the input space.
  • What is a backdoor? A hidden trigger pattern that causes a chosen output.
  • What are LLM-specific threats? Prompt injection, data leakage and insecure tool use.
