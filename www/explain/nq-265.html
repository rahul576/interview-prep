How would you sort the output by customer name and year?

Databases & SQL · concept · levels entry

In one line

Add ORDER BY c.name, order_year at the end: it sorts by name, then by year within each name, ascending by default; it can use select aliases because it is evaluated last, and without it row order is not guaranteed.

Detailed explanation

ORDER BY sorts the final result. With several columns it is a lexicographic sort: first by the first column, and only when those values are equal, by the next. So ORDER BY c.name, order_year lists each customer alphabetically and, within a customer, years from oldest to newest.

Each column can have its own direction: ASC (default) or DESC. ORDER BY c.name ASC, order_year DESC shows the most recent year first per customer; ORDER BY total_revenue DESC gives a "top customers" ranking. You can also control NULL placement with NULLS FIRST/NULLS LAST in PostgreSQL and Oracle.

Because ORDER BY is logically processed after SELECT, it can refer to aliases like order_year and total_revenue, and even to aggregates. This is the main difference from WHERE and (in most databases) GROUP BY.

A crucial point: SQL tables and query results have no inherent order. Even if results seem sorted today because of an index or a sort used for grouping, a different plan, parallel execution or a version upgrade can change it. If order matters, specify ORDER BY. Also add a tie-breaker (such as customer_id) so two customers with the same name are always in the same order, which is essential for pagination.

Text sorting depends on collation: case sensitivity, accents and language rules can change where "anil" and "Zoya" land.

How it works

  1. FROM, WHERE, GROUP BY, HAVING and SELECT produce the result rows.
  2. ORDER BY evaluates its sort keys (columns, aliases, expressions).
  3. The engine sorts, in memory or spilling to disk, or reads an index already in that order.
  4. LIMIT/OFFSET or FETCH FIRST are applied after sorting.

Example

SELECT c.customer_id, c.name,
       EXTRACT(YEAR FROM o.order_date) AS order_year,
       SUM(o.amount) AS total_revenue
FROM customers c
JOIN orders o ON o.customer_id = c.customer_id
GROUP BY c.customer_id, c.name, EXTRACT(YEAR FROM o.order_date)
ORDER BY c.name, c.customer_id, order_year DESC;

-- Top 10 customer-years by revenue
-- ... ORDER BY total_revenue DESC FETCH FIRST 10 ROWS ONLY;

Common mistakes

  • Relying on GROUP BY or an index to give sorted output.
  • No tie-breaker, causing unstable pagination.
  • Sorting a year stored as text and getting odd results.
  • Using aliases in WHERE because they worked in ORDER BY.

How to answer in the interview

"I'd add ORDER BY c.name, order_year at the end. That sorts by customer name and, for the same name, by year, both ascending by default; I could use DESC for the latest year first, or ORDER BY total_revenue DESC for top customers. ORDER BY can use the select aliases because it's evaluated last, after grouping and aggregation. And I'd stress that without ORDER BY the row order isn't guaranteed at all, so I'd also add customer_id as a tie-breaker."

Likely follow-up questions

  • What is the logical evaluation order? FROM/JOIN, WHERE, GROUP BY, HAVING, SELECT, DISTINCT, ORDER BY, then LIMIT/OFFSET.
  • Can ORDER BY use a column not in SELECT? Usually yes, except with DISTINCT or certain set operations.
  • Why is ORDER BY expensive on large results? Sorting is O(n log n) and may spill to disk; an index matching the order can avoid it.
