How does an MCP server expose tools, prompts, and capabilities?

AI/ML & GenAI · concept · levels senior, lead

In one line

An MCP server declares its capabilities in the initialize response, then exposes tools (name, description, inputSchema, optional outputSchema and annotations, handled via tools/call), resources (URIs that can be listed, read and subscribed to) and prompts (templates with arguments via prompts/get), usually built with official SDKs and sending change notifications.

Detailed explanation

Capability declaration: in its initialize result the server lists what it supports, for example tools, resources (with subscribe and listChanged), prompts, logging and completions. Clients use only what was declared.

Tools: each tool has a unique name, a clear description, an inputSchema in JSON Schema, optionally an outputSchema for structured content, and annotations such as readOnlyHint, destructiveHint and idempotentHint. The server implements tools/list and a tools/call handler that validates arguments, executes the operation and returns content blocks, or a result with isError: true for business errors. If tools change, it sends notifications/tools/list_changed.

Resources: identified by URIs such as file:///repo/README.md or postgres://orders/schema. Clients call resources/list, resources/read, and optionally resources/subscribe for update notifications. Resource templates allow parameterised URIs.

Prompts: reusable message templates with named arguments, listed with prompts/list and expanded with prompts/get; hosts often show them as slash commands.

SDKs: official SDKs exist for TypeScript, Python, Java, Kotlin, C#, Go and others. In Java, Spring AI's MCP support lets you turn annotated Spring bean methods into tools and run the server over stdio or HTTP, so the SDK handles JSON-RPC, schema generation and transport.

How it works

  1. Choose transport: stdio for local, Streamable HTTP for remote.
  2. Register tools, resources and prompts with the SDK.
  3. SDK answers initialize with the declared capabilities.
  4. Handlers validate input and call your domain services.
  5. Return concise content or structured output; flag errors.
  6. Emit list-changed or resource-updated notifications.

Example

@Service
public class OrderTools {
    private final OrderService orders;
    public OrderTools(OrderService orders) { this.orders = orders; }

    @Tool(description = "Get the current status of an order by ID, e.g. ORD-1234")
    public String orderStatus(@ToolParam(description = "Order ID") String orderId) {
        return orders.status(orderId).toString();
    }
}

@Bean
ToolCallbackProvider orderToolProvider(OrderTools tools) {
    return MethodToolCallbackProvider.builder().toolObjects(tools).build();
}

With the Spring AI MCP server starter, these tools are published over the configured transport.

Common mistakes

  • Exposing a whole REST API one-to-one as dozens of tools.
  • Vague descriptions or loose schemas.
  • Returning stack traces instead of useful error messages.
  • Declaring capabilities you have not implemented.

How to answer in the interview

"During initialize, the server declares which capabilities it supports, like tools, resources, prompts and logging, and whether it sends change notifications. Tools have a name, description and JSON Schema input, optionally an output schema and annotations like read-only or destructive, and the server handles tools/call. Resources are URIs that can be listed, read and subscribed to. Prompts are templates with arguments retrieved with prompts/get, often shown as slash commands. I'd use an official SDK; in Java, Spring AI can expose annotated bean methods as MCP tools, handling the protocol plumbing."

Likely follow-up questions

  • How would you expose a Spring service? Wrap a few task-focused methods with @Tool, add the MCP server starter, secure with OAuth.
  • Tool vs resource? Tools are model-invoked actions; resources are context the app or user selects.
  • How do you version tools? Keep names stable, add optional parameters, notify on list changes.
