What is a functional interface?

Java 8+ Features · concept · levels entry

In one line

A functional interface is an interface with exactly one abstract method (a SAM type); it may have any number of default and static methods, and it is the target type for lambdas and method references, e.g. Runnable, Comparator, Function.

Detailed explanation

Java represents functions as objects implementing an interface. When an interface has only one abstract method, there is no ambiguity about which method a lambda implements, so the compiler can turn () -> doWork() into an implementation of Runnable.run().

The "one abstract method" rule has nuances:

  • Default methods have bodies, so they don't count; neither do static or private methods.
  • Abstract methods that redeclare public Object methods (equals, hashCode, toString) don't count, because every implementation inherits them. That's why Comparator, which has compare plus a redeclared equals and many default/static methods, is functional.
  • Inherited abstract methods do count. An interface extending another functional interface stays functional only if it adds no new abstract method (or overrides to a single signature).

Built-in examples: older interfaces such as Runnable, Callable<V>, Comparator<T>, ActionListener; and since Java 8 the java.util.function package with about 40 types built on four shapes: Function<T,R>, Predicate<T>, Supplier<T>, Consumer<T>, plus two-argument (BiFunction), same-type (UnaryOperator, BinaryOperator) and primitive (IntPredicate, ToLongFunction) variants.

You can write your own, ideally marked with @FunctionalInterface so the compiler enforces the rule, when a domain name adds clarity (DiscountPolicy) or you need checked exceptions or more than two parameters.

How it works

  1. Declare an interface with one abstract method.
  2. Use it as a variable, parameter or return type.
  3. Supply a lambda, method reference or regular implementation.
  4. The compiler matches the lambda's signature to the abstract method.
  5. Calling the method executes the provided behaviour.

Example

@FunctionalInterface
interface TaxCalculator {
    BigDecimal tax(BigDecimal amount);
    default TaxCalculator withSurcharge(BigDecimal pct) {
        return a -> tax(a).add(a.multiply(pct));
    }
}

TaxCalculator gst = a -> a.multiply(new BigDecimal("0.18"));
BigDecimal t = gst.withSurcharge(new BigDecimal("0.01")).tax(new BigDecimal("1000")); // 190.00

Runnable r = () -> System.out.println("work");
Comparator<String> byLen = Comparator.comparingInt(String::length);
Function<String, Integer> len = String::length;
Predicate<Integer> even = n -> n % 2 == 0;

Common mistakes

  • Thinking default methods disqualify an interface.
  • Believing @FunctionalInterface is mandatory.
  • Creating custom interfaces that duplicate Function or Predicate without need.
  • Forgetting that inherited abstract methods count.

How to answer in the interview

"A functional interface is an interface with exactly one abstract method, also called a SAM type. It can still have any number of default and static methods, and methods that redeclare Object methods like equals don't count. Because there's only one method to implement, a lambda or method reference can supply it, like Runnable r = () -> doWork(). Classic examples are Runnable, Callable and Comparator, and Java 8 added java.util.function with Function, Predicate, Supplier and Consumer. I can write my own and mark it with @FunctionalInterface."

Likely follow-up questions

  • Is Comparator functional even though it has many methods? Yes, only compare is abstract apart from the Object method equals.
  • Can a functional interface be generic? Yes, like Function<T,R>; the lambda itself can't declare type parameters.
  • Why use your own instead of Function? For domain naming, checked exceptions or more parameters.
