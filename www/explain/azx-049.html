What does GitHub Advanced Security for Azure DevOps provide?

Azure DevOps & Pipelines · concept · levels mid, senior

In one line

GitHub Advanced Security for Azure DevOps (GHAzDO) brings secret scanning with push protection, dependency scanning and CodeQL code scanning to Azure Repos and Pipelines, with alerts in the repo's Advanced Security tab and an org security overview; it's enabled per repository, billed per active committer, and now sold as Secret Protection and Code Security.

Detailed explanation

Secret scanning detects credentials (cloud keys, PATs, connection strings, partner token patterns) in the repository history and new commits. Push protection checks pushes in real time and blocks those containing recognised secrets, with an option to bypass via a special commit message for false positives, which is auditable. Blocking before the secret lands is far cheaper than rotating after exposure.

Dependency scanning runs as a pipeline task (AdvancedSecurity-Dependency-Scanning@1), analysing manifests and lock files (npm, NuGet, Maven, pip, Go and others) and raising alerts for dependencies with known vulnerabilities from the GitHub Advisory Database, including fixed versions to upgrade to.

Code scanning uses the CodeQL engine: AdvancedSecurity-Codeql-Init@1, a build (or build mode none for interpreted and some compiled languages), and AdvancedSecurity-Codeql-Analyze@1. It finds vulnerabilities such as SQL injection, XSS, path traversal and insecure deserialisation, with data-flow explanations. Third-party SARIF results can also be published.

Findings appear in the repository's Advanced Security tab, can be dismissed with reasons, and roll up in an organisation-level security overview. They can also flow into Microsoft Defender for Cloud DevOps security for code-to-cloud context. Enablement is per repository, project or organisation, with auto-enable for new repos, and billing is based on unique active committers. Microsoft has split it into separately purchasable Secret Protection and Code Security offerings, matching GitHub's model.

How it works

  1. Enable Advanced Security on target repos (billing starts for active committers).
  2. Secret scanning and push protection work immediately on pushes.
  3. Add dependency and CodeQL tasks to pipelines on main and PRs.
  4. Alerts appear in the repo and security overview.
  5. Triage: fix, dismiss with reason, or create work items.

Example

steps:
- task: AdvancedSecurity-Codeql-Init@1
  inputs: { languages: 'csharp' }
- script: dotnet build src/Orders.sln -c Release
- task: AdvancedSecurity-Dependency-Scanning@1
- task: AdvancedSecurity-Codeql-Analyze@1

Common mistakes

  • Turning on push protection org-wide without communication or triage capacity.
  • Running CodeQL only nightly so PR authors never see findings.
  • Dismissing alerts without reasons.
  • Treating detection as enough without rotating found secrets.

How to answer in the interview

"GitHub Advanced Security for Azure DevOps brings GitHub's security features into Azure Repos and Pipelines. Secret scanning finds credentials in repos, and push protection blocks pushes containing them before they land. Dependency scanning runs in the pipeline and alerts on vulnerable packages with fixed versions. Code scanning uses CodeQL to find vulnerabilities like SQL injection in source code. Alerts show in each repo's Advanced Security tab and an organisation overview, and can surface in Defender for Cloud. It's enabled per repo or project, billed per active committer, and now sold as Secret Protection and Code Security."

Likely follow-up questions

  • Roll out push protection gently? Start with scanning history, fix existing secrets, pilot teams, communicate bypass process, then enforce.
  • Who are active committers? Unique people pushing to enabled repos in the last 90 days.
  • Secret found in history? Rotate first; rewriting history is secondary.
