Compare Azure Load Balancer, Application Gateway, Front Door and Traffic Manager.

Azure · concept · levels mid

In one line

Load Balancer is regional layer 4 (TCP/UDP), Application Gateway is regional layer 7 with WAF, Front Door is a global layer 7 entry point with CDN and WAF at Microsoft's edge, and Traffic Manager is DNS-based global routing for any protocol.

Detailed explanation

Azure's load-balancing services split along two axes: regional versus global, and layer 4 versus layer 7 (HTTP).

Azure Load Balancer works at layer 4. It distributes TCP and UDP flows using a hash of the 5-tuple, has very low latency and high throughput, and can be public or internal. The Standard SKU is zone-redundant and secure by default; the Basic SKU has been retired. It is used for VM backends, network virtual appliances (with HA ports) and as the default load balancer for AKS LoadBalancer services.

Application Gateway (v2) is a regional layer 7 reverse proxy. It supports path- and host-based routing, TLS termination and end-to-end TLS, cookie affinity, rewrites, autoscaling and an integrated Web Application Firewall based on OWASP rules. It is deployed in a dedicated subnet inside your VNet, so it can front private backends. For AKS, Application Gateway for Containers is the newer option.

Azure Front Door (Standard/Premium) is a global service running on Microsoft's edge network using anycast. Users connect to the nearest point of presence, where TLS is terminated, then traffic travels over Microsoft's backbone to the healthiest, fastest origin. It adds caching (CDN), WAF, rules and, in Premium, Private Link to origins. Failover between regions is quick because it is based on health probes, not DNS.

Traffic Manager is purely DNS-based: it answers DNS queries with the endpoint chosen by routing method (priority, weighted, performance, geographic, multivalue or subnet). It works for any protocol, but clients connect directly to the endpoint, and failover speed depends on DNS TTLs and client caching.

How it works

  1. Choose global entry: Front Door for HTTP(S), Traffic Manager for non-HTTP.
  2. Global layer routes users to a healthy region.
  3. In the region, Application Gateway or an ingress handles HTTP routing and WAF.
  4. Load Balancer distributes TCP/UDP to VMs or nodes.
  5. Health probes at each layer remove unhealthy backends.

Example

Typical layered design for a two-region web app:

Users → Azure Front Door (WAF, caching, global failover)
          ├─ West Europe:  Application Gateway / AKS ingress → pods
          └─ North Europe: Application Gateway / AKS ingress → pods
Non-HTTP game servers → Traffic Manager (performance) → regional Load Balancers

Common mistakes

  • Using Traffic Manager for HTTP apps and expecting instant failover.
  • Putting Application Gateway in front of a global audience as the only entry point.
  • Forgetting to lock origins so only Front Door can reach them.
  • Expecting Load Balancer to do path routing or TLS termination.
  • Running WAF in Detection mode forever.

How to answer in the interview

"Azure Load Balancer is a regional layer 4 balancer for TCP and UDP, very fast, used for VMs and as the AKS service load balancer. Application Gateway is a regional layer 7 proxy with path and host routing, TLS termination and an optional WAF. Front Door is a global layer 7 entry point on Microsoft's edge using anycast, with caching, WAF and fast health-probe-based failover between regions. Traffic Manager is DNS-based global routing by priority, performance, weight or geography; it works for any protocol but fails over only as fast as DNS TTLs allow. For a two-region web app I would use Front Door globally and Application Gateway or an AKS ingress regionally."

Likely follow-up questions

  • Which would you put in front of an app in two regions? Front Door, because of fast failover, WAF and caching.
  • How do you make sure origins only accept traffic from Front Door? Private Link in Premium, or the service tag plus the X-Azure-FDID header check.
  • When do you combine Front Door and Application Gateway? When you need regional private routing and WAF closer to the backends.
