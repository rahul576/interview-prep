How do you implement reliable citations in a RAG answer?

LLMOps & RAG · concept · levels mid, senior

In one line

Reliable citations come from giving every retrieved chunk a stable identifier, making the model cite those IDs per claim, then validating in code that each cited ID was actually retrieved, mapping it back to a document link and passage, and optionally running a groundedness check that the cited text really supports the claim.

Detailed explanation

A citation is only useful if a user can click it and find the sentence that backs the claim. Free-form references such as "according to the HR policy" are unverifiable, and models will happily invent document names. The fix is to make citation a closed vocabulary: the prompt contains chunks labelled [1], [2] or doc-17#p3, with title, source and date, and the instructions demand a citation after each factual sentence in a fixed format, plus an explicit "no source supports this" behaviour.

After generation the application, not the model, does the important work. It parses citations, rejects IDs that were not in the retrieved set (this catches hallucinated references), and resolves each ID to a URL, page number and the exact passage, which the UI shows on hover or in a side panel.

Several providers now offer native citation features. For example, Anthropic's Citations feature returns cited spans (character ranges for text documents, page ranges for PDFs) tied to the documents you passed in, and Azure AI Search and Vertex AI grounding return source references. These are more reliable than parsing free text because the span is guaranteed to exist in the source.

The final layer is attribution quality: the right source can be cited for a wrong statement. A groundedness or entailment check, with an LLM judge or NLI model, compares each claim with its cited passage and flags or removes unsupported sentences.

How it works

  1. Retrieve and rerank chunks; assign each a short ID and keep a map ID to document, page and offsets.
  2. Build the prompt with labelled chunks and a strict citation format.
  3. Generate the answer, or use the provider's native citation mode.
  4. Parse citations; drop or flag any ID not in the retrieved set.
  5. Run a groundedness check per claim against the cited text.
  6. Render answer with clickable sources and highlighted passages.

Example

chunks = retrieve(query)
ids = {f"S{i}": c for i, c in enumerate(chunks, 1)}
context = "\n".join(f"[{k}] ({c.title}, {c.date}) {c.text}" for k, c in ids.items())
answer = llm(SYSTEM + "Cite as [S1] after each claim. If unsupported, say so.\n" + context, query)

for cid in re.findall(r"\[(S\d+)\]", answer):
    if cid not in ids:
        flag("invented citation", cid)

Common mistakes

  • Letting the model write document titles or URLs itself instead of IDs.
  • Citing whole documents rather than passages, so users cannot verify quickly.
  • Never checking that the cited text supports the claim.
  • Losing page numbers and section paths during ingestion.

How to answer in the interview

"I give every retrieved chunk a short ID in the prompt, with title and date, and instruct the model to cite those IDs after each claim and to say when nothing supports an answer. In code I parse the citations, reject any ID that wasn't retrieved, and map the rest to a link and the exact passage for the UI. Where the provider offers native citations with character or page spans, I prefer those. For higher assurance I run a groundedness check that each claim is actually entailed by its cited passage, and I track citation accuracy in my evaluation set."

Likely follow-up questions

  • Correct source, wrong claim? Groundedness check per sentence; remove or rewrite the claim and log it as an eval case.
  • How do you measure citation quality? Citation precision and recall against labelled passages, plus judge-based support scores.
  • What if no chunk is relevant? Answer "I don't know" with no citation rather than citing a weak match.
