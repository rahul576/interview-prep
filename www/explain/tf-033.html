Creating an AKS cluster or RDS instance often fails in apply with a timeout, although it finishes later in the cloud. How do you handle it?

Terraform · scenario · levels mid, senior

In one line

Big resources can take longer than the provider's default timeout; Terraform errors while the cloud keeps creating the object, which then ends up tainted or missing from state; set a timeouts block, recover by untainting or importing, and make the CI job timeout longer than Terraform's.

Detailed explanation

Providers wrap long-running cloud operations in polling loops with timeouts. AKS clusters, RDS instances, Application Gateways or VPN gateways can take 20 to 60 minutes or more. If the operation exceeds the provider's default timeout for that resource, Terraform stops waiting and reports an error, but the cloud API keeps working and the resource usually completes a few minutes later.

What happens to state depends on the provider and the point of failure:

  • If the provider already received the object ID, it saves the resource in state but marks it tainted, because creation did not complete successfully. The next plan proposes to replace it, destroying a perfectly healthy cluster.
  • If the ID was not saved, the resource is absent from state. The next apply tries to create it again and fails with "already exists".

Prevention: many resources support a timeouts block with create, update, delete (and sometimes read) values, for example create = "90m". Check the resource documentation for supported operations and defaults.

Recovery: wait until the cloud operation finishes and verify the resource is healthy in the console or CLI. If it is in state and tainted, run terraform untaint <address>. If it is missing, add an import block (or run terraform import) with its ID. Then run a plan; it should show no changes or only minor ones.

Finally, the pipeline job timeout must be longer than the sum of Terraform timeouts. If CI kills Terraform mid-apply, the state may not be written, the lock stays behind, and resources are left in an unknown state.

How it works

  1. Provider starts a long operation and polls.
  2. Poll exceeds timeout; Terraform reports an error.
  3. Cloud finishes; Terraform state is tainted or missing.
  4. Verify health, then untaint or import.
  5. Set timeouts and adequate CI timeouts for future runs.

Example

resource "azurerm_kubernetes_cluster" "main" {
  name                = "aks-prod-weu"
  location            = "westeurope"
  resource_group_name = azurerm_resource_group.aks.name
  dns_prefix          = "aksprod"
  default_node_pool {
    name       = "system"
    vm_size    = "Standard_D4s_v5"
    node_count = 3
  }
  identity { type = "SystemAssigned" }

  timeouts {
    create = "90m"
    update = "120m"
    delete = "90m"
  }
}
terraform untaint azurerm_kubernetes_cluster.main
# or, if missing from state, add an import block with the cluster's resource ID

Common mistakes

  • Approving a plan that replaces a healthy but tainted cluster.
  • Re-running apply immediately while the cloud is still creating the resource.
  • CI timeouts shorter than Terraform timeouts.

How to answer in the interview

"Large resources like AKS clusters or RDS instances can take longer than the provider's default timeout, and when it expires Terraform reports an error although the cloud keeps creating the resource. Depending on the provider, the resource is saved as tainted, so the next apply wants to replace it, or isn't saved at all, so the next apply fails because it already exists. I set a timeouts block, for example create = "90m". To recover I wait for the resource to finish, then untaint it if it's healthy, or import it into state, and re-run the plan. I also make sure the CI job timeout is longer than the Terraform timeouts so the pipeline doesn't kill Terraform midway."

Likely follow-up questions

  • Risk of CI killing Terraform while it holds the lock? State not written, stale lock, and resources unknown to Terraform.
  • What does taint mean? The object is marked for replacement on the next apply.
  • Modern alternative to taint? terraform apply -replace=<address> for deliberate replacement.
