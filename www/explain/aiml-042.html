Should you classify text with an LLM prompt or train a dedicated classifier?

AI/ML & GenAI · concept · levels mid, senior

In one line

Prompt an LLM when you need to start fast with little labelled data or changing categories; train a dedicated classifier when volume, latency, cost and stable calibrated outputs matter; often the best path is LLM first, then distil its reviewed labels into a small model, comparing both on the same labelled test set.

Detailed explanation

LLM prompting for classification (support tickets, reviews, emails, intent) works almost immediately: describe the categories with definitions, add a few examples, request structured output. It needs little or no labelled data, handles nuance and long text well, and adapts to new categories by editing the prompt. That makes it ideal for prototypes, low volume, frequently changing taxonomies or long-tail categories. Downsides: cost per call, latency of hundreds of milliseconds or more, rate limits, occasional inconsistency, and confidence that is not well calibrated.

A dedicated classifier, from logistic regression on TF-IDF or embeddings to a fine-tuned small transformer such as a DistilBERT or ModernBERT-class model, needs a labelled dataset and a training pipeline. In return, at high volume it is orders of magnitude cheaper and faster, runs on CPUs or a small GPU, is deterministic, produces calibrated probabilities you can threshold, and is easy to monitor for drift. A classifier on top of frozen embeddings is a lightweight middle ground.

The common pattern is to combine them. Start with the LLM to ship quickly. Use it, with human review of a sample and of low-confidence cases, to label thousands of examples. Train a small model on those labels, a form of distillation. Route traffic: the small model handles confident predictions, and uncertain or out-of-distribution inputs fall back to the LLM or a human. When a new category appears, the LLM handles it via prompt changes while you collect examples to retrain.

Whatever you choose, build a labelled test set reviewed by humans and compare options on accuracy or macro-F1 per class, latency and cost per 1,000 predictions. Don't evaluate the distilled model only against LLM labels; use human-verified ground truth.

How it works

  1. Define categories clearly and label a test set of a few hundred examples.
  2. Prompt an LLM with definitions, examples and a JSON schema; measure.
  3. If volume or cost demands, use the LLM plus review to label a training set.
  4. Train a small classifier; compare on the same test set.
  5. Deploy with confidence thresholds and LLM or human fallback; retrain as categories evolve.

Common mistakes

  • Paying LLM prices for millions of simple, stable classifications.
  • Training on unreviewed LLM labels and inheriting systematic errors.
  • Evaluating with accuracy only on imbalanced classes.
  • No fallback for out-of-distribution inputs.

How to answer in the interview

"For a quick start or changing categories, I'd prompt an LLM with clear definitions, examples and structured output; it needs almost no labelled data. At high volume, a dedicated classifier, even logistic regression on embeddings or a small fine-tuned transformer, is far cheaper, faster and gives calibrated, stable outputs. My usual path is to start with the LLM, use it plus human review to label thousands of examples, distil into a small model and keep the LLM as fallback for low-confidence cases. I compare both on the same human-labelled test set for accuracy, latency and cost."

Likely follow-up questions

  • New category after training? Route it via the LLM or rules, collect labelled examples, then retrain.
  • What is distillation here? Training a smaller model to imitate a larger model's labels or outputs.
  • How do you detect drift? Monitor class distribution, confidence and periodic human-labelled samples.
