What is the time complexity of your solution?

DSA: Arrays & Strings · concept · levels mid

In one line

With n words of maximum length k, the sorted-key solution is O(n·k log k) time, the counting-key solution is O(n·k), map operations are average O(1) apart from hashing the key, and space is O(n·k).

Detailed explanation

Name the variables first: n = number of words, k = maximum word length. Interviewers want to see you separate the two.

Sorted-key approach, per word:

  • toCharArray() copy: O(k).
  • Arrays.sort: O(k log k).
  • new String(chars): O(k).
  • Hashing the key and map lookup: O(k) to compute the hash (Java caches a string's hash after first computation) plus average O(1) bucket access.
  • Appending to the list: amortised O(1).

Dominant term: O(k log k) per word, so O(n·k log k) total.

Counting-key approach, per word: count in O(k), serialise 26 counts in O(26) = O(1), hash the key in O(1) relative to k (fixed size). So O(k) per word, O(n·k) total. That is optimal, since you must read every character at least once.

Space: the map stores every word once (O(n·k) total characters) plus one key per group (at most n keys, each O(k) or O(26)). So O(n·k) auxiliary space. The output itself is also O(n·k).

Practical notes: for normal dictionary words (k ≈ 5–15), log k is tiny, so both approaches perform similarly and the sorted one is often simpler. The counting approach wins for long strings (k in the thousands) or when the alphabet is small. Average O(1) hashing assumes a good hash distribution; Java's treeified buckets cap pathological cases at O(log n) per lookup. Compare with brute-force pairwise comparison at O(n²·k).

How it works

  1. Define n and k explicitly.
  2. Cost the key construction per word.
  3. Add the map insertion cost.
  4. Multiply by n for total time.
  5. Sum stored words and keys for space.

Example

// O(n · k log k)
for (String w : words) {                    // n iterations
    char[] c = w.toCharArray();             // O(k)
    Arrays.sort(c);                         // O(k log k)
    map.computeIfAbsent(new String(c),      // O(k) build + hash, O(1) avg lookup
        x -> new ArrayList<>()).add(w);     // O(1) amortised
}

// O(n · k)
for (String w : words) {
    int[] cnt = new int[26];
    for (char ch : w.toCharArray()) cnt[ch - 'a']++;   // O(k)
    map.computeIfAbsent(Arrays.toString(cnt),           // O(26) = O(1)
        x -> new ArrayList<>()).add(w);
}

For n = 1,000,000 words with k = 10: about 10 million character operations plus sorting overhead, comfortably under a second.

Common mistakes

  • Saying "O(n)" without mentioning word length.
  • Ignoring the cost of hashing and copying the key.
  • Claiming HashMap is O(1) worst case.
  • Forgetting the space for storing the result.

How to answer in the interview

"Let n be the number of words and k the maximum length. With the sorted-characters key, each word costs O(k log k) to sort and O(k) to build and hash the key, so the total is O(n·k log k). With a frequency-count key it's O(k) per word, so O(n·k) overall, which is optimal because I have to read every character. Map operations are average O(1) apart from hashing. Space is O(n·k) to store the words and keys in the map."

Likely follow-up questions

  • When does k log k vs k matter? For long strings; for short dictionary words the difference is negligible.
  • Is HashMap lookup always O(1)? Average O(1); worst case O(log n) per bucket in Java 8+.
  • Can you do better than O(n·k)? No, you must read every character.
