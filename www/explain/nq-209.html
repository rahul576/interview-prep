How do you define request mappings in Spring Boot?

REST & API Design · concept · levels entry

In one line

Annotate a class with @RestController and a base @RequestMapping path, map handler methods with @GetMapping/@PostMapping/@PutMapping/@PatchMapping/@DeleteMapping, and bind input with @PathVariable, @RequestParam, @RequestBody (plus @Valid) and @RequestHeader.

Detailed explanation

In Spring MVC a request mapping connects an HTTP method plus URL pattern to a Java method. @RestController combines @Controller and @ResponseBody, so whatever a method returns is serialised by an HttpMessageConverter (normally Jackson) into the response body instead of being treated as a view name. A class-level @RequestMapping("/api/v1/orders") sets the common prefix, and the method-level composed annotations such as @GetMapping("/{id}") narrow it by HTTP verb and sub-path. They are shortcuts for @RequestMapping(method = RequestMethod.GET).

Inputs are bound declaratively. @PathVariable takes a URI template segment that identifies a resource; @RequestParam reads query-string or form parameters, with required and defaultValue for optional filters and paging; @RequestBody deserialises the JSON body into a DTO, and adding @Valid triggers Bean Validation before your code runs; @RequestHeader reads headers such as an idempotency key or correlation id.

Mappings can also be narrowed with consumes (the request Content-Type must match, otherwise 415) and produces (the response media type must match Accept, otherwise 406). When you need control over the status code and headers, return ResponseEntity<T>. A typical case is answering a POST with 201 Created and a Location header.

How it works

  1. At startup RequestMappingHandlerMapping scans controllers and registers every mapping (path, method, consumes, produces, params, headers).
  2. A request reaches the DispatcherServlet, which asks the handler mapping for the best match.
  3. Argument resolvers bind path variables, parameters, headers and the body, converting types and running validation.
  4. The method runs and returns a DTO or a ResponseEntity.
  5. A message converter serialises the result in the negotiated media type.

Example

@RestController
@RequestMapping(path = "/api/v1/orders", produces = MediaType.APPLICATION_JSON_VALUE)
class OrderController {
    private final OrderService service;
    OrderController(OrderService service) { this.service = service; }

    @GetMapping("/{id}")
    OrderDto get(@PathVariable long id) { return service.find(id); }

    @GetMapping
    Page<OrderDto> list(@RequestParam(defaultValue = "0") int page,
                        @RequestParam(required = false) String status) {
        return service.search(status, page);
    }

    @PostMapping(consumes = MediaType.APPLICATION_JSON_VALUE)
    ResponseEntity<OrderDto> create(@Valid @RequestBody CreateOrder req,
                                    @RequestHeader("Idempotency-Key") String key) {
        OrderDto dto = service.create(req, key);
        URI location = URI.create("/api/v1/orders/" + dto.id());
        return ResponseEntity.created(location).body(dto);
    }

    @DeleteMapping("/{id}")
    ResponseEntity<Void> delete(@PathVariable long id) {
        service.delete(id);
        return ResponseEntity.noContent().build();
    }
}

Common mistakes

  • Using @Controller without @ResponseBody and getting "template not found" errors.
  • Forgetting @Valid, so validation annotations on the DTO are silently ignored.
  • Putting verbs in paths (/getOrder) instead of using the HTTP method.
  • Returning entities directly instead of DTOs, which leaks internal fields.
  • Two mappings that overlap and cause an "ambiguous handler methods" error at startup.

How to answer in the interview

"I put @RestController on the class so return values go straight to JSON, and a base path such as /api/v1/orders with @RequestMapping. Each method then gets a composed annotation like @GetMapping("/{id}") or @PostMapping. For inputs I use @PathVariable for the resource id, @RequestParam with defaults for filters and paging, @RequestBody with @Valid for the JSON payload, and @RequestHeader for things like an idempotency key. I can restrict content types with consumes and produces. When the status matters, like 201 for a create or 204 for a delete, I return ResponseEntity."

Likely follow-up questions

  • How do you return 201 Created with a Location header? ResponseEntity.created(uri).body(dto), building the URI with ServletUriComponentsBuilder.fromCurrentRequest().path("/{id}").
  • What happens if consumes does not match? Spring returns 415 Unsupported Media Type; a produces mismatch gives 406.
  • How do you version the API? Usually a path prefix like /v1; header or media-type versioning are alternatives.
