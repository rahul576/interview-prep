How does the class-loading hierarchy work?

JVM & Performance · concept · levels mid, senior

In one line

Class loaders follow the parent delegation model: a loader first asks its parent, all the way up to Bootstrap, and only loads a class itself if no parent can, which protects core classes and avoids duplicates; some containers deliberately use child-first loading.

Detailed explanation

ClassLoader.loadClass implements a simple algorithm. First it checks whether this loader has already loaded the class (findLoadedClass). If not, it delegates to its parent; the parent repeats the process up to the Bootstrap loader. Only if the parent chain throws ClassNotFoundException does the loader call its own findClass to search its sources.

This gives two guarantees. Security and consistency: java.lang.String always comes from Bootstrap, so a JAR on the classpath containing a fake java.lang.String cannot replace it (the module system also forbids defining classes in java.* packages). Uniqueness: a class is loaded once, by the highest loader that can see it, so all code shares the same Class object and casts work. Loaders also see "upwards only": a class loaded by a parent cannot see classes only visible to a child, which is why frameworks use the thread context class loader to load application classes from library code.

Some containers invert the model for application code. Tomcat's WebappClassLoader looks in the web app's WEB-INF/classes and WEB-INF/lib first (child-first) and only then delegates, while still delegating JDK classes and Servlet API classes to parents. This lets each web app ship its own version of Jackson or Guava. OSGi and JBoss Modules use explicit dependency graphs instead of a strict tree.

How it works

  1. loadClass("com.acme.Order") called on a child loader.
  2. findLoadedClass returns the cached class if present.
  3. Otherwise parent.loadClass(...), recursively to Bootstrap.
  4. If a parent finds it, that parent's class is returned.
  5. If none does, the child's findClass searches its own JARs and calls defineClass.
  6. If still not found, ClassNotFoundException.

Example

// Simplified logic of ClassLoader.loadClass
protected Class<?> loadClass(String name, boolean resolve) throws ClassNotFoundException {
    synchronized (getClassLoadingLock(name)) {
        Class<?> c = findLoadedClass(name);
        if (c == null) {
            try {
                c = (parent != null) ? parent.loadClass(name, false)
                                     : findBootstrapClassOrNull(name);
            } catch (ClassNotFoundException ignored) { }
            if (c == null) c = findClass(name);   // only now search locally
        }
        if (resolve) resolveClass(c);
        return c;
    }
}

Common mistakes

  • Saying the child loads first by default.
  • Putting the same library both in the container's lib and the web app, causing ClassCastException or LinkageError.
  • Forgetting the context class loader when loading user classes from framework code.
  • Overriding loadClass and breaking delegation unintentionally.

How to answer in the interview

"Class loaders use parent delegation. When a loader is asked for a class, it checks its cache, then delegates to its parent, which delegates upward to Bootstrap. Only if no parent can find the class does the child search its own sources through findClass. That stops applications from replacing core classes like String and makes sure each class is loaded once by the highest loader that can see it. Containers like Tomcat use child-first loading for web-app libraries so each app can bring its own versions, but that can cause duplicate-class problems if a library appears at both levels."

Likely follow-up questions

  • What problems can child-first cause? The same class loaded twice, leading to ClassCastException, LinkageError or a mismatched interface.
  • How does JDBC find drivers if DriverManager is in a parent loader? Through ServiceLoader and the thread context class loader.
  • Can you replace java.lang.String with your own? No; delegation and module rules prevent it.
