How does AWS billing work, and how do you avoid surprise bills?

Cloud (AWS) · concept · levels entry

In one line

AWS bills pay-as-you-go for compute time, storage, requests and data transfer; avoid surprises with AWS Budgets alerts, Cost Anomaly Detection, regular Cost Explorer reviews by service and tag, and by hunting the usual culprits: idle resources, NAT gateway processing, data transfer and forgotten test environments.

Detailed explanation

Each service has its own pricing dimensions. Compute (EC2, Fargate, Lambda) is billed per second, hour or request plus duration. Storage is billed per GB-month (S3, EBS, snapshots, backups). Many services also charge per request or API call. Data transfer is the subtle one: inbound traffic is generally free, but traffic out to the internet, between regions and often between AZs is charged, as is data processed by NAT gateways and some load balancers. Public IPv4 addresses are also charged hourly.

The Free Tier helps new accounts experiment, but it has strict limits and some offers expire; exceeding them bills normally. Discounts come from Savings Plans and Reserved Instances for steady usage, and Spot for interruptible workloads.

Visibility and guardrails prevent shocks. AWS Budgets sends email, SNS or chat alerts when actual or forecasted spend crosses thresholds, and can even trigger actions such as applying a restrictive policy. Cost Anomaly Detection uses machine learning to flag unusual spikes per service or account. Cost Explorer shows trends grouped by service, account, region and cost allocation tag; the Cost and Usage Report (CUR, now Data Exports) gives line-item detail for Athena analysis. In Organizations, consolidated billing gives one view across accounts.

Common surprise sources: forgotten EC2 instances and RDS databases in test accounts, unattached EBS volumes and ancient snapshots, idle load balancers and Elastic IPs, NAT gateway data processing, cross-AZ chatter, CloudWatch Logs with no retention, S3 versioning keeping every old object, and over-provisioned instance sizes.

How it works

  1. Usage is metered per service and dimension.
  2. Costs appear in Billing and Cost Explorer within hours.
  3. Budgets compare actual and forecast spend to thresholds.
  4. Anomaly Detection flags unusual patterns.
  5. Tags attribute cost to teams and applications.
  6. Monthly invoice consolidates all accounts.

Example

aws budgets create-budget --account-id 123456789012 \
  --budget '{"BudgetName":"monthly-total","BudgetLimit":{"Amount":"500","Unit":"USD"},
             "TimeUnit":"MONTHLY","BudgetType":"COST"}' \
  --notifications-with-subscribers '[{"Notification":{"NotificationType":"FORECASTED",
      "ComparisonOperator":"GREATER_THAN","Threshold":80},
      "Subscribers":[{"SubscriptionType":"EMAIL","Address":"cloud-costs@example.com"}]}]'

A bill doubles overnight: Cost Explorer grouped by service shows "EC2-Other"; drilling down by usage type reveals NatGateway-Bytes after a new job started pulling data from S3 through NAT. Fix: add an S3 gateway endpoint.

Common mistakes

  • No budgets or alerts on any account, including sandboxes.
  • Ignoring data transfer and NAT costs in designs.
  • Never setting log retention or snapshot lifecycle.
  • Assuming the Free Tier covers everything.

How to answer in the interview

"AWS charges for what you use: compute by the second or hour, storage per GB-month, requests, and data transferred out or between AZs and regions. To avoid surprises I set up AWS Budgets with alerts on actual and forecast spend, enable Cost Anomaly Detection, and review Cost Explorer regularly grouped by service and tag. The usual surprises are idle instances, unattached EBS volumes and old snapshots, NAT gateway data processing, data transfer and test databases left running, so I also automate cleanup and use lifecycle and retention policies."

Likely follow-up questions

  • Bill doubled overnight: first check? Cost Explorer by service and usage type for the last days, plus anomaly alerts and CloudTrail for new resources.
  • Savings Plans vs Reserved Instances? Savings Plans commit to spend per hour across instance families; RIs commit to specific instance attributes.
  • How do you stop sandbox costs? Budgets with actions, scheduled shutdowns and automated cleanup tools.
