Which approaches exist for anomaly detection, and how do you choose one?

AI/ML & GenAI · concept · levels mid, senior

In one line

Choose by data type and labels: statistical baselines (z-score, MAD, seasonal) for single metrics, Isolation Forest or LOF for unlabelled multivariate data, autoencoders for complex signals, and supervised classifiers when labelled anomalies exist, validated by alert precision with domain experts.

Detailed explanation

Anomaly detection finds observations that differ from normal behaviour: fraud, intrusions, failing machines, sudden metric drops. Labels are usually scarce, anomalies are rare and "normal" drifts over time, which shapes the choice.

For a single time series such as checkout errors per minute, statistical methods are simple and explainable: z-scores, or robust versions using the median and median absolute deviation (MAD), seasonal baselines (compare with the same hour last week), STL decomposition and control charts. For multivariate tabular data without labels, Isolation Forest builds random trees and scores points by how few splits are needed to isolate them; anomalies isolate quickly. It is fast and scales well. Density and distance methods like Local Outlier Factor (LOF) flag points in regions much sparser than their neighbours; one-class SVM learns a boundary around normal data. Autoencoders trained on normal data reconstruct normal inputs well and anomalies badly, so high reconstruction error signals an anomaly; they suit high-dimensional sensor streams, logs or images.

When labelled anomalies exist, like confirmed chargebacks, a supervised classifier (often gradient boosting) is usually more accurate, but it only recognises patterns seen before. Teams therefore combine supervised models for known patterns with unsupervised detectors for novel ones. Selection criteria: data type and volume, label availability, latency, need for explanations, and alert fatigue. Evaluation without labels relies on domain experts reviewing top-ranked cases (precision@k), injected synthetic anomalies, and tracking how many alerts lead to action.

How it works

  1. Define what "anomalous" means with the business and the cost of misses versus false alarms.
  2. Start with a simple statistical baseline.
  3. Add Isolation Forest, LOF or an autoencoder for multivariate patterns.
  4. Score data and set a threshold from an alert budget (for example top 50 per day).
  5. Have experts label alerts, measure precision, and feed labels into a supervised model.

Example

from sklearn.ensemble import IsolationForest

iso = IsolationForest(n_estimators=300, contamination=0.005, random_state=0)
iso.fit(X_train)                       # mostly normal traffic
scores = -iso.score_samples(X_today)   # higher = more anomalous
alerts = X_today[scores > np.quantile(scores, 0.995)]

Common mistakes

  • Using plain mean and standard deviation on skewed or seasonal data.
  • Setting thresholds without an alert budget, causing alert fatigue.
  • Training an autoencoder on data that already contains many anomalies.
  • Relying only on supervised models and missing new attack types.

How to answer in the interview

"It depends on the data and labels. For a single metric I'd start with robust statistics and seasonal baselines. For unlabelled multivariate data, Isolation Forest is fast and effective, LOF works for local density differences, and autoencoders suit complex signals using reconstruction error. If we have confirmed anomalies like chargebacks, a supervised model is more accurate, combined with an unsupervised detector for new patterns. Because true rates are unknown, I'd set thresholds from an alert budget and measure precision with domain experts reviewing flagged cases."

Likely follow-up questions

  • Evaluating with almost no labels? Expert review of top-k alerts, injected synthetic anomalies and stability checks.
  • How do you handle seasonality? Compare against seasonal baselines or model residuals after decomposition.
  • How do you explain an alert? Show which features deviated most, using SHAP or per-feature reconstruction errors.
