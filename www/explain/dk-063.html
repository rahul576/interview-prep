How do seccomp, AppArmor and Linux capabilities harden containers?

Docker · concept · levels senior

In one line

Capabilities split root's powers, so run with --cap-drop ALL and add back only what is needed; seccomp filters system calls; AppArmor/SELinux add mandatory access control; no-new-privileges blocks setuid escalation; and --privileged disables nearly all of it.

Detailed explanation

These mechanisms apply least privilege at different levels, and together they make an exploited process much less useful to an attacker.

Linux capabilities break the all-powerful root into about 40 units such as NET_BIND_SERVICE (bind ports below 1024), CHOWN, NET_ADMIN (configure networking), SYS_PTRACE and the very broad SYS_ADMIN. Docker already starts containers with a reduced default set, but it still includes items most apps never need, like CHOWN, SETUID, NET_RAW and MKNOD. A hardened container uses --cap-drop ALL and adds back specific capabilities with --cap-add, often none at all for a non-root web service.

seccomp (secure computing mode) attaches a BPF filter to the process that allows or denies individual system calls. Docker's default profile blocks several dozen dangerous or rarely needed calls such as kexec_load, open_by_handle_at, init_module and unprivileged mount, which has neutralised many kernel exploits. Stricter custom profiles can allow only the syscalls an application uses. Kubernetes applies the runtime default only when you set seccompProfile: RuntimeDefault.

AppArmor (path-based, Ubuntu/Debian) and SELinux (label-based, RHEL/Fedora) are Linux Security Modules providing mandatory access control: even root inside the container cannot access files, mounts or devices outside its policy. Docker applies docker-default AppArmor or container_t SELinux labels automatically.

--security-opt no-new-privileges prevents processes from gaining privileges through setuid/setgid binaries or file capabilities. Combine with a non-root user and a read-only root filesystem. --privileged grants all capabilities, disables seccomp and LSM confinement and exposes all host devices; it should never be used for normal applications.

How it works

  1. The runtime computes the capability set and drops the rest.
  2. It loads the seccomp BPF filter before exec.
  3. It applies the AppArmor profile or SELinux label.
  4. It sets no_new_privs on the process.
  5. Kernel checks every privileged operation against these layers.

Example

docker run -d --name web \
  --user 10001 --read-only --tmpfs /tmp \
  --cap-drop ALL --cap-add NET_BIND_SERVICE \
  --security-opt no-new-privileges \
  --security-opt seccomp=/etc/docker/seccomp/web.json \
  registry.local/web:1.4
securityContext:
  runAsNonRoot: true
  allowPrivilegeEscalation: false
  readOnlyRootFilesystem: true
  capabilities: { drop: ["ALL"] }
  seccompProfile: { type: RuntimeDefault }

Common mistakes

  • Using --privileged to fix a permission error.
  • Adding SYS_ADMIN because one feature needs a mount.
  • Disabling seccomp (seccomp=unconfined) instead of extending the profile.
  • Assuming Kubernetes applies seccomp by default in every cluster.

How to answer in the interview

"Capabilities split root's powers into pieces like NET_BIND_SERVICE or SYS_ADMIN; I run with --cap-drop ALL and add back only what's needed. seccomp filters which system calls the process may make; Docker's default profile blocks dozens of dangerous calls and custom profiles can be stricter. AppArmor or SELinux add mandatory access control, confining files and resources even for root. no-new-privileges stops escalation through setuid binaries. Combined with a non-root user and read-only filesystem this is solid hardening, and --privileged turns almost all of it off, so it's never for normal apps."

Likely follow-up questions

  • How do you find needed capabilities? Start with none, test, and read denials in audit logs or use tracing tools.
  • How do you build a custom seccomp profile? Record syscalls with tools like strace or the Security Profiles Operator.
  • What does RuntimeDefault mean? The container runtime's default seccomp profile.
