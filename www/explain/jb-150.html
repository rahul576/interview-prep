What is JDBC, and how does a Java application communicate with a database?

Databases & SQL · concept · levels mid, senior

In one line

JDBC is the standard Java API (java.sql / javax.sql) for relational databases: a vendor driver implements it, and the application gets a Connection (from a pooled DataSource such as HikariCP), executes PreparedStatements, reads ResultSets, manages transactions and closes resources.

Detailed explanation

JDBC separates application code from database specifics. Interfaces such as Connection, PreparedStatement and ResultSet are defined by Java; each vendor ships a driver JAR (PostgreSQL, MySQL Connector/J, Oracle ojdbc) that implements them and speaks the database's wire protocol over TCP. Modern drivers are "type 4", pure Java. Since JDBC 4 drivers register themselves via the service loader, so Class.forName is no longer needed.

Opening a physical connection is expensive: TCP handshake, TLS, authentication, session setup. So production code obtains connections from a DataSource backed by a connection pool. HikariCP is the default in Spring Boot. "Closing" a pooled connection returns it to the pool.

The basic flow:

  1. Borrow a Connection.
  2. Create a PreparedStatement with ? placeholders and bind values.
  3. executeQuery() for SELECT, returning a ResultSet cursor, or executeUpdate() / executeBatch() for writes.
  4. Iterate the ResultSet, mapping columns to objects.
  5. Close ResultSet, statement and connection, ideally with try-with-resources.

Transactions default to auto-commit (every statement commits). For a unit of work you call setAutoCommit(false), then commit() or rollback(). SQLException carries a SQLState and vendor error code.

Higher-level tools all sit on top of JDBC: Spring's JdbcTemplate/JdbcClient, jOOQ, MyBatis, and JPA/Hibernate. Spring's @Transactional binds a connection to the thread and handles commit and rollback for you.

How it works

  1. The pool opens N physical connections at startup through the driver.
  2. A thread borrows one; the pool tracks it as active.
  3. The driver sends SQL and parameters using the database protocol.
  4. The database returns rows, streamed according to fetch size.
  5. Commit or rollback ends the transaction.
  6. Close returns the connection to the pool for reuse.

Example

// HikariCP DataSource (Spring Boot does this from application.yml)
HikariConfig cfg = new HikariConfig();
cfg.setJdbcUrl("jdbc:postgresql://db:5432/shop");
cfg.setUsername("app"); cfg.setPassword(System.getenv("DB_PASS"));
cfg.setMaximumPoolSize(20);
DataSource ds = new HikariDataSource(cfg);

String sql = "SELECT id, total FROM orders WHERE customer_id = ?";
try (Connection con = ds.getConnection();
     PreparedStatement ps = con.prepareStatement(sql)) {
    ps.setLong(1, 42L);
    try (ResultSet rs = ps.executeQuery()) {
        while (rs.next()) {
            System.out.println(rs.getLong("id") + " " + rs.getBigDecimal("total"));
        }
    }
}

Common mistakes

  • Using DriverManager.getConnection per request in production.
  • Not closing connections, leaking them from the pool.
  • Building SQL with string concatenation.
  • Forgetting to restore auto-commit or roll back on exceptions in manual transaction code.

How to answer in the interview

"JDBC is Java's standard API for relational databases. The vendor's driver implements it and speaks the database protocol, so my code is the same for Postgres or MySQL. In practice I get a Connection from a DataSource backed by a pool like HikariCP, because opening connections is expensive. I create a PreparedStatement with bind parameters, execute it and iterate the ResultSet. For transactions I turn off auto-commit and commit or roll back, or let Spring's @Transactional do it. Everything is closed with try-with-resources. JdbcTemplate, jOOQ, MyBatis and Hibernate are all built on top of JDBC."

Likely follow-up questions

  • What if you forget to close a pooled connection? It is never returned; the pool exhausts and requests time out.
  • What is fetch size? How many rows the driver fetches per round trip; important for streaming large results.
  • What does auto-commit mean? Each statement is its own transaction, committed immediately.
