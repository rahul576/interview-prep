What is dynamic programming? Explain it with the climbing stairs or coin change problem.

DSA: Algorithms & DP · concept · levels mid

In one line

Dynamic programming solves problems with overlapping subproblems and optimal substructure by storing subproblem results instead of recomputing them. It can be top-down memoization or bottom-up tabulation. Climbing stairs: ways(n) = ways(n-1) + ways(n-2) goes from exponential to O(n) (O(1) space). Coin change: dp[a] = 1 + min(dp[a - coin]).

Detailed explanation

Two properties signal DP:

  • Optimal substructure: an optimal solution is built from optimal solutions to smaller subproblems.
  • Overlapping subproblems: the same subproblems recur many times in a naive recursion. Without overlap, plain divide and conquer (merge sort) is enough.

Climbing stairs. You can climb 1 or 2 steps at a time. How many ways are there to reach step n? The last move was either 1 step (from n-1) or 2 steps (from n-2), so ways(n) = ways(n-1) + ways(n-2), with ways(0) = 1 and ways(1) = 1. That is Fibonacci. The naive recursion branches twice per call, roughly O(1.6ⁿ). ways(3) is computed again and again.

Two ways to fix it:

  • Memoization (top-down): keep the recursion, but cache results in a map or array. It is easy to derive from the recurrence and computes only the states you need, but it has recursion depth limits.
  • Tabulation (bottom-up): fill an array from the base cases upward. There is no recursion, and it often allows space optimisation. Here only the last two values matter, so it is O(n) time and O(1) space.

Coin change (minimum coins). Given coins [1, 2, 5] and an amount, dp[a] = the fewest coins to make a. dp[0] = 0, and dp[a] = 1 + min over coins c ≤ a of dp[a - c], or ∞ if unreachable. That is O(amount × coins) time and O(amount) space. Counting the number of ways instead uses dp[a] += dp[a - c] with the coin loop outside, so combinations aren't counted as permutations.

A recipe for DP problems: define the state (what does dp[i] mean?), write the recurrence (the choice made at the last step), set the base cases, pick the evaluation order, then optimise space.

How it works

  1. Spot the signals: "count the ways", "min/max", "is it possible", with choices at each step.
  2. Define the state dp[i] (or dp[i][j]).
  3. Write the recurrence from the last decision.
  4. Initialise the base cases.
  5. Compute top-down with a memo or bottom-up in dependency order.
  6. Reduce space if only recent states are needed.

Example

int climbStairs(int n) {
    int prev = 1, cur = 1;                 // ways(0), ways(1)
    for (int i = 2; i <= n; i++) { int next = prev + cur; prev = cur; cur = next; }
    return cur;
}

int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);           // "infinity"
    dp[0] = 0;
    for (int a = 1; a <= amount; a++)
        for (int c : coins)
            if (c <= a) dp[a] = Math.min(dp[a], dp[a - c] + 1);
    return dp[amount] > amount ? -1 : dp[amount];
}
// coins [1,2,5], amount 11 -> 3 (5+5+1)

Common mistakes

  • Jumping to code without defining what dp[i] means.
  • Wrong base cases (dp[0]).
  • Using Integer.MAX_VALUE as infinity and then adding 1, which overflows.
  • Mixing up the loop order when counting combinations versus permutations.

How to answer in the interview

"Dynamic programming applies when a problem has optimal substructure and overlapping subproblems, so I can store results instead of recomputing them. For climbing stairs with one or two steps, the number of ways to reach n is ways(n-1) plus ways(n-2). Naive recursion is exponential, but with memoization or a bottom-up table it's O(n), and since only the last two values matter, O(1) space. For coin change, dp of an amount is one plus the minimum of dp of amount minus each coin, which is O(amount times coins). My approach is always: define the state, write the recurrence, set the base cases, then optimise space."

Likely follow-up questions

  • How do you recognise DP? Choices at each step, "count, min/max or feasible", and a brute-force recursion that repeats subproblems.
  • Number of ways to make change? dp[a] += dp[a-c] with coins in the outer loop.
  • Why does greedy fail for coin change? Some denominations (1, 3, 4 for 6) make the locally best choice globally worse.
