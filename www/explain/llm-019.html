How do temperature and other sampling settings affect LLM behaviour in production, and can outputs be made deterministic?

LLMOps & RAG · concept · levels mid, senior

In one line

Temperature rescales the next-token distribution (low = focused, high = diverse), top_p/top_k limit candidate tokens; use low temperature for extraction, classification, code and tools, higher for creative work; even temperature 0 is not fully deterministic due to floating point, batching and provider updates, so design for variability.

Detailed explanation

At each step the model outputs logits, one score per vocabulary token, which softmax turns into probabilities. Temperature divides the logits before softmax: below 1 it sharpens the distribution so the top tokens dominate; above 1 it flattens it, giving lower-probability tokens more chance. Temperature 0 is treated as greedy decoding (always pick the top token).

top_p (nucleus sampling) keeps the smallest set of tokens whose cumulative probability reaches p, for example 0.9, and samples only among them; top_k keeps the k most likely tokens; min_p keeps tokens above a fraction of the top token's probability. Usually tune temperature or top_p, not both aggressively.

Guidance: extraction, classification, SQL, code, tool calling, factual Q&A: low temperature (0 to 0.3) for focus and repeatability. Brainstorming, marketing copy, varied responses: 0.7 to 1.0. Note that some reasoning models fix or restrict sampling parameters, and providers document recommended defaults per model, so check them.

Determinism. Even greedy decoding often gives different outputs across runs. Reasons: GPU floating-point arithmetic is not associative, and results depend on kernel choice and the order of reductions; batching with other users' requests changes matrix shapes and therefore kernels and numerics (batch-invariant kernels can fix this but are rarely default); mixture-of-experts routing may be affected by batch composition; and hosted providers update models, infrastructure or routing behind the same alias. Some APIs accept a seed for best-effort reproducibility, but it is not guaranteed. Pinning dated model versions helps.

So production systems should design for variability: evaluate on multiple samples and report pass rates, validate outputs structurally, avoid parsing exact phrasing, cache answers where repeatability matters, and log prompts, parameters and model versions for debugging.

How it works

  1. Model produces logits for all tokens.
  2. Divide by temperature; apply softmax.
  3. Filter with top_k / top_p / min_p.
  4. Sample a token (or take argmax at temperature 0).
  5. Append and repeat; stop at stop sequence or max tokens.

Example

extract = client.chat.completions.create(model=MODEL, temperature=0, seed=42,
    messages=[{"role": "user", "content": f"Extract the order id from: {email}"}])
ideas = client.chat.completions.create(model=MODEL, temperature=0.9, top_p=0.95, n=3,
    messages=[{"role": "user", "content": "Suggest names for a new coffee brand"}])

Common mistakes

  • Assuming temperature 0 means identical output forever.
  • High temperature on tool-calling agents, causing erratic actions.
  • Tuning temperature to fix a prompt or retrieval problem.
  • Evaluating with a single sample per test case.

How to answer in the interview

"The model outputs a probability distribution for the next token. Temperature scales it: low values make the most likely tokens dominate, high values flatten it for more diverse but riskier output, and top_p or top_k restrict sampling to the likeliest candidates. I use low temperature for extraction, classification, code and tool use, higher for creative tasks. Even at zero, outputs are not fully deterministic because of floating-point non-associativity, batching with other requests and provider-side updates; seeds help but are best effort. So I design for variability: evaluate over multiple samples, validate outputs and pin model versions."

Likely follow-up questions

  • Different answers at different times of day? Different batch composition and load-based routing change numerics; provider updates too.
  • Temperature vs top_p? Temperature reshapes the distribution; top_p truncates its tail.
  • How to get reproducible evals? Fixed versions, temperature 0, multiple runs and pass-rate thresholds.
