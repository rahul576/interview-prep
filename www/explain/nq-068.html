How would you find the product with the maximum price?

Coding Exercises · scenario · levels mid

In one line

products.stream().max(Comparator.comparingDouble(Product::getPrice)) returns an Optional<Product> because the list may be empty; use mapToDouble(...).max() if you only need the price, Collectors.maxBy per group, and decide how to handle ties.

Detailed explanation

Stream.max(comparator) is a terminal reduction that walks the stream once (O(n)) and keeps the element that the comparator considers greatest. Comparator.comparingDouble(Product::getPrice) compares prices as primitives with Double.compare, avoiding boxing.

Optional. If the list is empty, there is no maximum, so max returns Optional.empty(). Handle it deliberately:

  • orElseThrow() when an empty list is a bug or violates a precondition.
  • ifPresent(p -> ...) to act only when present.
  • map(Product::getName).orElse("n/a") for display.

Calling get() without checking defeats the purpose.

Only the price. products.stream().mapToDouble(Product::getPrice).max() returns an OptionalDouble with just the highest value — cheaper and clearer if you do not need the product itself.

Per category. Inside groupingBy, use Collectors.maxBy(Comparator.comparingDouble(Product::getPrice)), which yields Map<String, Optional<Product>>. Since every group has at least one element, the Optional is always present; unwrap it with collectingAndThen(maxBy(...), Optional::get), or use Collectors.toMap(Product::getCategory, Function.identity(), BinaryOperator.maxBy(cmp)) for a Map<String, Product> directly.

Ties. If several products share the highest price, max returns one of them; in the current JDK a sequential stream keeps the first one encountered, because the reduction uses BinaryOperator.maxBy, but the specification does not promise this. If the business needs a deterministic choice, add a tie-breaker (thenComparing(Product::getName)). To return all top products, compute the maximum price first, then filter(p -> p.getPrice() == max) — two passes, still O(n) — or group by price into a TreeMap and take the last entry.

How it works

  1. Build a comparator by price.
  2. max reduces the stream, keeping the greater element at each step.
  3. An empty stream yields Optional.empty.
  4. The caller unwraps the Optional explicitly.

Example

Product mostExpensive = products.stream()
        .max(Comparator.comparingDouble(Product::getPrice))
        .orElseThrow(() -> new IllegalStateException("No products"));

OptionalDouble highestPrice = products.stream()
        .mapToDouble(Product::getPrice).max();

Map<String, Product> topPerCategory = products.stream()
        .collect(Collectors.toMap(Product::getCategory, Function.identity(),
                 BinaryOperator.maxBy(Comparator.comparingDouble(Product::getPrice))));

// all products sharing the top price
double max = highestPrice.orElse(Double.NaN);
List<Product> allTop = products.stream()
        .filter(p -> Double.compare(p.getPrice(), max) == 0)
        .toList();

Common mistakes

  • Calling .get() on the Optional without checking.
  • Sorting the whole list to take the first element (O(n log n)).
  • Ignoring ties when the business expects all top items.
  • Using comparing(Product::getPrice) and boxing needlessly.

How to answer in the interview

"I'd write products.stream().max(Comparator.comparingDouble(Product::getPrice)). max takes a comparator and returns an Optional, because the list may be empty, so I'd handle it with orElseThrow or ifPresent. If I only need the price, mapToDouble(Product::getPrice).max() gives an OptionalDouble. Per category I'd use groupingBy with Collectors.maxBy, or toMap with BinaryOperator.maxBy. If several products share the top price, max returns just one; to get all of them, I find the max price first, then filter by it."

Likely follow-up questions

  • How would you return all products sharing the highest price? Compute the max price, then filter by it.
  • Why is the per-group Optional always present? groupingBy only creates groups with at least one element.
  • What is the complexity? O(n), a single pass.
