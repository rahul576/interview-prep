What is content negotiation?

REST & API Design · concept · levels mid, senior

In one line

Content negotiation is how client and server agree on a representation format: the client sends Accept for the response it wants and Content-Type for the body it sends; Spring's HttpMessageConverters pick the format, and mismatches give 406 Not Acceptable or 415 Unsupported Media Type.

Detailed explanation

A resource such as /orders/42 can be represented in several formats: JSON, XML, CSV, PDF. HTTP lets the client state its preferences instead of the server guessing.

Request side.

  • Accept: application/json (or application/xml, or a list with quality values: application/json;q=1.0, application/xml;q=0.5) says which response formats the client can handle.
  • Content-Type: application/json describes the format of the request body the client is sending.

Server side. The server picks the best matching representation it supports and sets Content-Type on the response. If it cannot produce any acceptable format, it returns 406 Not Acceptable. If it cannot read the request body's media type, it returns 415 Unsupported Media Type. When the response varies by a request header, the server should send Vary: Accept so caches store variants separately.

In Spring MVC, content negotiation is handled by HttpMessageConverters. Jackson's MappingJackson2HttpMessageConverter handles JSON by default; adding jackson-dataformat-xml registers an XML converter automatically in Spring Boot. On a mapping, produces limits response types and consumes limits accepted request types: @GetMapping(value = "/{id}", produces = {"application/json", "application/xml"}). Spring determines the requested type from the Accept header by default; a query parameter strategy (?format=xml) can be enabled via spring.mvc.contentnegotiation.favor-parameter=true. Path extensions (/orders/42.json) are deprecated and disabled for security reasons.

Negotiation also applies to other dimensions: Accept-Language for localised messages, Accept-Encoding for compression (gzip, br), and custom vendor media types for versioning, such as application/vnd.shop.order.v2+json.

How it works

  1. Client sends Accept (and Content-Type with a body).
  2. Server finds converters able to read the body (else 415).
  3. Server matches Accept against produces and converters (else 406).
  4. Response written with the chosen Content-Type and Vary: Accept.

Example

@RestController
@RequestMapping("/orders")
class OrderController {
    @GetMapping(value = "/{id}", produces = { MediaType.APPLICATION_JSON_VALUE, MediaType.APPLICATION_XML_VALUE })
    OrderDto get(@PathVariable long id) { return service.get(id); }

    @PostMapping(consumes = MediaType.APPLICATION_JSON_VALUE, produces = MediaType.APPLICATION_JSON_VALUE)
    ResponseEntity<OrderDto> create(@RequestBody NewOrder o) { ... }

    @GetMapping(value = "/{id}", produces = "application/vnd.shop.order.v2+json")
    OrderV2Dto getV2(@PathVariable long id) { ... }
}
curl -H "Accept: application/xml" https://api.shop.com/orders/42
curl -X POST -H "Content-Type: text/plain" -d 'x' https://api.shop.com/orders   # 415

Common mistakes

  • Confusing Accept (desired response) with Content-Type (body sent).
  • Forgetting Vary: Accept when responses differ by format.
  • Relying on path extensions like .json.
  • Returning 400 instead of 406/415 for format problems.

How to answer in the interview

"Content negotiation is how client and server agree on the format of a representation. The client sends an Accept header, such as application/json or application/xml, saying what it can handle, and Content-Type describes the body it's sending. The server picks a matching format and sets Content-Type on the response. In Spring MVC, HttpMessageConverters do the work: Jackson for JSON, and XML if the Jackson XML module is on the classpath, and I can restrict endpoints with produces and consumes. If nothing acceptable exists the server returns 406, and an unsupported request body gives 415. Language and compression are negotiated the same way."

Likely follow-up questions

  • How could content negotiation be used for API versioning? With vendor media types like application/vnd.shop.v2+json in the Accept header.
  • What does Vary: Accept do? Tells caches to store separate variants per Accept value.
  • What are quality values? q weights expressing client preference among formats.
