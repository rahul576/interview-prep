How would you represent groups of anagrams as key-value pairs?

DSA: Arrays & Strings · concept · levels entry

In one line

Use a Map<String, List<String>> where the key is the anagram signature (like "aet") and the value is the list of words with that signature; add with computeIfAbsent, and use a LinkedHashMap to keep groups in first-seen order.

Detailed explanation

Key–value grouping is the natural shape for this problem:

  • Key: a canonical signature shared by all anagrams, such as the sorted letters.
  • Value: all original words that produced that signature.

For the input ["eat", "tea", "tan", "ate", "nat", "bat"] the map is:

  • "aet" → [eat, tea, ate]
  • "ant" → [tan, nat]
  • "abt" → [bat]

Adding words is one line with computeIfAbsent(key, k -> new ArrayList<>()).add(word): it creates the list the first time a key is seen and returns the existing list otherwise. This replaces the older if (!map.containsKey(key)) map.put(key, new ArrayList<>()) pattern, which does two lookups. Streams can do the same with Collectors.groupingBy(this::key).

Choosing the map implementation:

  • HashMap: fastest, but iteration order is unspecified.
  • LinkedHashMap: preserves the order in which keys were first inserted, so groups appear in the order of their first word, which interviewers often ask for.
  • TreeMap: sorts groups by key, at O(log g) per operation.

Returning results: if the caller expects List<List<String>>, return new ArrayList<>(groups.values()). If they only want real groups (more than one word), filter: groups.values().stream().filter(g -> g.size() > 1).toList(). If they want groups sorted internally, sort each list, or use a TreeSet as the value if duplicates should be removed.

If the caller wants counts only, use Map<String, Integer> with merge(key, 1, Integer::sum), or groupingBy(key, counting()).

How it works

  1. Create the map (LinkedHashMap for ordering).
  2. For each word, compute its signature.
  3. computeIfAbsent the list for that signature and add the word.
  4. Return values(), optionally filtered or sorted.

Example

Map<String, List<String>> groups = new LinkedHashMap<>();
for (String w : List.of("eat", "tea", "tan", "ate", "nat", "bat")) {
    char[] c = w.toCharArray();
    Arrays.sort(c);
    groups.computeIfAbsent(new String(c), k -> new ArrayList<>()).add(w);
}
// {aet=[eat, tea, ate], ant=[tan, nat], abt=[bat]}

List<List<String>> all = new ArrayList<>(groups.values());
List<List<String>> realGroups = groups.values().stream()
        .filter(g -> g.size() > 1)
        .toList();                         // [[eat, tea, ate], [tan, nat]]

// Stream equivalent
Map<String, List<String>> viaStream = Stream.of("eat", "tea", "tan")
        .collect(Collectors.groupingBy(Main::sortedKey, LinkedHashMap::new, Collectors.toList()));

Common mistakes

  • Using HashMap and promising a particular output order.
  • Returning the live values() view when the caller may modify it.
  • Storing the normalised word instead of the original.
  • Double lookups with containsKey + get + put.

How to answer in the interview

"I'd use a Map<String, List<String>> where the key is the anagram signature, like the sorted letters aet, and the value is the list of words with that signature: aet maps to eat, tea and ate, ant to tan and nat, abt to bat. Adding is one line with computeIfAbsent. If the groups should come out in the order their first word appeared, I'd use a LinkedHashMap, and if the caller wants a list of lists I'd return new ArrayList of the map values."

Likely follow-up questions

  • What if the caller wants only groups with more than one word? Filter the values by size() > 1.
  • Why computeIfAbsent? One lookup, creates the list lazily, concise.
  • How would you remove duplicate words in a group? Use a LinkedHashSet as the value.
