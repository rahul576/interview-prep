What is the difference between throw and throws, and between Error and Exception?

Exceptions · concept · levels entry

In one line

throw is a statement that raises an exception instance; throws is a method-signature clause declaring exceptions it may propagate; Error signals serious JVM/environment problems you normally do not catch, while Exception signals conditions an application may handle.

Detailed explanation

throw takes one Throwable object: throw new IllegalArgumentException("amount must be positive");. Execution of the current block stops and the JVM looks up the call stack for a matching catch. You can throw only one object at a time, and it can be a newly created or an already caught exception.

throws appears in a method or constructor declaration: void load(Path p) throws IOException. It is part of the method's contract. For checked exceptions (subclasses of Exception that are not RuntimeException) it is mandatory: the compiler forces either a catch or a throws declaration. For unchecked exceptions it is optional and purely documentary. An overriding method may not declare broader checked exceptions than the method it overrides.

The hierarchy: Throwable has two subclasses.

  • Error: problems from the JVM or environment such as OutOfMemoryError, StackOverflowError, NoClassDefFoundError, ExceptionInInitializerError. The application generally cannot recover in a meaningful way, so you do not catch them, except perhaps at the very top level to log and exit.
  • Exception: conditions a program might anticipate and handle. Split into checked (IOException, SQLException, InterruptedException) and unchecked RuntimeException (NullPointerException, IllegalArgumentException, IllegalStateException), which usually indicate programming errors or business rule violations.

Catching Throwable or Error broadly is dangerous because after an OOM the JVM state may be inconsistent.

How it works

  1. throw creates or rethrows an exception object, capturing a stack trace at construction.
  2. The JVM unwinds frames, running finally blocks, until a matching catch.
  3. The compiler checks that checked exceptions are caught or declared with throws.
  4. If nothing catches it, the thread's uncaught exception handler prints it and the thread ends.

Example

public Account withdraw(Account acc, BigDecimal amount) throws InsufficientFundsException {
    if (amount.signum() <= 0)
        throw new IllegalArgumentException("amount must be positive"); // unchecked, no throws needed
    if (acc.balance().compareTo(amount) < 0)
        throw new InsufficientFundsException(acc.id());                 // checked, declared
    return acc.debit(amount);
}

Common mistakes

  • Confusing throw and throws in syntax.
  • Catching Error or Throwable and continuing as if nothing happened.
  • Declaring throws Exception on everything, which hides what can really fail.
  • Thinking RuntimeException is not a subclass of Exception.

How to answer in the interview

"throw is a statement that actually throws an exception object, like throw new IllegalArgumentException. throws is part of a method signature that declares which exceptions the method may propagate; for checked exceptions it's mandatory unless you catch them. Both Error and Exception extend Throwable. Errors are serious JVM or environment problems such as OutOfMemoryError or StackOverflowError that applications normally shouldn't catch. Exceptions are conditions the application can handle, split into checked ones like IOException and unchecked RuntimeExceptions like IllegalArgumentException."

Likely follow-up questions

  • Can a method declare throws for an unchecked exception? Does it matter? Yes; it compiles and documents intent but the compiler doesn't enforce handling.
  • Is NoClassDefFoundError checked? No, it's an Error.
  • Can an overriding method throw a new checked exception? No, only the same, narrower or none.
