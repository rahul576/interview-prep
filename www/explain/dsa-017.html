How do you validate that a binary tree is a binary search tree?

DSA: Trees & Graphs · concept · levels entry, mid

In one line

Recursively pass a (min, max) range that every node must lie strictly within, narrowing it to (min, node) going left and (node, max) going right. Use nullable or long bounds to avoid integer-limit bugs. Alternatively, an inorder traversal must be strictly increasing. Both are O(n).

Detailed explanation

A BST requires that every node in the left subtree is smaller than the node, and every node in the right subtree is larger. That is not just the immediate children. The classic wrong solution checks only left.val < node.val < right.val. It accepts this invalid tree:

      5
     / \
    3   8
       / \
      4   9     <- 4 is in 5's right subtree but 4 < 5

Node 8's children are fine locally, but 4 violates the ancestor constraint.

Bounds approach. Each node inherits a valid range from its ancestors. The root's range is (-∞, +∞). Going left, the upper bound becomes the current value. Going right, the lower bound becomes the current value. If any node falls outside its range, the tree is invalid.

Bound representation: if you use Integer.MIN_VALUE/MAX_VALUE as sentinels, a tree containing those exact values is wrongly rejected. Use Long bounds or nullable Integer (null meaning unbounded).

Inorder approach. Inorder traversal of a valid BST yields a strictly increasing sequence. Traverse while remembering the previous value (as an object or null initially), and fail as soon as curr <= prev. It is O(n) time, O(h) space, and can stop early.

Duplicates: clarify the definition. Most problems require strictly less and greater. Some allow duplicates on one side (<= left), and then the comparisons change accordingly.

How it works

  1. Call valid(root, null, null).
  2. If the node is null, return true.
  3. If low != null && val <= low or high != null && val >= high, return false.
  4. Return valid(left, low, val) && valid(right, val, high).

Example

public boolean isValidBST(TreeNode root) {
    return valid(root, null, null);
}
private boolean valid(TreeNode n, Integer low, Integer high) {
    if (n == null) return true;
    if ((low != null && n.val <= low) || (high != null && n.val >= high)) return false;
    return valid(n.left, low, n.val) && valid(n.right, n.val, high);
}

// Inorder variant
private Integer prev = null;
boolean inorder(TreeNode n) {
    if (n == null) return true;
    if (!inorder(n.left)) return false;
    if (prev != null && n.val <= prev) return false;
    prev = n.val;
    return inorder(n.right);
}

Common mistakes

  • Comparing only parent and child.
  • Using Integer.MIN_VALUE/MAX_VALUE sentinels, which fail on trees containing those values.
  • Using < instead of <=, which accepts duplicates when they aren't allowed.
  • Collecting the full inorder list when an early-exit comparison suffices (that is still O(n), but uses more memory).

How to answer in the interview

"The common mistake is only checking each node against its children. Every node in the left subtree must be smaller than all its ancestors on that path, not just its parent. So I recurse with a range: each node must lie strictly between a lower and an upper bound, and I narrow the upper bound going left and the lower bound going right. I use nullable or long bounds so values at the integer limits work. Alternatively, an inorder traversal must be strictly increasing, so I can track the previous value and fail early. Both are O(n) time and O(h) space."

Likely follow-up questions

  • kth smallest in a BST? Inorder traversal, stopping at the kth node. Augment nodes with subtree sizes for O(h).
  • Duplicates allowed? Define which side, and use <= on that side.
  • Fix a BST with two swapped nodes? Inorder, find the two inversions, swap their values.
