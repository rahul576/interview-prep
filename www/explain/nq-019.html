What are the key features introduced in Java 8?

Java 8+ Features · concept · levels entry

In one line

Java 8 (March 2014) added lambda expressions, functional interfaces, method references, the Stream API, default and static interface methods, Optional, the java.time Date/Time API and CompletableFuture, plus smaller changes such as Base64 and Metaspace replacing PermGen.

Detailed explanation

Java 8 brought functional programming into mainstream Java while staying backward compatible.

Lambdas (x -> x * 2) let you pass behaviour as values, targeting functional interfaces, interfaces with one abstract method, with standard ones in java.util.function (Function, Predicate, Supplier, Consumer). Method references (String::toUpperCase) shorten lambdas that only call a method.

The Stream API offers declarative, lazy pipelines (filter, map, reduce, collect) and one-word parallelism with parallelStream(). To retrofit it onto existing collections, interfaces needed default methods (bodies inherited by implementations) and static methods (helpers like Comparator.comparing), so Collection.stream() could be added without breaking every implementation.

Optional models a possibly absent return value. java.time replaced the mutable Date/Calendar with immutable types like LocalDate, Instant, ZonedDateTime, Duration. CompletableFuture enabled composable async code.

Smaller but useful items: java.util.Base64; Map.getOrDefault, computeIfAbsent, merge; String.join; StampedLock, LongAdder; Arrays.parallelSort; repeatable and type annotations; the Nashorn JavaScript engine (removed in Java 15); and Metaspace replacing PermGen for class metadata, ending OutOfMemoryError: PermGen space.

How it works

  1. Lambdas compile to invokedynamic plus LambdaMetafactory.
  2. Default methods let JDK interfaces gain stream-related methods.
  3. Streams evaluate lazily when a terminal operation runs.
  4. java.time objects are immutable; operations return new instances.

Example

// Lambdas + streams + method references
Map<String, Long> countByDept = employees.stream()
    .filter(e -> e.getSalary() > 40_000)
    .collect(Collectors.groupingBy(Employee::getDept, Collectors.counting()));

// Default method on a JDK interface
employees.removeIf(Employee::isInactive);
employees.sort(Comparator.comparing(Employee::getName));

// Optional and java.time
String email = repo.findById(7).map(Employee::getEmail).orElse("n/a");
long days = ChronoUnit.DAYS.between(LocalDate.of(2026, 1, 1), LocalDate.now());

// CompletableFuture
CompletableFuture.supplyAsync(this::fetchRates).thenAccept(this::publish);
String token = Base64.getEncoder().encodeToString("user:pass".getBytes(StandardCharsets.UTF_8));

Common mistakes

  • Mixing in later features (var, records, List.of) as if they were Java 8.
  • Listing features without explaining their benefit.
  • Forgetting default methods and java.time.
  • Saying Nashorn is still current.

How to answer in the interview

"Java 8, from 2014, was the biggest change since generics. It added lambdas and functional interfaces, bringing a functional style, and method references like String::toUpperCase. The Stream API gave declarative processing of collections, including parallel streams. Interfaces got default and static methods so they could evolve, which is how Collection got stream. Optional models absent values, java.time replaced Date and Calendar with immutable thread-safe types, and CompletableFuture enabled async composition. Smaller things include Base64 and Metaspace replacing PermGen. The feature I use most is streams with lambdas, because they make collection processing concise and readable."

Likely follow-up questions

  • Which Java 8 feature do you use most, and why? Streams and lambdas, for readable collection processing; java.time for correct date handling.
  • What is Metaspace? Native-memory storage for class metadata that replaced PermGen.
  • Is Java 8 still supported? Some vendors still offer support, but new projects use 17, 21 or 25.
