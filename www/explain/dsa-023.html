How do you find the maximum depth and the diameter of a binary tree?

DSA: Trees & Graphs · concept · levels mid

In one line

Max depth = 1 + max(depth(left), depth(right)), with null = 0. The diameter (the longest path between any two nodes, in edges) passes through some "peak" node as leftHeight + rightHeight. So run a single DFS that returns heights and updates a global maximum. Both are O(n) time, O(h) space.

Detailed explanation

Maximum depth is the number of nodes on the longest root-to-leaf path. Recursive postorder: a null subtree has depth 0, otherwise the node adds 1 to the deeper of its children. BFS also works. Count the levels.

Diameter is trickier. The longest path between two nodes doesn't have to pass through the root. It might live entirely inside a deep left subtree. Every path has a single highest node (its "peak"). At that peak, the path goes down into the left subtree as far as possible and down into the right subtree as far as possible. So the path length through a node = height(left) + height(right), measured in edges if height(null) = 0 and height(leaf) = 1.

The naive method computes heights separately for every node, which is O(n²) on skewed trees, because each height call re-walks the subtree. The efficient method does it in one postorder pass. The recursive function returns the height to its parent, and as a side effect updates best = max(best, left + right). Every node is computed once, so it is O(n).

Clarify the definition: LeetCode measures the diameter in edges. Some textbooks count nodes (edges + 1).

The same "return one thing, track another globally" pattern solves many tree problems:

  • Balanced check: return the height, or -1 if any subtree is unbalanced (|L-R| > 1).
  • Max path sum: return the best downward path gain, track the best path through the node.
  • Longest univalue path.

For very deep (skewed) trees, recursion depth equals n, so mention an iterative postorder if stack overflow is a concern.

How it works

  1. height(node): if null, return 0.
  2. L = height(node.left), R = height(node.right).
  3. diameter = max(diameter, L + R).
  4. Return 1 + max(L, R).
  5. The max depth is height(root). The diameter is the global value.

Example

class TreeMetrics {
    private int diameter = 0;

    int maxDepth(TreeNode n) {
        if (n == null) return 0;
        return 1 + Math.max(maxDepth(n.left), maxDepth(n.right));
    }

    int diameterOfBinaryTree(TreeNode root) {
        height(root);
        return diameter;                 // in edges
    }
    private int height(TreeNode n) {
        if (n == null) return 0;
        int l = height(n.left), r = height(n.right);
        diameter = Math.max(diameter, l + r);
        return 1 + Math.max(l, r);
    }
}
//        1
//       / \
//      2   3        depth = 3, diameter = 3 (4-2-1-3 or 5-2-1-3)
//     / \
//    4   5

Common mistakes

  • Assuming the diameter passes through the root.
  • Calling height() inside a loop over nodes, which is O(n²).
  • Mixing up the edge and node counts.
  • Returning the diameter from the recursive function instead of the height.

How to answer in the interview

"The maximum depth is recursive: zero for a null node, otherwise one plus the larger of the left and right depths. For the diameter, the longest path between any two nodes has some highest node where it equals the left height plus the right height, and that's not necessarily the root. So I do one DFS that returns each subtree's height, and at each node I update a global maximum with left plus right. Each node is visited once, so both are O(n) time and O(h) space. I'd confirm whether the diameter is measured in edges or nodes."

Likely follow-up questions

  • Height-balanced in one pass? Return -1 as a sentinel when any subtree is unbalanced and short-circuit.
  • Binary tree maximum path sum? Same pattern: return the max downward gain (clamped at 0), track left + node + right.
  • Diameter of a general tree or graph? BFS from any node to the farthest node, then BFS again from there.
