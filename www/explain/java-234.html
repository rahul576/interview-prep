What is the var keyword, and when should you not use it?

Java 8+ Features · concept · levels entry, mid

In one line

var (Java 10) is local variable type inference: the compiler infers the static type from the initialiser, so Java stays statically typed; it works only for locals with an initialiser, loop variables and lambda parameters, and should be avoided when the type isn't obvious.

Detailed explanation

var is not dynamic typing like JavaScript. When you write var orders = new ArrayList<Order>();, the compiler fixes the type as ArrayList<Order> at compile time, and the bytecode is identical to declaring it explicitly. Reassigning a different type fails to compile.

Where it is allowed: local variables with an initialiser, enhanced-for and classic for loop variables, try-with-resources variables, and (Java 11) lambda parameters, mainly so you can annotate them: (@NonNull var x, var y) -> .... Where it is not allowed: fields, method parameters, return types, catch parameters, variables without an initialiser, var x = null;, array initialisers like var a = {1, 2};, and lambdas or method references without a target type. Technically var is a reserved type name, not a keyword, so existing variables named var still compile.

Readability guideline: use it when the right-hand side makes the type obvious (constructors, factory methods with telling names, long generic types) or when the variable's name carries the meaning. Avoid it when the initialiser is a method call that hides the type (var result = service.process(x);), with numeric literals where the type matters (var total = 0; is int, not long), and with the diamond operator, because var list = new ArrayList<>(); infers ArrayList<Object>.

How it works

  1. The compiler sees var and requires an initialiser.
  2. It computes the initialiser's static type.
  3. That type, not an interface type, becomes the variable's declared type.
  4. All later uses are checked against it as normal.

Example

var customersByCity = new HashMap<String, List<Customer>>();   // good: type obvious
for (var entry : customersByCity.entrySet()) {                  // good: avoids Map.Entry<String, List<Customer>>
    process(entry.getKey(), entry.getValue());
}
try (var in = Files.newBufferedReader(path)) { ... }            // allowed

var result = pricingEngine.evaluate(cart);    // unclear: what type is this?
var count = 0;                                // int, may overflow if you meant long
var list = new ArrayList<>();                 // ArrayList<Object>!

// Not allowed:
// private var name = "x";        // field
// var x;                         // no initialiser
// var nothing = null;            // cannot infer

Common mistakes

  • Believing var makes Java dynamically typed.
  • Combining var with diamond and getting ArrayList<Object>.
  • Expecting the variable to be typed as the interface (it's the concrete class).
  • Using it everywhere and hurting readability in code reviews.

How to answer in the interview

"var, from Java 10, is local variable type inference. The compiler infers the type from the initialiser, but it's still statically typed, nothing dynamic happens at runtime. It's only for local variables with an initialiser, loop variables, try-with-resources and lambda parameters, not fields, method parameters or return types. I use it when the type is obvious from the right side, like a long generic map constructor, and avoid it when it hides the type, such as var result equals service.process, or with the diamond operator, which infers ArrayList of Object."

Likely follow-up questions

  • What type does var list = new ArrayList<>() infer? ArrayList<Object>.
  • Is var a keyword? No, a reserved type name, so var var = 1; compiles.
  • Why allow var in lambda parameters? To add annotations or modifiers like final consistently.
