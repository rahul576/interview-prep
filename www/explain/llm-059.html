What are LoRA and QLoRA, and when would you fully fine-tune a model instead?

LLMOps & RAG · concept · levels mid, senior

In one line

LoRA freezes the base model and trains small low-rank adapter matrices, using far less GPU memory and storage; QLoRA trains those adapters on a 4-bit quantised base model so large models fit on one GPU; adapters can be swapped or merged. Choose full fine-tuning only for large domain or language shifts with ample data and compute, accepting a higher risk of catastrophic forgetting.

Detailed explanation

Full fine-tuning updates every weight. For a 7B model that means storing gradients and optimiser states for billions of parameters (with Adam, several times the model size in memory) and producing a full copy of the model per task.

LoRA (Low-Rank Adaptation) observes that the weight change needed for a task has low intrinsic rank. For a weight matrix W, it learns ΔW = B·A, where A and B are thin matrices of rank r (for example 8-64). Only A and B are trained, typically well under 1% of parameters, applied to attention projections and often MLP layers. Benefits: much lower memory, faster training, adapters of megabytes to a few hundred megabytes, and the ability to serve many adapters on one base model (vLLM and others support multi-LoRA serving) or merge an adapter into the base weights for zero inference overhead.

QLoRA loads the frozen base model in 4-bit NF4 quantisation (with double quantisation and paged optimisers) while training the LoRA adapters in 16-bit precision. This lets you fine-tune much larger models on a single GPU (the original paper fine-tuned a 65B model on one 48 GB GPU) with quality close to 16-bit LoRA.

What PEFT is good at: output style and format, tone, following a schema, narrow tasks (classification, extraction), domain terminology. It is weaker at injecting large amounts of new knowledge; RAG is usually better for facts.

Full fine-tuning is justified for big shifts: a new language, a very different domain (legal, medical corpora at scale), or when evaluations show LoRA plateaus. It needs more data, compute and care (learning rates, mixing in general data) and risks catastrophic forgetting of general abilities.

How it works

  1. Choose base model and target modules.
  2. Set rank, alpha and dropout; optionally quantise base (QLoRA).
  3. Train adapters on curated chat-formatted data.
  4. Evaluate on task and general capability sets.
  5. Serve adapter dynamically or merge into base.

Example

from peft import LoraConfig, get_peft_model
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
import torch

bnb = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4",
                         bnb_4bit_compute_dtype=torch.bfloat16)
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3.1-8B-Instruct",
                                             quantization_config=bnb)
lora = LoraConfig(r=16, lora_alpha=32, lora_dropout=0.05,
                  target_modules=["q_proj", "k_proj", "v_proj", "o_proj"], task_type="CAUSAL_LM")
model = get_peft_model(model, lora)
model.print_trainable_parameters()   # a fraction of a percent of all parameters

Common mistakes

  • Fine-tuning to add facts that RAG would handle better.
  • Too few or inconsistent examples.
  • No general-capability evaluation after training.
  • Forgetting the chat template during training.

How to answer in the interview

"LoRA freezes the base weights and trains small low-rank matrices added to selected layers, usually under one percent of parameters, so it needs far less memory and produces small adapters that can be swapped per task or merged for serving. QLoRA goes further by loading the frozen base in 4-bit precision while training adapters in 16-bit, so fairly large models fit on a single GPU with little quality loss. That's enough for style, formats and narrow tasks. I'd only do full fine-tuning for big shifts like a new language or domain with lots of data and compute, watching for catastrophic forgetting, and only once evals show LoRA isn't enough."

Likely follow-up questions

  • Detecting lost capabilities? Run general benchmarks and your broader eval set before and after.
  • Choosing rank? Start around 8-16; increase if underfitting; validate.
  • Multi-tenant adapters? Serve one base with per-tenant LoRA adapters loaded on demand.
