What is the difference between greedy algorithms and dynamic programming? Give an example where greedy fails.

DSA: Algorithms & DP · concept · levels mid, senior

In one line

Greedy algorithms commit to the locally best choice at each step and never reconsider. That is fast, but only correct when the problem has the greedy-choice property (proved with an exchange argument). DP evaluates all relevant subproblems, so it is correct more generally but slower. Coins {1, 3, 4} for 6: greedy gives 4+1+1 (3 coins), while the optimum is 3+3 (2 coins).

Detailed explanation

Both techniques rely on optimal substructure. The difference is how many options they keep alive:

  • Greedy picks one option per step using a simple rule (largest, earliest finishing, cheapest) and reduces the problem. It is usually O(n log n) for the sort plus O(n).
  • DP considers every choice at each step and keeps the best result for each subproblem state. It is typically polynomial, but with larger constants or dimensions.

Greedy is correct only if you can prove that some optimal solution starts with the greedy choice (the greedy-choice property). The standard proof is the exchange argument: take any optimal solution, swap its first choice for the greedy one, and show it is no worse. Classic correct greedy algorithms include:

  • Interval scheduling (max non-overlapping meetings): pick the earliest end time.
  • Huffman coding: merge the two least frequent symbols.
  • Dijkstra (non-negative weights), Prim/Kruskal minimum spanning trees.
  • Fractional knapsack by value/weight ratio. Note that 0/1 knapsack needs DP.

Counterexample for coin change. Denominations {1, 3, 4}, amount 6. Greedy takes the largest coin that fits: 4, then 1, then 1, for 3 coins. The optimum is 3 + 3, 2 coins. DP (dp[a] = 1 + min(dp[a-c])) finds it: dp[6] = 1 + min(dp[5], dp[3], dp[2]) = 1 + min(2, 1, 2) = 2.

Greedy does work for canonical coin systems like Indian rupees (1, 2, 5, 10, 20, 50, ...), US cents (1, 5, 10, 25) or euros. Their denominations are designed so that greedy is always optimal. Whether a system is canonical can be checked algorithmically (Pearson's test), but there is no simple universal rule.

Interview heuristic: try a greedy rule, then actively hunt for a small counterexample. If you can't prove it or you find a counterexample, fall back to DP.

How it works

  1. Identify the choices at each step.
  2. Propose a greedy rule and test it on small or edge cases.
  3. Try an exchange argument. If it holds, implement the greedy algorithm (often sort plus scan).
  4. If a counterexample exists, define the DP state and recurrence instead.
  5. Compare complexity and pick the simplest correct solution.

Example

// Greedy: maximum non-overlapping meetings (correct)
int maxMeetings(int[][] m) {
    Arrays.sort(m, Comparator.comparingInt(a -> a[1]));   // earliest end first
    int count = 0, end = Integer.MIN_VALUE;
    for (int[] x : m) if (x[0] >= end) { count++; end = x[1]; }
    return count;
}

// Greedy coin change: WRONG for {1,3,4}, amount 6 -> returns 3
int greedyCoins(int[] coinsDesc, int amt) {
    int n = 0;
    for (int c : coinsDesc) { n += amt / c; amt %= c; }
    return n;
}

Common mistakes

  • Assuming greedy works because it passes the sample inputs.
  • Sorting intervals by start (or duration) instead of end for max scheduling.
  • Using greedy for 0/1 knapsack.
  • Saying "greedy works for any coins".

How to answer in the interview

"A greedy algorithm makes the locally optimal choice at each step and never reconsiders it. That's fast, but only correct if the problem has the greedy-choice property, which I'd show with an exchange argument, as with interval scheduling by earliest end time or Huffman coding. Dynamic programming considers all subproblems and combines them, so it's correct more generally but slower. A classic failure is coin change with coins 1, 3 and 4 for amount 6: greedy takes 4, 1, 1, three coins, but 3 plus 3 is two. For everyday currencies greedy happens to work because those coin systems are canonical."

Likely follow-up questions

  • Why does greedy work for Indian or US coins? They are canonical coin systems, where each denomination is designed so the largest-first choice is optimal.
  • What is an exchange argument? Swap an optimal solution's choice for the greedy one and show it stays optimal.
  • Jump game? Greedy works: track the farthest reachable index.
