What is cloud computing, and what is the difference between IaaS, PaaS and SaaS?

Cloud (AWS) · concept · levels entry

In one line

Cloud computing is renting compute, storage, databases and networking on demand over the internet with pay-as-you-go pricing; IaaS gives you infrastructure such as VMs (EC2), PaaS gives you a managed platform where you just deploy code (Elastic Beanstalk, RDS, Lambda), and SaaS is finished software for end users, with more responsibility shifting to the provider as you move up.

Detailed explanation

Before cloud, companies bought servers, waited weeks, sized for peak load and paid for idle capacity. Providers such as AWS, Azure and Google Cloud let you provision resources in minutes through an API, scale elastically and pay only for use. NIST lists five characteristics: on-demand self-service, broad network access, resource pooling, rapid elasticity and measured service.

The service models describe how much of the stack you manage. With IaaS you get virtual machines, networks and block storage (EC2, VPC, EBS) and manage the OS, patches, runtime, application and data: maximum control, most work.

With PaaS the provider also runs the OS and runtime; you deploy code or use a managed service such as Elastic Beanstalk, RDS or Lambda (serverless/FaaS).

With SaaS you use a complete application such as Gmail, Microsoft 365 or Salesforce, managing only users, data and settings.

Boundaries blur: containers on Fargate or EKS sit between IaaS and PaaS. The choice trades control against operational effort.

How it works

  1. Pick the model by how much control you need.
  2. Provision resources through the console, CLI or infrastructure as code.
  3. The provider runs the layers below your responsibility line.
  4. You manage the layers above it.
  5. Usage is metered and billed per second, hour, request or GB.

Example

A company runs an online shop three ways:

IaaS : EC2 instances + self-installed Nginx, Java and PostgreSQL
       -> you patch the OS, upgrade PostgreSQL, configure backups
PaaS : Elastic Beanstalk for the app + RDS PostgreSQL
       -> you deploy a JAR; AWS patches OS and DB engine, takes backups
SaaS : Shopify
       -> you configure products and payments; no servers at all

Common mistakes

  • Thinking cloud is automatically cheaper; idle resources still cost money.
  • Calling every managed service SaaS.
  • Ignoring that security responsibility shifts but never disappears.

How to answer in the interview

"Cloud computing means renting servers, storage, databases and networking on demand over the internet and paying for what you use, instead of buying hardware. The models differ in what you manage. With IaaS, like EC2, you get virtual machines and networks and manage the OS and everything above it. With PaaS, like Elastic Beanstalk, RDS or Lambda, the provider runs the platform and you just deploy code or use the service. SaaS is complete software, like Gmail or Salesforce. Moving up, the provider manages more and you manage less, trading control for less operational work."

Likely follow-up questions

  • Which model for a team without ops engineers? PaaS or serverless, so the provider handles servers, patching and scaling.
  • What is serverless? Services with no servers to manage that scale automatically and bill per use, such as Lambda or DynamoDB.
  • Public, private, hybrid cloud? Shared provider infrastructure, dedicated infrastructure, or a mix connected together.
