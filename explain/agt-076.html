What are agent skills, and how do they complement tools and MCP servers?

AI Agents & AIOps · concept · levels mid, senior

In one line

Agent skills are packages of instructions, scripts, templates and resources for a task, loaded on demand so they save context; they encode procedures and organisational know-how, complementing tools and MCP servers, which provide capabilities; they are versioned, shared and should be reviewed like code.

Detailed explanation

Tools and MCP servers give an agent the ability to do things: call an API, query a database, create a file. But agents also need to know how the organisation wants things done: which template a report uses, which steps an incident review follows, how to deploy through the internal platform. Putting all of that in every system prompt fills the context window and goes stale.

Skills, such as Anthropic's Agent Skills, solve this. A skill is a folder with a SKILL.md file containing a short name and description plus detailed instructions, and optionally scripts, templates and reference documents. Only the name and description sit in the agent's context by default. When a task matches, the agent loads the full skill, and reads extra files or runs bundled scripts only if needed. This progressive disclosure means many skills can be available without wasting context.

Skills encode procedures and organisational knowledge: the order of steps, conventions, checks and pitfalls. They complement tools: a skill can say "use the deploy MCP tool, but first run the migration check script, and never deploy on Fridays after 3 p.m.". Because skills are files, they are versioned in Git, shared across teams and agents, and improved over time. And because they directly guide an agent's actions, and may include executable scripts, they should be reviewed like code and installed only from trusted sources.

How it works

  1. Author writes a skill folder with SKILL.md and optional resources.
  2. Agent starts with only skill names and descriptions in context.
  3. A matching task causes the agent to read the full instructions.
  4. It follows the procedure, using tools and bundled scripts.
  5. Skills are versioned, reviewed and distributed like code.

Example

---
name: incident-review
description: Write a blameless postmortem in the company template from an incident ID.
---
# Incident review
1. Fetch the incident with the `incidents.get` tool and the chat export.
2. Build the timeline with `scripts/timeline.py <incident-id>`.
3. Fill `templates/postmortem.md`; never name individuals as causes.
4. List action items with owner and due date; mark unknowns "TBD".

Common mistakes

  • Putting business logic that needs guarantees in a skill instead of a tool.
  • Installing third-party skills without review.
  • Vague descriptions, so the skill is not picked up when relevant.
  • Huge skills that duplicate tool documentation.

How to answer in the interview

"Skills, like Anthropic's Agent Skills, are packages of instructions, scripts, templates and reference material for a type of task. Only a short description sits in context by default, and the full skill loads when relevant, so many can be available cheaply. They encode procedures and organisational knowledge, the how, while tools and MCP servers provide capabilities, the ability to call systems. A skill can say which tools to use in which order with which checks. They're versioned files shared across teams, and since they guide actions, I review them like code and only use trusted ones."

Likely follow-up questions

  • Skill vs tool implementation? Guarantees and validation in tools; guidance and conventions in skills.
  • Skill discovery? Clear, specific descriptions with trigger phrases.
  • Security risk? Malicious skills can instruct harmful actions or ship harmful scripts.
