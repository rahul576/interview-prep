How do you detect a cycle in a directed graph and produce a topological order?

DSA: Trees & Graphs · concept · levels mid

In one line

A topological sort orders the nodes of a DAG so every edge u -> v has u before v. With Kahn's algorithm, repeatedly remove in-degree-zero nodes using a queue. If not all nodes get processed, there is a cycle. Alternatively, run DFS with three colours (white/grey/black), where a back edge to a grey node means a cycle. Both are O(V + E).

Detailed explanation

Dependency problems everywhere are directed graphs: course prerequisites, build targets (Maven modules, Gradle tasks, Bazel), package managers, Terraform resource graphs, spreadsheet formula recalculation, database migration ordering, and Airflow DAGs. A valid execution order exists only if the graph has no directed cycle. So cycle detection and topological sort are two sides of one algorithm.

Kahn's algorithm (BFS).

  • Compute the in-degree (number of incoming edges) of each node.
  • Put every node with in-degree 0 into a queue. These have no unmet dependencies.
  • Repeatedly dequeue a node, append it to the order, and decrement the in-degree of each neighbour. When a neighbour reaches 0, enqueue it.
  • If the order contains fewer than V nodes, the remaining nodes all have in-degree above 0 forever. They are on or behind a cycle.

Kahn's algorithm naturally exposes parallelism: all nodes in the queue at the same time can run concurrently, which is how build tools and Terraform schedule work.

DFS with three colours.

  • White = unvisited, grey = on the current recursion stack, black = fully finished.
  • Visiting an edge to a grey node means a back edge, so there is a cycle. That is the case where a path leads back to an ancestor.
  • Adding nodes to a list when they turn black, then reversing that list, gives a topological order.

A plain visited set is not enough for directed graphs. Reaching an already-finished (black) node through another path is fine (a diamond shape), not a cycle.

Complexity: both are O(V + E) time and O(V) space, with the graph stored as an adjacency list.

How it works

  1. Build the adjacency list and the indeg[] array.
  2. Queue every node with indeg == 0.
  3. Poll u, append it to the order, and for each v in adj[u]: if (--indeg[v] == 0) queue.offer(v).
  4. When the queue is empty: if order.size() < V, report the cycle. Otherwise return the order.

Example

public List<Integer> topoSort(int n, int[][] edges) {        // edge: [from, to]
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    int[] indeg = new int[n];
    for (int[] e : edges) { adj.get(e[0]).add(e[1]); indeg[e[1]]++; }

    Deque<Integer> q = new ArrayDeque<>();
    for (int i = 0; i < n; i++) if (indeg[i] == 0) q.offer(i);
    List<Integer> order = new ArrayList<>();
    while (!q.isEmpty()) {
        int u = q.poll();
        order.add(u);
        for (int v : adj.get(u)) if (--indeg[v] == 0) q.offer(v);
    }
    if (order.size() < n) throw new IllegalStateException("cycle detected");
    return order;
}
// edges 0->1, 0->2, 1->3, 2->3 -> [0, 1, 2, 3]

Common mistakes

  • Using an undirected-graph cycle check (a visited set) on a directed graph.
  • Getting the edge direction backwards (prerequisite -> course versus course -> prerequisite).
  • Forgetting isolated nodes with no edges.
  • Not reversing the DFS post-order.

How to answer in the interview

"Topological sort orders a DAG so every dependency comes first, like build steps or course prerequisites. With Kahn's algorithm I compute every node's in-degree, queue the nodes with in-degree zero, and repeatedly remove one, append it to the order and decrement its neighbours' in-degrees, enqueueing any that reach zero. If I can't process all nodes, the remaining ones are part of a cycle. Alternatively, DFS with three colours detects a back edge to a node still on the recursion stack. Both are O(V plus E). Terraform, Gradle and Airflow all rely on this."

Likely follow-up questions

  • Where is this used in real tools? Terraform's resource graph, Gradle and Maven reactor ordering, Airflow DAGs, package managers.
  • Lexicographically smallest order? Use a min-heap instead of the queue in Kahn's algorithm.
  • Report the actual cycle? In DFS, keep parent links and walk back from the grey node when the back edge is found.
