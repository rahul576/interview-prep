What is the difference between count and for_each in Terraform?

Infrastructure as Code · concept · levels entry

In one line

count creates N instances addressed by index ([0], [1]); for_each creates one instance per element of a map or set, addressed by key (["alice"]), which keeps addresses stable when the collection changes.

Detailed explanation

Both meta-arguments let a single resource or module block create many objects. With count, you give a whole number and Terraform creates that many instances, exposing count.index inside the block. Instances are addressed by position, for example aws_instance.web[0].

With for_each, you give a map or a set of strings, and Terraform creates one instance per element, exposing each.key and each.value. Instances are addressed by key, for example aws_iam_user.users["alice"].

The difference matters when the collection changes. Suppose count = length(var.users) with users ["alice", "bob", "carol"]. If you remove bob, carol moves from index 2 to index 1. Terraform sees that index 1 now has different arguments and index 2 no longer exists, so it plans to modify or replace bob's object into carol and destroy the old carol: unnecessary churn, and for some resources, real data loss. With for_each keyed by username, removing bob destroys only ["bob"]; everything else is untouched.

So the rule of thumb is: use for_each whenever instances have a natural identity, and keep count for identical, interchangeable copies or for conditional creation, count = var.enabled ? 1 : 0. Note that for_each keys must be known at plan time, so you cannot key on attributes that are only known after apply, such as generated IDs.

How it works

  1. Terraform evaluates count or for_each during planning.
  2. It creates one instance address per index or key.
  3. It compares each address with the state.
  4. With count, a shifted list changes what each index means; with for_each, keys keep their identity.
  5. Only addresses that disappear are destroyed, only new ones are created.

Example

# Fragile: removing "bob" shifts carol's index
resource "aws_iam_user" "by_index" {
  count = length(var.users)
  name  = var.users[count.index]
}

# Stable: each user keyed by name
resource "aws_iam_user" "by_key" {
  for_each = toset(var.users)
  name     = each.key
}

# Conditional creation
resource "aws_cloudwatch_log_group" "debug" {
  count = var.enable_debug ? 1 : 0
  name  = "/app/debug"
}

Common mistakes

  • Using count over a list of names and then removing an item from the middle.
  • Passing a list directly to for_each instead of toset() or a map.
  • Keying for_each on values only known after apply.
  • Changing from count to for_each without moved blocks, which recreates everything.

How to answer in the interview

"count creates a number of instances addressed by index, for_each creates one per element of a map or set addressed by key. The practical difference is stability: if I remove an element from the middle of a count list, every later index shifts and Terraform wants to change or recreate resources that didn't really change. With for_each, addresses are keys, so only the removed item is destroyed. I use for_each for anything with an identity, like users, buckets or subnets, and count for identical copies or the classic conditional 'count = var.enabled ? 1 : 0'."

Likely follow-up questions

  • How would you convert count to for_each without recreating? Add moved blocks from res[0] to res["key"] (or use terraform state mv), then confirm the plan shows only moves.
  • Can you use both on one resource? No, they are mutually exclusive.
  • Why must keys be known at plan time? Terraform needs the full set of addresses to build the plan.
