How do you trace and debug an AI agent or LLM application running on Azure?

Azure AI & Foundry · concept · levels mid, senior

In one line

Trace AI apps with OpenTelemetry using the generative AI semantic conventions: each request is a trace with spans for model calls (model, tokens, latency, finish reason), retrieval and tool calls, sent to Application Insights and viewed step by step in Foundry, capturing prompt content carefully for privacy and turning failures into evaluation cases.

Detailed explanation

When an agent gives a wrong answer, logs saying "200 OK" tell you nothing. You need to see what the model saw, what it decided and what each tool returned.

Instrumentation: the Azure AI SDKs, the OpenAI SDK instrumentation, Semantic Kernel, Microsoft Agent Framework, LangChain and others emit OpenTelemetry spans following the GenAI semantic conventions. Attributes include gen_ai.operation.name, gen_ai.request.model, gen_ai.usage.input_tokens, gen_ai.usage.output_tokens, gen_ai.response.finish_reasons, and for tools the tool name and call ID. You add your own spans for retrieval (query, returned document IDs and scores) and business steps.

Trace structure: one user request is a root span; below it are spans for each model call, each retrieval, each tool call with arguments and results, and nested agent steps. Latency, token counts and errors are visible per step.

Backend: export to Application Insights with the Azure Monitor OpenTelemetry distro. The Foundry portal reads the same data and shows an agent-style step view, so you can see why the agent picked a tool, what it passed and how it reacted to the result. Application Insights adds dashboards, alerts and KQL queries for tokens, latency and failure rates.

Privacy: prompts and responses are extremely useful for debugging but may contain personal or confidential data. Content recording is off by default and enabled explicitly; capture it only in environments where allowed, redact sensitive fields, limit retention, and restrict access to the workspace.

Learning loop: interesting failures (wrong tool, hallucination, loops) become evaluation dataset entries, so fixes are verified and regressions prevented.

How it works

  1. Configure the Azure Monitor OpenTelemetry exporter.
  2. Enable GenAI instrumentation for the SDK or framework.
  3. Add custom spans for retrieval and business logic.
  4. Decide on content capture and redaction per environment.
  5. Inspect traces in Foundry or Application Insights; alert on anomalies.
  6. Promote failing traces to evaluation cases.

Example

import os
from azure.monitor.opentelemetry import configure_azure_monitor
from opentelemetry.instrumentation.openai_v2 import OpenAIInstrumentor
from opentelemetry import trace

os.environ["OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT"] = "false"  # true only in dev
configure_azure_monitor(connection_string=os.environ["APPLICATIONINSIGHTS_CONNECTION_STRING"])
OpenAIInstrumentor().instrument()

tracer = trace.get_tracer("helpdesk")
with tracer.start_as_current_span("retrieve_kb") as span:
    docs = search(query)
    span.set_attribute("retrieval.doc_ids", [d.id for d in docs])

Common mistakes

  • Logging full prompts with personal data in production by default.
  • Only tracing model calls, not retrieval and tools.
  • No correlation between user feedback and traces.
  • Debugging from single anecdotes rather than aggregated traces.

How to answer in the interview

"I instrument with OpenTelemetry using the GenAI semantic conventions supported by the Azure AI SDKs and agent frameworks. Each request becomes a trace with spans for model calls, including model, tokens, latency and finish reason, retrieval with the documents returned, and every tool call with arguments and results. Traces go to Application Insights, and Foundry shows them step by step, so I can see why the agent chose a tool or answered wrongly. Prompt content is captured only where allowed, with redaction and access control. Failures become evaluation cases to prevent regressions."

Likely follow-up questions

  • Agent loops calling the same tool? Look at tool results, errors the model can't interpret, and missing stop conditions; add max-iteration limits.
  • How to measure cost per request? Sum token attributes per trace times model price.
  • Sampling? Sample normal traffic, but keep all errors and flagged conversations.
