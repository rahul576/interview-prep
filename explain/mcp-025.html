What is the MCP Inspector, and how do you use it while developing a server?

MCP Servers · concept · levels entry, mid, senior

In one line

The MCP Inspector is the official interactive tool for testing servers without a model: run npx @modelcontextprotocol/inspector against a stdio command or HTTP URL, then list and call tools, read resources, get prompts and watch raw JSON-RPC messages, including auth flows.

Detailed explanation

When something goes wrong in a real host, you cannot easily tell whether the problem is your server, the host's configuration or the model's choices. The Inspector removes the model and host from the equation so you can exercise the server directly.

You start it with npx @modelcontextprotocol/inspector, optionally followed by the command that launches a stdio server, such as node build/index.js or uv run server.py, plus arguments and environment variables. It starts a local proxy and opens a browser UI. For remote servers you choose the Streamable HTTP transport (or legacy SSE) and enter the URL.

In the UI you can:

  • see the server's capabilities, info and instructions after connecting;
  • list tools and inspect names, descriptions and schemas exactly as a host would see them;
  • call tools with arguments you type, viewing content blocks, structured content and isError results;
  • read resources and templates, and get prompts with arguments;
  • watch notifications: progress, logs, list changes;
  • view the raw JSON-RPC history for debugging;
  • test authorization flows for remote servers, including OAuth discovery and token exchange.

There is also a CLI mode (--cli) for scripted checks, useful in CI for smoke tests. The Python SDK offers mcp dev server.py, which launches the Inspector for you.

Use it to check that schemas and descriptions look right, tools behave correctly on good and bad inputs, error messages are helpful, and auth works, before connecting a real host. Note the Inspector's local proxy should not be exposed to untrusted networks; it runs with authentication by default in recent versions.

How it works

  1. Build the server.
  2. Run npx @modelcontextprotocol/inspector <command> <args> or connect via URL.
  3. Connect; check capabilities and tool list.
  4. Call tools with valid, invalid and edge-case arguments.
  5. Inspect raw messages and stderr logs; fix and reconnect.

Example

# stdio server
npx @modelcontextprotocol/inspector node build/index.js
npx @modelcontextprotocol/inspector -e API_KEY=test uv run server.py

# Python SDK shortcut
uv run mcp dev server.py

# CLI mode for CI smoke test
npx @modelcontextprotocol/inspector --cli node build/index.js --method tools/list

Common mistakes

  • Testing only the happy path in the Inspector.
  • Assuming "works in the Inspector" means the model will use the tool well.
  • Different environment variables in the Inspector versus the real host config.
  • Exposing the Inspector proxy port on a shared network.

How to answer in the interview

"The MCP Inspector is the official developer tool for testing servers without a model. I run npx @modelcontextprotocol/inspector with the command that starts my stdio server, or point it at a Streamable HTTP URL, and it opens a browser UI. I can see capabilities, list and call tools with my own arguments, inspect structured results and errors, read resources and templates, get prompts, and watch the raw JSON-RPC messages and notifications. It also tests OAuth flows for remote servers. I use it to check schemas, descriptions and behaviour, and to separate server bugs from host or model issues."

Likely follow-up questions

  • Works in the Inspector but the model never calls it? The server is fine; the description, name or tool overload is the problem, or the host didn't enable it.
  • Inspector works but the host fails? Usually environment, paths or stdout pollution in the host launch.
  • Can it run in CI? Yes, with CLI mode.
