How would you group the results by customer name and order year?

Databases & SQL · concept · levels entry

In one line

Write GROUP BY c.customer_id, c.name, EXTRACT(YEAR FROM o.order_date): every non-aggregated SELECT column must be grouped, and including customer_id stops two customers with the same name being merged.

Detailed explanation

GROUP BY defines what "one row of output" means. Here we want one row per customer per year, so the grouping key is the combination of customer and year. All rows sharing that combination form one group, and aggregates such as SUM(o.amount) are computed inside it.

The rule in standard SQL is that every expression in the SELECT list must be either inside an aggregate or part of the GROUP BY (or functionally dependent on it). Otherwise the database would not know which value to show. PostgreSQL, for instance, allows GROUP BY c.customer_id alone and still lets you select c.name, because name is functionally dependent on the primary key. MySQL with ONLY_FULL_GROUP_BY (the default since 5.7) enforces the same logic.

Grouping by name alone is a real bug: two different "Rahul Sharma" customers would have their revenue added together. Always include the key; add the name for display.

Many databases (PostgreSQL, MySQL) also accept the select alias (GROUP BY order_year) or position (GROUP BY 1, 2, 3). SQL Server and Oracle do not accept the alias, because GROUP BY is logically evaluated before SELECT. Repeating the full expression is the portable choice; positions are fragile when someone reorders columns.

How it works

  1. FROM/JOIN/WHERE produce filtered rows.
  2. The engine computes the grouping key (customer_id, name, year) for each row.
  3. Rows with the same key are collected, via sorting or hashing.
  4. Aggregates are computed per group.
  5. One output row per group is returned, then ORDER BY sorts them.

Example

SELECT c.customer_id,
       c.name,
       EXTRACT(YEAR FROM o.order_date) AS order_year,
       SUM(o.amount)                   AS total_revenue
FROM customers c
JOIN orders o ON o.customer_id = c.customer_id
GROUP BY c.customer_id, c.name, EXTRACT(YEAR FROM o.order_date)
ORDER BY c.name, order_year;

Error if c.name is missing from GROUP BY in SQL Server: Column 'customers.name' is invalid in the select list because it is not contained in either an aggregate function or the GROUP BY clause.

Common mistakes

  • Grouping only by name.
  • Grouping by the full order_date instead of the year, giving one row per day.
  • Relying on aliases in GROUP BY and hitting errors on Oracle or SQL Server.
  • Using MySQL's old permissive mode and getting an arbitrary value for ungrouped columns.

How to answer in the interview

"I'd group by c.customer_id, c.name and EXTRACT(YEAR FROM o.order_date). Every non-aggregated column in the SELECT has to be in the GROUP BY, so the database knows how to form the groups, here one per customer and year, and SUM is calculated inside each. I include customer_id because two customers can share a name and I don't want their revenue merged. Some databases accept the alias or column position, but repeating the expression is the most portable."

Likely follow-up questions

  • What error do you get if a column is missing from GROUP BY? A "not a GROUP BY expression" or "invalid in the select list" error.
  • Can you group by an alias? In PostgreSQL and MySQL yes; in SQL Server and Oracle no.
  • What is functional dependency here? If you group by the primary key, other columns of that table are determined by it, so some databases allow selecting them.
