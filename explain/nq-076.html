What is the difference between Runnable and Callable?

Concurrency · concept · levels entry

In one line

Runnable.run() returns void and cannot throw checked exceptions; Callable<V>.call() returns a value and may throw checked exceptions. Callables are submitted to an ExecutorService, which returns a Future<V>.

Detailed explanation

Runnable has existed since Java 1.0: public void run(). It is designed for "do this work", with no way to return a result and no throws clause, so any checked exception like IOException must be caught inside. It can be passed directly to new Thread(...).

Callable<V> arrived with java.util.concurrent in Java 5: V call() throws Exception. It is designed for "compute this and give me the answer", and it may throw any exception. Thread does not accept a Callable; you hand it to an ExecutorService.submit(callable), or to invokeAll/invokeAny, and receive a Future<V>.

The Future is how the result and failures come back. future.get() blocks until the task finishes and returns its value; if call() threw, get() throws ExecutionException whose getCause() is the original exception. get(timeout, unit) avoids waiting forever, and cancel(true) interrupts the task.

submit also accepts a Runnable; then the Future's result is null (or a fixed value via submit(runnable, result)). Executors.callable(runnable) adapts a Runnable into a Callable. Both are functional interfaces, so lambdas work, and the compiler picks Callable when the lambda returns a value.

Use Callable for tasks that compute something, like fetching a price or querying a service. Use Runnable for fire-and-forget side effects, like sending a notification. In modern code, CompletableFuture.supplyAsync(Supplier) is often used instead of Callable when you want to compose results.

How it works

  1. Define the task: Runnable r = () -> log("hi"); or Callable<Integer> c = () -> compute();.
  2. Submit: pool.submit(c) returns Future<Integer>.
  3. A worker thread runs call() and stores the result or exception in the Future.
  4. The caller calls get() (ideally with timeout) to retrieve it.
  5. Exceptions arrive wrapped in ExecutionException.

Example

ExecutorService pool = Executors.newFixedThreadPool(4);

Runnable notify = () -> System.out.println("Sending email");      // no result
new Thread(notify).start();

Callable<BigDecimal> priceTask = () -> {
    if (offline()) throw new IOException("pricing service down");   // checked OK
    return pricingClient.priceFor("SKU-42");
};
Future<BigDecimal> future = pool.submit(priceTask);

try {
    BigDecimal price = future.get(2, TimeUnit.SECONDS);
} catch (ExecutionException e) {
    log.warn("Pricing failed", e.getCause());                      // the IOException
} catch (TimeoutException e) {
    future.cancel(true);
}

Common mistakes

  • Trying to pass a Callable to new Thread(...).
  • Calling get() without a timeout on a task that may hang.
  • Logging the ExecutionException instead of its cause.
  • Submitting and never checking the Future, losing failures.

How to answer in the interview

"Runnable has void run, so it can't return a result or throw checked exceptions. Callable has V call throws Exception, so it returns a value and can throw checked exceptions. I can pass a Runnable straight to a Thread, but a Callable goes to an ExecutorService, which returns a Future; future.get waits for the result and wraps any exception from call in an ExecutionException. submit also accepts Runnables, in which case the result is null. I use Callable for tasks that compute something, like fetching a price, and Runnable for fire-and-forget work."

Likely follow-up questions

  • How do you get the exception thrown inside a Callable? Call future.get() and catch ExecutionException; the original is getCause().
  • How do you convert a Runnable into a Callable? Executors.callable(runnable) or callable(runnable, result).
  • What does invokeAny do? Runs several Callables and returns the result of the first that completes successfully, cancelling the rest.
