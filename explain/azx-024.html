How do reservations, savings plans, spot VMs and Azure Hybrid Benefit help reduce compute costs?

Azure · concept · levels mid, senior

In one line

Right-size first, then cover the stable baseline with reservations (specific resource, one or three years, biggest discount) or savings plans (hourly compute spend commitment, flexible), run interruptible work on Spot VMs, and apply Azure Hybrid Benefit for existing Windows Server and SQL Server licences.

Detailed explanation

Commitment discounts on an oversized estate just lock in waste, so start with Azure Advisor right-sizing and shutdown recommendations, Cost Management analysis, and real utilisation metrics. Delete idle disks and IPs, schedule dev/test shutdowns and use autoscaling.

Reservations commit to a specific product for one or three years: a VM size family in a region (with instance size flexibility within the family), SQL Database or Managed Instance vCores, Cosmos DB throughput, App Service, storage capacity and others. Discounts reach roughly 70 percent or more for three-year terms on some VMs. You can pay upfront or monthly, and exchanges are possible within policy limits. They suit steady, predictable workloads.

Azure savings plan for compute commits to a fixed hourly spend (for example 20 dollars per hour) for one or three years. It applies automatically across VMs, App Service, Functions Premium, Container Instances, Container Apps and more, across regions and sizes. Discounts are somewhat lower than reservations (up to around 65 percent), but the flexibility is valuable when architectures change. Reservations are applied first, then savings plans, then pay-as-you-go.

Spot VMs use spare capacity at up to around 90 percent off, but can be evicted with 30 seconds' notice when Azure needs capacity or price exceeds your max. Use them for batch, rendering, CI agents, stateless scale sets and AKS spot node pools, with workloads designed for interruption.

Azure Hybrid Benefit lets you bring Windows Server and SQL Server licences with Software Assurance (or qualifying subscriptions) so you pay only the base compute rate; it also applies to RHEL and SUSE subscriptions and to Azure Arc scenarios.

How it works

  1. Right-size and clean up using Advisor and utilisation data.
  2. Identify the stable baseline (minimum usage over months).
  3. Cover the most stable part with reservations, the flexible part with a savings plan.
  4. Move interruptible jobs to Spot.
  5. Enable Hybrid Benefit where licences exist.
  6. Track utilisation of commitments monthly and adjust.

Example

Baseline: 400 vCPU steady, peaks 700.
- 250 vCPU D-series in West Europe → 3-year reservation
- ~120 vCPU-equivalent of mixed App Service/Container Apps → savings plan $X/hour
- CI agents and nightly batch → Spot scale set
- Windows VMs → Hybrid Benefit with existing SA licences
- Peaks → pay-as-you-go with autoscale

Common mistakes

  • Buying commitments before right-sizing.
  • Covering 100 percent of peak usage with commitments.
  • Running stateful, non-interruptible apps on Spot.
  • Forgetting to check commitment utilisation reports.

How to answer in the interview

"I right-size first with Advisor and utilisation data, because a discount on an oversized VM is still waste. Then I cover the steady baseline: reservations for stable, specific resources like a VM family or SQL vCores, which give the biggest discount, and a compute savings plan for the part that moves between services, sizes or regions. Batch jobs and CI agents run on Spot VMs, which are very cheap but can be evicted, and Windows and SQL workloads use Hybrid Benefit with existing licences. I review commitment utilisation every month."

Likely follow-up questions

  • How much to commit? Usually 60-80 percent of the long-term minimum baseline, increasing as confidence grows.
  • Reservation or savings plan first? Reservations for the most stable usage; savings plan for the rest.
  • Spot eviction handling? Scheduled Events, checkpointing, and mixed spot/regular node pools.
