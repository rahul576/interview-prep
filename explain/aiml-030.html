What is the difference between encoder-only, decoder-only and encoder-decoder transformer models?

AI/ML & GenAI · concept · levels mid, senior

In one line

Encoder-only models (BERT) use bidirectional attention to build representations for classification, embeddings and search; decoder-only models (GPT, Claude, Llama, Gemini) use causal attention to generate token by token and dominate modern LLMs; encoder-decoder models (T5) map an input sequence to an output sequence for translation and summarisation.

Detailed explanation

The original transformer had both an encoder and a decoder. Later models kept one or both parts depending on the job.

Encoder-only models, such as BERT, RoBERTa, DeBERTa and modern embedding models, read the whole input at once. Bidirectional self-attention lets every token see context on both sides, so "bank" in "river bank" gets a different representation from "bank account". They are trained with objectives like masked language modelling (predict hidden tokens). They do not generate long text, but they are excellent and cheap for understanding tasks: classification, named entity recognition, reranking, and especially embedding models that turn text into vectors for semantic search and RAG.

Decoder-only models, such as the GPT family, Claude, Llama, Gemini, Mistral, use causal (masked) attention: each token can only attend to earlier tokens. They are trained to predict the next token and generate output autoregressively. At scale this simple setup turned out to be remarkably general: question answering, coding, reasoning, translation and summarisation all become "continue this text", so nearly all modern LLMs use it. Its training is efficient because every position is a training example, and it pairs naturally with in-context learning.

Encoder-decoder (sequence-to-sequence) models, such as T5, BART and the original transformer, encode the input with bidirectional attention, then a decoder generates the output while attending to the encoder via cross-attention. This is a natural fit for tasks with a distinct input and output, like translation and summarisation, and remains common in speech recognition (for example Whisper) and some translation systems.

How it works

  1. Text is tokenised and embedded with position information.
  2. Encoder: bidirectional self-attention layers produce contextual vectors for every token.
  3. Decoder: causal self-attention ensures each position only sees earlier tokens.
  4. Encoder-decoder: the decoder also cross-attends to encoder outputs.
  5. Output: pooled vectors or a classifier head (encoder), or next-token probabilities (decoder).

Example

from sentence_transformers import SentenceTransformer
from transformers import pipeline

embedder = SentenceTransformer("all-MiniLM-L6-v2")           # encoder-only
vecs = embedder.encode(["reset my password", "forgot login"])

summariser = pipeline("summarization", model="t5-small")      # encoder-decoder
generator = pipeline("text-generation", model="gpt2")         # decoder-only

Common mistakes

  • Saying BERT can be used as a chatbot.
  • Thinking decoder-only models cannot do understanding tasks.
  • Confusing causal masking at training time with generation at inference.
  • Using a huge generative model where a small encoder classifier would be faster and cheaper.

How to answer in the interview

"Encoder-only models like BERT read the whole input with bidirectional attention and produce rich representations, so they're great and cheap for classification, entity extraction and especially embeddings for semantic search and RAG. Decoder-only models like GPT, Claude and Llama use causal attention and generate one token at a time; trained at scale they became general-purpose, so almost all modern LLMs use this design. Encoder-decoder models like T5 encode an input and decode an output with cross-attention, a natural fit for translation, summarisation and speech recognition."

Likely follow-up questions

  • Why are embedding models usually small encoders? Bidirectional context gives good representations cheaply, with low latency for indexing millions of documents.
  • What is causal masking? Blocking attention to future tokens so the model can't cheat when predicting the next token.
  • What is cross-attention? Decoder queries attending to encoder outputs.
