Explain CountDownLatch, CyclicBarrier and Semaphore with use cases.

Concurrency · concept · levels mid, senior

In one line

A CountDownLatch lets threads wait until N events have happened (one-shot), a CyclicBarrier makes a fixed group of threads wait for each other at a point (reusable), and a Semaphore limits concurrent access with permits; Phaser generalises latch and barrier.

Detailed explanation

All three are synchronisers in java.util.concurrent, built on AbstractQueuedSynchronizer, that replace hand-written wait/notify code.

CountDownLatch starts with a count. Worker threads call countDown() when they finish something; waiting threads call await() (optionally with a timeout) and are released when the count reaches zero. The roles are asymmetric: the counting threads don't wait. It is one-shot: once zero, it stays open and cannot be reset. Typical uses: the main thread waits until five services have started, a test waits until N async callbacks arrive, or a "starting gun" latch of 1 releases many threads at once for a load test.

CyclicBarrier is created for a fixed number of parties. Each thread calls await() and blocks until all parties have arrived; then all are released together, and an optional barrier action runs once (for example merging partial results). It then resets automatically, so it suits iterative, phased algorithms: each worker computes its slice of step k, waits at the barrier, then all move to step k+1. If one party times out or is interrupted, the barrier becomes broken and the others get BrokenBarrierException.

Semaphore holds a number of permits. acquire() takes one (blocking if none), release() returns one; tryAcquire(timeout) avoids waiting forever. It is used to limit concurrency: at most 20 simultaneous calls to a rate-limited partner API, or bounding how many virtual threads use a resource. A semaphore with one permit is a non-reentrant mutex, and any thread may release, so always release in finally.

Phaser supports a dynamic number of parties and multiple phases, covering both latch and barrier use cases.

How it works

  1. Latch: count N → countDown() decrements → zero releases all await()ers.
  2. Barrier: N parties call await() → last arrival runs action → all released → reset.
  3. Semaphore: permits P → acquire() decrements or blocks → release() increments and wakes a waiter.

Example

// Wait for services to start
CountDownLatch ready = new CountDownLatch(services.size());
services.forEach(s -> exec.submit(() -> { s.start(); ready.countDown(); }));
if (!ready.await(30, SECONDS)) throw new IllegalStateException("startup timeout");

// Phased simulation
CyclicBarrier step = new CyclicBarrier(4, grid::swapBuffers);
Runnable worker = () -> { for (int t = 0; t < steps; t++) { computeSlice(); step.await(); } };

// Limit calls to a partner API
Semaphore permits = new Semaphore(20);
permits.acquire();
try { partnerApi.call(); } finally { permits.release(); }

Common mistakes

  • Forgetting countDown() on failure paths (use finally), so await hangs.
  • Using a latch where repeated phases need a barrier.
  • Releasing a semaphore without acquiring it, inflating permits.
  • await() without timeouts in production code.

How to answer in the interview

"A CountDownLatch lets one or more threads wait until a count reaches zero, for example the main thread waiting for five services to start; it's one-shot. A CyclicBarrier makes a fixed number of threads wait for each other before continuing, and it's reusable, which suits phases of a parallel computation. A Semaphore holds permits and limits how many threads use a resource at once, like concurrent calls to a downstream API. Phaser generalises latch and barrier with dynamic parties."

Likely follow-up questions

  • Semaphore with virtual threads? Create a virtual thread per task and use a Semaphore to cap access to the scarce resource, instead of a small pool.
  • What breaks a CyclicBarrier? A timeout, interrupt or exception in the action; others get BrokenBarrierException.
  • Can a latch be reset? No; create a new one or use a barrier/Phaser.
