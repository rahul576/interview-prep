Which Terraform functions and expressions do you use most?

Infrastructure as Code · concept · levels mid

In one line

Most used: conditional expressions (cond ? a : b), for expressions to reshape collections, merge, lookup, try, coalesce, string functions (format, join, split, templatefile), and cidrsubnet for network planning.

Detailed explanation

Terraform has no user-defined functions in core (provider-defined functions exist since 1.8), so fluency with built-in functions and expressions keeps configurations concise.

Conditional expressions: var.env == "prod" ? 3 : 1 sets values per environment; both branches must have compatible types. Combined with count, they enable optional resources.

for expressions transform collections: [for s in var.subnets : s.id] builds a list, { for s in var.services : s.name => s } builds a map, often to feed for_each, and an if clause filters: { for k, v in var.users : k => v if v.admin }. Splat expressions aws_instance.web[*].id are shorthand for simple lists.

Map and collection helpers: merge(local.common_tags, var.extra_tags) combines maps, later maps winning; lookup(var.sizes, var.env, "t3.small") reads a key with a default; try(var.config.logging.bucket, null) returns the first expression that evaluates without error, ideal for optional nested attributes; coalesce(var.name, local.default_name) picks the first non-null, non-empty value; flatten, distinct, keys, values, contains, length, toset, zipmap are everyday tools. can() turns an expression into a boolean for validations.

Strings: format("%s-%s", var.project, var.env), join(",", var.cidrs), split(",", var.list), replace, lower, trimspace, and templatefile("${path.module}/user_data.sh.tftpl", { port = 8080 }), which renders user data, cloud-init or policy documents from template files. For JSON policies, jsonencode or the aws_iam_policy_document data source is safer than templated strings.

Networking: cidrsubnet(prefix, newbits, netnum) carves subnets from a VPC range, e.g. cidrsubnet("10.0.0.0/16", 4, 0) = 10.0.0.0/20; cidrhost gets a host address. This replaces hand-maintained address lists and avoids overlaps.

How it works

  1. Expressions are evaluated during plan where values are known.
  2. Unknown values propagate as "known after apply".
  3. Functions are pure: same inputs, same output (except things like timestamp()).
  4. Test them interactively in terraform console.

Example

locals {
  instance_count = var.env == "prod" ? 3 : 1
  tags           = merge(local.common_tags, var.extra_tags)
  services_map   = { for s in var.services : s.name => s if s.enabled }
  log_bucket     = try(var.config.logging.bucket, null)
  azs            = ["eu-west-1a", "eu-west-1b", "eu-west-1c"]
  private_subnets = {
    for i, az in local.azs : az => cidrsubnet(var.vpc_cidr, 4, i)
  }
}

resource "aws_instance" "app" {
  count         = local.instance_count
  instance_type = lookup(var.instance_types, var.env, "t3.small")
  user_data     = templatefile("${path.module}/user_data.sh.tftpl", { port = var.port })
  tags          = local.tags
}
> cidrsubnet("10.0.0.0/16", 4, 0)   "10.0.0.0/20"
> cidrsubnet("10.0.0.0/16", 4, 1)   "10.0.16.0/20"
> cidrsubnet("10.0.0.0/16", 4, 2)   "10.0.32.0/20"

Common mistakes

  • Overusing try and hiding real errors.
  • Building JSON with string templates instead of jsonencode.
  • Conditional branches with mismatched types.
  • Calculating CIDRs by hand and creating overlaps.

How to answer in the interview

"Conditional expressions, like env equals prod ? 3 : 1, for per-environment values. for expressions to transform collections, for example building a map from a list keyed by name to feed for_each, with an if clause to filter. merge for combining default and resource-specific tags, lookup with a default, try for optional nested attributes, and coalesce for the first non-empty value. For strings, format, join, split and templatefile for user data or policy templates. And cidrsubnet to calculate subnets from the VPC CIDR instead of maintaining address lists by hand."

Likely follow-up questions

  • How would you compute three /20 subnets from a /16 VPC CIDR? [for i in range(3) : cidrsubnet(var.vpc_cidr, 4, i)].
  • try vs can? try returns a fallback value; can returns true/false, mainly for validations.
  • Can you write your own functions? Not in HCL itself; provider-defined functions are available from 1.8.
