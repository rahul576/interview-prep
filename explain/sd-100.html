Design a data platform that ingests data from 50 operational sources into a lakehouse for analytics and ML.

Classic Design Problems · design · levels senior, lead

In one line

A lakehouse platform ingests via CDC, API connectors and event streams into object storage with open table formats (Delta Lake, Iceberg), refines data through bronze/silver/gold layers with orchestration and data quality checks, governs it with a catalogue, lineage and access control, and serves BI, ML and reverse ETL.

Detailed explanation

With 50 sources, consistency of approach matters more than any single tool. Ingestion depends on the source: operational databases use CDC (Debezium, AWS DMS or managed connectors) reading the transaction log with minimal load; SaaS systems use API connectors (Fivetran, Airbyte); applications publish events to Kafka. Each source gets an owner and a data contract describing schema and freshness.

The lakehouse combines cheap object storage with open table formats like Delta Lake or Apache Iceberg, which add ACID transactions, schema evolution, time travel and efficient upserts (MERGE) on Parquet files. Multiple engines can read them: Spark/Databricks, Trino, Snowflake, Flink.

Medallion layers structure refinement: bronze keeps raw data as received (append-only, replayable), silver holds cleaned, deduplicated, conformed tables (CDC merged into current state, standard types, keys), and gold contains business-level models and aggregates (dimensional models, metrics, feature tables).

Orchestration (Airflow, Dagster, Databricks Workflows) runs pipelines with dependencies; dbt handles SQL transformations and tests. Data quality checks (freshness, volume, nulls, uniqueness, referential integrity, anomaly detection) block bad data before it reaches gold. Governance through a catalogue such as Unity Catalog, DataHub or AWS Glue gives discovery, lineage, ownership and fine-grained access with masking of personal data.

How it works

  1. Onboard source: choose CDC/API/stream, define owner, schema contract and SLA.
  2. Land raw data in bronze Delta/Iceberg tables partitioned by ingestion date.
  3. Silver jobs merge CDC changes, dedupe, standardise and validate.
  4. Gold dbt models build facts, dimensions and feature tables.
  5. Quality tests run after each step; failures halt downstream jobs and alert owners.
  6. Serve: BI tools query gold, ML pipelines read features, reverse ETL syncs segments to CRM.

Example

-- Silver: apply CDC changes from bronze into a current-state Delta table
MERGE INTO silver.customers AS t
USING (
  SELECT * FROM bronze.customers_cdc
  WHERE _ingested_at > (SELECT max(_ingested_at) FROM silver.customers)
  QUALIFY row_number() OVER (PARTITION BY id ORDER BY _lsn DESC) = 1
) AS s
ON t.id = s.id
WHEN MATCHED AND s.op = 'd' THEN DELETE
WHEN MATCHED THEN UPDATE SET *
WHEN NOT MATCHED AND s.op <> 'd' THEN INSERT *;

Common mistakes

  • Dumping files into a "data swamp" with no table format, schema or owners.
  • Transforming in bronze, losing the ability to replay raw data.
  • No quality gates, so broken source data silently reaches dashboards.
  • Ignoring personal data: no masking, no erasure process.
  • Building 50 bespoke pipelines instead of reusable ingestion patterns.

How to answer in the interview

"I'd pick the ingestion method per source: CDC with Debezium for databases, Fivetran or Airbyte for SaaS APIs, and Kafka for application events. Everything lands in object storage using Delta Lake or Iceberg, giving ACID transactions, schema evolution and time travel. Data moves through bronze for raw, silver for cleaned and conformed, and gold for business models. Airflow or Dagster orchestrates, dbt transforms, and quality checks gate each layer. A catalogue like Unity Catalog provides lineage and access control with PII masking, and gold serves BI, ML features and reverse ETL."

Likely follow-up questions

  • Source changes schema without warning? Bronze accepts it, schema-drift detection alerts, silver uses explicit contracts; data contracts prevent repeats.
  • Batch or streaming? Streaming only where freshness matters; most gold models are fine with hourly batches.
  • Delta or Iceberg? Both are mature; choose by engine ecosystem and catalogue support.
