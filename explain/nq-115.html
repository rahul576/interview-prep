What are linear and non-linear data structures? Give examples.

Collections · concept · levels entry

In one line

Linear data structures arrange elements in a sequence (arrays, linked lists, stacks, queues), while non-linear structures form hierarchies or networks (trees, heaps, tries, graphs) that need strategies like DFS/BFS to traverse.

Detailed explanation

In a linear structure each element has at most one predecessor and one successor, so there is a single natural order and you can visit everything in one pass. Examples:

  • Array / ArrayList: contiguous, index access O(1).
  • Linked list: nodes linked by references, cheap insertion at a known position.
  • Stack: LIFO, push and pop at the top (ArrayDeque in Java).
  • Queue / Deque: FIFO or both ends (ArrayDeque, PriorityQueue is a queue interface but heap-based internally).

In a non-linear structure an element can be connected to several others. There is no single "next", so traversal needs a strategy: depth-first (pre-order, in-order, post-order for trees) or breadth-first (level order). Examples:

  • Trees: hierarchical parent-child relations; binary search trees and balanced red-black trees (TreeMap, TreeSet) give O(log n) ordered operations.
  • Heaps: complete binary trees with a priority property; PriorityQueue stores one in an array.
  • Tries: prefix trees for autocomplete and dictionary lookups.
  • Graphs: arbitrary vertices and edges, possibly cyclic, for routes, social networks and dependency resolution; represented as adjacency lists (Map<Node, List<Node>>) or matrices.

Hash tables are often discussed separately: logically a key-value structure, physically an array of buckets that in Java's HashMap contain lists or trees.

Linear structures are simpler and memory-efficient; non-linear ones model relationships and enable logarithmic search or path finding.

How it works

  1. Linear: start at the first element, follow index or next pointer to the end.
  2. Tree: start at the root, recurse into children (DFS) or use a queue per level (BFS).
  3. Graph: like a tree but track visited nodes to avoid cycles.
  4. Choose the structure based on the relationships in your data.

Example

// Linear
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1); stack.push(2); stack.pop();     // 2

// Non-linear: org chart as a tree, BFS by level
record Employee(String name, List<Employee> reports) {}
void printLevels(Employee ceo) {
    Queue<Employee> q = new ArrayDeque<>(List.of(ceo));
    while (!q.isEmpty()) {
        Employee e = q.poll();
        System.out.println(e.name());
        q.addAll(e.reports());
    }
}

Common mistakes

  • Calling a heap "linear" because it is stored in an array; logically it is a tree.
  • Forgetting the visited set when traversing graphs.
  • Using a list where lookups need a tree or hash structure.
  • Confusing a tree (no cycles, one parent) with a general graph.

How to answer in the interview

"In a linear structure elements form a sequence, each with at most one predecessor and successor, so you can walk them in one run: arrays and ArrayList, linked lists, stacks and queues. In a non-linear structure an element can connect to several others, forming a hierarchy or network, so you need DFS or BFS: trees like binary search trees and heaps, tries, and graphs. Hash tables sit a bit apart; Java's HashMap is an array of buckets with lists or trees inside. Linear structures are simpler, non-linear ones model hierarchies and relationships efficiently."

Likely follow-up questions

  • Organisation chart? A tree (n-ary), each employee with a list of reports.
  • Graph representation? Adjacency list for sparse graphs, matrix for dense ones.
  • Which is a heap? Non-linear (complete binary tree), stored in an array.
