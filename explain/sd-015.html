How do you choose between a relational database and a NoSQL database?

Data & Storage Design · concept · levels entry, mid, senior

In one line

Choose by access patterns, consistency needs and scale: relational for transactional, query-rich data (the default); key-value or wide-column for massive simple lookups; documents for flexible aggregates; graphs for relationship queries.

Detailed explanation

Relational databases (PostgreSQL, MySQL) give schemas, joins, ACID transactions and flexible ad-hoc queries. With indexing, read replicas, partitioning and good hardware they handle very large workloads; Postgres also stores JSON when you need flexibility.

NoSQL is a family:

  • Key-value (Redis, DynamoDB): blazing fast get/put by key.
  • Wide-column (Cassandra, ScyllaDB, Bigtable): huge write throughput, data modelled per query, horizontal scale across regions.
  • Document (MongoDB, Cosmos DB): JSON documents read and written as a whole.
  • Graph (Neo4j): traversals like "friends of friends who bought X".

You trade query flexibility and transactions for scale and specific performance profiles.

How it works

  1. List entities, access patterns, read/write volume and consistency needs.
  2. If you need multi-row transactions, joins and evolving queries → relational.
  3. If access is by key/time range at very large scale and you can model per query → wide-column/key-value.
  4. If each item is a self-contained aggregate with varying fields → document.
  5. Mix where justified (polyglot persistence), with one source of truth per entity.

Example

E-commerce: orders, payments, inventory in PostgreSQL; product catalogue search in Elasticsearch; shopping cart and sessions in Redis; clickstream events in Cassandra or a data lake.

Comparison

NeedChoice
Transactions, joins, reportingPostgreSQL / MySQL

Flexible nested documentsMongoDB / Cosmos DB
Relationship traversalNeo4j

Common mistakes

  • Picking NoSQL "for scale" when data fits easily in Postgres.
  • Modelling Cassandra like a relational DB and then needing joins.
  • Using a document DB for highly relational data with many cross-document updates.

How to answer in the interview

"I start relational by default because it gives transactions and query flexibility, and it scales further than people think. I'd move a specific workload to NoSQL when there's a clear reason, for example a write-heavy event log at hundreds of thousands of writes per second, or key lookups needing multi-region active-active. Then I'd model that store from its access patterns."

Likely follow-up questions

  • When would you move from Postgres to Cassandra? Sustained write volume beyond one primary, multi-region writes, simple query patterns.
  • Can relational DBs scale horizontally? Yes: Citus, Vitess, CockroachDB, Spanner, or manual sharding.
  • What is polyglot persistence's main cost? Operating several systems and keeping them consistent.
