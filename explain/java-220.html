What is the difference between sleep(), wait() and join()?

Concurrency · concept · levels entry, mid

In one line

Thread.sleep pauses the current thread without releasing locks; Object.wait must be called inside synchronized, releases the monitor and waits for notify/notifyAll, always in a loop; join waits for another thread to finish. In modern code prefer higher-level utilities.

Detailed explanation

Thread.sleep(ms) is a static method that puts the current thread in TIMED_WAITING for at least the given time. It has nothing to do with locks: any monitors or ReentrantLocks the thread holds stay held, so sleeping inside synchronized blocks every other thread that needs that lock. It throws InterruptedException if interrupted. Use it for simple delays or back-off, not for coordination.

Object.wait() is an instance method on the monitor object. You must own that object's monitor, i.e. be inside synchronized (obj), otherwise you get IllegalMonitorStateException. wait atomically releases the monitor and suspends the thread until another thread calls obj.notify() or notifyAll() (or a timeout or interrupt). Before returning it re-acquires the monitor. Always call it in a while loop that rechecks the condition, because of spurious wakeups (allowed by the spec), because notifyAll wakes threads whose condition may still be false, and because another thread may consume the state before you re-acquire the lock. Prefer notifyAll unless you're sure every waiter is interchangeable.

thread.join() makes the calling thread wait until thread terminates (optionally with a timeout). It also establishes happens-before: everything the joined thread did is visible afterwards. Internally it is implemented with waiting on the thread object.

In modern Java, raw wait/notify is rarely written by hand. Use BlockingQueue for producer-consumer, CountDownLatch or Future.get instead of join, ReentrantLock with Condition for multiple wait conditions, and CompletableFuture or structured concurrency to wait for results. With virtual threads, sleep and join unmount cheaply.

How it works

  1. sleep: thread → TIMED_WAITING, locks untouched → RUNNABLE after the time.
  2. wait: release monitor → WAITING → notified → BLOCKED re-acquiring → RUNNABLE.
  3. join: caller WAITING until target TERMINATED.

Example

class Mailbox {
    private String message;
    synchronized void put(String m) {
        message = m;
        notifyAll();
    }
    synchronized String take() throws InterruptedException {
        while (message == null) {     // while, not if
            wait();                   // releases the monitor
        }
        String m = message; message = null;
        return m;
    }
}

Thread worker = Thread.ofPlatform().start(() -> process());
worker.join(5_000);                   // wait up to 5 s for it to finish

Common mistakes

  • Using if instead of while around wait.
  • Calling wait outside synchronized.
  • Sleeping while holding a lock.
  • Calling notify when several kinds of waiters exist.

How to answer in the interview

"Thread.sleep pauses the current thread for a time and doesn't release any locks it holds. Object.wait must be called inside a synchronized block on that object; it releases the monitor and waits until another thread calls notify or notifyAll, and it should always be called in a loop that rechecks the condition because of spurious wakeups. join makes the current thread wait until another thread finishes. In modern code I prefer higher-level utilities like BlockingQueue, CountDownLatch, Condition or CompletableFuture over raw wait and notify."

Likely follow-up questions

  • Why while and not if? Spurious wakeups and competing threads mean the condition may be false after waking.
  • notify vs notifyAll? notify wakes one arbitrary waiter; notifyAll wakes all and is safer.
  • Does sleep(0) do anything? It may yield; behaviour is platform dependent.
