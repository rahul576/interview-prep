What is the difference between Iterator, ListIterator and the enhanced for loop?

Collections · concept · levels entry

In one line

An Iterator traverses any collection with hasNext/next and safe remove; a ListIterator adds bidirectional movement, add/set and indexes for lists; the enhanced for loop is sugar over an Iterator but gives you no way to remove.

Detailed explanation

Iterator<E> is the basic traversal contract: hasNext(), next() and the optional remove(), which deletes the element last returned by next. Because removal goes through the iterator, it updates the iterator's expected modCount and does not trigger ConcurrentModificationException. Java 8 added forEachRemaining.

ListIterator<E> is available only from List.listIterator(). It can move backwards with hasPrevious() and previous(), reports nextIndex() and previousIndex(), and can modify during traversal: set(e) replaces the last returned element and add(e) inserts at the cursor. It can start at any index with listIterator(i). It's the right tool for in-place transformations or for O(1) inserts in a LinkedList while walking it.

The enhanced for loop (for (T x : coll)) compiles to Iterator it = coll.iterator(); while (it.hasNext()) { T x = it.next(); ... } for any Iterable, and to an index loop for arrays. It is the most readable choice for read-only traversal, but the iterator is hidden. If you call coll.remove(x) inside it, the collection's modCount changes and the next next() throws ConcurrentModificationException.

For removal, prefer Collection.removeIf(predicate) (Java 8), which is concise and, for ArrayList, does a single efficient pass. Or use an explicit Iterator.

How it works

  1. iterator() returns a cursor and records expectedModCount.
  2. next() checks modCount, returns the element and advances.
  3. it.remove() removes via the collection and resynchronises expectedModCount.
  4. ListIterator keeps a cursor between elements, allowing previous, add and set.
  5. Enhanced for desugars to steps 1 and 2 only.

Example

List<String> words = new ArrayList<>(List.of("java", "", "spring", ""));

Iterator<String> it = words.iterator();
while (it.hasNext()) {
    if (it.next().isEmpty()) it.remove();      // safe
}

ListIterator<String> li = words.listIterator();
while (li.hasNext()) li.set(li.next().toUpperCase());  // in-place update

words.removeIf(w -> w.startsWith("S"));        // simplest removal

for (String w : words) System.out.println(w);  // read-only traversal

Common mistakes

  • Calling list.remove inside a for-each loop.
  • Calling it.remove() twice or before next() (IllegalStateException).
  • Using index-based loops with remove(i) and skipping elements.
  • Using get(i) loops on a LinkedList instead of an iterator.

How to answer in the interview

"An Iterator lets me traverse any collection with hasNext and next, and it supports safely removing the current element with remove. ListIterator only works on lists; it's bidirectional, gives indexes, and can set or add elements while iterating. The enhanced for loop is just syntactic sugar over an Iterator, so it's great for reading, but I can't remove through it; calling list.remove inside it throws ConcurrentModificationException. For removal I use Iterator.remove or, more often, removeIf."

Likely follow-up questions

  • How does removeIf avoid CME? It is implemented inside the collection, marking and compacting in one pass without an external iterator.
  • Is the enhanced for loop slower? No, it compiles to the same iterator code.
  • What is a Spliterator? A splittable iterator used by streams for parallel traversal.
