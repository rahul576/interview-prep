What is the difference between HashSet and TreeSet?

Collections · concept · levels entry

In one line

HashSet is a hash table: unordered, O(1) average, uses hashCode/equals, allows one null; TreeSet is a red-black tree: sorted, O(log n), uses compareTo/Comparator, rejects null with natural ordering, and offers NavigableSet methods.

Detailed explanation

Both implement Set and never contain duplicates, but they are built differently and suit different jobs.

HashSet is backed by a HashMap. An element's hashCode chooses a bucket and equals resolves collisions. Operations are average O(1), independent of size if the hash is good. Iteration order is unspecified and may change after a resize. One null element is allowed.

TreeSet is backed by a TreeMap, a red-black tree. Elements are ordered by natural ordering or a Comparator, and duplicates are detected when the comparison returns 0, so the comparator should be consistent with equals. Operations are O(log n): for a million elements that's about 20 comparisons per lookup, versus usually one or two for a hash. Iteration is always sorted. It implements NavigableSet, so you get first, last, floor, ceiling, higher, lower, subSet, headSet, tailSet and descendingSet. With natural ordering, adding null throws NullPointerException.

LinkedHashSet is the middle ground: hash performance plus predictable insertion order.

Practical rule: use HashSet for fast membership and de-duplication, TreeSet when you need sorted iteration or range queries, and LinkedHashSet when you need to remember the order in which items arrived.

How it works

  1. HashSet: hash → bucket → equals.
  2. TreeSet: compare down from root → insert → rebalance.
  3. HashSet iteration: bucket order.
  4. TreeSet iteration: in-order traversal, ascending.

Example

Set<String> hash = new HashSet<>(List.of("pear", "apple", "fig"));
System.out.println(hash);            // some order, e.g. [fig, apple, pear]

TreeSet<String> tree = new TreeSet<>(hash);
System.out.println(tree);            // [apple, fig, pear]
tree.ceiling("b");                   // "fig"

Set<String> linked = new LinkedHashSet<>(List.of("pear", "apple", "fig"));
System.out.println(linked);          // [pear, apple, fig]

Common mistakes

  • Using TreeSet when only uniqueness is needed.
  • Comparator inconsistent with equals, silently dropping elements.
  • Relying on HashSet printing order in tests.
  • Forgetting LinkedHashSet exists.

How to answer in the interview

"HashSet is backed by a hash table: no defined order, it uses hashCode and equals, gives average constant-time operations and allows one null. TreeSet is backed by a red-black tree: it keeps elements sorted by natural order or a Comparator, uses compareTo to detect duplicates, has log n operations, doesn't accept null with natural ordering, and as a NavigableSet gives me first, floor, ceiling and range views. I use HashSet for fast membership, TreeSet for sorted iteration or range queries, and LinkedHashSet when I need insertion order with hash performance."

Likely follow-up questions

  • When choose LinkedHashSet? De-duplicating while preserving arrival order.
  • Which is faster for contains? HashSet, on average.
  • Can TreeSet hold non-Comparable objects? Only with a Comparator.
