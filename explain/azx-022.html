What does Microsoft Defender for Cloud provide, and how do you use it in a DevOps team?

Azure · concept · levels mid, senior

In one line

Microsoft Defender for Cloud is a CNAPP: CSPM (secure score, recommendations, attack paths across Azure, AWS and GCP), workload protection plans (Servers, Containers, SQL, Storage, Key Vault and more), regulatory compliance dashboards and DevOps security for code and IaC, with alerts flowing to a SIEM like Microsoft Sentinel.

Detailed explanation

Cloud security posture management continuously assesses configuration against the Microsoft cloud security benchmark and other standards. Every subscription, and connected AWS accounts and GCP projects, gets a secure score and prioritised recommendations: storage with public access, VMs with open management ports, missing endpoint protection, unencrypted databases. The free Foundational CSPM covers the basics; Defender CSPM (paid) adds the cloud security graph, attack path analysis (for example "internet-exposed VM with a vulnerability that has a managed identity able to read a sensitive storage account"), agentless scanning, data security posture and governance rules that assign owners and due dates.

Workload protection plans add threat detection and vulnerability management for specific resource types: Defender for Servers (integrates Defender for Endpoint, vulnerability assessment, JIT access, file integrity monitoring), Defender for Containers (registry image scanning, Kubernetes runtime threat detection, posture for AKS, EKS, GKE), Defender for SQL, Defender for Storage (activity anomalies and on-upload malware scanning), Key Vault, Resource Manager, App Service, APIs and AI workloads.

Regulatory compliance maps controls to standards like ISO 27001, PCI DSS, NIST or CIS. DevOps security connects GitHub, Azure DevOps and GitLab to show code scanning, secret scanning, dependency and IaC misconfiguration findings (via GitHub Advanced Security or Microsoft Security DevOps) next to cloud findings, enabling code-to-cloud mapping. Alerts and recommendations can be exported continuously to Log Analytics, Sentinel or other SIEMs and to ticketing.

How it works

  1. Enable Defender for Cloud at management group scope via policy; choose plans per environment.
  2. Connect AWS/GCP and DevOps platforms.
  3. Review secure score and attack paths; assign owners with governance rules.
  4. Fix root causes in IaC modules and policies, not in the portal.
  5. Stream alerts to Sentinel; build playbooks for response.
  6. Track the score as a team KPI.

Example

# GitHub Actions: Microsoft Security DevOps scans code and IaC, results surface in Defender for Cloud
- uses: microsoft/security-devops-action@v1
  id: msdo
  with:
    tools: templateanalyzer,checkov,trivy
- uses: github/codeql-action/upload-sarif@v3
  with:
    sarif_file: ${{ steps.msdo.outputs.sarifFile }}

Common mistakes

  • Fixing a recommendation in the portal, then IaC reverts it on the next deploy.
  • Enabling every paid plan everywhere without cost review, or none in production.
  • Ignoring alerts because nobody owns them.
  • Treating secure score as the goal instead of reducing real attack paths.

How to answer in the interview

"Defender for Cloud has two halves. CSPM assesses posture across Azure and connected AWS and GCP against the Microsoft cloud security benchmark, giving a secure score, recommendations and, in Defender CSPM, attack path analysis. Workload protection plans add threat detection and vulnerability scanning for servers, containers, SQL, storage malware scanning and more. It also has regulatory compliance dashboards and DevOps security, which pulls code, secret and IaC findings from GitHub or Azure DevOps. In a team, I enable it via policy, send alerts to Sentinel, assign recommendations to owners and fix them in our Terraform or Bicep modules so they stay fixed."

Likely follow-up questions

  • How to stop IaC reverting fixes? Fix the module, add a deny or modify policy, and scan IaC in PRs.
  • Free vs paid? Foundational CSPM is free; Defender CSPM and workload plans are billed per resource.
  • What is attack path analysis? Graph-based detection of exploitable chains from exposure to sensitive assets.
