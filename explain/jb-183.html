What is JPA, and how does it differ from Hibernate?

Spring Data & JPA · concept · levels entry, mid

In one line

JPA (Jakarta Persistence) is a specification: standard annotations, the EntityManager API and JPQL for object-relational mapping, with no implementation; Hibernate is the most popular provider that implements it and adds extra features; EclipseLink is another provider, and Spring Data JPA uses Hibernate by default.

Detailed explanation

JPA started as part of Java EE (javax.persistence) and is now Jakarta Persistence (jakarta.persistence, version 3.x). It defines what an ORM must offer: annotations such as @Entity, @Id, @GeneratedValue, @OneToMany, @ManyToOne, @Version; the EntityManager interface (persist, find, merge, remove, createQuery); entity lifecycle states and the persistence context; the JPQL query language and the Criteria API; locking modes; lifecycle callbacks; and configuration via persistence.xml or properties. On its own it is just interfaces and documents; you cannot run anything with only the API jar.

Hibernate ORM is a persistence provider, the actual engine. It translates entities and JPQL into SQL for a specific database dialect, manages the persistence context and dirty checking, executes batching, handles caching and generates proxies for lazy loading. Hibernate existed before JPA and strongly influenced the specification. Current versions (Hibernate 6 and 7) implement Jakarta Persistence 3.x.

Hibernate offers features beyond the standard: its native Session API, @NaturalId, filters (@Filter) and @SoftDelete, @BatchSize and other fetch tuning, StatelessSession for bulk work, multi-tenancy support, second-level cache integrations, custom types and JSON mappings, @Formula, and HQL extensions. EclipseLink (the reference implementation) and others like OpenJPA implement the same spec with their own extras.

Coding against JPA interfaces keeps code portable and familiar; using Hibernate-specific features is fine when they bring clear value, ideally isolated in a few places. Spring Data JPA sits on top of JPA, generating repositories that use the EntityManager, and Spring Boot's spring-boot-starter-data-jpa brings Hibernate as the provider.

How it works

  1. You annotate entities with jakarta.persistence annotations.
  2. Spring Boot configures an EntityManagerFactory with Hibernate as provider.
  3. Your code or Spring Data uses the EntityManager interface.
  4. Hibernate implements those calls, generating SQL for the dialect.
  5. Optional Hibernate annotations or unwrap(Session.class) access extras.

Example

import jakarta.persistence.*;                      // JPA standard
import org.hibernate.annotations.BatchSize;         // Hibernate extra
import org.hibernate.annotations.NaturalId;

@Entity
public class Book {
    @Id @GeneratedValue(strategy = GenerationType.SEQUENCE)
    private Long id;

    @NaturalId
    private String isbn;

    @OneToMany(mappedBy = "book")
    @BatchSize(size = 50)
    private List<Review> reviews;
}

Book b = em.find(Book.class, 1L);                                   // portable JPA
Book byIsbn = em.unwrap(Session.class)
                .bySimpleNaturalId(Book.class).load("978-0134685991"); // Hibernate-specific

Common mistakes

  • Saying "JPA vs Hibernate" as if they were competing frameworks.
  • Mixing javax.persistence and jakarta.persistence after a Boot 3 upgrade.
  • Using Hibernate-specific features everywhere without noticing.
  • Confusing Spring Data JPA (repositories) with JPA itself.

How to answer in the interview

"JPA, now Jakarta Persistence, is a specification: standard interfaces and annotations for ORM, like Entity, Id, OneToMany, the EntityManager API and JPQL. It has no working code by itself. Hibernate is the most popular implementation, the provider that actually generates SQL, manages the persistence context and caches. EclipseLink is another. Coding against JPA keeps code portable, while Hibernate adds features beyond the standard like its Session API, natural ids, filters and batch fetching. Spring Data JPA sits on top of JPA and uses Hibernate by default."

Likely follow-up questions

  • When use a Hibernate-specific feature? When it clearly solves a problem (natural ids, batch fetching, StatelessSession) and portability isn't a goal.
  • What is Spring Data JPA? A repository abstraction generating JPA-based implementations.
  • Can you switch providers? Yes in theory; in practice extras and behaviour differences make it work.
