How do you secure a self-hosted LLM inference endpoint?

LLMOps & RAG · concept · levels mid, senior

In one line

Secure inference endpoints with authentication and per-model authorisation for every caller (via a gateway), private network access only (including metrics and admin endpoints), rate limits and quotas per client, input and output size limits, privacy-aware logging, trusted model sources in safe formats like safetensors, and regular patching of serving software, drivers and images.

Detailed explanation

Self-hosted inference servers (vLLM, TGI, Triton, Ollama, SGLang) are often deployed quickly for experiments and then stay, sometimes with no authentication and exposed ports. That invites free GPU usage, data exposure and denial of service.

Authentication and authorisation. Put an API gateway in front (Kong, Envoy, a cloud gateway, LiteLLM proxy) that authenticates callers with service identities (mTLS, OAuth client credentials, workload identity) or tokens, and authorises access per model. Built-in API key options in serving engines are a minimum, not a full solution.

Network. Private subnets only, Kubernetes NetworkPolicies allowing traffic just from approved services, no public load balancer. Engines also expose metrics, health and sometimes management endpoints (model loading, LoRA adapter loading); these must be protected too, since dynamic loading endpoints can be abused.

Resource abuse. Rate limits and token quotas per client stop one service from monopolising GPUs. Input size limits (max prompt tokens, max output tokens, max request body, max images) prevent denial of service by huge or endless requests. Set request timeouts and concurrency caps.

Logging and privacy. Log usage metadata per client (model, tokens, latency, status). Log prompt and response content only where permitted, with redaction, strict access control and retention limits, because prompts frequently contain personal or confidential data.

Model supply chain. Download models only from trusted, verified sources; verify checksums or signatures; prefer safetensors, which stores only tensors, over pickle-based formats that can execute code when loaded; disable trust_remote_code, which runs Python code shipped in model repositories, unless that code has been reviewed and pinned.

Patching. Inference servers, Python dependencies, CUDA drivers and base images have had security vulnerabilities, including remote code execution issues. Scan images, track advisories, and update regularly.

How it works

  1. Client -> gateway (authN, authZ, quotas, size limits) over mTLS.
  2. Gateway -> private inference service (NetworkPolicy-restricted).
  3. Inference pods run non-root with read-only model volumes.
  4. Metrics/admin endpoints internal only.
  5. Logs: metadata always; content redacted and access-controlled.
  6. CI scans images; models verified before deployment.

Example

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: vllm-ingress, namespace: inference }
spec:
  podSelector: { matchLabels: { app: vllm } }
  policyTypes: [Ingress]
  ingress:
    - from:
        - namespaceSelector: { matchLabels: { name: llm-gateway } }
      ports: [{ port: 8000, protocol: TCP }]

vLLM args: --max-model-len 16384, --api-key from a secret, no --trust-remote-code.

Common mistakes

  • Inference ports exposed publicly without auth.
  • Unprotected metrics or adapter-loading endpoints.
  • No max token limits, enabling resource exhaustion.
  • Loading pickle checkpoints or remote code from unverified repositories.

How to answer in the interview

"Inference endpoints are expensive and powerful, so they must not be open. Every caller authenticates through a gateway with service identities and is authorised for specific models. The endpoint sits on a private network with network policies, and the engine's metrics and management endpoints are protected too. Rate limits and quotas per client stop one service exhausting GPUs, and limits on prompt and output tokens prevent denial of service. I log usage per client, but content only where allowed, with redaction. Models come from verified sources in safetensors format with remote code disabled, and the serving stack, drivers and images are patched regularly."

Likely follow-up questions

  • Why disable remote code? It executes arbitrary Python from the model repository at load time.
  • Multi-tenant GPUs? Separate quotas, namespaces and possibly separate deployments for sensitive tenants.
  • Prompt injection relevance? The endpoint is raw; application-level guardrails still apply.
