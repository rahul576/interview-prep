Which loss functions and optimisers are common in deep learning, and how do you choose?

AI/ML & GenAI · concept · levels mid, senior

In one line

Use cross-entropy for classification (and next-token prediction), MSE, MAE or Huber for regression, specialised losses (contrastive, ranking, focal) for special tasks, and usually AdamW with warmup and cosine decay, or SGD with momentum when tuned for best generalisation in vision.

Detailed explanation

The loss function is the precise definition of what the model is rewarded for, so it should match the task and the business cost. Cross-entropy compares predicted probabilities with the true label and heavily penalises confident wrong answers: binary cross-entropy with a sigmoid for two classes or multi-label problems, categorical cross-entropy with softmax for one-of-many classes. Language models use cross-entropy on next-token prediction. Label smoothing reduces overconfidence. For regression, MSE penalises large errors heavily, MAE is robust to outliers, and Huber loss is quadratic for small errors and linear for large ones. Quantile loss gives prediction intervals.

Specialised tasks: contrastive losses (InfoNCE, triplet loss) train embedding models to pull similar pairs together and push others apart; ranking losses (pairwise, listwise) for search and recommendations; focal loss down-weights easy examples so rare, hard objects in detection get attention; Dice/IoU losses for segmentation; class weights for imbalance.

Optimisers decide how gradients become updates. SGD with momentum is simple, memory-light and, with a well-tuned schedule, often generalises very well; it is still common for CNNs. Adam keeps running estimates of each parameter's gradient mean and variance and adapts step sizes per parameter, converging quickly with less tuning. AdamW decouples weight decay from the adaptive update, fixing how regularisation behaves in Adam, and is the default for transformers and LLM fine-tuning. Adam-family optimisers need extra memory for two state values per parameter. Learning-rate schedules, typically linear warmup then cosine or linear decay, plus gradient clipping, often matter as much as the optimiser choice.

How it works

  1. Identify the output type: class, multi-label, number, ranking, embedding.
  2. Pick the matching loss and any weighting for imbalance.
  3. Start with AdamW (lr around 1e-4 to 3e-4 for transformers) or SGD with momentum 0.9 for CNNs.
  4. Add warmup, decay and gradient clipping.
  5. Run a learning-rate sweep and compare validation metrics, not only loss.

Common mistakes

  • Using MSE for classification.
  • Applying softmax manually before a loss that already includes it.
  • Using Adam's L2 penalty and thinking it equals AdamW weight decay.
  • Skipping warmup for transformers and seeing early loss spikes.

How to answer in the interview

"The loss defines what the model optimises: cross-entropy for classification and next-token prediction, MSE or Huber for regression depending on outliers, and specialised losses like contrastive for embeddings, ranking losses for recommenders or focal loss for imbalanced detection. For optimisers, AdamW is my default for transformers because it adapts per-parameter learning rates and handles weight decay correctly; SGD with momentum can generalise better in vision when tuned. I always pair it with a schedule, warmup then cosine decay, and gradient clipping."

Likely follow-up questions

  • Why focal loss for imbalanced detection? It down-weights the many easy background examples so training focuses on hard, rare objects.
  • Why warmup? Early gradients and Adam's statistics are unreliable, so large initial steps destabilise training.
  • Why does AdamW use more memory? It stores two moving averages per parameter.
