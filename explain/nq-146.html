What is the Builder pattern?

Design Patterns · concept · levels entry

In one line

Builder constructs a complex object step by step through named, chainable methods ending in build(), avoiding telescoping constructors and making it easy to validate and produce immutable objects.

Detailed explanation

The GoF definition is "separate the construction of a complex object from its representation." In modern Java it is mostly used for objects with many optional parameters.

The problem: a User with name, email, age, phone, address and preferences. Constructors multiply (User(name), User(name, email), User(name, email, age) ...), the telescoping constructor anti-pattern. Or one big constructor new User("Ana", "a@x.com", 30, null, null, true) where argument order is easy to get wrong and nulls are cryptic. JavaBeans-style setters fix readability but leave a mutable object that may be used half-built.

The solution: a builder accumulates values through named methods and creates the object in one step: User u = User.builder().name("Ana").email("a@x.com").age(30).build();

  • Each value is named, so the code documents itself.
  • Optional values can be skipped and get defaults.
  • build() can validate (email present, age positive) and throw before any invalid object exists.
  • The target class can have final fields and no setters, so it is immutable and safely shareable across threads.

Examples: StringBuilder (loosely related mutable accumulator), HttpRequest.newBuilder(), HttpClient.newBuilder(), Spring UriComponentsBuilder and MockMvcRequestBuilders, and Lombok @Builder, which generates it from annotations. Builders are also great for test data with sensible defaults.

The GoF version also includes a Director that runs building steps in a set order for different builder implementations, but that is rare in business code.

How it works

  1. Target class has a private constructor taking the builder.
  2. Static builder() returns a new Builder.
  3. Builder methods set fields and return this.
  4. build() validates and constructs the immutable object.
  5. Callers chain calls and finish with build().

Example

public final class User {
    private final String name, email; private final int age;
    private User(Builder b) { name = b.name; email = b.email; age = b.age; }
    public static Builder builder() { return new Builder(); }

    public static final class Builder {
        private String name, email; private int age;
        public Builder name(String n)  { name = n; return this; }
        public Builder email(String e) { email = e; return this; }
        public Builder age(int a)      { age = a; return this; }
        public User build() {
            if (name == null || email == null) throw new IllegalStateException("name and email required");
            return new User(this);
        }
    }
}

// Lombok equivalent
@Builder @Value class Product { String sku; @Builder.Default int qty = 1; }

Common mistakes

  • Using a builder for a two-field class.
  • Skipping validation in build().
  • Forgetting @Builder.Default with Lombok, losing field defaults.
  • Sharing a builder between threads.

How to answer in the interview

"Builder separates constructing a complex object from its representation and builds it step by step. It solves the telescoping constructor problem, where many optional fields mean many constructors or one with ten arguments in an easy-to-confuse order. With a builder I write User.builder().name("Ana").email(...).age(30).build(); each method is named, optional values can be skipped, and build validates everything and returns an immutable object. JDK examples are HttpRequest.newBuilder and StringBuilder; in Spring there's UriComponentsBuilder, and Lombok @Builder generates the code."

Likely follow-up questions

  • How does a builder help immutability? It collects values first, then assigns them once to final fields.
  • What is the Director in GoF Builder? An object that runs the build steps in order, reusable across builders.
  • Builder vs constructor with records? Records are concise but positional; builders help when there are many optional fields.
