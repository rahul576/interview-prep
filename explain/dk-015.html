How do you use docker inspect, and what information does it show?

Docker · concept · levels entry

In one line

docker inspect returns the full low-level JSON for containers, images, volumes and networks: state and exit code, OOMKilled, image, command, env, mounts, network settings and IP, ports, restart policy, health; extract fields with --format Go templates or jq, making it a first stop for debugging.

Detailed explanation

docker ps and docker images show summaries; docker inspect shows everything the daemon knows about an object. It works on any object type (docker inspect name), or type-specifically: docker container inspect, docker image inspect, docker volume inspect, docker network inspect. Use --type when a name is ambiguous.

For a container, the most useful sections are:

  • State: Status, Running, ExitCode, Error, OOMKilled, StartedAt/FinishedAt, and Health with recent healthcheck results.
  • Config: image, Cmd, Entrypoint, Env, User, WorkingDir, labels, exposed ports.
  • HostConfig: port bindings, restart policy, memory/CPU limits, privileged flag, capabilities, log config.
  • Mounts: each bind mount or volume with source, destination and read-only flag.
  • NetworkSettings: networks joined, IP addresses, gateway, published ports.
  • RestartCount, LogPath, the image ID.

For an image: layers (RootFS), architecture/OS, default Cmd/Entrypoint, env, exposed ports, labels such as org.opencontainers.image.revision. For a volume: driver and Mountpoint on the host. For a network: subnet, gateway and connected containers.

Formatting: -f/--format uses Go templates to print just what you need: {{.State.ExitCode}}, {{json .Mounts}}, {{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}. Or pipe JSON to jq for richer queries.

Typical debugging questions it answers: why did it stop (exit code, OOMKilled)? Did my env var or mount actually apply? Which IP and network is it on? Which exact image digest is running? What is the health check saying?

Be aware that docker inspect shows environment variables in plain text, another reason not to pass secrets via env.

How it works

  1. CLI asks the daemon API for the object's full description.
  2. Daemon returns JSON (an array, one element per object).
  3. --format applies a Go template to each element, or you post-process with jq.

Example

docker inspect -f '{{.State.Status}} exit={{.State.ExitCode}} oom={{.State.OOMKilled}}' api
docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}} {{end}}' api
docker inspect -f '{{json .Mounts}}' api | jq '.[] | {Type, Name, Source, Destination, RW}'
docker inspect -f '{{json .State.Health}}' api | jq '.Log[-1]'
docker inspect -f '{{.HostConfig.RestartPolicy.Name}} {{.HostConfig.Memory}}' api
docker image inspect -f '{{.Architecture}} {{.Os}} {{.Config.Entrypoint}}' shop-api:1.4.2
docker volume inspect -f '{{.Mountpoint}}' pgdata

Common mistakes

  • Scrolling through hundreds of lines instead of using --format or jq.
  • Confusing Config (what was requested) with State (what happened).
  • Sharing raw inspect output that contains secrets in Env.
  • Forgetting --type when a container and image share a name.

How to answer in the interview

"docker inspect returns the full low-level configuration and state of a Docker object as JSON, for containers, images, volumes and networks. For a container it shows the image, command, environment, mounts, network settings including the IP, published ports, restart policy, health status and the state with exit code and whether it was OOM-killed. I extract single fields with --format and a Go template, like docker inspect -f '{{.State.ExitCode}}' web, or pipe it to jq. It's one of my first tools when a container is misconfigured or stopped unexpectedly."

Likely follow-up questions

  • Find which volume a container uses? docker inspect -f '{{json .Mounts}}' name, look at Name and Source.
  • Was the container OOM-killed? Check .State.OOMKilled and exit code 137.
  • Check an image's architecture? docker image inspect -f '{{.Architecture}}' image.
