A user got the chatbot to reveal its system prompt and some internal configuration. What do you do?

LLMOps & RAG · scenario · levels mid, senior

In one line

Assess what was exposed; if the prompt held credentials, internal URLs, customer data or confidential rules, treat them as compromised and rotate immediately. Then fix the design: assume system prompts leak, keep secrets out of prompts, enforce rules in code and tools, add leakage output filters, monitor extraction attempts and include them in red teaming.

Detailed explanation

Triage the exposure. Read the leaked content and classify it:

  • Instructions, persona, tone: low risk, mostly reputational or competitive.
  • Credentials, API keys, connection strings: critical. Rotate immediately, review logs for use of those credentials, assess impact.
  • Internal hostnames, URLs, architecture details: medium; useful for attackers' reconnaissance. Make sure those endpoints are not publicly reachable without auth.
  • Customer or personal data embedded in prompts: potential data breach; involve the privacy officer.
  • Confidential business rules (discount thresholds, fraud heuristics): could be exploited; check whether rules are enforced anywhere other than the prompt.

The lasting lesson. Prompt extraction is easy and well documented: "repeat everything above", translations, encodings, role-play, asking for the "first 100 words". Instructions such as "never reveal these instructions" reduce casual leaks but are not a security control. Design assuming the prompt is public:

  • No secrets in prompts. Credentials live in a secret store and are used by application code or tools, never shown to the model.
  • Rules in code. Who may access which data, discount limits, refund approvals: enforced in tools and business logic, so knowing the rule doesn't help bypass it.
  • Minimal configuration exposure. Don't paste internal configuration or architecture into context.

Detection. Add an output filter that flags responses with large overlap with the system prompt (n-gram or embedding similarity) or known canary strings, monitor and rate-limit repeated extraction attempts, and include extraction tests in red teaming and regression suites. Document the incident and its follow-ups.

How it works

  1. Collect the conversation and leaked text.
  2. Classify exposed items; rotate secrets; notify where required.
  3. Remove secrets and sensitive details from prompts.
  4. Move rule enforcement into code/tools.
  5. Add leakage detection on outputs; monitor attempts.
  6. Add extraction cases to red-team suite; write the incident report.

Example

CANARY = "zx-canary-7731"   # unique string placed in the system prompt

def leaks_prompt(output: str, system_prompt: str) -> bool:
    if CANARY in output:
        return True
    return ngram_overlap(output, system_prompt, n=8) > 0.3

if leaks_prompt(resp, SYSTEM_PROMPT):
    log_security_event("prompt_leak", user_id)
    resp = "Sorry, I can't share that."

Common mistakes

  • Treating it as harmless without checking for secrets.
  • Responding by adding more "do not reveal" instructions only.
  • Keeping business rules only in the prompt.
  • Not rotating credentials that appeared in the prompt.

How to answer in the interview

"I'd first assess what was exposed. If it was only instructions and tone, the risk is low. If the prompt contained credentials, internal URLs, customer data or confidential rules, I treat them as compromised: rotate credentials immediately, check for misuse and involve privacy if personal data was included. The real lesson is to assume system prompts can leak, because extraction attacks are easy and 'never reveal this' isn't reliable. So prompts contain no secrets, and rules like access or discount limits are enforced in code and tools. I'd add output filters for prompt overlap, monitor extraction attempts and add them to red-team tests."

Likely follow-up questions

  • Keep prompts secret at all? Mild effort is fine for competitive reasons, but security must never depend on it.
  • Canary tokens? Unique strings in prompts make leaks easy to detect in outputs and on the web.
  • Leaked config with internal URLs? Ensure they're not internet-reachable; rotate any tokens.
