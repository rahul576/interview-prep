What is the difference between @Mock and @InjectMocks?

Testing · concept · levels mid, senior

In one line

@Mock creates a mock of a dependency; @InjectMocks creates a real instance of the class under test and injects the declared mocks into it (constructor first, then setter, then field); both need MockitoExtension, and because injection fails silently, explicit constructor wiring is often clearer.

Detailed explanation

In a typical service test you have one real object and several fakes. @Mock OrderRepository repo gives a Mockito mock: all methods return defaults (null, 0, empty Optional, empty list) until stubbed, and every call is recorded for verification.

@InjectMocks OrderService service tells Mockito to instantiate the real OrderService and supply the mocks. Mockito tries, in order:

  1. Constructor injection: the biggest constructor, resolving arguments by type from declared mocks. If an argument cannot be resolved, null is passed.
  2. Setter injection: for a no-arg constructor, it calls setters matching mock types (then names).
  3. Field injection: sets fields by type, then name.

These annotations are processed by @ExtendWith(MockitoExtension.class) in JUnit 5 (or MockitoAnnotations.openMocks(this), which replaced the deprecated initMocks). MockitoExtension creates fresh mocks for each test method.

The big pitfall: if Mockito cannot inject something, for example a dependency has no mock declared or there are two mocks of the same type, it does not fail. You get null fields and a confusing NullPointerException later, or the wrong mock injected. It also never injects into a dependency created inside the constructor with new. That is why many teams skip @InjectMocks and write service = new OrderService(repo, payments) in a @BeforeEach: the compiler then guarantees every dependency is provided. Constructor injection in production code makes both approaches reliable.

Do not confuse these with Spring's @MockitoBean (formerly @MockBean), which replaces a bean inside a Spring application context; @Mock knows nothing about Spring and is much faster.

How it works

  1. MockitoExtension runs before each test.
  2. Fields with @Mock (and @Spy, @Captor) are initialised.
  3. The @InjectMocks class is instantiated with the mocks via constructor, setter or field.
  4. The test stubs mocks and exercises the real object.
  5. After the test, strict stubs check for unused stubbings.

Example

@ExtendWith(MockitoExtension.class)
class OrderServiceTest {

    @Mock OrderRepository repo;
    @Mock PaymentClient payments;

    @InjectMocks OrderService service;     // real object, mocks injected

    @Test
    void returnsOrderTotal() {
        when(repo.findById(1L)).thenReturn(Optional.of(new Order(1L, BigDecimal.TEN)));
        assertThat(service.total(1L)).isEqualByComparingTo("10");
    }
}

// Explicit alternative: compile-time safety
@BeforeEach
void setUp() {
    service = new OrderService(repo, payments, Clock.systemUTC());
}

Common mistakes

  • Forgetting @ExtendWith(MockitoExtension.class), leaving all fields null.
  • Expecting @InjectMocks to fail loudly when a dependency is missing.
  • Two mocks of the same type with field injection, injecting the wrong one.
  • Using @MockitoBean in plain unit tests and paying for a Spring context.

How to answer in the interview

"@Mock creates a mock of a dependency, like a repository, whose methods return defaults until I stub them. @InjectMocks creates a real instance of the class I'm testing and injects those mocks, trying constructor injection first, then setters, then fields. Both need MockitoExtension in JUnit 5. The catch is that injection fails silently, so a missing mock turns into a NullPointerException later. Because of that I use constructor injection in production code, and often just build the service with new in the test and pass the mocks explicitly, which the compiler checks."

Likely follow-up questions

  • @Mock vs @MockitoBean? @Mock is plain Mockito; @MockitoBean replaces a bean in a Spring context.
  • Can @InjectMocks inject into another @InjectMocks? No, it only injects mocks and spies one level.
  • What does @Spy with @InjectMocks do? The spy is injected like a mock but runs real methods unless stubbed.
