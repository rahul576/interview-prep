How do you find the length of the longest substring without repeating characters?

DSA: Arrays & Strings · concept · levels entry, mid

In one line

Use a sliding window with two pointers and a map of each character's last seen index. When the right pointer hits a character already inside the window, jump the left pointer past its previous position. Each character is processed once, so it is O(n) time and O(k) space for the character set.

Detailed explanation

The brute force checks every substring for uniqueness, which is O(n²) substrings with O(n) checks each, or O(n³). Even with a set it is O(n²). The sliding window pattern does better because a valid window (no repeats) stays valid if we shrink it from the left. So we never need to restart from scratch.

Keep left as the start of the current window and move right across the string. Store last[c] = the most recent index of character c. When s[right] was seen at an index greater than or equal to left, it is a duplicate inside the window, so set left = last[c] + 1. Then update last[c] = right and the best length right - left + 1.

The condition last[c] >= left (or using max(left, last[c] + 1)) is crucial. A character may have been seen long ago, before the current window, and must not drag left backwards. This is the most common bug.

Complexity: right moves n times and left only ever moves forward, so it is O(n) time. Space is O(min(n, k)), where k is the alphabet size. Use an int[128] for ASCII or a HashMap<Character,Integer> for general Unicode. A variant uses a HashSet and moves left one step at a time while removing characters. It is still O(n), but up to 2n steps.

How it works

  1. left = 0, best = 0, last filled with -1.
  2. For right from 0 to n-1, let c = s[right].
  3. If last[c] >= left, set left = last[c] + 1.
  4. Set last[c] = right.
  5. best = max(best, right - left + 1).
  6. Return best.

Example

public int lengthOfLongestSubstring(String s) {
    int[] last = new int[128];
    Arrays.fill(last, -1);
    int left = 0, best = 0;
    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        if (last[c] >= left) left = last[c] + 1;
        last[c] = right;
        best = Math.max(best, right - left + 1);
    }
    return best;
}
// "abcabcbb" -> 3 ("abc"); "pwwkew" -> 3 ("wke"); "abba" -> 2

The "abba" case shows why the >= left check matters. At the final a, its last index 0 is outside the window that starts at 2.

Common mistakes

  • Moving left backwards for characters seen before the window ("abba").
  • Off-by-one in the window length (right - left instead of +1).
  • Using int[26] when the input can contain spaces, digits or Unicode.
  • Restarting the scan from left after each duplicate, which is O(n²).

How to answer in the interview

"I'd use a sliding window with two pointers. I move the right pointer across the string and keep a map from each character to the last index where I saw it. If the current character was last seen inside the current window, meaning at or after left, I move left to just past that position. Then I record the new index and update the best length as right minus left plus one. Left only moves forward, so each character is handled a constant number of times: O(n) time and O(k) space for the alphabet."

Likely follow-up questions

  • At most two distinct characters? Keep counts in the window. While there are more than 2 distinct, shrink from the left, decrementing counts.
  • Return the substring itself? Track the left where best was achieved.
  • Why is it O(n) despite the inner adjustment? Each pointer only moves forward, at most n steps each.
