What are window functions? Explain ROW_NUMBER(), RANK(), and DENSE_RANK().

Databases & SQL · concept · levels mid, senior

In one line

Window functions compute a value over a set of related rows (the window, defined with OVER (PARTITION BY ... ORDER BY ...)) without collapsing them; ROW_NUMBER numbers rows uniquely, RANK shares ranks on ties and leaves gaps, and DENSE_RANK shares ranks without gaps.

Detailed explanation

GROUP BY turns many rows into one per group, so you lose the detail. A window function keeps every row and adds a computed column based on its "neighbours". The OVER clause defines the window:

  • PARTITION BY splits rows into independent groups (like GROUP BY, but without collapsing).
  • ORDER BY orders rows within each partition, needed for ranking and running totals.
  • An optional frame (ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) for moving averages.

The ranking functions differ only in how they treat ties. For salaries 100, 100, 90, 80:

  • ROW_NUMBER: 1, 2, 3, 4. Unique; ties ordered arbitrarily unless you add a tie-breaker.
  • RANK: 1, 1, 3, 4. Olympic-style: ties share the rank, then a gap.
  • DENSE_RANK: 1, 1, 2, 3. Ties share the rank, no gaps.

Other useful window functions include SUM() OVER for running totals, LAG/LEAD for comparing with the previous or next row, FIRST_VALUE, and NTILE for buckets.

Classic uses: top N per group, deduplication (keep the latest row per business key with ROW_NUMBER() = 1), latest order per customer, running balances and month-over-month change. Window functions are evaluated after WHERE, GROUP BY and HAVING, so you filter their results in an outer query or CTE. They are supported in PostgreSQL, Oracle, SQL Server and MySQL 8+.

How it works

  1. Rows pass FROM, WHERE, GROUP BY and HAVING.
  2. Rows are partitioned by the PARTITION BY expression.
  3. Each partition is sorted by the ORDER BY expression.
  4. The function is computed for each row relative to its partition.
  5. An outer query can filter, for example rn = 1.

Example

SELECT name, dept, salary,
       ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC) AS rn,
       RANK()       OVER (PARTITION BY dept ORDER BY salary DESC) AS rnk,
       DENSE_RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS drnk
FROM employee;

-- Latest order per customer
WITH x AS (
  SELECT o.*, ROW_NUMBER() OVER (PARTITION BY customer_id
                                 ORDER BY created_at DESC, id DESC) AS rn
  FROM orders o
)
SELECT * FROM x WHERE rn = 1;

Common mistakes

  • Filtering WHERE rn = 1 in the same query level.
  • Using ROW_NUMBER without a deterministic tie-breaker, giving different results each run.
  • Confusing PARTITION BY with GROUP BY and expecting fewer rows.
  • Forgetting an index on (partition column, order column) for large tables.

How to answer in the interview

"Window functions calculate a value across related rows while keeping every row, unlike GROUP BY. The OVER clause defines the window: PARTITION BY splits rows into groups and ORDER BY orders them within each group. ROW_NUMBER gives a unique sequence even for ties, RANK gives ties the same rank and then skips, so 100, 100, 90 become 1, 1, 3, and DENSE_RANK doesn't skip, giving 1, 1, 2. I use them for top N per department, keeping the latest row per key to deduplicate, and with LAG or running SUMs for trends. Since they run after WHERE, I filter on them in a CTE."

Likely follow-up questions

  • Latest order per customer? ROW_NUMBER partitioned by customer ordered by date descending, keep rn = 1.
  • What do LAG and LEAD do? Return a value from the previous or next row in the window.
  • Running total? SUM(amount) OVER (PARTITION BY account ORDER BY created_at).
