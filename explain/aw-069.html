How does AWS Config work, and what are conformance packs?

Cloud (AWS) · concept · levels senior

In one line

AWS Config records resource configurations and change history linked to CloudTrail, evaluates compliance with managed or custom rules (Lambda or Guard), fixes issues with SSM Automation remediation, packages rules into conformance packs for standards like CIS or PCI, and gives a multi-account view through aggregators.

Detailed explanation

The configuration recorder captures a configuration item whenever a supported resource changes: security groups, buckets, IAM roles, VPCs, RDS instances and hundreds more. Each item stores attributes, relationships (an instance belongs to a subnet and SG) and links to the CloudTrail event that caused it, so you can answer "who opened port 22 last Tuesday?" Items go to an S3 delivery channel and can be queried with advanced queries in SQL-like syntax.

Rules evaluate compliance. Managed rules cover common checks: s3-bucket-public-read-prohibited, encrypted-volumes, restricted-ssh, rds-storage-encrypted, iam-user-mfa-enabled. Custom rules use Lambda or CloudFormation Guard policy-as-code. Rules run on configuration changes or periodically, and proactive mode can check resources before deployment. Results are COMPLIANT, NON_COMPLIANT or NOT_APPLICABLE.

Remediation actions attach an SSM Automation document to a rule, such as AWS-DisableS3BucketPublicReadWrite, running manually or automatically with retries.

Conformance packs are YAML templates bundling rules and remediations, deployed as one unit to an account or the whole organisation. AWS provides sample packs for CIS, PCI DSS, HIPAA, NIST 800-53 and operational best practices. They give a compliance score per pack, useful for audits, often combined with Audit Manager.

Aggregators collect configuration and compliance data from many accounts and regions into one view, typically in the security or audit account.

How it works

  1. Enable the recorder (all or selected types) and delivery channel.
  2. Resource changes create configuration items linked to CloudTrail.
  3. Rules evaluate on change or schedule.
  4. Non-compliant resources trigger remediation and EventBridge events.
  5. Conformance packs and aggregators report compliance across the organisation.

Example

# conformance pack snippet
Resources:
  RestrictedSSH:
    Type: AWS::Config::ConfigRule
    Properties:
      ConfigRuleName: restricted-ssh
      Source: {Owner: AWS, SourceIdentifier: INCOMING_SSH_DISABLED}
  S3PublicRead:
    Type: AWS::Config::ConfigRule
    Properties:
      ConfigRuleName: s3-bucket-public-read-prohibited
      Source: {Owner: AWS, SourceIdentifier: S3_BUCKET_PUBLIC_READ_PROHIBITED}
  S3PublicReadRemediation:
    Type: AWS::Config::RemediationConfiguration
    Properties:
      ConfigRuleName: s3-bucket-public-read-prohibited
      TargetType: SSM_DOCUMENT
      TargetId: AWS-DisableS3BucketPublicReadWrite
      Automatic: true
      MaximumAutomaticAttempts: 3
      RetryAttemptSeconds: 60
      Parameters:
        S3BucketName: {ResourceValue: {Value: RESOURCE_ID}}
        AutomationAssumeRole: {StaticValue: {Values: ["arn:aws:iam::111122223333:role/config-remediation"]}}

Common mistakes

  • Recording every resource type continuously in busy accounts, causing big bills.
  • Enabling Config in one region only.
  • Automatic remediation on production without testing and exceptions.
  • Treating Config as prevention; it detects after the fact.

How to answer in the interview

"AWS Config continuously records the configuration of resources like security groups, buckets and roles, with full change history linked to CloudTrail, which is invaluable for audits and incidents. Rules evaluate compliance: hundreds of managed rules exist, and custom rules use Lambda or Guard. Non-compliant resources can be fixed automatically with SSM Automation remediation. Conformance packs bundle many rules and remediations for a standard like CIS or PCI into one deployable package, and aggregators give a multi-account, multi-region view."

Likely follow-up questions

  • What is the cost risk of recording everything? Each configuration item costs money; high-churn resources can generate millions, so use periodic recording or exclude types.
  • Config versus SCPs? SCPs prevent; Config detects and remediates.
  • What is proactive evaluation? Checking resource configs before creation, for example from CloudFormation hooks.
