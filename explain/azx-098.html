How do you control the cost of Azure OpenAI and Foundry workloads?

Azure AI & Foundry · concept · levels mid, senior

In one line

Control AI costs by making token usage visible per app and team, choosing the smallest model that meets quality (or model router), using prompt caching and semantic caching, sending offline work to Batch, limiting context and max output tokens, and setting budgets and alerts; consider PTU reservations for steady volume.

Detailed explanation

Costs are driven by tokens × price per token, and prices differ by orders of magnitude between models. So cost control is mostly about which model and how many tokens.

Visibility first: Azure Monitor metrics show tokens per deployment, but not per feature. An API Management AI gateway emits token metrics with dimensions like subscription, team or product feature, so you can attribute spend. Add budgets and alerts in Cost Management and tag resources by team.

Model choice is the biggest lever. Use mini or nano models for classification, extraction, routing and simple Q&A; keep large reasoning models for genuinely hard tasks (and limit reasoning effort where supported). Foundry's model router can choose a suitable model per request automatically. Evaluate each choice so cost cuts don't silently reduce quality.

Caching:

  • Prompt caching discounts repeated prompt prefixes (for prompts above a minimum length), so put stable content first: system prompt, instructions, tool definitions, then variable user content.
  • Semantic caching at the gateway returns stored answers for similar questions, avoiding the model call entirely.

Batch API: offline work like nightly summarisation, tagging or embeddings backfills at roughly 50% discount.

Token hygiene: shorter system prompts, fewer but better retrieved chunks (rerank, then send top 3-5), summarising long conversation history, sensible max output tokens, and structured outputs instead of verbose prose.

Commitments: for steady, high volume, provisioned throughput reservations may be cheaper than pay-as-you-go.

How it works

  1. Tag resources and route traffic through a gateway with token metrics.
  2. Build dashboards per team and feature; set budgets.
  3. Evaluate cheaper models per use case.
  4. Restructure prompts for caching; add semantic cache.
  5. Move offline jobs to Batch.
  6. Review monthly and adjust.

Example

<!-- APIM inbound: emit tokens per team and feature -->
<azure-openai-emit-token-metric namespace="genai">
  <dimension name="Team" value="@(context.Request.Headers.GetValueOrDefault("x-team","unknown"))" />
  <dimension name="Feature" value="@(context.Request.Headers.GetValueOrDefault("x-feature","unknown"))" />
  <dimension name="Subscription ID" />
</azure-openai-emit-token-metric>
<azure-openai-semantic-cache-lookup score-threshold="0.05" embeddings-backend-id="embeddings" />

Common mistakes

  • Using the largest model for every request.
  • Putting variable content at the start of prompts, defeating caching.
  • Sending 20 retrieved chunks "to be safe".
  • No per-feature attribution, so nobody owns the bill.

How to answer in the interview

"First I make cost visible: token usage per app and team via Azure Monitor and an API Management gateway emitting token metrics, with budgets and alerts. The biggest lever is model choice: the smallest model that meets the quality bar, like mini or nano for classification, large reasoning models only for hard tasks, or the model router. Prompt caching discounts stable prefixes, so system prompts go first, and semantic caching avoids repeat calls. Offline work goes to Batch at about half price. I also limit context and max output tokens, and for steady volume consider PTU reservations."

Likely follow-up questions

  • Attribute costs to features? Gateway dimensions or headers per feature, joined with price per model.
  • Risk of semantic caching? Stale or wrong answers for subtly different questions; tune thresholds and TTLs.
  • When are reasoning models worth it? Multi-step problems where accuracy gains justify the cost, measured by evaluation.
