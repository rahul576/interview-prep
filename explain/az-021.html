Your Azure bill jumped 30 percent last month. How do you investigate and reduce it?

Azure · scenario · levels lead

In one line

Use Cost Management cost analysis to find what grew (by service, resource group, tag), check anomalies, then cut waste: remove idle resources, right-size with Advisor, buy reservations or savings plans, use spot, schedule dev shutdowns, tune logging, and prevent repeats with budgets and ownership tags.

Detailed explanation

A 30 percent jump is a signal to investigate quickly but methodically. Start with Azure Cost Management + Billing: open cost analysis for the last two months, group by service name, then by subscription, resource group, resource and tag, and compare daily costs to find when the increase started. Check cost anomaly alerts, and correlate with deployments, new projects or traffic changes in the activity log.

Typical causes:

  • New resources left running, such as test VMs, GPU nodes or premium databases.
  • Autoscaling that scaled out and never scaled back, for example AKS node pools.
  • Log Analytics ingestion spikes from debug logging or new diagnostic settings.
  • Data egress and cross-region traffic.
  • Premium storage, snapshots and backups accumulating.
  • Reservations that expired, moving workloads back to pay-as-you-go.

Then optimise. Delete idle and orphaned resources: unattached disks, unused public IPs, old snapshots, empty App Service plans. Right-size using Azure Advisor cost recommendations and utilisation metrics. For steady workloads, buy Reservations (specific resources) or Azure savings plans for compute (flexible hourly commitment). Use spot node pools for interruptible batch work, schedule shutdown of dev and test environments outside working hours, and use autoscale with sensible minimums. For logs, filter at collection with data collection rules, use Basic or Auxiliary plans for verbose tables, reduce retention, and consider commitment tiers.

Prevent recurrence: mandatory tags (owner, cost centre, environment) via Policy, budgets with alerts per subscription or team, showback reports so teams see their costs, and a regular FinOps review.

How it works

  1. Cost analysis: compare months, group by service then resource.
  2. Find the date and source of the increase; check anomalies.
  3. Confirm cause with activity log and metrics.
  4. Remove idle resources; right-size with Advisor.
  5. Apply commitment discounts, spot and scheduling.
  6. Add budgets, tags, alerts and regular reviews.

Example

Finding orphaned resources and the most expensive log tables:

az disk list --query "[?diskState=='Unattached'].{name:name, rg:resourceGroup, sizeGb:diskSizeGb}" -o table
az network public-ip list --query "[?ipConfiguration==null].{name:name, rg:resourceGroup}" -o table
Usage
| where TimeGenerated > ago(30d) and IsBillable == true
| summarize IngestedGB = sum(Quantity) / 1000 by DataType
| top 10 by IngestedGB desc

Common mistakes

  • Cutting resources before understanding the cause.
  • Buying reservations for workloads that are about to change.
  • Ignoring log ingestion and egress, which often hide large costs.
  • No tags, so costs cannot be attributed to owners.
  • One-off clean-ups without budgets or governance to prevent recurrence.

How to answer in the interview

"I would open Cost Management cost analysis and compare the two months grouped by service, subscription, resource group and tag to see exactly what grew and when, and check cost anomaly alerts and the activity log for the cause. Typical culprits are new resources left running, AKS node pools scaled out, Log Analytics ingestion spikes, egress and premium storage. Then I remove idle and orphaned resources like unattached disks and public IPs, right-size using Advisor, buy reservations or savings plans for steady workloads, use spot node pools for batch work, schedule dev and test shutdown, and reduce log ingestion. Budgets with alerts per team and mandatory cost tags prevent repeats."

Likely follow-up questions

  • Log Analytics is 25 percent of the bill. What would you change? Filter in data collection rules, Basic or Auxiliary logs for verbose tables, shorter retention and commitment tiers.
  • Reservations or savings plans? Reservations for stable specific resources; savings plans for flexible compute.
  • How do you build cost awareness in teams? Showback dashboards, budgets per team and cost in design reviews.
