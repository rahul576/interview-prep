How do you view and manage processes in Linux?

Linux · concept · levels entry, mid

In one line

View processes with ps and top/htop, understand PID, PPID and state, control them with signals (SIGTERM before SIGKILL), run them in the background with &, nohup or better systemd, adjust priority with nice/renice, and find them with pgrep/pkill and lsof.

Detailed explanation

Every running program is a process with a PID, a parent PID (PPID), an owner, and a state: R running or runnable, S interruptible sleep (waiting for an event), D uninterruptible sleep (usually I/O), T stopped, and Z zombie (exited, not yet reaped by its parent).

ps aux lists all processes with user, PID, CPU and memory percentages, RSS and command. ps -ef shows the PPID, and ps -eo pid,ppid,stat,%cpu,%mem,cmd --sort=-%cpu lets you choose columns and sort. top gives a live, sortable view; htop is a friendlier version.

You control processes with signals. kill PID sends SIGTERM, a polite request that the program can handle to shut down cleanly; kill -9 PID sends SIGKILL, which cannot be caught and leaves no chance to clean up, so it is a last resort. pgrep -f name finds PIDs by name or command line and pkill signals them, but check the match first.

For job control, a command ending in & runs in the background; jobs, fg and bg manage it,. nohup (or setsid, or a tmux session) keeps a command running after you log out. For anything long-lived, a systemd service is the proper answer. nice starts a process with a priority adjustment from -20 (highest) to 19 (lowest), renice changes it for a running process. lsof -p PID shows open files and sockets, and lsof -i :8080 shows who holds a port.

How it works

  1. List processes and find the one of interest (ps, top, pgrep).
  2. Inspect it: state, parent, resource usage, open files.
  3. Adjust priority with renice if it is hogging CPU.
  4. Stop it with SIGTERM; escalate to SIGKILL only if needed.
  5. Manage long-running work with systemd rather than nohup.

Example

ps -eo pid,ppid,stat,%cpu,%mem,cmd --sort=-%cpu | head
pgrep -af gunicorn
sudo lsof -i :8080
renice +10 -p 4321
nohup ./backfill.sh > backfill.log 2>&1 &
jobs; fg %1
kill 4321; sleep 10; kill -0 4321 && kill -9 4321

Common mistakes

  • Going straight to kill -9.
  • Running pkill java on a shared host and killing the wrong JVMs.
  • Leaving production jobs under nohup instead of systemd.
  • Trying to kill a zombie instead of fixing its parent.

How to answer in the interview

"ps aux lists all processes with PID, user, CPU and memory, and ps -ef also shows the parent PID; top or htop gives a live sorted view. Each process has a PID, a parent and a state such as running, sleeping, D for waiting on I/O, or zombie. I control them with signals: kill sends SIGTERM to stop politely, and kill -9 sends SIGKILL, which cannot be caught, as a last resort. An ampersand runs a command in the background, nohup keeps it after logout, though for real services I use systemd, and nice changes priority. pgrep and pkill work by name and lsof shows open files and ports."

Likely follow-up questions

  • What is the difference between nice and renice? nice sets priority when starting a process; renice changes it for a running one.
  • What does D state mean? Uninterruptible sleep, usually waiting on disk or network storage; it cannot be killed until the I/O returns.
  • How do you find what is using a port? ss -tulpn or lsof -i :PORT.
