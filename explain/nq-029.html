What are UnaryOperator and BinaryOperator?

Java 8+ Features · concept · levels entry, mid

In one line

UnaryOperator<T> extends Function<T,T> (one T in, one T out) and BinaryOperator<T> extends BiFunction<T,T,T> (two Ts in, one T out); they're used by List.replaceAll, Stream.iterate, reduce, Map.merge, and offer helpers like identity(), minBy and maxBy.

Detailed explanation

Function<T, R> and BiFunction<T, U, R> allow different input and output types. Very often, though, an operation keeps the same type: trimming a string, doubling a number, adding two amounts. Writing Function<String, String> or BiFunction<Integer, Integer, Integer> is verbose and hides the intent. The operator interfaces express "same type in and out" directly.

UnaryOperator<T> inherits T apply(T t) from Function<T,T>. Examples: String::trim, x -> x * 2, BigDecimal::negate. APIs that use it: List.replaceAll(UnaryOperator<E>) transforms every element in place; Stream.iterate(seed, UnaryOperator) generates successive values; Optional/Function composition. UnaryOperator.identity() returns its argument, typed correctly as an operator.

BinaryOperator<T> inherits T apply(T a, T b) from BiFunction<T,T,T>. Examples: Integer::sum, BigDecimal::add, Math::max, String::concat. It's exactly the shape Stream.reduce needs, and is also used by Map.merge, Collectors.reducing, Collectors.toMap's merge function, and Arrays.parallelPrefix. Static helpers BinaryOperator.minBy(comparator) and maxBy(comparator) return the smaller or larger of two elements.

For primitives there are IntUnaryOperator, LongUnaryOperator, DoubleUnaryOperator (applyAsInt etc.) and IntBinaryOperator, LongBinaryOperator, DoubleBinaryOperator, which avoid boxing; IntStream.reduce and IntStream.iterate use them.

How it works

  1. Declare an operator variable or pass a lambda where one is expected.
  2. The compiler checks that input and output types are identical.
  3. The API calls apply (or applyAsInt for primitives).
  4. Because they extend Function/BiFunction, andThen composition is available.

Example

UnaryOperator<String> normalise = s -> s.trim().toLowerCase(Locale.ROOT);
List<String> emails = new ArrayList<>(List.of("  A@X.COM ", "b@y.com "));
emails.replaceAll(normalise);                         // [a@x.com, b@y.com]

List<Integer> powers = Stream.iterate(1, x -> x * 3).limit(5).toList(); // [1,3,9,27,81]

BinaryOperator<BigDecimal> add = BigDecimal::add;
BigDecimal total = prices.stream().reduce(BigDecimal.ZERO, add);

Map<String, Integer> stock = new HashMap<>();
stock.merge("SKU-1", 5, Integer::sum);               // BinaryOperator as remapping
stock.merge("SKU-1", 3, Integer::sum);               // SKU-1=8

BinaryOperator<Employee> higherPaid = BinaryOperator.maxBy(Comparator.comparing(Employee::salary));
Optional<Employee> top = employees.stream().reduce(higherPaid);

IntBinaryOperator mul = (a, b) -> a * b;
int factorial = IntStream.rangeClosed(1, 5).reduce(1, mul);   // 120

Common mistakes

  • Using Function<T,T> where UnaryOperator<T> is required (e.g. replaceAll won't accept a plain Function variable).
  • Passing a non-associative BinaryOperator to reduce.
  • Forgetting primitive variants in numeric hot paths.
  • Confusing UnaryOperator.identity() with Function.identity() types.

How to answer in the interview

"They're specialisations for operations where inputs and output have the same type. UnaryOperator extends Function of T to T: one T in, one T out, like String::trim or x -> x * 2. List.replaceAll takes a UnaryOperator, and UnaryOperator.identity returns its input. BinaryOperator extends BiFunction of T, T, T: two Ts in, one out, like Integer::sum, which is exactly what reduce needs. It's also used by Map.merge, and it has static minBy and maxBy taking a Comparator. Primitive versions are IntUnaryOperator and IntBinaryOperator."

Likely follow-up questions

  • Where else is BinaryOperator used in the Collections API? Map.merge, Collectors.toMap merge functions, Collectors.reducing, Arrays.parallelPrefix.
  • Is a UnaryOperator a Function? Yes, it extends Function<T,T>, so it can be used wherever that Function is expected.
  • What does Stream.iterate take? A seed and a UnaryOperator (plus a Predicate in the Java 9 overload).
