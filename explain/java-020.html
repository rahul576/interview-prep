Describe the JVM memory areas and how garbage collection generations work.

JVM & Performance · concept · levels mid, senior

In one line

The JVM has a shared heap for objects, a stack per thread for frames and locals, Metaspace in native memory for class metadata, plus the PC register, native method stacks and code cache; most collectors are generational, allocating in Eden, aging objects through survivor spaces and promoting long-lived ones to the old generation.

Detailed explanation

Heap. Shared by all threads; holds every object and array; sized with -Xms/-Xmx (or MaxRAMPercentage in containers); managed by the garbage collector. Exhausting it gives OutOfMemoryError: Java heap space.

Thread stacks. Each thread has its own stack of frames, one per method call, containing local variables, the operand stack and return information. Frames vanish when the method returns, so no GC is needed. Size is set by -Xss; deep recursion gives StackOverflowError.

Metaspace. Since Java 8, class metadata (class structures, method bytecode, constant pools) lives in native memory, replacing PermGen. It grows dynamically, so it is usually capped with -XX:MaxMetaspaceSize.

Others. The PC register per thread points at the current bytecode instruction; native method stacks serve JNI code; the code cache stores JIT-compiled machine code. Thread stacks, Metaspace, code cache, GC structures and direct ByteBuffers are all off-heap, which matters when sizing containers.

Generations. The weak generational hypothesis says most objects die young. So the heap is split: the young generation (Eden plus two survivor spaces) and the old generation. New objects are allocated in Eden by pointer bumping in thread-local buffers. When Eden fills, a minor GC copies the few live objects into a survivor space and increments their age; dead objects cost nothing. Objects that reach the tenuring threshold (up to 15) or do not fit are promoted to the old generation, which is collected less often by major or mixed collections.

G1 (default since Java 9) keeps this logic but uses many equal-sized regions tagged as eden, survivor, old or humongous. ZGC became generational in Java 21 and, in recent JDKs, generational-only. Parallel and Serial use contiguous generations.

How it works

  1. Class metadata is loaded into Metaspace.
  2. A thread calls a method; a frame is pushed on its stack.
  3. new allocates the object in Eden; the reference sits in the frame.
  4. Eden fills; a minor GC copies live objects to a survivor space.
  5. Objects surviving several cycles are promoted to the old generation.
  6. Old generation fills; a concurrent cycle, mixed or full GC reclaims it.

Example

java -Xms2g -Xmx2g -Xss512k -XX:MaxMetaspaceSize=256m \
     -XX:+UseG1GC -Xlog:gc*:file=gc.log:time,uptime -jar app.jar

jcmd <pid> GC.heap_info        # current generation/region usage
jstat -gcutil <pid> 1000       # S0 S1 E O M percentages every second

Common mistakes

  • Saying objects live on the stack; only references and primitives do (escape analysis aside).
  • Calling Metaspace part of the heap.
  • Setting container memory equal to -Xmx, ignoring off-heap usage.
  • Assuming every collector uses fixed contiguous generations.

How to answer in the interview

"The heap is shared by all threads and holds objects and arrays; it is managed by the garbage collector. Each thread has its own stack of frames holding local variables, operand stacks and return addresses, which is why deep recursion gives StackOverflowError. Metaspace, in native memory since Java 8, stores class metadata, and there are also the PC register, native method stacks and the code cache for JIT-compiled code. Most collectors are generational: new objects go into Eden, minor GCs copy survivors between the survivor spaces, and objects that survive enough cycles are promoted to the old generation, which is collected less often, because most objects die young. G1 does the same with regions instead of fixed areas."

Likely follow-up questions

  • What is the difference between a minor GC, a major GC and a full GC? Minor collects young only; major targets the old generation; full collects the entire heap, usually in a long stop-the-world pause.
  • Why two survivor spaces? Copying between them compacts live objects and keeps one always empty.
  • What is a TLAB? A thread-local allocation buffer in Eden that makes allocation a lock-free pointer bump.
