Explain a retrieval-augmented generation pipeline end to end.

LLMOps & RAG · concept · levels entry, mid, senior

In one line

RAG has an offline ingestion side (load, parse, clean, chunk, embed, index with metadata) and an online query side (rewrite, embed, hybrid retrieve with filters, rerank, build a grounded prompt, answer with citations), all evaluated offline and monitored in production.

Detailed explanation

Retrieval-augmented generation gives a model access to private or fresh knowledge at query time instead of retraining it, and lets answers cite sources.

Ingestion (offline, continuous).

  • Connectors load documents from SharePoint, Confluence, Google Drive, databases, ticket systems, websites or file shares, ideally incrementally (only changed documents).
  • Parsing turns PDFs, Word, HTML and slides into clean text while preserving structure: headings, lists, tables, code. Layout-aware parsers or OCR handle scanned documents. Boilerplate (menus, footers) is removed and duplicates detected.
  • Metadata: source URL, title, section path, author, dates, language, document type and access permissions.
  • Chunking splits documents into retrievable units, ideally along structure.
  • Embedding: each chunk becomes a vector via an embedding model.
  • Indexing: vectors, text and metadata go into a vector index, usually with a keyword (BM25) index too.

Query (online).

  • Optionally rewrite the question (standalone form from chat history, extract filters).
  • Embed the query with the same embedding model.
  • Retrieve candidates with hybrid search (vector plus keyword) and metadata filters (permissions, product, date).
  • Rerank the top 30 to 100 candidates with a cross-encoder; keep the best few.
  • Prompt: instructions (answer only from context, cite sources, say you don't know), the retrieved chunks with IDs, and the question.
  • Generate the answer with citations that map to source links.

Quality loop. Offline evaluation with a test set (retrieval recall, faithfulness, correctness), and production monitoring: retrieval scores, "no answer" rates, user feedback, latency and cost. Most quality problems originate in ingestion and retrieval (bad parsing, poor chunking, missing documents), not in the model.

How it works

  1. Sync and parse sources; attach metadata and ACLs.
  2. Chunk, embed and upsert into hybrid index.
  3. At query time, rewrite and embed the question.
  4. Hybrid retrieve with filters; rerank; select top k.
  5. Generate a grounded, cited answer; log and evaluate.

Example

def answer(question, user):
    q = rewrite_standalone(question, user.history)
    candidates = index.hybrid_search(q, k=50, filter={"allowed_groups": user.groups})
    top = reranker.rank(q, candidates)[:6]
    context = "\n\n".join(f"[{c.id}] {c.title}: {c.text}" for c in top)
    prompt = (f"Answer using only the sources below. Cite as [id]. "
              f"If the answer is not there, say you don't know.\n\n{context}\n\nQuestion: {question}")
    return llm.generate(prompt), [c.url for c in top]

Common mistakes

  • Treating RAG as "vector DB plus prompt" and neglecting parsing.
  • No permission metadata, leaking restricted content.
  • Pure vector search missing exact identifiers.
  • Shipping without an evaluation set.

How to answer in the interview

"RAG has an offline indexing side and an online query side. Ingestion loads documents from sources like Confluence, SharePoint or databases, parses them into clean structured text, attaches metadata such as source, date and permissions, splits them into chunks, embeds each chunk and stores vectors, text and metadata in an index, usually with a keyword index too. At query time I rewrite the question if needed, embed it, run hybrid search with metadata and permission filters, rerank the candidates and keep the top few. The prompt tells the model to answer only from that context with citations, and the pipeline is evaluated offline and monitored in production."

Likely follow-up questions

  • Where do most problems originate? Parsing, chunking and retrieval, not generation.
  • How do you keep the index fresh? Incremental sync with change detection and deletes.
  • RAG vs fine-tuning? RAG for knowledge and freshness; fine-tuning for behaviour and format.
