What is Spring Boot, and how does it differ from the Spring Framework?

Spring Boot · concept · levels mid, senior

In one line

Spring Framework provides the core features (DI, MVC, transactions, data access) but leaves configuration to you; Spring Boot is an opinionated layer on top that adds auto-configuration based on the classpath, starter dependencies, an embedded server with an executable jar, externalised configuration and production features like Actuator.

Detailed explanation

With plain Spring Framework you assemble everything yourself: declare a DispatcherServlet, a DataSource and connection pool, an EntityManagerFactory, transaction manager, Jackson ObjectMapper, view resolvers, choose compatible library versions, and deploy a WAR to an external Tomcat or application server. That is flexible but repetitive and error-prone.

Spring Boot keeps the same framework underneath and removes this setup:

  • Auto-configuration: conditional configuration classes create beans when the right libraries are on the classpath and you have not defined your own. Add the PostgreSQL driver and a URL property, and you get a HikariCP DataSource, JPA and a transaction manager. Your own beans always win.
  • Starters: dependency bundles such as spring-boot-starter-web, -data-jpa, -security, -actuator, with managed, tested versions through the Boot parent or BOM, so you rarely specify versions.
  • Embedded server: Tomcat by default (Jetty, Undertow or Netty for WebFlux), so the app is an executable fat jar started with java -jar, ideal for containers. Build plugins also create OCI images with Buildpacks.
  • Externalised configuration: application.yml/.properties, profiles, env vars and command-line overrides with defined precedence, plus type-safe @ConfigurationProperties.
  • Production readiness: Actuator health checks, metrics with Micrometer, Kubernetes probes, graceful shutdown, structured logging.
  • Developer experience: DevTools, Testcontainers and Docker Compose integration, test slices like @WebMvcTest, @DataJpaTest.

Boot is "opinionated" in its defaults, but not restrictive: you can override any property, define your own beans, or exclude auto-configurations. In short: Spring is the framework; Boot is the fastest, most consistent way to configure and run it.

How it works

  1. You add starters to the build.
  2. @SpringBootApplication triggers component scanning and auto-configuration.
  3. Conditions check classpath, beans and properties and register defaults.
  4. SpringApplication.run creates the context and starts the embedded server.
  5. Actuator and config binding provide operational features.

Example

<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-web</artifactId>
</dependency>
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>
<dependency>
  <groupId>org.postgresql</groupId>
  <artifactId>postgresql</artifactId>
  <scope>runtime</scope>
</dependency>
@SpringBootApplication
public class ShopApplication {
    public static void main(String[] args) { SpringApplication.run(ShopApplication.class, args); }
}
./mvnw package && java -jar target/shop-1.0.jar --spring.profiles.active=prod

Common mistakes

  • Calling Spring Boot a different framework that replaces Spring.
  • Saying Boot "cannot be customised".
  • Not knowing how to see what auto-configuration did.

How to answer in the interview

"The Spring Framework provides the core: dependency injection, MVC, transactions and data access. But on its own I'd have to configure a lot: the DispatcherServlet, data sources, a servlet container and many beans, and pick compatible versions. Spring Boot is an opinionated layer on top that removes that work. Auto-configuration creates sensible beans based on the classpath and properties and backs off when I define my own; starters like spring-boot-starter-web bring compatible libraries; and an embedded Tomcat lets me run the app as an executable jar with java -jar. It also adds externalised configuration with profiles and production features like Actuator health checks and metrics."

Likely follow-up questions

  • How would you see which auto-configurations were applied and why? Start with --debug for the conditions report or call /actuator/conditions.
  • Can you deploy Boot as a WAR? Yes, extend SpringBootServletInitializer and package as WAR.
  • What is the Boot BOM? spring-boot-dependencies, which manages versions of supported libraries.
