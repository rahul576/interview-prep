What is the purpose of the test() method in Predicate and the get() method in Supplier?

Java 8+ Features · concept · levels entry

In one line

test(T) is the single abstract method of Predicate: it evaluates a condition and returns a boolean, called by filter, removeIf and anyMatch; get() is the single abstract method of Supplier: it returns a value with no input, representing a lazy computation used by orElseGet, Stream.generate and ThreadLocal.withInitial.

Detailed explanation

Every functional interface has one method that a lambda implements. For Predicate<T> that method is boolean test(T t). When you write filter(o -> o.isPaid()), the lambda body becomes the implementation of test. The stream then calls test on each element and keeps those returning true. Other callers include Collection.removeIf (removes elements where test is true), anyMatch, allMatch, noneMatch, Optional.filter, takeWhile and dropWhile. You invoke it directly with predicate.test(x), for example in your own validation framework.

For Supplier<T> the method is T get(). It takes nothing and returns a value, so it models deferred work: the code inside runs only when someone calls get(), and may run zero, one or many times. That's why it's used wherever laziness matters:

  • Optional.orElseGet(supplier) calls get() only if the Optional is empty.
  • Stream.generate(supplier) calls get() repeatedly to produce an infinite stream.
  • ThreadLocal.withInitial(supplier) calls it once per thread to create the initial value.
  • Objects.requireNonNullElseGet, Collectors.toCollection(TreeSet::new), CompletableFuture.supplyAsync, and logging APIs like log.debug(() -> expensive()) also use it.

Supplier does not cache the result; each get() re-executes. If you need memoisation, wrap it (Guava's Suppliers.memoize or your own lazy holder).

How it works

  1. A lambda passed where Predicate is expected implements test.
  2. The API iterates and calls test(element), branching on the boolean.
  3. A lambda passed where Supplier is expected implements get.
  4. The API calls get() only at the moment it needs a value.

Example

Predicate<Order> isLarge = o -> o.total().compareTo(new BigDecimal("10000")) > 0;
boolean flag = isLarge.test(order);                 // explicit invocation
orders.removeIf(Order::isCancelled);                // removeIf calls test
boolean anyLarge = orders.stream().anyMatch(isLarge);

Supplier<Config> loader = () -> configService.loadFromRemote();   // nothing runs yet
Config cfg = localConfig.orElseGet(loader);         // get() only if empty

ThreadLocal<SimpleDateFormat> fmt =
    ThreadLocal.withInitial(() -> new SimpleDateFormat("yyyy-MM-dd"));  // once per thread

List<Double> randoms = Stream.generate(Math::random).limit(3).toList();

Common mistakes

  • Assuming a Supplier caches its value.
  • Calling supplier.get() eagerly and passing the result, losing laziness.
  • Using Predicates with side effects inside test.
  • Confusing get() on Supplier with Optional.get().

How to answer in the interview

"test is the single abstract method of Predicate. It takes one argument and returns true or false, and every lambda I pass as a condition implements it; filter, removeIf, anyMatch and allMatch call test on each element. get is the single abstract method of Supplier. It takes no arguments and returns a value, so it represents a deferred or lazy computation: orElseGet calls get only if the value is missing, Stream.generate calls it repeatedly, and ThreadLocal.withInitial uses it to create each thread's initial value. I can also call predicate.test(x) or supplier.get() directly."

Likely follow-up questions

  • Why is orElseGet with a Supplier more efficient than orElse? The supplier runs only when the Optional is empty.
  • Does Supplier cache its result? No, each get() executes again.
  • What's BooleanSupplier? A primitive variant with getAsBoolean().
