What is the Template Method pattern?

Design Patterns · concept · levels mid

In one line

Template Method defines the skeleton of an algorithm in a base-class method (often final) and lets subclasses override specific steps or optional hooks, reusing the invariant workflow while varying the details.

Detailed explanation

Many processes share the same sequence of steps and differ only in a few of them. Importing CSV, JSON or XML files always means: open, parse, validate, save, close, report. Copying that workflow into each importer duplicates code and lets the order drift.

Template Method moves the fixed sequence into an abstract base class:

  • The template method (importFile()) calls the steps in order. Marking it final stops subclasses from changing the sequence.
  • Abstract primitive operations (parse()) must be implemented by every subclass.
  • Hook methods (beforeSave(), shouldSkip(record)) have default, often empty, implementations that subclasses may override.

This follows the Hollywood principle: "don't call us, we'll call you." The base class controls the flow and calls subclass code at the right moments.

Examples: HttpServlet.service() dispatches to doGet/doPost; AbstractList implements most of List on top of get and size; JUnit's lifecycle; Spring's AbstractController historically. Spring's JdbcTemplate, RestTemplate, TransactionTemplate and JmsTemplate use the same idea with callbacks instead of inheritance: the template handles connections, exceptions and cleanup, and you pass a RowMapper or TransactionCallback lambda for the variable part.

Downsides: it relies on inheritance, which couples subclasses to the base class, limits you to one base class, and can lead to fragile hierarchies. The composition-based alternative is to pass the variable steps as Strategy objects or lambdas, exactly what JdbcTemplate does.

How it works

  1. Write an abstract class with a final template method.
  2. The template method calls steps in a fixed order.
  3. Declare varying steps as abstract; optional ones as hooks with defaults.
  4. Subclasses implement only those steps.
  5. Clients call the template method on a subclass instance.

Example

public abstract class DataImporter {
    public final ImportReport importFile(Path file) {          // template method
        List<Record> records = parse(readAll(file));            // varying step
        records.removeIf(this::shouldSkip);                     // hook
        records.forEach(this::validate);
        repository.saveAll(records);
        return new ImportReport(file, records.size());
    }
    protected abstract List<Record> parse(String content);
    protected boolean shouldSkip(Record r) { return false; }    // hook default
    private void validate(Record r) { /* common rules */ }
}

public class CsvImporter extends DataImporter {
    protected List<Record> parse(String content) { /* split lines */ return List.of(); }
}

// Same idea via callback (composition)
List<String> names = jdbcTemplate.query("SELECT name FROM users", (rs, i) -> rs.getString(1));

Common mistakes

  • Not making the template method final, letting subclasses break the order.
  • Too many abstract steps, forcing subclasses to implement irrelevant ones.
  • Deep inheritance chains of templates.
  • Calling JdbcTemplate a pure GoF Template Method without noting it uses callbacks.

How to answer in the interview

"Template Method defines the skeleton of an algorithm in a base class method, usually final, and lets subclasses override certain steps without changing the structure. For example an abstract DataImporter has importFile, which always opens, parses, validates and saves, while CsvImporter and JsonImporter only override parse. Hooks with default implementations are optional extension points. It removes duplicated workflow code and guarantees the order. Examples are HttpServlet.service calling doGet, AbstractList, and JdbcTemplate, which applies the idea with callbacks instead of inheritance. The downside is inheritance coupling; Strategy is the composition alternative."

Likely follow-up questions

  • How would you do it with composition? Pass the varying steps as strategy interfaces or lambdas into a single concrete class.
  • What is a hook method? An optional step with a default implementation that subclasses may override.
  • Template Method vs Strategy? Template Method varies steps via inheritance; Strategy swaps whole algorithms via composition.
