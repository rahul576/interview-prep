What is the difference between ArrayList and LinkedList, and which one do you use by default?

Collections · concept · levels entry, mid

In one line

ArrayList is backed by a resizable array with O(1) index access, while LinkedList is a doubly linked list of nodes; I default to ArrayList because of cache locality and lower memory, and use ArrayDeque for queues.

Detailed explanation

An ArrayList keeps its elements in one contiguous Object[]. Reading get(i) is a direct array lookup, so it is O(1). Appending is amortised O(1): most adds just write into a free slot, and only occasionally does the list grow by about 1.5 times and copy the array. Inserting or removing in the middle is O(n) because every later element is shifted with System.arraycopy.

A LinkedList stores each element in a Node with prev and next references. Inserting or removing is O(1) once you hold the position (via a ListIterator or at the head and tail), but finding that position by index is O(n) because it walks from the nearer end. LinkedList also implements Deque.

The textbook view says LinkedList wins for inserts, but real hardware disagrees. Each node is a separate object with a header and two references, so it costs roughly 24 to 40 bytes per element instead of about 4 to 8 for an array slot. Nodes are scattered on the heap, so iteration means pointer chasing and frequent CPU cache misses, whereas an array streams through memory and benefits from prefetching. Even a middle insert in an ArrayList is often faster, because arraycopy of a contiguous block is extremely quick compared with walking nodes to find the spot.

How it works

  1. new ArrayList<>() starts with an empty shared array; the first add allocates capacity 10.
  2. Adds write into elementData[size++] until the array is full.
  3. When full, a new array of about 1.5 times the size is created with Arrays.copyOf.
  4. LinkedList add creates a node and links it after last, updating two references.
  5. LinkedList get(i) walks from first or last, whichever is nearer.

Example

List<Order> orders = new ArrayList<>(expectedSize); // presize to avoid copies
orders.add(order);
Order third = orders.get(2);                        // O(1)

Deque<Task> work = new ArrayDeque<>();              // queue/stack, not LinkedList
work.offerLast(task);
Task next = work.pollFirst();

Common mistakes

  • Choosing LinkedList "because we insert a lot" without measuring.
  • Calling get(i) in a loop on a LinkedList, which makes the loop O(n²).
  • Using LinkedList or Stack for queues instead of ArrayDeque.
  • Forgetting to presize an ArrayList when the size is known.

How to answer in the interview

"ArrayList is a resizable array, so index access is constant time and appends are amortised constant time, but inserting in the middle shifts elements. LinkedList is a doubly linked list, so it can relink in constant time once you are at a position, but reaching that position is linear. In practice I default to ArrayList: contiguous memory gives great cache locality and much lower overhead per element, and that usually beats LinkedList even for inserts. If I need a queue or a stack, I use ArrayDeque rather than LinkedList."

Likely follow-up questions

  • How does ArrayList grow? It allocates a new array of about 1.5 times the old capacity and copies the elements.
  • When might LinkedList still make sense? Heavy insert/remove through a ListIterator on a long list, measured with a benchmark.
  • Is either thread safe? No; use concurrent collections or external synchronisation.
