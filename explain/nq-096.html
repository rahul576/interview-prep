Given a list or array of strings, how would you group words that are anagrams of one another?

DSA: Arrays & Strings · scenario · levels mid

In one line

Map each word to a canonical key (its sorted characters or a character-count signature), group words in a HashMap<String, List<String>> by that key, and return the map values; this runs in O(n·k log k) with sorting or O(n·k) with counting.

Detailed explanation

All anagrams share the same multiset of characters, so any representation that depends only on that multiset can act as a group key. Words with equal keys are anagrams; words with different keys are not.

Two common keys:

  • Sorted characters: "eat", "tea" and "ate" all become "aet". Simple to write; costs O(k log k) per word of length k.
  • Frequency count: count letters into an int[26] and turn it into a string like "1#0#0#0#1#...", costing O(k) per word, better for long words.

Algorithm: iterate once over the input. For each word, compute the key and append the word to the list for that key using computeIfAbsent, which creates the list on first sight. Finally return new ArrayList<>(map.values()).

Complexity: for n words with maximum length k, sorting keys give O(n·k log k) time; counting keys give O(n·k). Space is O(n·k) for the keys and lists. Compare this with the brute-force approach of comparing every pair, O(n²·k), which is far slower for large lists.

Variations the interviewer may add: keep groups in the order of first appearance (use LinkedHashMap), return only groups with more than one word, sort each group, or handle case and spaces (normalise before building the key while storing the original word).

How it works

  1. Create Map<String, List<String>> groups.
  2. For each word, normalise if required and build the key.
  3. groups.computeIfAbsent(key, k -> new ArrayList<>()).add(word).
  4. After the loop, collect groups.values().
  5. Return them as List<List<String>>.

Example

public static List<List<String>> groupAnagrams(String[] words) {
    Map<String, List<String>> groups = new LinkedHashMap<>();   // keeps first-seen order
    for (String w : words) {
        char[] chars = w.toCharArray();
        Arrays.sort(chars);
        String key = new String(chars);
        groups.computeIfAbsent(key, k -> new ArrayList<>()).add(w);
    }
    return new ArrayList<>(groups.values());
}

// ["eat","tea","tan","ate","nat","bat"]
// -> [[eat, tea, ate], [tan, nat], [bat]]

Common mistakes

  • Comparing every pair of words (quadratic).
  • Using chars.toString() as the key (gives an identity string like [C@1b6d3586, not the contents).
  • Using the int[] array itself as a map key (arrays use identity equality).
  • Forgetting to normalise case when the problem requires it.

How to answer in the interview

"Anagrams share the same multiset of characters, so I map each word to a canonical key and group by it. The simplest key is the word with its characters sorted: eat, tea and ate all become aet. I loop once over the words, compute the key, and add the word to a HashMap<String, List<String>> with computeIfAbsent. At the end the map values are the groups. For n words of length up to k that's O(n·k log k) because of sorting each word, and O(n·k) space. With a character-count key instead of sorting it becomes O(n·k)."

Likely follow-up questions

  • How do you keep groups in first-appearance order? Use a LinkedHashMap.
  • Why not compare all pairs? That is O(n²·k); hashing by key is linear in n.
  • How do you return only real groups? Filter values with size() > 1.
