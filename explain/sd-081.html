Design semantic search over a product catalogue of 50 million items.

AI & ML System Design · design · levels mid, senior

In one line

Semantic product search embeds items and queries with the same model, retrieves with an ANN index (HNSW/IVF) that is sharded and quantised for 50M items, combines it with keyword search and filters (hybrid), re-ranks with business signals, and measures relevance offline (NDCG) and online (A/B).

Detailed explanation

Keyword search fails when users describe needs ("warm jacket for trekking") rather than product names. Embeddings place text with similar meaning close together in vector space, so semantically related products match even without shared words.

Exact nearest-neighbour search over 50M vectors per query is too slow, so we use approximate nearest neighbour indexes: HNSW graphs (high recall, memory-heavy) or IVF clustering (probe a few clusters), often with product quantisation or int8 to shrink vectors 4–30x. 50M × 768 float32 ≈ 150 GB raw, so shard across nodes and replicate for QPS.

Vectors alone miss exact matches (model numbers, brand names, sizes), so hybrid retrieval runs BM25 in parallel and fuses results (reciprocal rank fusion), with structured filters (category, price, in stock) applied inside the search (pre-filtering) to avoid empty results.

Final re-ranking blends relevance with popularity, conversion, margin, availability and personalisation, possibly a learning-to-rank model trained on clicks.

How it works

  1. Offline: product text (title + attributes + description) → embedding → upsert into vector index; update on catalogue changes via CDC.
  2. Query: normalise, detect filters ("under ₹2000") → embed → ANN top 200 + BM25 top 200 with filters.
  3. Fuse → re-rank → top 48 results.
  4. Log queries, clicks, add-to-cart for training and evaluation.

Example

{ "query": { "hybrid": { "queries": [
    { "match": { "title": "warm jacket for trekking" } },
    { "knn": { "embedding": { "vector": [0.12, -0.03], "k": 200 } } } ] } },
  "post_filter": { "range": { "price": { "lte": 2000 } } } }

Common mistakes

  • Different embedding models for indexing and queries.
  • Post-filtering after ANN (returns too few results).
  • Ignoring exact-match needs.
  • No offline relevance set to judge changes.

How to answer in the interview

"Products and queries are embedded with the same model; an HNSW or IVF index, sharded and quantised, retrieves nearest neighbours fast. I'd run BM25 alongside for exact terms and apply structured filters inside the search, then fuse the results and re-rank with popularity, stock and personalisation. Relevance is tracked offline with NDCG on labelled queries and online with A/B tests on conversion."

Likely follow-up questions

  • Keep embeddings fresh? CDC-triggered re-embedding; full re-index on model change with alias swap.
  • HNSW vs IVF-PQ? HNSW better recall/latency, more memory; IVF-PQ compact.
  • Multilingual queries? Multilingual embedding models.
