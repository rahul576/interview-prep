A stateful application on Kubernetes must keep its data when pods are rescheduled or updated. How do you design its storage?

Kubernetes · scenario · levels entry, mid, senior

In one line

Keep data on PersistentVolumes via PVCs, run the app as a StatefulSet with volumeClaimTemplates for stable identity and one volume per pod, use a CSI StorageClass with WaitForFirstConsumer and Retain, add backups and snapshots, and consider an operator or managed database.

Detailed explanation

A container's writable layer and emptyDir volumes live and die with the pod. Data that must survive rescheduling and updates needs a PersistentVolume, requested through a PersistentVolumeClaim, so storage has its own lifecycle independent of pods.

A StatefulSet with volumeClaimTemplates gives each replica a stable identity (db-0, db-1), a stable DNS name through a headless Service, ordered rollout, and its own PVC (data-db-0). When db-0 is rescheduled or updated, it reattaches to the same claim, so its data follows it. A Deployment sharing one ReadWriteOnce PVC cannot do this safely.

A StorageClass drives dynamic provisioning through the cloud CSI driver: disk type, IOPS, encryption. In multi-zone clusters set volumeBindingMode: WaitForFirstConsumer, so the disk is created in the zone where the pod is scheduled, not in a random zone where the pod could never run. For important data use reclaimPolicy: Retain, so deleting a PVC does not destroy the disk, and allowVolumeExpansion: true for growth. Remember that block volumes are zonal: a pod can only move to nodes in that zone.

Volumes are not backups: corruption and accidental deletes replicate happily. Schedule CSI VolumeSnapshots or Velero backups and test restores. For databases, an operator such as CloudNativePG, or a managed cloud database, usually beats a hand-built StatefulSet because it handles replication, failover, backups and upgrades.

How it works

  1. Define a StorageClass with CSI driver, WaitForFirstConsumer, Retain, expansion.
  2. Create a headless Service and a StatefulSet with volumeClaimTemplates.
  3. Each pod gets its own PVC, bound to a PV in its zone.
  4. Rescheduled pods reattach to the same PVC.
  5. Snapshots and backups run on a schedule; restores are tested.

Example

apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata: { name: ssd-retain }
provisioner: ebs.csi.aws.com
parameters: { type: gp3, encrypted: "true" }
reclaimPolicy: Retain
allowVolumeExpansion: true
volumeBindingMode: WaitForFirstConsumer
---
apiVersion: apps/v1
kind: StatefulSet
metadata: { name: db }
spec:
  serviceName: db
  replicas: 3
  selector: { matchLabels: { app: db } }
  template:
    metadata: { labels: { app: db } }
    spec:
      containers:
        - name: db
          image: postgres:17
          volumeMounts: [{ name: data, mountPath: /var/lib/postgresql/data }]
  volumeClaimTemplates:
    - metadata: { name: data }
      spec:
        accessModes: ["ReadWriteOnce"]
        storageClassName: ssd-retain
        resources: { requests: { storage: 100Gi } }

Common mistakes

  • Storing data in emptyDir or the container filesystem.
  • Immediate binding in multi-zone clusters, leaving pods unschedulable.
  • Treating replicated volumes as backups.
  • Hand-building database clustering that an operator already solves.

How to answer in the interview

"Anything in the container filesystem or an emptyDir disappears with the pod, so data goes on PersistentVolumes via PVCs. I use a StatefulSet with volumeClaimTemplates, so each replica has a stable name like db-0 and its own PVC, and reattaches to it when rescheduled. A StorageClass with the CSI driver provisions disks dynamically; I use WaitForFirstConsumer so the disk is created in the pod's zone, Retain for important data and allow expansion. Volumes are not backups, so I add snapshots or Velero and test restores. For databases I'd prefer an operator like CloudNativePG or a managed database."

Likely follow-up questions

  • Why is WaitForFirstConsumer important in multi-zone clusters? It delays disk creation until scheduling, so the disk lands in the pod's zone.
  • What happens to PVCs when you scale a StatefulSet down? They are kept by default; the retention policy can change that.
  • ReadWriteMany? Needs file storage such as EFS or Azure Files; slower, but shareable.
