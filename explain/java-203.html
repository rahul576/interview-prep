How do enums work in Java, and what can they do beyond simple constants?

Core Java & OOP · concept · levels entry, mid

In one line

A Java enum is a full class with a fixed set of singleton instances: it can have fields, constructors, methods, constant-specific behaviour and interfaces, and works best with EnumMap/EnumSet and switch; persist it by name, not ordinal.

Detailed explanation

Every enum implicitly extends java.lang.Enum. Each constant is a public static final instance created once when the enum class is initialised, so constants are effectively singletons and thread-safe to share. You cannot instantiate an enum with new; constructors are implicitly private.

Beyond simple constants, enums can:

  • Hold state in final fields set by a constructor, for example a currency code and its minor units.
  • Have methods, including static lookup helpers.
  • Implement interfaces, so they fit into strategy-style designs.
  • Provide constant-specific bodies: declare an abstract method and let each constant implement it. This replaces switch statements on the enum, keeping behaviour next to data.

Built-in methods: values() returns all constants in declaration order, valueOf(String) looks one up by exact name (throws IllegalArgumentException if unknown), name() and ordinal() give its name and position. EnumSet is a bit-vector set and EnumMap an array-backed map, both much faster and more compact than HashSet/HashMap for enum keys.

Enums also give the simplest correct singleton in Java (resistant to reflection and serialization attacks). Modern switch expressions (Java 14+) over enums can be exhaustive without a default, so the compiler tells you when a new constant is missing.

How it works

  1. The compiler turns the enum into a final class extending Enum.
  2. A static initialiser creates each constant once, in order.
  3. ordinal is assigned by declaration position.
  4. Serialization writes only the name and resolves to the existing constant on read.
  5. Switches on enums compile to efficient lookups.

Example

public enum Operation implements DoubleBinaryOperator {
    PLUS("+")  { public double applyAsDouble(double a, double b) { return a + b; } },
    TIMES("*") { public double applyAsDouble(double a, double b) { return a * b; } };

    private final String symbol;
    Operation(String symbol) { this.symbol = symbol; }
    public String symbol() { return symbol; }
}

EnumMap<Operation, Long> usage = new EnumMap<>(Operation.class);

@Enumerated(EnumType.STRING)   // JPA: store "PLUS", never the ordinal
private Operation op;

Common mistakes

  • Persisting ordinal(); inserting or reordering a constant corrupts existing data.
  • Calling valueOf on user input without handling IllegalArgumentException.
  • Using big switch statements instead of constant-specific methods.
  • Using HashMap with enum keys where EnumMap is better.

How to answer in the interview

"An enum is a special class with a fixed set of instances that the JVM creates once, so each constant is a thread-safe singleton. Enums can have fields, a private constructor and methods, implement interfaces, and even have constant-specific behaviour by declaring an abstract method that each constant overrides, which is a neat strategy pattern. For collections keyed by enums I use EnumMap and EnumSet because they are array and bit-vector based. One rule I'm strict about: never persist the ordinal; with JPA I use EnumType.STRING or a converter with a stable code."

Likely follow-up questions

  • How would you persist an enum safely with JPA? @Enumerated(EnumType.STRING) or an AttributeConverter mapping to a stable code.
  • Can enums extend a class? No, they already extend Enum; they can implement interfaces.
  • Why is an enum a good singleton? The JVM guarantees one instance, even across serialization and reflection.
