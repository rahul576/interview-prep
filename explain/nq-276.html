What annotations and assertions do you commonly use in unit tests?

Testing · concept · levels entry

In one line

Commonly used are JUnit 5's @Test, @BeforeEach/@AfterEach, @BeforeAll/@AfterAll, @DisplayName, @Nested, @ParameterizedTest, @Disabled, Mockito's @ExtendWith(MockitoExtension.class), @Mock, @InjectMocks, @Captor, @Spy, Spring's @WebMvcTest, @DataJpaTest, @SpringBootTest, @MockitoBean, and assertions such as assertEquals, assertThrows, assertAll and AssertJ assertThat.

Detailed explanation

JUnit 5 annotations:

  • @Test marks a test method.
  • @BeforeEach / @AfterEach run before and after every test, for fresh setup and cleanup.
  • @BeforeAll / @AfterAll run once per class (static methods), for expensive shared setup like starting a container.
  • @DisplayName("rejects orders above credit limit") gives readable reports.
  • @Nested groups related scenarios in inner classes, each with its own setup.
  • @ParameterizedTest with @ValueSource, @CsvSource, @MethodSource, @EnumSource runs one test over many inputs.
  • @Disabled, @Tag, @Timeout, @TempDir for skipping, grouping, time limits and temporary folders.

Mockito annotations: @ExtendWith(MockitoExtension.class) enables processing; @Mock creates mocks; @InjectMocks creates the class under test with mocks injected; @Captor declares an ArgumentCaptor; @Spy wraps a real object.

Spring Boot Test: @WebMvcTest, @DataJpaTest, @JsonTest and @SpringBootTest choose how much context to load; @MockitoBean and @MockitoSpyBean replace beans; @Sql loads data; @ServiceConnection wires Testcontainers.

JUnit assertions (org.junit.jupiter.api.Assertions): assertEquals(expected, actual), assertNotEquals, assertNull/assertNotNull, assertTrue/assertFalse, assertSame, assertIterableEquals, assertThrows (returns the exception), assertDoesNotThrow, assertTimeout, and assertAll, which runs a group and reports all failures instead of stopping at the first.

AssertJ (assertThat(...)) is preferred by many teams: fluent chains like isEqualTo, hasSize, contains, containsExactly, extracting(Order::status), isEqualByComparingTo for BigDecimal, assertThatThrownBy(...).hasMessageContaining(...), and soft assertions. IDE auto-completion guides you and failure messages show the actual contents.

How it works

  1. Annotations tell JUnit and extensions what to run and how to prepare.
  2. Lifecycle methods run around each test.
  3. Mockito fields are initialised before each test.
  4. Assertions throw AssertionFailedError on mismatch, failing the test.
  5. Reports show display names and failure messages.

Example

@ExtendWith(MockitoExtension.class)
@DisplayName("Invoice service")
class InvoiceServiceTest {
    @Mock InvoiceRepository repo;
    @InjectMocks InvoiceService service;
    @Captor ArgumentCaptor<Invoice> saved;

    @Test
    void createsInvoiceWithTax() {
        service.create(new BigDecimal("100.00"));
        verify(repo).save(saved.capture());
        Invoice inv = saved.getValue();
        assertAll(
            () -> assertNotNull(inv.number()),
            () -> assertEquals(new BigDecimal("118.00"), inv.total()));
        assertThat(inv.lines()).hasSize(1).extracting(Line::type).containsExactly(TAX_INCLUDED);
    }

    @ParameterizedTest
    @CsvSource({"0", "-5"})
    void rejectsNonPositiveAmounts(String amount) {
        var ex = assertThrows(IllegalArgumentException.class,
                              () -> service.create(new BigDecimal(amount)));
        assertThat(ex).hasMessageContaining("positive");
    }
}

Common mistakes

  • Swapping expected and actual in assertEquals, producing confusing messages.
  • Using assertTrue(a.equals(b)) instead of assertEquals, losing detail.
  • Non-static @BeforeAll methods.
  • Comparing BigDecimal with isEqualTo, where scale makes 100.0 differ from 100.00.

How to answer in the interview

"From JUnit 5 I use @Test, BeforeEach and AfterEach for setup and cleanup, BeforeAll for one-time setup, DisplayName for readable names, Nested to group scenarios and ParameterizedTest with CsvSource or MethodSource. From Mockito: ExtendWith MockitoExtension, Mock, InjectMocks, Captor and occasionally Spy. In Spring tests: WebMvcTest, DataJpaTest, SpringBootTest and MockitoBean. For assertions I use assertEquals, assertThrows to check exceptions and assertAll to report several failures at once, and mostly AssertJ's assertThat with hasSize, extracting and containsExactly because the messages are much clearer."

Likely follow-up questions

  • Why is assertAll useful? It reports all failed checks in one run instead of stopping at the first.
  • assertThrows vs try/catch? assertThrows is concise, fails if nothing is thrown and returns the exception.
  • BeforeEach vs BeforeAll? Per test vs once per class; BeforeAll suits expensive shared resources.
