What does CI/CD look like for machine learning, and what is continuous training?

MLOps · concept · levels mid, senior, lead

In one line

ML CI/CD moves two artefacts: pipeline code, tested and deployed like software, and trained models, produced by the pipeline; continuous training (CT) retrains automatically on schedule or triggers, with automated evaluation gates before registration and promotion, and monitoring feeding back into retraining.

Detailed explanation

In ordinary software, CI/CD builds and ships code. In ML, the code (feature pipelines, training, serving) produces another artefact, the model, whose quality depends on data. So delivery has layers.

CI runs on every change: unit tests for feature and preprocessing code, data validation tests against schemas and expectations, linting, and a quick smoke training run on a small sample to catch breakage in the training logic. CD deploys the pipeline itself to dev, staging and production, so the production training pipeline is versioned, reviewed and tested rather than a notebook someone runs.

Continuous training is the extra loop introduced in MLOps maturity models: the deployed pipeline retrains the model on a schedule, when new data lands, or when drift or performance degradation is detected. Each candidate goes through automated evaluation: thresholds agreed upfront, comparison against the current production model on the same data and key segments, and checks like latency and fairness. Passing models are registered, optionally approved by a human for high-risk use cases, and deployed with a gradual rollout (shadow or canary). Monitoring in production then informs the next retrain.

How it works

  1. Developer changes feature or training code; CI runs tests, data checks and a mini training run.
  2. Merge deploys the updated pipeline to staging, then production.
  3. A trigger (schedule, new data, drift alert) starts the production training pipeline.
  4. The pipeline validates data, trains, evaluates and compares with the champion.
  5. If gates pass, the model is registered and promoted, with approval if required.
  6. Deployment rolls out gradually; monitoring watches metrics and can trigger rollback or retraining.

Example

# GitHub Actions: CI for the training pipeline code
jobs:
  ci:
    steps:
      - uses: actions/checkout@v4
      - run: pip install -r requirements.lock
      - run: pytest tests/                     # feature + preprocessing unit tests
      - run: python -m pipeline.validate --sample data/sample.parquet
      - run: python -m pipeline.train --sample --max-epochs 1   # smoke training
  deploy-pipeline:
    needs: ci
    if: github.ref == 'refs/heads/main'
    steps:
      - run: python -m pipeline.compile && az ml job create -f pipeline.yml

Common mistakes

  • Treating the model as the only artefact and running training by hand.
  • Auto-promoting retrained models without comparing against production.
  • Skipping data tests, so CI passes while the data is broken.
  • No rollback path when an automatically retrained model misbehaves.

How to answer in the interview

"ML has two artefacts: the pipeline code and the models it produces. CI tests the code, validates data and does a quick training run on a sample. CD deploys the pipeline itself through environments, so production training is versioned and reviewed. Continuous training means that pipeline retrains automatically on a schedule, new data or drift. Every candidate must pass evaluation gates, including beating the current production model, before it's registered and promoted, with human approval for high-risk models, then rolled out gradually. Monitoring closes the loop."

Likely follow-up questions

  • Which checks must pass before auto-replacing production? Data validation, thresholds, champion comparison overall and per segment, latency and smoke tests.
  • Where does a feature store fit? Shared feature definitions used by both training and serving pipelines.
  • What is the difference between CD of pipelines and CD of models? One ships code that trains; the other ships a trained artefact to serving.
