Design a food delivery platform like DoorDash or Swiggy.

Classic Design Problems · design · levels entry, mid, senior

In one line

Food delivery = geo restaurant search + an order state machine + dispatch that matches couriers by proximity, load and prep-time-aware ETA + real-time courier tracking + payments/notifications, all scaled for mealtime peaks and partitioned by city.

Detailed explanation

Three parties must coordinate in real time: customer, restaurant, courier. The order service is the backbone: a persisted state machine (placed → accepted → preparing → ready → picked up → delivered, plus cancelled/refunded), emitting events at each transition.

Search uses a geo index of restaurants that deliver to the customer's location (delivery polygons), with menus cached heavily since they change rarely; availability (open, busy) changes more often.

Dispatch is an optimisation problem: assign couriers so food is picked up just as it's ready, minimise delivery time and courier idle time, and batch orders on the same route. Inputs: courier locations (updates every few seconds), predicted food preparation time (ML on restaurant, items, time of day, current load), traffic-aware ETAs. Many companies run assignment in short batches (every few seconds per zone) rather than first-come.

Peaks are predictable (lunch, dinner, weekends, rain), so pre-scale services and courier incentives in advance.

How it works

  1. Customer searches → geo index → restaurants + cached menus.
  2. Checkout → payment authorisation → order PLACED → restaurant tablet notified.
  3. Restaurant accepts; dispatch assigns courier near predicted ready time.
  4. Courier location stream → tracking for customer (WebSocket/push).
  5. Delivered → capture payment → payouts, ratings.

Example

Order 881: PLACED 19:02 → ACCEPTED 19:03 (prep ETA 14 min)
Dispatch at 19:08 picks courier 7 (6 min away) → arrives 19:16, food ready 19:17

Common mistakes

  • Assigning a courier immediately and having them wait 15 minutes.
  • A single global dispatch service (partition by city/zone).
  • Synchronous coupling between order placement and courier assignment.

How to answer in the interview

"Restaurant search uses a geospatial index with cached menus. Orders follow a persisted state machine that publishes events. Dispatch runs per city, assigning couriers in short batches using locations, predicted prep time and traffic-aware ETAs so pickup aligns with food readiness, and batching nearby orders. Couriers stream locations for live tracking, and services scale ahead of lunch and dinner peaks."

Likely follow-up questions

  • Estimate prep time? ML on historical prep times, items, restaurant load, time of day.
  • Restaurant never accepts? Timeouts, auto-cancel and refund.
  • Surge? Dynamic delivery fees, courier incentives, wider delivery radius limits.
