How do you apply consistent naming and tagging conventions through Terraform?

Infrastructure as Code · concept · levels mid

In one line

Use provider-level default tags/labels for mandatory tags, a naming module or locals that builds names from variables (org, app, env, component) and handles provider length and character limits, and enforce both with variable validation and policy checks in CI.

Detailed explanation

Consistent names and tags are what make a cloud estate operable: you can tell what a resource is from its name, find its owner, attribute its cost and write IAM or policy rules that match patterns. When each engineer types names by hand, you get prod-db, db-production and DB1.

Tags. The AWS provider's default_tags block adds a standard set (environment, application, owner, cost centre, managed-by) to every taggable resource; resource-level tags are merged on top. The Google provider has default_labels. The azurerm provider has no equivalent, so modules merge a local.common_tags map into every resource, often backed by Azure Policy that inherits tags from the resource group. Some resources need special care: auto scaling group tags must be marked to propagate to instances, and volumes created by instances may need explicit tags.

Names. A small naming module (or locals in each root module) takes inputs such as org, app, env, region, component and outputs standard names like acme-pay-prod-euw1-api. Because providers differ, the module handles the rules: S3 bucket names are global, lowercase and up to 63 characters; Azure storage account names are 3-24 lowercase letters and digits with no dashes; some names cannot be changed without replacement.

Enforcement. Variable validation blocks reject an env outside an allowed list. Policy checks on the plan (OPA/Conftest, Checkov, Sentinel) fail resources without mandatory tags. Cloud-side controls such as AWS Organizations tag policies or Azure Policy catch anything created outside Terraform.

How it works

  1. Root module declares org, app, env, owner variables with validation.
  2. Provider default_tags applies the common set.
  3. Naming module returns names per resource type, truncated or stripped as required.
  4. Resources use module.name.* outputs and add specific tags.
  5. CI policy rejects missing tags; cloud policy audits drift.

Example

variable "env" {
  type = string
  validation {
    condition     = contains(["dev", "test", "prod"], var.env)
    error_message = "env must be dev, test or prod."
  }
}

locals {
  base         = "${var.org}-${var.app}-${var.env}"
  storage_name = substr(replace(lower("${var.org}${var.app}${var.env}"), "-", ""), 0, 24)
}

provider "aws" {
  region = "eu-west-1"
  default_tags {
    tags = { env = var.env, app = var.app, owner = var.owner, managed-by = "terraform" }
  }
}

Common mistakes

  • Names that exceed limits only in production because the env string is longer.
  • Changing a naming convention on resources whose name change forces replacement.
  • Relying only on Terraform when resources are also created by consoles or other tools.

How to answer in the interview

"For tags I use the provider's default_tags, or default_labels on GCP, so every resource gets environment, application, owner and cost centre automatically, and resources add their own tags on top. On Azure I merge a common tags map in modules. For names I have a small naming module that builds names from variables like org, app, env and component, and handles each provider's limits, like Azure storage accounts with no dashes and a 24-character limit. Variable validation and policy checks in CI reject anything missing mandatory tags, and cloud tag policies catch what's created outside Terraform."

Likely follow-up questions

  • How would you add a new mandatory tag to every existing resource? Add it to default_tags, roll out stack by stack; tag changes are in-place updates, then turn on enforcement.
  • What about resources that cannot be renamed? Keep legacy names via overrides; apply the convention to new resources.
  • Tags or names for automation? Tags; names are for humans and are harder to change.
