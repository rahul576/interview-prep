Which basic Docker commands do you use every day?

Docker · concept · levels entry

In one line

The everyday Docker commands are docker build -t to create images, docker run (with -d, -p, -e, --name, -v) to start containers, docker ps, logs, exec, inspect to observe and debug, docker images, pull, push for registries, and stop, rm, prune to clean up.

Detailed explanation

Interviewers ask this to see whether you have really used Docker, so explain what each command and flag does rather than listing names.

Building: docker build -t myapp:1.0 . builds an image from the Dockerfile in the current directory (the . is the build context) and tags it. Add -f for another Dockerfile or --target for a stage.

Running: docker run -d -p 8080:80 -e ENV=dev --name web myapp:1.0. -d detaches (runs in background), -p host:container publishes a port, -e sets environment variables (or --env-file), --name gives a friendly name, -v mounts a volume or bind mount, --rm removes the container when it exits, and -it gives an interactive terminal.

Observing and debugging: docker ps lists running containers (-a includes stopped ones). docker logs -f --tail 100 web follows output. docker exec -it web sh runs a shell inside a running container. docker inspect web shows full configuration, IPs, mounts and exit codes. docker stats shows live CPU and memory. docker cp copies files in or out.

Images and registries: docker images lists local images, docker pull downloads, docker tag adds a name, docker login and docker push upload to Docker Hub, ECR, ACR or GHCR.

Cleaning up: docker stop sends SIGTERM then SIGKILL after a timeout, docker rm removes containers, docker rmi removes images, and docker system prune removes stopped containers, unused networks, dangling images and build cache.

How it works

  1. Build and tag an image from the Dockerfile.
  2. Run it with ports, environment and volumes.
  3. Check status, logs and resource usage.
  4. Debug inside with exec or inspect.
  5. Push to a registry for other environments.
  6. Stop, remove and prune what is no longer needed.

Example

docker build -t myapp:1.0 .
docker run -d --name web -p 8080:80 -e ENV=dev -v web-data:/data myapp:1.0
docker ps
docker logs -f --tail 50 web
docker exec -it web sh
docker cp web:/app/logs/error.log ./error.log
docker tag myapp:1.0 myregistry.azurecr.io/myapp:1.0
docker push myregistry.azurecr.io/myapp:1.0
docker stop web && docker rm web
docker system prune -f

Common mistakes

  • Confusing the port order: -p 8080:80 is host 8080 to container 80.
  • Using docker exec to fix things in production instead of rebuilding the image.
  • Running docker system prune -a --volumes on a shared machine and deleting needed data.
  • Forgetting docker ps -a, then wondering where an exited container went.

How to answer in the interview

"Day to day, I build images with docker build -t myapp:1.0 . and run them with docker run -d -p 8080:80 -e ENV=dev --name web myapp:1.0, which starts it in the background, maps host port 8080 to the container's port 80 and sets an environment variable. To check things I use docker ps, docker logs -f web, and docker exec -it web sh to get a shell for debugging, plus inspect for exit codes and config and stats for resource usage. docker pull and docker push move images to and from registries like ECR or ACR. For cleanup I use stop, rm and docker system prune, and for multi-container setups docker compose up and down."

Likely follow-up questions

  • How do you copy a file out of a container? docker cp container:/path ./local.
  • Difference between stop and kill? stop sends SIGTERM and waits (default 10 s) before SIGKILL; kill sends SIGKILL immediately by default.
  • exec vs attach? exec starts a new process; attach connects to the main process's stdio.
