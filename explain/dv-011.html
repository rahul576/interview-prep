What is the OSI model? Explain its layers with examples.

Networking · concept · levels entry

In one line

The OSI model splits networking into seven layers: physical, data link (MAC, switches), network (IP, routers), transport (TCP/UDP, ports), session, presentation and application (HTTP, DNS); DevOps engineers use it to troubleshoot layer by layer and to understand L4 versus L7 devices.

Detailed explanation

The OSI model is a reference model: real stacks (the TCP/IP model) merge some layers, but the numbering is the common vocabulary ("it's a layer 7 issue").

  1. Physical: bits as electrical, optical or radio signals: cables, fibre, Wi-Fi radio, NICs. Problems: unplugged cables, bad optics, duplex mismatches.
  2. Data link: frames between devices on the same local network, addressed by MAC addresses; switches, VLANs, ARP (mapping IP to MAC, often placed between 2 and 3), Ethernet.
  3. Network: packets routed between networks by IP address; routers, subnets, route tables, ICMP (ping, traceroute). Cloud route tables and NAT live here.
  4. Transport: end-to-end delivery between processes identified by ports; TCP (reliable, ordered, connection-oriented) and UDP (connectionless, fast). Security groups and L4 load balancers work mainly at layers 3-4.
  5. Session: establishing and managing sessions or dialogues; in practice handled inside applications or TLS session resumption.
  6. Presentation: data format, encoding, compression and encryption; TLS is often placed here (though it sits between transport and application in practice), along with character encoding and serialisation formats.
  7. Application: protocols applications use: HTTP, DNS, SMTP, SSH, gRPC. L7 load balancers, API gateways and WAFs inspect this layer.

Why it matters in DevOps: troubleshooting bottom-up: is the link up (1-2), is the IP reachable and routed (3), is the port open (4), does TLS succeed (6), does the app return the right HTTP response (7)? It also explains why an L4 load balancer can't route by URL path while an L7 one can, and why a WAF can block SQL injection while a security group cannot.

How it works

  1. Application creates data (HTTP request).
  2. TLS encrypts it; TCP segments it and adds ports.
  3. IP adds source and destination addresses.
  4. Ethernet frames it with MAC addresses.
  5. The physical layer transmits bits; the receiver decapsulates in reverse order.

Example

ip link show                    # L1/L2: interface up, MAC address
ip neigh                        # L2/L3: ARP table
ip route; traceroute 10.0.2.15  # L3: routing path
nc -vz 10.0.2.15 443            # L4: port open
openssl s_client -connect app.example.com:443 -servername app.example.com </dev/null   # L6: TLS
curl -I https://app.example.com # L7: HTTP status

Common mistakes

  • Listing layers without examples or relevance.
  • Placing DNS at the network layer (it's an application protocol).
  • Thinking real traffic follows all seven layers strictly.
  • Confusing switches (L2) with routers (L3).

How to answer in the interview

"The OSI model describes networking in seven layers. Physical is cables and signals. Data link moves frames on the local network using MAC addresses and switches. Network routes packets between networks using IP and routers. Transport is TCP for reliable ordered connections and UDP for fast connectionless messages, identified by ports. Session and presentation cover sessions and encoding or encryption such as TLS. Application is protocols like HTTP and DNS. In DevOps I use it to troubleshoot layer by layer and to understand L4 versus L7 load balancers, security groups versus WAFs."

Likely follow-up questions

  • At which layer does a security group operate, and a WAF? Security groups at layers 3-4 (IPs, ports, protocols); a WAF at layer 7 (HTTP content).
  • How does the TCP/IP model differ? Four layers: link, internet, transport, application.
  • Where is ARP? Between layers 2 and 3, mapping IP addresses to MAC addresses.
