How does thread interruption work, and how should code handle InterruptedException?

Concurrency · concept · levels mid, senior

In one line

Interruption is a cooperative cancellation mechanism: interrupt() sets a flag, blocking methods throw InterruptedException and clear the flag, and code must never swallow it but either propagate it or restore it with Thread.currentThread().interrupt(); executors rely on it for shutdownNow and Future.cancel(true).

Detailed explanation

Java has no safe way to forcibly stop a thread (Thread.stop is deprecated and removed in recent JDKs because it could leave objects corrupted). Instead, t.interrupt() asks a thread to stop by setting its interrupt status. What happens next depends on the target:

  • If it is blocked in an interruptible method, sleep, wait, join, BlockingQueue.put/take, Future.get, lockInterruptibly, CountDownLatch.await, the method throws InterruptedException and clears the flag.
  • If it is in an InterruptibleChannel I/O operation, the channel is closed and it gets ClosedByInterruptException. Classic java.io socket streams are not interruptible on platform threads (closing the socket is the usual workaround), but virtual threads do support interrupting blocking socket I/O.
  • If it is running CPU code, nothing happens automatically; the code must check Thread.currentThread().isInterrupted() periodically.
  • Thread.interrupted() (static) checks and clears the flag; isInterrupted() only checks.

Handling InterruptedException. It is a request to stop, so swallowing it (catch (InterruptedException e) {}) breaks cancellation for everyone up the stack. The two correct options:

  1. Propagate: declare throws InterruptedException and let the caller decide.
  2. Restore and exit: if you can't throw (e.g. inside Runnable.run), call Thread.currentThread().interrupt() to re-set the flag, then return or wrap in an unchecked exception, so higher layers still see it.

Only code that owns the thread (the executor's worker loop) should decide to ignore it.

Where it's used. ExecutorService.shutdownNow() interrupts all workers; Future.cancel(true) interrupts the task's thread; structured concurrency cancels subtasks by interrupting them; frameworks use it for request timeouts. Tasks that ignore interruption can't be cancelled and delay shutdown. Note CompletableFuture.cancel(true) does not interrupt.

How it works

  1. Caller invokes t.interrupt(); flag set.
  2. Blocking call in t throws InterruptedException and clears the flag.
  3. Handler propagates or restores the flag.
  4. Loop checks isInterrupted() and exits cleanly.

Example

// Restoring the flag in a Runnable
public void run() {
    try {
        while (!Thread.currentThread().isInterrupted()) {
            Job job = queue.take();             // throws if interrupted
            handle(job);
        }
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();     // restore, then exit
    } finally {
        cleanup();
    }
}

// CPU-bound loop made cancellable
for (int i = 0; i < rows.size(); i++) {
    if ((i & 1023) == 0 && Thread.currentThread().isInterrupted()) {
        throw new CancellationException("cancelled at row " + i);
    }
    compute(rows.get(i));
}

Common mistakes

  • Empty catch blocks for InterruptedException.
  • Using Thread.interrupted() when you meant isInterrupted(), clearing the flag.
  • Long CPU loops that never check the flag.
  • Retrying in a loop after interruption, so the thread never stops.

How to answer in the interview

"Interruption is a cooperative cancellation mechanism: interrupt sets a flag on the thread, and the thread decides how to respond. Blocking methods like sleep, wait, join and BlockingQueue.take throw InterruptedException and clear the flag. Code must not swallow it: either propagate the exception or restore the status with Thread.currentThread().interrupt(), so callers higher up can see it. Executors use interruption for shutdownNow and Future.cancel(true), so tasks that ignore it can't be cancelled. For CPU-bound loops I check isInterrupted periodically."

Likely follow-up questions

  • Make a long CPU loop cancellable? Check isInterrupted() every N iterations and exit or throw.
  • Why does InterruptedException clear the flag? The exception itself delivers the signal; you restore the flag if you can't propagate it.
  • Why was Thread.stop removed? It released locks at arbitrary points, leaving shared state corrupted.
