How do you reference a resource that may or may not exist because it uses count = 0 or 1?

Terraform · concept · levels mid, senior

In one line

count turns a resource into a list, so resource[0] fails when count is 0; use one(resource.x[*].attr), which returns the element or null, or try(resource.x[0].attr, null), and consider for_each when there may be more than one optional instance.

Detailed explanation

Optional resources are commonly written as count = var.create_public_ip ? 1 : 0. Even when the count is 1, the resource is a list of instances, so its address is azurerm_public_ip.this[0]. Referencing azurerm_public_ip.this[0].id works when the resource exists but fails with an "Invalid index" error when the count is 0, because the list is empty.

The cleanest pattern is the splat expression plus one(). The splat azurerm_public_ip.this[*].id always returns a list: empty when count is 0, one element when it is 1. one() converts that list to a single value: the element if there is exactly one, null if the list is empty, and an error if there are two or more, which protects you if someone later changes the count logic.

Because null means "omit" for resource arguments, the result can often be passed straight into an optional argument, such as a NIC's public_ip_address_id, and Terraform will simply not set it when the IP does not exist. The same works for module outputs: an output that is null when the feature is disabled.

try(azurerm_public_ip.this[0].id, null) is an alternative that catches the index error and returns a default. It works but is less precise: it would also silently hide a typo in the attribute name.

When a feature could have several optional instances, or you want readable addresses, for_each with a map is clearer: an empty map creates nothing, and each instance has a stable key. For a single optional instance, for_each = var.enabled ? { this = true } : {} is also common.

How it works

  1. Declare the optional resource with count = condition ? 1 : 0.
  2. Reference it with one(resource.name[*].attribute).
  3. Pass the result to optional arguments; null omits them.
  4. Expose it in outputs, which are null when disabled.
  5. Switch to for_each for multiple or keyed optional instances.

Example

resource "azurerm_public_ip" "this" {
  count               = var.public ? 1 : 0
  name                = "pip-${var.name}"
  location            = var.location
  resource_group_name = var.resource_group_name
  allocation_method   = "Static"
  sku                 = "Standard"
}

resource "azurerm_network_interface" "this" {
  name                = "nic-${var.name}"
  location            = var.location
  resource_group_name = var.resource_group_name
  ip_configuration {
    name                          = "primary"
    subnet_id                     = var.subnet_id
    private_ip_address_allocation = "Dynamic"
    public_ip_address_id          = one(azurerm_public_ip.this[*].id)   # null when not public
  }
}

output "public_ip" {
  value = one(azurerm_public_ip.this[*].ip_address)
}

Common mistakes

  • Using [0] directly and breaking the disabled case.
  • Using try broadly and hiding attribute typos.
  • Using count for collections of named objects, causing index shifts.
  • Forgetting that one() errors when more than one element exists.

How to answer in the interview

"With count, the resource becomes a list even with one instance, so you reference index 0, which fails when the count is zero. The cleanest way is one() with the splat expression: one of the resource splat id returns the element when it exists and null when it doesn't, and fails clearly if there are ever more than one. Since null means omit for arguments, I can pass it straight into optional arguments or outputs. try with index 0 and a null default also works. For multiple optional instances I prefer for_each with a map."

Likely follow-up questions

  • Why is for_each sometimes better? Stable keys, readable addresses and no index shifting.
  • What does the splat return with count 0? An empty list.
  • How do you migrate from count to for_each? moved blocks from [0] to the new key.
