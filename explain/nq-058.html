How would you update existing product objects using forEach()?

Coding Exercises · scenario · levels entry

In one line

With mutable objects, iterate and call setters inside forEach — products.forEach(p -> p.setPrice(p.getPrice() * 0.85)), or filter first with stream().filter(...).forEach(...); the same objects change, so all references see it, and you must not use it on shared objects in parallel or modify the list while iterating.

Detailed explanation

Sometimes updating existing objects is exactly what is needed: JPA entities inside a transaction (the persistence context detects changes and flushes them), domain objects held in a cache, or a legacy class with getters and setters.

Two forms:

  • Iterable.forEach directly on the list: products.forEach(p -> p.setPrice(p.getPrice() * 0.85)); — simplest when every element is updated.
  • stream().filter(...).forEach(...) when only some elements should change, such as one category.

What happens: the list still contains the same object references. Their internal state changes, so any other code holding references to those products — a cache, another list, the persistence context — sees the new prices. No new list is created.

Rules and caveats:

  • The objects must be mutable; records and immutable classes have no setters.
  • Do not structurally modify the list (add or remove elements) during forEach. For ArrayList, Iterable.forEach checks the modification count and throws ConcurrentModificationException. To remove elements, use removeIf; to replace elements, use replaceAll.
  • In a parallel stream, forEach runs on multiple threads. Updating independent objects is technically fine if each object is touched once, but if objects are shared, or the update reads other state, you get race conditions. Keep such updates sequential.
  • forEach on a parallel stream has no defined order; forEachOrdered keeps encounter order.
  • For money, use BigDecimal with rounding.

How it works

  1. Obtain the list of mutable products.
  2. Optionally filter to the products that should change.
  3. forEach invokes the Consumer for each product.
  4. The Consumer calls setters on the existing object.
  5. All references now see the updated state.

Example

class Product {
    private String name;
    private String category;
    private double price;
    private int stock;
    // getters and setters
}

// update all products
products.forEach(p -> p.setPrice(p.getPrice() * 0.85));

// update only electronics
products.stream()
        .filter(p -> "Electronics".equals(p.getCategory()))
        .forEach(p -> p.setPrice(p.getPrice() * 0.85));

// wrong: structural modification during iteration
products.forEach(p -> { if (p.getStock() == 0) products.remove(p); }); // ConcurrentModificationException

// right
products.removeIf(p -> p.getStock() == 0);

Common mistakes

  • Removing or adding elements inside forEach.
  • Using parallelStream().forEach to update shared state.
  • Expecting forEach to return a new list.
  • Applying the discount twice because the update ran in two code paths.

How to answer in the interview

"If Product is a mutable class with setters, I'd write products.stream().filter by the condition, then forEach calling setPrice with price times 0.85, or without filtering just products.forEach directly. The list keeps the same objects, now with new prices, so anyone holding references sees the change, which is what you want for entities in a transaction. This only works with mutable objects, I wouldn't do it in a parallel stream over shared objects, and I must not add or remove list elements during iteration; for that I'd use removeIf."

Likely follow-up questions

  • What happens if you remove elements inside forEach? ConcurrentModificationException for ArrayList; use removeIf or an Iterator's remove.
  • Iterable.forEach vs a for loop? Same effect; the loop supports break, checked exceptions and index access.
  • How do entities get saved? Dirty checking flushes changes at transaction commit.
