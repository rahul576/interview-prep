How would you find whether an array contains a subarray with a given sum, including negative numbers?

DSA: Arrays & Strings · concept · levels mid

In one line

With negatives the sliding window fails (sums aren't monotonic). Instead use prefix sums with a hash map. A subarray (j, i] sums to target exactly when prefix[i] - prefix[j] = target, so check whether prefix - target has been seen. Seed the map with 0. That is O(n) time, O(n) space.

Detailed explanation

For non-negative numbers a two-pointer window works: extend right while the sum is too small, and shrink left when it is too big. That works because adding elements only increases the sum. With negative numbers this monotonicity breaks. Shrinking the window can increase the sum, so the window has no reliable rule for which pointer to move.

Prefix sums fix this. Define P[i] = sum of the first i elements. The sum of the subarray from j+1 to i is P[i] - P[j]. We need some earlier j with P[j] = P[i] - target. Scan left to right, maintaining a hash map of prefix sums seen so far. At each index, check the map for current - target.

Details that matter:

  • Seed the map with 0 (the prefix before index 0), so subarrays starting at index 0 are found. Example: [5], target 5.
  • Existence: store prefix to first index if you also want the longest subarray, or just use a set.
  • Counting: store prefix to count of occurrences, and add count[current - target] to the answer at each step. That is LeetCode "Subarray Sum Equals K".
  • Order: check before inserting the current prefix, otherwise target 0 matches an empty subarray.

Complexity: one pass, expected O(1) map operations, so O(n) time and O(n) space. The brute force (all pairs with running sums) is O(n²).

How it works

  1. map = {0: 1}, sum = 0, count = 0.
  2. For each x: sum += x.
  3. count += map.getOrDefault(sum - target, 0).
  4. map.merge(sum, 1, Integer::sum).
  5. Return count > 0 for existence, or count for the number of subarrays.

Example

public int subarraySum(int[] nums, int k) {
    Map<Long, Integer> seen = new HashMap<>();
    seen.put(0L, 1);
    long sum = 0;
    int count = 0;
    for (int x : nums) {
        sum += x;
        count += seen.getOrDefault(sum - k, 0);
        seen.merge(sum, 1, Integer::sum);
    }
    return count;
}
// nums = [3, 4, -7, 1, 3, 3, 1, -4], k = 7
// prefix: 3, 7, 0, 1, 4, 7, 8, 4 -> 4 subarrays sum to 7

The answer counts [3,4], [3,4,-7,1,3,3], [1,3,3] and [3,3,1], all found purely through prefix differences, despite the negative values.

Common mistakes

  • Using a sliding window when negatives are allowed.
  • Forgetting to seed {0: 1}, which misses subarrays starting at index 0.
  • Storing a set instead of counts when the question asks "how many".
  • Inserting the current prefix before checking (wrong for k = 0).
  • Integer overflow in the running sum. Use long.

How to answer in the interview

"With negative numbers a sliding window doesn't work, because the sum isn't monotonic as the window changes. I use prefix sums. While scanning I keep a running sum and a hash map of the prefix sums I've seen. If the current sum minus the target is in the map, the elements between that earlier point and now add up to the target. I seed the map with zero so subarrays starting at index zero are found. To count subarrays I store counts per prefix sum and add them up. It's O(n) time and O(n) space."

Likely follow-up questions

  • Count the subarrays? Map prefix to frequency and accumulate freq[sum - k].
  • Longest subarray with sum k? Map prefix to its first index and maximise i - firstIndex.
  • Sum divisible by k? Use prefix sums modulo k, normalising negative remainders.
