What is the Adapter pattern?

Design Patterns · concept · levels entry

In one line

Adapter is a structural pattern that converts the interface of a class into the interface clients expect, wrapping the adaptee and translating calls so incompatible classes can work together.

Detailed explanation

You often have code written against one interface and a class (legacy, third-party, another team's) that does the job but exposes a different API. Changing either side is undesirable or impossible. An adapter sits between them.

Roles:

  • Target: the interface your code uses (PaymentGateway).
  • Adaptee: the existing class with a different interface (a vendor SDK).
  • Adapter: implements Target, holds the Adaptee, and translates method names, parameter types, units, exceptions and return values.
  • Client: works only with Target.

There are two forms. The object adapter uses composition (holds an adaptee instance) and is the usual choice in Java. The class adapter extends the adaptee and implements the target, which requires inheritance and is less flexible.

In backend work this is the standard way to integrate third-party services: your domain defines PaymentGateway.charge(Money, CardToken), and StripePaymentAdapter maps it to Stripe's SDK, converting rupees to paise, mapping SDK exceptions to your own PaymentFailedException. Benefits: the vendor can be swapped, tests can mock the target interface, and vendor types do not leak into your domain. In hexagonal architecture, outbound adapters are exactly this.

JDK examples: InputStreamReader adapts a byte InputStream to a character Reader; Arrays.asList presents an array as a fixed-size List; Collections.enumeration adapts a collection to the legacy Enumeration. Spring MVC's HandlerAdapter lets DispatcherServlet invoke different handler types.

How it works

  1. Define or identify the target interface the client needs.
  2. Create an adapter class implementing it.
  3. Inject or construct the adaptee inside the adapter.
  4. Translate each call: arguments, units, results, errors.
  5. Wire the adapter where the target is expected.

Example

public interface PaymentGateway {
    PaymentResult charge(BigDecimal amountInRupees, String cardToken);
}

@Component
class StripePaymentAdapter implements PaymentGateway {
    private final StripeClient stripe;           // adaptee (vendor SDK)
    StripePaymentAdapter(StripeClient stripe) { this.stripe = stripe; }

    @Override
    public PaymentResult charge(BigDecimal rupees, String token) {
        try {
            long paise = rupees.movePointRight(2).longValueExact();
            var intent = stripe.createPaymentIntent(paise, "inr", token);
            return new PaymentResult(intent.getId(), intent.getStatus().equals("succeeded"));
        } catch (VendorException e) {
            throw new PaymentFailedException("Stripe charge failed", e);
        }
    }
}

Common mistakes

  • Letting vendor types leak through the adapter into business code.
  • Putting business logic in the adapter instead of pure translation.
  • Confusing Adapter with Facade.
  • Forgetting to translate errors and units (paise vs rupees, time zones).

How to answer in the interview

"Adapter is a structural pattern that converts a class's interface into the interface the client expects, so incompatible classes can work together. The adapter implements the target interface, holds the adaptee and translates each call. A typical case: my code depends on a PaymentGateway interface, and I integrate a third-party SDK by writing a StripePaymentAdapter that implements it and calls the SDK, converting units and exceptions. That keeps vendor types out of the domain and makes the vendor swappable and mockable. JDK examples are InputStreamReader and Arrays.asList."

Likely follow-up questions

  • How does Adapter differ from Facade? Adapter converts one interface to another; Facade offers a simpler interface over a whole subsystem.
  • Object vs class adapter? Object adapters use composition; class adapters use inheritance and are less flexible.
  • Where does Spring use Adapter? HandlerAdapter in MVC, and listener adapters such as MessageListenerAdapter.
