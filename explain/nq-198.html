What is the difference between JDK dynamic proxies and CGLIB proxies?

Spring Framework · concept · levels mid, senior

In one line

A JDK dynamic proxy implements the target's interfaces via java.lang.reflect.Proxy and an InvocationHandler, so it can only be injected by interface; a CGLIB proxy generates a runtime subclass of the class, so it works without interfaces and by concrete type, but cannot proxy final classes or methods; Spring Boot defaults to CGLIB (proxyTargetClass=true).

Detailed explanation

JDK dynamic proxies are part of the JDK. Proxy.newProxyInstance creates a class at runtime that implements a given set of interfaces and forwards every call to an InvocationHandler, where Spring runs the advice chain before calling the target. Because the proxy class only implements interfaces and is not a subclass of the target, it can be assigned only to interface types. If you inject OrderServiceImpl by its class, Spring fails with BeanNotOfRequiredTypeException ("is expected to be of type OrderServiceImpl but was actually of type jdk.proxy2.$Proxy..."). Methods not declared on an interface cannot be intercepted.

CGLIB (repackaged inside Spring core) generates bytecode for a subclass of the target class and overrides its non-final methods to route through the advice chain. It works for classes without interfaces, can be injected by concrete class, and intercepts public, protected and package-visible methods. Its limits come from inheritance: it cannot subclass final classes and cannot override final methods (those calls go straight to the proxy instance's own, uninitialised state). Spring uses Objenesis to create the proxy instance without calling the target's constructor, so constructors with side effects aren't run twice and no default constructor is required.

Defaults: plain Spring Framework uses a JDK proxy when the bean implements at least one interface, and CGLIB otherwise. Spring Boot sets spring.aop.proxy-target-class=true by default, so CGLIB is used even when interfaces exist, which avoids the injection-by-class surprise. Kotlin classes are final by default, which is why the kotlin-spring (all-open) plugin exists. Performance differences between the two are negligible today.

How it works

  1. Auto-proxy creator decides a bean needs a proxy.
  2. It checks proxyTargetClass and whether the bean has interfaces.
  3. JDK: create $Proxy implementing the interfaces with an InvocationHandler.
  4. CGLIB: generate Target$$SpringCGLIB$$0 subclass, instantiate via Objenesis.
  5. Calls route through the advice chain to the target instance.

Example

public interface PaymentService { void pay(Order o); }

@Service
public class StripePaymentService implements PaymentService {
    @Transactional public void pay(Order o) { ... }
}

@Component
class Checkout {
    // Works with both proxy types:
    Checkout(PaymentService payments) { }
    // Works only with CGLIB (Spring Boot default); fails with JDK proxies:
    // Checkout(StripePaymentService payments) { }
}
spring:
  aop:
    proxy-target-class: false   # force JDK proxies when interfaces exist

Common mistakes

  • Declaring @Transactional methods final, silently losing the transaction with CGLIB.
  • Injecting by implementation class when JDK proxies are in use.
  • Final Kotlin classes without the all-open plugin.
  • Assuming the constructor runs twice with CGLIB (Objenesis avoids it).

How to answer in the interview

"A JDK dynamic proxy creates at runtime a class implementing the target's interfaces and routes calls through an InvocationHandler, so it only works with interfaces and can only be injected by interface type. CGLIB generates a runtime subclass of the target class, overriding methods to add advice, so it works without interfaces and can be injected by class, but can't proxy final classes or final methods. Spring Framework uses JDK proxies when interfaces exist, but Spring Boot sets proxyTargetClass to true, so CGLIB is the default."

Likely follow-up questions

  • Error injecting a JDK proxy by class? BeanNotOfRequiredTypeException.
  • Why does Boot prefer CGLIB? Avoids injection-by-class failures and intercepts non-interface methods.
  • What does Objenesis do? Instantiates the proxy without calling the target's constructor.
