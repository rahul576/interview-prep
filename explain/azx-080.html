What outbound types exist for AKS, and how do you route cluster egress through Azure Firewall?

Azure Kubernetes (AKS) · concept · levels senior, lead

In one line

AKS outbound types are loadBalancer (default, SNAT via LB public IPs), managedNATGateway / userAssignedNATGateway (scalable SNAT, stable IPs), and userDefinedRouting (route table sends 0.0.0.0/0 to Azure Firewall); with firewall egress you must allow required AKS FQDNs, service tags and ports.

Detailed explanation

loadBalancer: AKS adds outbound rules on the Standard Load Balancer, translating node traffic to its public IPs. It is simple, but each IP gives a limited number of SNAT ports per node, and busy clusters calling many external endpoints can hit SNAT port exhaustion, seen as intermittent connection timeouts. You can add more outbound IPs or allocate ports manually.

managedNATGateway / userAssignedNATGateway: a NAT Gateway on the node subnet provides up to 64,000 SNAT ports per public IP, up to 16 IPs, with dynamic allocation. It is the better option for high outbound volume and gives stable public IPs for partner allowlisting. Managed means AKS creates it; user-assigned means you bring your own on the subnet.

userDefinedRouting: AKS creates no outbound path and expects a route table on the subnet, usually with 0.0.0.0/0 next hop to an Azure Firewall or network virtual appliance in the hub. All egress is then inspected, filtered and logged centrally, which hub-and-spoke enterprises usually require.

With firewall egress you must allow what AKS needs, otherwise cluster creation, upgrades or node joins fail:

  • The AzureKubernetesService FQDN tag in application rules (covers MCR, AKS endpoints, package repositories and more).
  • The API server endpoint (TCP 443) and NTP (UDP 123).
  • Azure Monitor, Key Vault, ACR and other services workloads use, ideally via private endpoints so they bypass the firewall.
  • Rules for application dependencies: external APIs, package mirrors, image registries.

Ingress through a public load balancer with UDR can cause asymmetric routing, so expose public endpoints through the firewall (DNAT) or an Application Gateway instead.

How it works

  1. Choose an outbound type at cluster design time.
  2. For UDR: create the firewall and route table, associate it with the node subnet.
  3. Add FQDN tag, network rules and app-specific rules.
  4. Create the cluster with --outbound-type userDefinedRouting.
  5. Monitor firewall logs for denied traffic during first deployments.

Example

az network route-table route create -g rg-net --route-table-name rt-aks -n default \
  --address-prefix 0.0.0.0/0 --next-hop-type VirtualAppliance --next-hop-ip-address 10.0.1.4

az network firewall application-rule create -g rg-hub -f fw-hub --collection-name aks \
  -n aks-fqdn --priority 100 --action Allow --source-addresses 10.1.0.0/16 \
  --protocols Https=443 Http=80 --fqdn-tags AzureKubernetesService

az aks create -g rg-apps -n aks-prod --vnet-subnet-id $SUBNET_ID \
  --outbound-type userDefinedRouting --network-plugin azure --network-plugin-mode overlay

Common mistakes

  • Missing the FQDN tag or NTP rule, so nodes never become ready.
  • Not associating the route table before cluster creation.
  • Exposing public LoadBalancer services in UDR clusters and hitting asymmetric routing.
  • Ignoring SNAT exhaustion on busy default clusters.

How to answer in the interview

"There are four outbound types. loadBalancer, the default, uses the LB public IPs for SNAT but can hit port limits. Managed or user-assigned NAT Gateway gives many more ports and stable IPs. userDefinedRouting means AKS creates no outbound path and the subnet route table sends 0.0.0.0/0 to Azure Firewall in the hub, so egress is inspected and logged. Then I must allow the AKS FQDN tag, the API server and NTP, plus whatever workloads need, ideally using private endpoints for Azure services, otherwise creation and upgrades fail."

Likely follow-up questions

  • Why decide at creation? It shapes subnet routing and IP design; changing it later is limited and disruptive.
  • How do you detect SNAT exhaustion? Load balancer SNAT connection metrics and failed outbound connections.
  • Can you restrict egress per namespace? Yes, with Cilium FQDN network policies in addition to the firewall.
