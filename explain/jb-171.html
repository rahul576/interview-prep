What is the difference between application.properties and application.yml?

Spring Boot · concept · levels mid, senior

In one line

Both are externalised configuration files that Spring Boot loads into the Environment and can express the same settings: .properties is flat key=value, while .yml is hierarchical, supports lists neatly and multiple profile documents in one file; if both exist in the same place, properties win, and YAML has indentation pitfalls and is not loaded by @PropertySource.

Detailed explanation

application.properties uses one line per key: spring.datasource.url=jdbc:postgresql://localhost/shop. It is simple, easy to grep and diff, and works with every tool, but nested settings repeat their prefixes, and lists use indexes like app.cors.origins[0]=....

application.yml uses YAML, where indentation expresses nesting. Prefixes are written once, lists use - items, and maps read naturally, so large configurations (Spring Cloud Gateway routes, Resilience4j instances, Kafka settings) are much more readable. A single YAML file can hold multiple documents separated by ---, each with spring.config.activate.on-profile, to keep profile overrides together. (Since Boot 2.4, .properties files also support multi-document sections with #---.)

Both are parsed into the same property keys, so code using @Value or @ConfigurationProperties does not care which format you use, and relaxed binding applies to both. When both application.properties and application.yml exist in the same location, .properties takes precedence for keys present in both; mixing them is confusing, so pick one per project.

Remember the bigger precedence order: profile-specific files override the default file, files outside the jar override packaged ones, and environment variables and command-line arguments override files.

YAML pitfalls:

  • Indentation must use spaces; a wrong indent silently moves a key to another parent.
  • Type coercion: unquoted values like on, off, yes, no, or 08 may be interpreted differently; quote strings such as passwords and version numbers.
  • Special characters (:, #, *, @) need quotes.
  • @PropertySource loads only .properties (or XML) by default; YAML needs a custom PropertySourceFactory, or use spring.config.import.

How it works

  1. Boot finds application.properties and application.yml in the classpath root, /config, current directory and ./config/.
  2. Each file is parsed into property sources; YAML is flattened into dotted keys.
  3. Profile-specific documents and files are added for active profiles.
  4. Higher-precedence sources override lower ones.
  5. Beans bind values from the merged Environment.

Example

# application.properties
spring.datasource.url=jdbc:postgresql://localhost:5432/shop
spring.datasource.hikari.maximum-pool-size=10
app.cors.allowed-origins[0]=https://app.example.com
app.cors.allowed-origins[1]=https://admin.example.com
# application.yml (same settings) plus a prod document
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/shop
    hikari:
      maximum-pool-size: 10
app:
  cors:
    allowed-origins:
      - https://app.example.com
      - https://admin.example.com
---
spring:
  config:
    activate:
      on-profile: prod
  datasource:
    hikari:
      maximum-pool-size: 30

Common mistakes

  • Tabs or misaligned indentation in YAML.
  • Having both files and not knowing which value wins.
  • Unquoted values like no or leading-zero numbers.
  • Expecting @PropertySource("classpath:x.yml") to work.

How to answer in the interview

"Both do the same job: externalised configuration that Spring Boot binds into the Environment, and they can express the same settings. application.properties uses flat key-value lines, which is simple but repetitive for nested keys. application.yml is hierarchical through indentation, so nested settings and lists are more readable, and one file can hold several documents separated by three dashes, each activated for a profile. If both exist in the same location, properties win. The YAML pitfalls are indentation mistakes, type coercion of unquoted values, and that @PropertySource doesn't load YAML by default. I pick one format per project, usually YAML."

Likely follow-up questions

  • In what order does Spring Boot resolve configuration from files, environment variables and command-line arguments? Packaged files, then profile files, then external files, then environment variables, then system properties and command-line arguments, which win.
  • How do you import extra config files? spring.config.import=optional:file:./extra.yml.
  • Can you validate configuration? Yes, @ConfigurationProperties with @Validated.
