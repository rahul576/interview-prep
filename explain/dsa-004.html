How do you check whether two strings are anagrams?

DSA: Arrays & Strings · concept · levels entry

In one line

Two strings are anagrams if they have the same character counts. Check that the lengths match, then increment counts for one string and decrement for the other using an int[26] (lowercase) or a hash map (Unicode), and verify that everything is zero. That is O(n) time, versus O(n log n) for sorting.

Detailed explanation

An anagram is a rearrangement of the same letters: "listen" and "silent". Order doesn't matter, only the multiset of characters. That gives two classic approaches.

Counting (frequency array). First, if lengths differ, return false immediately. Then walk both strings at the same time, doing count[s[i]]++ and count[t[i]]--. If every count is zero at the end, they are anagrams. For a fixed alphabet (26 lowercase letters) the array has constant size, so it is O(n) time and O(1) space. For arbitrary Unicode use a HashMap<Integer,Integer> keyed by code point. Iterating char values breaks on surrogate pairs such as emoji. Space is then O(k) for the distinct characters.

Sorting. Convert both to char arrays, sort, and compare. It is simpler to write and gets O(n log n) time. That is fine for short strings, but asymptotically worse.

Clarify the rules first: is it case sensitive? Do spaces and punctuation count? ("Dormitory" and "dirty room" are anagrams only if you ignore case and spaces.) Normalise before counting: lowercase, strip non-letters, and possibly Unicode-normalise accents.

How it works

  1. If s.length() != t.length(), return false.
  2. int[] count = new int[26].
  3. For each i: count[s[i]-'a']++ and count[t[i]-'a']--.
  4. If any count is non-zero, return false. Otherwise return true.
  5. Early-exit variant: decrement in a second loop and return false as soon as a count goes negative.

Example

public boolean isAnagram(String s, String t) {
    if (s.length() != t.length()) return false;
    int[] count = new int[26];
    for (int i = 0; i < s.length(); i++) {
        count[s.charAt(i) - 'a']++;
        count[t.charAt(i) - 'a']--;
    }
    for (int c : count) if (c != 0) return false;
    return true;
}

Common mistakes

  • Skipping the length check.
  • Using int[26] when input contains uppercase letters, digits or spaces, which causes an index out of bounds.
  • Iterating chars instead of code points for emoji or other non-BMP text.
  • Not clarifying case and whitespace rules.

How to answer in the interview

"First I'd check the lengths. If they differ, they can't be anagrams. Then I'd count character frequencies: increment for each character of the first string and decrement for the second, using an array of 26 for lowercase letters or a hash map for general Unicode. If every count ends at zero, they're anagrams. That's O(n) time and constant space for a fixed alphabet. Sorting both strings and comparing also works and is shorter, but it's O(n log n). I'd also clarify case sensitivity and whether spaces count."

Likely follow-up questions

  • Group a list of words by anagram? Use a map keyed by the sorted word or a 26-count signature. O(n·k log k) or O(n·k).
  • Find all anagrams of p in s? Use a fixed-size sliding window with count arrays. O(n).
  • Streaming or huge strings? Counting works in a single pass without loading everything into memory.
