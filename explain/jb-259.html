What is the difference between JUnit 4 and JUnit 5?

Testing · concept · levels entry, mid

In one line

JUnit 5 is a modular rewrite (Platform + Jupiter + Vintage) with renamed lifecycle annotations, an extension model (@ExtendWith) replacing JUnit 4's runners and rules, and new features like @ParameterizedTest, @Nested, @DisplayName, assertThrows and lambdas; it needs Java 8+ and tests no longer have to be public.

Detailed explanation

JUnit 4 was a single jar built around reflection and the @RunWith runner. Only one runner could be used per class, so combining Spring's runner with Mockito's or a parameterised runner was awkward, and @Rule was a partial workaround.

JUnit 5 splits responsibilities:

  • JUnit Platform launches tests and is what IDEs, Maven Surefire and Gradle talk to; other engines (Spock, Cucumber, jqwik) plug into it.
  • JUnit Jupiter is the new programming and extension model (org.junit.jupiter.api).
  • JUnit Vintage runs existing JUnit 3 and 4 tests on the Platform, enabling gradual migration.

Annotation changes: @Before → @BeforeEach, @After → @AfterEach, @BeforeClass → @BeforeAll, @AfterClass → @AfterAll, @Ignore → @Disabled, @Category → @Tag. @Test lost its expected and timeout attributes in favour of assertThrows and assertTimeout / @Timeout.

Extensions: @ExtendWith composes any number of extensions (MockitoExtension, SpringExtension), with callbacks for lifecycle, parameter resolution and exception handling. Constructor and method parameters can be injected, for example TestInfo or a Mockito mock.

New features: @ParameterizedTest with @ValueSource, @CsvSource, @MethodSource, @EnumSource; @Nested inner classes for grouping scenarios; @DisplayName; @RepeatedTest; dynamic tests with @TestFactory; assertAll for grouped assertions; lambda-based lazy messages; per-class test instance lifecycle; parallel execution.

Note that JUnit 6 (released in 2025) continues the Jupiter model with a Java 17 baseline and unified version numbers, so the JUnit 4 to 5 migration is the big one.

How it works

  1. Add the JUnit BOM, junit-jupiter, and junit-vintage-engine for old tests.
  2. Both engines run on the Platform in the same build.
  3. Migrate classes gradually: change imports and annotations.
  4. Replace runners and rules with extensions.
  5. Remove Vintage when no JUnit 4 tests remain.

Example

// JUnit 4
@RunWith(MockitoJUnitRunner.class)
public class PriceTest {
    @Before public void setUp() { }
    @Test(expected = IllegalArgumentException.class)
    public void rejectsNegative() { new Price(-1); }
}

// JUnit 5
@ExtendWith(MockitoExtension.class)
class PriceTest {
    @BeforeEach void setUp() { }

    @Test
    @DisplayName("negative prices are rejected")
    void rejectsNegative() {
        var ex = assertThrows(IllegalArgumentException.class, () -> new Price(-1));
        assertEquals("price must be >= 0", ex.getMessage());
    }

    @ParameterizedTest
    @ValueSource(ints = {0, 1, 999})
    void acceptsValidPrices(int value) { assertDoesNotThrow(() -> new Price(value)); }
}

Common mistakes

  • Mixing org.junit.Test and org.junit.jupiter.api.Test imports, so tests silently do not run.
  • Forgetting the Vintage engine during migration and losing JUnit 4 tests.
  • Using assertEquals(message, expected, actual) order from JUnit 4; in JUnit 5 the message is last.
  • Expecting @BeforeAll to work on non-static methods without per-class lifecycle.

How to answer in the interview

"JUnit 5 is modular: the Platform launches tests and integrates with tools, Jupiter is the new API, and Vintage runs old JUnit 4 tests so you can migrate gradually. Lifecycle annotations were renamed to BeforeEach, AfterEach, BeforeAll and AfterAll, and Ignore became Disabled. The biggest change is that runners and rules were replaced by a composable extension model, so Spring and Mockito extensions work together. It adds parameterised tests, nested classes, display names, assertThrows and assertAll, uses lambdas, and test classes no longer need to be public."

Likely follow-up questions

  • How to migrate a large JUnit 4 suite? Add Vintage, write new tests in Jupiter, convert module by module, possibly with OpenRewrite recipes.
  • What replaces @Rule TemporaryFolder? @TempDir.
  • What replaced @RunWith(Parameterized)? @ParameterizedTest with argument sources.
