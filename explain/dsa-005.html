How do you merge overlapping intervals?

DSA: Arrays & Strings · concept · levels mid

In one line

Sort intervals by start, then sweep. If the current interval starts after the last merged end, append it. Otherwise extend the last end to max(lastEnd, curEnd). Sorting dominates, so it is O(n log n) time with O(n) output.

Detailed explanation

Given intervals like [[1,3],[2,6],[8,10],[15,18]], merge any that overlap: [[1,6],[8,10],[15,18]]. Without sorting, any interval could overlap any other, so you'd compare all pairs (O(n²)) and possibly repeat merges. Sorting by start time creates a key property: once an interval doesn't overlap the last merged one, no later interval can overlap any earlier merged interval. That is because later intervals start even further right. So a single linear sweep suffices after sorting.

During the sweep, compare each interval only with the last interval in the result:

  • cur.start > last.end: there is a gap, so start a new merged interval.
  • Otherwise they overlap, so last.end = max(last.end, cur.end). The max matters because the current interval may sit entirely inside the last one ([1,10] and [2,3]).

Clarify whether touching intervals ([1,2] and [2,3]) count as overlapping. For closed intervals they usually do, so use >. For half-open time slots [start, end) they might not.

Complexity: O(n log n) for the sort plus O(n) for the sweep. Space is O(n) for the output (and O(log n) to O(n) for the sort).

This pattern underlies calendar and meeting-room problems, merging IP ranges, and collapsing booked time slots. Meeting Rooms II (minimum rooms) is a related problem. Sort start and end times separately, or use a min-heap of end times. The answer is the maximum number of meetings overlapping at once.

How it works

  1. If the input is empty, return empty.
  2. Sort by start.
  3. Push the first interval into merged.
  4. For each next interval: if start > last.end, append it. Otherwise last.end = max(last.end, end).
  5. Return merged.

Example

public int[][] merge(int[][] intervals) {
    Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));
    List<int[]> merged = new ArrayList<>();
    for (int[] cur : intervals) {
        if (merged.isEmpty() || cur[0] > merged.get(merged.size() - 1)[1]) {
            merged.add(cur);
        } else {
            int[] last = merged.get(merged.size() - 1);
            last[1] = Math.max(last[1], cur[1]);
        }
    }
    return merged.toArray(new int[0][]);
}
// [[1,4],[2,3],[5,7],[6,8]] -> [[1,4],[5,8]]

Common mistakes

  • Forgetting to sort, or sorting by end instead of start.
  • Setting last.end = cur.end instead of the max, which fails on nested intervals.
  • Not clarifying whether touching endpoints merge.
  • Using a[0] - b[0] in the comparator, which can overflow with extreme values. Use Integer.compare.

How to answer in the interview

"I'd sort the intervals by start time, then walk through them, keeping a list of merged intervals. If the current interval starts after the end of the last merged one, there's no overlap and I append it. Otherwise they overlap and I extend the last merged interval's end to the max of both ends. The max handles nested intervals. Because the list is sorted, I only ever need to compare with the last merged interval. Sorting dominates, so it's O(n log n) time and O(n) for the output. I'd confirm whether touching intervals should merge."

Likely follow-up questions

  • How many meeting rooms are needed? Sort by start and keep a min-heap of end times. The peak heap size is the answer.
  • Insert a new interval into a sorted list? Add the ones before, merge the overlapping ones, add the rest. O(n).
  • Intervals arriving as a stream? Keep a balanced tree (TreeMap) keyed by start and merge with neighbours on insert.
