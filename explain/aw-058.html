Compare CloudFormation, AWS CDK and Terraform for AWS infrastructure.

Cloud (AWS) · concept · levels mid

In one line

CloudFormation is native declarative YAML/JSON with AWS-managed state, the AWS CDK lets you write infrastructure in real programming languages that synthesise to CloudFormation, and Terraform uses HCL with its own state file and thousands of providers across clouds and SaaS; choose by team skills, scope and ecosystem.

Detailed explanation

CloudFormation needs nothing extra: AWS stores state, handles rollbacks, and integrates with StackSets, Service Catalog, Control Tower and CloudFormation Hooks for policy enforcement. New AWS services usually appear in the CloudFormation registry early, often at launch. The downsides are verbose templates, limited logic, and AWS-only scope.

CDK lets developers use TypeScript, Python, Java, C# or Go with loops, functions, classes and unit tests. Constructs come in levels: L1 maps directly to CloudFormation resources, L2 adds sensible defaults and helper methods like bucket.grantRead(fn), and L3 patterns build whole architectures. cdk synth produces CloudFormation templates, so you inherit its state management and rollbacks, and its limits. CDK suits application teams who want infrastructure next to their code, but abstractions can hide what is created, so review the synthesised diff.

Terraform (or the open-source OpenTofu fork) uses HCL and a state file stored remotely, for example in S3 with state locking. Its strength is the provider ecosystem: AWS, Azure, Google Cloud, Kubernetes, Datadog, GitHub, Cloudflare and more in one workflow, plus a mature module registry. terraform plan shows exact changes. You own state security, locking and drift handling, and new AWS features depend on provider releases, though the AWS provider is usually quick and the AWS Cloud Control provider covers new resources automatically. Since 2023, Terraform is under the BUSL licence, which some organisations avoid by using OpenTofu.

Selection factors: existing skills and standards, multi-cloud or SaaS needs, whether developers or a platform team own infrastructure, and governance tooling.

How it works

  1. CloudFormation: template, then change set, then stack.
  2. CDK: code, then cdk synth to a template, then cdk diff, then cdk deploy via CloudFormation.
  3. Terraform: HCL, then terraform plan against state, then apply via provider APIs.
  4. All three: run in CI with review of the plan or diff.

Example

The same bucket in CDK and Terraform:

const bucket = new s3.Bucket(this, "Reports", {
  versioned: true,
  encryption: s3.BucketEncryption.S3_MANAGED,
  blockPublicAccess: s3.BlockPublicAccess.BLOCK_ALL,
});
bucket.grantRead(reportFunction);
resource "aws_s3_bucket" "reports" {
  bucket = "reports-${var.env}"
}
resource "aws_s3_bucket_versioning" "reports" {
  bucket = aws_s3_bucket.reports.id
  versioning_configuration { status = "Enabled" }
}

Common mistakes

  • Managing the same resource with two tools, causing fights and drift.
  • Storing Terraform state locally or unencrypted.
  • Over-abstracted CDK constructs nobody can reason about.
  • Choosing by hype rather than team skills and operating model.

How to answer in the interview

"CloudFormation is native: declarative YAML, state managed by AWS, StackSets and Service Catalog integration, early support for new services, but verbose. CDK lets me use TypeScript or Python with loops and reusable constructs and synthesises CloudFormation, which suits developer teams. Terraform uses HCL and its own state, and its provider ecosystem manages AWS, Azure, Kubernetes, Datadog and GitHub in one workflow with a mature module registry. I choose based on team skills, multi-cloud or SaaS needs and existing standards, and I never let two tools manage one resource."

Likely follow-up questions

  • What problems appear if two tools manage one resource? Each overwrites the other's changes, producing endless drift and possible deletions.
  • How secure Terraform state? Encrypted S3 bucket with versioning, locking, and restricted access because state holds secrets.
  • What is cdk-nag? A rule pack that checks CDK apps against security best practices at synth time.
