How do loops and conditionals work in Ansible tasks?

Configuration Management · concept · levels entry

In one line

loop runs a task once per item (item), with dict2items and loop_control for structures and labels; when adds conditions on variables, facts or registered results; until/retries/delay retries a task until a condition holds.

Detailed explanation

Loops. loop: takes a list and runs the task for each element, available as {{ item }}. To iterate over a dictionary, convert it with {{ users | dict2items }}, which yields item.key and item.value. Nested data can be flattened with filters like subelements or product. loop_control adjusts behaviour: loop_var renames item (essential when including tasks that loop themselves), label shortens noisy output, index_var gives the index, and pause waits between iterations. The older with_items style still works but loop is the modern form.

Conditionals. when: takes a raw Jinja2 expression (no {{ }}) and skips the task if false. Conditions can use variables, facts (ansible_facts['os_family'] == 'Debian'), registered results (result.rc != 0, result is changed), or tests like is defined. A list under when means all conditions must be true. When combined with a loop, when is evaluated per item, so you can act only on matching elements, such as creating only users with active: true.

Retries. until: with retries and delay repeats a task until the condition becomes true, which is the standard way to wait for something like an HTTP health endpoint or a cluster to become ready.

Performance note: many modules such as apt, dnf and package accept a list in name. Passing the list directly installs everything in one transaction, which is much faster than looping one package at a time.

How it works

  1. Ansible evaluates the loop expression to a list.
  2. For each item it evaluates when.
  3. If true, it runs the module with that item.
  4. Results are collected in result.results if registered.
  5. With until, the task repeats until the condition passes or retries are exhausted.

Example

- name: Install packages on Debian family (single transaction)
  ansible.builtin.apt:
    name: [nginx, curl, jq]
    state: present
  when: ansible_facts['os_family'] == 'Debian'

- name: Create active users only
  ansible.builtin.user:
    name: "{{ item.key }}"
    shell: "{{ item.value.shell | default('/bin/bash') }}"
  loop: "{{ users | dict2items }}"
  loop_control:
    label: "{{ item.key }}"
  when: item.value.active

- name: Wait until the app is healthy
  ansible.builtin.uri:
    url: http://localhost:8080/health
  register: health
  until: health.status == 200
  retries: 10
  delay: 5

Common mistakes

  • Wrapping when expressions in {{ }}.
  • Looping over packages instead of passing a list.
  • Nested includes both using item, overwriting each other (use loop_var).
  • until without register, so the condition has nothing to test.

How to answer in the interview

"loop runs a task once per element, with the current element as item; dictionaries are iterated with dict2items, and loop_control lets me rename the loop variable or set a label for cleaner output. when adds conditions based on variables, facts or registered results, like os_family equals Debian, so one playbook covers several platforms, and with a loop it's evaluated per item, so I can create only active users. until with retries and delay repeats a task until, say, a health endpoint responds. And for packages I pass the list directly to the module, which is one transaction instead of many."

Likely follow-up questions

  • Why is passing a list of packages to apt faster than looping? One dependency resolution and transaction instead of one per package.
  • How do you loop over nested lists? Filters like subelements, product or flatten.
  • How do you check whether a registered task changed? when: result is changed.
