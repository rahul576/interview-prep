Compare ARM templates, Bicep and Terraform for Azure infrastructure as code.

Azure · concept · levels entry, mid

In one line

ARM templates are Azure's native but verbose JSON; Bicep is a concise Azure-only DSL that compiles to ARM with day-zero resource support and no state file; Terraform uses HCL with a state file and supports many clouds and SaaS providers.

Detailed explanation

All Azure deployments ultimately go through Azure Resource Manager (ARM). ARM templates describe resources in JSON. They are declarative and complete, but long, hard to read, and awkward for loops, conditions and modularisation.

Bicep is Microsoft's domain-specific language that transpiles to ARM JSON. It supports every Azure resource type and API version as soon as it exists in ARM, because it uses the same resource provider schemas. It has clean syntax, strong typing and IntelliSense in VS Code, modules (local or in a registry), and what-if to preview changes. Azure itself is the source of truth, so there is no state file to store, lock or secure. Deployment stacks add lifecycle management: resources removed from the template can be deleted or detached, and deny settings can protect managed resources from manual changes.

Terraform by HashiCorp uses HCL and providers: azurerm for Azure (plus azapi for brand-new features), and providers for AWS, GCP, Kubernetes, GitHub, Datadog and many more. It keeps a state file, usually in an Azure Storage backend with locking, which lets terraform plan show exact differences and track resources it manages. It has a large ecosystem of modules and is often the standard in multi-cloud organisations. Note that Terraform moved to the Business Source Licence in 2023; OpenTofu is the open-source fork.

Choice: Bicep for Azure-only teams wanting native support and no state management; Terraform for multi-cloud, existing Terraform skills, or managing non-Azure resources in the same workflow.

How it works

  1. Write declarative code describing desired resources.
  2. Preview: az deployment group what-if (Bicep) or terraform plan.
  3. Review in a pull request; run validation and linting in CI.
  4. Apply through a pipeline with a federated identity.
  5. Bicep: ARM records deployments; Terraform: state file updated.
  6. Detect drift with periodic what-if or plan runs.

Example

param location string = resourceGroup().location
param env string

resource sa 'Microsoft.Storage/storageAccounts@2023-05-01' = {
  name: 'storders${env}${uniqueString(resourceGroup().id)}'
  location: location
  sku: { name: 'Standard_ZRS' }
  kind: 'StorageV2'
  properties: { allowBlobPublicAccess: false, minimumTlsVersion: 'TLS1_2' }
}
resource "azurerm_storage_account" "orders" {
  name                     = "stordersprod001"
  resource_group_name      = azurerm_resource_group.rg.name
  location                 = "westeurope"
  account_tier             = "Standard"
  account_replication_type = "ZRS"
}

Common mistakes

  • Writing new ARM JSON by hand instead of Bicep.
  • Storing Terraform state locally or without locking.
  • Mixing manual portal changes with IaC, causing drift.
  • Assuming Bicep's incremental mode deletes removed resources (use deployment stacks).
  • Choosing Terraform only because "it is multi-cloud" in an Azure-only company.

How to answer in the interview

"ARM templates are Azure's native JSON format, complete but verbose. Bicep is a concise language that compiles to ARM, supports new Azure features on day zero, needs no state file because Azure is the source of truth, and offers modules, what-if previews and deployment stacks for lifecycle management. Terraform uses HCL and a state file, typically stored in Azure Storage with locking, works across many clouds and SaaS providers, and has a big module ecosystem and precise plans. I choose Bicep for Azure-only organisations and Terraform when the company is multi-cloud or already standardised on it."

Likely follow-up questions

  • How do you handle drift with Bicep compared with Terraform? Scheduled what-if or deployment stack deny settings versus scheduled terraform plan.
  • How do you secure Terraform state? Private storage account, RBAC, versioning and blob lease locking.
  • Can you import existing resources? Yes: terraform import or import blocks; for Bicep, export or decompile then refine.
