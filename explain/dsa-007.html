How do you compute the product of an array except self without using division?

DSA: Arrays & Strings · concept · levels mid

In one line

answer[i] = product of everything left of i × product of everything right of i. Fill the output with prefix products in one pass, then multiply by a running suffix product from the right. That is O(n) time, O(1) extra space (besides the output), with no division, so zeros are handled correctly.

Detailed explanation

The obvious approach is to compute the total product and divide by nums[i]. It fails in two ways:

  1. Zeros: with one zero, every position except the zero's gets 0, and the zero's position needs the product of the others. Dividing by zero is undefined. With two or more zeros, everything is 0. Handling this needs special-case counting.
  2. The problem often forbids division explicitly. Division can also misbehave with integer rounding.

Instead, decompose: answer[i] = prefix[i] * suffix[i], where prefix[i] = nums[0]·…·nums[i-1] and suffix[i] = nums[i+1]·…·nums[n-1]. Computing two separate arrays is O(n) time and O(n) extra space. To get O(1) extra space, reuse the output array:

  • Left pass: out[0] = 1, then out[i] = out[i-1] * nums[i-1].
  • Right pass: keep a variable right = 1, going from i = n-1 down to 0: out[i] = right and right = nums[i].

Each element ends up multiplied by every other element exactly once, and zeros flow through naturally with no special cases.

Overflow: the product of many values may overflow int. Many problem statements guarantee it fits, but in real code you'd use long, BigInteger or modular arithmetic.

How it works

  1. out = new int[n], out[0] = 1.
  2. For i in 1..n-1: out[i] = out[i-1] * nums[i-1].
  3. right = 1.
  4. For i from n-1 down to 0: out[i] = right, then right = nums[i].
  5. Return out.

Example

public int[] productExceptSelf(int[] nums) {
    int n = nums.length;
    int[] out = new int[n];
    out[0] = 1;
    for (int i = 1; i < n; i++) out[i] = out[i - 1] * nums[i - 1];
    int right = 1;
    for (int i = n - 1; i >= 0; i--) {
        out[i] *= right;
        right *= nums[i];
    }
    return out;
}
// nums = [1, 2, 3, 4]
// after left pass : [1, 1, 2, 6]
// after right pass: [24, 12, 8, 6]
// nums = [0, 4, 5] -> [20, 0, 0]

Common mistakes

  • Using division and breaking on zeros.
  • Including nums[i] itself in the prefix (an off-by-one).
  • Updating right before multiplying out[i].
  • Claiming O(1) space while allocating separate prefix and suffix arrays. Mention that the output array isn't counted.

How to answer in the interview

"For each index, the answer is the product of everything to its left times everything to its right. In a first pass I write prefix products into the output, so output i is the product of all elements before i. In a second pass from the right I keep a running suffix product and multiply each output by it, then fold in the current element. No division is needed, so zeros just work. It's O(n) time and O(1) extra space apart from the output array."

Likely follow-up questions

  • How do zeros break the division approach? You can't divide by zero, and with one zero only that index gets a non-zero product.
  • Overflow concerns? Use long or BigInteger, or a modulus if the problem asks for one.
  • Same idea elsewhere? Prefix sums, "trapping rain water" (prefix and suffix max), and range queries.
