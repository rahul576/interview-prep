Design a search autocomplete (typeahead) service.

System Design · design · levels senior, lead

In one line

Typeahead serves precomputed top-K suggestions per prefix from memory or Redis, built from a trie or search-engine prefix index ranked by popularity from search logs (plus trending and personal boosts), refreshed by an offline pipeline, and kept fast with client debouncing and edge caching.

Detailed explanation

Autocomplete must respond in tens of milliseconds, on every keystroke, at huge request volumes. That rules out computing suggestions by scanning data at query time.

Data structure: a trie maps prefixes to nodes; walking to the node for "ipho" and collecting descendants gives candidates. Collecting and sorting at query time is slow for short prefixes, so each node stores its precomputed top-K (e.g. 10) completions. Alternatives: Elasticsearch/OpenSearch completion suggester (in-memory FST), or edge n-gram fields for infix-tolerant matching, or simply a key-value store with key = prefix, value = top-K list.

Ranking: popularity (query frequency from logs, weighted by recency with time decay), plus signals such as conversion, trending boost, location, and personalisation (user's recent searches, merged at serving time).

Pipeline: a batch job (Spark) aggregates query logs daily or hourly, filters offensive or unsafe terms and spam, computes top-K per prefix, and publishes an immutable snapshot that serving nodes load and swap atomically. For trending, a streaming job (Flink/Kafka Streams) counts queries over a sliding window (e.g. last hour) and merges a small trending list.

Serving: stateless services hold the trie in memory (sharded by prefix range if too large) or read from Redis. The client debounces input (e.g. 100-150 ms), cancels outdated requests, and caches results locally; responses for short popular prefixes are cacheable at the CDN for a few minutes.

How it works

  1. Logs -> Kafka -> data lake.
  2. Batch job: normalise queries, count with decay, filter, build prefix -> top-K map.
  3. Publish snapshot; servers load into memory or Redis.
  4. Client types "iph" -> debounced request GET /suggest?q=iph.
  5. Server returns cached top-K, merged with trending and personal history.
  6. Selections are logged, feeding the next build.

Example

final class TrieNode {
    final Map<Character, TrieNode> children = new HashMap<>();
    List<String> topK = List.of();                    // precomputed offline
}

final class Suggester {
    private volatile TrieNode root;                  // swapped atomically on new snapshot
    List<String> suggest(String prefix) {
        TrieNode n = root;
        for (char c : prefix.toLowerCase().toCharArray()) {
            n = n.children.get(c);
            if (n == null) return List.of();
        }
        return n.topK;
    }
    void load(TrieNode newRoot) { this.root = newRoot; }
}

Common mistakes

  • Querying the database with LIKE 'pre%' on each keystroke.
  • Collecting and sorting all descendants at query time.
  • No profanity or safety filtering.
  • No client debouncing, multiplying load.
  • Updating the live trie in place with locks instead of swapping snapshots.

How to answer in the interview

"Suggestions must come back in tens of milliseconds as the user types, so I precompute. Offline, a pipeline aggregates search logs, ranks queries by popularity with time decay, filters offensive terms, and builds a prefix-to-top-K map, as a trie or using the Elasticsearch completion suggester. Serving nodes load the snapshot in memory or Redis, so a lookup is one read. Trending queries come from a streaming job over the last hour, merged at serving time with personal history. On the client I debounce keystrokes, and popular prefixes are cached at the edge."

Likely follow-up questions

  • Trending from the last hour? Sliding-window counts in Flink, boost terms whose rate jumps against baseline.
  • Typos? Fuzzy matching on the completion suggester or spelling correction.
  • Multiple languages? Separate tries per locale with language-specific normalisation.
