What is the difference between final, finally and finalize?

Core Java & OOP · concept · levels entry

In one line

final is a keyword (variable cannot be reassigned, method cannot be overridden, class cannot be extended); finally is a block that always runs after try/catch for cleanup; finalize() was a GC callback that is deprecated for removal and replaced by try-with-resources and Cleaner.

Detailed explanation

The three names are similar but unrelated.

final has three uses:

  • Variable/field: can be assigned only once. For a reference, the reference is fixed, not the object (a final List can still be modified). final fields also have special Java Memory Model guarantees: after construction they are safely visible to other threads, which is why they are key for immutable classes. Local variables used in lambdas must be final or effectively final.
  • Method: cannot be overridden, useful for template methods or security-sensitive logic.
  • Class: cannot be extended, like String or Integer. Sealed classes (Java 17) give finer control.

finally belongs to exception handling: try { ... } catch (...) { ... } finally { ... }. The finally block runs whether the try completes normally, returns, or throws, and whether or not a catch matched. It is used to release resources, unlock locks, or reset state. It does not run if the JVM halts (System.exit, Runtime.halt, a crash or the process being killed), and a daemon thread may be abandoned at shutdown. Avoid return or throwing inside finally: it overrides the original result and can swallow exceptions.

finalize() is a protected method on Object that the garbage collector might call before reclaiming an object. It was problematic: no guarantee when or whether it runs, it slows GC, it can resurrect objects, and exceptions in it are ignored. It has been deprecated since Java 9 and deprecated for removal since Java 18 (JEP 421), and finalization can be disabled with --finalization=disabled. For cleanup, use try-with-resources with AutoCloseable for deterministic release, and java.lang.ref.Cleaner only as a safety net for native resources.

How it works

  1. final is enforced by the compiler (and JVM for classes/methods).
  2. finally: the compiler copies the finally code onto every exit path of the try/catch.
  3. On exception, catch runs (if matching), then finally, then the exception continues.
  4. On return, the return value is computed, finally runs, then the method returns.
  5. finalize: GC queued objects to a finalizer thread; now replaced by Cleaner and try-with-resources.

Example

public final class Money {                        // final class
    private final BigDecimal amount;              // final field
    public Money(BigDecimal amount) { this.amount = amount; }
}

Lock lock = new ReentrantLock();
lock.lock();
try {
    updateInventory();
} finally {
    lock.unlock();                                // always runs
}

try (Connection c = dataSource.getConnection();   // replaces finalize-style cleanup
     PreparedStatement ps = c.prepareStatement(SQL)) {
    ps.executeUpdate();
}

static int value() {
    try { return 1; }
    finally { return 2; }                         // returns 2: don't do this
}

Common mistakes

  • Believing a final collection is immutable.
  • Returning or throwing from finally, hiding the real exception.
  • Relying on finalize() to close files or connections.
  • Assuming finally runs after System.exit().

How to answer in the interview

"final is a keyword: a final variable can't be reassigned, a final method can't be overridden, and a final class can't be extended; final fields also get safe-publication guarantees. finally is a block after try or catch that always executes, whether or not an exception is thrown, so it's used for cleanup like unlocking; it's skipped only in cases like System.exit or the JVM crashing. finalize was a method the garbage collector might call before reclaiming an object, but it was unpredictable and slow, deprecated since Java 9 and marked for removal since Java 18. For cleanup I use try-with-resources, or Cleaner as a safety net."

Likely follow-up questions

  • If both the try block and the finally block contain a return statement, which value is returned? The finally block's return; it overrides the try's value and would also swallow an exception.
  • What is effectively final? A local variable never reassigned after initialisation, which lambdas and inner classes may capture.
  • How does Cleaner differ from finalize? It registers a separate cleanup action that cannot resurrect the object and runs on a dedicated thread, but is still non-deterministic.
