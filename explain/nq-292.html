What is the difference between a JAR and a WAR file?

Build Tools · concept · levels entry

In one line

A JAR is a Java archive of classes, resources and a manifest, used for libraries and standalone apps (Spring Boot's executable fat jar embeds the server); a WAR packages a web application with a WEB-INF structure for deployment into an external servlet container such as Tomcat or WildFly.

Detailed explanation

Both are ZIP files with a META-INF/MANIFEST.MF; the difference is structure and how they are run.

A JAR (Java ARchive) contains compiled .class files and resources. A plain JAR is typically a library placed on the classpath. If the manifest has a Main-Class, it can be run with java -jar. A Spring Boot executable jar (fat or uber jar) goes further: it nests all dependency JARs in BOOT-INF/lib, your classes in BOOT-INF/classes, and a special launcher; it also contains an embedded server (Tomcat, Jetty or Undertow), so the application is self-contained and runs anywhere with a JRE — ideal for containers.

A WAR (Web application ARchive) follows the servlet specification layout:

  • WEB-INF/web.xml – optional deployment descriptor (servlet 3.0+ allows annotations instead).
  • WEB-INF/classes – your compiled classes.
  • WEB-INF/lib – dependency JARs.
  • Static content (HTML, JS, JSP) at the root.

A WAR does not contain a server. It is deployed into an external servlet container or application server — Tomcat, Jetty, WildFly/JBoss EAP, WebLogic, WebSphere — which provides the servlet API, often JNDI datasources and other services, and can host several applications.

Modern microservices mostly use executable JARs: one process per service, configuration through environment variables, easy containerisation. WARs remain common in organisations running shared, centrally managed application servers. Related: an EAR bundles multiple modules for Jakarta EE servers.

How it works

  1. JAR: java -jar app.jar starts the main class; Spring Boot's launcher starts the embedded server.
  2. WAR: copy app.war into the server's deployment folder (e.g. Tomcat webapps/).
  3. The container unpacks it, creates a classloader per app and starts servlets.
  4. The context path is usually derived from the WAR name.

Example

<packaging>war</packaging>
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-tomcat</artifactId>
  <scope>provided</scope>
</dependency>
public class ServletInitializer extends SpringBootServletInitializer {
    @Override
    protected SpringApplicationBuilder configure(SpringApplicationBuilder app) {
        return app.sources(OrdersApplication.class);
    }
}
java -jar target/orders.jar               # executable JAR
cp target/orders.war $CATALINA_HOME/webapps/

Common mistakes

  • Packaging the embedded Tomcat in compile scope inside a WAR.
  • Assuming a plain library JAR is runnable.
  • Mixing servlet API versions (javax vs jakarta) with the target server.
  • Forgetting the WAR name defines the context path.

How to answer in the interview

"A JAR is a zip of compiled classes, resources and a manifest, used for libraries and standalone apps. A Spring Boot executable fat jar also contains all dependencies and an embedded server, so I just run java -jar. A WAR packages a web application for deployment into an external servlet container or app server like Tomcat, JBoss or WebLogic, with the WEB-INF structure: web.xml, classes and lib. Microservices and containers mostly use JARs, while WARs remain where organisations run shared application servers. Spring Boot can produce either."

Likely follow-up questions

  • How do you make a Spring Boot app deployable as a WAR? Packaging war, embedded Tomcat as provided, and extend SpringBootServletInitializer.
  • Can a WAR still run with java -jar? A Spring Boot WAR can, because it keeps the launcher.
  • What is an EAR? An enterprise archive bundling several JAR and WAR modules.
