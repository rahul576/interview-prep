How do custom annotations work, and how are they processed?

Core Java & OOP · concept · levels mid, senior

In one line

Custom annotations are declared with @interface; @Retention (SOURCE, CLASS, RUNTIME) decides how long they survive, @Target where they may appear, and they are processed at runtime by reflection or AOP or at compile time by annotation processors.

Detailed explanation

An annotation is metadata. By itself it does nothing; some code has to read it and act. Declaring one looks like an interface with @ in front; its "methods" are attributes, which may have defaults and must be primitives, String, Class, enums, other annotations or arrays of these.

Meta-annotations configure it:

  • @Retention: SOURCE (discarded by javac, e.g. @Override), CLASS (kept in the class file but not visible at runtime, the default), RUNTIME (visible via reflection, needed for Spring-style processing).
  • @Target: where it can be used, such as TYPE, METHOD, FIELD, PARAMETER, TYPE_USE.
  • @Inherited: class-level annotation is inherited by subclasses. @Documented and @Repeatable also exist.

Processing options:

  1. Runtime reflection: method.getAnnotation(Audited.class). Used by JUnit, Jackson, JPA.
  2. Spring AOP: an @Aspect with @Around("@annotation(com.shop.Timed)") wraps annotated beans' methods in a proxy. Note proxy limits: self-invocation inside the same class bypasses the aspect, and private methods aren't intercepted.
  3. Compile-time annotation processors (JSR 269, javax.annotation.processing.Processor): run inside javac and generate new source files, as in MapStruct, Dagger, Immutables. Lombok is a special case that modifies the compiler's AST using internal APIs.
  4. Bean Validation custom constraints via @Constraint(validatedBy = ...).

Spring also supports meta-annotations: an annotation annotated with @Transactional or @Service acts as a composed shortcut.

How it works

  1. Declare the annotation with retention and target.
  2. Place it on classes, methods or fields.
  3. A processor reads it: reflection at runtime, a proxy/aspect, or javac at compile time.
  4. The processor applies behaviour or generates code based on its attributes.

Example

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Timed { String value() default ""; }

@Aspect @Component
class TimedAspect {
    @Around("@annotation(timed)")
    Object time(ProceedingJoinPoint pjp, Timed timed) throws Throwable {
        long start = System.nanoTime();
        try { return pjp.proceed(); }
        finally {
            log.info("{} took {} ms", pjp.getSignature().toShortString(),
                     (System.nanoTime() - start) / 1_000_000);
        }
    }
}

Common mistakes

  • Forgetting @Retention(RUNTIME), so reflection never sees the annotation.
  • Expecting a Spring aspect to fire on self-invocation or private methods.
  • Putting business logic into annotation attributes instead of code.
  • Writing a custom annotation where Micrometer's existing @Timed/@Observed would do.

How to answer in the interview

"You declare an annotation with @interface and attributes. Retention controls its life: SOURCE is dropped by the compiler, CLASS stays in bytecode, and RUNTIME is visible through reflection. Target restricts where it can be placed. Annotations do nothing alone; something reads them. At runtime that's reflection or Spring AOP, for example a @Timed annotation handled by an @Around aspect that measures duration. At compile time annotation processors like MapStruct generate code. With Spring AOP I remember that proxies don't intercept self-calls."

Likely follow-up questions

  • How would you implement a @Timed annotation? RUNTIME retention, METHOD target, and an @Around aspect timing proceed().
  • Why doesn't the aspect fire for internal calls? The call doesn't go through the proxy.
  • What is the default retention? CLASS.
