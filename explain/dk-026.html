How do you install Docker on a Linux server and allow a user to run it?

Docker · concept · levels entry

In one line

Install Docker Engine from Docker's official repository, enable it with systemctl enable --now docker, and allow a user with usermod -aG docker <user>, knowing that the docker group is root-equivalent; rootless mode is the safer alternative.

Detailed explanation

Linux distributions often ship older packages (docker.io, or Podman on RHEL), so for current features you add Docker's official apt or dnf repository with its signing key and install docker-ce, docker-ce-cli, containerd.io, docker-buildx-plugin and docker-compose-plugin. The convenience script get.docker.com exists, but on servers the repository method or configuration management (Ansible, cloud-init) is better because it is repeatable and reviewable. Then you enable and start the service with systemd.

The daemon listens on /var/run/docker.sock, owned by root and the docker group. To let a user run docker without sudo, you add them to that group and they must log in again (or run newgrp docker) for the membership to apply. Understand what this grants: anyone in the docker group can run docker run -v /:/host --privileged and modify the host, so membership is effectively root. Treat it like sudo rights, give it only to trusted admins, and audit it.

Rootless mode runs the daemon itself as an ordinary user using user namespaces, so a compromise of that user or a container escape does not give host root. It has limitations, such as binding ports below 1024 and some networking and storage features. Further hardening: configure log rotation in /etc/docker/daemon.json, keep the daemon off TCP unless protected by TLS, and keep packages updated.

How it works

  1. Add Docker's GPG key and repository.
  2. Install the engine, CLI, containerd and plugins.
  3. systemctl enable --now docker starts it and enables it at boot.
  4. Add trusted users to the docker group; they re-login.
  5. Verify with docker run hello-world and docker info.

Example

# Ubuntu
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo usermod -aG docker alice
docker run --rm hello-world && docker version && docker compose version

Common mistakes

  • Treating docker group membership as harmless.
  • chmod 666 /var/run/docker.sock to "fix" permission errors.
  • Installing the old distro package and missing Compose v2 or BuildKit features.
  • Forgetting log rotation, so a chatty container fills the disk.

How to answer in the interview

"I add Docker's official repository, install docker-ce, the CLI, containerd and the buildx and compose plugins, and enable the service with systemctl enable --now docker, ideally through Ansible or cloud-init so it's repeatable. By default only root can use the socket, so to let a user run docker without sudo I add them to the docker group and they log in again. I'm careful because docker group membership is effectively root on the host. Where that's a concern I use rootless mode. Then I verify with docker run hello-world and configure log rotation."

Likely follow-up questions

  • How do you verify the installation? docker run hello-world, docker info, systemctl status docker.
  • Why is the docker group dangerous? It can mount the host filesystem in a privileged container.
  • How do you enable rootless mode? Install the rootless extras and run dockerd-rootless-setuptool.sh install as the user.
