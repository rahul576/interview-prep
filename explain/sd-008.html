What is consistent hashing, and where is it used?

SD Fundamentals · concept · levels entry, mid, senior

In one line

Consistent hashing places keys and nodes on a hash ring so adding or removing a node moves only about 1/N of the keys, instead of reshuffling almost everything like hash mod N.

Detailed explanation

With hash(key) % N, changing N from 4 to 5 remaps roughly 80% of keys. For a cache that means a flood of misses hitting the database; for a database it means moving most of the data.

Consistent hashing maps the hash space onto a circle. Each node owns positions on the ring; a key belongs to the first node clockwise from its hash. Adding a node only steals keys from its neighbour. To avoid uneven load (some nodes owning big arcs), each physical node gets many virtual nodes spread around the ring, which also lets stronger machines take more load.

How it works

  1. Hash each node's virtual IDs (e.g. nodeA#1..#200) onto the ring.
  2. Hash the key; walk clockwise to the next virtual node; that physical node owns the key.
  3. For replication, continue clockwise to the next N−1 distinct physical nodes.
  4. On node join/leave, only the affected arcs move.

Example

import bisect, hashlib
def h(s): return int(hashlib.md5(s.encode()).hexdigest(), 16)
ring = sorted((h(f"{n}#{i}"), n) for n in ["A","B","C"] for i in range(100))
def node_for(key):
    i = bisect.bisect(ring, (h(key),)) % len(ring)
    return ring[i][1]

Common mistakes

  • Forgetting virtual nodes, giving very uneven load.
  • Assuming it solves hot keys; one hot key still lands on one node.
  • Confusing it with Redis Cluster's fixed hash slots (16,384 slots assigned to nodes), a related but different approach.

How to answer in the interview

"Modulo hashing remaps almost every key when the node count changes, which is disastrous for caches. Consistent hashing puts nodes and keys on a ring; a key goes to the next node clockwise, so a new node only takes over a small arc, about 1/N of the keys. Virtual nodes even out the load. Cassandra, DynamoDB and many cache clients use it."

Likely follow-up questions

  • How is replication done? Store each key on the next N distinct nodes clockwise.
  • What about hot keys? Needs separate handling: local caching or key splitting.
  • How do Redis Cluster slots differ? Fixed 16,384 slots; resharding moves whole slots between nodes.
