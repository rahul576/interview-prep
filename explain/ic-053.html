How do you run only part of an Ansible playbook or target specific hosts?

Configuration Management · concept · levels mid

In one line

Narrow an Ansible run with --limit and host patterns for where it runs, --tags / --skip-tags for what runs, and --start-at-task, --step, --check and the **--list-* flags for debugging, remembering that skipped tasks can break later ones.

Detailed explanation

A playbook normally runs every play against every host its hosts: line matches. In real operations you rarely want that: you want to test a change on one server, re-apply only the nginx configuration, or resume after a failure. Ansible gives you two independent dials.

Host selection. --limit intersects the play's hosts with a pattern: a single host (web1), a group (web), an intersection (web:&prod, hosts in both), an exclusion (web:!web3), a wildcard (web*) or a file of hosts (--limit @retry_hosts.txt).

Task selection. Tags label tasks, blocks, roles or imports. --tags nginx runs only tagged work; --skip-tags packages skips the slow parts. Two special tags matter: always runs even when other tags are selected (unless explicitly skipped with --skip-tags always), and never runs only when requested by name, useful for dangerous tasks like a database reset. Tags on **import_ are inherited by every imported task (static), while tags on include_** apply only to the include statement itself unless you use apply:.

Debugging aids. --start-at-task "Deploy config" resumes from a task, --step asks before each task, --check --diff shows what would change, and --list-hosts, --list-tasks and --list-tags show the effect of your filters before anything runs.

How it works

  1. Ansible loads the inventory and resolves each play's hosts: pattern.
  2. --limit intersects that host list with your pattern.
  3. Tasks are filtered by --tags/--skip-tags, keeping always and dropping never unless named.
  4. Remaining tasks run; handlers fire only if a task that ran notified them.
  5. Failed hosts can be re-run with --limit on just those hosts.

Example

# Preview, then apply the nginx part to one prod web server
ansible-playbook site.yml --limit 'web:&prod' --list-hosts
ansible-playbook site.yml --limit web1.prod --tags nginx --check --diff
ansible-playbook site.yml --limit web1.prod --tags nginx
- name: Gather app facts used by later tasks
  ansible.builtin.command: /opt/app/bin/version
  register: app_version
  changed_when: false
  tags: [always]

Common mistakes

  • Skipping a task that registers a variable or creates a directory, so a later tagged task fails.
  • Forgetting the quotes around patterns like 'web:&prod', so the shell interprets & or !.
  • Expecting tags on include_tasks to apply to the included tasks.
  • Running without --list-hosts first and hitting more servers than intended.

How to answer in the interview

"I control two things separately: which hosts and which tasks. For hosts I use --limit with inventory patterns, for example web:&prod for the intersection, so I can try a change on one server first. For tasks I tag roles and tasks and run --tags nginx or skip slow parts with --skip-tags. Before running I check with --list-hosts and --list-tasks, and I use --check --diff on the first host. For debugging there's --start-at-task and --step. The catch is dependencies: if I skip a task that registers a variable, a later task breaks, so such tasks get the always tag."

Likely follow-up questions

  • What does the special tag "always" do? The task runs whatever tags you select, unless you explicitly skip always.
  • And the "never" tag? The task is skipped unless you request it, or one of its other tags, by name.
  • How do you re-run only failed hosts? Use --limit with the failed hosts (or a retry file if enabled).
