What are Bloom filters and other probabilistic data structures, and where do they help in system design?

Distributed Systems · concept · levels entry, mid, senior

In one line

Probabilistic structures trade exactness for tiny memory: Bloom filters answer "definitely not / maybe in set", HyperLogLog counts distinct items, Count-Min Sketch estimates frequencies; they're mergeable and power LSM databases, crawlers, analytics and caches.

Detailed explanation

Bloom filter: a bit array of m bits and k hash functions. Adding an item sets k bits; checking tests them. If any is 0 → definitely absent; if all are 1 → probably present (false positive). No false negatives. Size for n items and false-positive rate p: m ≈ −n·ln(p)/(ln 2)², k ≈ (m/n)·ln 2. Roughly 10 bits per item for 1%. Standard Bloom filters don't support deletion (counting/cuckoo filters do).

Uses: Cassandra/RocksDB skip SSTables that can't contain a key; crawlers check seen URLs; CDNs avoid caching one-hit wonders; databases avoid lookups for non-existent keys (cache penetration protection).

HyperLogLog: estimates cardinality (unique visitors) with ~0.81% error using ~12 KB in Redis (PFADD, PFCOUNT, PFMERGE), regardless of billions of items.

Count-Min Sketch: a 2D array of counters with several hashes; estimates frequency (overestimates only). Used for heavy hitters, trending topics, rate limiting by key.

How it works

  1. Choose structure by question: membership, distinct count, frequency.
  2. Size it for expected n and error.
  3. Shards keep their own; merge (OR for Bloom, union for HLL, add for CMS).

Example

PFADD visitors:2026-11-21 user:1 user:2 user:3
PFCOUNT visitors:2026-11-21
PFMERGE visitors:week visitors:2026-11-15 visitors:2026-11-21

Common mistakes

  • Using Bloom filters where false positives are unacceptable without a follow-up check.
  • Undersizing filters (false-positive rate explodes).
  • Expecting deletions from a standard Bloom filter.

How to answer in the interview

"They trade exact answers for very small memory. A Bloom filter tells me an item is definitely not in a set or probably is, so LSM databases skip disk reads and crawlers skip seen URLs. HyperLogLog counts unique users in about 12 KB with around 1% error, and Count-Min Sketch estimates frequencies for trending or heavy hitters. All are mergeable, which suits sharded systems."

Likely follow-up questions

  • Size a Bloom filter? ~9.6 bits/item for 1% FP; formula above.
  • Delete support? Counting Bloom or cuckoo filters.
  • Cache penetration? Bloom filter of existing keys before hitting the DB.
