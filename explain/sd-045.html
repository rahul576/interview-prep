Design a Pastebin-like service where users share text snippets by link.

Classic Design Problems · design · levels entry

In one line

Pastebin needs a unique short key per paste, content in object storage with metadata in a DB, caching/CDN for the read-heavy traffic, TTL-based expiry, and rate limiting and abuse controls.

Detailed explanation

It's a warm-up problem; interviewers judge structure and trade-offs more than cleverness.

Keys: 7–8 base62 characters (62^7 ≈ 3.5 trillion) from a random generator with a collision check, or from an ID generator (Snowflake → base62). Random keys make unlisted pastes hard to guess.

Storage: pastes can be MBs; put the text in object storage (S3) under the key, and metadata (key, owner, created, expires_at, size, visibility, syntax) in a DB. Small pastes could live in the DB directly; mention the threshold trade-off.

Reads: maybe 10:1 vs writes; popular pastes cached in Redis and at a CDN (Cache-Control respects visibility and expiry).

Expiry: checked on read; a background job deletes expired objects and rows (or use S3 lifecycle rules + DB TTL indexes).

Abuse: size limits, rate limits per IP/account, malware/phishing scanning, takedown flow.

How it works

  1. POST /pastes {content, expiry, visibility} → generate key → upload to S3 → insert metadata → return URL.
  2. GET /{key} → cache → metadata check (exists, not expired, visible) → content from cache/S3/CDN.
  3. Cleanup job for expired pastes.

Example

Estimate: 1M new pastes/day ≈ 12 writes/s; 10M reads/day ≈ 120 reads/s
Avg 10 KB → 10 GB/day → ~3.6 TB/year in object storage

Common mistakes

  • Sequential, guessable IDs for private/unlisted content.
  • Storing large blobs in the relational DB.
  • Caching pastes past their expiry or after deletion.

How to answer in the interview

"I'd generate a random 7-character base62 key, store content in object storage and metadata in a database. Reads dominate, so popular pastes are cached in Redis and served through a CDN. Expiry is enforced on read and by a cleanup job. Rate limits, size caps and content scanning prevent abuse."

Likely follow-up questions

  • Syntax highlighting? Client-side, or precompute HTML once on write and store it.
  • Custom aliases? Unique constraint on alias, reserved words list.
  • Analytics? View events to a queue, aggregated asynchronously.
