Retrieval finds the right document, but the model still answers incorrectly or ignores it. What do you do?

LLMOps & RAG · scenario · levels mid, senior

In one line

Inspect the exact prompt the model received: fix weak or buried instructions, too much irrelevant context, truncated chunks, and the model preferring training knowledge; use clearer grounding instructions, better context ordering, few-shot examples, a stronger model, groundedness checks and new evaluation cases.

Detailed explanation

When retrieval is right but the answer is wrong, the failure is in generation, and the first step is to look at the fully assembled prompt for the failing cases, not the template.

Common causes:

  • Instructions. The system prompt does not clearly say "answer only from the provided sources", contradicts itself, or is so long that the grounding rule is buried among tone and formatting rules.
  • Distracting context. The right chunk is there among 15 others; similar-looking but irrelevant chunks lead the model to the wrong passage. Long contexts also make information in the middle easier to overlook.
  • Truncation. The chunk was cut before the crucial sentence ("...except for employees in Germany, who"), or the prompt builder truncated context to fit a token budget, dropping the last chunk.
  • Prior knowledge. The document contradicts what the model learned in training (an internal definition, a new policy, an updated price), and the model trusts its prior.
  • Task difficulty. The answer requires combining numbers or conditions across chunks, which smaller models get wrong.

Fixes: rewrite instructions so grounding comes first and is explicit, including what to do when sources conflict (prefer the most recent) and when they are insufficient; send fewer chunks, ordered with the most relevant nearest the question; repair chunking or expand to the parent section; add few-shot examples showing source-faithful answers; try a stronger model or reasoning mode for complex cases; and add a groundedness check after generation.

How it works

  1. Log full prompts and outputs for failing cases.
  2. Confirm the needed fact is present and complete in the context.
  3. Classify cause: instructions, noise, truncation, prior knowledge, reasoning.
  4. Apply the targeted fix.
  5. Add the cases to the evaluation set; compare versions.

Example

SYSTEM
You answer questions using ONLY the sources below.
- If sources conflict, prefer the one with the latest effective date.
- If the sources do not contain the answer, say "I can't find this in our documents."
- Cite sources as [S1], [S2] after each claim.

SOURCES
[S1] (Expense policy v2026-09, effective 2026-10-01) ...
[S2] ...

QUESTION
Can I expense a taxi after 9 pm?

Common mistakes

  • Debugging the template instead of the real assembled prompt.
  • Assuming more context always helps.
  • Blaming the model without checking truncation.
  • Fixing one case without adding it to the evaluation set.

How to answer in the interview

"I'd look at the exact prompt the model saw for those cases. Typical issues: grounding instructions are weak or buried in a long system prompt; the right chunk is surrounded by many irrelevant ones that distract the model; the chunk is cut off before the key sentence; or the document contradicts what the model believes from training. Fixes are clear instructions to answer only from sources and how to handle conflicts, fewer and better-ordered chunks, chunking repairs, few-shot examples, a stronger model for complex reasoning, and a groundedness check that flags unsupported answers. Every case goes into the evaluation set."

Likely follow-up questions

  • Retrieval vs generation failure at scale? Score context recall and faithfulness separately: if the expected chunk was retrieved but the answer is unfaithful, it's generation.
  • Conflicting sources? Rules in the prompt plus version metadata to filter.
  • Does a bigger model fix it? Often helps reasoning, but not noise or truncation.
