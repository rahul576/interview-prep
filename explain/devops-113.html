How does Kubernetes scheduling work? Explain node selectors, affinity, taints and tolerations.

Kubernetes · concept · levels mid, senior

In one line

The scheduler filters nodes that can run a pod (resource requests, ports, volumes, nodeSelector/affinity, taints) and scores the rest; node affinity attracts pods to labelled nodes, pod (anti-)affinity and topology spread constraints co-locate or spread replicas, and taints repel pods unless they have matching tolerations.

Detailed explanation

For each pending pod, kube-scheduler runs two phases. Filtering removes nodes that cannot run it: not enough allocatable CPU or memory after existing requests, host port conflicts, volume zone constraints, a nodeSelector or required affinity that does not match, or a taint the pod does not tolerate. Scoring ranks the remaining nodes with plugins (spreading load, image locality, preferred affinities, topology spread), and the pod is bound to the best one. If no node passes filtering, the pod stays Pending with an event explaining why, and a node autoscaler may add capacity.

nodeSelector and node affinity. nodeSelector is a simple label match (gpu: "true"). Node affinity is more expressive: requiredDuringSchedulingIgnoredDuringExecution (hard) and preferredDuringScheduling… (soft, weighted), with operators like In, NotIn, Exists. Use it for hardware (GPU, ARM), zones or node pools.

Pod affinity and anti-affinity place pods relative to other pods by label within a topology key (node, zone). Affinity co-locates (cache next to app); anti-affinity separates (no two replicas on one node). Topology spread constraints are usually better for spreading: maxSkew: 1 across topology.kubernetes.io/zone keeps replicas evenly distributed, with whenUnsatisfiable choosing hard or soft behaviour.

Taints and tolerations work the other way round: a node taint (dedicated=gpu:NoSchedule) repels all pods except those with a matching toleration. Effects are NoSchedule, PreferNoSchedule and NoExecute (also evicts running pods). Kubernetes itself taints nodes that are not ready or under pressure.

Priority and preemption let important pods evict lower-priority ones when no node fits.

How it works

  1. Pod created without nodeName.
  2. Filter: requests fit, selectors/affinity match, taints tolerated.
  3. Score: spread, preferences, image locality.
  4. Bind to highest-scoring node; kubelet starts it.
  5. None fit → Pending; preemption or autoscaling may help.

Example

spec:
  tolerations:
    - { key: dedicated, operator: Equal, value: gpu, effect: NoSchedule }
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
          - matchExpressions: [{ key: accelerator, operator: In, values: [nvidia-l4] }]
  topologySpreadConstraints:
    - maxSkew: 1
      topologyKey: topology.kubernetes.io/zone
      whenUnsatisfiable: DoNotSchedule
      labelSelector: { matchLabels: { app: inference } }

Common mistakes

  • Using only a toleration and expecting pods to land on the tainted nodes.
  • Hard anti-affinity with more replicas than nodes, leaving pods Pending.
  • Missing requests, so the scheduler packs nodes badly.
  • Forgetting that IgnoredDuringExecution means label changes don't move running pods.

How to answer in the interview

"The scheduler first filters nodes that can run the pod, based on resource requests, ports, volumes, selectors and taints, then scores the rest and binds to the best one. nodeSelector and node affinity attract pods to nodes with certain labels, like GPU nodes, with hard or soft rules. Pod anti-affinity and topology spread constraints spread replicas across nodes and zones for availability, while pod affinity co-locates pods. Taints on nodes repel pods unless they have matching tolerations, which is how you dedicate nodes, like a system or GPU pool. If nothing fits, the pod stays Pending and the event tells you why."

Likely follow-up questions

  • Why should GPU nodes use both taints and node affinity? The taint keeps other pods off; the affinity makes GPU pods go there; a toleration alone only permits.
  • Spread constraints or anti-affinity? Spread constraints give even distribution with skew control and scale better.
  • What does NoExecute do? Evicts running pods without a toleration, optionally after tolerationSeconds.
