What switch-related enhancements were introduced in newer Java versions?

Modern Java (11-21) · concept · levels entry, mid

In one line

Switch expressions (Java 14) return a value with arrow labels, no fall-through, multiple labels and yield; pattern matching for switch (Java 21) adds type patterns, record patterns, when guards, case null and exhaustiveness checks.

Detailed explanation

The classic switch statement had well-known problems: forgetting break caused accidental fall-through, it could not return a value, and it only worked with primitives, strings and enums.

Switch expressions (standard in Java 14) fix the first two. With case X -> there is no fall-through; several constants can share a label (case SAT, SUN ->); and the whole switch is an expression you can assign or return. If a branch needs several statements, use a block and yield the value. A switch expression must be exhaustive: for enums either cover all constants or add default. The arrow form can also be used in ordinary switch statements.

Pattern matching for switch (standard in Java 21) lets you switch on any object and match on its type: case String s ->, case Integer i ->. You can add guards with when: case Integer i when i > 100 ->. Record patterns deconstruct records inline: case Point(int x, int y) ->. A case null branch handles nulls explicitly; without it, a null selector still throws NullPointerException as before. Case order matters: a more general pattern before a specific one is a compile error ("dominated" label).

Over sealed types and enums, the compiler checks exhaustiveness, so you can omit default and get a compile error when a new subtype appears. Java 22 also added the unnamed pattern _ for components you do not need.

How it works

  1. Selector is evaluated once.
  2. Labels are tested top to bottom: constants, types, then guards.
  3. First match runs; arrow form never falls through.
  4. Expression form yields a value; compiler checks exhaustiveness.

Example

int days = switch (month) {
    case FEBRUARY -> 28;
    case APRIL, JUNE, SEPTEMBER, NOVEMBER -> 30;
    default -> 31;
};

String grade = switch (score / 10) {
    case 10, 9 -> "A";
    case 8 -> { log("B grade"); yield "B"; }
    default -> "C";
};

String describe(Object o) {
    return switch (o) {
        case null -> "null";
        case Integer i when i > 100 -> "big int " + i;
        case Integer i -> "int " + i;
        case String s -> "string of " + s.length();
        case Point(int x, int y) -> "point " + x + "," + y;
        default -> "other";
    };
}

Common mistakes

  • Mixing : and -> labels in one switch (not allowed).
  • Using return instead of yield inside a switch-expression block.
  • Putting case Integer i before case Integer i when ... (dominated label).
  • Adding default over sealed types and losing exhaustiveness checks.

How to answer in the interview

"Java 14 made switch an expression. Arrow labels don't fall through, so no break, several labels can share a case, and the switch returns a value, using yield when a branch needs a block. Java 21 added pattern matching for switch: I can switch on any object, match on types like case String s, add guards with when, handle case null explicitly and deconstruct records with record patterns. Over enums and sealed types the compiler checks exhaustiveness, so I can drop default and the build fails when a new subtype is added. That removes a whole class of missing-case and fall-through bugs."

Likely follow-up questions

  • What does yield do in a switch expression? Returns a value from a block branch of the switch expression.
  • What happens if the selector is null? NullPointerException unless there is a case null.
  • What is a dominated case label? A label that can never match because an earlier one already covers it; it's a compile error.
