What is the difference between EntityManager and Session?

Spring Data & JPA · concept · levels entry, mid

In one line

Both represent a persistence context / unit of work: EntityManager is the standard JPA interface, Session is Hibernate's native API, which since Hibernate 5.2 extends EntityManager and adds extra features; in Spring you inject the EntityManager and unwrap(Session.class) when you need Hibernate specifics.

Detailed explanation

An EntityManager (JPA) and a Session (Hibernate) are the same concept: a short-lived object, usually one per transaction, that holds the persistence context (first-level cache of managed entities), tracks changes through dirty checking, and flushes them to the database. Both are created by a factory: EntityManagerFactory and Hibernate's SessionFactory (which extends EntityManagerFactory).

EntityManager is the portable API defined by Jakarta Persistence: persist, merge, find, getReference, remove, flush, clear, detach, refresh, lock, createQuery/createNamedQuery/createNativeQuery, getCriteriaBuilder and entity graphs. Code written against it works with any provider.

Session predates JPA. In modern Hibernate, Session extends EntityManager, so everything above is available, plus Hibernate-specific capabilities: natural-id loading (bySimpleNaturalId), filters (enableFilter), multi-load by ids (byMultipleIds), fine-grained FlushMode and CacheMode, setJdbcBatchSize, doWork for raw JDBC access, and fetch profiles. Legacy methods like save, update and saveOrUpdate were deprecated in Hibernate 6 and removed in 7 in favour of the JPA-style persist and merge. For bulk processing, Hibernate also provides StatelessSession, which has no persistence context.

In a Spring application you normally inject the EntityManager with constructor injection or @PersistenceContext. What you receive is a shared, thread-safe proxy: the actual EntityManager is not thread-safe, but the proxy delegates each call to the EntityManager bound to the current transaction and thread. When you need a Hibernate feature, call entityManager.unwrap(Session.class) inside a transaction. Avoid opening sessions manually from the SessionFactory, which bypasses Spring's transaction management.

How it works

  1. Spring Boot creates an EntityManagerFactory backed by Hibernate's SessionFactory.
  2. Beans receive a shared EntityManager proxy.
  3. A transaction begins; a real Session/EntityManager is bound to the thread.
  4. Proxy calls go to that instance; unwrap returns the underlying Session.
  5. Commit flushes and closes it.

Example

@Repository
class BookDao {
    private final EntityManager em;              // shared, thread-safe proxy
    BookDao(EntityManager em) { this.em = em; }

    @Transactional(readOnly = true)
    public Book byIsbn(String isbn) {
        Session session = em.unwrap(Session.class);   // Hibernate-specific API
        return session.bySimpleNaturalId(Book.class).load(isbn);
    }

    @Transactional
    public void archiveOld(Instant cutoff) {
        em.createQuery("update Book b set b.archived = true where b.published < :c")
          .setParameter("c", cutoff)
          .executeUpdate();                       // portable JPA
    }
}

Common mistakes

  • Thinking they are different persistence mechanisms.
  • Sharing a real EntityManager across threads.
  • Opening Sessions manually and bypassing Spring transactions.
  • Calling unwrap outside a transaction and getting an unbound or new instance.

How to answer in the interview

"Both represent a persistence context, a unit of work that tracks managed entities in a first-level cache and flushes changes. EntityManager is the standard JPA interface with persist, merge, find, remove and createQuery, so it's portable. Session is Hibernate's native API that predates JPA; in modern Hibernate it extends EntityManager and adds things like natural-id loading, filters and finer control of flush and batching. In Spring I inject the EntityManager and call unwrap(Session.class) only when I need a Hibernate-specific feature."

Likely follow-up questions

  • Is EntityManager thread-safe? No; Spring injects a shared proxy that delegates to the transaction-bound instance.
  • SessionFactory vs EntityManagerFactory? SessionFactory extends EntityManagerFactory; one per database.
  • StatelessSession? A Hibernate API without persistence context, for bulk operations.
