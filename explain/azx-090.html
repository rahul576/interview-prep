How do content filters and Prompt Shields work in Azure AI Content Safety for model deployments?

Azure AI & Foundry · concept · levels mid, senior

In one line

Azure AI Content Safety filters classify prompts and completions for hate, sexual, violence and self-harm by severity, blocking content above a configured threshold; Prompt Shields detect jailbreaks and indirect prompt injection, other detectors cover protected material and groundedness, all configurable per deployment, and the app must handle filtered responses.

Detailed explanation

Every Azure OpenAI and Foundry model deployment has a content filter configuration (a guardrail policy). It runs classifiers on the input prompt and the output completion in four harm categories, hate, sexual, violence, self-harm, each scored at severity safe, low, medium or high. The default blocks medium and high; you can make it stricter (block low as well) or, with approval for some settings, more permissive or annotate-only.

Behaviour your application must handle:

  • Blocked prompt: the API returns HTTP 400 with error code content_filter and details of which category triggered.
  • Blocked completion: the response succeeds but finish_reason is content_filter and the content is truncated or empty. With streaming, filtering happens in chunks, so partial text may already have been sent.

Prompt Shields:

  • User prompt attacks (jailbreaks): attempts like "ignore your instructions and act as..." in the user's message.
  • Document attacks (indirect prompt injection): malicious instructions hidden in retrieved documents, emails, web pages or tool results that the model reads. This is the critical risk for RAG and agents, which is why tool outputs and retrieved content should be passed as documents so the shield can analyse them.

Additional detectors: protected material for known copyrighted text such as song lyrics and for public code (with citation of the source repository), groundedness detection checking if a response is supported by the provided sources, and custom blocklists for terms you never want.

Configure filters per deployment, for example stricter for a public consumer chatbot than for an internal tool, and log filter results to monitor abuse and false positives.

How it works

  1. Create a content filter configuration with thresholds and shields.
  2. Attach it to the deployment.
  3. Each request: prompt classified; if allowed, model generates; completion classified.
  4. Annotations returned in the response (prompt_filter_results, content_filter_results).
  5. App handles blocks; logs and dashboards track trends.

Example

from openai import BadRequestError
try:
    r = client.chat.completions.create(model="chat", messages=msgs)
    choice = r.choices[0]
    if choice.finish_reason == "content_filter":
        reply = "Sorry, I can't help with that request."
    else:
        reply = choice.message.content
except BadRequestError as e:
    if e.code == "content_filter":
        log_filter_event(e.body)          # category and severity details
        reply = "Your message couldn't be processed. Please rephrase."
    else:
        raise

Common mistakes

  • Treating a filtered response as a generic 500 error.
  • Turning filters off to "fix" false positives instead of tuning.
  • Concatenating retrieved documents into the user message, hiding them from document shields.
  • Not monitoring filter rates, missing abuse patterns.

How to answer in the interview

"Deployments use Azure AI Content Safety. Filters classify prompts and completions for hate, sexual, violence and self-harm at different severities and block anything above the threshold; a blocked prompt returns a 400 and a blocked completion returns finish reason content_filter, which the app must handle gracefully. Prompt Shields catch jailbreaks in user prompts and indirect prompt injection in documents or tool results. There are also protected material and groundedness detectors. I configure filters per deployment and log results to watch abuse and false positives."

Likely follow-up questions

  • How should the app respond to a filtered completion? A polite, neutral message, no raw error, optionally offer to rephrase.
  • Does the shield stop all prompt injection? No; also use least-privilege tools and human approval for risky actions.
  • Streaming effect? Content may arrive before a later chunk is filtered; handle mid-stream stops.
