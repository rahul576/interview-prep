What does Azure API Management provide, and how is it used as an AI gateway?

Azure · concept · levels mid, senior

In one line

Azure API Management (APIM) is a managed gateway, developer portal and management plane: products, subscriptions, versions and revisions, plus XML policies for JWT validation, rate limits, transformation and caching; as an AI gateway it adds token-based limits, load balancing and failover across model deployments, semantic caching, token metrics and content safety for LLM APIs.

Detailed explanation

APIM has three parts: the gateway that proxies calls (managed in Azure, or the self-hosted gateway container in Kubernetes or on-premises), the management plane (APIs defined from OpenAPI, configuration as code), and the developer portal where consumers discover APIs and get keys. APIs are grouped into products, consumers get subscription keys per product, and versions (v1, v2) and revisions (non-breaking changes you can test before making current) evolve APIs safely.

Policies run in inbound, backend, outbound and on-error sections at global, product, API or operation scope: validate-jwt (Entra ID tokens), rate-limit-by-key and quota-by-key, set-header, rewrite-uri, JSON/XML transformations, cache-lookup/store, ip-filter, authentication-managed-identity to call backends without secrets, and backend circuit breakers and load-balanced pools. Tiers range from Consumption to Developer, Basic/Standard/Premium and the newer v2 tiers with VNet integration.

As an AI gateway in front of Azure OpenAI / Azure AI Foundry models or other LLM endpoints:

  • Token limits (llm-token-limit / azure-openai-token-limit) enforce tokens-per-minute and quotas per subscription, team or app, rather than just request counts.
  • Backend pools load-balance across deployments and regions with priorities and weights, and circuit breakers honour 429 and Retry-After, so traffic can use provisioned throughput (PTU) first and spill over to pay-as-you-go.
  • Semantic caching returns cached completions for similar prompts using embeddings and Redis.
  • Token metric emission sends prompt and completion token counts with dimensions to Application Insights for chargeback.
  • Content safety policies and managed identity auth to the models.

How it works

  1. Import API from OpenAPI or the Azure OpenAI resource.
  2. Configure backends or a backend pool with priorities.
  3. Inbound: validate JWT, apply token limits, semantic cache lookup.
  4. Forward to the selected backend with managed identity.
  5. Outbound: cache store, emit token metrics.
  6. Consumers subscribe via products; monitor usage.

Example

<inbound>
  <base />
  <validate-jwt header-name="Authorization" failed-validation-httpcode="401">
    <openid-config url="https://login.microsoftonline.com/{tenant}/v2.0/.well-known/openid-configuration" />
  </validate-jwt>
  <llm-token-limit counter-key="@(context.Subscription.Id)"
                   tokens-per-minute="20000" estimate-prompt-tokens="true" />
  <llm-emit-token-metric namespace="genai">
    <dimension name="Team" value="@(context.Subscription.Name)" />
  </llm-emit-token-metric>
  <set-backend-service backend-id="openai-pool" />
</inbound>

Common mistakes

  • Rate limiting by request count for LLMs, where token usage varies hugely.
  • Passing API keys of model deployments to clients instead of using managed identity.
  • No retry/failover on 429 from model endpoints.
  • Editing policies in the portal without source control (use APIOps).

How to answer in the interview

"API Management is a managed gateway with a developer portal and management plane. I group APIs into products with subscription keys, evolve them with versions and revisions, and use policies for JWT validation, rate limits and quotas, transformations, caching and managed identity calls to backends. As an AI gateway in front of Azure OpenAI or other models, it enforces token-based limits per team, load-balances across deployments and regions with PTU first and spillover to pay-as-you-go, caches semantically similar prompts, emits token metrics for chargeback and applies content safety. That makes it the single control point for enterprise LLM use."

Likely follow-up questions

  • Fair token budgets per team? Token limit policy keyed by subscription or team claim, plus quotas.
  • Versions vs revisions? Versions are breaking and visible to consumers; revisions are non-breaking changes.
  • Self-hosted gateway use? Low latency and data locality for on-premises or multi-cloud APIs.
