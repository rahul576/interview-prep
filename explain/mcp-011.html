What is the prompts primitive in MCP, and how is it used?

MCP Servers · concept · levels entry, mid

In one line

Prompts are reusable, parameterised message templates that a server offers; clients discover them with prompts/list and fetch them with prompts/get plus arguments, and they are user-controlled, typically surfaced as slash commands.

Detailed explanation

Server authors know which workflows work best with their system: how to review a pull request using their GitHub tools, how to summarise an incident from their alerting data, how to write a good SQL query against their warehouse. Prompts let them ship that knowledge as ready-made templates rather than hoping each user phrases a good request.

A client calls prompts/list (paginated) and receives, for each prompt, a name, optional title, a description and an arguments list, where each argument has a name, description and required flag. When the user picks one, the client calls prompts/get with the prompt name and argument values. The server returns a list of messages (with user or assistant roles) ready to send to the model. Messages can contain text, images, audio and embedded resources, so a /review-pr prompt can embed the actual diff, or an /incident-summary prompt can embed recent alert logs.

Prompts are user-controlled. Hosts present them as slash commands, menu entries or buttons, and the user explicitly decides to use one; the model does not invoke prompts on its own. Hosts can use argument completion (completion/complete) to suggest values like repository or incident ids. Servers that support listChanged notify clients when the prompt set changes.

Prompts carry lower risk than tools because nothing executes automatically. However, servers should still validate arguments, since user-provided values and embedded resource content end up in the model's context and could carry injected instructions or sensitive data.

How it works

  1. Server declares the prompts capability.
  2. Client calls prompts/list and shows entries as slash commands.
  3. User selects one and fills arguments (with completion help).
  4. Client calls prompts/get; server validates arguments and builds messages, embedding resources if useful.
  5. Host inserts the messages into the conversation and the model responds, possibly calling tools.

Example

from mcp.server.fastmcp import FastMCP
mcp = FastMCP("incidents")

@mcp.prompt(title="Summarise incident")
def incident_summary(incident_id: str, audience: str = "engineering") -> str:
    """Summarise an incident for the given audience."""
    if not incident_id.startswith("INC-"):
        raise ValueError("incident_id must look like INC-1234")
    timeline = incidents.timeline(incident_id)
    return (f"Write a concise summary of {incident_id} for a {audience} audience. "
            f"Cover impact, root cause, timeline and follow-ups.\n\nTimeline:\n{timeline}")

The host shows this as /incident_summary with two arguments.

Common mistakes

  • Using prompts for actions; prompts only produce messages.
  • Expecting the model to discover and call prompts by itself.
  • Embedding huge resources without trimming.
  • Not validating arguments that end up in model context.

How to answer in the interview

"Prompts are reusable, parameterised message templates that a server offers, capturing workflows the server author knows work well. The client lists them with prompts/list, which returns names, descriptions and arguments, and fetches one with prompts/get and argument values; the server returns messages ready for the model, which can embed resources like a diff or log excerpt. They're user-controlled, usually shown as slash commands such as /review-pr, and the user decides when to use them. They're lower risk than tools since nothing runs automatically, but the server should still validate arguments because they end up in the model's context."

Likely follow-up questions

  • Why ship prompts instead of documentation? Users get a tested workflow in one click, with live data embedded.
  • Can prompts call tools? Not directly, but the resulting conversation can lead the model to call tools.
  • Do all hosts support prompts? No; support varies, so do not rely on them for essential functionality.
