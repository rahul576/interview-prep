What is the Spring Framework?

Spring Framework · concept · levels entry, mid

In one line

Spring is an open-source framework for enterprise Java whose core is an IoC container providing dependency injection, plus AOP for cross-cutting concerns and modules for web (MVC, WebFlux), data access, transactions, security and messaging, letting you build loosely coupled, testable applications from POJOs.

Detailed explanation

Spring appeared in 2003 as a reaction to the heavyweight EJB 2 model, where business objects had to implement container interfaces, needed XML deployment descriptors and could hardly be tested outside an application server. Rod Johnson's idea was that ordinary Java objects (POJOs) plus a lightweight container could provide the same enterprise services.

Core container: the ApplicationContext creates objects called beans, wires their dependencies (dependency injection) and manages their lifecycle. Classes depend on interfaces, the container supplies implementations, and in tests you pass mocks directly. This is inversion of control: the framework, not your code, assembles the application.

AOP: cross-cutting concerns such as transactions, security, caching and logging are applied through proxies around beans. That is how @Transactional begins and commits a transaction without any transaction code in your method.

Modules built on this core:

  • Web: Spring MVC (servlet-based, blocking) and Spring WebFlux (reactive, non-blocking).
  • Data access: JdbcTemplate/JdbcClient, ORM integration with JPA/Hibernate, a consistent DataAccessException hierarchy, and the separate Spring Data projects for repositories.
  • Transactions: declarative, technology-independent transaction management.
  • Testing: the TestContext framework, MockMvc.
  • Integration: messaging (JMS, AMQP, Kafka via Spring for Apache Kafka), scheduling, caching, validation.

Around the framework is a large ecosystem: Spring Boot (auto-configuration, embedded server, production features), Spring Security, Spring Data, Spring Cloud, Spring Batch, Spring Integration, Spring AI and more. Current generations are Spring Framework 6.x with Boot 3.x on Java 17+, and Framework 7 with Boot 4, released in late 2025.

How it works

  1. You write POJOs and declare them as beans with annotations or @Bean methods.
  2. The container reads the configuration and creates and wires the beans.
  3. Post-processors add proxies for transactions, security and caching.
  4. Framework modules (MVC, data) plug into the container as beans too.
  5. The container manages startup and shutdown.

Example

public interface PaymentGateway { void charge(String customer, BigDecimal amount); }

@Service
class CheckoutService {
    private final PaymentGateway gateway;
    private final OrderRepository orders;

    CheckoutService(PaymentGateway gateway, OrderRepository orders) {   // injected by Spring
        this.gateway = gateway;
        this.orders = orders;
    }

    @Transactional   // AOP proxy handles begin/commit/rollback
    public void checkout(Order order) {
        orders.save(order);
        gateway.charge(order.customer(), order.total());
    }
}

// Test without any container
var service = new CheckoutService(mock(PaymentGateway.class), mock(OrderRepository.class));

Common mistakes

  • Saying Spring and Spring Boot are the same thing.
  • Describing Spring only as a "web framework".
  • Mentioning only annotations and not explaining IoC and DI.
  • Creating beans with new, losing injection and proxies.

How to answer in the interview

"Spring is an open-source framework for building enterprise Java applications. Its core is the IoC container, which creates objects called beans and wires them together through dependency injection, so my classes depend on interfaces, stay loosely coupled and are easy to test as plain POJOs. AOP handles cross-cutting concerns like transactions, security and logging through proxies, which is why @Transactional works without boilerplate. Around that core there are modules for web with Spring MVC and WebFlux, data access, declarative transactions, messaging and testing, and the ecosystem adds Spring Security, Spring Data and Spring Boot, which builds on it with auto-configuration and embedded servers."

Likely follow-up questions

  • What problem did Spring originally solve compared with EJB? Heavy container-bound components that were hard to test; Spring offered the same services for POJOs with a lightweight container.
  • Spring vs Spring Boot? Boot is an opinionated layer that auto-configures Spring and packages it as a runnable app.
  • What is a bean? An object created and managed by the Spring container.
