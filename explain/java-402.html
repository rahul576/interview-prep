How would you find the second-highest salary, or the top N per department, in SQL?

Databases & SQL · concept · levels entry, mid

In one line

Use window functions: DENSE_RANK() OVER (ORDER BY salary DESC) and filter rank = 2 for the second-highest salary, and add PARTITION BY department with rank <= N for top N per department, deciding explicitly how to treat ties and NULLs.

Detailed explanation

The classic answer for the second-highest salary is a subquery: the maximum salary below the overall maximum. It works, but does not generalise to "third" or "top N per group".

Window functions do. They compute a value for each row over a set of related rows without collapsing them. The three ranking functions differ on ties:

  • ROW_NUMBER gives 1, 2, 3 even for equal values, picking an arbitrary order among ties unless you add a tie-breaker.
  • RANK gives ties the same rank and then skips: 100, 100, 90 become 1, 1, 3.
  • DENSE_RANK gives ties the same rank without gaps: 1, 1, 2.

For "second-highest salary value", DENSE_RANK is correct, because if two people earn the top salary, the second-highest value is still the next distinct amount. For "exactly N people per department", ROW_NUMBER with a deterministic tie-breaker is right. Because window functions are evaluated after WHERE, you filter on the rank in an outer query or CTE (or with QUALIFY in databases that support it, such as Snowflake or BigQuery).

NULL salaries sort first or last depending on the database, so filter them out or use NULLS LAST.

How it works

  1. Choose the ranking function based on how ties should behave.
  2. Define the window: PARTITION BY the group, ORDER BY the measure descending.
  3. Compute the rank in a CTE or derived table.
  4. Filter the rank in the outer query.
  5. Handle NULLs and add a tie-breaker column if needed.

Example

-- Second-highest distinct salary
SELECT DISTINCT salary FROM (
  SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
  FROM employee WHERE salary IS NOT NULL
) t WHERE rnk = 2;

-- Subquery alternative
SELECT MAX(salary) FROM employee
WHERE salary < (SELECT MAX(salary) FROM employee);

-- Top 3 earners per department
WITH ranked AS (
  SELECT e.*, DENSE_RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rnk
  FROM employee e
)
SELECT dept_id, name, salary FROM ranked WHERE rnk <= 3;

Common mistakes

  • Using LIMIT 1 OFFSET 1 without DISTINCT, which returns the top salary again when there is a tie.
  • Filtering on the window alias directly in WHERE, which fails because windows run later.
  • Using ROW_NUMBER when the requirement is "salary values", silently dropping ties.
  • Forgetting that the query should return NULL or nothing when there is no second salary.

How to answer in the interview

"For the second-highest salary I can use a subquery, max salary less than the max, but my general approach is a window function. I compute DENSE_RANK over salary descending in a CTE and select where the rank is two, which handles ties correctly. For top N per department I add PARTITION BY department and filter rank less than or equal to N. The choice of function matters: ROW_NUMBER gives unique numbers and drops ties arbitrarily, RANK leaves gaps after ties, and DENSE_RANK doesn't. I also exclude NULL salaries and confirm with the interviewer how ties should be treated."

Likely follow-up questions

  • RANK vs DENSE_RANK? Both share ranks on ties; RANK leaves gaps afterwards, DENSE_RANK does not.
  • Why can't you filter a window function in WHERE? Window functions are evaluated after WHERE, GROUP BY and HAVING.
  • How do you get the latest order per customer? ROW_NUMBER partitioned by customer ordered by date descending, keep row 1.
