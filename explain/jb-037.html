What is the difference between List, Set, and Map?

Collections · concept · levels entry, mid

In one line

A List is an ordered, indexed collection that allows duplicates, a Set holds unique elements, and a Map stores key-value pairs with unique keys; choose by access pattern.

Detailed explanation

A List keeps elements in a sequence, usually insertion order, and lets you read or write by position: get(2), add(0, x). Duplicates are fine. ArrayList is the default; it is ideal for things like the line items of an order or the rows of a report, where position and repeats matter.

A Set models a mathematical set: adding an element that is already present is a no-op and add returns false. Duplicates are detected with equals/hashCode (or compareTo for TreeSet). The variants differ in order: HashSet has no order and O(1) average operations, LinkedHashSet keeps insertion order, and TreeSet keeps sorted order with O(log n). A set suits user roles, tags or "already processed ids".

A Map associates keys with values. Keys are unique (putting an existing key replaces the value), values may repeat. Its strength is fast lookup by key: HashMap for O(1) average, LinkedHashMap for insertion order or LRU, TreeMap for sorted keys. Typical use: product id → product, or word → count. Map is not a Collection, but keySet() is a Set and values() is a Collection.

So the decision is: if you need positional access or duplicates, use a List; if you need uniqueness or fast "contains", use a Set; if you look things up by an identifier, use a Map.

How it works

  1. List: elements stored by index; contains is O(n) on ArrayList.
  2. Set: add checks for an equal element first.
  3. Map: put(k, v) hashes or compares the key and stores or replaces the value.
  4. Ordering depends on the implementation, not the interface.

Example

List<String> items = new ArrayList<>(List.of("pen", "pen", "book")); // duplicates ok
Set<String> roles = new HashSet<>(Set.of("ADMIN", "USER"));
roles.add("ADMIN");                                   // ignored, returns false
Map<Long, Product> byId = new HashMap<>();
byId.put(42L, product);
Product p = byId.get(42L);                            // O(1) lookup

// Latest 100 unique search terms, in order:

Common mistakes

  • Using list.contains in a loop for de-duplication (O(n²)).
  • Forgetting equals/hashCode on custom elements in a Set or Map key.
  • Assuming HashSet or HashMap keep insertion order.
  • Calling Map a Collection.

How to answer in the interview

"A List is ordered, allows duplicates and supports index access, like the line items of an order in an ArrayList. A Set keeps only unique elements; HashSet has no order, LinkedHashSet keeps insertion order and TreeSet keeps it sorted, which fits something like a user's roles. A Map stores key-value pairs with unique keys and fast lookup by key, like a HashMap from product id to product. I choose by access pattern: positions and duplicates mean a list, uniqueness means a set, lookup by key means a map."

Likely follow-up questions

  • Latest 100 unique search terms in order? A LinkedHashSet (or LinkedHashMap) with remove-then-add and evicting the first.
  • How does a Set detect duplicates? hashCode then equals, or compareTo for TreeSet.
  • Can a Map have null keys? HashMap one; TreeMap and ConcurrentHashMap no.
