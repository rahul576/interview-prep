What is reinforcement learning, and where is it used in practice today?

AI/ML & GenAI · concept · levels mid, senior

In one line

In reinforcement learning an agent learns a policy by acting in an environment and maximising cumulative reward, balancing exploration and exploitation; today it powers games, robotics, bidding and, above all, RLHF and RL-trained reasoning in language models.

Detailed explanation

Unlike supervised learning, there are no correct labels per input. The agent observes a state, takes an action, receives a reward and a new state, and learns which actions maximise the discounted sum of future rewards, not just the immediate one. The problem is formalised as a Markov decision process. Key ideas: a value function estimates how good a state or action is long term; a policy maps states to actions. Value-based methods (Q-learning, DQN) learn action values; policy-gradient methods (REINFORCE, PPO) optimise the policy directly; actor-critic methods combine both.

The exploration versus exploitation trade-off is central: the agent must sometimes try uncertain actions to discover better strategies instead of always repeating what has worked (epsilon-greedy, entropy bonuses). Credit assignment is hard because rewards often arrive long after the actions that caused them.

Practical uses: game playing (AlphaGo, AlphaZero), robotics and control, often trained in simulators then transferred; data centre cooling and industrial control; ads bidding, pricing and recommendations (frequently as simpler contextual bandits). The most influential use today is in language models: RLHF trains a reward model from human preference comparisons and optimises the model against it (PPO, or related preference methods such as DPO that avoid an explicit RL loop), and reinforcement learning with verifiable rewards (correct maths answers, passing unit tests) is a key ingredient in training reasoning models and coding agents. RL needs lots of interaction or a good simulator, and reward design is critical, because agents exploit flawed rewards, known as reward hacking.

How it works

  1. Define states, actions and a reward signal aligned with the true goal.
  2. The agent acts according to its current policy, with some exploration.
  3. The environment returns a reward and next state; transitions are collected.
  4. The algorithm updates value estimates or the policy to favour higher return.
  5. Repeat over many episodes, evaluating the policy and guarding against reward exploits.

Common mistakes

  • Using full RL when a contextual bandit or supervised model would do.
  • Designing a reward proxy that the agent can game.
  • Training only in a simulator and ignoring the sim-to-real gap.
  • Equating RLHF with "the model learns from users live"; it is an offline training stage.

How to answer in the interview

"In RL an agent learns a policy by trial and error: it observes a state, acts, gets a reward and learns to maximise long-term reward. The key challenges are exploration versus exploitation and credit assignment for delayed rewards. It's used in games, robotics with simulators, ad bidding and recommendations, often as bandits. Its biggest impact right now is in LLMs: RLHF aligns models to human preferences, and RL with verifiable rewards like correct answers or passing tests trains reasoning models. Good reward design matters because agents will exploit any loophole."

Likely follow-up questions

  • What is reward hacking? The agent maximises the proxy reward in unintended ways, such as an LLM gaming tests or a judge model.
  • What is a contextual bandit? One-step RL: choose an action given context, observe reward, no long-term state.
  • On-policy versus off-policy? On-policy learns from the current policy's data (PPO); off-policy can reuse old data (Q-learning).
