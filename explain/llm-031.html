How do you evaluate a RAG system?

LLMOps & RAG · concept · levels mid, senior

In one line

Evaluate retrieval and generation separately on a test set of real questions with reference answers and sources: retrieval with recall at k, MRR, nDCG, context precision; generation with faithfulness/groundedness, answer relevance, correctness and correct abstention, scored by calibrated LLM judges (Ragas, DeepEval) plus human review and online feedback.

Detailed explanation

A wrong answer can come from missing documents, bad retrieval, or the model misusing good context, so evaluate the stages separately.

Test set. Collect 100 to a few hundred representative questions: from search logs, support tickets, subject-matter experts, or synthetic generation from documents (reviewed by humans). For each, record the reference answer and the source chunks or documents that contain it. Include hard cases: multi-hop, exact identifiers and questions whose answer is not in the corpus. Version the set and grow it from production failures.

Retrieval metrics (no LLM needed when sources are labelled):

  • Recall at k: share of questions whose relevant chunk is in the top k.
  • MRR: average of 1/rank of the first relevant result.
  • nDCG: rewards relevant results near the top, with graded relevance.
  • Context precision: share of retrieved chunks that are relevant (noise in the prompt).

Generation metrics:

  • Faithfulness / groundedness: every claim in the answer is supported by retrieved context (detects hallucination).
  • Answer relevance: the answer addresses the question.
  • Correctness: agreement with the reference answer.
  • Abstention: says "I don't know" when the answer is absent, and does not refuse when it is present.

LLM-as-judge. Most generation metrics are scored by an LLM with a rubric, using frameworks such as Ragas, DeepEval, TruLens, or cloud evaluators in Azure AI Foundry, Vertex AI and Bedrock. Judges have biases (verbosity, position, self-preference), so calibrate them against a human-labelled sample, use clear rubrics and binary or small scales.

Process. Run the suite in CI on every change to prompts, chunking, embeddings or models, compare against a baseline and block regressions. Online, track thumbs up/down, citation clicks, escalation to human agents, "no answer" rates and retrieval scores.

How it works

  1. Build and version a labelled test set.
  2. Run retrieval; compute recall at k, MRR, nDCG.
  3. Run generation; score faithfulness, relevance, correctness, abstention.
  4. Calibrate judges against human labels.
  5. Gate releases in CI; monitor online signals and feed failures back.

Example

from ragas import evaluate
from ragas.metrics import faithfulness, answer_relevancy, context_precision, context_recall

results = evaluate(dataset=eval_ds,   # question, answer, contexts, reference
                   metrics=[faithfulness, answer_relevancy, context_precision, context_recall])
print(results)

Common mistakes

  • Only end-to-end "looks good" manual checks.
  • A test set without unanswerable questions.
  • Trusting LLM judges without human calibration.
  • Evaluating once at launch, never in CI.

How to answer in the interview

"I evaluate retrieval and generation separately, because a bad answer can come from either. First I build a test set of real or realistic questions with reference answers and the source documents, including hard and unanswerable ones. For retrieval I measure recall at k, MRR, nDCG and context precision. For generation I measure faithfulness, meaning every claim is supported by the context, answer relevance, correctness against the reference, and whether it correctly says it does not know. Many of these use an LLM as judge with Ragas or DeepEval, calibrated against human review. It runs in CI, and online I add user feedback and citation clicks."

Likely follow-up questions

  • No historical questions? Synthesise from documents with an LLM, have experts review, then grow from pilot usage.
  • How big a test set? Enough per category to detect regressions; start with 100 to 200.
  • Judge model choice? A strong model, calibrated, ideally different from the generator.
