How would you write a script to find the top 10 IP addresses in a web server access log?

Scripting · concept · levels entry, mid

In one line

Extract the IP field with awk '{print $1}', count with sort | uniq -c, order with sort -rn and take head -10; for structured or huge logs use a streaming Python Counter or tools that handle compression and parallelism.

Detailed explanation

In the common and combined log formats used by Nginx and Apache, the client IP is the first whitespace-separated field. The classic pipeline is: awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10. uniq -c only counts adjacent duplicates, which is why the first sort is required. sort -rn sorts numerically in reverse so the highest counts come first.

The pipeline streams the file, so memory use is low, except that sort must see all lines; GNU sort handles that with temporary files on disk. A faster variant counts in awk itself with an associative array, so only unique IPs are kept in memory: awk '{c[$1]++} END {for (ip in c) print c[ip], ip}' access.log | sort -rn | head.

Real logs add complications. Behind a load balancer the first field may be the proxy's IP, and the real client is in X-Forwarded-For, so you need the right field or log format. JSON logs are better parsed with jq or Python. In Python, read the file line by line (not read()), split or parse JSON, and use collections.Counter with most_common(10). For rotated or compressed logs, zcat -f access.log* reads both plain and gzip files. For very large volumes, split work with GNU parallel, or better, query a log platform such as Loki, Elasticsearch or CloudWatch Logs Insights.

How it works

  1. Read the log as a stream.
  2. Extract the IP field per line.
  3. Count occurrences (sort + uniq -c, or a hash map).
  4. Sort counts descending.
  5. Print the top ten.

Example

awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -10

# include rotated and gzipped logs, counting in awk
zcat -f /var/log/nginx/access.log* | awk '{c[$1]++} END {for (ip in c) print c[ip], ip}' | sort -rn | head -10
import sys
from collections import Counter

counts = Counter()
with open(sys.argv[1], encoding="utf-8", errors="replace") as f:
    for line in f:
        ip = line.split(" ", 1)[0]
        counts[ip] += 1

for ip, n in counts.most_common(10):
    print(f"{n:>8} {ip}")

Common mistakes

  • Using uniq -c without sorting first.
  • Sorting counts alphabetically instead of with -n.
  • Reading huge files fully into memory in Python.
  • Counting the load balancer's IP instead of the real client.

How to answer in the interview

"In the shell I extract the first field with awk, pipe it to sort and uniq -c to count, then sort -rn to get the highest counts first and head to take ten. It streams the file so memory stays low, apart from sort, which can spill to disk; counting in an awk array avoids even that. For JSON logs or more complex parsing I would write a short Python script that reads line by line and uses Counter with most_common of ten. For rotated or compressed files I use zcat -f, and behind a load balancer I make sure I use the X-Forwarded-For client IP."

Likely follow-up questions

  • How would you count only 5xx responses in the last hour? Filter on the status field and timestamp first, e.g. awk '$9 ~ /^5/' combined with a time filter.
  • Why is awk counting faster? It keeps only unique keys instead of sorting every line.
  • Where would you do this in production? In the log platform, with a query and a dashboard.
