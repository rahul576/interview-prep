What is prompt engineering?

AI/ML & GenAI · concept · levels entry

In one line

Prompt engineering is designing the instructions and context given to an LLM so it produces accurate, useful and consistently formatted results: a clear task, relevant context, explicit constraints, a defined output format, examples, and iterative evaluation, while guarding against hallucination and prompt injection.

Detailed explanation

An LLM predicts a response from everything in its context, so the quality of that context drives the quality of the answer. Prompt engineering is the practical discipline of shaping it.

Core elements of a good prompt:

  • Task: what exactly to do ("Write JUnit 5 tests for PriceCalculator", not "help with tests").
  • Context: the code, requirements, documents or data the model needs; it cannot guess your codebase.
  • Constraints: Java version, frameworks, coding standards, what not to change, length limits.
  • Output format: JSON matching a schema, a unified diff, a Markdown table.
  • Role / system prompt: in applications, a system prompt sets persistent behaviour, tone and rules.

Useful techniques: few-shot prompting (show one or two input-output examples), asking the model to reason before answering or letting reasoning models think, decomposing a big task into steps or chained prompts, and grounding ("answer only from the provided documents; say 'not found' otherwise") to reduce hallucinations.

In applications, prompt engineering becomes engineering: prompts are versioned, tested against an evaluation set, and combined with structured outputs (JSON Schema enforced by the API) and validation in code. Since many prompts include untrusted text (emails, web pages, tickets), you must defend against prompt injection by clearly delimiting data, limiting tool permissions and never letting content grant itself authority. The term today often expands into context engineering: deciding what information, tools and history the model sees at each step.

How it works

  1. State the task and success criteria precisely.
  2. Add only the relevant context and clear delimiters around data.
  3. Specify constraints and the exact output format.
  4. Add examples if the format or style is subtle.
  5. Test on a set of cases, inspect failures and iterate.
  6. Version the prompt and monitor it in production.

Example

System: You are a senior Java reviewer. Follow the team rules below.
<rules> Java 21, Spring Boot 3, constructor injection, no System.out </rules>

User: Review the diff between <diff> tags. Return JSON:
{"issues":[{"file":string,"line":int,"severity":"high|medium|low","message":string}]}
Only report real problems; return {"issues":[]} if none.

Common mistakes

  • Vague tasks with no context, then blaming the model.
  • Asking for JSON in words only, without schema enforcement and validation.
  • Overloading one prompt with many unrelated tasks.
  • Tweaking prompts by feel without an evaluation set.
  • Mixing untrusted input with instructions without delimiters.

How to answer in the interview

"Prompt engineering is designing the instructions and context we give a language model so the output is accurate and consistently formatted. A good prompt states the task clearly, includes the relevant context like code or requirements, sets constraints such as the Java version or what not to change, and defines the output format, for example JSON. Techniques include few-shot examples, system prompts for role and rules, asking it to reason step by step, breaking big tasks into smaller ones and grounding answers in provided sources. In applications I version prompts, test them against an evaluation set, and defend against prompt injection from untrusted input."

Likely follow-up questions

  • How do you get reliably parseable JSON? Use the API's structured output or tool calling with a JSON Schema, then validate and retry on failure.
  • Zero-shot vs few-shot? Zero-shot gives only instructions; few-shot adds examples to show the pattern.
  • What is context engineering? Managing everything the model sees: retrieved data, tools, memory and history, not just the wording.
