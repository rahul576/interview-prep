What is in-context learning, and how do zero-shot and few-shot prompting differ from fine-tuning?

AI/ML & GenAI · concept · levels entry, mid

In one line

In-context learning is an LLM performing a task from instructions or examples in the prompt without changing weights; zero-shot gives only instructions, few-shot adds a handful of examples, while fine-tuning changes the weights for consistent behaviour at scale.

Detailed explanation

Large language models can pick up a task at inference time just from the prompt. Nothing is learned permanently; the model conditions its predictions on the context it is given. This emerged as models scaled and is the basis of most LLM applications.

Zero-shot prompting describes the task: "Classify this review as positive, negative or neutral. Reply with one word." Modern instruction-tuned models are strong zero-shot, especially with clear definitions and output format. Few-shot prompting adds a few input-output examples, showing the exact format, label set, tone and edge cases ("'Arrived late but works fine' → neutral"). This often noticeably improves accuracy and consistency, particularly for unusual formats or company-specific categories. Example choice matters: cover diverse and tricky cases, keep formats identical, avoid all examples sharing one label, and consider dynamically retrieving the most similar examples for each input.

Fine-tuning trains on hundreds to thousands of examples so the behaviour is built into the weights, using full fine-tuning or parameter-efficient methods like LoRA. Compared with prompting: prompting is instant to iterate, needs no training pipeline or labelled set, works with the latest models and is easy to change, but instructions and examples consume context tokens on every call (cost and latency, partly offset by prompt caching) and can be less consistent. Fine-tuning gives consistent style or format, shorter prompts and can let a smaller, cheaper model match a larger one, but needs data, evaluation and retraining when requirements change, and it is not a good way to add frequently changing knowledge, for which RAG is better. The usual path is: zero-shot, then few-shot, then RAG or fine-tuning only if evaluations show the need.

How it works

  1. Write a clear zero-shot instruction with output format.
  2. Evaluate on a labelled test set.
  3. Add a few representative examples and re-evaluate.
  4. If still insufficient, retrieve examples dynamically or add RAG for knowledge.
  5. Fine-tune only when volume, consistency or cost justify it, then compare on the same evaluation set.

Common mistakes

  • Jumping to fine-tuning before trying good prompts.
  • Few-shot examples that are all similar or all the same label.
  • Using fine-tuning to inject facts that change often.
  • Not measuring with an evaluation set when changing prompts.

How to answer in the interview

"In-context learning is the model doing a task from what's in the prompt, with no weight updates. Zero-shot means just instructions; few-shot adds a handful of input-output examples, which pins down format and edge cases and often boosts accuracy. Fine-tuning actually trains the weights on many examples. I start with prompting because it's fast and flexible, but it costs context tokens every call. I'd fine-tune for high-volume, stable tasks where I need consistent output, shorter prompts or a cheaper model, and use RAG rather than fine-tuning for changing knowledge."

Likely follow-up questions

  • How would you pick good few-shot examples? Diverse, representative, covering edge cases, balanced labels, possibly retrieved per input by similarity.
  • Does the order of examples matter? It can; recency and label patterns influence outputs, so test it.
  • When does fine-tuning beat RAG? For style, format or behaviour; RAG is better for facts and fresh knowledge.
