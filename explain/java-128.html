What changed in Spring Boot 3 compared with Spring Boot 2?

Spring Boot · concept · levels mid, senior

In one line

Spring Boot 3 (on Spring Framework 6) requires Java 17+, moves from javax to jakarta (Jakarta EE 9/10), reworks observability around the Micrometer Observation API and Micrometer Tracing (replacing Sleuth), adds AOT and GraalVM native images, ProblemDetail, HTTP interfaces, and later virtual threads and RestClient.

Detailed explanation

Baseline: Boot 3.0 (November 2022) needs Java 17 and supports newer LTS versions; Boot 2.7 worked on Java 8. This let Spring use records, text blocks and modern APIs.

Jakarta EE: the biggest migration effort. Java EE moved to the Eclipse Foundation and renamed its packages, so javax.persistence, javax.servlet, javax.validation become jakarta.*. Every library touching these APIs must be a Jakarta-compatible version: Hibernate 6, Tomcat 10+, newer Jersey and so on. Tools like OpenRewrite recipes and the Spring Boot Migrator automate much of it.

Observability: the Micrometer Observation API instruments once and produces metrics and traces; Micrometer Tracing with OpenTelemetry or Brave bridges replaces Spring Cloud Sleuth, which ended with Boot 2.x. Trace ids appear in logs automatically.

Native and AOT: Spring's ahead-of-time engine generates bean definitions at build time so applications can compile to GraalVM native images, starting in tens of milliseconds with lower memory; the same AOT output supports CRaC and faster JVM startup.

Web features: ProblemDetail and ErrorResponse for RFC 7807/9457 error responses; declarative HTTP interfaces with @HttpExchange/@GetExchange; Spring Security 6 with SecurityFilterChain beans and the lambda DSL (the old WebSecurityConfigurerAdapter was removed); auto-configuration registration moved to AutoConfiguration.imports. Trailing-slash matching is no longer on by default.

Later 3.x releases: 3.1 added Docker Compose and Testcontainers service connections; 3.2 added virtual threads support (spring.threads.virtual.enabled), RestClient and JdbcClient; later releases added structured logging and SSL bundle improvements. Boot 4.0, released in November 2025 on Spring Framework 7, continues this line, so a Boot 2 codebase today usually migrates through 3.x.

How it works

  1. Upgrade to Boot 2.7 and Java 17 first; fix deprecations.
  2. Run OpenRewrite to switch javax to jakarta and update APIs.
  3. Upgrade dependencies to Jakarta-compatible versions.
  4. Rewrite security config to SecurityFilterChain, and replace Sleuth with Micrometer Tracing.
  5. Use spring-boot-properties-migrator to detect renamed properties, then test.

Example

<parent>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-parent</artifactId>
  <version>3.5.0</version>
</parent>
<properties><java.version>21</java.version></properties>
// Boot 2:  import javax.persistence.Entity;
import jakarta.persistence.Entity;

// HTTP interface (Spring 6)
public interface StockClient {
    @GetExchange("/stock/{sku}")
    StockDto get(@PathVariable String sku);
}
mvn -U org.openrewrite.maven:rewrite-maven-plugin:run \
  -Drewrite.recipeArtifactCoordinates=org.openrewrite.recipe:rewrite-spring:RELEASE \
  -Drewrite.activeRecipes=org.openrewrite.java.spring.boot3.UpgradeSpringBoot_3_0

Common mistakes

  • Jumping from an old 2.x straight to 3.x without passing through 2.7 deprecation fixes.
  • Mixing javax and jakarta libraries on the classpath, causing runtime errors.
  • Forgetting third-party libraries that are not yet Jakarta-ready.
  • Assuming native images work with all reflection-heavy libraries without hints.

How to answer in the interview

"Spring Boot 3 is built on Spring Framework 6 and needs Java 17 as a minimum. The biggest migration item is the move from Java EE to Jakarta EE, so javax imports become jakarta and every related library must be a compatible version, like Hibernate 6 and Tomcat 10. Observability was reworked around the Micrometer Observation API, with Micrometer Tracing replacing Spring Cloud Sleuth. It has AOT processing and first-class GraalVM native image support. It added ProblemDetail for standard error responses and declarative HTTP interfaces, and Security 6 removed WebSecurityConfigurerAdapter. Later 3.x versions added virtual threads, RestClient, JdbcClient and Testcontainers integration."

Likely follow-up questions

  • How would you plan a Boot 2 to 3 migration for twenty services? Shared parent and libraries first, OpenRewrite automation, a pilot service, then waves with contract tests.
  • What replaced Sleuth? Micrometer Tracing with an OpenTelemetry or Brave bridge.
  • What is the properties migrator? A dependency that reports and temporarily remaps renamed properties at startup.
