Is Java pass-by-value or pass-by-reference? Explain with an example.

Core Java & OOP · concept · levels entry, mid

In one line

Java is always pass-by-value: for primitives the value is copied; for objects the reference is copied, so a method can mutate the object the caller sees, but reassigning the parameter never changes the caller's variable.

Detailed explanation

In pass-by-value, the method receives a copy of the argument. In pass-by-reference (as in C++ int& or C# ref), the method receives an alias of the caller's variable, so assigning to the parameter changes the caller's variable. Java only has the first.

The confusion comes from object variables. In Java, a variable of type List<String> does not contain the list; it contains a reference (a pointer-like value) to a list on the heap. When you call addItem(cart), the reference value is copied into the parameter. Now two variables, the caller's and the parameter, hold references to the same object.

Consequences:

  • Mutating the object through the parameter (cart.add("book"), order.setStatus(PAID)) changes the shared object, so the caller sees it. This looks like pass-by-reference but is not.
  • Reassigning the parameter (cart = new ArrayList<>()) only changes the method's local copy of the reference. The caller's variable still points to the original object. In true pass-by-reference, the caller's variable would change.
  • Primitives are copied directly: incrementing an int parameter never affects the caller.
  • Immutable objects (String, Integer, BigDecimal) cannot be mutated, so a method cannot change them in any visible way; "modifying" them creates a new object assigned only to the local parameter.

This is why a swap(Integer a, Integer b) method cannot work in Java, and why methods that need to "return" several values use a return object (a record) instead. Design-wise, the ability to mutate shared objects means defensive copies matter for encapsulation, and making parameters final can document that they are not reassigned.

How it works

  1. Caller evaluates the argument: a primitive value or a reference value.
  2. That value is copied into the parameter, a new local variable on the method's stack frame.
  3. Operations through the reference act on the shared heap object.
  4. Assigning a new value to the parameter changes only the local copy.
  5. When the method returns, the parameter disappears; the caller's variable is untouched.

Example

static void addItem(List<String> cart) {
    cart.add("book");                 // mutates the shared object: caller sees it
}

static void replaceCart(List<String> cart) {
    cart = new ArrayList<>();         // reassigns local copy only
    cart.add("pen");
}

static void increment(int n) { n++; } // copy of the value

List<String> myCart = new ArrayList<>();
addItem(myCart);
replaceCart(myCart);
int count = 1;
increment(count);

System.out.println(myCart);           // [book]  (not [pen], not [])
System.out.println(count);            // 1

static void swap(Integer a, Integer b) { Integer t = a; a = b; b = t; }  // no effect on caller

Common mistakes

  • Saying "objects are passed by reference".
  • Expecting a method that reassigns a parameter to change the caller's variable.
  • Expecting String parameters to be modifiable.
  • Forgetting that mutable arguments can be changed by called code (needing defensive copies).

How to answer in the interview

"Java is always pass-by-value. For primitives the value itself is copied. For objects, the value that's passed is the reference, so the method gets a copy of the reference that points to the same object. If the method mutates the object, for example adds to a list, the caller sees the change because it's the same object. But if the method reassigns the parameter to a new object, that only changes its local copy, and the caller's variable still points to the original. That's why you can't write a working swap method for two Integers in Java."

Likely follow-up questions

  • How would you write a swap method for two Integer variables, and why does it not work? Swapping parameters only swaps the local copies of the references; the caller's variables are unchanged. You would swap elements of an array or return a pair instead.
  • How do you return multiple values? Return a record or small value object.
  • Why do defensive copies matter? Because callers and callees share mutable objects, a class must copy mutable inputs and outputs to protect its state.
