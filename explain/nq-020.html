What is a lambda expression, and how does it work internally?

Java 8+ Features · concept · levels entry, mid

In one line

A lambda is a concise anonymous function (params) -> body implementing a functional interface; internally javac moves the body into a private synthetic method and emits an invokedynamic call site that LambdaMetafactory links at runtime, generating no separate .class file.

Detailed explanation

Conceptually, a lambda is behaviour passed as data. Its type is the target functional interface, and its parameter types are usually inferred from it.

Compilation: unlike anonymous inner classes, which javac compiles into Outer$1.class files, a lambda's body is desugared into a private method of the enclosing class, named like lambda$main$0. It is static if the lambda captures nothing from the instance, and an instance method if it uses this. Captured local variables become extra leading parameters of that method. At the place where the lambda is created, javac emits an invokedynamic instruction whose bootstrap method is LambdaMetafactory.metafactory.

Runtime linkage: the first time that invokedynamic executes, the bootstrap method generates (with hidden classes in modern JDKs) a small class that implements the functional interface and forwards the interface method to the synthetic method. It returns a CallSite; subsequent executions reuse it with no bootstrap cost. For non-capturing lambdas, the call site returns the same instance every time, effectively a singleton, because it has no state. Capturing lambdas create a new small object per evaluation holding the captured values.

Why this design? It avoids class-file bloat and class-loading cost per lambda, and it keeps the translation strategy flexible: future JDKs can change how lambdas are implemented without recompiling code. The JIT can also inline lambda calls aggressively. Method references use the same mechanism, pointing at the existing method directly.

How it works

  1. javac type-checks the lambda against the target interface.
  2. The body becomes a private synthetic method (lambda$...).
  3. An invokedynamic instruction is placed at the creation site.
  4. On first execution, LambdaMetafactory spins a hidden class implementing the interface.
  5. The call site is linked and reused; non-capturing lambdas return a cached instance.

Example

public class Demo {
    public static void main(String[] args) {
        Function<Integer, Integer> twice = x -> x * 2;   // non-capturing
        int base = 10;
        Function<Integer, Integer> plus = x -> x + base; // capturing 'base'
        System.out.println(twice.apply(4) + plus.apply(1));
    }
}
javac Demo.java && javap -p -c Demo
# private static java.lang.Integer lambda$main$0(java.lang.Integer);
# private static java.lang.Integer lambda$main$1(int, java.lang.Integer);
# invokedynamic #7, 0  // InvokeDynamic #0:apply:()Ljava/util/function/Function;
# invokedynamic #11, 0 // InvokeDynamic #1:apply:(I)Ljava/util/function/Function;

Note that base became a parameter of lambda$main$1, and no Demo$1.class appears.

Common mistakes

  • Saying lambdas are compiled into anonymous inner classes.
  • Assuming every lambda evaluation allocates a new object.
  • Relying on lambda identity (==), which is unspecified.
  • Ignoring that capturing lambdas in hot loops can allocate.

How to answer in the interview

"A lambda is a concise anonymous function, parameters, arrow and body, that implements the single abstract method of a functional interface, so behaviour can be passed as data. Internally javac doesn't generate an inner class file. It moves the body into a private synthetic method in the enclosing class and emits an invokedynamic instruction at the creation site. The first time it runs, the bootstrap method LambdaMetafactory creates an implementation of the interface that calls that method. For non-capturing lambdas the same instance is reused. It's lighter than inner classes and gives the JVM freedom to optimise."

Likely follow-up questions

  • Why can a non-capturing lambda be a singleton? It has no state, so one instance behaves identically everywhere.
  • What tool shows the synthetic method? javap -p -c.
  • Do method references use invokedynamic? Yes, the same LambdaMetafactory mechanism.
