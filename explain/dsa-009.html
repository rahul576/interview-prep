How do you reverse a singly linked list?

DSA: Lists, Stacks & Queues · concept · levels entry

In one line

Walk the list with three pointers: prev, curr, next. Save curr.next, point curr.next back to prev, then advance both. When curr is null, prev is the new head. That is O(n) time, O(1) space. The recursive version uses O(n) stack and can overflow.

Detailed explanation

In a singly linked list each node knows only its successor. Reversing means flipping every next pointer to point at the predecessor. The challenge is that once you overwrite curr.next, you lose the way forward. So you must save the next node first.

Iterative algorithm:

  • prev = null (the old head becomes the new tail, pointing to null), curr = head.
  • Loop while curr != null: next = curr.next, curr.next = prev, prev = curr, curr = next.
  • Return prev.

Each node is visited once, so it is O(n) time with a constant number of pointers, O(1) space. It also handles the edge cases (empty list, single node) without special code.

Recursive alternative: reverse the rest of the list from head.next, then make head.next.next = head and head.next = null, returning the new head from the deepest call. It is elegant, but it uses O(n) call-stack space. In Java a list of a few hundred thousand nodes can throw StackOverflowError. Java does not do tail-call elimination, so prefer the iterative version in production.

Variants interviewers like:

  • Reverse between positions m and n: walk to the node before m, reverse n-m+1 nodes with the same loop, and reconnect both ends. A dummy head avoids special-casing m = 1.
  • Reverse in groups of k.
  • Palindrome check: find the middle with slow/fast pointers, reverse the second half, compare, then restore.

How it works

  1. prev = null, curr = head.
  2. next = curr.next saves the rest of the list.
  3. curr.next = prev flips the link.
  4. prev = curr, curr = next advances.
  5. Repeat until curr == null, then return prev.

Example

public ListNode reverse(ListNode head) {
    ListNode prev = null, curr = head;
    while (curr != null) {
        ListNode next = curr.next;
        curr.next = prev;
        prev = curr;
        curr = next;
    }
    return prev;
}

// Recursive (O(n) stack)
public ListNode reverseRec(ListNode head) {
    if (head == null || head.next == null) return head;
    ListNode newHead = reverseRec(head.next);
    head.next.next = head;
    head.next = null;
    return newHead;
}
// 1 -> 2 -> 3 -> null   becomes   3 -> 2 -> 1 -> null

Common mistakes

  • Overwriting curr.next before saving it, which loses the rest of the list.
  • Returning head (now the tail) instead of prev.
  • Forgetting head.next = null in the recursive version, which creates a cycle.
  • Using recursion on very long lists without mentioning the stack risk.

How to answer in the interview

"I'd iterate with three pointers. Prev starts as null, current is the head. In each step I save current's next, point current's next back to prev, then move prev to current and current to the saved next. When current becomes null, prev is the new head. That's O(n) time and O(1) space, and it handles empty and single-node lists naturally. A recursive version is shorter but uses O(n) stack space, which can overflow on long lists in Java, so I prefer the iterative one."

Likely follow-up questions

  • Reverse only between positions m and n? Use a dummy head, walk to m-1, reverse the sublist, and reconnect both ends.
  • Reverse in groups of k? Count k nodes, reverse them, link to the recursively or iteratively reversed remainder.
  • Doubly linked list? Swap prev and next in each node, and the new head is the old tail.
