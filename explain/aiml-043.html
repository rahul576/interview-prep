How do speech-to-text and text-to-speech work in applications, such as a voice-based interview practice app?

AI/ML & GenAI · concept · levels entry, mid

In one line

Speech-to-text (ASR) turns audio into transcripts with models like Whisper or cloud services, text-to-speech (TTS) synthesises natural voices, and in a voice interview app you balance latency (streaming), accuracy on accents and technical terms, browser vs cloud vs local options, and privacy and consent.

Detailed explanation

Speech-to-text (automatic speech recognition) converts audio into text. Modern neural models, such as OpenAI Whisper (open weights, many languages) and cloud services from Azure, Google Cloud and AWS, produce punctuated transcripts, word timestamps and often speaker labels. Streaming ASR returns partial results while the person is still speaking, with a final transcript after a pause, detected by voice activity detection (VAD). Batch mode processes a full recording, usually more accurately.

Text-to-speech synthesises audio from text using neural voices with natural prosody. Options include cloud TTS (many voices, SSML control of pauses and pronunciation), the browser's Web Speech API (speechSynthesis, free and offline-capable but voice quality varies by device), and small local models that can run on-device. Some newer speech-to-speech multimodal models handle listening and speaking in one real-time model.

In a voice-based interview practice app: the app reads the question aloud with TTS, records the answer with MediaRecorder or streams microphone audio, ASR produces the transcript, and the transcript is scored against key points (perhaps by an LLM), with feedback on content and delivery, such as filler words and speaking pace computed from timestamps.

Key design choices. Latency: conversations feel unnatural beyond about a second of silence, so stream audio and start TTS playback early. Accuracy: accents, background noise, cheap microphones and domain vocabulary ("Kubernetes", "Terraform", "idempotent") cause errors; use custom vocabularies or phrase hints where supported, prompts with expected terms for Whisper, and post-correction against a glossary. Cost and offline: browser Web Speech recognition support varies and may send audio to a vendor's servers; local Whisper variants give privacy at the cost of device performance. Privacy: recorded voice is personal data, so obtain clear consent, minimise retention, encrypt and let users delete recordings.

How it works

  1. TTS speaks the interview question.
  2. The app captures microphone audio after user permission.
  3. Audio streams to ASR; VAD detects the end of the answer.
  4. The final transcript (with timestamps) is sent for scoring.
  5. Feedback is shown and optionally spoken; recordings follow the retention policy.

Example

// Browser: speak the question, then record the answer for server-side ASR
speechSynthesis.speak(new SpeechSynthesisUtterance("Explain blue-green deployment."));

const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
const rec = new MediaRecorder(stream, { mimeType: "audio/webm" });
const chunks = [];
rec.ondataavailable = e => chunks.push(e.data);
rec.onstop = () => fetch("/api/transcribe", { method: "POST", body: new Blob(chunks) });
rec.start();

Common mistakes

  • Waiting for the full recording before any processing, adding seconds of delay.
  • Ignoring technical vocabulary, so "Kafka" becomes "café".
  • Storing recordings indefinitely without consent.
  • Testing only with one accent and a quiet room.

How to answer in the interview

"Speech-to-text converts audio to a transcript using models like Whisper or cloud ASR, ideally streaming partial results; text-to-speech generates natural voices from cloud, browser or local models. In a voice interview app, TTS reads the question, the user answers, ASR transcribes and we score the transcript. The design concerns are latency, so I'd stream; accuracy with accents, noise and technical terms, which I'd improve with phrase hints and glossary correction; browser versus cloud versus local trade-offs; and privacy, with explicit consent and short retention."

Likely follow-up questions

  • How to improve recognition of technical terms? Custom vocabulary or phrase hints, prompting Whisper with expected terms, and glossary-based post-correction.
  • How do you detect when the user finished? Voice activity detection with a silence timeout, plus a manual stop button.
  • How do you measure ASR quality? Word error rate on a labelled set covering accents and domain terms.
