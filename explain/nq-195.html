What is aspect-oriented programming (AOP)?

Spring Framework · concept · levels entry, mid

In one line

AOP modularises cross-cutting concerns (logging, security, transactions, caching, metrics) into aspects; key terms are join point, pointcut, advice, aspect and weaving, advice types are before, after returning, after throwing, after and around, and Spring AOP is proxy-based while AspectJ weaves bytecode.

Detailed explanation

Object-oriented design organises code by responsibility, but some requirements cut across many classes: logging, auditing, security checks, transactions, retries, caching and metrics. Implemented by hand they scatter the same code everywhere and tangle it with business logic. Aspect-oriented programming lets you write such a concern once and declare where it applies.

Terminology:

  • Join point: a point during execution where behaviour can be added. In Spring AOP it is always a method execution on a bean.
  • Pointcut: an expression selecting join points, for example execution(* com.acme.service..(..)), within(com.acme..), @annotation(com.acme.Audited) or bean(*Service).
  • Advice: the code to run at selected join points. Types: @Before, @AfterReturning (access to the result), @AfterThrowing (access to the exception), @After (finally), and @Around, the most powerful, which controls whether and how the method proceeds.
  • Aspect: a class combining pointcuts and advice (@Aspect).
  • Target object: the bean being advised; AOP proxy: the object wrapping it.
  • Weaving: linking aspects with targets.

Spring AOP weaves at runtime using JDK dynamic or CGLIB proxies. It is simple and needs no special compiler, but only intercepts public (and, with CGLIB, protected/package) method calls made through the proxy, so self-invocation, private methods, constructors and field access are not intercepted. AspectJ weaves at compile time or load time (LTW), modifying bytecode, so it can advise any method, constructors, field access and self-calls, at the cost of build or agent setup. Spring uses AspectJ's annotation style and pointcut language even in proxy mode.

Spring itself uses AOP for @Transactional, @Cacheable, @Async, @PreAuthorize and @Retryable.

How it works

  1. Define an @Aspect bean with pointcuts and advice.
  2. An auto-proxy creator checks each bean against pointcuts.
  3. Matching beans are wrapped in proxies with an advice chain.
  4. A call to the proxy runs the advice chain around the target method.
  5. Non-matching beans are injected as-is.

Example

@Aspect
@Component
class AuditAspect {
    @Pointcut("@annotation(com.acme.audit.Audited)")
    void audited() {}

    @AfterReturning(pointcut = "audited()", returning = "result")
    void logSuccess(JoinPoint jp, Object result) {
        log.info("AUDIT {} returned {}", jp.getSignature().toShortString(), result);
    }

    @AfterThrowing(pointcut = "audited()", throwing = "ex")
    void logFailure(JoinPoint jp, Exception ex) {
        log.warn("AUDIT {} failed: {}", jp.getSignature().toShortString(), ex.getMessage());
    }
}

Common mistakes

  • Pointcuts so broad that they match framework or infrastructure beans.
  • Expecting advice on private methods or internal calls.
  • Using @Around without calling proceed() or without rethrowing exceptions.
  • Business logic hidden in aspects, hard to trace.

How to answer in the interview

"AOP separates cross-cutting concerns such as logging, security, transactions and metrics from business logic so I write them once in an aspect. A join point is a point in execution, in Spring always a method call; a pointcut selects join points, like an execution expression or an annotation; advice is the code that runs, before, after returning, after throwing, after or around; and an aspect combines them. Weaving links aspects to targets. Spring AOP weaves at runtime with proxies, while AspectJ weaves bytecode at compile or load time and can intercept more join points."

Likely follow-up questions

  • Limits of proxy-based AOP? No self-invocation, private methods, constructors or final methods.
  • Ordering multiple aspects? @Order or the Ordered interface.
  • Where does Spring use AOP? Transactions, caching, async, method security, retries.
