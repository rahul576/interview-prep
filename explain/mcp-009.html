How do MCP resources work: URIs, resource templates and subscriptions?

MCP Servers · concept · levels entry, mid, senior

In one line

MCP resources are read-only data identified by URIs with a MIME type, discovered via resources/list and fetched via resources/read; resource templates use URI templates for parameterised access, and subscriptions notify clients when a resource changes.

Detailed explanation

A resource is a unit of context the server can provide: a file, a database schema, a log, a ticket, a configuration. Each has a URI such as file:///project/README.md, postgres://db/schema/orders or a custom scheme like jira://ticket/PAY-123, plus a name, optional title, description, mimeType and optional size and annotations.

Discovery and reading. Clients call resources/list (paginated with cursors) to see fixed resources, and resources/read with a URI to get contents. Contents come back as text (with MIME type) or base64-encoded binary (blob), and one read may return several content items.

Resource templates. Large or dynamic sets cannot be listed one by one. Servers publish templates via resources/templates/list using RFC 6570 URI templates, e.g. logs://{service}/{date} or github://repos/{owner}/{repo}/issues/{number}. The client or user fills in parameters, often assisted by the completion feature (completion/complete), which suggests valid values like service names.

Subscriptions. If the server declares the subscribe capability, a client can call resources/subscribe for a URI; when the resource changes, the server sends notifications/resources/updated and the client re-reads it. Separately, with listChanged, the server sends notifications/resources/list_changed when the set of resources changes.

How resources reach the model is the host's decision: the user attaches them through a picker, the application selects relevant ones, or a tool result includes a resource link. Resources are application-controlled, not called by the model on its own.

How it works

  1. Client checks the server's resources capability (subscribe, listChanged).
  2. Lists resources and templates.
  3. User or app picks a resource or fills a template (with completion).
  4. Client calls resources/read and the host adds contents to the context.
  5. Optionally subscribes and re-reads on update notifications.

Example

{"jsonrpc":"2.0","id":1,"method":"resources/templates/list"}
→ {"resourceTemplates":[{"uriTemplate":"logs://{service}/{date}","name":"Service logs",
    "mimeType":"text/plain","description":"Error logs for one service and day (YYYY-MM-DD)"}]}

{"jsonrpc":"2.0","id":2,"method":"resources/read","params":{"uri":"logs://checkout/2026-11-20"}}
→ {"contents":[{"uri":"logs://checkout/2026-11-20","mimeType":"text/plain","text":"..."}]}

{"jsonrpc":"2.0","id":3,"method":"resources/subscribe","params":{"uri":"config://app/feature-flags"}}

Common mistakes

  • Listing millions of individual resources instead of using templates.
  • Returning enormous resources without size information or summaries.
  • Assuming the model will read resources by itself, as with tools.
  • Serving resources without checking the user's permission for that URI.

How to answer in the interview

"A resource is read-only context identified by a URI, like a file, a database schema or a ticket, with a name and MIME type. Clients discover them with resources/list and fetch them with resources/read, getting text or base64 binary. For large or dynamic sets, servers publish resource templates with URI templates such as logs://{service}/{date}, and completion helps fill parameters. If the server supports subscriptions, a client subscribes to a URI and gets an updated notification when it changes, then re-reads it; there's also a list-changed notification. The host decides how resources reach the model, for example the user attaching them."

Likely follow-up questions

  • How should a host choose resources for limited context? User selection first, then relevance ranking, size limits and summaries.
  • Who checks permissions? The server, per URI and per user.
  • Can resources be binary? Yes, base64 blobs with a MIME type, like images or PDFs.
