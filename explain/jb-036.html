Explain the Java Collections Framework hierarchy.

Collections · concept · levels entry, mid

In one line

The hierarchy starts at Iterable → Collection, which branches into List, Set (with SortedSet/NavigableSet) and Queue/Deque; Map is a separate hierarchy, and Collections and Arrays are utility classes.

Detailed explanation

Iterable<T> is the root: anything that can produce an Iterator and be used in a for-each loop. Collection<E> extends it and defines the common operations: add, remove, contains, size, stream, removeIf.

Under Collection:

  • List: ordered, indexed, duplicates allowed. Implementations: ArrayList (default), LinkedList, legacy Vector/Stack, and CopyOnWriteArrayList.
  • Set: no duplicates. HashSet, LinkedHashSet; SortedSet → NavigableSet → TreeSet; EnumSet; concurrent ConcurrentSkipListSet, CopyOnWriteArraySet.
  • Queue: FIFO or priority. PriorityQueue; Deque extends Queue for both ends: ArrayDeque, LinkedList. The BlockingQueue family lives in java.util.concurrent.

Java 21 added sequenced collections: SequencedCollection (with getFirst, getLast, addFirst, reversed) sits above List and Deque, and SequencedSet above LinkedHashSet and SortedSet.

Map does not extend Collection because it holds key-value pairs; methods like add(E) make no sense for it. It offers three collection views instead: keySet(), values(), entrySet(). Implementations: HashMap, LinkedHashMap, TreeMap (via SortedMap/NavigableMap), EnumMap, WeakHashMap, IdentityHashMap, legacy Hashtable, and in java.util.concurrent ConcurrentHashMap and ConcurrentSkipListMap. SequencedMap was also added in Java 21.

The Collections class provides sort, unmodifiableX, synchronizedX, emptyList and more; Arrays provides sort, binarySearch, asList and stream. Since Java 9 the interfaces themselves have factories like List.of.

How it works

  1. Program to interfaces: declare List, Set, Map.
  2. Choose the implementation by order, uniqueness, lookup and concurrency needs.
  3. Use views (keySet, entrySet) to treat a map as collections.
  4. Use utility classes and factories for wrappers and constants.

Example

Iterable
 └─ Collection
     ├─ SequencedCollection (21)
     ├─ List ─ ArrayList, LinkedList, CopyOnWriteArrayList
     ├─ Set ─ HashSet ─ LinkedHashSet
     │   └─ SortedSet ─ NavigableSet ─ TreeSet
     └─ Queue ─ PriorityQueue, BlockingQueue...
         └─ Deque ─ ArrayDeque, LinkedList

Map ─ HashMap ─ LinkedHashMap
 ├─ SortedMap ─ NavigableMap ─ TreeMap
 └─ ConcurrentMap ─ ConcurrentHashMap

Common mistakes

  • Saying Map extends Collection.
  • Declaring variables as ArrayList instead of List.
  • Confusing Collection (interface) with Collections (utility class).
  • Using legacy Vector, Stack or Hashtable in new code.

How to answer in the interview

"At the root is Iterable, extended by Collection. Collection has three main branches: List, ordered with duplicates, like ArrayList and LinkedList; Set, no duplicates, like HashSet, LinkedHashSet and TreeSet via SortedSet and NavigableSet; and Queue and Deque, like PriorityQueue and ArrayDeque. Java 21 added SequencedCollection for collections with a defined order. Map is a separate hierarchy because it stores key-value pairs, with HashMap, LinkedHashMap, TreeMap and ConcurrentHashMap. The Collections and Arrays classes provide sorting, wrappers and helpers."

Likely follow-up questions

  • Why doesn't Map extend Collection? Its unit is a key-value pair; it exposes collection views instead.
  • Collection vs Collections? Interface vs static utility class.
  • What did Java 21 add? SequencedCollection, SequencedSet and SequencedMap.
