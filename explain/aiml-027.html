Why are GPUs used for deep learning, and how do training and inference differ in hardware needs?

AI/ML & GenAI · concept · levels entry, mid

In one line

Deep learning is dominated by parallel matrix multiplications, which GPUs (thousands of cores, tensor cores, high memory bandwidth) do far faster than CPUs; training needs much more memory and compute on large clusters, while inference runs continuously and is driven by latency and cost per request.

Detailed explanation

A neural network layer is essentially a large matrix multiply followed by simple element-wise operations. CPUs have a few dozen powerful cores optimised for branching, sequential logic. GPUs have thousands of simpler cores plus tensor cores that perform small matrix multiplications in low precision (BF16, FP8) in a single operation, and high-bandwidth memory (HBM) delivering terabytes per second. For deep learning this gives speed-ups of one to two orders of magnitude. Software stacks such as CUDA, cuDNN and frameworks like PyTorch make this accessible.

Training is the heavier job. Besides the weights, it must hold activations for backpropagation, gradients, and optimiser state (AdamW keeps two extra values per parameter), often several times the memory of the weights alone. It processes massive datasets for many steps, so large models train on clusters of hundreds to many thousands of GPUs connected by fast interconnects (NVLink, InfiniBand) using data, tensor and pipeline parallelism, for weeks. Throughput and reliability (checkpointing, failed nodes) dominate.

Inference only runs the forward pass, so memory is mainly weights plus the KV cache for LLMs. But it runs for every request, continuously, so latency, throughput and cost per token matter. Techniques include quantisation (INT8, FP8, 4-bit), continuous batching, KV-cache optimisation, distillation into smaller models, speculative decoding and autoscaling. LLM generation is often memory-bandwidth bound, not compute bound. Alternatives to NVIDIA GPUs include AMD GPUs, Google TPUs, AWS Trainium (training) and Inferentia (inference), and inference-focused chips from other vendors; small models can still run on CPUs or edge NPUs.

How it works

  1. Data is loaded and batched into GPU memory.
  2. Matrix multiplications run in parallel across cores and tensor cores.
  3. Training adds the backward pass, gradient synchronisation across GPUs and optimiser updates.
  4. Inference runs only forward passes, batched across concurrent requests.
  5. Serving systems scale replicas with demand and use quantised weights to cut cost.

Example

# Check GPU utilisation and memory while serving
nvidia-smi --query-gpu=name,utilization.gpu,memory.used,memory.total --format=csv
# Serve an open model with continuous batching (vLLM)
vllm serve meta-llama/Llama-3.1-8B-Instruct --max-model-len 8192 --gpu-memory-utilization 0.9

Common mistakes

  • Assuming inference hardware must match training hardware.
  • Ignoring memory bandwidth and only comparing FLOPS.
  • Underestimating that annual inference cost can exceed training cost.
  • Leaving GPUs idle with no batching or autoscaling.

How to answer in the interview

"Neural networks are mostly big matrix multiplications, which are massively parallel. GPUs have thousands of cores, tensor cores and very high memory bandwidth, so they're far faster than CPUs for this. Training needs much more memory because you store activations, gradients and optimiser state, and big models train on thousands of interconnected GPUs for weeks, a large one-off cost. Inference is forward-only but runs for every request, so latency and cost per request matter, and we use quantisation, batching and smaller models. TPUs, Trainium and Inferentia are alternatives."

Likely follow-up questions

  • Why can a year of inference cost more than training? Training is one-off; inference runs for millions of requests every day.
  • What is quantisation? Storing weights and activations in lower precision to save memory and speed up inference.
  • Why is LLM decoding memory-bound? Each token requires reading all weights and the KV cache with little compute per byte.
