How do you choose an embedding model, and what happens when you change it?

LLMOps & RAG · concept · levels mid, senior

In one line

Choose an embedding model by evaluating recall on your own data (leaderboards like MTEB are only a start), weighing language, domain, dimensions, max input, latency, cost, hosting and residency; changing it means re-embedding the whole corpus, because vectors from different models are not comparable, so build the new index in parallel and switch atomically.

Detailed explanation

Evaluation. The MTEB leaderboard ranks models across many tasks, but your domain (legal, medical, internal jargon, product codes), languages and query style can reorder rankings. Build a labelled set of real queries with their relevant chunks and measure recall at k, MRR or nDCG for each candidate, ideally with your reranker in the loop.

Other factors:

  • Multilingual support if documents and questions mix languages (for example Hindi questions over English docs).
  • Dimensions: 384 to 3,072 typical; more dimensions mean more storage, memory and search cost.
  • Max input length: longer limits allow bigger chunks.
  • Latency and throughput for ingestion and queries.
  • Price: hosted models from OpenAI, Cohere, Voyage AI, Google, Mistral and others charge per token; open models (BGE, E5, GTE, Nomic, Jina, Qwen embedding families) can be self-hosted on modest GPUs or CPUs.
  • Data residency, and the vendor's deprecation policy.

Changing models is a migration. Vector spaces of different models (and even different versions of one model) are incompatible, so you cannot mix old and new vectors or embed queries with a different model than documents. You must re-embed the entire corpus, rebuild the index, and switch query embedding at exactly the same moment as the index.

Practical approach: store the model name, version, dimensions and preprocessing as index metadata; build the new index side by side (blue-green); backfill with batch embedding jobs while dual-writing new and updated documents to both indexes; evaluate the new index offline and with shadow or A/B traffic; then switch an alias; keep the old index for rollback for a while.

How it works

  1. Shortlist models from leaderboards and constraints.
  2. Evaluate recall on your labelled query set.
  3. For migration, create a new index with the new dimensions.
  4. Backfill with batch jobs; dual-write ongoing changes.
  5. Evaluate, switch alias and query model together, keep old index for rollback.

Example

INDEX_META = {"embedding_model": "provider/model-name", "version": "2026-03", "dims": 1024, "normalize": True}

def embed_query(q, index_meta):
    model = load_embedder(index_meta["embedding_model"], index_meta["version"])
    return model.embed(q, input_type="query", dims=index_meta["dims"])

Common mistakes

  • Picking the top leaderboard model without testing on your data.
  • Updating the query embedder without re-indexing documents.
  • Not recording which model built an index.
  • Forgetting query/document input types or normalisation.

How to answer in the interview

"MTEB is a starting point, but I evaluate candidate embedding models on our own documents and real queries, measuring recall, because domain vocabulary and languages change rankings. I also weigh multilingual support, dimensions, which drive storage and search cost, max input length, latency, price for hosted models versus self-hosting open ones, and data residency. Changing the model is a migration: vectors from different models are not comparable, so the whole corpus must be re-embedded and query embedding must switch at the same time. I record the model version with the index, build the new one in parallel, evaluate it, switch an alias and keep the old one for rollback."

Likely follow-up questions

  • Re-embed 100 million chunks without downtime? Parallel batch jobs, dual-write, new index, alias switch.
  • Fine-tune an embedding model? Yes, with query-passage pairs from your domain, when recall plateaus.
  • Reduce dimensions? Matryoshka truncation or quantisation, validated by recall.
