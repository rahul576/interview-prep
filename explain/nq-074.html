What are the different ways to create threads in Java?

Concurrency · concept · levels entry

In one line

Create threads by extending Thread, passing a Runnable/lambda to new Thread(...), submitting Callable tasks to an ExecutorService (returns a Future), using CompletableFuture.supplyAsync, or creating virtual threads (Thread.ofVirtual(), Java 21); always call start(), not run().

Detailed explanation

1. Extend Thread. Override run() and call start(). Simple, but your class can no longer extend anything else, and the task is welded to the thread mechanism.

2. Implement Runnable. Put the work in run() and pass it to new Thread(runnable).start(). Since Java 8, Runnable is a functional interface, so a lambda is usual. This separates the task from how it is executed.

3. Callable with an ExecutorService. Callable<V> returns a value and may throw checked exceptions. You submit it to a thread pool and receive a Future<V>; get() waits for the result. Thread pools reuse threads and bound concurrency, so in real applications (and in Spring via TaskExecutor or @Async) this is preferred over creating threads manually.

4. CompletableFuture. supplyAsync(supplier, executor) and runAsync(...) run work asynchronously and let you chain thenApply, thenCombine and error handlers without blocking. Without an explicit executor they use the common ForkJoinPool.

5. Virtual threads (Java 21+). Thread.ofVirtual().start(task), Thread.startVirtualThread(task) or Executors.newVirtualThreadPerTaskExecutor(). They are cheap, so you can have one per blocking task.

Also useful: ScheduledExecutorService for delayed or periodic tasks, and the Thread.Builder API for naming threads.

Whatever you use, start() creates the new thread; calling run() would just execute on the current thread.

How it works

  1. Define the work (Runnable, Callable, Supplier or lambda).
  2. Choose the mechanism: raw Thread, pool, CompletableFuture, virtual thread.
  3. Start it: start(), submit(), supplyAsync().
  4. The JVM schedules it on a new or pooled thread.
  5. Retrieve results via join(), Future.get() or callbacks; shut down pools.

Example

// 1. Extend Thread
new Thread() { public void run() { System.out.println("A"); } }.start();

// 2. Runnable lambda
new Thread(() -> System.out.println("B"), "worker-b").start();

// 3. Callable + ExecutorService
ExecutorService pool = Executors.newFixedThreadPool(2);
Future<String> f = pool.submit(() -> "C");
System.out.println(f.get());
pool.shutdown();

// 4. CompletableFuture
CompletableFuture.supplyAsync(() -> "D", pool2)
                 .thenAccept(System.out::println);

// 5. Virtual thread
Thread vt = Thread.ofVirtual().start(() -> System.out.println("E"));
vt.join();

Common mistakes

  • Calling run() instead of start().
  • Creating an unbounded number of platform threads per request.
  • Using supplyAsync for blocking I/O on the common pool.
  • Forgetting to shut down executors.

How to answer in the interview

"There are several ways. I can extend Thread and override run, then call start. More commonly I implement Runnable, usually as a lambda, and pass it to a Thread, which separates the task from the thread. If the task returns a value or throws checked exceptions I use Callable and submit it to an ExecutorService, which gives me a Future; in real applications pools from Executors or Spring are preferred to manual threads. CompletableFuture.supplyAsync runs work asynchronously and chains steps, and since Java 21 I can create virtual threads with Thread.ofVirtual. In all cases I call start, not run."

Likely follow-up questions

  • What happens if you call run() instead of start()? The code runs synchronously on the current thread; no new thread is created.
  • Which approach do you use in Spring Boot? An injected ThreadPoolTaskExecutor or @Async, or virtual threads via spring.threads.virtual.enabled.
  • What is a daemon thread? A thread that does not keep the JVM alive once all non-daemon threads finish.
