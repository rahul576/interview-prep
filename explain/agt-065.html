How are AI assistants used in security operations, and what should DevOps teams know about them?

AI Agents & AIOps · concept · levels mid, senior

In one line

In security operations, AI assistants triage and summarise alerts, investigate with SIEM queries and threat intelligence, explain detections and suggest responses, while analysts approve containment; DevOps teams should know quality depends on their logs and asset context, and that attackers use and target AI too.

Detailed explanation

Security operations centres (SOCs) face a huge volume of alerts with limited analysts. AI assistants such as Microsoft Security Copilot, Google Security Operations' Gemini features and AI features in SIEM and XDR products help in several ways. They triage and summarise alerts and incidents, enrich them with asset, identity and vulnerability context, translate questions into SIEM queries (KQL, YARA-L, SPL), check threat intelligence for indicators, explain in plain language what a detection means, and suggest response steps. Increasingly, agents carry out parts of investigations automatically, such as triaging phishing reports.

Containment actions, like isolating a host, disabling an account or blocking an IP range, remain human-approved or tightly scoped playbooks, because a wrong decision can disrupt the business as badly as the attack.

DevOps teams should know two things. First, AI quality depends on the data they provide: consistent, complete logs from applications, Kubernetes, CI/CD and cloud control planes, accurate asset inventories, ownership and tags. An assistant cannot explain an attack on a service whose audit logs are missing. Second, attackers use AI too, to scale phishing, write malware variants and find vulnerabilities, and they target AI systems, through prompt injection, model abuse and stolen API keys, so the AI applications DevOps runs need security monitoring as well.

How it works

  1. Detections fire in the SIEM/XDR.
  2. AI enriches with asset, identity and threat intel context.
  3. It summarises, scores and proposes investigation queries.
  4. Analyst reviews; AI runs approved queries and drafts the report.
  5. Containment through playbooks with human approval.
  6. Feedback tunes detections and triage.

Example

// Suggested by assistant: sign-ins from the flagged IP for the affected user (Microsoft Sentinel)
SigninLogs
| where TimeGenerated > ago(24h)
| where UserPrincipalName == "svc-deploy@contoso.com" or IPAddress == "203.0.113.45"
| project TimeGenerated, UserPrincipalName, IPAddress, AppDisplayName, ResultType, Location
Summary: service account svc-deploy used from unfamiliar IP to access Key Vault;
CI/CD logs show no pipeline run at that time → possible credential leak.
Suggested: rotate secret, disable account pending review (requires analyst approval).

Common mistakes

  • DevOps logs without user, service or request identifiers.
  • Assets missing from inventory, so alerts lack owners.
  • Letting AI agents perform containment without approval.
  • Forgetting to monitor the company's own AI applications.

How to answer in the interview

"SOCs use assistants like Security Copilot or SIEM vendor AI to triage and summarise alerts, enrich them with asset and identity context, run investigation queries, check threat intelligence and suggest response steps, while analysts approve containment like isolating hosts or disabling accounts. For DevOps, the key points are that the AI is only as good as the logs, asset inventory and ownership data we provide, and that attackers use AI and target AI systems, so our own AI applications need security monitoring too."

Likely follow-up questions

  • Most valuable DevOps telemetry? Cloud audit logs, identity logs, CI/CD and Kubernetes audit logs.
  • Can AI write detections? It can draft them; test against known data before deploying.
  • Biggest risk? Wrong containment decisions or missed context.
