What does the static keyword mean when applied to variables, methods, blocks and nested classes?

Core Java & OOP · concept · levels entry

In one line

static means "belongs to the class, not an instance": a static variable has one shared copy, a static method runs without an instance (so no this), a static block runs once at class initialisation, and a static nested class has no outer-instance reference.

Detailed explanation

Static variables (class variables) exist once per class per class loader, regardless of how many objects you create. static final fields with immutable values are constants, such as MAX_RETRIES. Mutable static fields are effectively global state: shared between all threads and all tests, which makes them a common source of race conditions and flaky tests.

Static methods are called on the class, like Math.max or List.of. Because there is no instance, they cannot use this or super and cannot access instance fields or methods directly. They are resolved at compile time, so they are not polymorphic: a subclass method with the same signature hides the parent's rather than overriding it. Static factory methods (Optional.of, LocalDate.now) are a widely used idiom.

Static initialiser blocks (static { ... }) run once when the class is initialised, which happens on first active use: creating an instance, calling a static method, or reading a non-constant static field. The JVM guarantees this happens once and thread-safely, which is the basis of the holder idiom for lazy singletons. If a static block throws, the class becomes unusable (ExceptionInInitializerError, then NoClassDefFoundError).

Static nested classes don't need an instance of the outer class and don't hold a hidden reference to it, making them the right choice for builders and helper types.

There is also static import (import static java.lang.Math.*;), which only affects naming.

How it works

  1. Class loading reads the class; static fields get default values.
  2. On first active use, the JVM initialises the class: runs static field initialisers and static blocks in textual order.
  3. Static methods are invoked with invokestatic, with no receiver object.
  4. Static fields live with the class metadata and are reachable as long as the class is loaded.

Example

public class IdGenerator {
    private static final AtomicLong COUNTER = new AtomicLong(); // shared, thread-safe
    private static final Map<String, String> PREFIXES;

    static {                                   // runs once at class init
        PREFIXES = Map.of("order", "ORD", "invoice", "INV");
    }

    public static String next(String type) {   // no instance needed; no 'this'
        return PREFIXES.get(type) + "-" + COUNTER.incrementAndGet();
    }

    private static class Holder {              // lazy, thread-safe singleton
        static final IdGenerator INSTANCE = new IdGenerator();
    }
}

Common mistakes

  • Using mutable static fields as caches or "current user" holders.
  • Expecting static methods to be overridden polymorphically.
  • Doing risky I/O in static blocks.
  • Calling static methods through instance references, which compiles but misleads readers.

How to answer in the interview

"Static means the member belongs to the class rather than an instance. A static variable has a single copy shared by all instances; static final ones are constants. A static method is called on the class without an instance, so it can't use this or instance members, and it isn't overridden, only hidden. A static block runs once when the class is initialised, which the JVM does thread-safely. A static nested class doesn't hold a reference to an outer instance. I use static for constants, factory and utility methods, but I avoid mutable static state because it's global state that hurts testing and thread safety."

Likely follow-up questions

  • Can a static method be overridden? No; a same-signature static method in a subclass hides it, resolved by reference type.
  • When does a static block run? On class initialisation, at first active use, once.
  • Can a static method access instance fields? Only through an explicit object reference.
