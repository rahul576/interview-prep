What are records in Java, and how do you define one?

Modern Java (11-21) · concept · levels entry, mid

In one line

A record (standard since Java 16) is a concise, final class for immutable data carriers: you declare record Point(int x, int y) {} and the compiler generates private final fields, a canonical constructor, accessors, equals, hashCode and toString.

Detailed explanation

Before records, a simple value class needed fields, a constructor, getters, equals, hashCode and toString, often fifty lines or a Lombok annotation. A record says "this class is just its data". The header lists the components, and from them the compiler derives everything else.

For record Point(int x, int y) you get:

  • private final int x and private final int y;
  • a canonical constructor Point(int x, int y);
  • accessor methods x() and y() (not getX());
  • equals and hashCode based on all components, and a readable toString such as Point[x=1, y=2].

The class is implicitly final and extends java.lang.Record, so it cannot extend anything else, but it can implement interfaces. You can add a compact constructor for validation or normalisation, extra constructors that delegate to the canonical one, static factory methods, static fields and instance methods. You cannot add extra instance fields.

Records were previewed in Java 14 and 15 and became final in 16, so they are available in every modern LTS (17, 21, 25). They work with Jackson for JSON, Spring @ConfigurationProperties, Spring Data projections and, in Java 21, record patterns that deconstruct them in instanceof and switch. Typical uses are DTOs, API responses, events, map keys and intermediate values in streams.

How it works

  1. Declare record Name(Type a, Type b) { }.
  2. Compiler creates final fields and the canonical constructor.
  3. Accessors named after components are generated.
  4. equals/hashCode/toString use all components.
  5. Optional compact constructor runs before fields are assigned.

Example

public record Money(BigDecimal amount, String currency) {
    public Money {                       // compact constructor
        Objects.requireNonNull(amount);
        if (amount.signum() < 0) throw new IllegalArgumentException("negative");
        currency = currency.toUpperCase();
    }
    public static Money inr(String v) { return new Money(new BigDecimal(v), "INR"); }
    public Money plus(Money o) { return new Money(amount.add(o.amount), currency); }
}

Money m = Money.inr("100.00");
m.amount();          // accessor
System.out.println(m); // Money[amount=100.00, currency=INR]

Common mistakes

  • Calling getAmount(); the accessor is amount().
  • Trying to extend a class or add instance fields.
  • Assigning this.amount = ... in a compact constructor (you assign the parameter).
  • Assuming deep immutability when a component is a mutable list.

How to answer in the interview

"A record is a special final class for immutable data, standard since Java 16. I declare it with a header like record Point(int x, int y), and the compiler generates private final fields, the canonical constructor, accessors named x() and y(), and equals, hashCode and toString from all components. It extends java.lang.Record, so it can't extend another class, but it can implement interfaces and have static factories and extra methods. I validate in a compact constructor. I use records for DTOs, events, API responses and map keys."

Likely follow-up questions

  • How do you validate fields in a record? In a compact constructor, throwing on invalid values or normalising parameters.
  • Can a record be generic? Yes, for example record Pair<A, B>(A first, B second).
  • Do records work with Jackson? Yes, modern Jackson versions bind via the canonical constructor.
