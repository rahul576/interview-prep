How would you sort products by name using Comparator?

Coding Exercises · scenario · levels entry

In one line

Use sorted(Comparator.comparing(Product::getName)) to get a new list sorted by name; add .reversed() for descending, String.CASE_INSENSITIVE_ORDER for case-insensitive, thenComparing for ties, Comparator.nullsFirst for null names, and list.sort(...) to sort in place.

Detailed explanation

Comparator.comparing(keyExtractor) builds a comparator that extracts a key from each object and compares keys by their natural order. String implements Comparable, so names compare lexicographically by UTF-16 code unit — uppercase letters sort before lowercase, and accented characters may not sort as a human expects.

With streams: products.stream().sorted(Comparator.comparing(Product::getName)).toList() returns a new list; the original order is unchanged. sorted is a stateful intermediate operation — it must see all elements before emitting any — and it is stable, so equal elements keep their relative order.

Variations:

  • Descending: Comparator.comparing(Product::getName).reversed(), or comparing(Product::getName, Comparator.reverseOrder()).
  • Case-insensitive: comparing(Product::getName, String.CASE_INSENSITIVE_ORDER).
  • Locale-aware (proper alphabetical order for human languages): comparing(Product::getName, Collator.getInstance(Locale.ENGLISH)).
  • Tie-breakers: .thenComparing(Product::getPrice) sorts products with equal names by price.
  • Null names: comparing(Product::getName, Comparator.nullsFirst(Comparator.naturalOrder())); without it, a null name throws NullPointerException.

In place: products.sort(Comparator.comparing(Product::getName)) sorts the existing mutable list (it fails on immutable lists like List.of). Collections.sort(list, cmp) does the same. Both use TimSort, O(n log n).

How it works

  1. Choose the key extractor, Product::getName.
  2. Comparator.comparing wraps it into a Comparator.
  3. Optionally adjust: key comparator, reversed, thenComparing, nullsFirst.
  4. Pass it to sorted for a new list, or list.sort for in-place.

Example

List<Product> byName = products.stream()
        .sorted(Comparator.comparing(Product::getName))
        .toList();

List<Product> byNameDesc = products.stream()
        .sorted(Comparator.comparing(Product::getName).reversed())
        .toList();

Comparator<Product> robust = Comparator
        .comparing(Product::getName,
                   Comparator.nullsFirst(String.CASE_INSENSITIVE_ORDER))
        .thenComparing(Product::getPrice);

products.sort(robust);   // in place, mutable list only

// category ascending, then price descending
products.sort(Comparator.comparing(Product::getCategory)
        .thenComparing(Product::getPrice, Comparator.reverseOrder()));

Common mistakes

  • Calling sorted() without a comparator on a class that is not Comparable.
  • Using list.sort on an immutable List.of(...) list.
  • Placing .reversed() at the end of a chain and reversing every key unintentionally.
  • Expecting case-insensitive or locale-aware order from natural String ordering.

How to answer in the interview

"I'd pass a comparator built from the name getter: products.stream().sorted(Comparator.comparing(Product::getName)).toList(). That sorts by name ascending using natural String order and returns a new list, while the original stays as it is. For descending I add reversed; for case-insensitive I pass String.CASE_INSENSITIVE_ORDER as the key comparator; to break ties I chain thenComparing; and if names can be null I wrap with Comparator.nullsFirst. To sort the existing list in place, I'd use products.sort with the same comparator."

Likely follow-up questions

  • Sort by category, then price descending? comparing(Product::getCategory).thenComparing(Product::getPrice, Comparator.reverseOrder()).
  • Is the sort stable? Yes, both sorted and List.sort are stable.
  • Complexity? O(n log n) using TimSort.
