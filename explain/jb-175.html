What is the difference between @Controller and @RestController?

Spring Boot · concept · levels mid, senior

In one line

@Controller marks a Spring MVC controller whose methods normally return a view name rendered by a template engine; @RestController = @Controller + @ResponseBody, so return values are serialised directly to the response body (JSON or XML) by HttpMessageConverters.

Detailed explanation

Both are stereotype annotations detected by component scanning, and both register their @RequestMapping methods with Spring MVC. The difference is how the return value is handled.

In a @Controller, a returned String like "orders/list" is a logical view name. A ViewResolver maps it to a template such as templates/orders/list.html, and Thymeleaf, FreeMarker or JSP renders HTML using data you put in the Model. This is classic server-side rendering: forms, redirects ("redirect:/orders"), flash attributes.

@RestController (since Spring 4) is meta-annotated with @Controller and @ResponseBody. @ResponseBody tells Spring to skip view resolution and write the return value to the HTTP response body. A message converter is chosen by content negotiation: the Accept header and the produces attribute are matched against converters' supported media types. With Jackson on the classpath, objects become JSON; with jackson-dataformat-xml, XML is possible too. Strings returned from a REST controller are written as plain text, not view names.

You can mix styles: in a @Controller class put @ResponseBody on a specific method, for example an AJAX endpoint next to page handlers, or return ResponseEntity, which is always written to the body and lets you set status and headers. Error handling follows the same split: @ControllerAdvice for views, @RestControllerAdvice for APIs.

Use @RestController for REST APIs consumed by SPAs, mobile apps or other services, and @Controller for server-rendered pages. A common bug is using @Controller for an API and getting a "template not found" or circular view path error because Spring tries to resolve the returned object as a view.

How it works

  1. DispatcherServlet invokes the handler method.
  2. The return value handler checks for @ResponseBody (or ResponseEntity).
  3. If present: content negotiation selects a converter, which writes JSON or XML.
  4. If absent: the value is a view name; a ViewResolver renders the template with the model.
  5. The response is sent.

Example

@Controller
@RequestMapping("/orders")
class OrderPageController {
    @GetMapping
    String list(Model model) {
        model.addAttribute("orders", service.findAll());
        return "orders/list";                     // Thymeleaf template
    }

    @GetMapping("/{id}/status")
    @ResponseBody
    StatusDto status(@PathVariable long id) {     // JSON from a @Controller
        return service.status(id);
    }
}

@RestController
@RequestMapping("/api/orders")
class OrderApiController {
    @GetMapping(value = "/{id}", produces = { MediaType.APPLICATION_JSON_VALUE, MediaType.APPLICATION_XML_VALUE })
    OrderDto get(@PathVariable long id) { return service.find(id); }   // JSON or XML by Accept
}

Common mistakes

  • Using @Controller for APIs and getting template errors.
  • Returning a view name from a @RestController and getting the literal string.
  • Expecting XML output without an XML converter on the classpath.

How to answer in the interview

"@Controller marks a Spring MVC controller whose methods normally return a view name, which a view resolver renders with a template engine like Thymeleaf into HTML. @RestController is a convenience annotation that combines @Controller with @ResponseBody on every method, so the return value is not treated as a view name but written straight into the HTTP response body, serialised to JSON or XML by message converters, usually Jackson. I use @RestController for REST APIs and @Controller for server-rendered pages. In a @Controller I can still put @ResponseBody on one method, or return ResponseEntity, for a mixed case."

Likely follow-up questions

  • How does Spring decide whether to return JSON or XML? Content negotiation: the Accept header and produces are matched against available message converters.
  • Can a @RestController return HTML? Yes as a String with produces = text/html, but templates are better served by @Controller.
  • What does ResponseEntity add? Control over status code and headers alongside the body.
