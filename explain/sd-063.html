How do distributed systems order events without a reliable global clock?

Distributed Systems · concept · levels senior, lead

In one line

Physical clocks drift, so distributed systems order events with sequence numbers from a leader, Lamport clocks (causal total order), vector clocks (detect concurrency), hybrid logical clocks (causality + near wall time) or TrueTime (bounded uncertainty in Spanner).

Detailed explanation

NTP keeps clocks within milliseconds, sometimes much worse (VM pauses, leap seconds, misconfigured hosts). Two writes 2 ms apart on different machines can't be ordered by timestamps, and last-writer-wins by wall clock can silently drop the newer write.

  • Lamport clock: a counter; increment on each event; on receiving a message, set max(local, received) + 1. If A happened-before B, L(A) < L(B). The converse doesn't hold, so you can't detect concurrency.
  • Vector clock: one counter per node. Comparing vectors tells you before, after or concurrent, so conflicts can be surfaced (Dynamo's shopping cart siblings). Size grows with participants.
  • Hybrid logical clock (HLC): combines physical time with a logical counter; stays close to real time, preserves causality; used in CockroachDB, MongoDB, YugabyteDB.
  • TrueTime (Spanner): GPS + atomic clocks give an interval [earliest, latest]; commits wait out the uncertainty (~ms) to guarantee external consistency.
  • Simplest: a single leader per partition assigns increasing sequence numbers (Kafka offsets, DB LSNs).

How it works

  1. Decide what ordering you need: per entity, causal, or global.
  2. Per entity → partition + sequence number.
  3. Causal → Lamport/HLC.
  4. Detect conflicts → vector clocks/CRDTs.

Example

Vector clocks: A=[2,0] B=[1,1] → neither ≥ the other → concurrent → conflict to merge
Lamport: send(m) at L=5 → receiver L=max(3,5)+1=6

Common mistakes

  • LWW with client timestamps.
  • Assuming NTP-synced clocks are good enough for ordering.
  • Global ordering when per-key ordering suffices.

How to answer in the interview

"I don't rely on wall clocks for ordering because they drift. The simplest solution is a single sequencer per partition, like Kafka offsets. For causality across nodes, Lamport or hybrid logical clocks; to detect concurrent updates, vector clocks, so conflicts can be merged instead of silently dropped. Spanner's TrueTime is the special case where hardware-bounded clock uncertainty is waited out."

Likely follow-up questions

  • Why is LWW dangerous for carts? Concurrent adds get dropped; merge sets instead.
  • What's a CRDT? A data type whose replicas merge deterministically without coordination.
  • Commit wait in Spanner? Waits until the timestamp is certainly in the past everywhere.
