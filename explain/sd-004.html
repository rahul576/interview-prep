How do load balancers work, and which algorithms and layers are used?

SD Fundamentals · concept · levels entry, mid, senior

In one line

A load balancer spreads traffic across healthy backends using an algorithm (round robin, least connections, hashing), at layer 4 (TCP) or layer 7 (HTTP), and must itself be highly available.

Detailed explanation

Load balancers are the front door of almost every scalable system. They provide scalability (more backends = more capacity), availability (unhealthy instances are removed via health checks) and operational flexibility (rolling deploys, canaries, draining).

Layer 4 balancers route TCP/UDP connections without reading content: very fast, protocol-agnostic, but they balance per connection, which is uneven for long-lived HTTP/2 or gRPC connections. Layer 7 balancers understand HTTP: they can route by path or host, terminate TLS, add headers, retry, and balance per request.

How it works

  1. Client resolves DNS to the load balancer address (often anycast or a cloud LB).
  2. LB terminates TLS (L7) or passes the connection through (L4).
  3. It picks a backend using the algorithm, considering only instances passing health checks.
  4. During deploys, instances are drained: no new requests, existing ones finish.
  5. Global setups add GeoDNS or anycast in front of regional load balancers.

Example

upstream api {
    least_conn;
    server 10.0.1.10:8080 max_fails=3 fail_timeout=10s;
    server 10.0.1.11:8080 max_fails=3 fail_timeout=10s;
}
server { listen 443 ssl; location /api/ { proxy_pass http://api; } }

Comparison

AlgorithmGood for
Round robinSimilar instances, similar requests
Weighted round robinMixed instance sizes, canaries
Least connectionsRequests with very different durations
Consistent hashingCache affinity, sticky routing by key

Common mistakes

  • Health checks that only test "process is up", not "can serve requests".
  • Relying on sticky sessions instead of making services stateless.
  • Using an L4 balancer for gRPC and getting all traffic on one backend.
  • Forgetting the load balancer itself can be a single point of failure.

How to answer in the interview

"I'd put a layer-7 load balancer in front of the stateless service, terminating TLS and routing by path. It uses health checks to remove bad instances and least-connections because request times vary. For HA I'd use the cloud's managed load balancer across zones, and at global scale add GeoDNS or anycast to route users to the nearest region."

Likely follow-up questions

  • How do you deploy without dropping requests? Connection draining plus readiness checks.
  • How does a load balancer avoid being a SPOF? Managed multi-zone LBs, active/passive pairs with a floating IP, or anycast.
  • Why is gRPC tricky? Long-lived HTTP/2 connections need request-level (L7) balancing.
