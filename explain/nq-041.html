What does map() return, and what does forEach() return?

Java 8+ Features · concept · levels entry

In one line

map returns a new Stream<R> of transformed elements and is a lazy intermediate operation, so you can keep chaining; forEach returns void and is a terminal operation that ends the pipeline.

Detailed explanation

map has the signature <R> Stream<R> map(Function<? super T, ? extends R> mapper). It applies the function to each element and produces a stream of the results. The element type can change: Stream<String> with String::length becomes Stream<Integer>. Because the return type is a stream, you can attach more operations (filter, sorted, collect). And because it is intermediate, it is lazy: calling map on its own processes nothing; it only adds a stage that will run when a terminal operation is invoked.

forEach has the signature void forEach(Consumer<? super T> action). It is terminal: calling it triggers evaluation of the whole pipeline and runs the action for each element. It returns nothing, so the stream is consumed and you cannot chain anything after it. Its purpose is side effects at the end of the pipeline, such as printing or publishing.

The practical consequence is that these two are not interchangeable. If you want a value, use map followed by a collecting operation (toList, collect, reduce, sum). If you only want to do something with each element, use forEach. A common beginner pattern is to use forEach to fill an external list, which works sequentially but is fragile and unsafe in parallel streams.

There is also Iterable.forEach on collections (list.forEach(...)), which likewise returns void and does not need a stream at all. For parallel streams, forEach gives no ordering guarantee; forEachOrdered processes elements in encounter order.

How it works

  1. stream.map(f) creates a new stage and returns Stream<R> immediately.
  2. Further intermediate operations add more stages.
  3. A terminal operation such as forEach starts evaluation.
  4. Each element passes through f and then into the forEach consumer.
  5. The stream is now consumed; the forEach call returns void.

Example

List<String> words = List.of("java", "stream", "api");

Stream<Integer> lengths = words.stream().map(String::length); // nothing runs yet
List<Integer> result = lengths.toList();                      // [4, 6, 3]

words.stream()
     .map(String::toUpperCase)
     .forEach(System.out::println);  // prints JAVA, STREAM, API; returns void

// Does not compile: forEach returns void
// words.stream().forEach(System.out::println).count();

Common mistakes

  • Writing stream.map(x -> { log(x); return x; }) without a terminal operation and wondering why nothing logs.
  • Using forEach to accumulate into an external ArrayList.
  • Trying to chain after forEach, which does not compile.
  • Assuming forEach preserves order in a parallel stream.

How to answer in the interview

"map is an intermediate operation that returns a new Stream of the transformed elements, for example a Stream of String mapped with String::length gives a Stream of Integer. Since it returns a stream I can keep chaining, and it is lazy, so nothing happens until a terminal operation runs. forEach is a terminal operation that returns void. It runs the action for each element and ends the pipeline, so nothing can be chained after it. I use map when I want transformed values, followed by toList or collect, and forEach only for side effects at the end, like printing or publishing events."

Likely follow-up questions

  • Can you chain another operation after forEach? No; it returns void and the stream is consumed.
  • What does peek return? A stream, so it is intermediate and chainable, but it is intended for debugging.
  • forEach vs forEachOrdered? In parallel streams only forEachOrdered guarantees encounter order.
