How would you collect transformed products into a new list?

Coding Exercises · scenario · levels entry

In one line

map then collect: collect(Collectors.toList()) (no mutability guarantee) or toList() (Java 16+, unmodifiable); use Collectors.toCollection(ArrayList::new) for a specific mutable type and Collectors.toUnmodifiableList() (Java 10+) for an explicit immutable one.

Detailed explanation

After transforming elements with map, a terminal operation gathers them into a collection. Several options exist, and the difference is mostly about mutability and nulls:

collect(Collectors.toList()) — the classic Java 8 way. The Javadoc makes no guarantees about the type, mutability, serializability or thread-safety of the returned list. In practice the JDK returns an ArrayList, so code that later calls add works, but relying on that is fragile.

Stream.toList() — added in Java 16. Shorter, and the returned list is unmodifiable: add, remove or set throw UnsupportedOperationException. Unlike toUnmodifiableList, it allows null elements. It is the default choice in modern code when the result is read-only, which it usually should be.

Collectors.toUnmodifiableList() — Java 10+. Explicitly unmodifiable, and it throws NullPointerException on null elements.

Collectors.toCollection(ArrayList::new) — when the caller genuinely needs a mutable list, or a specific type such as LinkedList or a TreeSet for sorted unique elements.

Switching from collect(Collectors.toList()) to toList() in existing code is not always a drop-in replacement: callers that modify the list will start failing at runtime.

Collecting creates a new list; the source list is unchanged. If you also need the elements transformed into a different type, map first (map(Product::getName)) and collect List<String>.

How it works

  1. stream() over the source list.
  2. map transforms each element.
  3. A collector or toList() accumulates results into a new container.
  4. The chosen method determines mutability and null handling.

Example

List<Product> discounted = products.stream()
        .map(p -> p.withPrice(p.price() * 0.85))
        .collect(Collectors.toList());          // Java 8+

List<Product> readOnly = products.stream()
        .map(p -> p.withPrice(p.price() * 0.85))
        .toList();                               // Java 16+, unmodifiable
// readOnly.add(x);  -> UnsupportedOperationException

ArrayList<Product> mutable = products.stream()
        .map(p -> p.withPrice(p.price() * 0.85))
        .collect(Collectors.toCollection(ArrayList::new));

List<String> names = products.stream().map(Product::name).toList();

Common mistakes

  • Calling add on a list from toList().
  • Assuming Collectors.toList() is guaranteed to be an ArrayList.
  • Replacing collect(toList()) with toList() without checking callers.
  • Using a mutable result and sharing it across threads.

How to answer in the interview

"I'd map and then collect: products.stream().map(...).collect(Collectors.toList()). Since Java 16 I can write .toList(), which returns an unmodifiable list, so a later add throws UnsupportedOperationException. Collectors.toList makes no guarantee about mutability, though in practice it's an ArrayList. If the caller needs a specific mutable type, I use Collectors.toCollection(ArrayList::new). And Collectors.toUnmodifiableList is the explicit immutable version from Java 10, which also rejects nulls."

Likely follow-up questions

  • toList() vs Collectors.toList()? toList is unmodifiable and shorter; Collectors.toList has no guarantees but is mutable in practice.
  • How to collect into a Set or Map? Collectors.toSet(), toMap(keyFn, valueFn) or groupingBy.
  • Is the source list changed? No, a new list is created.
