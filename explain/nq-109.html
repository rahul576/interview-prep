Given a two-dimensional array, how would you find the minimum-cost path from the top-left cell to the bottom-right cell?

DSA: Algorithms & DP · scenario · levels mid, senior

In one line

With moves restricted to right and down, the minimum-cost path is a classic dynamic programming problem: dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1]), filled in row order, with the answer at dp[m-1][n-1] in O(m·n) time.

Detailed explanation

The key observation is that a cell can only be entered from the cell above or the cell to the left. So the cheapest way to reach (i, j) is the cell's own cost plus the cheaper of the two cheapest ways to reach those predecessors. This is optimal substructure: an optimal path to the end contains optimal paths to every cell on it. Because many different paths share prefixes, the subproblems overlap, and storing each answer once avoids exponential recomputation.

Boundary cells need special handling. The start cell is just grid[0][0]. Cells in the first row can only be reached from the left, and cells in the first column only from above, so both are running prefix sums. Every other cell uses the general recurrence. Since each row depends only on the current and previous row, memory can drop from O(m·n) to O(n) with a single rolling array, or to O(1) extra space if you are allowed to overwrite the input grid.

Always clarify the movement rules. If you may move in all four directions, the dependency graph has cycles, a fixed fill order no longer exists, and the right tool is Dijkstra's algorithm with a priority queue (non-negative costs), giving O(m·n·log(m·n)).

How it works

  1. Handle the edge case of an empty grid and return 0 or throw.
  2. Set dp[0][0] = grid[0][0].
  3. Fill the first row: dp[0][j] = dp[0][j-1] + grid[0][j].
  4. Fill the first column: dp[i][0] = dp[i-1][0] + grid[i][0].
  5. For each remaining cell, apply grid[i][j] + min(top, left) in row-major order.
  6. Return dp[m-1][n-1]; optionally backtrack to recover the path.

Example

public int minPathCost(int[][] grid) {
    int m = grid.length, n = grid[0].length;
    int[] dp = new int[n];               // one rolling row
    dp[0] = grid[0][0];
    for (int j = 1; j < n; j++) dp[j] = dp[j - 1] + grid[0][j];
    for (int i = 1; i < m; i++) {
        dp[0] += grid[i][0];             // first column: only from above
        for (int j = 1; j < n; j++) {
            dp[j] = grid[i][j] + Math.min(dp[j], dp[j - 1]); // dp[j]=top, dp[j-1]=left
        }
    }
    return dp[n - 1];
}
// grid {{1,3,1},{1,5,1},{4,2,1}} -> 7  (1 -> 3 -> 1 -> 1 -> 1)

Common mistakes

  • Picking the cheaper neighbour greedily instead of using accumulated costs.
  • Forgetting to initialise the first row and column separately.
  • Using DP when moves in all directions are allowed.
  • Integer overflow on large grids with large costs; use long if needed.

How to answer in the interview

"First I'd confirm the moves are only right and down. Then each cell can only be reached from above or from the left, so the cheapest cost to a cell is its own cost plus the minimum of those two accumulated costs. I fill a DP table row by row: the first row and column are prefix sums, every other cell uses the recurrence, and the answer is the bottom-right value. That's O(m times n) time, and I can reduce space to one row. If moves in all four directions were allowed, I'd switch to Dijkstra because the grid would contain cycles."

Likely follow-up questions

  • How would you also print the actual path? Backtrack from the end, moving to whichever of top or left has the smaller dp value, or store a parent direction per cell.
  • What if costs can be negative? With right/down moves DP still works; with cycles you need Bellman-Ford.
  • Can you do it in O(1) extra space? Yes, by overwriting the input grid if mutation is allowed.
