What is a minor GC versus a major/full GC?

JVM & Performance · concept · levels mid, senior

In one line

A minor GC collects only the young generation (Eden and survivors): it is frequent and short and promotes survivors; a major GC targets the old generation, and a full GC collects the whole heap, usually as a long stop-the-world pause that signals problems such as a leak or undersized heap.

Detailed explanation

Minor (young) GC. Triggered when Eden fills. The collector traces live young objects (starting from roots plus old-to-young references tracked in card tables or remembered sets), copies them into a survivor space or promotes them to the old generation, and clears Eden. Since most objects die young, there is little to copy, so pauses are typically a few to tens of milliseconds. Frequency depends on allocation rate and young-generation size; several per second can be normal for busy services.

Major GC. Loosely means collecting the old generation. With G1 this is not a single event: a concurrent marking cycle runs alongside the application, followed by mixed collections that evacuate young plus some old regions in normal-sized pauses. With ZGC, old-generation work is almost entirely concurrent. With Parallel GC, old collection is a full stop-the-world compaction.

Full GC. Collects and compacts the entire heap, often including class unloading from Metaspace, stopping all application threads. On a large heap it can take seconds. In G1 and ZGC it is a fallback, so a full GC in logs is a warning sign.

Common triggers.

  • Promotion failure / evacuation failure: the old generation has no room for survivors.
  • Concurrent marking cannot keep up with allocation (G1 "to-space exhausted").
  • Explicit System.gc() calls from code or libraries.
  • Metaspace reaching its threshold or limit.
  • Heap dumps via jmap -dump:live or jcmd GC.heap_dump.
  • Humongous allocation pressure in G1.

Interpretation. If old-generation usage after each full GC keeps climbing, suspect a leak. If it drops well but refills quickly, the heap is too small for the live set and allocation rate, or objects are promoted prematurely.

How it works

  1. Allocation fills Eden: minor GC copies survivors, promotes aged objects.
  2. Old generation fills gradually through promotion.
  3. Collector-specific old-gen work runs (concurrent cycle and mixed GCs in G1).
  4. If that fails or is forced, a full stop-the-world GC compacts everything.
  5. GC logs record each event's cause and pause.

Example

java -Xlog:gc:file=gc.log:time,uptime -jar app.jar
[12.4s] GC(310) Pause Young (Normal) (G1 Evacuation Pause) 2900M->610M(4096M) 9.8ms
[85.1s] GC(402) Pause Young (Mixed) (G1 Evacuation Pause) 3300M->1500M(4096M) 28.4ms
[903.6s] GC(977) Pause Full (G1 Compaction Pause) 4090M->3950M(4096M) 2873.5ms

The last line shows a full GC that freed almost nothing: a classic leak or undersized heap symptom.

Common mistakes

  • Treating "major" and "full" as exactly the same in every collector.
  • Worrying about frequent short minor GCs while ignoring full GCs.
  • Not checking the GC cause in logs.
  • Hiding full GCs with a bigger heap instead of finding the leak.

How to answer in the interview

"A minor GC collects only the young generation, Eden and the survivor spaces. Most objects die young, so it's frequent and short: live objects are copied to a survivor space, and those that survive enough cycles are promoted to the old generation. A major GC collects the old generation, and in G1 that's done through concurrent marking plus mixed collections. A full GC collects the whole heap, usually as a long stop-the-world pause, so it should be rare. It's triggered by promotion or evacuation failure, System.gc calls, Metaspace exhaustion or heap dumps. Frequent full GCs usually mean a leak or an undersized heap."

Likely follow-up questions

  • How do you see GC pause times in a running service? GC logs (-Xlog:gc), jstat -gcutil, JFR, or Micrometer's jvm.gc.pause metric in Prometheus.
  • Is a frequent minor GC a problem? Only if pauses or CPU add up; reduce allocation or enlarge the young generation.
  • What is premature promotion? Objects promoted before dying because survivors are too small, filling the old generation.
