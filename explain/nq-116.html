What is the difference between ArrayList and LinkedList?

Collections · concept · levels entry

In one line

ArrayList is a resizable array with O(1) get; LinkedList is a doubly linked list with O(n) get but O(1) relinking once positioned, implements Deque, uses more memory, and suffers poor cache locality, so ArrayList is the default.

Detailed explanation

ArrayList stores references in one contiguous array. Index access is a single array read, O(1). Appending writes the next free slot and is amortised O(1); when full it grows by about 1.5 times and copies. Inserting or deleting at index i shifts all later elements, O(n), but that shift is a fast System.arraycopy of a contiguous block.

LinkedList stores each element in a node with item, prev and next. get(i) must walk from the head or tail, whichever is closer, so it is O(n). Inserting or removing is O(1) once you are at the position, for example at the ends (addFirst, removeLast) or via a ListIterator. Because it implements both List and Deque, it can be used as a queue or stack.

Why ArrayList wins in practice:

  • Memory: a LinkedList node object costs roughly 24 bytes (compressed oops) on top of the element; an ArrayList slot is 4 to 8 bytes.
  • Cache locality: array elements are adjacent, so the CPU prefetches them; linked nodes are scattered, causing cache misses during iteration.
  • GC: one array vs one object per element.
  • Finding the position in a LinkedList is O(n) anyway, which usually cancels its cheap relink.

For queue or deque usage, ArrayDeque beats LinkedList too. LinkedList's one real feature is allowing null in a Deque, which is rarely desirable.

How it works

  1. ArrayList get(i): bounds check, return elementData[i].
  2. ArrayList add(i, e): shift tail right, store.
  3. LinkedList get(i): iterate from nearer end to node i.
  4. LinkedList add(i, e): find node, create new node, fix four links.

Example

List<Integer> array = new ArrayList<>();
List<Integer> linked = new LinkedList<>();

for (int i = 0; i < linked.size(); i++) {
    linked.get(i);              // O(n) each -> O(n^2) loop! use for-each
}

Deque<String> queue = new ArrayDeque<>(); // better than LinkedList for queues
queue.offer("job-1");
queue.poll();

Common mistakes

  • Indexed for loops over a LinkedList.
  • Claiming LinkedList insertion in the middle is O(1) without the search cost.
  • Using LinkedList as a queue instead of ArrayDeque.
  • Not presizing ArrayList for large known sizes.

How to answer in the interview

"ArrayList stores elements in a resizable array, so get by index is constant time and appending is amortised constant, but inserting or removing in the middle shifts elements. LinkedList is a doubly linked list: get by index walks the list, which is linear, while inserting or removing is constant once you're at the position, for example at the ends; it also implements Deque. Each node carries two extra references, so it uses much more memory, and scattered nodes give poor cache locality. So ArrayList is my default, and for queues I use ArrayDeque."

Likely follow-up questions

  • Why is LinkedList rarely right? Memory overhead, cache misses and O(n) positioning outweigh cheap relinking.
  • How does ArrayList grow? By about 1.5 times with an array copy.
  • Does LinkedList allow null? Yes, unlike ArrayDeque.
