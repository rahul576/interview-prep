What is the difference between map(), filter(), sorted(), collect(), and forEach()?

Java 8+ Features · concept · levels entry

In one line

filter, map and sorted are intermediate operations that return a new stream (keep, transform, order), while collect and forEach are terminal operations: collect builds a result container and forEach performs a side effect and returns void.

Detailed explanation

filter(Predicate<T>) keeps only the elements for which the predicate returns true. The element type stays the same, but the count can shrink. Use it for conditions such as "active users" or "orders over 1,000".

map(Function<T, R>) transforms each element into exactly one new value, possibly of a different type. The count stays the same: a Stream<User> becomes a Stream<String> of emails. For one-to-many transformations you use flatMap, and for primitives mapToInt, mapToLong or mapToDouble.

sorted() orders elements by natural order (the type must be Comparable) and sorted(Comparator) by a comparator you provide, for example Comparator.comparing(User::lastName).thenComparing(User::firstName). It is a stateful operation: it has to buffer all elements before emitting the first, so it costs memory and cannot work on an infinite stream.

collect(Collector) is terminal and gathers elements into a result: Collectors.toList(), toSet(), toMap(...), joining(", "), groupingBy(...), partitioningBy(...), counting() and so on. Since Java 16 you can also use stream.toList(), which returns an unmodifiable list.

forEach(Consumer<T>) is terminal and returns nothing. It exists for side effects at the end of a pipeline: printing, sending messages, writing to a log. It should not be used to build collections by adding to an external list, because that is not thread-safe in parallel streams and it hides intent. In parallel streams forEach also does not respect encounter order; use forEachOrdered when order matters.

How it works

  1. The source creates a stream, for example orders.stream().
  2. filter drops elements that fail the predicate.
  3. map converts each remaining element into a new value.
  4. sorted buffers the elements and orders them.
  5. collect runs the pipeline and returns a container, or forEach runs it for side effects.

Example

record Order(String customer, double amount, String status) {}

List<String> topCustomers = orders.stream()
    .filter(o -> o.status().equals("PAID"))          // keep
    .sorted(Comparator.comparingDouble(Order::amount).reversed()) // order
    .map(Order::customer)                             // transform
    .distinct()
    .collect(Collectors.toList());                    // gather

Map<String, Double> totals = orders.stream()
    .collect(Collectors.groupingBy(Order::customer,
             Collectors.summingDouble(Order::amount)));

topCustomers.forEach(System.out::println);           // side effect, returns void

Common mistakes

  • Using forEach with list.add(...) instead of collect or toList().
  • Calling sorted() on objects that are not Comparable, giving ClassCastException.
  • Using Collectors.toMap without a merge function when keys can repeat, giving IllegalStateException.
  • Expecting stream.toList() to be modifiable.

How to answer in the interview

"filter, map and sorted are intermediate operations that return a stream. filter takes a Predicate and keeps matching elements, so the count can shrink. map takes a Function and transforms each element, keeping the count but possibly changing the type. sorted orders elements by natural order or a Comparator, and it is stateful because it must see all elements first. collect and forEach are terminal. collect uses a Collector such as toList, toMap, joining or groupingBy to build a result. forEach just runs a Consumer for each element and returns void, so it is for side effects like printing, not for building collections."

Likely follow-up questions

  • Why is collecting with forEach into an external list discouraged? It relies on shared mutable state, races in parallel streams and hides intent; collect is safe and clearer.
  • Difference between map and flatMap? map gives one output per element; flatMap maps each element to a stream and flattens them.
  • Collectors.toList() vs Stream.toList()? The latter (Java 16) returns an unmodifiable list; the former gives no guarantee but is an ArrayList in practice.
