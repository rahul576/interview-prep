Explain the use of static, final, this, and super keywords.

Core Java & OOP · concept · levels mid, senior

In one line

static = belongs to the class, shared by all instances; final = cannot change (variable not reassigned, method not overridden, class not extended); this = the current object and this() constructor chaining; super = the parent class's members and constructor.

Detailed explanation

static marks members that belong to the class itself. Static fields have one copy shared by all objects (static final ones are constants); static methods are called as ClassName.method() and have no this, so they cannot touch instance members directly; static blocks run once on class initialisation; static nested classes need no outer instance. Use it for constants, factories and stateless utilities; avoid mutable static state.

final means "fixed". A final variable can be assigned once; for references it fixes the reference, not the object's contents. A final method cannot be overridden. A final class cannot be extended (String, Integer, records). Final fields also get safe-publication guarantees under the Java Memory Model, and lambdas can only capture effectively final locals.

this refers to the current instance. Uses: disambiguating fields from parameters (this.name = name), passing the current object to another method, returning this for fluent builders, and this(...) to call another constructor of the same class, which must be the first statement.

super refers to the parent part of the current object. super.method() calls the parent implementation, typically from an override that extends rather than replaces behaviour. super.field accesses a hidden parent field. super(...) calls a parent constructor; if you don't write it, the compiler inserts super(), which fails if the parent has no no-arg constructor. Until Java 22 both this() and super() had to be the very first statement; newer releases are relaxing this with flexible constructor bodies that allow some validation code before the call.

Neither this nor super exists in a static context.

How it works

  1. Static members are initialised when the class is initialised.
  2. Constructors chain: this(...) within the class, then super(...) up to Object.
  3. Fields are initialised parent-first, then the child.
  4. The compiler enforces final assignment rules and forbids overriding final methods.

Example

public class SavingsAccount extends Account {
    public static final BigDecimal MIN_BALANCE = new BigDecimal("1000"); // static + final
    private final String branch;                                         // assigned once

    public SavingsAccount(String id) { this(id, "MAIN"); }               // this(): chaining
    public SavingsAccount(String id, String branch) {
        super(id);                                                       // parent constructor
        this.branch = branch;                                            // this disambiguates
    }
    @Override public String describe() {
        return super.describe() + " [savings, " + branch + "]";          // parent version
    }
    public static SavingsAccount open(String id) { return new SavingsAccount(id); }
}

Common mistakes

  • Using this inside a static method.
  • Thinking a final List is immutable.
  • Forgetting the parent has no no-arg constructor, causing a compile error.
  • Calling both this() and super() in the same constructor (not allowed).

How to answer in the interview

"static means the member belongs to the class, not an instance: static fields are shared and static methods are called without an object, which suits constants and utilities. final means it can't change: a final variable can't be reassigned, so static final fields are constants, a final method can't be overridden and a final class can't be extended. this refers to the current object; I use it to disambiguate fields and to chain constructors with this(). super refers to the parent: super.method() calls the parent version and super() calls the parent constructor, which has to come first."

Likely follow-up questions

  • Can you use this or super inside a static method? No, there's no current instance.
  • Is a final reference immutable? No, only the reference is fixed.
  • What if you don't call super()? The compiler inserts a no-arg super() call.
