Why do we split data into training, validation and test sets, and what is cross-validation?

AI/ML & GenAI · concept · levels entry, mid

In one line

The training set fits parameters, the validation set tunes hyperparameters and selects models, and the test set gives a final unbiased estimate, used once; k-fold cross-validation rotates folds for more reliable estimates, and time-based splits are needed for temporal data.

Detailed explanation

A model must be judged on data it has not learned from. If you evaluate on the same data you trained or tuned on, the estimate is optimistic, sometimes wildly so.

The training set (often around 60-80%) is used to fit the model's parameters, such as weights or tree splits. The validation set is used to compare models and tune hyperparameters, like tree depth, learning rate or regularisation strength, and for early stopping. Because you make many decisions based on it, you gradually fit to it too. The test set is held back until the end and used once to estimate performance on truly unseen data. If you keep tuning after looking at test results, it is no longer unbiased.

Cross-validation uses limited data better. In k-fold cross-validation, the data is split into k folds (commonly 5 or 10); the model trains k times, each time validating on a different fold and training on the rest; scores are averaged, and their spread shows how stable the estimate is. Stratified folds keep class proportions balanced, important for imbalanced data. Group k-fold keeps related records, such as all rows of one customer, in the same fold, avoiding leakage.

For time-dependent data, random splits leak future information into training. Use time-based splits or rolling/expanding-window validation, always training on the past and testing on later periods. Also fit preprocessing such as scaling or encoding only on training data, ideally inside a pipeline.

How it works

  1. Hold out a test set first and do not touch it.
  2. Split the rest into training and validation, or use k-fold CV.
  3. Fit preprocessing and models on training folds only.
  4. Tune hyperparameters by validation or CV scores.
  5. Retrain the chosen model on all non-test data.
  6. Evaluate once on the test set and report.

Common mistakes

  • Tuning against the test set.
  • Fitting scalers or encoders on the full dataset before splitting.
  • Random splits on time series or grouped data.
  • Ignoring the variance across folds.

How to answer in the interview

"The training set fits the model's parameters, the validation set is used to compare models and tune hyperparameters, and the test set is kept until the end and used once for an unbiased estimate, because tuning on it makes it optimistic. Cross-validation makes better use of limited data: in k-fold, each fold takes a turn as validation and the scores are averaged, with stratified folds for imbalanced classes. For time-dependent data I use time-based or rolling splits, always training on the past, and I fit preprocessing only on training data inside a pipeline."

Likely follow-up questions

  • Why fit scaling only on training data? Otherwise test statistics leak into training, inflating scores.
  • How many folds? 5 or 10 is typical; more costs compute.
  • Nested cross-validation? Inner loop tunes, outer loop estimates performance without bias.
