How do you pass provider configurations into modules, and what is configuration_aliases for?

Terraform · concept · levels mid, senior

In one line

Configure providers in the root module; child modules inherit the default provider automatically, and for extra configurations you define an alias, pass it via the module's providers argument, and declare the expected alias in the module with configuration_aliases.

Detailed explanation

A provider configuration (region, credentials, subscription, features) describes where Terraform manages resources. Terraform's rule is that reusable modules should not configure providers; they only declare which providers they need in required_providers. The root module configures them, and every child module implicitly inherits the default (unaliased) configuration of each provider.

Many designs need more than one configuration of the same provider: a primary and a DR region, a second AWS account for DNS or logging, or a hub and spoke Azure subscription. In the root you create an aliased provider, such as provider "aws" { alias = "dr" region = "eu-west-2" }. Aliased configurations are never inherited; you pass them explicitly with providers = { aws.replica = aws.dr } in the module block, mapping the module's local name on the left to the root's configuration on the right.

Inside the module, required_providers declares configuration_aliases = [aws.replica]. This documents that the module expects a second AWS configuration, makes Terraform validate that the caller passes it, and lets resources use provider = aws.replica. Resources without a provider argument use the default aws.

Why not configure providers inside modules? A module with its own provider block cannot use count, for_each or depends_on. Worse, if you remove the module call, Terraform must destroy its resources but the provider configuration was deleted with the module, so the destroy fails with "provider configuration not present". Passing providers from the root avoids both problems.

How it works

  1. Root module defines default and aliased provider configurations.
  2. Child modules declare provider requirements, plus configuration_aliases for extra ones.
  3. Module blocks map aliases with providers = {...}.
  4. Resources select a configuration with provider = aws.<alias>.
  5. Terraform validates that all required aliases are passed.

Example

# root
provider "aws" { region = "eu-west-1" }
provider "aws" {
  alias  = "dr"
  region = "eu-west-2"
}

module "backup" {
  source    = "./modules/replicated-bucket"
  providers = { aws = aws, aws.replica = aws.dr }
}
# modules/replicated-bucket/versions.tf
terraform {
  required_providers {
    aws = {
      source                = "hashicorp/aws"
      version               = ">= 6.0"
      configuration_aliases = [aws.replica]
    }
  }
}

resource "aws_s3_bucket" "replica" {
  provider = aws.replica
  bucket   = "acme-backup-replica"
}

Common mistakes

  • Provider blocks with region or credentials inside shared modules.
  • Expecting aliased providers to be inherited automatically.
  • Trying to select providers dynamically with for_each; provider references must be static.
  • Removing a module that contains its own provider block, breaking destroy.

How to answer in the interview

"Provider configuration belongs in the root module, and child modules inherit the default provider automatically. When I need another configuration, like a DR region or a second account, I define a provider with an alias in the root and pass it explicitly with the providers argument in the module block, for example aws.replica = aws.dr. Inside the module, required_providers declares configuration_aliases = [aws.replica], which documents and validates the expectation, and resources use provider = aws.replica. Reusable modules shouldn't contain configured provider blocks, because that prevents count and for_each on the module and breaks destroy when the module is removed."

Likely follow-up questions

  • Why can a module with its own provider not be removed cleanly? The provider configuration disappears with the module, so Terraform cannot destroy its resources.
  • Same stack in five regions? One aliased provider per region and one module call per region, or Stacks with provider for_each.
  • Since which version? configuration_aliases since Terraform 0.15.
