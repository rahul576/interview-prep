What are the main memory areas in the JVM?

JVM & Performance · concept · levels entry, mid

In one line

The JVM's runtime data areas are the shared heap (objects, garbage collected) and method area/Metaspace (class metadata, native memory), and per thread a JVM stack of frames, a program counter register and a native method stack; HotSpot also has the code cache for JIT code and uses direct buffers off-heap.

Detailed explanation

Heap. Created at JVM start, shared by all threads. Every object and array lives here. Sized with -Xms/-Xmx or MaxRAMPercentage, divided into young and old generations (or regions in G1/ZGC), managed by the garbage collector. Error: OutOfMemoryError: Java heap space.

Method area (Metaspace). Logically shared storage for class-level data: class structures, field and method data, method bytecode, and the runtime constant pool. In HotSpot since Java 8 it is Metaspace in native memory, which replaced PermGen. Capped with -XX:MaxMetaspaceSize. Error: OutOfMemoryError: Metaspace (or Compressed class space).

JVM stack (per thread). Each method call pushes a frame holding local variables, an operand stack for computation, and data for returning. Size per thread set by -Xss. Errors: StackOverflowError when too deep, or OutOfMemoryError if a new thread's stack cannot be allocated.

PC register (per thread). Holds the address of the current bytecode instruction; undefined while executing native code. The only area with no OutOfMemoryError defined.

Native method stack (per thread). Used by native (JNI) code; in HotSpot it is combined with the Java stack.

Code cache. Stores machine code produced by the JIT compilers (C1/C2). If full, the JVM logs "CodeCache is full. Compiler has been disabled" and performance drops. Sized with -XX:ReservedCodeCacheSize.

Other native memory. Direct ByteBuffers (NIO, Netty) limited by -XX:MaxDirectMemorySize (error: Direct buffer memory), GC data structures, thread structures, symbol tables. Native Memory Tracking shows all of these.

Understanding these areas explains why a JVM's process memory (RSS) is always bigger than -Xmx, which is critical for container sizing.

How it works

  1. JVM starts: reserves heap, Metaspace, code cache.
  2. Classes load: metadata goes into Metaspace.
  3. Each thread gets a stack, PC register and native stack.
  4. Objects are allocated on the heap; references live in frames.
  5. JIT-compiled code is placed in the code cache.

Example

java -XX:NativeMemoryTracking=summary -Xmx1g -jar app.jar
jcmd <pid> VM.native_memory summary
Java Heap (reserved=1048576KB, committed=1048576KB)

Code (reserved=251904KB, committed=13056KB)        <- code cache
GC (reserved=60000KB, committed=60000KB)

Common mistakes

  • Listing PermGen for modern JVMs.
  • Assuming the JVM uses only -Xmx memory.
  • Forgetting the code cache and direct buffers.
  • Saying the string pool is in Metaspace (it is on the heap).

How to answer in the interview

"The runtime data areas are the heap, shared by all threads, where objects and arrays live and which the garbage collector manages; the method area, implemented since Java 8 as Metaspace in native memory, holding class metadata, method bytecode and the runtime constant pool; and per thread, a JVM stack of frames with local variables and operand stacks, a program counter register pointing at the current instruction, and a native method stack for native code. HotSpot also has the code cache for JIT-compiled code, and direct buffers live outside the heap. That's why the process uses more memory than Xmx, which matters for container sizing."

Likely follow-up questions

  • Which of these areas can throw OutOfMemoryError, and with what message? Heap ("Java heap space"), Metaspace ("Metaspace"), direct memory ("Direct buffer memory"), thread creation ("unable to create native thread"); the PC register cannot.
  • Why is RSS larger than -Xmx? Metaspace, stacks, code cache, GC structures and direct buffers are native.
  • What happens when the code cache is full? The JIT stops compiling new code, so performance degrades.
