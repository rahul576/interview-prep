What is ExecutorService, and why is it used?

Concurrency · concept · levels entry

In one line

ExecutorService (in java.util.concurrent) decouples submitting tasks from running them: it manages a pool of worker threads and a task queue, reuses threads, bounds concurrency, returns Futures, and must be shut down when no longer needed.

Detailed explanation

Creating a raw Thread per task has three problems: thread creation is relatively expensive, nothing limits how many threads exist (a traffic burst can create thousands and exhaust memory or CPU), and there is no standard way to get results, cancel tasks or stop everything cleanly.

ExecutorService solves this. You submit a Runnable or Callable; the service puts it in a queue and one of its worker threads picks it up. Threads are reused, so creation cost is paid once, and the pool size caps concurrency. You get back a Future to wait for the result (get), check completion or cancel. Bulk methods invokeAll (wait for all) and invokeAny (first successful result) handle groups of tasks. Lifecycle methods shutdown, shutdownNow and awaitTermination stop it cleanly.

The Executors class offers factory methods: newFixedThreadPool(n), newCachedThreadPool(), newSingleThreadExecutor(), newScheduledThreadPool(n) for delayed and periodic tasks, newWorkStealingPool() (a ForkJoinPool), and since Java 21 newVirtualThreadPerTaskExecutor(). Several of these use unbounded queues or unbounded threads, so for production services you usually construct a ThreadPoolExecutor directly with a bounded queue, named threads and a rejection policy. In Spring Boot you typically inject a managed ThreadPoolTaskExecutor.

Executor threads are non-daemon by default, so an executor that is never shut down can keep the JVM running. Since Java 19 ExecutorService implements AutoCloseable, so try-with-resources shuts it down and waits for tasks automatically.

How it works

  1. Create the executor (factory or ThreadPoolExecutor).
  2. submit(task) puts the task in the work queue (or hands it to an idle thread).
  3. A worker thread takes the task, runs it, stores the result in the Future.
  4. The caller retrieves results with Future.get() or invokeAll.
  5. Call shutdown() and awaitTermination() (or close()) at the end.

Example

try (ExecutorService pool = Executors.newFixedThreadPool(4)) {     // Java 19+ AutoCloseable
    List<Callable<Integer>> jobs = List.of(
            () -> countRows("orders"),
            () -> countRows("customers"),
            () -> countRows("invoices"));

    for (Future<Integer> f : pool.invokeAll(jobs, 10, TimeUnit.SECONDS)) {
        System.out.println(f.get());
    }
}   // close() = shutdown + wait

ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(1);
scheduler.scheduleAtFixedRate(this::refreshCache, 0, 5, TimeUnit.MINUTES);

Common mistakes

  • Never shutting down the executor.
  • Creating a new executor per request instead of sharing one.
  • Using unbounded factories in production without understanding the risks.
  • Submitting tasks and ignoring the Futures, losing exceptions.

How to answer in the interview

"ExecutorService decouples submitting tasks from running them. It manages a pool of worker threads and a task queue: I submit Runnables or Callables and get Futures back, and the executor reuses threads instead of creating one per task, which saves creation cost and limits how many run at once, so a burst of work doesn't exhaust memory or CPU. Executors provides factories like fixed, cached, scheduled and, since Java 21, virtual-thread-per-task, but in production I prefer a ThreadPoolExecutor with a bounded queue and rejection policy. And I always shut it down, with shutdown and awaitTermination or try-with-resources."

Likely follow-up questions

  • Why is an unbounded queue in a fixed thread pool risky? Under overload tasks accumulate without limit, latency grows and memory can run out, with no backpressure.
  • Executor vs ExecutorService? Executor only has execute(Runnable); ExecutorService adds submit, Futures, bulk invocation and lifecycle.
  • What does ScheduledExecutorService add? schedule, scheduleAtFixedRate and scheduleWithFixedDelay for delayed and periodic tasks.
