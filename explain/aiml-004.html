Explain the bias-variance trade-off.

AI/ML & GenAI · concept · levels mid, senior

In one line

Bias is error from overly simple assumptions (underfitting); variance is error from sensitivity to the training data (overfitting); total error is bias² + variance + irreducible noise, and you balance them with model complexity, regularisation, more data and validation.

Detailed explanation

Imagine training the same model type many times on different samples of data. Bias measures how far the average prediction is from the truth: a model that is too simple, like a straight line fitted to a curved relationship, misses the pattern every time, scoring poorly on both training and test data. That is underfitting.

Variance measures how much predictions change between those training samples. A very flexible model, like a deep, unpruned decision tree, fits each sample's noise, so it scores very well on training data but poorly on new data. That is overfitting.

For squared error, expected error decomposes into bias squared + variance + irreducible noise. The noise cannot be removed by any model. Increasing complexity usually lowers bias and raises variance, so error on unseen data typically follows a U-shape, and the best model sits near the bottom.

We control the trade-off by choosing model complexity (tree depth, polynomial degree, number of features), adding regularisation (L1/L2, dropout), getting more training data (which mainly reduces variance), using ensembles (bagging such as random forests reduces variance; boosting reduces bias), and tuning with validation sets or cross-validation.

Deep learning complicates the classic picture: very large, over-parameterised networks trained on huge datasets often generalise well, and double descent shows test error can fall again beyond the point of interpolating training data. The trade-off remains a useful guide, but it is more nuanced there.

How it works

  1. Train models of increasing complexity.
  2. Measure training and validation error for each.
  3. High error on both: high bias, so increase capacity or features.
  4. Low training error, high validation error: high variance, so regularise, simplify or add data.
  5. Pick the complexity with lowest validation error.

Example

from sklearn.tree import DecisionTreeRegressor
from sklearn.model_selection import cross_val_score

for depth in [1, 2, 4, 8, 16, None]:
    model = DecisionTreeRegressor(max_depth=depth, random_state=0)
    train = model.fit(X, y).score(X, y)
    cv = cross_val_score(model, X, y, cv=5).mean()
    print(depth, round(train, 2), round(cv, 2))
# depth 1: train 0.41, cv 0.39 → high bias
# depth 4: train 0.83, cv 0.78 → good balance
# None:    train 1.00, cv 0.55 → high variance

Common mistakes

  • Adding more data to fix a high-bias model.
  • Judging a model only on training performance.
  • Thinking bias here means fairness bias.
  • Applying the classic U-curve rigidly to large neural networks.

How to answer in the interview

"Bias is error from overly simple assumptions, like a linear model on curved data, which underfits and does badly on training and test data. Variance is sensitivity to the specific training data, like a very deep tree that memorises noise and does well on training but poorly on new data. More complexity usually lowers bias but raises variance, so we look for the balance that minimises error on unseen data, using validation or cross-validation, regularisation, more data and the right model complexity. In deep learning the picture is more nuanced, since huge models often still generalise well."

Likely follow-up questions

  • Learning curves? Converging high curves mean bias; a persistent gap means variance.
  • Bagging vs boosting? Bagging reduces variance; boosting reduces bias.
  • Double descent? Test error can drop again beyond the interpolation point.
