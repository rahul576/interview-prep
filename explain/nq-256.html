Given Customer and Orders tables, write a query to calculate total revenue per customer per year.

Databases & SQL · scenario · levels mid

In one line

Join customers to orders on customer_id, extract the year from the order date, SUM the amount, and GROUP BY customer and year, grouping by the id (not just the name) and filtering out cancelled orders.

Detailed explanation

Each order belongs to one customer through the foreign key orders.customer_id. To get revenue per customer per year:

  1. Join customer and orders on customer_id so each order row carries its customer's details.
  2. Derive the year: EXTRACT(YEAR FROM order_date) is standard SQL and works in PostgreSQL, Oracle and MySQL; YEAR(order_date) works in MySQL and SQL Server.
  3. Aggregate with SUM(amount).
  4. Group by the customer key and the year. Include customer_id, not only name, so two different customers called "Rahul Mehta" are not merged. Including name in the GROUP BY is needed in strict SQL modes; PostgreSQL also allows it to be omitted when grouping by the primary key, because name is functionally dependent on it.
  5. Order by name and year for readability.

Practical refinements an interviewer likes to hear:

  • Status filter: exclude cancelled or refunded orders (WHERE o.status NOT IN ('CANCELLED', 'REFUNDED')) or define revenue per the business rule.
  • Line-level revenue: if the amount lives in order_items, join that table and sum quantity * unit_price, being careful not to double-count when joining several one-to-many tables.
  • Customers without orders: use LEFT JOIN and COALESCE(SUM(o.amount), 0); note that their year will be NULL unless you build a calendar of years with a cross join.
  • Performance: an index on orders(customer_id, order_date) (or including amount) helps; for date ranges, filter with order_date >= '2025-01-01' AND order_date < '2026-01-01' rather than wrapping the column in a function, so an index on order_date can be used.
  • Money types: amounts should be DECIMAL/NUMERIC, not floating point.

How it works

  1. FROM/JOIN combines each order with its customer.
  2. WHERE removes cancelled orders.
  3. GROUP BY forms one group per customer and year.
  4. SUM computes revenue per group.
  5. ORDER BY sorts the output.

Example

SELECT c.customer_id,
       c.name,
       EXTRACT(YEAR FROM o.order_date) AS order_year,
       SUM(o.amount)                   AS total_revenue
FROM customer c
JOIN orders o ON o.customer_id = c.customer_id
WHERE o.status <> 'CANCELLED'
GROUP BY c.customer_id, c.name, EXTRACT(YEAR FROM o.order_date)
ORDER BY c.name, order_year;

-- Revenue from line items instead
SELECT c.customer_id, c.name, EXTRACT(YEAR FROM o.order_date) AS order_year,
       SUM(oi.quantity * oi.unit_price) AS total_revenue
FROM customer c
JOIN orders o       ON o.customer_id = c.customer_id
JOIN order_items oi ON oi.order_id   = o.order_id
GROUP BY c.customer_id, c.name, EXTRACT(YEAR FROM o.order_date);

Common mistakes

  • Grouping only by name, merging different customers.
  • Selecting non-aggregated columns that are not in GROUP BY.
  • Forgetting to exclude cancelled or refunded orders.
  • Double-counting by joining items and payments in the same query.
  • Using YEAR() in a database that does not support it.

How to answer in the interview

"I'd join customer and orders on customer id, extract the year from the order date with EXTRACT, or YEAR in MySQL, sum the amount, and group by customer id, name and year, ordering by name and year. I group by customer id as well as name so two customers with the same name aren't merged. I'd also confirm the business definition of revenue, for example excluding cancelled orders, and if the amounts live in an order items table, I'd join that and sum quantity times unit price. An index on orders customer id and order date keeps it efficient."

Likely follow-up questions

  • Include customers with no orders as zero? LEFT JOIN from customer and COALESCE(SUM(o.amount), 0).
  • Show year-over-year growth? Use LAG(total_revenue) OVER (PARTITION BY customer_id ORDER BY order_year).
  • Only customers above 10,000 a year? Add HAVING SUM(o.amount) > 10000.
