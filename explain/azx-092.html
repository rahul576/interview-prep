How would you build a RAG solution on Azure with Azure AI Search?

Azure AI & Foundry · design · levels mid, senior, lead

In one line

Build RAG on Azure by ingesting documents with AI Search indexers and skillsets (cracking, OCR, chunking), integrated vectorization for embeddings, hybrid search (BM25 + vectors fused with RRF) plus the semantic ranker, security trimming by user permissions, and a grounded prompt with citations, evaluated continuously.

Detailed explanation

Ingestion: an indexer pulls from a data source such as Blob Storage, ADLS, SharePoint or Azure SQL on a schedule, tracking changes. A skillset cracks documents (PDF, Office, HTML), optionally runs OCR on images, and uses a text split skill to create chunks with overlap (for example 512 tokens with 10-20% overlap) so each chunk fits the model context and keeps meaning. Index projections write each chunk as its own search document with a parent ID, title, URL and metadata.

Integrated vectorization: an embedding skill calls an embedding model deployed in Foundry (for example text-embedding-3-large) to vectorize each chunk at indexing time, and a vectorizer on the index embeds the user's query at search time, so the app sends plain text.

Retrieval: hybrid search runs BM25 keyword search and vector similarity in parallel and merges results with reciprocal rank fusion. Keywords catch exact terms (product codes, names), vectors catch meaning. The semantic ranker then reranks the top results with a cross-encoder model, which noticeably improves relevance, and can produce captions.

Security trimming: users must only retrieve chunks from documents they may see. Store permitted group IDs on each chunk and add a filter with the user's groups, or use the newer document-level access control that carries source permissions (ACLs or Entra-based) into the index.

Generation: the top 3-8 chunks go into the prompt with instructions to answer only from the sources, say "I don't know" otherwise, and cite chunk titles or URLs. Evaluate retrieval quality (recall, ranking) and answer quality (groundedness, relevance) with a test set, and monitor in production. For complex questions, agentic retrieval can split queries into sub-queries.

How it works

  1. Data source + indexer + skillset (crack, OCR, split, embed).
  2. Index with text, vector and filter fields, semantic configuration and vectorizer.
  3. Query: hybrid search with user's permission filter, semantic rerank.
  4. Build the prompt with top chunks and citations.
  5. Call the chat model; return answer with sources.
  6. Evaluate offline and monitor online.

Example

POST /indexes/policies/docs/search?api-version=2024-07-01
{
  "search": "How many days of parental leave do I get?",
  "vectorQueries": [{ "kind": "text", "text": "How many days of parental leave do I get?",
                      "fields": "contentVector", "k": 50 }],
  "queryType": "semantic",
  "semanticConfiguration": "default",
  "filter": "group_ids/any(g: search.in(g, 'hr-all,emp-nl'))",
  "select": "title,url,chunk",
  "top": 5
}

Common mistakes

  • Pure vector search, missing exact identifiers.
  • Chunks too large or without overlap, hurting precision.
  • Filtering permissions in the app after retrieval, leaking into the prompt.
  • No evaluation set, so changes are judged by gut feeling.

How to answer in the interview

"Indexers ingest documents from Blob, SharePoint or databases on a schedule, and a skillset cracks them, runs OCR and splits them into overlapping chunks. Integrated vectorization calls a Foundry embedding model at indexing and query time. At query time I use hybrid search, BM25 plus vectors merged with reciprocal rank fusion, then the semantic ranker reranks the top results. Security trimming filters by the user's groups or uses document-level access control. The top chunks go into the prompt with instructions to answer only from them and cite sources, and I evaluate retrieval and answers continuously."

Likely follow-up questions

  • How to handle deleted documents? A soft-delete detection policy on the data source so the indexer removes them.
  • How to choose chunk size? Experiment with the evaluation set; typically a few hundred tokens with overlap.
  • When use agentic retrieval? Multi-part or conversational questions needing several sub-queries.
