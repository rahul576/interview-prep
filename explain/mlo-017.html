What is the difference between data drift and concept drift, and how do you detect them?

MLOps · concept · levels mid, senior

In one line

Data drift (covariate shift) is a change in the input distribution; concept drift is a change in the relationship between inputs and target. Data drift is detected immediately with PSI, KS, chi-squared or KL/JS divergence; concept drift usually shows only through falling performance once labels arrive or through proxies. Tune thresholds to avoid false alarms.

Detailed explanation

Data drift means P(X) changes: a marketing campaign brings younger customers, a new market opens, or a sensor is recalibrated. The model may still be correct for each input, but it now sees regions of feature space it was trained on less. Concept drift means P(Y|X) changes: fraudsters change tactics, customer preferences shift after a price change, or a regulation changes what counts as default. The same inputs now lead to different outcomes, so the model is wrong even if inputs look identical. A related case is label (prior) shift, where the base rate of the target changes.

Detecting data drift compares current feature distributions with a reference (training data or a stable recent window). Common methods: the Population Stability Index (rule of thumb: below 0.1 stable, 0.1 to 0.25 moderate, above 0.25 significant), the Kolmogorov-Smirnov test for numeric features, chi-squared for categorical ones, and KL or Jensen-Shannon divergence or Wasserstein distance. Multivariate drift can be found with a domain classifier that tries to distinguish reference from current data. Tools: Evidently, WhyLabs, NannyML, and cloud monitors in SageMaker, Azure ML and Vertex AI.

Detecting concept drift requires labels: monitor performance as ground truth arrives, or use proxies such as analyst feedback, complaints, or estimated performance methods. With large samples, statistical tests flag tiny, harmless differences as significant, so prefer effect-size metrics, weight by feature importance and tune thresholds on history.

How it works

  1. Store a reference distribution per feature and for predictions.
  2. Compute drift statistics per window (hourly, daily) and per segment.
  3. Weight alerts by feature importance; combine with prediction drift.
  4. Join labels when available and track performance over time.
  5. Investigate pipeline health before treating drift as real.
  6. Retrain or adjust when drift is real and impacts performance.

Example

import numpy as np

def psi(ref, cur, bins=10):
    edges = np.quantile(ref, np.linspace(0, 1, bins + 1))
    r = np.histogram(ref, edges)[0] / len(ref) + 1e-6
    c = np.histogram(cur, edges)[0] / len(cur) + 1e-6
    return float(np.sum((c - r) * np.log(c / r)))

Common mistakes

  • Treating every statistically significant drift as a problem.
  • Assuming no data drift means the model is fine (concept drift is invisible to input checks).
  • Monitoring only global distributions, not segments.
  • Forgetting pipeline bugs that mimic drift.

How to answer in the interview

"Data drift is a change in the input distribution, like a campaign bringing younger customers. Concept drift is a change in how inputs relate to the target, like fraudsters changing tactics, so the same inputs mean something different. Data drift I can detect immediately with PSI, KS or chi-squared tests or divergence measures against a reference, using tools like Evidently. Concept drift usually shows only as falling performance once labels arrive, or via proxies. I tune thresholds and weight by feature importance, because with big samples tests flag harmless changes."

Likely follow-up questions

  • Why can a model degrade with no data drift? Concept drift, or a change in an unmonitored feature or label definition.
  • What is a domain classifier? A model trained to tell reference from current data; high AUC means multivariate drift.
  • How often to compute drift? Matching traffic volume and decision cadence, often daily with hourly for critical models.
