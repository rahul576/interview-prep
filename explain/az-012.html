When would you use Azure Functions, Container Apps, App Service or AKS?

Azure · concept · levels mid

In one line

Functions for short event-driven code, Container Apps for serverless containers and microservices with KEDA scaling and scale-to-zero, App Service for straightforward web apps and APIs, and AKS when you need full Kubernetes control; the trade-off is control versus operational effort.

Detailed explanation

Azure Functions runs small pieces of code in response to triggers: HTTP, timers, queues, Service Bus, Event Hubs, Blob or Cosmos DB changes, with bindings reducing integration code. On the Flex Consumption or Consumption plans you pay per execution and it scales automatically, including to zero; Premium plans avoid cold starts and add VNet integration. Durable Functions adds stateful orchestrations. It suits glue code, event processing and scheduled jobs, less so long-running or chatty services.

Azure Container Apps runs any container on a managed Kubernetes-based platform without exposing the cluster. It provides KEDA-based autoscaling on HTTP, queue length or custom metrics, scale to zero, revisions with traffic splitting, built-in ingress, Dapr integration for service invocation and pub/sub, jobs, and workload profiles including GPUs. It is ideal for microservices and background workers when you do not want to run Kubernetes yourself.

Azure App Service is a mature PaaS for web apps and APIs, from code or containers, with deployment slots, built-in authentication, autoscale, custom domains and certificates. It suits traditional web applications and teams that want minimal operations.

Azure Kubernetes Service (AKS) gives you real Kubernetes: custom networking, service meshes, operators, CRDs, GitOps, specialised node pools and portability. Microsoft manages the control plane, but you own upgrades, node pools, add-ons, security and capacity. AKS Automatic reduces some of that effort with opinionated defaults. Choose AKS when you need Kubernetes features or run a platform for many teams.

How it works

  1. Start from workload shape: event-driven function, container service, or web app.
  2. Consider team skills and operational capacity.
  3. Check needs: scale-to-zero, VNet, long-running, GPUs, custom networking.
  4. Prefer the most managed option that meets requirements.
  5. Revisit as scale and team size grow.

Example

Deploying a microservice to Container Apps with queue-based scaling:

az containerapp create -g rg-shop -n orders-worker \
  --environment cae-shop --image acrshop.azurecr.io/orders-worker:1.4.2 \
  --min-replicas 0 --max-replicas 20 \
  --scale-rule-name sb-queue --scale-rule-type azure-servicebus \
  --scale-rule-metadata queueName=orders namespace=sb-shop messageCount=50 \
  --scale-rule-identity <user-assigned-identity-id>

Common mistakes

  • Choosing AKS by default for a small team with a few services.
  • Putting long-running, CPU-heavy work into consumption Functions.
  • Ignoring cold start for latency-sensitive Functions.
  • Using App Service for many tiny microservices with complex service-to-service needs.
  • Not considering cost at idle versus at steady high load.

How to answer in the interview

"Azure Functions fits short, event-driven code triggered by queues, timers or HTTP, billed per execution on the Flex Consumption plan. Container Apps runs containers serverlessly on a managed Kubernetes-based platform with KEDA autoscaling, scale to zero, revisions and Dapr, which suits microservices without managing a cluster. App Service is a simple, mature platform for web apps and APIs with slots and built-in auth. AKS gives full Kubernetes control for complex platforms, custom networking and operators, but brings the most operational effort. I choose the most managed option that meets the requirements, because the trade-off is control versus operations."

Likely follow-up questions

  • A team of three wants to run eight microservices. What would you recommend? Container Apps: microservice features without cluster operations.
  • When would you move from Container Apps to AKS? When you need custom operators, meshes, node-level control or a multi-team platform.
  • How do you avoid Function cold starts? Premium or Flex Consumption with always-ready instances.
