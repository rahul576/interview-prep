What is aggregation, and how does it differ from composition?

Core Java & OOP · concept · levels entry

In one line

Both are has-a whole-part relationships, but aggregation has weak ownership: parts have their own lifecycle and can be shared; composition has strong, exclusive ownership: parts are created and destroyed with the whole and never shared.

Detailed explanation

Aggregation says "this whole groups these parts". A football team has players, but players existed before joining, can be transferred to another team, and still exist if the team is dissolved. A playlist contains songs, but deleting the playlist doesn't delete the songs from the library, and the same song can be in many playlists. The whole holds references to parts that live independently.

Composition says "this whole is made of these parts and owns them". An Order consists of OrderLines: a line makes no sense without its order, can't move to another order, and is deleted with it. A House has Rooms. The owner is responsible for creating parts and controlling their lifecycle.

The test questions:

  1. Can the part exist without the whole? Yes points to aggregation.
  2. Can the part be shared by several wholes or moved? Yes points to aggregation.
  3. Should deleting the whole delete the parts? Yes points to composition.

How it typically looks in Java:

  • Aggregation: parts are passed in from outside (constructor or setter), the whole stores references, and other objects may hold references to the same parts.
  • Composition: parts are created inside the owner (often in its methods, from raw data), kept private, not exposed for others to keep, and often immutable value objects or package-private classes.

The classification can depend on the domain. A car and its engine is usually composition in a car-sales model (the engine is part of that car), but in a garage-management system, engines are tracked separately, swapped between cars and have their own serial numbers, so it becomes aggregation. Interviewers like this nuance.

In persistence: composition maps to cascade = ALL, orphanRemoval = true or @Embedded/@ElementCollection; aggregation must not cascade remove.

How it works

  1. Identify the whole and the part.
  2. Apply the existence, sharing and deletion tests.
  3. For aggregation, inject part references; for composition, construct parts internally.
  4. Encapsulate composition parts; never return mutable internals.
  5. Reflect the choice in database cascades.

Example

// Aggregation: players come from outside and can move
class Team {
    private final Set<Player> players = new HashSet<>();
    void sign(Player p)    { players.add(p); }
    void release(Player p) { players.remove(p); }     // player still exists
}

// Composition: lines are created and owned by the order
class Order {
    private final List<OrderLine> lines = new ArrayList<>();
    void add(String sku, int qty, BigDecimal price) { lines.add(new OrderLine(sku, qty, price)); }
    BigDecimal total() { return lines.stream().map(OrderLine::amount).reduce(BigDecimal.ZERO, BigDecimal::add); }
}
record OrderLine(String sku, int qty, BigDecimal price) {
    BigDecimal amount() { return price.multiply(BigDecimal.valueOf(qty)); }
}

Common mistakes

  • Deciding by syntax instead of lifecycle.
  • Exposing composition parts through mutable getters.
  • Cascade-deleting aggregated parts.
  • Ignoring that the domain context can change the answer.

How to answer in the interview

"Both are has-a, whole-part relationships. In aggregation ownership is weak: the part has its own lifecycle, can exist before and after the whole, and can be shared, like a team and its players, where a player can move teams. In composition ownership is strong and exclusive: the part is created and destroyed with the whole and isn't shared, like an Order and its OrderLines. In Java, aggregation usually means references passed in from outside, while composition parts are created inside the owner and never exposed for others to keep."

Likely follow-up questions

  • Is a car and its engine aggregation or composition, and why? Depends on the domain: composition if the engine is just part of the car, aggregation if engines are tracked and swapped independently.
  • How do you map composition in JPA? Cascade ALL with orphanRemoval, or embeddables.
  • Can composition parts be immutable? Ideally yes, as value objects.
