Explain try, catch, finally, throw, and throws.

Exceptions · concept · levels entry, mid

In one line

try wraps code that may throw, catch handles specific exception types (most specific first), finally always runs for cleanup, throw raises an exception object, and throws declares checked exceptions in a method signature.

Detailed explanation

These five keywords form Java's exception mechanism.

try marks a block whose exceptions you want to handle or clean up after. It must be followed by at least one catch or a finally (or be a try-with-resources).

catch (Type e) handles exceptions assignable to that type. Multiple catch blocks are checked top to bottom, so order them from most specific to most general; putting catch (Exception e) before catch (IOException e) is a compile error because the second is unreachable. Since Java 7, multi-catch (catch (IOException | SQLException e)) handles unrelated types with the same code; the variable is implicitly final.

finally runs after try and any catch, whether the block completed normally, threw, or returned. It is used for cleanup that must happen: releasing locks, resetting state, closing resources. For anything AutoCloseable, try-with-resources is preferred because it closes automatically in reverse order and records suppressed exceptions. Avoid return or throw inside finally because they mask the original outcome.

throw raises an exception instance: throw new IllegalArgumentException("amount must be positive"). It can also rethrow a caught exception.

throws in a method signature declares exceptions that may propagate, for example String read(Path p) throws IOException. It is mandatory for checked exceptions not handled inside the method and optional for unchecked ones.

Good practice: catch only what you can handle, keep the cause when wrapping, and let the rest propagate to a central handler.

How it works

  1. Code in try runs; if no exception, catch blocks are skipped.
  2. If an exception is thrown, the JVM checks catch clauses in order for the first matching type.
  3. The matching catch runs; if none matches, the exception continues propagating.
  4. finally runs in every case before control leaves the statement.
  5. Unhandled exceptions move up the call stack.

Example

public Config load(Path path) throws ConfigException {          // declares
    if (path == null) throw new IllegalArgumentException("path required"); // raises
    lock.lock();
    try {
        String json = Files.readString(path);
        return mapper.readValue(json, Config.class);
    } catch (NoSuchFileException e) {                             // specific first
        return Config.defaults();
    } catch (IOException e) {                                     // general after
        throw new ConfigException("Cannot read " + path, e);      // keep cause
    } finally {
        lock.unlock();                                            // always runs
    }
}

Common mistakes

  • Catching Exception first and making later catches unreachable.
  • Empty catch blocks.
  • Using finally for closing streams instead of try-with-resources.
  • Returning from finally, which swallows exceptions.

How to answer in the interview

"try wraps code that might throw. One or more catch blocks follow, each handling a specific type, ordered from most specific to most general, or combined with multi-catch. finally always runs after try and catch, whether or not an exception occurred, so it's used for cleanup like releasing locks, although for closing resources I prefer try-with-resources. throw is the statement that raises an exception object, like throw new IllegalArgumentException. throws is part of the method signature and declares checked exceptions the method may propagate, such as IOException."

Likely follow-up questions

  • Why should catch blocks go from specific to general? The first match wins, and a general catch first makes specific ones unreachable (compile error).
  • Can you catch multiple exceptions in one block? Yes, multi-catch with |.
  • Does finally run after return? Yes, before the method actually returns.
