Which BlockingQueue implementations exist, and how do you implement producer-consumer with them?

Collections · concept · levels mid, senior

In one line

Main BlockingQueue types are ArrayBlockingQueue (bounded), LinkedBlockingQueue (optionally bounded), SynchronousQueue (direct hand-off), DelayQueue and PriorityBlockingQueue; in producer-consumer, put blocks when full and take blocks when empty, giving back-pressure, with poison pills or interruption for shutdown.

Detailed explanation

BlockingQueue adds waiting operations to Queue. There are four styles: add/remove throw, offer/poll return immediately, put/take block forever, and offer(e, timeout)/poll(timeout) block for a limited time.

  • ArrayBlockingQueue: fixed capacity array, one lock for both ends, optional fairness.
  • LinkedBlockingQueue: linked nodes, separate put and take locks; capacity defaults to Integer.MAX_VALUE, so always pass a bound in production.
  • SynchronousQueue: zero capacity; each put waits for a take. Used by Executors.newCachedThreadPool, so a task is handed to an idle thread or a new thread is created.
  • PriorityBlockingQueue: unbounded heap, takes the highest priority first.
  • DelayQueue: elements implement Delayed and become available only after their delay expires, good for retries and timeouts.
  • Also LinkedTransferQueue and LinkedBlockingDeque.

In producer-consumer, the queue decouples speeds. With a bounded queue, a fast producer blocks on put instead of exhausting memory: that is back-pressure. Consumers take and process. Shutdown is the tricky part: either enqueue a poison pill (one per consumer) so they exit after draining, or interrupt them (take throws InterruptedException). Today you would usually let an ExecutorService manage consumers.

How it works

  1. Create a bounded queue sized for your burst tolerance.
  2. Producers call put (or offer with timeout to fail fast).
  3. Consumers loop on take, process, repeat.
  4. On shutdown, producers send one poison pill per consumer.
  5. Consumers exit when they see the pill; join or await them.

Example

BlockingQueue<Order> q = new ArrayBlockingQueue<>(1_000);
Order POISON = new Order(-1);

Runnable producer = () -> {
    for (Order o : source) q.put(o);          // blocks when full
    for (int i = 0; i < CONSUMERS; i++) q.put(POISON);
};
Runnable consumer = () -> {
    while (true) {
        Order o = q.take();                    // blocks when empty
        if (o == POISON) return;
        process(o);
    }
};

(Interrupt handling omitted for brevity; real code must catch InterruptedException and restore the flag.)

Common mistakes

  • Unbounded LinkedBlockingQueue hiding a backlog until OutOfMemoryError.
  • Swallowing InterruptedException in consumers.
  • Sending one poison pill for many consumers.
  • Busy-polling with poll() in a loop instead of blocking.

How to answer in the interview

"The main implementations are ArrayBlockingQueue, bounded; LinkedBlockingQueue, optionally bounded; SynchronousQueue with zero capacity for direct hand-off; DelayQueue for delayed items; and PriorityBlockingQueue. For producer-consumer, producers call put, which blocks when the queue is full, and consumers call take, which blocks when it's empty, so a bounded queue gives natural back-pressure. To stop consumers I send a poison pill per consumer or interrupt them, and I use offer and poll with timeouts when blocking forever isn't acceptable."

Likely follow-up questions

  • Which queue does newCachedThreadPool use? SynchronousQueue, so tasks go straight to a thread and new threads are created as needed.
  • ArrayBlockingQueue vs LinkedBlockingQueue? One lock and preallocated array vs two locks and per-node allocation.
  • What does drainTo do? Moves available elements in bulk, useful for batching.
