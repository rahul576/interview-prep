Compare VPC peering, Transit Gateway and PrivateLink.

Cloud (AWS) · concept · levels mid

In one line

VPC peering is a one-to-one, non-transitive private link between two VPCs with no overlapping CIDRs; Transit Gateway is a regional hub connecting many VPCs, VPNs and Direct Connect with central route tables; PrivateLink exposes one service through interface endpoints, works with overlapping CIDRs and gives consumers access to only that service.

Detailed explanation

VPC peering connects two VPCs, in the same or different accounts and regions, so instances communicate over private IPs on the AWS backbone. There is no gateway in the path, no bandwidth bottleneck and no hourly charge (you pay normal data transfer). But peering is not transitive: if A peers with B and B with C, A cannot reach C through B. Connecting N VPCs needs up to N(N-1)/2 peerings, and each side's route tables must be updated. CIDRs must not overlap. It suits a few VPCs with simple relationships.

Transit Gateway (TGW) is a managed hub-and-spoke router in a region. Each VPC, Site-to-Site VPN and Direct Connect gateway attaches once. TGW route tables and associations control which attachments can reach which, enabling segmentation (prod cannot talk to dev, everything reaches shared services), centralised egress and inspection through a firewall VPC. TGWs in different regions can peer. It scales to thousands of attachments. Costs are per attachment-hour plus per GB processed, so it is not free for heavy traffic. AWS Cloud WAN builds on similar concepts for global networks.

PrivateLink works differently: it connects a service, not networks. A provider puts the service behind a Network Load Balancer (or other supported targets) and creates an endpoint service; consumers create interface VPC endpoints, ENIs with private IPs in their subnets. Traffic is one-directional (consumer to service), consumers see nothing else in the provider VPC, and because traffic is NATed through the endpoint, overlapping CIDRs are fine. Providers approve connections and can allow-list accounts. AWS services themselves (ECR, STS, SQS) are offered this way, and it is the standard for SaaS providers serving many customer VPCs. Charges are per endpoint-hour per AZ and per GB.

How it works

  1. Peering: request and accept, then add routes on both sides.
  2. TGW: create the hub, attach VPCs, configure route tables and propagation.
  3. PrivateLink: provider creates NLB and endpoint service; consumer creates interface endpoint.
  4. Security groups and NACLs still apply in all cases.

Example

Need                                         Choice
2-3 VPCs, simple, no overlap                 VPC peering
40 VPCs + on-prem VPN + segmentation          Transit Gateway
SaaS API to 50 customer VPCs (CIDRs overlap)  PrivateLink endpoint service
aws ec2 create-vpc-endpoint-service-configuration \
  --network-load-balancer-arns arn:aws:elasticloadbalancing:...:loadbalancer/net/api-nlb/abc \
  --acceptance-required

Common mistakes

  • Expecting transitive routing through a peered VPC.
  • Designing overlapping CIDRs and later needing peering or TGW.
  • Using TGW for one high-volume VPC pair and paying processing charges.
  • Using PrivateLink when two-way network connectivity is required.

How to answer in the interview

"VPC peering connects two VPCs directly over private IPs. It's simple with no extra hop, but it isn't transitive, so many VPCs need a mesh of peerings, and CIDRs can't overlap. Transit Gateway is a regional hub: each VPC, VPN and Direct Connect attaches once, and TGW route tables control who reaches whom, scaling to thousands of VPCs at a per-attachment and per-GB cost. PrivateLink exposes one service behind an NLB as interface endpoints in consumer VPCs; it works with overlapping CIDRs and gives consumers access only to that service, which is ideal for SaaS."

Likely follow-up questions

  • Let 50 customer VPCs access your SaaS API privately? PrivateLink endpoint service with an NLB and allow-listed accounts.
  • Can peering span regions? Yes, inter-region peering is supported.
  • How do you inspect traffic centrally? TGW routing through an inspection VPC with AWS Network Firewall.
