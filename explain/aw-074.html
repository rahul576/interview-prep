A Lambda function is timing out or being throttled in production. How do you troubleshoot?

Cloud (AWS) · scenario · levels senior

In one line

Use the function's CloudWatch metrics (Duration, Errors, Throttles, ConcurrentExecutions) to tell timeouts from throttling, use X-Ray traces and REPORT log lines to find slow downstream calls, VPC issues or cold starts, and fix throttling by managing account and reserved concurrency and buffering bursts with SQS.

Detailed explanation

Identify the problem: timeouts show up as Task timed out after N seconds in logs and as errors with Duration at the configured limit. Throttling shows in the Throttles metric and as TooManyRequestsException (HTTP 429) for synchronous callers; asynchronous and event source invocations retry automatically.

Timeouts: the REPORT line for each invocation shows duration, billed duration, memory used and Init Duration for cold starts. X-Ray or OpenTelemetry traces show which subsegment is slow. Typical causes are a slow downstream API or database without its own client timeout, waiting on database connections (consider RDS Proxy), a function in a VPC without a NAT or VPC endpoint so calls hang until timeout, large cold starts for Java or .NET (use SnapStart or provisioned concurrency), or simply too little memory. Lambda allocates CPU proportionally to memory, so raising memory often reduces duration and cost; Lambda Power Tuning finds the sweet spot.

Throttling: each account has a regional concurrency quota (often 1,000 by default, lower on new accounts) shared by all functions, and scaling speed is limited (each function can add up to 1,000 concurrent executions every 10 seconds). Reserved concurrency guarantees capacity for one function but also caps it; an over-reserved neighbour or runaway function can starve others. Concurrency equals requests per second times average duration, so slow downstream calls also increase throttling. Fixes: request a quota increase, set reserved concurrency for critical functions and caps for noisy ones, use provisioned concurrency for predictable bursts, reduce duration, and put SQS (with a maximum concurrency setting on the event source mapping) in front of bursty synchronous producers.

How it works

  1. Check Errors versus Throttles and ConcurrentExecutions over time.
  2. For timeouts, read REPORT lines and traces to find the slow segment.
  3. Verify VPC routing, client timeouts and connection handling.
  4. Tune memory and cold starts.
  5. For throttles, review account concurrency and reserved settings.
  6. Add queues, retries with backoff and alarms.

Example

aws logs start-query --log-group-name /aws/lambda/checkout \
  --start-time $(date -d '-1 hour' +%s) --end-time $(date +%s) \
  --query-string 'filter @type = "REPORT"
    | stats max(@duration), avg(@duration), max(@initDuration), count(*) by bin(5m)'

aws lambda put-function-concurrency --function-name checkout \
  --reserved-concurrent-executions 200
import requests
# client timeout well below the 30 s function timeout
resp = requests.get(PAYMENTS_URL, timeout=(2, 5))

Common mistakes

  • Raising the function timeout instead of finding the slow dependency.
  • HTTP or database clients with no timeouts.
  • Reserved concurrency on many functions, starving the rest of the account.
  • Forgetting that VPC functions need NAT or endpoints to reach AWS APIs.

How to answer in the interview

"I start with CloudWatch: Duration, Errors, Throttles and ConcurrentExecutions tell me whether it is timeouts or throttling. For timeouts, X-Ray traces and the REPORT lines show where time goes: usually a slow downstream call without its own timeout, slow database connections, a VPC function with no route to the service, or cold starts for big Java functions. More memory also means more CPU. Throttling means the account limit or a function's reserved concurrency is hit, so I check other functions using the pool, request an increase and put SQS in front of bursty producers."

Likely follow-up questions

  • Why set a client timeout shorter than the function timeout? So the function can handle the failure, log it and return or retry instead of being killed.
  • What is the difference between reserved and provisioned concurrency? Reserved guarantees and caps capacity; provisioned keeps environments pre-initialised to avoid cold starts.
  • How do you limit Lambda load on a database? Reserved concurrency or SQS maximum concurrency, plus RDS Proxy.
