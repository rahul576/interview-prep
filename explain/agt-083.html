How would you explain to business stakeholders what AI agents can and cannot do today?

AI Agents & AIOps · concept · levels entry

In one line

Explain agents as software that completes multi-step tasks using tools and company data, strong today for well-defined tasks with clear success checks, but still making mistakes and needing oversight for important decisions; start with assistance, automate as reliability is proven, and remember value depends on data, integration and process change, measured by outcomes, not hype.

Detailed explanation

Business stakeholders hear two extreme stories: agents will replace whole departments, or they are just chatbots. A good explanation sits in between and uses plain language.

What an agent is: software that uses an AI model to work through a task on its own, step by step. Unlike a chatbot that only answers, it can look things up in our systems, use tools such as the CRM or ticketing system, take actions and report back.

What works well today: tasks that are well defined and have clear success checks: triaging and routing support tickets, preparing reports by pulling data from several systems, answering policy questions with citations, fixing simple bugs where tests confirm the fix, handling routine customer requests like address changes.

What is still hard: agents make mistakes, sometimes confidently; they can be misled by malicious content in emails or documents; and they are less reliable on long, vague tasks where many steps must all go right. So important decisions and actions need human oversight.

The sensible path: start with agents assisting people, drafting replies, suggesting categories, preparing summaries, and automate more as data proves they are reliable. Value depends less on the model than on access to good data, integration with our systems and adapting processes. And we should agree up front on how to measure outcomes, like handling time and quality, rather than chasing hype.

How it works

  1. Start with the business process and its pain points, not the technology.
  2. Pick a task with clear inputs, outputs and success checks.
  3. Launch in assist mode with humans approving.
  4. Measure accuracy and time saved against a baseline.
  5. Increase autonomy for the parts that prove reliable.

Example

A short explanation for a customer service director:

"Think of the agent as a fast new team member who can read every system but is still on probation.
 Week 1-6: it drafts replies and suggested refunds; your team approves each one.
 We track: % of drafts sent unchanged, handling time, customer satisfaction.
 If 90%+ of drafts for address changes go out unchanged, we let it handle those alone,
 while refunds over £50 always stay with a person."

Common mistakes

  • Using jargon (tokens, RAG, embeddings) with non-technical stakeholders.
  • Promising full automation from day one.
  • Hiding the error rate to win approval.
  • Ignoring the process and data work needed.

How to answer in the interview

"I'd say an agent is software that uses AI to work through a multi-step task on its own: it can look things up in our systems, use tools and take actions, not just answer questions. Today it's strong for well-defined tasks with clear checks, like triaging tickets or preparing reports. It still makes mistakes, can be misled and struggles with long, vague tasks, so important decisions need oversight. We'd start with the agent assisting people, then automate more as it proves reliable. The value depends on our data, integration and process changes, and we'd measure outcomes, not hype."

Likely follow-up questions

  • First use case to propose? High-volume, rule-based work with an easy quality check, like ticket triage.
  • Will it replace staff? It shifts work to exceptions and higher-value tasks first.
  • How do we know it's working? Agreed baseline metrics reviewed monthly.
