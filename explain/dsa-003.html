How do you find the maximum subarray sum (Kadane’s algorithm)?

DSA: Arrays & Strings · concept · levels entry, mid

In one line

Kadane's algorithm scans once, tracking the best sum of a subarray ending at the current index, cur = max(x, cur + x), and the global maximum. It runs in O(n) time and O(1) space. Initialising both with the first element handles the all-negative case.

Detailed explanation

The brute force tries all O(n²) subarrays (with running sums). Kadane's algorithm is really a tiny dynamic programme. Let best_ending_here[i] be the maximum sum of a subarray that ends exactly at index i. Such a subarray either is just nums[i] alone, or extends the best subarray ending at i-1. So:

cur(i) = max(nums[i], cur(i-1) + nums[i])

The intuition: if the running sum so far is negative, it can only hurt anything that comes next, so we restart at the current element. The answer is the maximum cur seen over all positions. Because each state depends only on the previous one, we keep a single variable instead of an array, so space is O(1).

Edge cases:

  • All negative numbers ([-3, -1, -2]): the answer is -1, the largest single element. If you initialise best = 0, you wrongly return 0, an empty subarray, unless the problem explicitly allows empty subarrays. Initialise both cur and best to nums[0] and loop from index 1.
  • Overflow: with large values, use long.

To return indices, track a tentative start that resets whenever we restart, and record start/end whenever best improves.

How it works

  1. cur = best = nums[0].
  2. For i from 1: cur = max(nums[i], cur + nums[i]).
  3. best = max(best, cur).
  4. Return best.

Example

public int maxSubArray(int[] nums) {
    int cur = nums[0], best = nums[0];
    int start = 0, bestStart = 0, bestEnd = 0;
    for (int i = 1; i < nums.length; i++) {
        if (nums[i] > cur + nums[i]) { cur = nums[i]; start = i; }
        else cur += nums[i];
        if (cur > best) { best = cur; bestStart = start; bestEnd = i; }
    }
    return best;   // indices: bestStart..bestEnd
}
// [-2,1,-3,4,-1,2,1,-5,4] -> 6 from [4,-1,2,1] (indices 3..6)

Trace: cur goes -2, 1, -2, 4 (restart), 3, 5, 6, 1, 5. The best is 6.

Common mistakes

  • Initialising best = 0, which breaks all-negative inputs.
  • Resetting cur to 0 before adding the element, which changes the semantics subtly.
  • Forgetting that the subarray must be contiguous (that is a different problem from the max subsequence).
  • Not asking whether an empty subarray is allowed.

How to answer in the interview

"I'd use Kadane's algorithm. I scan once, keeping the best sum of a subarray that ends at the current position and the overall best. For each element, the current sum becomes the larger of the element alone or the current sum plus the element. If the previous running sum is negative, it only hurts, so effectively we restart. Then I update the global maximum. It's O(n) time and O(1) space. I initialise both values with the first element so an all-negative array returns its largest element rather than zero, and I can track a start index to return the boundaries."

Likely follow-up questions

  • Return start and end indices? Reset a tentative start on restart, and save it when best improves.
  • Maximum product subarray? Track both the max and min product ending here, because a negative times a negative flips.
  • Circular array? The answer is max(normal Kadane, total minus the minimum subarray), unless all values are negative.
