How would you find the top K most frequent elements in a large array?

DSA: Arrays & Strings · concept · levels mid

In one line

Count frequencies with a hash map (O(n)), then keep a min-heap of size K ordered by count, evicting the smallest when it exceeds K. That is O(n log k) time. Bucket sort by frequency gives O(n). For streams or huge data, use Count-Min Sketch / Space-Saving or a distributed map-reduce.

Detailed explanation

Counting is unavoidable: one pass with HashMap<Integer,Integer> (or merge(x, 1, Integer::sum)) gives each distinct value's frequency in O(n). Call the number of distinct values m.

Selecting the top K can be done in several ways:

  • Sort all entries by count: O(m log m). Simple, but wasteful when K is small.
  • Min-heap of size K: iterate the entries, offer each, and if size > K, poll the smallest. The heap always holds the K largest seen so far, and its root is the weakest of them. That is O(m log k) time and O(k) heap space. A min-heap is used (not max) because we want to quickly discard the smallest candidate.
  • Bucket sort: frequencies are between 1 and n, so create buckets[freq] lists and walk from high frequency down until K elements are collected. That is O(n) time and O(n) space.
  • Quickselect on the entries by count: average O(m).

For a "large array", clarify the scale. If the distinct values don't fit in memory, or the data is a never-ending stream:

  • Distributed: partition by hash of the value so the same value goes to the same worker, count locally, take a local top K, then merge (map-reduce, Spark, Kafka Streams).
  • Approximate: Count-Min Sketch plus a heap, or the Space-Saving / Misra-Gries algorithms track heavy hitters in fixed memory with bounded error. Use sliding windows for "trending" items.

How it works

  1. freq = count(nums).
  2. PriorityQueue<Map.Entry> heap ordered by count, ascending.
  3. For each entry: heap.offer(e). If heap.size() > k, heap.poll().
  4. Drain the heap and reverse for descending order.

Example

public int[] topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> freq = new HashMap<>();
    for (int x : nums) freq.merge(x, 1, Integer::sum);

    PriorityQueue<Map.Entry<Integer, Integer>> heap =
        new PriorityQueue<>(Map.Entry.comparingByValue());
    for (var e : freq.entrySet()) {
        heap.offer(e);
        if (heap.size() > k) heap.poll();
    }
    int[] res = new int[k];
    for (int i = k - 1; i >= 0; i--) res[i] = heap.poll().getKey();
    return res;
}
// [1,1,1,2,2,3], k=2 -> [1,2]

Common mistakes

  • Using a max-heap of all elements (O(m log m)) and calling it optimal.
  • Forgetting tie-breaking rules if the problem requires deterministic order.
  • Ignoring that huge distinct-value sets may not fit in memory.
  • Thinking local top-Ks from random shards are exact. Partition by key first.

How to answer in the interview

"First I count frequencies with a hash map in O(n). Then I keep a min-heap of size K ordered by frequency. I add each entry, and if the heap grows beyond K, I remove the smallest. At the end it holds the K most frequent. That's O(n log k) time. An alternative is bucket sort, where index i holds the elements seen i times, which gives O(n). If the data were huge or a never-ending stream, I'd partition by key and count in parallel, or use an approximate heavy-hitters structure like Count-Min Sketch with a heap."

Likely follow-up questions

  • Never-ending stream? Sliding-window counts with Count-Min Sketch or Space-Saving plus a heap of size K.
  • Why a min-heap and not a max-heap? The root is the weakest candidate, so eviction is O(log k).
  • Top K by a combination of recency and frequency? Use a decayed score (exponential decay) as the heap key.
