How do you count the number of islands in a grid?

DSA: Trees & Graphs · concept · levels mid

In one line

Scan every cell. When you find unvisited land, increment the count and flood-fill its whole island with DFS or BFS, marking cells visited. That is O(rows × cols) time. Prefer BFS (or iterative DFS) on huge grids to avoid stack overflow, and Union-Find when land is added dynamically.

Detailed explanation

An island is a group of land cells ('1') connected horizontally or vertically (clarify whether diagonals count). Counting islands is counting connected components in an implicit graph where each land cell is a node with up to four neighbours.

Flood fill approach. Iterate over all cells. When a land cell has not been visited, it belongs to a new island: increment the counter, then explore everything reachable from it and mark it visited, so it is never counted again. Marking options:

  • Mutate the grid (set to '0'): O(1) extra memory, but it destroys the input. Ask if that is allowed.
  • Use a separate boolean[][] visited.

DFS vs BFS. Recursive DFS is the shortest code, but a 1000×1000 grid of all land means a recursion depth of up to a million, which causes StackOverflowError in Java. Use BFS with a queue or an explicit stack. Mark cells visited when enqueueing, not when dequeueing, to avoid adding the same cell multiple times.

Complexity: each cell is visited a constant number of times, so time is O(R·C). Space is O(R·C) in the worst case for the visited array or queue. BFS's queue is often O(min(R, C)) in practice.

Union-Find (disjoint set union) treats each land cell as a set and unions it with land neighbours. The island count equals the number of sets. It shines in the dynamic version ("Number of Islands II"): when land is added one cell at a time, add a new set (count++), union with existing neighbours (count-- per successful union), and report the count after each addition. With path compression and union by rank, each operation is nearly O(1) (inverse Ackermann).

How it works

  1. count = 0.
  2. For each cell (r, c): if grid[r][c] == '1', then count++ and run bfs(r, c).
  3. BFS: set the cell to '0' and enqueue it. Pop, check the 4 neighbours in bounds that are '1', mark them and enqueue.
  4. Return count.

Example

public int numIslands(char[][] grid) {
    int rows = grid.length, cols = grid[0].length, count = 0;
    int[][] dirs = {{1,0},{-1,0},{0,1},{0,-1}};
    for (int r = 0; r < rows; r++)
        for (int c = 0; c < cols; c++) {
            if (grid[r][c] != '1') continue;
            count++;
            Deque<int[]> q = new ArrayDeque<>();
            q.offer(new int[]{r, c}); grid[r][c] = '0';
            while (!q.isEmpty()) {
                int[] cell = q.poll();
                for (int[] d : dirs) {
                    int nr = cell[0] + d[0], nc = cell[1] + d[1];
                    if (nr >= 0 && nr < rows && nc >= 0 && nc < cols && grid[nr][nc] == '1') {
                        grid[nr][nc] = '0';            // mark on enqueue
                        q.offer(new int[]{nr, nc});
                    }
                }
            }
        }
    return count;
}

Common mistakes

  • Marking visited on dequeue, which duplicates queue entries.
  • Recursive DFS on huge grids, which overflows the stack.
  • Including diagonal neighbours when the problem says 4-directional (or vice versa).
  • Modifying the input grid without asking.
  • Bounds checks in the wrong order (index before checking range).

How to answer in the interview

"I scan each cell of the grid. When I find land that I haven't visited, I increment the island count and flood-fill from that cell with BFS or DFS, visiting all four-directionally connected land and marking it visited, either in a visited array or by overwriting the grid if that's allowed. Every cell is processed a constant number of times, so it's O(rows times columns). On very large grids I'd use BFS or an explicit stack to avoid stack overflow. If land is added one cell at a time, I'd switch to Union-Find, so each addition updates the count in near-constant time."

Likely follow-up questions

  • Land added one cell at a time? Union-Find: count++ for new land, count-- for each successful union with a neighbour.
  • Largest island area? Return the size from each flood fill and keep the max.
  • Distinct island shapes? Record a normalised path signature or relative coordinates per island in a set.
