How would you group products by category using Collectors.groupingBy()?

Coding Exercises · scenario · levels mid

In one line

products.stream().collect(Collectors.groupingBy(Product::getCategory)) returns a Map<String, List<Product>> (a HashMap by default); add a downstream collector (counting, mapping, summingDouble) to change what is stored per key, a map factory like TreeMap::new for sorted keys, and use partitioningBy for true/false splits.

Detailed explanation

groupingBy is the stream equivalent of SQL GROUP BY. Its classifier function computes a key for each element; elements with the same key go into the same group.

Three overloads:

  1. groupingBy(classifier) — values are List<T>, map is a HashMap. Key order is therefore not defined.
  2. groupingBy(classifier, downstream) — the downstream collector decides what is stored for each key:
  • counting() → Map<String, Long> with product counts.
  • mapping(Product::getName, toList()) → names only per category.
  • summingDouble(Product::getPrice), averagingDouble, maxBy(comparator).
  • toSet(), or collectingAndThen(toList(), List::copyOf) for immutable lists.
  1. groupingBy(classifier, mapFactory, downstream) — choose the map type: TreeMap::new for keys sorted alphabetically, LinkedHashMap::new to keep encounter order, () -> new EnumMap<>(Category.class) for enum keys.

Nested grouping works by using groupingBy as the downstream: group by category, then by brand.

partitioningBy(predicate) is a special case with exactly two groups, true and false, and returns Map<Boolean, List<T>>. Unlike groupingBy, both keys are always present, even when one group is empty.

Null keys: groupingBy throws NullPointerException if the classifier returns null ("element cannot be mapped to a null key"). Map null categories to a placeholder like "UNCATEGORISED" first.

For parallel streams, groupingByConcurrent builds a ConcurrentMap directly, avoiding expensive map merging, at the cost of order.

How it works

  1. For each product, the classifier computes its category.
  2. The collector looks up or creates the group for that key.
  3. The element is added via the downstream collector.
  4. The finished map is returned.

Example

Map<String, List<Product>> byCategory = products.stream()
        .collect(Collectors.groupingBy(Product::getCategory));

Map<String, Long> countPerCategory = products.stream()
        .collect(Collectors.groupingBy(Product::getCategory, Collectors.counting()));

Map<String, List<String>> namesSorted = products.stream()
        .collect(Collectors.groupingBy(Product::getCategory, TreeMap::new,
                 Collectors.mapping(Product::getName,
                     Collectors.collectingAndThen(Collectors.toList(),
                         l -> l.stream().sorted().toList()))));

Map<Boolean, List<Product>> lowStock = products.stream()
        .collect(Collectors.partitioningBy(p -> p.getStock() < 10));

Common mistakes

  • Expecting keys in sorted or insertion order from the default HashMap.
  • Null category values causing NullPointerException.
  • Grouping and then streaming each list again to count, instead of a downstream collector.
  • Using groupingBy for a boolean split where partitioningBy is clearer.

How to answer in the interview

"I'd write products.stream().collect(Collectors.groupingBy(Product::getCategory)), which gives a Map from category to a list of products in a HashMap. A downstream collector changes what's stored per key: counting for counts, mapping to names, or summingDouble for totals. The three-argument version takes a map factory, like TreeMap::new for sorted keys. And for a two-way split such as low stock or not, partitioningBy gives a Map<Boolean, List<Product>> with both keys always present."

Likely follow-up questions

  • How would you get names per category, sorted? groupingBy with TreeMap::new and a mapping downstream, sorting names via collectingAndThen.
  • What if category can be null? Map nulls to a placeholder key first.
  • groupingBy vs toMap? toMap gives one value per key with a merge function; groupingBy collects many.
