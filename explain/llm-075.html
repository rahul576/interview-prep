What are embeddings, and where are they used besides RAG?

LLMOps & RAG · concept · levels entry, mid, senior

In one line

Embeddings are dense vectors that encode meaning so similar items sit close together (measured by cosine similarity or dot product); besides RAG they power semantic search, recommendations, clustering, deduplication, classification features, routing, anomaly detection and, with multimodal models, text-to-image search.

Detailed explanation

An embedding model maps an input (a sentence, document, product, image) to a vector of typically several hundred to a few thousand dimensions. Training (often contrastive) pushes related items together and unrelated ones apart, so geometric closeness reflects semantic similarity: "reset my password" and "I forgot my login" end up near each other despite sharing no words. Some modern models support variable output dimensions (Matryoshka-style), trading a little accuracy for smaller, cheaper vectors.

Uses beyond RAG:

  • Semantic search: product search, help-centre search, code search, often combined with keyword search.
  • Recommendations: items similar to what a user viewed; users similar to other users; "related articles".
  • Clustering and topic discovery: group thousands of support tickets or survey responses into themes, then label clusters with an LLM.
  • Deduplication: near-duplicate documents, repeated questions, duplicate bug reports.
  • Classification: embeddings as features for a lightweight classifier (logistic regression, small MLP) are often far cheaper and faster than calling an LLM per item, with good accuracy given labelled data.
  • Routing: send a request to the right team, tool, prompt or model by nearest labelled example.
  • Anomaly detection: inputs far from usual patterns (fraudulent descriptions, out-of-scope prompts, drift in user queries).
  • Caching: semantic cache keys.
  • Multimodal: CLIP-style models place images and text in a shared space, enabling "find photos of red sneakers" without captions.

Practical points: choose a model for your languages and domain; store the model name and version with vectors; never compare vectors from different models, because each model defines its own space; normalise when using cosine similarity.

How it works

  1. Choose an embedding model suited to data and languages.
  2. Embed items in batches; store vectors with IDs and metadata.
  3. Index with an ANN structure (HNSW, IVF) for fast nearest-neighbour search.
  4. Embed the query or new item; find neighbours.
  5. Use neighbours for search, recommendation, cluster or label assignment.
  6. Re-embed everything when changing models.

Example

from sklearn.cluster import KMeans
from sklearn.linear_model import LogisticRegression

X = embed(ticket_texts)                       # (n, d) matrix
themes = KMeans(n_clusters=12).fit_predict(X) # discover complaint themes

clf = LogisticRegression(max_iter=1000).fit(embed(labelled_texts), labels)
team = clf.predict(embed(["My card was charged twice"]))[0]   # route to "billing"

Common mistakes

  • Mixing vectors from different models or versions.
  • Using an English-only model for multilingual data.
  • Calling an LLM per item when an embedding classifier would do.
  • Ignoring metadata filtering alongside similarity.

How to answer in the interview

"An embedding is a dense vector, typically hundreds to a few thousand dimensions, that captures meaning so similar items are close together, measured with cosine similarity or dot product. Besides RAG they power semantic search and recommendations, clustering of tickets or feedback into themes, near-duplicate detection, and features for cheap classifiers instead of an LLM call per item. They're useful for routing requests to the right team or model, for anomaly detection, and with multimodal models for searching images by text. One rule: never compare embeddings from different models, because each model has its own vector space."

Likely follow-up questions

  • Why not compare across models? Different training produces unrelated coordinate systems.
  • Cosine vs dot product? Same for normalised vectors; dot product includes magnitude otherwise.
  • Choosing a model? Benchmark on your data and languages; consider dimensions and cost.
