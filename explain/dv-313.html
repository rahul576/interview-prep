How does Argo CD work? Explain Applications, sync and health status.

GitOps & Helm · concept · levels entry, mid

In one line

An Argo CD Application maps a Git source (plain YAML, Kustomize or Helm) to a destination cluster and namespace; Argo CD renders the source and compares it with the live cluster to show sync status (Synced/OutOfSync) and separately health status (Healthy, Progressing, Degraded, etc.), syncing manually or automatically with prune and self-heal, ordered by sync waves and hooks, and governed by projects and RBAC.

Detailed explanation

Argo CD's repo server renders manifests, the application controller compares desired and live state and applies changes, and the API server/UI handles SSO and RBAC.

An Application has a source (repo URL, revision, path, and Helm or Kustomize options) and a destination (cluster API and namespace), plus a project and syncPolicy.

Sync status answers "does the cluster match Git?" Argo CD renders the manifests and diffs them with live objects. If everything matches it is Synced; otherwise OutOfSync, and the UI or argocd app diff shows exactly which fields differ. Fields changed by controllers (like HPA replicas) can be excluded with ignoreDifferences.

Health status answers "is it working?" It is calculated per resource with built-in checks: a Deployment is Progressing while rolling out and Healthy when all replicas are updated and available; Degraded if it fails (for example progress deadline exceeded). An app can be Synced but Degraded, for example the right image deployed but crash-looping.

Sync can be manual (click or CLI) or automated on every Git change. Prune deletes resources removed from Git; self-heal reverts manual changes. Sync waves (annotation with a number) and hooks (PreSync, Sync, PostSync, SyncFail) order work, for example CRDs, then a migration Job, then the Deployment. AppProjects with RBAC limit which repos, clusters and namespaces each team can deploy to.

How it works

  1. Create an Application (UI, CLI or YAML, ideally YAML in Git).
  2. Repo server renders manifests from the source revision.
  3. Controller diffs them with live state → sync status.
  4. Sync applies changes in wave order, running hooks.
  5. Health checks evaluate resources → health status; repeat continuously.

Example

apiVersion: argoproj.io/v1alpha1
kind: Application
metadata: { name: orders-prod, namespace: argocd }
spec:
  project: shop
  source:
    repoURL: https://github.com/acme/deploy-config
    targetRevision: main
    path: apps/orders/overlays/prod
  destination:
    server: https://kubernetes.default.svc
    namespace: orders
  syncPolicy:
    automated: { prune: true, selfHeal: true }
    syncOptions: [ CreateNamespace=true ]
# migration runs before the Deployment
metadata:
  annotations:
    argocd.argoproj.io/hook: PreSync
    argocd.argoproj.io/hook-delete-policy: HookSucceeded

Common mistakes

  • Treating Synced as "working"; check health too.
  • Fighting OutOfSync caused by HPA or mutating webhooks instead of using ignoreDifferences.
  • Creating Applications by clicking in the UI rather than declaring them in Git.
  • Enabling automated prune on a path that is shared with other tools.

How to answer in the interview

"In Argo CD an Application defines a source, a Git path with plain manifests, Kustomize or a Helm chart, and a destination cluster and namespace. Argo CD renders the source and compares it with the live cluster: if they match the app is Synced, otherwise OutOfSync, with a diff I can inspect. Health is separate: each resource is Healthy, Progressing or Degraded based on things like rollout status, so an app can be Synced but Degraded. Sync can be manual or automated, with prune to delete what was removed from Git and self-heal to undo manual changes. Sync waves and hooks order things, like a migration job before the deployment, and AppProjects with RBAC limit what each team can deploy where."

Likely follow-up questions

  • App of apps or ApplicationSet for many services? ApplicationSet generators (Git directories × clusters) usually scale better.
  • Why OutOfSync right after sync? Controllers or webhooks mutate fields; use ignoreDifferences or server-side diff.
  • How do you roll back? Revert the Git commit; Argo CD's own rollback is disabled when automated sync is on.
