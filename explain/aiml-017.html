What is the difference between bagging and boosting ensembles?

AI/ML & GenAI · concept · levels mid, senior

In one line

Both combine many models: bagging trains them independently in parallel on bootstrap samples and averages, mainly reducing variance; boosting trains them sequentially, each fixing the previous errors, mainly reducing bias but risking overfitting.

Detailed explanation

An ensemble works because different models make different errors, and combining them cancels some of those errors. The two classic families take opposite approaches.

Bagging (bootstrap aggregating) draws many random samples of the training data with replacement, trains a strong, low-bias but high-variance model (typically a deep tree) on each one, and averages predictions or takes a majority vote. Since each model sees slightly different data, their errors are partly independent and averaging reduces variance without increasing bias. Random forests add random feature subsets at each split to decorrelate trees further. Models train in parallel, and rows left out of each bootstrap give an out-of-bag error estimate.

Boosting trains weak, high-bias learners (shallow trees) one after another. AdaBoost increases the weight of misclassified examples so the next learner focuses on them; gradient boosting fits each new tree to the negative gradient of the loss (the residuals for squared error). The ensemble becomes a strong model, mainly reducing bias. Because it keeps chasing errors, it can fit noise and outliers, so it needs a small learning rate (shrinkage), depth limits, subsampling and early stopping. XGBoost, LightGBM and CatBoost are the popular implementations.

A third approach, stacking, trains different model types (say, logistic regression, gradient boosting and a neural network) and fits a meta-model on their out-of-fold predictions. Blending and simple weighted averaging are lighter variants.

How it works

  1. Bagging: create N bootstrap samples.
  2. Train one model per sample in parallel.
  3. Average or vote their predictions.
  4. Boosting: fit a weak learner, measure errors or gradients.
  5. Fit the next learner to those errors, add it with a small weight, repeat until validation stops improving.

Example

from sklearn.ensemble import BaggingClassifier, GradientBoostingClassifier, StackingClassifier
from sklearn.tree import DecisionTreeClassifier
from sklearn.linear_model import LogisticRegression

bag   = BaggingClassifier(DecisionTreeClassifier(), n_estimators=200, n_jobs=-1)
boost = GradientBoostingClassifier(learning_rate=0.05, max_depth=3,
                                   n_estimators=500, n_iter_no_change=20)
stack = StackingClassifier([("bag", bag), ("boost", boost)],
                           final_estimator=LogisticRegression())

Common mistakes

  • Saying boosting reduces variance and bagging reduces bias (it is the other way round).
  • Bagging a stable model like linear regression and expecting big gains.
  • Boosting without early stopping on noisy labels.
  • Stacking using in-fold predictions, which leaks.

How to answer in the interview

"Both combine models to beat any single one. Bagging trains models independently on bootstrap samples and averages them, which mainly cuts variance; random forest is the classic. Boosting trains models in sequence, each focusing on what the previous ones got wrong, either by reweighting examples like AdaBoost or fitting residual gradients like XGBoost, so it mainly reduces bias but can overfit noise unless I use a small learning rate and early stopping. Stacking is a third option where a meta-model learns how to combine different model types."

Likely follow-up questions

  • Why is boosting harder to parallelise? Each tree depends on the previous ensemble; only work within a tree parallelises.
  • What is out-of-bag error? Validation on rows not included in each bootstrap sample.
  • When would stacking be worth it? Competitions or when diverse models give clearly complementary errors and latency allows.
