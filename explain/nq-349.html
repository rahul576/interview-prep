What are the main components of MCP architecture?

AI/ML & GenAI · concept · levels mid

In one line

MCP has three roles, host, client and server, on top of a protocol layer of JSON-RPC 2.0 messages carried by a transport (stdio or Streamable HTTP); connections begin with an initialisation handshake negotiating version and capabilities, and clients may offer features like sampling, roots and elicitation.

Detailed explanation

Host: the AI application the user interacts with, such as a desktop assistant, an IDE or a custom agent. It runs or calls the language model, decides which servers to connect, aggregates context and enforces user consent and security policy.

Client: a connector inside the host that maintains a one-to-one stateful session with one server. A host connected to GitHub and a database has two clients. Clients isolate servers from each other.

Server: a program that exposes capabilities for some system: tools (callable functions), resources (readable data identified by URIs) and prompts (templates). It can be local or remote.

Protocol layer: JSON-RPC 2.0 defines requests (with id, expecting a response), responses and notifications (one-way, such as notifications/tools/list_changed or progress updates).

Transports: stdio for local servers launched as subprocesses, and Streamable HTTP for remote servers, where the client POSTs messages and the server may stream responses using Server-Sent Events; remote servers use OAuth-based authorisation.

Lifecycle: the client sends initialize with its protocol version and capabilities; the server replies with its own; the client sends notifications/initialized; then normal operation; then shutdown.

Client features: sampling (server requests an LLM completion through the host, keeping the host in control), roots (which directories or URIs the server should work within) and elicitation (server asks the user for additional input through the host).

How it works

  1. Host creates a client per configured server.
  2. Client connects via stdio or HTTP.
  3. Handshake: initialize request and response, then initialized notification.
  4. Client lists tools, resources and prompts.
  5. Requests and notifications flow during the session.
  6. Connection is closed on shutdown.

Example

{ "jsonrpc": "2.0", "id": 1, "method": "initialize",
  "params": { "protocolVersion": "2025-06-18",
              "capabilities": { "roots": {}, "sampling": {}, "elicitation": {} },
              "clientInfo": { "name": "my-agent", "version": "1.0" } } }

The server answers with, for example, "capabilities": { "tools": { "listChanged": true }, "resources": {} }.

Common mistakes

  • Thinking one client talks to many servers.
  • Confusing host and client.
  • Forgetting capability negotiation, so features are used that the other side does not support.

How to answer in the interview

"MCP has three roles. The host is the AI application the user works with, which manages the model and user consent. Inside it, an MCP client keeps a one-to-one connection with a single MCP server, so two servers mean two clients. The server exposes tools, resources and prompts. Underneath is JSON-RPC 2.0 for requests, responses and notifications, over stdio for local servers or Streamable HTTP for remote ones. Each connection starts with an initialise handshake negotiating version and capabilities, and clients can also offer features to servers like sampling, roots and elicitation."

Likely follow-up questions

  • Why does the host manage consent? It sees the user and all servers; servers are untrusted and isolated from each other.
  • What is sampling for? Lets a server use an LLM without its own API key, under host control.
  • Is the session stateful? Yes, a connection has a lifecycle with negotiated capabilities.
