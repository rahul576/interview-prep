Explain the different kinds of nested classes in Java.

Core Java & OOP · concept · levels entry, mid

In one line

Java has static nested classes (no outer instance), inner classes (hold an implicit reference to the outer instance), local classes (declared in a method) and anonymous classes (unnamed one-off implementations), with lambdas replacing most anonymous classes.

Detailed explanation

Static nested class. Declared with static inside another class. It behaves like a top-level class that is namespaced and can access the outer class's private static members. It does not need, or hold, an outer instance. Typical uses: builders, Map.Entry-style node classes, DTOs that belong to one type.

Inner (non-static member) class. Each instance is tied to an instance of the outer class and can access its fields directly, via a hidden Outer.this reference. You create one with outer.new Inner(). The hidden reference is the main risk: if the inner object outlives the outer (stored in a static cache, registered as a listener, passed to another thread), it keeps the whole outer object graph alive, a classic memory leak. It also makes inner classes awkward to serialise.

Local class. Declared inside a method body; visible only there. It can capture effectively final local variables.

Anonymous class. A local class without a name, declared and instantiated in one expression, often to implement an interface or extend a class on the spot. Since Java 8, lambdas replace anonymous classes for functional interfaces; unlike anonymous classes, lambdas do not introduce a new scope for this and only capture the outer instance if they actually use it.

Since Java 16, inner classes may declare static members, and records, enums and interfaces nested in a class are implicitly static.

How it works

  1. The compiler generates separate class files such as Outer$Builder.class and Outer$1.class.
  2. For inner classes it adds a synthetic field holding the outer instance and passes it to the constructor.
  3. Captured locals are copied into fields, which is why they must be effectively final.
  4. Since Java 11, nestmates let nested classes access each other's private members without synthetic accessors.

Example

public class Pizza {
    private final String size;
    private Pizza(Builder b) { this.size = b.size; }

    public static class Builder {            // static nested: no Pizza instance needed
        private String size = "M";
        public Builder size(String s) { this.size = s; return this; }
        public Pizza build() { return new Pizza(this); }
    }
}

button.addListener(new ClickListener() {      // anonymous class, captures Outer.this
    public void onClick() { refresh(); }
});
button.addListener(() -> refresh());          // lambda equivalent

Common mistakes

  • Making helper classes inner instead of static, causing hidden references and leaks.
  • Registering anonymous listeners on long-lived objects and never removing them.
  • Expecting this inside an anonymous class to refer to the outer object.
  • Trying to modify captured local variables.

How to answer in the interview

"There are four kinds. A static nested class is just a top-level class scoped inside another; it needs no outer instance, so it's ideal for builders. An inner class holds an implicit reference to the outer instance, which lets it use outer fields but can leak memory if the inner object lives longer, for example as a listener or in a cache. Local classes are declared inside methods, and anonymous classes are unnamed one-off implementations. Since Java 8 I use lambdas for functional interfaces instead of anonymous classes. My default is static unless the class really needs the outer instance."

Likely follow-up questions

  • Why should a Builder usually be a static nested class? It must exist before the outer object is built, so it can't need an outer instance.
  • What does Outer.this mean? The outer instance captured by an inner class.
  • Do lambdas capture this? Only if the body uses instance members.
