What are VPC endpoints, and what is the difference between gateway and interface endpoints?

Cloud (AWS) · concept · levels mid

In one line

VPC endpoints give private subnets access to AWS services without the internet or NAT; gateway endpoints exist only for S3 and DynamoDB, work via route tables and are free, while interface endpoints (PrivateLink) create ENIs with private IPs for many services, use private DNS, cost per hour and per GB, and both support endpoint policies.

Detailed explanation

By default, a call from a private instance to s3.eu-west-1.amazonaws.com resolves to a public IP and travels through the NAT gateway, costing NAT processing fees and requiring internet egress. Endpoints keep that traffic on the AWS network.

Gateway endpoints support only Amazon S3 and DynamoDB. You create one in the VPC and associate it with route tables; AWS adds a route with a prefix list of the service's IP ranges pointing to the endpoint. There is no charge, no ENI and no DNS change, so they should be enabled in virtually every VPC. They only work for traffic originating in that VPC, not from on-premises or peered networks.

Interface endpoints, powered by PrivateLink, place an elastic network interface with a private IP in each chosen subnet. They exist for most AWS services: ECR (api and dkr), STS, Secrets Manager, SSM, SQS, SNS, CloudWatch Logs and monitoring, KMS and S3 too. With private DNS enabled, the normal service hostname resolves to the endpoint's private IPs, so SDKs and CLIs work unchanged. They are protected by security groups and can be reached from on-premises through VPN or Direct Connect. They cost per endpoint per AZ per hour plus per GB processed, so in multi-account setups teams often centralise them in a shared VPC.

Endpoint policies are resource policies on the endpoint restricting what can be done through it, for example only access to company buckets, preventing data exfiltration to arbitrary S3 buckets. Combine with bucket policies using aws:SourceVpce to require that data be accessed only through the endpoint.

How it works

  1. Create a gateway endpoint for S3/DynamoDB and attach route tables.
  2. Create interface endpoints in private subnets for other services.
  3. Enable private DNS; allow HTTPS (443) from the VPC in the endpoint security group.
  4. Attach endpoint policies.
  5. Traffic bypasses NAT and the internet.

Example

aws ec2 create-vpc-endpoint --vpc-id vpc-0abc --vpc-endpoint-type Gateway \
  --service-name com.amazonaws.eu-west-1.s3 --route-table-ids rtb-private-a rtb-private-b

for svc in ecr.api ecr.dkr sts logs; do
  aws ec2 create-vpc-endpoint --vpc-id vpc-0abc --vpc-endpoint-type Interface \
    --service-name com.amazonaws.eu-west-1.$svc --subnet-ids subnet-a subnet-b \
    --security-group-ids sg-endpoints --private-dns-enabled
done

A private EKS cluster needs at least ecr.api, ecr.dkr, the S3 gateway endpoint (image layers are stored in S3), sts for IAM roles for service accounts, plus ec2 and logs depending on add-ons.

Common mistakes

  • No S3 gateway endpoint, paying NAT fees for S3 traffic.
  • Interface endpoint security group blocking port 443.
  • Forgetting private DNS, so traffic still goes to public endpoints.
  • Missing the S3 endpoint when pulling ECR images privately.

How to answer in the interview

"VPC endpoints let resources in private subnets reach AWS services without the internet or a NAT gateway. Gateway endpoints exist only for S3 and DynamoDB; they're added as route table targets and cost nothing, so I enable them almost everywhere. Interface endpoints use PrivateLink to create ENIs with private IPs in my subnets for services like ECR, Secrets Manager, STS, SQS or CloudWatch, with private DNS so SDKs work unchanged; they cost per hour and per GB. Endpoint policies restrict what can be accessed through them. Together they improve security and often save a lot of NAT cost."

Likely follow-up questions

  • Endpoints for a private EKS cluster to pull from ECR? ecr.api, ecr.dkr, S3 gateway, plus sts and others as needed.
  • How do you restrict a bucket to the endpoint? Bucket policy denying requests where aws:SourceVpce is not your endpoint.
  • Can on-prem use gateway endpoints? No; use interface endpoints for S3 instead.
