What is Metaspace?

JVM & Performance · concept · levels mid

In one line

Metaspace stores class metadata (class structures, method bytecode, constant pools, annotations) since Java 8, replacing PermGen; it lives in native memory and grows automatically, so cap it with -XX:MaxMetaspaceSize; OutOfMemoryError: Metaspace usually means a class loader leak or too many generated classes.

Detailed explanation

When a class is loaded, the JVM creates an internal representation: its fields, methods, bytecode, the runtime constant pool, annotations, vtables and profiling data. That is class metadata. Until Java 7 it lived in PermGen, a fixed-size part of the heap that was hard to size and frequently overflowed.

Metaspace (JEP 122, Java 8) moved this to native memory. Each class loader gets its own chunks of Metaspace, so when a loader becomes unreachable and is collected, all its classes are unloaded and the memory is returned in bulk. With compressed class pointers, part of the data, the class structures themselves, lives in the Compressed Class Space (-XX:CompressedClassSpaceSize, 1 GB reserved by default), which can overflow separately with OutOfMemoryError: Compressed class space.

Sizing flags.

  • -XX:MaxMetaspaceSize: hard cap; unlimited by default. Setting it in containers turns an invisible native-memory creep into a clear error.
  • -XX:MetaspaceSize: the initial high-water mark that triggers a GC to unload classes (shown as Metadata GC Threshold in logs). Raising it avoids early full GCs during startup of large applications.

Typical causes of Metaspace OOM.

  • Class loader leaks: after hot redeploys in Tomcat or other containers, something in a parent loader (a ThreadLocal, a JDBC driver in DriverManager, a static cache, a running thread) still references the old application loader, so its thousands of classes stay loaded.
  • Runtime class generation: dynamic proxies, CGLIB or ByteBuddy, scripting engines, or frameworks creating a new class per call.
  • Simply many classes in a large application with an overly tight limit.

Investigation. jcmd VM.metaspace and VM.classloader_stats show usage per loader; -Xlog:class+load,class+unload shows whether classes are being unloaded; a heap dump in MAT can reveal duplicate class loaders and their paths to GC roots.

How it works

  1. Class loaded: metadata allocated in Metaspace chunks owned by its loader.
  2. Usage reaches the high-water mark: GC attempts class unloading.
  3. Unreachable class loaders are collected; their metadata is freed.
  4. If usage reaches MaxMetaspaceSize, OutOfMemoryError: Metaspace is thrown.

Example

java -XX:MetaspaceSize=128m -XX:MaxMetaspaceSize=300m -jar app.jar

jstat -gc <pid> 2000 | awk '{print $9, $10}'   # MC (capacity), MU (used)
jcmd <pid> VM.metaspace summary
jcmd <pid> VM.classloader_stats | sort -k4 -n | tail

Common mistakes

  • Leaving it unbounded in containers.
  • Believing MetaspaceSize is the maximum.
  • Raising the limit without checking for class loader leaks.
  • Placing the string pool or static values in Metaspace.

How to answer in the interview

"Metaspace is where the JVM stores class metadata: class structures, method bytecode, the constant pool and annotations. It replaced the Permanent Generation in Java 8. Unlike PermGen, which was part of the heap with a fixed maximum and often caused OutOfMemoryError: PermGen space, Metaspace is in native memory and grows as needed, by default without a limit, so I usually cap it with MaxMetaspaceSize. Class metadata is freed when its class loader is garbage collected. Problems typically come from class loader leaks after hot redeploys or from libraries generating many proxy classes at runtime, and I investigate them with jcmd VM.metaspace, class loading logs and a heap dump."

Likely follow-up questions

  • How would you investigate a Metaspace OutOfMemoryError? Check loader stats, class load/unload logs and a heap dump for duplicate loaders and their GC root paths.
  • What is the Compressed Class Space? A reserved region for class structures when compressed class pointers are on.
  • Does Metaspace get garbage collected? Indirectly; classes are unloaded when their loader is collected.
