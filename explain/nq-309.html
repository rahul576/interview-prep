What is the difference between Amazon S3 and Azure Blob Storage?

Cloud (AWS) · concept · levels entry

In one line

Amazon S3 and Azure Blob Storage are equivalent, highly durable object storage services; they differ mainly in structure (S3 buckets and objects versus Azure storage accounts, containers and blobs with block, append and page blob types), tier names and access control (IAM, bucket policies and presigned URLs versus Azure RBAC with Entra ID and SAS tokens).

Detailed explanation

Both store unstructured data such as documents, images, backups, logs and data lake files, accessed over HTTP APIs and SDKs, with eleven nines of durability for standard redundancy options.

Structure:

  • S3: a bucket (globally unique name, in a region) contains objects identified by keys; "folders" are just key prefixes.
  • Azure: a storage account (with a redundancy option such as LRS, ZRS, GRS) contains containers, which contain blobs. Block blobs for normal files, append blobs for logs, page blobs for random-access disks. Enabling a hierarchical namespace turns it into Data Lake Storage Gen2 with real directories.

Storage tiers: S3 Standard, Intelligent-Tiering, Standard-IA, One Zone-IA and Glacier classes (Instant Retrieval, Flexible Retrieval, Deep Archive); Azure Hot, Cool, Cold and Archive. Both support lifecycle rules to move or delete data by age.

Security: AWS uses IAM policies, bucket policies, Block Public Access and presigned URLs for temporary access; Azure uses Azure RBAC with Microsoft Entra ID, managed identities and SAS tokens (prefer user delegation SAS). Both encrypt at rest by default and support customer-managed keys (KMS, Key Vault).

Common features: versioning, object lock or immutability for compliance, cross-region replication, event notifications (S3 Event Notifications/EventBridge, Azure Event Grid) and static website hosting.

How it works

  1. Create the container (bucket or storage account plus container).
  2. Upload objects with a key or blob name via SDK or CLI.
  3. Grant access through IAM or RBAC roles, not account keys.
  4. Share temporarily with presigned URLs or SAS.
  5. Apply lifecycle and versioning policies.

Example

# AWS
aws s3 cp invoice.pdf s3://acme-invoices/2026/11/invoice.pdf
aws s3 presign s3://acme-invoices/2026/11/invoice.pdf --expires-in 900

# Azure
az storage blob upload --account-name acmestore -c invoices \
  -n 2026/11/invoice.pdf -f invoice.pdf --auth-mode login

Common mistakes

  • Public buckets or containers by accident.
  • Using storage account keys in application code.
  • Archive tiers for data needed quickly (retrieval takes hours).
  • No lifecycle rules, so costs grow silently.

How to answer in the interview

"They're equivalent object storage services, both highly durable and accessed over HTTP. The structure differs: S3 has buckets containing objects identified by keys, while Azure has storage accounts with containers containing blobs, which can be block, append or page blobs. Both have cost tiers: S3 Standard, Infrequent Access and Glacier versus Azure Hot, Cool, Cold and Archive, with lifecycle rules. Security uses IAM, bucket policies and presigned URLs in AWS, and Azure RBAC with Entra ID and SAS tokens in Azure. Both support versioning, encryption and event notifications."

Likely follow-up questions

  • Let a browser upload directly? Backend issues a presigned PUT URL or a user delegation SAS; the browser uploads straight to storage.
  • What is Data Lake Storage Gen2? Blob Storage with hierarchical namespace for analytics.
  • Is S3 strongly consistent? Yes, strong read-after-write consistency since 2020.
