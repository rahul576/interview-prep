How does Dijkstra’s algorithm find shortest paths, and when does it fail?

DSA: Trees & Graphs · concept · levels mid, senior

In one line

Dijkstra's algorithm grows shortest paths from the source using a min-priority queue of tentative distances. It repeatedly settles the closest node and relaxes its edges. With a binary heap it runs in O((V + E) log V). It fails with negative edge weights (use Bellman-Ford), and for unweighted graphs plain BFS is enough.

Detailed explanation

Dijkstra solves single-source shortest paths on graphs with non-negative weights, such as road networks, network routing (OSPF) and service latency maps.

Core idea: keep dist[v], the best known distance from the source (0 for the source, ∞ for the others). Repeatedly take the unsettled node with the smallest tentative distance. Because all weights are non-negative, no other path can later reach it more cheaply, so its distance is final. Then relax each outgoing edge u -> v with weight w: if dist[u] + w < dist[v], update dist[v], record prev[v] = u, and push (dist[v], v) into the heap.

Java implementation detail: PriorityQueue has no efficient decrease-key, so we use lazy deletion. We push duplicate entries and, when polling, skip any entry whose distance is larger than the current dist[v] (it is stale). Complexity stays O((V + E) log V), or E log E, which is equivalent.

Why negative weights break it. The "settled is final" argument fails. A node can be settled at distance 5, and later a path through a negative edge reaches it at 3, but it is never revisited. Bellman-Ford relaxes all edges V-1 times (O(V·E)) and handles negatives. One extra round detects negative cycles, where shortest paths are undefined. Johnson's algorithm reweights to use Dijkstra for all pairs.

Unweighted graphs (or all weights equal): a BFS queue visits nodes in distance order already, so it is O(V + E) with no heap. For 0/1 weights, 0-1 BFS with a deque. A\* adds a heuristic (straight-line distance) to guide the search toward a single target, as in maps and game pathfinding.

How it works

  1. dist[] = ∞, dist[src] = 0, push (0, src).
  2. Poll (d, u). If d > dist[u], skip it (stale).
  3. For each edge (u, v, w): if dist[u] + w < dist[v], update dist and prev, then push.
  4. Repeat until the heap is empty, or until the target is polled (early exit).
  5. Rebuild the path by following prev from the target and reversing it.

Example

long[] dijkstra(List<List<int[]>> adj, int src) {      // adj[u] = {v, w}
    long[] dist = new long[adj.size()];
    Arrays.fill(dist, Long.MAX_VALUE);
    dist[src] = 0;
    PriorityQueue<long[]> pq = new PriorityQueue<>(Comparator.comparingLong(a -> a[0]));
    pq.offer(new long[]{0, src});
    while (!pq.isEmpty()) {
        long[] top = pq.poll();
        int u = (int) top[1];
        if (top[0] > dist[u]) continue;                 // stale entry
        for (int[] e : adj.get(u)) {
            long nd = dist[u] + e[1];
            if (nd < dist[e[0]]) { dist[e[0]] = nd; pq.offer(new long[]{nd, e[0]}); }
        }
    }
    return dist;
}

Common mistakes

  • Using Dijkstra with negative edges.
  • Not skipping stale heap entries, which wastes work (it is still correct, but slower).
  • Integer overflow when adding to Integer.MAX_VALUE as infinity.
  • Marking nodes visited when pushed rather than when polled.

How to answer in the interview

"Dijkstra keeps a tentative distance for every node, zero for the source, and a min-priority queue ordered by distance. It repeatedly takes the closest unsettled node. Since weights are non-negative, that distance is final, and it relaxes the node's outgoing edges, updating a neighbour's distance and pushing it if the path is shorter. With a binary heap it's O((V plus E) log V). It fails with negative edge weights, because a settled node could later be reached more cheaply, so I'd use Bellman-Ford there, which also detects negative cycles. For unweighted graphs a plain BFS is simpler and faster."

Likely follow-up questions

  • Return the actual path? Store prev[v] on each relaxation and walk back from the target.
  • Why no decrease-key in Java? PriorityQueue lacks it, so we push duplicates and skip stale entries.
  • Huge road networks? Use A* with a good heuristic, bidirectional search, or contraction hierarchies.
