What is the difference between Consumer and Function?

Java 8+ Features · concept · levels entry

In one line

Both take one input, but a Consumer<T> (void accept(T)) performs a side effect and returns nothing, used in forEach and peek, while a Function<T,R> (R apply(T)) returns a result, ideally without side effects, used in map.

Detailed explanation

The difference is about intent and return type. Use a Function when you want a new value derived from the input: converting an entity to a DTO, extracting a field, parsing a string. Use a Consumer when you want to do something with the value: print it, log it, save it, send it, add it to a builder.

Because a Function returns a value, it fits transformations in pipelines such as Stream.map, Optional.map, Collectors.groupingBy(classifier) and Map.computeIfAbsent. Functions passed to map should be pure: the stream may process elements in any order (in parallel), may skip elements entirely (for example count() on a sized stream may not call map at all since Java 9), and side effects make code harder to test and reason about.

A Consumer, by contrast, exists for side effects. It's used by Iterable.forEach, Stream.forEach, Optional.ifPresent, Stream.peek (debugging), and Map.forEach (with BiConsumer). Since it returns nothing, it ends a chain rather than feeding a next step.

Both offer andThen, but with different meaning: consumer1.andThen(consumer2) runs both actions on the same input in sequence; function1.andThen(function2) pipes the output of the first into the second. Function also has compose and identity(). Two-argument forms are BiConsumer<T,U> and BiFunction<T,U,R>; primitive forms include IntConsumer and IntFunction.

How it works

  1. Decide whether you need a result (Function) or an action (Consumer).
  2. Implement apply or accept with a lambda or method reference.
  3. Pass Function to transforming APIs, Consumer to terminal/action APIs.
  4. Chain with andThen according to each interface's semantics.

Example

Function<Customer, CustomerDto> toDto = c -> new CustomerDto(c.id(), c.name());
Consumer<CustomerDto> publish = dto -> eventBus.publish("customer.updated", dto);
Consumer<CustomerDto> audit   = dto -> log.info("published {}", dto.id());

customers.stream()
    .map(toDto)                       // Function: returns a value
    .forEach(publish.andThen(audit)); // Consumer chain: both actions per element

Function<String, String> trim = String::trim;
Function<String, Integer> parse = Integer::parseInt;
int n = trim.andThen(parse).apply(" 42 ");   // output of trim feeds parse -> 42

Map<String, Integer> stock = Map.of("A1", 5, "B2", 0);
stock.forEach((sku, qty) -> System.out.println(sku + "=" + qty));   // BiConsumer

Common mistakes

  • Doing side effects (DB writes, logging) inside map.
  • Using forEach with a Consumer to build a list instead of collecting.
  • Misunderstanding what andThen means for each type.
  • Relying on peek for business logic.

How to answer in the interview

"Both take one input. A Consumer has void accept: it performs a side effect such as printing, saving or sending, and returns nothing, so it's used in forEach and peek. A Function has R apply: it transforms the input into a result, ideally without side effects, and it's used in map. So if I want a new value I use a Function, and if I want to do something with the value I use a Consumer. Both have andThen for chaining, and BiConsumer and BiFunction are the two-argument versions."

Likely follow-up questions

  • Why should functions passed to map avoid side effects? Execution order and even execution itself aren't guaranteed, especially in parallel or with short-circuiting.
  • What does Consumer.andThen do? Runs the second consumer after the first on the same input.
  • Is Runnable a Consumer? No, Runnable takes no input; it's closer to a no-arg action.
