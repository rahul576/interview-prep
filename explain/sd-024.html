How do you store and serve large files such as images, videos or documents?

Data & Storage Design · concept · levels entry, mid, senior

In one line

Store large files in object storage (S3/Blob), keep only metadata in the database, upload and download directly via pre-signed URLs with multipart/resumable uploads, process asynchronously, and deliver through a CDN.

Detailed explanation

Putting files in a database bloats it, slows backups and wastes expensive storage. Proxying uploads through app servers ties up threads and bandwidth. Object storage is cheap, extremely durable (11 nines on S3) and scales without limit.

The backend's job becomes authorisation and bookkeeping: issue a short-lived pre-signed URL, record metadata, and react when the upload completes. Multipart uploads split big files into parts that upload in parallel and can be retried individually, so a 4 GB video doesn't restart from zero on a network blip.

After upload, an event triggers processing: virus scanning, thumbnails, video transcoding, text extraction. Files are served through a CDN, with signed URLs/cookies for private content. Lifecycle policies move old objects to cheaper tiers (S3 IA/Glacier, Azure Cool/Archive).

How it works

  1. Client: POST /uploads {name, size, type} → server validates quota/type, creates metadata row PENDING, returns pre-signed (multipart) URLs.
  2. Client uploads parts directly to storage, then calls complete.
  3. Storage event → queue → workers scan and process; status READY or REJECTED.
  4. Download: server checks permission, returns a signed CDN URL.

Example

url = s3.generate_presigned_url("put_object",
    Params={"Bucket": "uploads", "Key": f"u/{user_id}/{file_id}", "ContentType": ctype},
    ExpiresIn=900)

Common mistakes

  • Streaming uploads through the API servers.
  • Trusting the client-provided content type (validate after upload).
  • Making the bucket public instead of using signed URLs.
  • No cleanup of abandoned multipart uploads.
  • Serving user files from the main domain (XSS risk); use a separate domain.

How to answer in the interview

"Files go to object storage, not the database. The API only authorises and records metadata, then hands out pre-signed URLs so clients upload directly, using multipart uploads for large files. Upload completion triggers asynchronous scanning and processing through a queue. Downloads go through a CDN with signed URLs, and lifecycle rules move old files to cheaper tiers."

Likely follow-up questions

  • How do you enforce quotas? Check before issuing URLs; verify actual size on completion.
  • How do you stop malware? Quarantine until a scanner marks it clean.
  • Resumable uploads protocol? S3 multipart or the tus protocol.
