Why might mapToDouble() be unnecessary if getPrice() already returns a double?

Coding Exercises · concept · levels mid

In one line

Collectors like summingDouble(Product::getPrice) already accept a ToDoubleFunction, and a getter returning a primitive double fits it directly, so an extra mapToDouble is redundant there; mapToDouble is needed only when you want DoubleStream operations like sum(), average() or summaryStatistics(), and there is no boxing to remove.

Detailed explanation

There are two different ways to sum prices, and confusion comes from mixing them.

Collector-based. Collectors.summingDouble(ToDoubleFunction<? super T> mapper) takes a function from the element to a primitive double. Product::getPrice, returning double, is exactly such a function. The collector internally calls it per element and adds the results into a primitive accumulator (with compensated summation for accuracy). So writing products.stream().mapToDouble(Product::getPrice).boxed().collect(summingDouble(d -> d)) or similar adds steps that do nothing useful. Within groupingBy, summingDouble and averagingDouble are the natural choice anyway, because you cannot call mapToDouble on each group.

Primitive-stream based. mapToDouble(Product::getPrice) converts Stream<Product> into a DoubleStream. That stream has its own terminal operations: sum(), average() (returning OptionalDouble), max(), min() and summaryStatistics(). When you want a single overall total, products.stream().mapToDouble(Product::getPrice).sum() is concise and idiomatic, so mapToDouble is the right tool here.

Boxing. Boxing happens when a primitive is wrapped into an object such as Double. Since getPrice() returns a primitive and both ToDoubleFunction and DoubleStream work with primitives, no boxing occurs in either approach. mapToDouble would make a difference only if the getter returned a Double object and you were using a boxed Stream<Double>; then unboxing into a DoubleStream avoids object overhead — and you would have to think about null values, which cause a NullPointerException on unboxing.

Readability is the real decision criterion: collectors for grouped or combined results, mapToDouble(...).sum() for a single total. Performance differences are negligible.

How it works

  1. summingDouble(mapper) applies the mapper to each element and accumulates a primitive double.
  2. mapToDouble(mapper) creates a DoubleStream of primitive values.
  3. DoubleStream terminals compute sum, average or statistics.
  4. Neither boxes when the getter returns a primitive.

Example

// overall total: mapToDouble is idiomatic
double total = products.stream().mapToDouble(Product::getPrice).sum();
OptionalDouble avg = products.stream().mapToDouble(Product::getPrice).average();

// collector already takes a ToDoubleFunction: no mapToDouble needed
double total2 = products.stream().collect(Collectors.summingDouble(Product::getPrice));

// per category: only the collector form works
Map<String, Double> perCat = products.stream()
        .collect(Collectors.groupingBy(Product::getCategory,
                 Collectors.summingDouble(Product::getPrice)));

// redundant
double clumsy = products.stream()
        .mapToDouble(Product::getPrice).boxed()
        .collect(Collectors.summingDouble(Double::doubleValue));

Common mistakes

  • Adding mapToDouble and then boxing back to use a collector.
  • Believing a primitive getter causes boxing in summingDouble.
  • Using reduce(0.0, Double::sum) on a boxed stream when sum() exists.
  • Forgetting nulls when the getter returns Double.

How to answer in the interview

"Collectors like summingDouble or averagingDouble already accept a ToDoubleFunction, and getPrice returning a primitive double fits it directly, so an extra mapToDouble step before collecting is redundant. mapToDouble is useful when I want to stay on a DoubleStream and call its own operations, like sum, average or summaryStatistics, for example a single overall total. And since getPrice already returns a primitive, there's no boxing to remove; mapToDouble would only matter if the getter returned a Double object. So I choose based on readability."

Likely follow-up questions

  • Which is clearer, and does performance differ? mapToDouble().sum() for one total, collectors for groups; performance is effectively the same.
  • Why does DoubleStream.average() return OptionalDouble? The stream may be empty.
  • Is double summation exact? No; both use compensated summation but still have floating-point limits.
