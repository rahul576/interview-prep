What are handoffs between agents, and when do you use them instead of an orchestrator?

AI Agents & AIOps · concept · levels mid, senior

In one line

A handoff transfers control and context from one agent to a specialist that then owns the interaction; an orchestrator keeps control, delegates subtasks and collects results. Use handoffs for conversational routing, orchestrators for task decomposition, and pass essential context, prevent loops and allow escalation to humans.

Detailed explanation

Both patterns split work across multiple agents, but they differ in who owns the conversation. In a handoff, a triage agent recognises that another agent is better suited and transfers control, with relevant context, to it. The specialist then talks to the user directly with its own instructions and tools. The OpenAI Agents SDK models this explicitly as handoffs, and similar patterns exist in other frameworks.

Customer service is the classic case: a triage agent identifies the request type and hands off to a billing agent (with invoice and refund tools), a technical support agent (diagnostics tools) or a cancellation agent (retention offers). Each specialist has a smaller, focused prompt and tool set, which improves reliability.

In an orchestrator (supervisor or orchestrator-worker) pattern, the lead agent never gives away control. It breaks a complex task into subtasks, delegates them to worker agents, collects their results and decides what to do next. Research reports, code migrations and multi-source analyses fit here.

Handoffs need care. Context must transfer, a structured summary of the customer, intent and what has already been tried, so users do not repeat themselves. Loops, where agents keep handing back and forth, are prevented with handoff limits and clear routing rules. Humans are a valid handoff target for complex, sensitive or angry cases.

How it works

  1. Triage agent classifies intent and checks eligibility.
  2. It calls a handoff tool with target agent and structured context.
  3. Specialist agent takes over with its own prompt and tools.
  4. Specialist resolves, hands back for a new topic, or escalates to a human.
  5. Handoff count and routing decisions are traced and limited.

Example

from agents import Agent, handoff

billing = Agent(name="Billing", instructions="Resolve invoices and refunds.", tools=[get_invoice, refund])
tech = Agent(name="Tech support", instructions="Diagnose connectivity issues.", tools=[line_test])
human = Agent(name="Human escalation", instructions="Create a ticket for a human agent.", tools=[create_ticket])

triage = Agent(
    name="Triage",
    instructions="Identify the request and hand off. Never solve billing or tech issues yourself.",
    handoffs=[billing, tech, handoff(human)],
)

Common mistakes

  • Handing off without context, forcing users to repeat themselves.
  • Specialists that can hand back freely, creating ping-pong loops.
  • Too many overlapping specialists with unclear boundaries.
  • No human escalation path.

How to answer in the interview

"In a handoff, one agent passes control and context to a specialist, which then talks to the user directly, like triage handing off to billing or tech support. With an orchestrator, the lead agent keeps control, delegates subtasks to workers and combines results. I use handoffs for conversational routing where one specialist should own the interaction, and orchestrators for breaking complex tasks into parts. With handoffs I make sure a structured context summary is passed, limit handoffs to prevent loops, and include a human as a handoff target."

Likely follow-up questions

  • Testing routing? A labelled set of requests with expected specialists; measure routing accuracy.
  • Combining both? A specialist can itself orchestrate workers.
  • Shared memory? Pass a structured summary rather than the whole transcript when possible.
