What is Application Gateway for Containers, and how does it differ from the older AGIC?

Azure Kubernetes (AKS) · concept · levels senior, lead

In one line

Application Gateway for Containers (AGC) is a newer Azure-managed layer 7 load balancer for Kubernetes, configured by an in-cluster ALB Controller from Gateway API or Ingress resources, sending traffic directly to pod IPs with near real-time updates, traffic splitting, mTLS and WAF; the older AGIC drove a classic Application Gateway v2 through slow ARM updates.

Detailed explanation

AGIC (Application Gateway Ingress Controller) watched Ingress resources and translated them into the configuration of a standard Application Gateway v2. Every change, such as a pod rescheduling or a new route, meant rewriting the gateway configuration through ARM, which could take tens of seconds or minutes. During that time the gateway could send traffic to pods that no longer existed, causing 502 errors during deployments. It also had scale limits and coupled the cluster tightly to a shared gateway that other teams might also modify.

AGC was designed for containers. It is a separate Azure resource with frontends (entry points with FQDNs) and an association to a delegated subnet in the cluster's VNet. The ALB Controller in the cluster watches Gateway API (GatewayClass azure-alb-external, Gateway, HTTPRoute) or Ingress resources and pushes configuration to AGC, which updates in near real time and routes directly to pod IPs.

Features include weighted traffic splitting for canary and blue-green, header and query-based routing, URL rewrites and redirects, mutual TLS to frontends and backends, WAF policies, autoscaling and zone redundancy. It can be deployed managed by the ALB Controller (the controller creates the AGC resource from an ApplicationLoadBalancer custom resource) or bring-your-own, where you create AGC with Bicep or Terraform and reference it.

It is also a natural migration target after the Ingress NGINX retirement. Azure Front Door is still often placed in front for global routing, CDN caching and edge WAF.

How it works

  1. Install the ALB Controller (Helm or AKS add-on) with a workload identity.
  2. Create AGC and its association to a delegated subnet.
  3. Create a Gateway referencing AGC; it receives a frontend FQDN.
  4. Define HTTPRoutes to services; AGC routes to pod IPs.
  5. Changes to routes or pods propagate within seconds.

Example

apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: public-gw
  namespace: shop
  annotations:
    alb.networking.azure.io/alb-id: /subscriptions/<sub>/resourceGroups/rg-net/providers/Microsoft.ServiceNetworking/trafficControllers/agc-prod
spec:
  gatewayClassName: azure-alb-external
  listeners: [{ name: http, port: 80, protocol: HTTP }]
---
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata: { name: shop, namespace: shop }
spec:
  parentRefs: [{ name: public-gw }]
  rules:
  - backendRefs:
    - { name: shop-v1, port: 80, weight: 90 }
    - { name: shop-v2, port: 80, weight: 10 }

Common mistakes

  • Expecting AGC to be configured like a classic Application Gateway in the portal.
  • Forgetting the delegated subnet and identity permissions for the controller.
  • Running AGIC with heavy pod churn and blaming the app for 502s.
  • Skipping Front Door when global routing or edge caching is needed.

How to answer in the interview

"Application Gateway for Containers is a managed layer 7 load balancer built for Kubernetes. The ALB Controller in the cluster watches Gateway API or Ingress resources and configures AGC, which routes straight to pod IPs and updates almost instantly. It supports weighted traffic splitting, header routing, mTLS and WAF. AGIC instead drove a classic Application Gateway by rewriting its whole configuration through ARM, which was slow, hit limits and caused 502s during rollouts. I'd use AGC for new designs, often with Front Door in front for global routing."

Likely follow-up questions

  • When add Front Door? Multi-region failover, global anycast entry, CDN caching and edge WAF.
  • Managed vs BYO deployment? Managed is simpler; BYO fits teams managing infrastructure in Terraform.
  • Can AGC replace Ingress NGINX? Yes, it is one of Microsoft's recommended migration targets.
