How do you detect a cycle in a linked list and find where it starts?

DSA: Lists, Stacks & Queues · concept · levels entry, mid

In one line

Use Floyd's tortoise and hare: slow moves 1 step, fast moves 2. If they meet, there is a cycle. If fast hits null, there isn't. To find the start, reset one pointer to the head and move both 1 step at a time. They meet at the cycle entrance. That is O(n) time, O(1) space, versus a hash set at O(n) space.

Detailed explanation

A cycle exists when some node's next points back to an earlier node, so naive traversal never ends.

Hash set approach: walk the list, storing visited node references. The first node already in the set is the cycle start. It is simple, but costs O(n) extra memory.

Floyd's algorithm uses two pointers. Inside a cycle, the fast pointer gains one node per step on the slow one, so it must eventually land exactly on it. It cannot skip over, because the gap shrinks by exactly 1 each step. Without a cycle, fast reaches null.

Why resetting finds the start. Let:

  • a = distance from the head to the cycle start
  • b = distance from the cycle start to the meeting point
  • c = cycle length

When they meet, slow has walked a + b and fast has walked 2(a + b). Fast's extra distance a + b must be a whole number of loops: a + b = k·c. So a = k·c - b. Walking a steps from the meeting point is the same as going c - b steps to the start, plus whole loops. So a pointer from the head and a pointer from the meeting point, both moving one step at a time, arrive at the cycle start together.

Bonus: the cycle length is found by keeping one pointer fixed at the meeting point and counting steps until the other returns.

The same idea detects cycles in sequences defined by x -> f(x), such as "find the duplicate number" in an array of 1..n, or "happy number".

How it works

  1. slow = fast = head.
  2. While fast != null && fast.next != null: slow = slow.next, fast = fast.next.next. If slow == fast, break.
  3. If the loop ended without meeting, there is no cycle. Return null.
  4. slow = head. While slow != fast, advance both by 1.
  5. Return slow, the cycle start.

Example

public ListNode detectCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) {
            ListNode p = head;
            while (p != slow) { p = p.next; slow = slow.next; }
            return p;                 // cycle start
        }
    }
    return null;                      // no cycle
}
// 3 -> 2 -> 0 -> -4 -> (back to 2): returns node 2

Common mistakes

  • Checking only fast != null and then calling fast.next.next, which throws a NullPointerException.
  • Comparing node values instead of references (values can repeat).
  • Resetting both pointers to the head.
  • Not being able to explain why the reset works.

How to answer in the interview

"I'd use Floyd's cycle detection: a slow pointer moving one step and a fast pointer moving two. If fast reaches null there's no cycle. If they meet, there is one, because inside the loop fast closes the gap by one node per step. To find the start, I reset one pointer to the head and move both one step at a time, and they meet at the cycle's entrance. That works because the distance from the head to the start equals the distance from the meeting point to the start, modulo the cycle length. It's O(n) time and O(1) space. A hash set of visited nodes is simpler but uses O(n) memory."

Likely follow-up questions

  • Why does resetting work? From 2(a+b) = a+b+kc we get a = kc - b, so both pointers reach the start together.
  • Cycle length? From the meeting point, count steps until you return to it.
  • Find the duplicate in an array of 1..n without modifying it? Treat i -> nums[i] as a linked list and apply Floyd.
