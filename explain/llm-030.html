What query transformation techniques improve retrieval, such as query rewriting, multi-query and HyDE?

LLMOps & RAG · concept · levels mid, senior

In one line

Improve retrieval by transforming the query: rewrite conversational follow-ups into standalone queries, generate multiple query variants and merge results, use HyDE (embed a hypothetical answer), decompose complex questions, and extract metadata filters, measuring gains against extra latency and cost.

Detailed explanation

Users type questions, not search queries. They are short, ambiguous, rely on chat context, or combine several needs. Query transformation uses a (usually small, fast) LLM to turn the question into better retrieval input.

Standalone rewriting. In a conversation, "what about the second one?" or "does that apply in Germany?" has no searchable meaning on its own. A rewriter takes recent history and produces "Does the parental leave policy apply to employees in Germany?". This is the single most valuable transformation for chat-based RAG.

Multi-query. Generate three to five paraphrases or perspectives of the question, retrieve for each, and merge results with reciprocal rank fusion (RAG-Fusion). It improves recall when the corpus uses different vocabulary from the user.

HyDE (Hypothetical Document Embeddings). Ask the model to write a short hypothetical answer, then embed that instead of, or in addition to, the question. An answer-shaped passage often lies closer in embedding space to real answer passages than a terse question does. It can hurt when the model's guess is wrong or off-domain (for example internal product names it does not know), pulling retrieval towards plausible but irrelevant content, and it adds a generation step before retrieval.

Decomposition. "Compare the travel policy for contractors and employees" becomes two sub-queries, each retrieved separately, with results combined; multi-hop questions can be answered step by step (an agentic retrieval loop).

Filter extraction (self-query). The model extracts structured fields from the question, like product = "X200", region = "EU", year >= 2024, and applies them as metadata filters, which is much more precise than hoping embeddings capture them.

Each transformation adds an LLM call (tens to hundreds of ms and token cost) and new failure modes. Use small models, run transformations in parallel where possible, and measure on a test set: keep only those that improve recall or answer quality enough to justify the cost.

How it works

  1. Receive question plus chat history.
  2. Rewrite to standalone; extract filters.
  3. Optionally generate variants, a HyDE passage or sub-questions.
  4. Retrieve for each with filters; fuse with RRF.
  5. Rerank and pass top chunks to generation.

Example

REWRITE = """Given the conversation and the follow-up, write a standalone search query.
Also extract JSON filters: product, region, year. Return JSON {"query":..., "filters":{...}}."""

plan = small_llm.json(REWRITE, history=history[-6:], question=q)
variants = small_llm.list(f"Give 3 alternative phrasings of: {plan['query']}")
results = [search(v, filters=plan["filters"], k=30) for v in [plan["query"], *variants]]
candidates = rrf(results)

Common mistakes

  • Embedding raw follow-up questions without history.
  • Using HyDE for proprietary terminology the model does not know.
  • Stacking every technique without measuring.
  • Letting extracted filters be too strict, returning nothing.

How to answer in the interview

"User questions are often poor search queries. In a chat, a follow-up only makes sense with history, so an LLM rewrites it into a standalone query first. Multi-query generates several phrasings and merges their results to improve recall. HyDE asks the model for a hypothetical answer and embeds that, because answer-shaped text lands closer to relevant passages. Complex questions can be decomposed into sub-questions, and the model can extract filters like product, region or date to apply as metadata filters. Each adds model calls, latency and cost, so I measure the gain on a test set before keeping it."

Likely follow-up questions

  • When does HyDE hurt? When the model's guess is wrong or domain-specific terms are unknown.
  • Which is most valuable? Standalone rewriting for conversational RAG.
  • Fallback if filters return nothing? Relax filters progressively and log the case.
