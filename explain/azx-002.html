Compare availability sets, availability zones and Virtual Machine Scale Sets for running VMs reliably.

Azure · concept · levels entry, mid, senior

In one line

Availability sets spread VMs across fault and update domains within one datacenter (99.95% SLA), availability zones spread them across separate datacenters (99.99% SLA), and Virtual Machine Scale Sets manage many VMs with autoscaling, rolling upgrades and repairs; a zone-spanning Flexible scale set is usually the best default.

Detailed explanation

Availability sets are the original VM resilience feature. VMs in a set are distributed across fault domains (up to three, groups of hardware sharing power and network switches) and update domains (groups rebooted together during planned host maintenance, up to 20). This protects against a rack failure or maintenance reboot taking all VMs down, with a 99.95% SLA for two or more VMs. It does not protect against a whole datacenter failing.

Availability zones put VMs in physically separate datacenters in the region. With two or more VMs across two or more zones, Microsoft offers a 99.99% SLA. You deploy zonal VMs and disks, and use zone-redundant load balancers in front.

Virtual Machine Scale Sets (VMSS) manage a fleet of VMs as one resource: autoscale on metrics or schedules, rolling upgrades of the image or configuration, automatic instance repairs using health probes, and distribution across zones and fault domains. There are two orchestration modes. Uniform mode uses identical instances, historically for large stateless fleets. Flexible mode, now recommended, supports standard VM resources, mixed sizes and Spot/regular mixes, spreading across zones and fault domains at the same time, and replaces the use case of availability sets.

A single VM with Premium SSD or Ultra disks has a 99.9% SLA, suitable only for non-critical or legacy workloads that cannot be clustered.

Note that infrastructure-level redundancy only helps if the application is designed for it: stateless tiers behind a load balancer, and replicated data tiers such as SQL Always On or clustered databases.

How it works

  1. Decide between single VM, set, zones or scale set based on SLA.
  2. For zones: deploy instances into zones 1, 2 and 3.
  3. Put a zone-redundant Standard Load Balancer in front.
  4. Use a Flexible scale set for autoscale and repairs.
  5. Configure health probes, rolling upgrade policy and autoscale rules.
  6. Ensure the application tier handles instance loss.

Example

az vmss create -g rg-web -n vmss-web --orchestration-mode Flexible \
  --image Ubuntu2204 --vm-sku Standard_D2ds_v5 --zones 1 2 3 \
  --instance-count 3 --platform-fault-domain-count 1 \
  --lb lb-web --admin-username azureuser --generate-ssh-keys
az monitor autoscale create -g rg-web --resource vmss-web \
  --resource-type Microsoft.Compute/virtualMachineScaleSets \
  --min-count 3 --max-count 12 --count 3
az monitor autoscale rule create -g rg-web --autoscale-name vmss-web \
  --condition "Percentage CPU > 70 avg 5m" --scale out 2

Common mistakes

  • Using availability sets for new designs in zone-enabled regions.
  • Deploying a scale set into a single zone.
  • Assuming infrastructure redundancy fixes a stateful single-instance app.
  • No health probe, so automatic repairs cannot detect failed instances.
  • Ignoring that zone-to-zone data transfer and capacity need planning.

How to answer in the interview

"An availability set spreads VMs across fault domains, separate racks, and update domains, which reboot at different times, all within one datacenter; it gives a 99.95 percent SLA but does not survive a datacenter outage. Availability zones put VMs in physically separate datacenters, with a 99.99 percent SLA for two or more VMs across zones. Virtual Machine Scale Sets manage a fleet of VMs as one resource, with autoscaling, rolling upgrades and automatic repairs, and can span zones. Flexible orchestration is now the recommended mode, combining fleet management with spreading across zones and fault domains, so my default is a zone-spanning flexible scale set behind a zone-redundant load balancer."

Likely follow-up questions

  • When would you still use a single VM with Premium SSD? For non-critical or legacy workloads that cannot be clustered, accepting a 99.9% SLA.
  • Uniform or Flexible mode? Flexible for most new workloads; Uniform for very large identical fleets.
  • How do automatic instance repairs work? Health probes detect unhealthy instances, which are deleted and recreated.
