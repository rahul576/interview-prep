What is the Linux file system hierarchy? Explain /etc, /var, /home, /tmp and /usr.

Linux · concept · levels entry

In one line

Linux uses one directory tree rooted at /, where /etc holds configuration, /var variable data such as logs, /home user directories, /tmp temporary files and /usr installed programs and libraries, as defined by the Filesystem Hierarchy Standard.

Detailed explanation

Unlike Windows drive letters, Linux has a single hierarchy starting at the root directory /. Every disk, partition, network share or virtual filesystem is mounted at some directory inside that tree, so /data might be a separate SSD and /mnt/nfs a remote share. The Filesystem Hierarchy Standard (FHS) describes where things belong, which is why you can find your way around any distribution.

/etc holds host-specific configuration: /etc/hosts, /etc/fstab, /etc/ssh/sshd_config, /etc/nginx/, /etc/systemd/system/. It should contain text config, not binaries. /var holds variable data that changes as the system runs: logs in /var/log, package caches in /var/cache, application state in /var/lib (databases, Docker's data in /var/lib/docker), and spool files for mail and print queues. Because /var grows, it is often a separate filesystem, and a full /var is a common outage cause.

/home has a directory per user (/home/alice); root's home is /root. /tmp is for temporary files, world-writable with the sticky bit, and is often a RAM-backed tmpfs cleared on reboot. /usr holds the bulk of installed software: /usr/bin for commands, /usr/lib for libraries, /usr/share for documentation and data, and /usr/local for software installed manually outside the package manager. /opt is for self-contained third-party packages.

On most modern distributions /bin, /sbin and /lib are symlinks into /usr (the "usr merge"). /proc and /sys are virtual filesystems exposing kernel and process information, and /dev contains device files.

How it works

  1. The kernel mounts the root filesystem at /.
  2. /etc/fstab or systemd mount units attach other filesystems.
  3. Programs read config from /etc and write state to /var.
  4. Users work in /home; temp data goes to /tmp.
  5. Virtual filesystems /proc, /sys and /dev are mounted by the kernel and systemd.

Example

ls /
ls -l /bin                 # lrwxrwxrwx /bin -> usr/bin  (usr merge)
cat /etc/os-release
du -sh /var/log/*
findmnt / /var /tmp        # which filesystem backs each path
cat /proc/meminfo | head -3

Common mistakes

  • Storing application data in /tmp and losing it on reboot.
  • Letting /var/log fill the root filesystem.
  • Installing manual software into /usr/bin instead of /usr/local or /opt.
  • Editing files in /proc or /sys without knowing they change the running kernel.

How to answer in the interview

"Linux has one directory tree starting at the root slash, and every disk is mounted somewhere inside it. /etc holds system-wide configuration like /etc/hosts and service configs. /var holds variable data, especially logs in /var/log, plus caches and application state in /var/lib. /home has a directory per user, and /tmp holds temporary files that may be cleared on reboot. /usr contains installed programs and libraries, with /usr/local for manually installed software. On modern distros /bin and /sbin are symlinks into /usr. /proc and /sys are virtual filesystems exposing kernel and process information."

Likely follow-up questions

  • What is stored in /proc and how would you use it? Per-process directories and kernel info, like /proc/<pid>/status, /proc/meminfo and /proc/cpuinfo, for debugging.
  • Why put /var on its own filesystem? So runaway logs cannot fill the root filesystem.
  • /opt versus /usr/local? /opt for self-contained vendor packages, /usr/local for locally built software in the standard layout.
